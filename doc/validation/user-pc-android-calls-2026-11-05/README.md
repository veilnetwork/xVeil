# Репорт ПК ↔ Android: запросы, звонки и реестр загрузок — 2026-11-05

Исходные пользовательские материалы сохранены вне репозитория. Здесь только
технические агрегаты: без имени, username, ID контакта/звонка/кадра, сетевых
адресов и сырых журналов. Версия отчёта ПК: `0.13.94+113 (diagnostic)`, Veil

В JSON ПК 347 событий, `dropped_events=0`, 33 message ACK, 96 успешных локальных

Единственный `TransportUnavailable` записан ранее дальнейшего успешного трафика.
Он не доказывает непрерывный отказ узла. Общая ошибка закрытого контейнера также
не доказывает повреждение registry, нехватку диска или отказ всех сообщений.

## Изменение жизненного цикла загрузок

Background start/reconnect не читает реестр до открытия контейнера; после
unlock/reconnect обычное планирование возобновляется. Ожидаемая ошибка чтения
при close/dispose не записывается как неисправность registry. Неудачный read
не кэшируется пустым и не разрешает перезаписать неизвестный registry.
FormatException, неполный registry и FileSystemException/errno при открытом
контейнере продолжают диагностироваться. Explicit download requests сохраняют
строгую проверку хранилища. Никакие registry bytes не удаляются для «лечения».

Два assertion-red до правки: запуск при закрытом контейнере и закрытие во время
удержанного чтения. Unit-регрессия отдельно проверяет последующее открытие,
положительный resume tick и сохранность intent. Реальная worker/native HVS
проверена с холодным повторным открытием; synthetic unit backend не выдан за
физическое устройство.

## Новая анонимная диагностика сигнализации

Opt-in diagnostic builds экспортируют `callSignalDecision`:

- `code` — индекс CallSignalType; `-1` при неразбираемом signal body;
- `direction` — 0 outgoing, 1 incoming;
- `transport` — 0 ordinary inbox, 1 realtime inbox, -1 outgoing path set;
- `state` — 0 sendRequested, 1 decoded, 2 malformed, 3 rejectedProvenance,
  4 rejectedContact, 5 rejectedEnding, 6 duplicate, 7 handlerMissing,
  8 dispatched.

Это фиксированные категории. В отчёт не попадают call/frame/contact IDs,
текст, endpoint URI, ключи и исходные исключения. Health исключён из новых
покадровых событий, чтобы не вытеснять свидетельства ringing; прежние счётчики
liveness остаются. Dispatched означает передачу callback, не решение FSM и
не запуск медиа. Отсутствие следующей стадии также не заменяет сетевой захват.
Маршрутизация, подписи, consent, ACK/dedup и протокол звонков не ослаблялись.

12 тестов реальных ingress/transport boundaries проверяют обе полосы:
доставка, отсутствие обработчика, consent, provenance, duplicate и malformed;
два дополнительных — исходящий запрос с принятым/непринятым контактом.
После исправления matcher все 14 текущих diagnostic assertions повторно
проверены на runtime из базы: 14 assertion-red из-за отсутствия сведений.
Исходники кандидата восстановлены побайтово, повтор — 14 passed. Промежуточная ошибка размещения диагностических вызовов была поймана
компилятором; исправлена и не засчитана как воспроизведение product-дефекта.
Исправлен и matcher test fixture: вложенные map сравниваются по содержимому.
Privacy canaries проверяются на фактическом экспорте из production producer.
