# Сжатие: безопасное восстановление ссылок мастер-личностей — 2026-11-11

Подтверждены и исправлены ошибки восстановления roster после успешной
native-перезаписи. Исходный пользовательский случай «оба пароля перестали
открывать контейнер» этим не воспроизведён и не объявляется устранённым.

## Подтверждённые механизмы

| Случай | Прежнее поведение | Исправление |
| --- | --- | --- |
| Отказ/ошибка чтения одной личности после rewrite | Отсутствие записи в неполной карте ключей считалось отсутствием самой личности; её ссылка удалялась из master roster | Неполная карта не используется для записи roster; ошибка чтения не разрешает удаление |
| Повтор remap с исходными credentials | Уже обновлённые ключи отсутствовали среди старых, и исправленная запись удалялась | Распознаются подтверждённые текущие ключи; завершённый repair не пишет roster повторно |
| Первый master сохранён, запись duress master отказала | Повтор восстановления портил уже сохранённый master | Повторяемый repair сохраняет обе мастер-личности, метки и флаг anonymous |
| Не удалось повторно открыть master | Возвращался пустой список ошибок | Возвращается признак незавершённого восстановления |
| Ссылку нельзя сопоставить | Сохранялся сокращённый roster | Сохраняется прежний roster целиком; неполный результат не публикуется |
| Repair не завершён после успешного rewrite | Приложение могло сообщить общий успех сжатия | Один повтор metadata repair; при повторной ошибке — отдельный безопасный тип и понятное сообщение |

Сама native-перезапись повторно не запускается. После двух неудачных попыток
возвращается `CompactionRosterRepairIncomplete`; восстановление исходной
сессии по-прежнему выполняется в существующем finally, только пока её lease
действует. Проверки lock/wipe из
[предыдущего раунда](../compaction-remap-session-2026-11-11/README.md) сохранены.

Для успешного holder repair по-прежнему используются только ключи, полученные
при открытии пространств переданными паролями. Не добавлялись дисковый журнал
паролей, копия исходного контейнера или записи о скрытых личностях вне него.

## Ошибка в интерфейсе и анонимный отчёт

Незавершённый repair отличается от отказа самой перезаписи в RU/EN/ES.
Сообщение полностью переносится в диалоге, вместо длинного однострочного
errorText поля. Оно сообщает, что сжатие состоялось, а проверка личностей и
обновление списка не завершились; предлагает вход собственными паролями.
Это не обещание успешного чтения при неисправном диске.

В ErrorJournal остаётся `kind: storage-compaction`, но тип теперь отличим:
`CompactionRosterRepairIncomplete`. У исключения нет полей с ключами,
метками или путями. Widget-проверка экспортирует настоящий ErrorJournal и
проверяет только разрешённые `kind/type/frames`, без текста исключения.
Из remap failure markers удалены префиксы SpaceKeys; log summary выводит
количество отказов вместо меток и ключевых байтов.

## Проверки

Пять исходных сценариев падали до исправления remap. Отдельные два сценария
владельца операции после этого ещё падали: transient не восстанавливался,
persistent возвращал успешные размеры. Они прошли после bounded retry и
отдельного отказа. Дополнительно проверено сохранение всего roster при
несопоставимой ссылке.

Финальная связанная серия: **160 passed, 0 skipped**, включая новые
controller/widget-проверки, старые lock/wipe/lifecycle и native compaction.
Анализатор пяти изменённых Dart-областей: No issues found.
Все Flutter-запуски с `TMPDIR=/private/tmp/`.

Ранний focused-запуск без переменной библиотеки пропустил два native-теста;
они не считались пройденными. Зачётная финальная серия выполнена с явным
проверенным pin.

### Реальная hidden-volume

macOS, hidden-volume 2.7.0, перед запуском сверены байты библиотеки:
`a1c9a791ca186a7aa432e736565da07c897087617397fe19cf24e9b87f290fa8`.
Rust не собирался.

`test/native/compaction_roster_repair_test.dart`: три реальных пространства,
child + два master, разные пароли, Argon min. После настоящего rewrite
искусственно отклоняется либо чтение child, либо запись второго master на
границе storage API. Затем повторяется только remap. Свежие worker-isolates
читают сохранённые roster и открывают child именно указанными в них ключами;
профиль и файл **70000 байт** совпадают. Флаг anonymous в duress master
сохранён. Ещё один remap с теми же credentials также безопасен.

Оба native-сценария прошли. В отдельной копии исходников откатан только метод
remap к родительскому, остальные изменения сохранены: **0 passed / 2 rejected**,
без ошибок компиляции. Один сценарий отвергнул исчезновение записи, второй —
ошибку повторного сопоставления ключей. Копия и её build cache удалены.

## Границы и очистка

Сбои чтения/записи вводятся на границе API приложения; это не физическая
поломка носителя или native fault injection. Этот раунд не квалифицирует
Android, power-loss, crash между публикацией файла и remap, весь master/
all-online набор или исходный контейнер пользователя.

Native handles и workers закрыты, синтетические контейнеры удалены вместе с
test fixtures. Временный проект регрессионного контроля удалён. Основной
Android xVeil и пользовательские контейнеры не менялись. Сырые журналы,
пароли, пути и ключевые байты не включены в репозиторий. Push и релиза нет.
