# Пакетное применение собственной истории — 2026-11-04

## Причина и изменение

[Предыдущий native probe](../native-commit-stages-2026-11-04/README.md)
показал цену частых durable-коммитов. Убирать барьеры записи нельзя; вместо
этого обычный mirror-applier теперь может подготовить до 16 коротких уже
позиционированных сообщений для одной транзакции контейнера.

Подготовка каждой строки остаётся последовательной и проходит тот же merge.
Её future останавливается на границе append и не объявляет успех до durable
публикации. Блокировка конкретного message key удерживается до завершения
обычного merge и его последующих действий. Существующая строка не заменяется
старой историей: applier возвращается в обычный merge, который учитывает
положительное подтверждение доставки и исправление source position.

Хранилище замораживает payload до ожиданий, ограничивает пакет 16 строками
и прежним inline-размером, удерживает stream gates в постоянном порядке,
проверяет наличие строки, tombstone и clear watermark. Перед native commit
повторно проверяются действующий sibling, binding, видимость и срок жизни.
Начало удаления/очистки во время подготовки запрещает публикацию, а не
заставляет eraser ждать под scan gate: страница остаётся для безопасного повтора.
Курсор сохраняется только после всех durable inserts и продолжений applier.

Большие/непозиционированные записи и хранилища без этой возможности используют
прежний последовательный путь. Редактирование, удаление и исправление уже
существующих строк не выдаются за пакетные новые вставки.

Mailbox для собственных устройств не добавлялся. Для догрузки по-прежнему
нужен доступный источник; недоступность всех источников не обходится внешним
хранением. Wire/криптография, HVS/Veil, fsync/padding/churn и engine pins не менялись.

## Проверки

- Регрессионный тест 64 коротких сообщений на прежнем коде получил 64 post
  commits вместо допустимых четырёх. На новом — четыре пакета по 16.
  Проверяется число реальных post-транзакций, а не порог времени.
- 203 проверки истории/merge/delivery/order/удаления/census прошли. Включены
  отзыв посреди страницы и непосредственно перед storage commit, отказ записи,
  потеря ответа после успешного commit, tombstone, неподдерживаемый payload,
  close/erase, удержание message key и гонка с уже сохранённой wire-копией.
- Изменение ожидания revoke-теста с 20 строк на 16 отражает атомарность:
  следующий подготовленный пакет не сохраняется целиком; курсор прежний.
- Девять тестов с обычной проверенной native HVS прошли. В том числе пакет
  из 16 строк в одной post-транзакции, перезапуск, отказ до commit и потерянный
  ответ после commit: повтор не создаёт новые post-записи и сохраняет high-water.
- Дополнительно прошли 152 проверки storage/clear/retention/delete-scrub и
  жизненного цикла файлов: новые границы пакетной записи не изменили их исходы.
- Analyzer: 13 изменённых Dart-файлов, замечаний нет.

В стендовой переписи пакет считается одной storage operation; время ожидания
не размножается на число строк. Одновременно приостановленные historyApply
контексты пересекаются: их inclusive durations нельзя складывать как disk time.

## Сквозная проверка

На трёх отдельных native-процессах A/B/C одного Mac, с настоящими узлами,
ratchet и контейнерами, sparse crash/reconnect серия прошла:

- При очередном наблюдении B держал 1823 строки; после SIGKILL локально
  восстановились 1847 — запись продолжалась между наблюдением и завершением.
  Без A/C эти 1847 сохранены; подтверждён поздний provisional tail за дырой.
- Вернулся только A. Реально выполнен prefix fallback; все 2000 ID, порядок,
  source positions и delivered сошлись. Unknown IDs/дубли не приняты oracle;
  completed-history retries — 0. Последующий запуск B без источников сохранил
  результат. Это проверка локального восстановления, а не mailbox-доставки.
- После готовности A все строки видны за 20,856 с, вся проверяемая позиционная
  модель сошлась за 26,077 с. Наблюдатель опрашивает состояние порциями;
  разница этих времён не является отдельным точным временем CPU/диска.
  Общий таймер первичной миграции — 79,201 с, он включает остановку и рестарты.
- В окне восстановления B зарегистрированы 9 preparedBatch operations
  (все изменили хранилище, ошибок нет), 100 corrections source ordering,
  112 message-log commit RPC. Это разные категории: число RPC нельзя считать
  числом отдельных сообщений, а метод census не измеряет native fsync.
- Driver и cleanup завершились с 0. Проверены 31 PID и 42 порта; своих
  процессов/listeners нет, runtime удалён. Все 1424 выбранных inputs и SHA
  обычных native-библиотек неизменны; submodules чистые.

26,077 с не объявляются ускорением относительно прошлых 41,726 с:
тогда B сохранил 1572 строки, сейчас 1847. Объём остатка и подготовленной
истории различается, парного контроля нет. Доказанное сокращение количества
post-транзакций относится к фиксированным тестовым входам выше. Пользовательская
latency остаётся отдельным открытым измерением.

Первый запуск не засчитан: в подготовке отсутствовал каталог диагностических
результатов, B завершился до миграции. При остановке закрыты все 14 своих PID,
проверены 10 портов, удалён runtime, подтверждены неизменность inputs и native
библиотек. Для следующего запуска каталог создан заранее.

AST-индекс обновлён без LLM. Инструмент сообщил коллизии имён в Dart parts;
этот граф не считается полным доказательством связей. Проверки опираются на
исходники и исполнение production-пути.

Push, релиз, обновление сидов, установка приложения и замена native библиотек
не выполнялись. Общая latency и расширенная multi-device матрица остаются открытыми.
