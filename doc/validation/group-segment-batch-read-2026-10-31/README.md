# Пакетное чтение метаданных сегментов — 2026-10-31

**Подтверждено и исправлено:** загрузка group journal последовательно запрашивала
on-disk metadata и in-volume manifest каждого сегмента отдельными worker RPC.
Это повторные переключения изолятов; сами KV-lookup нужны и не исключаются.

## Правка и границы

- Добавлена необязательная capability `AsyncKvBatchReader`: до 64 точных KV-ключей
  в одном запросе, с прежним порядком и null на месте отсутствующего ключа.
  Список и mutable-байты ключей копируются до ожиданий. Worker не перечисляет
  namespace и не хранит результаты между вызовами.
- `HiddenVolumeStorage.loadFiles` / `AsyncFileStore.loadFiles` читают не больше
  восьми файлов с обязательным потолком для каждого. GroupService использует
  порции по 8 и 128 КиБ на файл — до 1 МиБ возвращаемых raw-байтов на fast path.
  Payload читается и проверяется по прежним log ID, без пропуска частей.
- Только текущие незавершённые одинаковые порции разделяют JSON-разбор. Ключ
  порции кодируется как JSON-массив; completed/error future удаляется. Объекты
  GroupBundle каждого читателя независимы, авторизация между чтениями не кэшируется.
- Отсутствующая/неполная или чрезмерно большая порция возвращает caller к
  прежним одиночным чтениям. Они выявляют конкретную дыру или читают допустимый
  большой legacy-сегмент. Пропуск сегмента и сохранение урезанной истории запрещены.
- Для смешанных on-disk/in-volume файлов и backend без capability сохранён
  обычный путь. Приоритет blob tier, file ceiling и привязка к исходной storage
  session сохраняются. Close/erase не позволяет batch продолжиться в новой личности.
- Потолок проверяет также фактические возвращаемые байты, а prefetch ограничивает
  развёртывание record IDs. Тест поймал переполнение бюджета при max-int ceiling
  у промежуточного кандидата; оно исправлено до установки QA. Прежняя QA-сборка
  этого кандидата не устанавливалась, новый AOT проверен отдельно.
- Wire, подписи, ratchet, durable apply/ACK и записи журнала не менялись.

## Настоящий worker: A/B/A

Свежий native encrypted container на фазу, настоящие подписи и GroupService,
128/256 строк по 4 КиБ текста, 20 полных чтений `load` на профиль. Проверены все
строки и порядок; `messagesOf` с проверкой подписей выполнен отдельно от таймера.
Одинаковые Veil/hidden-volume библиотеки, исходники после контроля восстановлены.

Число отдельных metadata RPC в B: 40 для header; batch RPC — ещё 80/120.
Пакеты содержат те же metadata keys; число native KV-lookup не объявляется
сокращённым. Сэкономлены IPC round trips, payload не исключён.

Время 20 чтений, мс: 9 сегментов — **604,044 / 586,247 / 605,726**;
18 сегментов — **1165,454 / 1136,795 / 1173,371**. Возвращённый кандидат дал

сокращения общей сетевой догрузки. Тест нового бюджета RPC красный на старом пути.

## Физическая серия A/B/C

Три текущих Dart-клиента, Android profile/AOT и два Mac с текущими JIT kernels
и прежними Runner/plugins. Native-библиотеки зафиксированы. Перед стартом
проверено наличие предыдущих 100 сообщений на всех трёх, личности сохранены.

B остановлен; A отправил 98 новых сообщений, C — два. Дождались полного набора
на A/C и минимум 300 секунд offline, затем C остановлен, B запущен при online A.
Фактический интервал остановка B → готовность B — 357,6 с, включая запуск.
