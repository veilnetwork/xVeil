# Восстановление пропущенных редакций через собеседника

**Обычный режим прошёл полный native-сценарий A/B/C.**
**Ветка onion пока открыта:** B не завершает начальную привязку за 180 секунд,
поэтому проверка восстановления редакций в этом режиме не началась.

## Подтверждённые находки

| Находка | Воспроизведение до исправления | Результат |
| --- | --- | --- |
| При равной версии C не возвращает отличающийся текст | Ожидался один ответ, получено ноль | Исправлено сравнение версий и хешей |
| При равной версии теряется отличие только в inline emoji | Ответ не формировался | Исправлено; компонентная проверка значений |
| Новая версия при прежнем тексте остаётся только в памяти | После ответа сохранялось 7 вместо 99 | Версия сохраняется после повторного открытия |
| При большей версии и том же тексте новые emoji не применяются | Сохранялось прежнее изображение | Исправлено сравнение содержимого |
| Недопустимая версия подавляет следующий запрос | Настоящая версия 99 не возвращалась | Недопустимый номер отклоняется |
| Копия редакции от собеседника доступна как собственное авторское событие | Её текст находился в `loadEventsSince` | Происхождение сохраняется, авторский replay исключён |
| Первая строка страницы не получает пропущенную редакцию | Native: 99 из 100, единственная старая строка — нижняя граница нового окна | Включены известные граничные ID; три новых теста сначала воспроизвели ошибку |
| После перезапуска B не расшифровывает ответы C | На SDK до исправления: окно 100 доходит до C, но B получает `authentication failed` | Исправлено и проверено в обычном режиме; onion не прошёл предшествующую привязку |

Первые шесть воспроизведений выполнены на сохранённых Dart-исходниках
`e3a64bc2` со сверенными хешами. Отдельные проверки Rust воспроизвели отсутствие
привязки без сессии, приоритет старой самостоятельной личности, обход выбора
ключа в relay fan-out и отправку по старому физическому ключу при отсутствии
нужного сертификата. Это отдельные этапы исправления, а не единый снимок старого
релиза.

## Что изменено

Запрос сверки содержит совместимое дополнительное поле с SHA-256 содержимого
редакций: текста и inline emoji. При равной версии используется тот же
детерминированный выбор, что в хранилище и собственных страницах истории.
Версия сохраняется и при неизменном тексте; чтение текста с версией согласовано.
Для известных ID редакции включают обе временные границы страницы: первая
строка и несколько сообщений с общей миллисекундой больше не исключаются.
Для поиска отсутствующих сообщений прежние строгие границы сохранены.

Вернувшаяся от собеседника редакция хранится как отражённая копия. Её версия
участвует в выборе видимого состояния, но не утверждает авторскую позицию и
не публикуется заново от своего имени. Признак сохраняется в контейнере,
зеркале и собственных страницах. Получение той же редакции от своего устройства
может повысить происхождение до авторского без изменения текста и версии.
Автоматическая отправка отражённой строки как нового собственного сообщения
исключена. Старые участники игнорируют дополнительное поле; сверка конфликтов
равных версий через собеседника требует обновления обеих сторон.

### Адресация и шифрование в Veil

Ответ остаётся адресован физическому устройству, которое запросило сверку.
Для шифрования SDK отдельно устанавливает его делегированную личность и точный
instance по проверенным сертификатам. При холодном старте сохранённый
подписанный документ используется только для выбора поиска: текущие документ,
registry и сертификат конкретного устройства проверяются обычным resolver.
Старая самостоятельная личность физического ключа не подменяет делегирование.
Две разные делегированные личности или разные instance не выбираются по порядку
обхода кэша. Авторитет текущего собственного документа и сессии другой личности
сохраняется.

Обычный relay fan-out больше не трактует известный физический адрес устройства
как адрес всей личности. Если точный ключ для такого ответа не найден,
отправка возвращает ошибку вместо перехода к старому самостоятельному ключу.
Начальная зашифрованная привязка своего устройства сохраняет прежнее поведение:
в этот момент получатель ещё может не иметь ключа общей личности.

Криптографические проверки не отключались, ratchet не сбрасывался для успешного
прогона. Новых производственных тестовых API или переключателей нет.

## Проверки

* Предыдущий цикл: **537 компонентных проверок в 27 файлах**.
* Текущий цикл: **1 019 тестов Rust прошли**, 16 штатно отключены; **116 тестов
  Dart в четырёх файлах прошли**. `dart analyze` и Clippy с `-D warnings` чисты.
* Native использует отдельные процессы A/B/C, настоящую привязку B к A,
  настоящий SDK, зашифрованные контейнеры и изолированные локальные реле.
* Конкурирующие состояния подготовлены в остановленных контейнерах. Это
  контролируемая подготовка данных, не имитация одновременных действий UI.
  Живое состояние читает его worker, повторного открытия занятого контейнера нет.

| Устройства и действие | Ожидается | Обычный режим | Onion |
| --- | --- | --- | --- |
| A/B/C online: привязка B к A | B принимает группу устройств | Пройдено | **Не пройдено за 180 с** |
| A offline, B и C после перезапуска | B получает все 100 редакций от C | 100/100, без дублей и смены порядка | Этап не начался |
| Повторное открытие B | Все версии и происхождение сохранены; отражённые значения не появляются в авторском replay | Пройдено | Этап не начался |
| A/B/C online, новая волна из 100 ID | История B сходится; B действительно расшифровывает ответы C | 100/100; зафиксировано 100 разных ответов C на B | Этап не начался |
| C offline, A/B online; A передаёт авторскую историю с тем же текстом | B повышает происхождение всех копий без изменения значений | Пройдено; проверено и после повторного открытия B | Этап не начался |

В обычном прогоне не обнаружено `authentication failed` или `NoSession` ни на
одном устройстве. Восстановление первой волны заняло 12,541 с **после готовности
B и начального снимка состояния**; это не полное время запуска приложения.

При работающем A часть редакций может прийти на B через собственную
синхронизацию раньше дублирующего ответа C. Поэтому условие этого этапа —
все 100 правильных строк без дублей и смены порядка **и положительная проверка
расшифрованного ответа C непосредственно на B**. Требование получить все 100
повторных копий именно от C было избыточным; итоговая история остаётся строгим
условием. Для этого этапа используются другие ID, чтобы поздние пакеты
предыдущего этапа не могли засчитать доставку.

После обычного прогона проверены **12 process groups и 16 PID**, после onion —
**5 групп и 9 PID**. Живых участников нет; контейнеры стендов удалены. Проверки
выполнялись с `TMPDIR=/private/tmp/`; во время Rust-сборок проверялось наличие
внешней файловой системы. GUI-приложения и телефон в этом цикле не запускались.

Исправление SDK сохранено в `8cb2f13b`; hidden-volume не менялся.
Отдельный дефект начальной привязки в onion остаётся предметом следующей
проверки. Причина этого сбоя пока не установлена.

Старый кандидат namespace 3 закрыт по истории проекта: его чтение намеренно
исключено `7c2dbb292` с принятым сбросом истории ещё в июле. Исправлен оставшийся
неверный комментарий. Полная матрица multi-device, длительный offline, Windows,
физические звонки и все варианты установки этим отчётом не закрываются.

В отчёте только агрегаты и хеши программ. Runtime ID, адреса, ключи, пароли,
контейнеры, пользовательское содержимое и сырые журналы не публикуются.
