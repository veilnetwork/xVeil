# Записи metadata не переходят в следующий контейнер

Агрегаты: [summary.json](summary.json).

## Подтверждённые дефекты

В `putSetting`, `saveProfile` и `saveNodeConfig` чтение старого значения и
его замена не составляли одну отслеживаемую операцию. После `await` запись
повторно обращалась к текущему `_as`. Управляемый тест через публичный API
приостанавливает чтение в A, открывает B на том же Storage, затем освобождает
чтение: значение A оказывалось в B. Это воспроизведение storage-границы с
in-memory backend, не утверждение об утечке в пользовательском случае.

Тот же путь имел ещё три ошибки:

- 16 одновременных одинаковых сохранений создавали 16 транзакций.
- Задержавшаяся старая запись могла перезаписать более новую.
- Close/erase не ждали принятую запись; после erase она могла вернуть данные.

Общий `_metadataWrite` закрепляет операцию за исходным store через существующий
write fence. Read/compare/commit одного физического ключа выполняются по
очереди; разные ключи не получают общей очереди. Ошибка остаётся ошибкой
своего caller, но не блокирует следующий запрос. Completed values не
кэшируются, активный хвост удаляется по завершении. Close/erase дожидаются
принятых операций; новые во время maintenance получают отказ.

Профиль кодируется до очереди, строки настроек/config неизменяемые. Форматы
на диске, plaintext-политика, namespace и durable commit не менялись.
В контролируемом burst для каждого из трёх API: **16 → 1 транзакция**.

## Проверки

Шесть сценариев повторены для трёх API: identical burst, порядок с независимым
ключом, retry после ошибки, смена контейнера, close и erase. Управляемые
Futures и виртуальные часы, без порогов wall time. На точном исходном файле
`d51bf0df`: **15 assertion-red / 3 passed**; candidate восстановлен побайтно.
После исправления — **18 passed**, связанные storage/history suites —
**205 passed**, включая эти 18. Analyzer и diff checks чисты.

Дополнительно с verified immutable HVS: contact decision/preferences/consent
и file lifecycle — **50 passed**, из них **26 native и 24 in-memory**.
Отдельный native test подтверждает профиль и сообщения после close/reopen —
**1 passed**. Первый одновременный Flutter-запуск этого smoke остановился
до теста из-за гонки `install_name_tool` за общим build asset; он не засчитан.
Последовательный повтор прошёл. Сквозной stand ниже запускался один раз.

## Что показала очередь большой догрузки

Строгий FIFO-анализ старой VM-трассы сопоставил 11676 RPC и worker spans:
нет внутренних пропусков, counts совпадают, порядок последовательностей
доказан. Из 42,798 с окна 1151 commit handler занял 24,097 с. 7936 `get`
заняли в обработчиках всего 0,376 с, но сумма ожиданий перед worker —
18,283 с. Ожидания параллельных RPC пересекаются и не суммируются как wall time.
Handler включает FFI и Dart worker adapter, это не чистое время fsync.

Новая трасса также qualified: 11199 RPC/worker spans, 1141 commit handler,
23,199 с обработки commit в окне 42,492 с. Граничные неполные spans отброшены,
внутренние пропуски не исправлялись. Окно VM-трассы и окно storage census
различаются; их абсолютные counts не приравниваются.

Профиль привёл к найденным гонкам, но их вклад в исходные 37–38 с не доказан.
Остаток требует атрибуции транзакций по вызывающим операциям.

## Native regression

A/B/C — три Mac/JIT процесса, две личности, три loopback Core, настоящие
transport/ratchet/HVS; provider fixture без полного foreground SessionPipeline.
Все **2000** исходных ID, итоговый порядок, канонические позиции и `delivered`
сошлись без дублей/потерь; повторов завершённой истории — 0.
Count стал полным за **32,628 с**, полная сходимость — **37,853 с**.
В предыдущем прогоне — 32,439/37,664 с. Общего ускорения нет оснований заявлять:
по одному прогону, свежие identities/caches, poll около 5 с. Основная задержка
остаётся. Offline/crash и мобильный сценарий здесь не выполнялись.

SDK `b9b88bb7` и HVS `eceb9158` не менялись. Проверены происхождение и SHA
immutable FFI/CLI/HVS до/после, 1499 frozen source/package inputs неизменны,
CPU profile содержит samples. Поздняя попытка OS mappings пришлась уже на
закрытые процессы и не считается дополнительной проверкой фактических mappings.
Сырые IDs/адреса/журналы остаются приватными.

Проверены 22 PID / 33 порта: своих процессов/listeners нет, runtime root удалён.
Телефон отключён, production и пользовательские контейнеры не менялись,
push/релиза нет. Составные metadata-операции с файловым tier, включая roster,
нуждаются в отдельной lifecycle-проверке; эта запись не объявляет их исправленными.
