# NETCALL-01: подготовка стенда без перехвата фокуса

**Новый звонок и handover не выполнены. NETCALL-01 остаётся открыт.** Poco
доступен по ADB, но Android отклонил установку отдельного QA-пакета с
`INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`. Запрошено
подтверждение следующей попытки. Основной Android APK не заменялся: его SHA
совпал до/после, Wi-Fi и mobile-data settings не изменились.

## Что проверено

Подготовлены отдельные Android ARM64 и macOS ARM64 profile/AOT артефакты из
текущего приложения. Это операторский стенд с объявленными private overlays,
а не неизменённый дистрибутив: отдельные package/bundle/profile, скрытое
нефокусируемое окно, ручной запуск Flutter engine, отключённые запросы
разрешений Mac и test-only вызов настоящего onboarding controller. Mac
настроен на приём без микрофона; это не проверка двусторонней слышимости.
Никаких новых endpoint или изменений default mute в продукт не добавлялось.

Android SDK/storage/media заморожены из проверенного опубликованного APK
0.13.102. Все **11** скопированных native libraries, пакет QA и точные
сетевые assets сверены внутри нового APK. Mac использует SDK `2cd89257`,
qualified storage и media из 0.13.102; выбранные библиотеки и новый App AOT
подтверждены в отображениях фактического процесса, подпись проверена после
выполнения. По одному наличию исходников происхождение библиотек не заявляется.
Новых Rust-сборок не было; случайный Cargo-вызов был запрещён для этой сборки.

Все три существующих тестнет-сервера прошли **read-only** проверку версии
0.11.53 и native health. Их актуальные дескрипторы/PSK хранятся только в
private workspace. Стенд передаёт явные тестнет-пиры, `builtin_seed_policy`
выключен, meeting points выключены. Production-сервисы не менялись.

На Mac настоящий onboarding создал отдельную зашифрованную QA-личность;
API подтвердил `ready`, `realStack=true`, `network=testnet`, актуальные QA
version/profile markers. Перечисление медиаустройств прошло. После создания
личности проверено: process activation policy `prohibited`, процесс не
активен и не является foreground application. Окно невидимо и не может стать
key/main window. Ввод пользователя и рабочий xVeil не затрагивались.

## Не засчитанные попытки

Первые сборки остановились на предупреждениях только private overlay.
Универсальная Flutter/lipo проверка не приняла список архитектур; зачтён
явный ARM64 Xcode build. VPN extension и требующие developer certificate
entitlements исключены только из QA-обвязки. Универсальная сборка и VPN не
квалифицируются этим результатом.

Прежний операторский `XVEIL_STORE_PATH` вне каталога preferences был правильно
отклонён новым managed-storage guard. Защита сохранена: тест переведён на
обычный отдельный QA-профиль под собственным bundle ID. До этого приложение
показывало startup-failure boundary, а не предоставляло debug API; ожидание
API не засчитано как успешный старт. Для скрытого окна также понадобился
явный запуск engine; изменения относятся к стенду.

## Завершение и следующий шаг

Настоящий lock завершился, native stack остановлен (`locked`, `realStack=false`).
После этого SIGTERM не завершил host-процесс за окно наблюдения. Только
собственный QA-процесс завершён SIGKILL; проверены его выход и освобождение
четырёх известных TCP-портов. Это **отдельное наблюдение, не объяснение
NETCALL-01**. Следующий native-контроль должен сравнить обработчики сигналов
host до/после embedded node без Flutter: текущий FFI запускает общий foreground
loop, в котором регистрируются SIGINT/SIGTERM/SIGHUP.

Позднее этот отдельный случай воспроизведён без Flutter и исправлен:
[embedded host signals](../embedded-host-signals-2026-11-18/README.md).
Повтор на том же App AOT с новой SDK завершился обычным SIGTERM без SIGKILL.
Исходные результаты подготовки выше сохраняются, не переписаны как успешные.

Промежуточные сборочные файлы этого цикла удалены — освобождено примерно
1,3 ГиБ. Для разрешённого повтора сохранены точные QA APK/app, их provenance
и отдельный тестовый профиль; shared caches и пользовательские сборки не
удалялись. [Сводка](preparation-check.json) не содержит адресов, ключей,
device IDs, PID и raw logs.

После подтверждения установки нужен настоящий звонок через заданные реле,
с измерением native audio RX age при Wi-Fi → cellular → Wi-Fi. Готовый
стенд, системные события сети и `ready` не доказывают восстановление аудио.
Нового push или релиза нет.
