# Меньше roster reads при подготовке страницы истории

Агрегаты: [summary.json](summary.json). Продолжение
[аварийной догрузки](../history-crash-retention-2026-11-07/README.md).

## Подтверждённая лишняя работа

Источнику страницы достаточно локально подготовить до 32 сообщений,
а затем заново авторизовать адресата перед каждой отправленной частью.
Раньше он дополнительно перечитывал полный device journal перед кодированием
каждой строки. Gate-тест удерживает последний encoder: **31 дополнительное
чтение внутри страницы на прежнем коде → 0**. Это прямой счётчик операций,
не вывод по сетевому времени.

Свежая проверка остаётся перед подготовкой страницы и **каждой** ответной
частью. Кэш авторизации/roster не добавлен. Перед и после каждого encoder
синхронно проверяются текущая binding/readiness и закрытие. Отдельное
исключение сохранено для inline-файла без content ID: его подготовка может
регистрировать контент, поэтому перед таким encoder по-прежнему нужен
свежий roster read. Подготовка текста и уже адресованного медиа остаётся
локальной; права на сетевую выдачу она не предоставляет.

Новый тест поймал отсутствие inline-file gate в промежуточном варианте;
он исправлен до native-прогона. Удаление финального part-authorization
gate делает revoke-тест assertion-red: адресат отозван во время последнего
encoder, и ответ обязан не выйти в сеть. Baseline/performance guard тоже
assertion-red; после обоих probes окончательный production-файл восстановлен
побайтно. Изменение binding в encoder не допускает следующего callback.

**92 related tests passed, skipped 0; analyzer/format/diff checks чисты.**
Приём, durable apply/cursor, ratchet и подписи не менялись. Пределы прежние:
32 строки / 128 КиБ страницы, 2-КиБ slices, 64 parts, существующая отдельная
входящая очередь и её byte/frame budgets. Mailbox собственным устройствам
не добавлен.

## Native crash/reconnect

Тот же сценарий: три процесса A/B/C на одном Mac, две личности, три loopback
Core, реальные SDK/ratchet/HVS, JIT/provider fixture без полного foreground
SessionPipeline. CPU/VM profiling выключен. Native-библиотеки не пересобирались;
их SHA и фактические OS mappings проверены. Телефон не использовался.

- Из 2000 строк B получил **623**, затем завершён настоящим `SIGKILL` (−9).
- A/C остановлены. Inspector нового B **до создания сети** подтвердил все
  623 ID, тела, delivered и все уже известные canonical positions. При offline
  источниках этот неполный набор сохранился.
- Вернулся только A. Все **2000/2000** ID, тела, итоговый порядок/позиции
  и delivered сошлись автоматически, без дублей; completed-history retries — 0.
- A снова выключен, C остаётся выключенным. После ещё одного запуска B
  inspector до сети подтвердил полную сохранность всех 2000 записей, их тел,
  статусов и canonical positions. Обычное чтение подтвердило тот же результат.

| Наблюдение | Предыдущий прогон | Текущий |
|---|---:|---:|
| Строк перед аварией | 815 | 623 |
| Весь migration/crash-сценарий | 121,539 с | 75,600 с |
| После возврата из `start(A)` до сходимости | 87,015 с | 51,241 с |
| Page query ingress A → last part B, медиана | 447,612 мс (60) | 142,478 мс (42) |
| Last part B → next query ingress A, медиана | 591,077 мс (60) | 547,369 мс (42) |
| `myOtherDevices` census A / B после restart | 4303 / 5950 | 888 / 3737 |

Request/response сопоставлены по private request ID в общей clock domain
одного Mac. В обеих сериях исключён один ID с повторными query; учитываются
лишь полные, неповторённые ответы. Сами ID, тела и content witnesses
в публичные артефакты не включены. Census await пересекаются и не являются
исключительным wall time.

**Это не A/B/A:** точки аварии, число повторно кодируемых/применяемых строк,
кэши и scheduling различались. Кодирование A/B: 1899/784 → 1343/188 строк;
величину общего ускорения по этим двум запускам не доказываем. Удаление
31 лишнего чтения на полной текстовой странице доказано отдельно тестом.
Медиана ответа на страницу улучшилась в наблюдаемом прогоне, а следующий
крупный интервал — получение следующего запроса и обработка на получателе —
сохранился около половины секунды. Полная догрузка остаётся активной задачей.

## Границы и завершение

Не проверены этим прогоном мобильная смена сети, часы/сутки offline и все
стадии crash consistency. Нельзя переносить измерение JIT/loopback на AOT,
публичные маршруты или реальный телефон.

Driver и cleanup завершились с exit 0. Проверены 27 owned PID и 27 портов:
живых процессов/слушателей нет, одноразовые контейнеры и runtime directory
удалены. Все 1506 замороженных source/dependency inputs и native artifacts
сверены после прогона. SDK/HVS, реальные контейнеры, телефон и production
не менялись. Push/релиза нет.
