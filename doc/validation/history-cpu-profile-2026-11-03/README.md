# CPU-профиль миграции с настоящими процессами

2026-11-03. Это тестовый инструмент для следующего разбора задержек, не
оптимизация production-кода и не часть пользовательского debug-экспорта.

## Инструмент и проверки

`test/support/stand_cpu_profile.dart` использует локальный VM service. Опция
`XVEIL_E2E_CPU_PROFILE=1` добавляет `--enable-vmservice` процессам стенда.
Окно сбрасывается вместе со storage timing; если worker перезапущен при
adoption, его первый последующий storage inspect начинает новое окно.
Профиль сохраняется при штатном teardown в приватный evidence-каталог.
`device.stop` выполняется и при ошибке профилирования. По умолчанию профайлер
не включён; приложение и его diagnostic exporter этот helper не импортируют.

Контрольный `testWidgets` создаёт CPU-нагрузку и требует ненулевых сэмплов с
её функцией, а не просто успешного JSON-ответа:

```sh
TMPDIR=/private/tmp/ XVEIL_E2E_CPU_PROFILE=1 flutter test --no-pub \
  --enable-vmservice --reporter expanded test/native/stand_cpu_profile_test.dart
```

Первый стенд не был зачтён: `testWidgets` подменял HTTP-клиент ответом 400.
Обход тестовой подмены теперь ограничен клиентом loopback VM service, без
смены глобального HttpOverrides. Повторный widget-контроль прошёл. Неудачный
запуск завершился и очищен: 18 PIDs/26 портов, runtime-контейнеров нет. Это
сбой оснастки, не подтверждение дефекта мессенджера.

Сырые профили содержат служебные isolate/function metadata и пути. Они
остаются только в приватном каталоге синтетического стенда; здесь приведены
числа и имена статических функций, без IDs, адресов, секретов или raw profiles.
Никакие эти поля не добавлялись в пользовательские анонимные отчёты.

## Миграция 2000 сообщений

Три реальных процесса A/B/C, worker/HV и native-подписи, loopback-реле,
публичные seeds/discovery выключены. Production-код включает фильтр stale
`onlyTo`; во время прогона исходники зафиксированы. SDK/CLI/FFI намеренно
заморожены на ранее проверенном `eb644a83`, HV одинаков — последняя SDK
этой серией не квалифицируется.

Полная история сошлась за **46,442 с**, количество за 41,322 с, delivered
2000/2000, точные IDs/порядок/source positions совпали, завершённая история
не переотправлялась. Это один instrumented-прогон, без вывода об ускорении.

Профиль A покрывает окно **68,205 с**, которое включает link и teardown,
поэтому его нельзя приравнивать к migration timer. Главный isolate — 3618
сэмплов, HV-worker — 5273. В главном isolate следующие inclusive ticks:

| Функция | Inclusive ticks |
| --- | ---: |
| `_validMessageFor` | 1658 |
| `_postMessage` | 1329 |
| `_retainedMessageRows` | 1025 |
| `_messagesOfBundle` | 936 |
| `_canonicalRetainedMessageView` | 911 |
| `_acceptedMessageRows` | 845 |
| `_verdictKey` | 538 |
| `_messageChainScope` | 99 |

Строки перекрываются по стеку, их нельзя складывать, превращать в проценты
wall time или объявлять одной причиной всех 46 секунд. В worker также много
сэмплов в native `fcntl`; они не доказывают, какая операция/блокировка
составляет критический путь. Профиль подтверждает заметную повторную работу
в local authoring, но не обосновывает хранение авторизационного вердикта
между асинхронными операциями. Кандидат только на сокращение построения scope
имеет малую отдельную долю; сначала нужны интервалы порций/Outbox/I/O.

В этом запуске B перезапустился при adoption, и его окно оказалось лишь
2,972 с до миграции — **оно не считается профилем догрузки B**. После этого
исправлен старт нового окна на первом inspect нового worker.

## Контроль нового окна после adoption

Отдельная native-серия со 100 сообщениями, те же библиотеки и схема стенда:
все данные сошлись за 5,425 с, delivered 100/100, повторов нет. Это проверка
профайлера на перезапуске, не масштабирование результата 2000 строк.
Финальный B-профиль покрывает **8,079 с** после нового старта, содержит 281
сэмпл главного isolate, в том числе `_messagesOfBundle` и
`_canonicalRetainedMessageView`. Раннее окно старого процесса не выдаётся за
свидетельство работы нового.

Проверены выход всех собственных процессов и освобождение портов: 22/31 в
серии 2000, 23/32 в серии 100. Runtime-контейнеры удалены; 1394 frozen-файла
и native artifacts сверены до/после. Raw-профили и синтетические ключи не
публиковались. Телефон, Windows, публичные реле и пользовательские контейнеры
не менялись. Push/релиза нет.

Догрузка остаётся активной. Следующий шаг — разложение времени порции на
подготовку/commit/replication admission, ожидание room и явную pacing-паузу;
CPU-профиль не заменяет эту декомпозицию.
