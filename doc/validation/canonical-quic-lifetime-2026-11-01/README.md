# Завершение QUIC вместе с основной сессией

2026-11-01, SDK `cc908a50`. Продолжение
[разбора холодного подключения](../route-miss-queue-2026-11-01/README.md).
Исправлен подтверждённый дефект времени жизни транспорта. Это не доказательство
причины всех 58,690 с предыдущего подключения и не закрытие NETCALL-01.

## Подтверждённый механизм

У основной OVL1-сессии не было явного владельца закрытия QUIC. После отмены
handshake или завершения сессии сохранённые datagram/parallel-ссылки могли
удерживать соединение живым. Общий parallel watcher сам держит ссылку на
родителя и ждёт его закрытия; простого удаления основного byte stream
недостаточно. Удалённый узел мог продолжать считать прежнюю сессию активной.

Guard получает конкретный QUIC handle **до первого await**, включая чтение
входящего префикса. Отказ/отмена закрывают его; успешная OVL1-регистрация
передаёт guard в SessionGuard. При завершении закрывается именно это
соединение, до взятия node-state locks. Поиск текущего соединения по peer ID
не используется: поздний teardown старого владельца не должен закрывать замену.
Не-QUIC transport не меняется.

Проверенные handoff/parallel binding явно передают владение существующей
сессии и не закрываются admission-guard при раннем возврате. Авторизация,
дедупликация, reputation, таймауты и backoff не ослаблены; wire не изменён.

## Воспроизведение и регрессии

Все четыре сценария используют настоящий loopback QUIC и production
`register_connection_session`, без реле и внешней сети:

| Сценарий | Свидетель |
|---|---|
| Отмена исходящего OVL1 при молчащем собеседнике | QUIC bidi принят после настоящего HELLO; task удерживается ответом, затем abort/join; сохранённый handle должен быть закрыт |
| Завершение успешно зарегистрированной сессии | Настоящий OVL1 обмен; handle открыт при живой AttachedDebugSession и закрыт после её drop |
| Отмена при неполном входящем префиксе | Один байт передан; gate фиксирует первый poll чтения production peek до отмены; QUIC закрывается |
| Штатный handoff | Настоящий challenge-response; runtime возвращает adopted, соединение остаётся открытым, payload читается из swap-канала |

Первые два теста на исходном коде: **0 passed / 2 failed**. Дополнительный
входящий gate-тест провалился на промежуточном исправлении, где guard начинался
слишком поздно. Ошибки компиляции новых fixtures отдельно не считаются красным
воспроизведением. Финальный runtime-набор: **789 passed / 11 ignored**.
Промежуточный session-набор: **679 passed / 8 ignored**; session source не менялся.
Игноры не считаются прохождением. Временные ограничения тестов — deadlock guards,
а не критерий ускорения сети.

## Физическая проверка

Используется только прежний изолированный профиль Mac и два узла линии.
На Mac заменяется native SDK; frontend/AOT, media и hidden-volume прежние.
Тестовые серверы оставлены на SDK `4f9c85f2`; таким образом изменение клиента
проверяется отдельно, без одновременной замены серверов. Телефон/Windows,
мобильный handover и звонки в этой серии не проверяются.

До исправления четыре одиночных peer-снимка после native-ready появились через
0,053 / 0,588 / 11,728 / 0,575 с. Они **не квалифицируют устойчивую сессию**:
серверный журнал содержит быстрые закрытия, отказ duplicate и прежнюю сессию,
пережившую выход приложения. Полные 58,690 с на этом минимальном стенде не
воспроизведены. Сравнивать эти одиночные снимки с устойчивым гейтом кандидата
как измерение ускорения нельзя.

Кандидат дал следующие локальные наблюдения после `native-ready`:

| Запуск | Первый local ACTIVE snapshot | Local ACTIVE держится ≥3 с |
|---|---:|---:|
| 1 | 0,580 с | 3,838 с |
| 2 | 0,583 с | 31,105 с |
| 3 | 11,538 с | 19,195 с |
| 4 | 37,345 с | 40,641 с |

**Это не четыре подтверждённых двусторонних подключения.** Серверный журнал
не подтверждает каждый локальный гейт; местами локальный ACTIVE переживает
отказ/закрытие на сервере. Ни первый snapshot, ни удержание локального ACTIVE
три секунды не принимаются за end-to-end readiness. Transport identity Mac
не менялась между запусками. Два наблюдаемых серверных canonical-соединения
жили 36,037 / 36,553 с (open→close по часам одного сервера) и сохранялись после
остановки соответствующего приложения. Вывод об устранении холодной задержки
**опровергнут этой серией**; ускорение или регрессия общей задержки не доказаны,
поскольку исходная серия не квалифицировала устойчивость тем же оракулом.

Локальный журнал пишет `node.stop`, а затем teardown session. Следующий
участок — фактический порядок остановки embedded runtime/connector и успевает
ли транспорт передать close до остановки своего I/O. Само наличие позднего
`session.close` ещё не доказывает конкретную причину отсутствия remote close.
Исправление SessionGuard оставлено как отдельный доказанный механизм;
вся задержка подключения остаётся активной.

Результат и ограничения записаны в `result.json`. Все четыре процесса Mac
завершены, четыре собственных runtime-каталога удалены, QA P2P-policy возвращена
в allowAll. Все шесть тестовых служб остановлены и их порты освобождены;
production PID/binary/config сохранены 6/6. Временный debug-конфиг S1 восстановлен,
rollback timer остановлен. Нового push/релиза нет.
Бинарник сверяется по SHA после codesign; сборка использует отдельный внешний
Cargo target с проверкой mount и watchdog. Сырые логи, адреса, идентификаторы
соседей, токены и пути QA-контейнеров не включаются в публичный результат.
