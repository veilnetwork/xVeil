# Успешное соединение не должно отменять чужие handshake

2026-11-03. Локальное исправление в SDK, без push/релиза и установки на устройства.
NETCALL-01 остаётся открытым до повторной физической проверки.

## Подтверждённый механизм

`ConnectivityGain` сообщает, что исходящий handshake с одним узлом завершён:
обновляет внешний адрес и будит ожидающие повторы остальных соединений. Однако
он использовал тот же `force_reconnect_notify`, который connector слушает для
**отмены уже выполняющегося dial при смене локальной сети**. Поэтому первый
успех мог оборвать параллельные handshake к другим узлам. Это происходит и без
реальной смены сети; debounce лишь ограничивает частоту таких отмен.

Regression на настоящих `NodeRuntime`/`NodeServices` подписывается на штатный
сигнал отмены, вызывает production connectivity-gain hook и непосредственно
опрашивает future до/после события. Старый код доставил лишнюю отмену — тест
упал по этому условию. Нет предположения о скорости сети, scheduler yield или
elapsed-time порога. Это доказательство ошибочной проводки сигналов, не
причинная атрибуция всех секунд пользовательского mobile handover.

## Исправление

Connectivity-gain имеет собственное широковещательное уведомление только для
ожидающих retry/backoff. Все пять соответствующих ветвей connector слушают
оба повода проснуться. Незавершённый dial продолжает слушать прежний отдельный
force-reconnect сигнал; реальное событие сети по-прежнему его отменяет.

Сохранены debounce, backoff-reset, srflx permit, shutdown/endpoint-refresh,
ban/directional admission, протокол и C ABI. Уведомление одного участника не
меняет endpoint или криптографическое состояние других соединений.

Первый кандидат дополнительной async-обёртки мог потерять wake между созданием
future и первым poll. Это **пойманная регрессия кандидата**, не ещё один дефект
выпущенного приложения. Отдельный красный тест воспроизвёл её без таймеров.
Финальный вариант создаёт оба `Notified` сразу, до опроса внешнего select.

## Проверки и границы

- Полный runtime suite с `production-seeds`: **797 passed, 11 ignored**.
  Пропущенные не считаются пройденными.
- Новый wiring regression проверяет отсутствие лишней отмены, настоящий
  retry-wake и srflx-wake. Отдельный regression проверяет событие до первого poll.
- Существующий pending-transport fixture дополнен gain непосредственно перед
  настоящим `force_reconnect_all_peers`: старый dial отменяется, следующий
  начинается. Таймауты этого fixture — deadlock guards на виртуальных часах.
- `cargo check` встроенного FFI с `node-embedded,production-seeds,packet-tunnel`
  прошёл. Форматирование и diff-check чистые.

Сборки использовали прежний target того же checkout без dependency overrides.
Отдельная внешняя ФС проверялась до запуска и watchdog на всём протяжении;
потери mount не было. Происхождение test executable и исходников сохранено
по хешам в приватном proof, без публикации адресов/идентификаторов/логов.

Подключённый Android доступен по ADB, но SIM отсутствуют: физический переход
Wi-Fi → cellular в этом цикле не выполнен. Ни снижение паузы 12–20 с, ни
исправление NETCALL-01 целиком, ни устранение холодных QUIC-потерь не заявлены.
Реальная слышимость Poco ↔ Windows, большая история и multi-device матрица
статуса не меняют. Пользовательские приложения, сети телефона и реле не
менялись; тестовые runtime завершены вместе с test executable. Нового engine
pin, APK/DLL, обновления сидов, push или релиза не было.
