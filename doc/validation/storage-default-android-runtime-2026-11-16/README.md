# Android: три режима без opt-in и сохранность старого скрытого пространства

## Область проверки

Квалифицирован frozen source `a6afc7f1`: обычный `lib/main.dart`, Android ARM64
release/AOT, testnet, без debug hook. Это изолированные debug-signed QA APK,
а не опубликованный выпуск или замена основного приложения пользователя.

Три сборки: новый default без `XVEIL_MANAGED_STORAGE`, контроль с явным false
и обновляющий APK снова без определения флага. Проверены фактически переданные
Gradle/Dart definitions и product compile, не только команды сборщика.
Для каждого APK сверены 3047 source inputs, подпись, AOT без kernel/JIT,
asset routing, пять выбранных native strip-реконструкций и обе privacy-проверки.
Проверки повторены после основной runtime-серии, до изменений локализации.
Дополнительный wrong-password контроль использует сохранённый побайтно тот же APK.

## Новый обычный default

Полный штатный UI — без подмены controller/storage или скрытого QA API.
Сертификаты действительно сохранены через Android DocumentsUI; полный ID
сопоставлен с drawer, история — с реально введёнными уникальными заметками.

| Режим | Создание и открытие | Независимые проверки |
|---|---|---|
| Зашифрованный | Единственный выбранный default из трёх; пароль и подтверждение; тот же ID/заметка после cold-open | Один catalog entry, три data-role payload; неверный пароль не меняет их SHA |
| Незашифрованный | Явный выбор с предупреждением; без password step; passwordless cold-open | SQLite integrity OK, признак unencrypted и заметка читаются без ключа; encrypted sibling payloads неизменны |
| Скрытый | Явный выбор; прежний пароль после cold-open | В каталоге остаются только две видимые личности; неверный пароль сохраняет все пять data payload SHA |

Каждая история содержит собственную заметку ровно один раз, чужих заметок нет,
композер пустой, запрос на переписку с собой не появляется.

Штатная очистка encrypted и unencrypted завершилась с положительным Done,
без паролей других личностей. В первом случае побайтно сохранились четыре
sibling/hidden role files, во втором — шесть. После обеих очисток все три
личности повторно открылись с теми же ID и заметками. Малые fixtures не дают
оснований обещать экономию места или скорость очистки.

Это новая квалификация default-ON APK; более ранние
[all-mode QA проверки](../managed-storage-android-allmodes-aot-2026-11-16/README.md)
с явным opt-in не используются вместо неё.

## Контролируемое обновление существующего hidden

Legacy-контроль — тот же современный код/native inputs с явным
`XVEIL_MANAGED_STORAGE=false`, а не APK официального старого релиза.
Проверка доказывает переход маршрутизации/default; полная историческая
межверсионная матрица этим не заявляется.

1. Через настоящий legacy-мастер с двумя вариантами создано скрытое
   пространство, сохранён сертификат и введена заметка. Каталог managed
   отсутствует. Полный перезапуск с паролем сохранил ID и заметку.
2. После остановки процесса сохранены SHA контейнера, UID и независимая копия.
   Новый default APK установлен через in-place update того же QA package/signing,
   без uninstall, очистки данных или замены контейнера.
3. После установки и после запуска **до пароля** SHA контейнера и UID прежние.
4. Старый пароль в штатном UI открыл тот же полный ID и старую заметку.
   Новая заметка записана рядом с ней; ещё один полный перезапуск сохранил обе
   ровно по одному разу. Публичный catalog identity count остался нулевым.
5. Отдельный Mac/native reader прочитал копии до/после обновления без запуска
   узла: sovereign material непустой и тот же, ID старого сообщения сохранён,
   новая строка появляется только в after-копии. Обе строки имеют delivered.
   Нативный reader сверён по SHA, 50 UniFFI checksums и всем 145 Rust producer
   inputs. Копии после чтения сохранили исходные SHA; Android оригинал не открывался
   хостовым reader. Это один реальный cross-platform copy-read case, не power-loss.

Девять файлов трёх ранее созданных личностей другого QA package побайтно
сохранились на всём протяжении legacy-обновления.

## Уборка и границы

Оба QA приложения остановлены; группа процессов собственного headless AVD
завершена, порты освобождены. Четыре известные fixture-certificate exports
удалены только после совпадения SHA. Виртуальные тестовые профили сохранены;
реальные Mac/Android/Windows профили, production-сиды и пользовательский ввод
не затронуты. Окон/активации/перехвата фокуса не было.

После дополнительного виртуального reboot четыре ранее удалённых экспорта
снова оказались видимыми. Они совпали по SHA, были удалены повторно, затем
выполнен guest sync перед финальной остановкой. Причина повторного появления
не атрибутирована; это не app erase operation. Стойкое удаление exports через
ещё один reboot не заявляется. Весь этот AVD и его документы — только fixtures.

Три APK сохранены с прежними SHA и provenance, staging source snapshots и
native inputs оставлены. Удалены только их собственные generated build caches
суммарным du около 2,98 GiB и воспроизводимые strip outputs; shared caches
не чистились. Старые artifact paths ведут к сохранённым побайтным копиям.

Ошибки наблюдателей не засчитывались как сбои продукта: full ID мог быть
частью подписи drawer, заметка — частью bubble с временем. Проверены полные
токены, точная единственность и пустой composer, без пересоздания рабочих
личностей. Первый host-reader compile неверно ожидал nodeId у UserProfile;
исправленная проверка сравнивает непустой sovereign material и реальные IDs
строк. Проверка старой несовместимой host-библиотеки не засчитана как reader pass.

После frozen runtime-серии сокращён EN/RU/ES текст Start over: он больше не
утверждает, что пароль требуется любой личности, включая plaintext.
Он не входит в перечисленные APK; gen-l10n/analyzer и четыре существующих
start-over controls прошли отдельно на окончательных строках.

Новые native assets/API и финальные приложения ещё требуют согласованного
выпуска. Контрольный переход не квалифицирует все старые релизы, physical OEM,
все master/child/crash сценарии, исходный installer error HyperOS, звонки или
Windows-camera. Исправления handshake/desktop-alert из параллельной рабочей
ветки не входят в snapshot `a6afc7f1` и требуют интеграции перед финальной сборкой.
Push/релиза этим раундом нет.
