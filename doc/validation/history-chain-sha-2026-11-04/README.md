# SHA-256 цепочки при материализации истории — 2026-11-04

## Откуда взят участок

В предыдущем qualified recovery-window B выполнил 2335 свежих own-device
lookup. Их inclusive await — 35,75 с; сумма RPC меньше и не объясняет всю
обработку. При разборе найден повторный pure-Dart SHA-256 над canonical row
и подписью при проверке predecessor в подписанной групповой цепочке.
Все свежие journal/membership/revoke проверки необходимы и сохраняются.
Параллельное применение строк не выбрано: оно меняет гранулярность остановки
при отзыве. Точное происхождение всех оставшихся ожиданий ещё не установлено.

## Изменение

Существующий Veil `veil_sha256` уже используется для индекса cache вердиктов.
Его backend выделен в общий `Sha256Backend`, без изменения байтового
контракта; прежний VerificationCacheDigest сохраняет API и memoized handles.
GroupService с NativeGroupSigner применяет тот же primitive к свежим
`canonicalBytes || signature`. Domain `groupMessageHash` остаётся независимым
Dart-эталоном. Другие signer и хосты без primitive используют Dart SHA-256.

Это вычисление стандартного SHA-256, а не новый алгоритм или формат chain.
Ключи, подписи, документы, eligibility, ACL, свежий journal и retention не
кэшируются этой правкой. Mutable bytes хешируются заново. Native-копии
обнуляются в finally; authoritative state не переносится между чтениями.
Новых Rust ABI, wire fields, движков и изменений HVS нет.

## Проверка совпадения

- Оба backend сверены с независимым Dart SHA-256 на блочных границах,
  пустом вводе, NIST `abc`, разбиении на части и изменяемых входах.
- Protocol hash на canonical rows с подписями длиной 0/64/3400 совпал,
  включая изменение signature и NodeId bytes после первого вычисления.
  Большая синтетическая подпись проверяет digest, не hybrid-верификатор.
- Реальный NativeGroupSigner/GroupService прочитал цепочку из 64 строк,
  построенную прежним domain hash, и дописал ровно прежний commitment.
  Отдельная корректно подписанная строка с неверным predecessor не видна.
- Первый oracle нового native теста ошибочно выбирал последнюю строку
  временного порядка вместо конкретного дописанного сообщения. Oracle
  исправлен на выбор по body; это ошибка fixture, не дефект приложения.
- 533 group/history/sync проверки прошли; 3 skipped отдельно. Первый запуск
  ошибочно называл несуществующий group_crypto_test.dart и не зачтён как
  успешная команда; повтор использовал настоящий group_crypto_lookup_test.dart.
- Ещё 10 backend/cache/crypto/native проверок прошли; analyzer пяти файлов
  без замечаний. Полная Android/AOT квалификация здесь не выполняется.

## Компонентный A/B/A

Синтетический журнал 256 корректно подписанных и связанных строк, payload
512 символов; настоящий worker/HVS, NativeGroupSigner, 40 messagesOf после
одинакового warmup. Один неизменный контейнер, независимые процессы.

| Исходник приложения | Суммарное время 40 материализаций |
|---|---:|
| A1 — прежний | 441,130 мс |
| B — кандидат | 413,065 мс |
| A2 — прежний | 445,305 мс |

Для каждой фазы SHA контейнера одинаков до/после; все 256 body и каждый
prevHash сверены с независимым domain hash. Через VM getObject сверены полные
исходники исполняемого GroupService с выбранным checkout; selected lib
inputs заморожены. Библиотеки Veil/HVS одинаковы и проверены по SHA.
Изолированный baseline не строит Rust и не меняет dependency pins.

Предварительный primitive-control на 2000 хешей дал 86,756 → 22,788 →
88,967 мс при синтетической подписи 3400 байт. Он подтверждает цену операции,
но не оценивает весь путь. Итоговый journal-control выше использует реальные
64-байтовые Ed25519 signatures. Ни один timing не используется как test assert.

## Сквозная квалификация

На настоящем native A/B/C island B принудительно завершён при 1664
наблюдавшихся строках. После локального восстановления без A/C сохранены
1672, включая sparse late tail с provisional positions; prefix fallback
реально выполнен. Вернулся только A: все 2000 ID/порядок/source positions/
delivered сошлись. Completed-history retries — 0, invalid snapshots — 0.
Повторный запуск B без A/C сохранил точный результат.

После готовности A — **36,513 с**. Предыдущие 41,827 с не являются парным
контролем: тогда B сохранил 1583 строки, теперь 1672. Объём повторной обработки
отличается. Ускорение всей догрузки в процентах не устанавливается.

Qualified post-restart storage timeline: 12331 RPC/handler в закрытом окне
48,271 с из capture 48,636 с. Исключены только 139 крайних RPC и столько же
handlers; внутреннего пропуска нет. В нём commit — 568 вызовов, 9,971 с
inclusive await / 8,978 с handler; grouped read — 1344 вызова, 5,376 с await /
4,757 с handler. Эти суммы не являются pure I/O или эксклюзивным wall time.
Значительный остаток — durable commits и большой объём свежей обработки;
общий latency-дефект остаётся открытым. Другие captures не подменяют этот:
короткий setup прошёл отдельно, SIGKILL trace без close и короткий reopen
с несопоставленными spans отвергнуты и не используются для атрибуции.

Driver и teardown завершились с 0. Независимо проверены 31 PID, 42 порта,
удаление runtime и отсутствие оставшихся процессов/listeners. Все 1416
source/native inputs во время прогона неизменны. Производственные узлы и
устройства пользователя не использовались.

Первая подготовка standalone A/B/A harness требовала package_graph и
включения VM service; Isolate.resolvePackageUri оказался недоступен в
FlutterTester. Исправлен только harness, выбранные результаты получены с
проверкой реально скомпилированного исходника через VM. Эти ошибки не
объявляются дефектами приложения.

Mailbox собственных устройств остаётся выключенным по решению владельца.
При offline всех держателей истории нужен живой источник. Push, релиза,
изменений APK, пинов движков, сидов и production-реле нет.
