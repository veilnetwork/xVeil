# Прерывание догрузки 100000 сообщений внутри незавершённой страницы

## Задача и граница проверки

После [увеличения bounded page до 256 строк](../history-page256-100000-2026-11-10/README.md)
проверен следующий участок multi-device matrix: получатель уже записал часть
страницы, но ещё не продвинул её durable cursor. Процесс принудительно
завершается, оба источника выключаются, затем возвращается только один.

Production-код в этом цикле не менялся. В test-only стенд добавлены независимая
одноразовая остановка на выбранной синтетической строке и проверка точных
сохранённых курсоров до запуска сети. Выбор строки передаётся runtime environment,
без новых уникальных Dart defines/kernel entries. Существующий сценарий crash
до первого apply сохранён и выполнен повторно.

Четыре Mac/JIT процесса: A/B/E одной личности, C другой; три изолированных Core,
настоящие FFI, ratchet и hidden-volume storage. Архив полностью доступен A и E;
у B до начала есть одна прежняя строка. Начальные authenticated ответы обоих
источников получены целиком до разрешения apply. Это ответы первых страниц,
а не доставка всего архива до crash. Sibling mailbox не включён, production-реле
не используются. Полной копии архива в device journal источника нет.

## Детерминированный fault и oracle

Selected-row gate стоит перед подготовкой выбранной строки. При размере
публикации 64 и странице 256 выбор строки с индексом 50000 оставляет
**49984 архивных строки durable**, ещё одну прежнюю строку и незавершённую
страницу. Оба курсора прочитаны из storage; как минимум один строго отстаёт
от уже записанного prefix. Это проверяется assertion, а не выводится из
прошедшего времени. Gate не отпускается; B получает **SIGKILL, exit −9**.

После остановки A/E и до запуска сети B отдельный storage inspector проверяет:

- точные ID, body, delivered и ранее canonical positions всех 49985 строк;
- отсутствие пропусков, дублей и лишних строк;
- точное равенство обоих raw cursor values сохранённым перед crash.

Inspector закрывается до создания live storage owner. Raw cursor values,
ID и содержимое остаются только в приватном witness; наружу выводятся
числовые результаты сравнения. Отдельный offline snapshot подтверждает
тот же набор перед возвратом источника.

Затем запускается **только A**; E и C остаются offline. Получатель завершает
догрузку, сравниваются все 100000 архивных + 1 прежняя строка, включая итоговый
порядок. Новая сессия B содержит authenticated history parts именно от A;
успех не выводится только из счётчика строк. После остановки A/B выполняется
ещё одно холодное открытие B до сети: полный набор и оба сохранённых на этой
границе курсора снова совпадают. Для большого архива промежуточное наблюдение
компактное, каждые 5 с; полная проверка выполняется на контрольных границах.

## Результаты

| Сценарий | Архив | Записано до SIGKILL | Сохранено до сети | Итог после возврата A | Холодное сохранение |
|---|---:|---:|---:|---:|---:|
| До первого apply, smoke | 512 | 0 | 1 прежняя | 513 | 513 |
| Внутри страницы, smoke | 512 | 320 | 321, оба cursor совпали | 513 | 513, оба cursor совпали |
| Внутри страницы, полный | 100000 | 49984 | 49985, оба cursor совпали | 100001 | 100001, оба cursor совпали |

Все три native-сценария прошли. В полном: разрешение apply → selected gate
**72,755 с**; запуск единственного источника → полная сходимость **76,324 с**;
**4893 authenticated recovery parts**, history failures после restart **0**.
Общий runner wall time **295,152 с**, включая seed, несколько открытий,
остановок и проверки. Это один fault-прогон, не A/B и не новая оценка ускорения.

**34 helper/oracle checks passed / 0 skipped**, analyzer шести изменённых
Dart-файлов чист. Проверены отдельность первого/среднего gate, одноразовость,
ограниченная lease, retirement/stop, отсутствие данных в marker, отказ
некорректных индексов/путей и oracle, не принимающий пустое совпадение,
подменённые ID/body, дубли или регресс статуса за сохранность.

SIGKILL обрывает первый wire log: его footer/полнота не утверждаются. Начальные
полные authenticated ответы подтверждены live-наблюдением до crash, дальнейшее
получение — отдельным in-memory wire snapshot нового процесса. Старый оборванный
захват не объявляется полным или без потерь.

## Происхождение, уборка и остаток

Все три случая используют одинаковые **1532 frozen inputs** и одинаковые
проверенные native artifacts; реальные worker mappings сверены. Production
соответствует `e91e470a`, Rust не собирался. После каждого сценария проверены
owned процессы/порты: **43/58**, **46/61**, **48/67**; оставшихся процессов и
слушателей нет, synthetic runtime удалён, native artifacts не изменились.
Cache остался около **9,5 ГиБ / 92 entries**, свободно около **148 ГиБ**.
Приватные исходные журналы и witness в Git не добавлены. Push/релиза нет.

Подтверждено восстановление именно этой частично записанной страницы и
сохранность до сетевого ремонта. Новый production-дефект этим прогоном не
воспроизведён. Это не SIGKILL в выбранной native-инструкции fsync/ratchet/ACK
и не полная квалификация crash consistency. Android/AOT, длительный offline,
другие fault windows, revoke/split-brain и оставшаяся matrix требуют отдельных
проверок. Latency и NETCALL-01 остаются активными.
