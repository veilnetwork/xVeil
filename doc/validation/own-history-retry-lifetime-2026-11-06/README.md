# Повтор own-device history после восстановления связи

Агрегаты: [summary.json](summary.json).

## Подтверждённые механизмы

В прежнем `_MessagingOwnHistory.wake` присутствие авторизованного sibling
снимало cooldown, но `_begin` игнорировал уже существующий pull. Незавершённый
запрос продолжал ждать своей лестницы 2/4/8/16/30 с. Теперь сигнал будит
текущий запрос с теми же ID, query и durable cursor. Сохраняются минимум
2 с между попытками, предел шести попыток и 30-с throttle повторных presence.
Ранний сигнал переносит повтор на конец минимального интервала, не теряется
и не откладывает уже более ранний таймер.

Таймаут ожидания не отменяет Future отправки. Прежде очередной retry мог
начать новую отправку, пока старая ещё выполнялась; смена bindings/roster
теряла её учёт. Теперь кредит принадлежит завершению настоящего `_send`,
включая его ratchet persistence, а не истечению внешнего deadline. На sibling
разрешён один незавершённый request send; глобально — до 32. Освобождение
кредита продолжает только актуальный pull после обычных проверок допуска.
Старая подготовка, ещё не вызвавшая transport, может уступить место новой
binding/page; её позднее продолжение проверяет захваченные ID и binding.

Аналогичная ошибка была в ответах: после timeout slot `_serving` освобождался,
хотя отправка части ещё выполнялась. Он теперь занят до завершения Future.
Предел ответов также 32, отдельно от запросов: полный duplex сохраняется.
Это два независимых лимита, не общий потолок в 32 операции.

Если retry timer срабатывал во время readiness/expiry barrier, запрос мог
остаться без таймера: следующий `_begin` снова игнорировал существующий pull.
Теперь такая попытка помечается ожидающей и возобновляется при readiness.

Wire-формат, подписи, roster/provenance, отзыв, durable cursor и ratchet
барьеры не менялись. Mailbox для своих устройств не добавлялся. Внешний
deadline по-прежнему ограничивает ожидание; он не обещает отмену transport.
Навсегда незавершённая отправка удерживает свой ограниченный кредит.

## Детерминированные проверки

Десять тестов используют настоящий MessagingService и authenticated ingress,
виртуальные часы и управляемые transport Futures. Проверяются recovery
с сохранением query, минимальный интервал, readiness, таймаут запроса/ответа,
смена binding, оба глобальных лимита при смене roster и запрет отозванному
sibling. Ожидание реального времени не используется.

На точном исходном файле из `4e4038c4`: **8 assertion failures / 2 passed**,
без compile/load failures; candidate затем восстановлен побайтно.
Candidate: **139 passed** в четырёх связанных suites, включая десять новых;
analyzer — без замечаний.

Первая версия candidate дала отдельный отказ существующего теста: поиск
device ID старого владельца удерживал новую binding, хотя transport ещё
не запускался. Различение подготовки и начатой отправки это исправило.
Дополнительный тест поймал лишнюю немедленную отправку на startup presence;
исправление сохраняет исходный двухсекундный минимум. Эти промежуточные
версии не считаются прошедшими квалификацию.

## Native regression: 2000 сообщений

Три Mac/JIT процесса A/B/C, A/B одной личности, C другой; три loopback Core,
настоящие SDK/ratchet/HVS. Это provider fixture, не полный foreground
SessionPipeline, Android или мобильный провайдер.

- SDK `b9b88bb7`, HVS `eceb9158`; исходники SDK/HVS не менялись.
- Все 2000 сообщений у B: **32,737 с**; полное совпадение ID, порядка,
  канонических позиций и `delivered`: **38,065 с**.
- В промежуточном полном snapshot порядок/позиции ещё различались;
  последующий snapshot сошёлся. Проверка не остановилась на одном count.
- Дублей/потерь по итоговому oracle нет; повторов завершённой истории — 0.
- Offline/crash сценарии в этом migration-only прогоне **не выполнялись**.

Это проверка корректности, не A/B и не доказательство общего ускорения.
Прежнее ожидание около 13 с в partition и вся медленная догрузка этим
не объявляются объяснёнными или устранёнными.

SHA выбранных immutable библиотек/CLI проверены до и после стенда; OS mappings
подтвердили обе библиотеки в трёх рабочих процессах. Управляющий test host
их не загружает и не считался четвёртым клиентом. 1497 файлов исходников
и package inputs оставались неизменными во время прогона; CPU profile
содержит реальные samples. Сырые журналы, адреса и IDs остаются приватными.

Стенд завершён: проверены 22 PID / 34 порта, своих процессов/listeners нет,
runtime root удалён. Телефон отключён пользователем; production-реле и
пользовательские контейнеры не затрагивались. Push/релиза нет.
