# Эхо, фоновый шум и управление шумоподавлением

2026-11-02. Локальные исходники и сборки; push/релиза и установки пользователям нет.

## Подтверждённый механизм

Оба прямых Call-пути (direct/group) используют общий APM helper, который включал
только AGC2. Они обходят WebRtcVoiceEngine::ApplyOptions, а defaults WebRTC
оставляют AEC и NS выключенными. Render-reference при этом подключён:
AudioState → AudioTransportImpl::NeedMorePlayData → ProcessReverseAudioFrame;
захват проходит RecordedDataIsAvailable → ProcessAudioFrame → AudioSender.
Следовательно, для software AEC отсутствовала конфигурация, а не обратный PCM-путь.
Это подтверждённый пробел обработки звука, но не доказательство всей причины
конкретного пользовательского эха Poco/mobile ↔ Windows/Wi-Fi.

Теперь software AEC и NS включены по умолчанию. NS использует kHigh, как обычный
voice-путь закреплённого WebRTC. Прежние параметры AGC2 сохранены. Переключатель
«Шумоподавление» в аудионастройках звонка изменяет только NS; AEC остаётся включён.
Прямой и групповой движки принимают изменение без пересоздания RTP/ADM/capture.
Выбор сохраняется в зашифрованном контейнере локально для identity/device, не
в списке переносимых/синхронизируемых настроек. Отказ native или записи не
объявляется успехом; последовательные изменения сериализованы. Движок,
подключённый во время сохранения, получает текущий выбор и последующий rollback.

Поправлен прежний комментарий iOS: VoiceChat сам по себе не включает
AVAudioEngine voice processing. Здесь за software AEC отвечает Call APM.
[Контракт Apple](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/voicechat).

## Проверки

- **333 Flutter tests passed**, один финальный scoped запуск: настройки,
  контроллеры direct/group, call service, UI выбора устройств/группового звонка,
  анонимная диагностика. Analyzer: 11 изменённых файлов, замечаний нет.
- Два новых gate-теста подключения движка во время записи сначала упали на
  старой реализации; после исправления проходят и success, и rollback.
- **4 FFI checks passed**: две проверки с новой fixture-библиотекой и две без
  новых optional symbols. Проверены direct/group, native refusal, аргумент
  bool→int, вызовы после dispose; реальных устройств эта fixture не открывает.
- Реальный WebRTC/AudioTransportImpl, 10-мс PCM, синтезированный линейный
  акустический путь из фактически отрендеренного mono/stereo сигнала: прежняя
  конфигурация не подавляет эхо; новая даёт >90 dB подавления в этой идеальной
  модели. **Это не измерение эха в комнате или слышимой громкости на Windows.**
- Стационарный шум: NS уменьшает выходную энергию на 11,66 dB; runtime on/off/on
  — −55,92 / −43,53 / −55,10 dBFS. Near-only речь не заглушена. В double-talk
  корреляция с обработанной чистой речью 0,753 → 0,805, уровень −1,39 dB
  относительно near-only. Проверяются улучшение против старого AGC-only и
  отсутствие заглушения, **не MOS/разборчивость**. Сырая волна не служит oracle
  после фильтрации/AGC/NS. Пробный абсолютный порог 0,85 не прошёл и отброшен
  как не имеющий обоснования в контракте; этот запуск не засчитан как pass.
- Прежний quiet-speech/limiter/silence/noise smoke прошёл с новой APM-конфигурацией;
  bounded transient clipping проверяется прежними ограничениями, не заявляется
  полное отсутствие clipping при резком скачке громкости.
- Native direct/group C ABI smoke с fake ADM проверяет NS до/во время захвата,
  сохранение AEC/AGC, RTP-пакеты и отсутствие новых запусков recording/смены
  send-stream. Обычная macOS dylib отдельно собрана: оба NS-экспорта есть,
  test-hook экспортов нет. Хеши исходников/библиотек сохранены в private proof.
  Ни одна из этих проверок не является физическим звонком.

## Границы

Закреплённые платформенные engine-артефакты **ещё не пересобраны/не перепинены**;
изменения не объявляются установленными в приложение или исправленными у
пользователя. Перед выпуском нужен новый immutable pin всех целевых движков
с source-digest guard. Старые локальные diagnostic-библиотеки без NS API
по-прежнему могут принимать звук; попытка изменить NS у них возвращает отказ.

Нужна физическая проверка эха, шума, double-talk и слышимости Poco ↔ Windows.
Пропуски речи и handover-пауза остаются открытыми: увеличение packetization
без измерений не применялось. В коде есть 10-мс capture и адаптивный Opus
40/60 мс, а не единое фиксированное «окно 50 мс». Jitter/packetization этим
раундом не менялись. Сиды, сетевые политики и реальные контейнеры не тронуты;
тестовые процессы завершились, временные runner-каталоги удалены.
