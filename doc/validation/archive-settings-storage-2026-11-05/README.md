# Сохранённые настройки в оффлайн-архиве — 2026-11-05

База `1b69a23c`. Локальная работа без push/релиза, APK, engine pins,
изменений сидов, Rust/native ABI и mailbox для своих устройств.

## Подтверждение

В предыдущем цикле fixture с `nickname:claimed` не перенёс значение. Отдельные
проверки теперь подтвердили причину: Storage.settingsKeys по документированному
контракту перечисляет весь raw namespace (`set:*`, `file:*`, `conv_seq:*` и т.д.).
Экспортёр сравнивал эти ключи с логическими именами регистрации/allowlist и
передавал их без снятия префикса в getSetting. getSetting сам добавляет `set:`.
В результате сохранённые настройки не попадали ни в plan, ни в архив.

Четыре assertion-red на прежней библиотеке: preview и фактические записи
архива, каждый на обычном backend и настоящем worker/native HVS. Preview
показывал 0 вместо 2, архив не содержал ожидаемой transferable setting.
Это независимое воспроизведение, не приписывание старому пользовательскому
репорту о звонках. Библиотека HVS проверена по ранее закреплённому SHA;
checkout clean и source revision совпадает с её provenance.

Прежний round-trip double возвращал логические имена из settingsKeys и
потому не мог обнаружить ошибку. Он приведён к настоящему raw-key контракту.
Другие места использования API проверены по исходникам: диагностика,
сборщики мусора, reachability групп и sticker sync ожидают полные ключи.
Менять общий Storage API или HiddenVolumeStorage здесь было бы неверно.

## Исправление

Один внутренний reader экспортёра выбирает только `set:` keys и снимает
ровно один префикс. Им пользуются и preview, и фактический export. Существующие
allowlist и регистрация synced settings применяются к логическому имени;
правила импорта и действующие значения получателя не менялись. Повторный
импорт raw transferable setting не заменяет уже имеющееся значение.

Проверки содержат `set:set:nickname:claimed`, отдельные raw file/cursor keys,
локальную window setting и canaries ключевого/ratchet-состояния. Они не
становятся настройками архива. Префикс не снимается повторно. Тестовые raw
bookkeeping строки не являются квалификацией целостности файлового архива.

## Проверки и границы

round-trip, контактный policy archive, настоящий экран export, settings GC и
