# NETCALL-01: возвращённый Poco, три физических наблюдения

## Результат

**NETCALL-01 остаётся подтверждённым открытым дефектом.** Один звонок
самостоятельно завершился после смены сети; два последующих сохранились,
но в P2P-сценарии повторилась длительная пауза приёма. Изменений production-кода
по результатам этой серии нет. Таймауты, proof/consent gates и критерий
подтверждения нового маршрута не ослаблялись.

| Сценарий | Мобильная сеть | Итог |
|---|---|---|
| Первый звонок, P2P разрешён | Проверка остановилась раньше плановых 120 с | Mac завершил звонок: `origin=livenessTimeout`, `silence=21s` |
| Новый стенд, relay-only с начала звонка | 120 с, затем 45 с возврата Wi-Fi | Тот же звонок; epoch 1 на обоих концах; max observed native audio RX age 1153 / 2939 мс (Mac / Poco) |
| На том же новом стенде, второй звонок с P2P | 120 с, затем 45 с возврата Wi-Fi | Тот же звонок сохранился, но epoch 3 → 5 на обоих концах; max age 11844 / 5148 мс |

Последние два звонка имели отдельный подтверждённый двусторонний аудиоприём
на Wi-Fi до переключения. Первый был relay-only, второй действительно начал
с P2P на обоих клиентах. Во время каждого 120-с Cellular interval хост
опрашивал только Mac; Poco записывал состояние локально. Проверялись цифровые
счётчики RTP, **не слышимость речи человеком**. В третьем звонке по два снимка
каждого endpoint не содержали native counters во время пересоздания медиа;
они учтены отдельно, а не как нулевая пауза. Максимальный age — максимум
наблюдённых снимков; при смене epoch он не ограничивает полную длительность
перерыва сверху.

## Первый неудачный звонок

После отключения Wi-Fi Mac сначала переключился на relay и снова принимал
аудио: счётчик вырос с 203 до 255. Поэтому первоначальное промежуточное
предположение «после переключения приёма совсем не было» отвергнуто.
Затем приём остановился, локальный repair сменил epoch 1 → 3, после чего
нового аудио до завершения уже не было.

На обоих Core новые сессии телефона появились примерно за 1–2 с после
смены сети. Позже **оба Core** закрыли сессии телефона по keepalive timeout;
зафиксированы unacked probes и устаревший genuine RX. На Mac терминальный
журнал прямо указывает liveness timeout. Отбой телефона — последующая
очистка скрипта: телефонные часы отставали примерно на секунду, сравнение
сырых wall timestamps ошибочно меняло бы причинный порядок.

Частичная транспортная корреляция также опровергает полное отсутствие
входящих данных на Mac: 53 sampled `relay_send` телефона сопоставлены с
authenticated frame/dispatch на Mac и с RTP receive. Оставшиеся отправки
этим не объявляются одной доказанной потерей: начало source send, queue
admission и успешный flush не равны удалённой доставке. PCAP содержит новые
TCP-потоки с остановившимся ACK и повторной отправкой одних диапазонов;
полная связь их роли и срока жизни с конкретной сессией ещё не завершена.
Причина первого завершения не объявляется исправленной.

Перед этим звонком Mac пришлось перезапустить: первая копия приложения
раскрыла framework symlinks, и mapping guard остановил подготовку **до звонка**.
Копия заменена с сохранением symlinks, deep/strict signature и canonical AOT
mapping проверены. Возможное влияние предшествовавшей замены сессий отдельно
не исключалось. Поэтому выполнены два последующих контроля на новом стенде
с единственным запуском каждого клиента.

## Уточнённый участок паузы в P2P-контроле

Сопоставлены `media.rtp.cell(sealed)` → sealed-cell digest → Core opaque
dispatch/ordered record → authenticated RTP receive. Все идентификаторы,
диапазоны и корреляционные хеши остаются в приватном захвате.

Для Poco → Mac относительно окончания команды выключения Wi-Fi:

| Окно | RTP с непустым payload | Source path | Найдено в RTP receive Mac |
|---|---:|---|---:|
| −5…0 с | 41 | direct | 41 |
| 0…5 с | 39 | direct | 0 |
| 5…10 с | 43 | direct | 0 |
| 10…15 с | 34 | 20 direct + 14 relay | 9 |
| 15…20 с | 43 | relay | 43 |
| 20…25 с | 38 | relay | 38 |

Это counts RTP, **не уникальных cells, не обязательно человеческой речи**;
batch может содержать несколько RTP. Source path здесь — native source
attempt, не подтверждение wire send. Совпадение digest устанавливает
принадлежность захваченных байтов, но не причину отсутствующих пакетов.

На Poco ранний watchdog начал relay recovery примерно через 4 с. Подготовка
дошла до настройки feedback около 7,1 с, затем кандидат не прошёл проверку
доставки и был закрыт. Сохранился старый direct sender. После local rebuild
relay стал активен примерно на 14-й секунде; позже вернулся P2P с сохранением
уже нового engine. Mac перешёл на relay раньше Poco. Таким образом,
**неудачная квалификация кандидата и поздний выход из старого direct пути** —
конкретный следующий участок расследования. Причина отказа sealed echo
пока не доказана; один только штатный budget 600 мс не объявляется виновником.

## Происхождение и границы

Оба клиента исполняли полный profile AOT Dart `460d74e2`. До unlock проверены
runtime revision/digest/mode, на Mac — фактические canonical mappings и SHA
App.framework/FFI, на Android — SHA установленного APK. Замена kernel blob
не использовалась. В HEAD `b45a8f82` последующие изменения `lib/` относительно
этого AOT относятся только к group routing scan и own-history page size;
код звонков совпадает. Эта серия **не квалифицирует** новый размер history page
на Android.

SDK: Android `bbcd967a`, Mac `c8f4929b`, два временных Core `e974cebe`.
Два коммита поверх Core — диагностические TCP counters/gate, не функциональные
изменения восстановления сессий. Media/HV заморожены и проверены.

В последнем стенде fine TCP gate включён только на Poco: 100 мс / 180 с /
8192 rows на процесс, lease не продлевался между звонками. Во втором звонке
нельзя предполагать, что fine mode ещё действовал. Есть полные обычные native
и opaque/record захваты; trace-limit в журнале телефона не достигнут.
Это последовательные контроли с растущими кэшами и разными маршрутами,
**не A/B и не доказанное ускорение**. Одно место, один провайдер, без Windows.

## Завершение

Оба стенда остановлены. Проверены выход приложений/коллекторов/observers,
освобождение портов, восстановление исходного QA APK, SHA основного APK и
старого QA-контейнера, permissions, P2P policy, Wi-Fi/mobile settings и debug
properties. На двух серверах каждого стенда временные Core, конфиги, state,
runtime, captures и units удалены после копирования и проверки доказательств;
production PID/config/binary независимо совпали с исходными.

В публичных артефактах нет адресов, identity/device/call IDs, CID, RTP SSRC,
correlation digests, ключей, путей пользовательских контейнеров или сырых
журналов. Приватные захваты сохранены для дальнейшей атрибуции. Push/релиза нет.
