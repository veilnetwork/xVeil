# Мобильный baseline прервался до переключения сети

Продолжение [здорового контроля](../core-transit-reference-2026-11-07/README.md).
Poco / Android 16 с SIM, Mac, SDK `c6699c28`, прежний qualified QA AOT,
один изолированный testnet Core через obfs4/TCP 443. P2P denied. Production
service, конфиг и бинарник не менялись. Новые routing Dart-правки эта сборка
не содержит и не квалифицирует.

На этот раз TCP info trace включён явно: `VEIL_RT_TRACE=1` и
`RUST_LOG=warn,transport.tcp_trace=info`. Окружение, PID, binary SHA и точный
systemd invocation проверены. В финальном журнале **1207 TCP trace rows**,
из них **344 handshake rows**; лимит выборки не достигнут. Это устраняет
пробел наблюдения предыдущего раунда, но не означает успешную передачу.

## Что произошло

Оба сценария начинались на validated cellular. До команды включения Wi-Fi
требовался устойчивый приём на обоих концах. **Оба предусловия провалились;
переключение внутри звонка не выполнялось ни разу.**

- **Poco → Mac:** первоначально пять свежих срезов приёма с обоих концов
  получены. Затем Mac остановился на 97 принятых аудиопакетах, возраст
  последнего native RX достиг 10,825 с. Телефон продолжал наращивать TX и
  принимать звук. Отказ критерия нельзя объяснить одной тишиной микрофона:
  источник продолжал отправку payload. Где исчезли эти пакеты, пока не доказано.
  Скрипт завершил оба конца через diagnostic API; самопроизвольный отбой
  этого разговора не установлен.
- **Mac → Poco:** телефон получил предложение, сформировал answer и запустил
  аудио; Mac оставался в dialing и не запускал медиаприём. Свежий приём на
  обоих концах не появился. Mac завершился по ringTimeout, телефон — по
  пришедшей remote cancellation. Это недоставка подтверждения/сигнализации,
  а не доказанная проблема capture/playout и не handover.

Повторы старых сигналов видны в private trace. Счётчики разных media epochs
не складываются, сброс в -1 не принят за свежий приём. Слышимость человеком
не проверялась. [Анонимные агрегаты](summary.json).

## Что не удалось приписать звонку

PCAP целиком разобран до EOF: 15 523 packets / 168 flows, 110 fresh SYN.
Снимались только соединения QA-порта, без несвязанных исходящих HTTPS;
size/SHA проверены до удаления удалённого захвата. Snaplen 192 ограничивает
содержимое, сетевой захват остаётся приватным.

У одного TCP-соединения зафиксированы retransmissions, 53 727 queued bytes
и 43 956 notsent bytes, повторный payload не подтверждался. Но этот socket
появился **после отказа второго сценария**. Его нельзя считать причиной
остановки первого аудиопотока или недоставленного answer. Максимум измеренного
Core independent-FIFO wait в захвате — 498 мс; сам по себе он не объясняет
наблюдавшиеся секунды. Без связи конкретного сигнала/медиапакета с выбранным
каналом и соответствующим transport tuple причинная атрибуция остаётся открытой.

**NETCALL-01 открыт.** Плохой baseline теперь воспроизведён с рабочей TCP
инструментировкой; перенастройка громкости, увеличение аудиопакета или таймаута
не следуют из этих данных. Следующая проверка должна связать source admission,
прохождение Core и native callback Mac для остановившегося направления.

## Завершение стенда

1533 SDK inputs, 1480 frontend inputs и 19 harness inputs неизменны.
Свежий rollback APK, normal APK и старый QA-контейнер сверены по SHA;
network/stay-on/audio permission и actual/stored P2P восстановлены по readback.
Mac потребовал SIGKILL после grace; выход процесса и освобождение портов
проверены. Logcat/probe завершены. Собственные capture/Core services, unit,
runtime, конфиг и бинарник удалены; production PID/config/exe прежние.
App debug log вынесен из bundle, strict codesign повторно проверен.
Сырые журналы, адреса, идентификаторы и захват не опубликованы.
Push/релиза нет.
