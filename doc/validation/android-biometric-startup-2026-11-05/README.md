# Android: инициализация быстрого входа по отпечатку

## Подтверждённый механизм

На Poco с Android 16 отдельное QA-приложение с неизменённым
`QuickUnlockVault` воспроизвело отказ настройки. В native-журнале
`flutter_secure_storage` 10.3.4: `Algorithm changed detected`, затем отказ
инициализации из-за `migrateOnAlgorithmChange=false`. Та же версия зависимости
закреплена в опубликованной 0.13.94. Это подтверждённый механизм отказа новой
биометрической записи; исходный контейнер пользователя не открывался и не
менялся.

У нового namespace нет маркеров алгоритмов. Native factory предполагает
исторические RSA/PKCS1 + AES/CBC; целевая биометрическая конфигурация использует
AES-GCM. Быстрая ветка пропуска marker-less migration для биометрического ключа
не применяется: ему требуется аутентифицированный cipher. Запрет миграции
останавливал создание даже совершенно новой записи.

## Изменение

Только Android-хранилище биометрического секрета разрешает существующий путь
инициализации/миграции библиотеки. `enforceBiometrics=true`,
`strongBiometricOnly`, AES-GCM и `resetOnError=false` сохранены. Новый слот
по-прежнему получает собственный случайный namespace. Для пустого namespace
native-код не расшифровывает предполагаемые старые данные: он создаёт целевой
ключ и запрашивает аутентификацию с CryptoObject. Ошибка не включает сброс
данных или запасной вход по PIN. Хранилище графического ключа не менялось.

## Автоматические проверки

Новый MethodChannel regression test использует настоящий Dart adapter и
`QuickUnlockVault`; native-отказ воспроизводится моделью наблюдённого контракта.
Три случая красные до правки, зелёные после: первая запись; повторная настройка
с ротацией namespace и восстановлением секрета; отказ аутентификации без
публикации настроенного входа. Проверяются также целевые алгоритмы и строгая
биометрическая политика. Это не замена реальной Android KeyStore проверке.

Связанные suites: 75 passed, без skip. Scoped analyzer чистый. Публичный stand
`test/native/android_biometric_vault_probe.dart` использует реальный
`QuickUnlockVault`, LocalAuth и hidden-volume. Только отдельный debug package,
фиктивный пароль, собственный encrypted-контейнер и контрольная запись;
пользовательский контейнер не используется.

## Физическая проверка

Baseline APK воспроизвёл отказ и не опубликовал configured credential.
Candidate APK установлен; source SHA, точные plugin versions, HVS Dart/native
и SHA установленного APK проверены. Настоящий тестовый HVS-контейнер создан.
Независимый парольный контроль прошёл: неверный пароль отвергнут, верный открыл
тот же контейнер и прочитал контрольную запись.
Первая попытка candidate остановлена biometric lockout после неудачных касаний;
владелец снял его обычным системным unlock. Отказ ОС не обходился, enrollment
и PIN не менялись. Затем с настоящим отпечатком прошли:

| Проверка | Фактический результат |
|---|---|
| Настроить новый защищённый слот | `containerCreated=true`, `configured=true` |
| Полный force-stop и запуск с другим PID | Выход прежнего процесса проверен |
| Открыть после этого перезапуска | Точный пароль восстановлен; encrypted-контейнер открыт; marker прочитан |
| Повторное открытие в живом процессе | Успех; не выдано за холодный запуск |
| Открыть и отменить системный запрос | Пароль не восстановлен; контейнер не открыт |
| Пароль после отмены биометрии | Неверный отвергнут; верный прочитал marker |
| Удалить быстрый вход, снова force-stop/start | Настройка выключена; openSystem не возвращает пароль |

Владелец подтвердил оба системных запроса при холодном открытии: LocalAuth и
криптографический запрос native-хранилища. Пустой/устаревший result не считался
успехом: проверялись операция, явные boolean-поля и смена процесса. Прежний
неудачный configure и lockout не засчитаны как прохождение.

Исходные core-файлы byte-identical в приложении стенда; переписан только import
prefix отдельного entrypoint. Встроенный HVS ELF совпал с проверенным ранее
артефактом, HVS source/Dart SHA зафиксированы. Rust не пересобирался. После
проверки QA-процесс остановлен, отсутствие PID проверено, только собственный
probe package удалён вместе с фиктивным контейнером и его OS-хранилищем.
Временный UI dump на телефоне удалён; основной xVeil остаётся 0.13.94.

Сырые журналы, пути sandbox и идентификаторы остаются в локальном private cache.
В этом документе нет биометрических данных или пользовательских секретов.
Проверка на других OEM, изменение набора отпечатков и полный reboot телефона
не заявлены. Push/релиз и native pins в этом цикле не менялись.
