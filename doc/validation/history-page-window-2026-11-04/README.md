# Размер порции own-history — 2026-11-04

## Наблюдение и границы атрибуции

В предыдущем sparse crash/reconnect прогоне B выполнил 2777 свежих own-device
lookup. Завершённых RPC внутри этих контекстов: 8213 get, 4102 getBatch,
2051 readLogBatch и 2051 readLogGroups. Эти проверки читают актуальный журнал;
подмена их долгоживущим кэшем разрешений не выполняется.

Отдельный прогон с CPU profiler восстановил все 2000 ID/positions/delivered
и retained state, но **не прошёл полный sparse qualifier**: наблюдатель не
поймал поздний хвост за дырой после crash. Driver exit 1 не переименован в pass.
Его профиль используется только для локализации работы. Из 2379 samples main
isolate B 1234 находились внутри messagesOfBundle, 957 — внутри validMessageFor,
579 — canonicalBytes; worker имел 4516 samples, включая 2805 внутри commit и
1456 внутри readLogGroups. Это вложенные стеки, не независимые миллисекунды;
FFI samples также не раскладывают fsync/очередь на отдельные стадии. Один JSON
parse не объясняет всю задержку. CPU-профили остаются локальными и приватными.

Teardown этого профилирующего прогона проверил 34 PID и 54 порта: живых owned
процессов/listeners нет, runtime удалён; 1406 frozen inputs и native SHA прежние.
Граф обновлён AST-only; доказательства основаны на исходниках и runtime.
Private CPU-профили сжаты с проверкой обратной распаковки: 484 → 21 МБ,
без удаления нужного evidence и без публикации сырых данных.

## Проверяемое изменение

Порция коротких сообщений ограничивалась восемью строками даже при свободном
byte budget. Это повторяло запрос/ответ, snapshot и durable cursor чаще, чем
требовал прежний лимит в 128 КиБ. Message-page теперь содержит до **32 событий**.
Inventory (8 разговоров) и гранулярность prefix proofs не меняются.

Остаются прежними: 128-КиБ page, 64 части по 2048 байт, ограничения admission,
один outstanding request на sibling, budgets отдельных больших records и
полное durable-применение до продвижения курсора. Перед каждым событием,
после await apply и перед отправкой carrier проверяется актуальное устройство.
Смена binding/revoke/expiry, idempotency и prefix proofs не обходятся.
Mailbox для собственных устройств не используется.

## Контроли

- До изменения новый контроль 65 коротких сообщений требовал 3 запроса, но
  получал 9: настоящий красный результат, без порогов wall-clock.
- После: 3 запроса, ровно 65 применений, без ошибок.
- 33 допустимых события в одном принудительно поданном ответе отвергаются
  **до любого apply**, durable cursor остаётся прежним.
- Revoke во время применения двадцатой строки прекращает оставшуюся порцию;
  курсор всей порции не коммитится. Возврат из await по-прежнему проверяется.
- Restart после двух сохранённых порций продолжает с 64-й строки. Ошибка
  сохранения первой полной порции оставляет cursor null и безопасно повторяется.
- Prefix/gap/edit/delivery/provisional-position тесты сохраняют точные ID,
  позиции и содержимое. Ожидаемое число page requests обновлено под новую
  ёмкость; подтверждённый ранний prefix проверяется в реально собранном ответе.
- Byte-limited, escaped UTF-8, out-of-order/repeated parts, large record,
  admission, TTL и сохранность обычной доставки покрыты существующими тестами.

115 тестов history/device-sync/census прошли, analyzer двух файлов чистый.
Ранний запуск дополнительного boundary-контроля без найденного test name
не зачтён: затем контроль добавлен и выполнен, отдельно и в общей серии.

## Native qualification

Два прогона на неизменных исходниках и native SHA восстановили все 2000 ID,
порядок, source positions и delivered, без completed-history retries и invalid
snapshots. После повторного запуска без A/C результат сохранился в обоих.

Первый: после crash B удержал 1539 строк, но поздний хвост не наблюдался;
сходимость после A ready — 30,662 с. Его driver exit 1 **не зачтён** как полный
sparse-контроль. Teardown успешен (27 PID, 29 портов, runtime удалён).

Второй прошёл строгий driver (exit 0 / cleanup 0): SIGKILL при 1519 строках,
после восстановления B offline — 1542 строки, включая **95 поздних provisional
rows за дырой**. A/C offline при запуске B, затем возвращается только A.
Fallback-prefix запрос реально использован. Все 2000 строк сошлись и сохранились
без источников. Время после A ready — **41,020 с**. Teardown: 27 PID / 33 порта,
нет owned процессов/listeners, runtime удалён, 1406 frozen inputs и native SHA
не менялись.

Сравнение с предыдущим зачтённым прогоном на том же HVS, но без парного A/B:

|---|---:|---:|
| Строки B после crash | 1549 | 1542 |
| Поздние provisional rows за дырой | 85 | 95 |

Это наблюдения разных прогонов: обратная история, размер пропуска и объём
обработки различаются; причинный процент общего ускорения не выводится.
Снятие лишних round trips доказано отдельным 65-строчным red/green контролем.
В новой полной серии суммарный request→first part — 8,090 с, first→last part —
1,320 с, last part→next request — 24,901 с. Эти интервалы включают обработку,
I/O и транспорт; не складываются с inclusive contexts как независимые затраты.
Wire probe не потерял записей, 22 запроса сопоставились с 22 полными ответами.

Остаётся существенная работа внутри apply и актуальных проверок журнала:
629 history-apply на B — 8,679 с inclusive await; 1914 own-device lookup —
23,197 с inclusive await. Они могут перекрываться; разрешения не кэшируются.
Долгая догрузка **не объявляется полностью устранённой**.

## Ограничения

macOS/JIT stand не квалифицирует Android/AOT, длительный offline и всю
multi-device матрицу. Старыми клиентами этот увеличенный row cap может
отвергаться; совместимость старых версий исключена владельцем из активной
очереди. Native ABI этого изменения не касается. Push/релиза, изменения APK,
engine pins, публичных сидов или реле в цикле нет.
