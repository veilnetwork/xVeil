# Восстановление публикации истории звонков после сбоя

## Подтверждённый дефект

Локальный результат звонка сохранялся в контейнер, после чего callback
запускал отдельную фоновую публикацию в группу своих устройств. Завершение
процесса между этими действиями оставляло результат только на одном устройстве.
Обязательство повторить публикацию не сохранялось.

На исходном `541851ea` независимый процесс записал в настоящий контейнер
окончательную длительность **75 секунд**. После подтверждения записи родитель
завершил всю группу этого процесса через SIGKILL, до запуска publisher.
Обычный запуск A восстановил 75 секунд, но B и его групповой журнал оставались
с прежними **0 секунд** всё контрольное окно **45 секунд**.

Первый подготовительный прогон остановился раньше: запись B после привязки
не появилась на A за 120 секунд. Для проверки самой границы сбоя следующий
отрицательный контроль сначала подтвердил общую исходную запись после reconnect.
Этот подготовительный таймаут не используется как доказательство потери после
сбоя; это разные наблюдения.

### Отдельный дефект сразу после привязки

Прогон без дополнительного reconnect воспроизвёл первый таймаут и после
добавления очереди: событие было сохранено в группе B, но отсутствовало на A.
На A зафиксирован отказ проверки подписи B. Его локальный документ личности
уже содержал новую делегацию, а синхронный verifier продолжал использовать
закэшированную копию до привязки. Перечитывание по таймеру/следующему lookup
не спасало уже отброшенный и подтверждённый транспортом первый кадр.

Теперь link перечитывает канонический локальный документ **до** рассылки
membership snapshot; принятие обновления своего документа тоже освежает кэш.
Чтения упорядочены, поэтому запоздавший старый read не восстановит прежний
набор ключей поверх нового. Собственный документ по-прежнему берётся из
контейнера, а не заменяется документом, заявленным отправителем.

Повторный native прогон без перезапуска A принял первую запись нового B;
в нём также прошли online-публикация следующей ревизии, post-commit SIGKILL
и восстановление окончательного результата на обоих устройствах.

## Исправление

* Локальная ревизия и обязательство её публикации записываются одной транзакцией
  внутри hidden-volume. Используется префикс существующего settings namespace;
  новые namespace, файлы вне контейнера и сообщения в mailbox не добавлены.
* Сохраняется последнее обязательство для каждого звонка, включая результат,
  сразу вышедший за пределы видимого окна истории. Входящие зеркальные записи
  такого обязательства не создают.
* При запуске и после временной ошибки publisher повторяет передачу в локальный
  долговечный журнал группы устройств. После этого обычный механизм синхронизации
  доставляет событие другим устройствам.
* Удаление обязательства сравнивает токен точной сохранённой ревизии. Завершение
  старой отправки не стирает более новый результат, записанный во время ожидания.
* Проверка уже опубликованных результатов ждёт окончания групповой транзакции.
  Она не принимает незавершённую запись из рабочей копии batch за сохранённую.
  Будущие timestamps учитываются только для устранения повторной публикации;
  прежний временной барьер применения входящих событий сохраняется.
* Видимые записи старой версии однократно проверяются при обновлении. Маркер
  миграции ставится после сохранения всех обязательств; сокращение группового
  журнала позже не запускает повторную отправку всей истории при каждом boot.
* Повторная обработка ограничена страницами по 64 записи. Продолжение очереди
  сохраняет позицию между проходами: восемь неудачных страниц не блокируют
  следующие записи. Пустая очередь не вызывает повторную загрузку всего журнала.
* У несвязанной личности остаётся обычная ограниченная история для будущей
  привязки; бесконечная очередь без получателя не накапливается.
* Закрытие владельца останавливает таймер и ждёт уже допущенные операции.
  В диагностику записывается фиксированная ошибка без исходного текста
  исключения, контакта, ID звонка или пути контейнера.

## Проверки

| Сценарий | Результат |
| --- | --- |
| Первая запись свежепривязанного B, без перезапуска A | До обновления кэша отсутствовала на A за 120 с; после обновления принята |
| Native A/B — одна личность, C — другая; SIGKILL после локального commit | До исправления A=75, B=0; после исправления A=B=75, оба device fold также 75 |
| Повторный обычный запуск A | Окончательный результат сохранён, одна видимая строка звонка |
| Локальная запись B при одновременно online A/B | Окончательный результат доходит до A |
| Отказ journal append | Нет ни строки, ни отдельного обязательства публикации |
| Отказ группового commit | Обязательство не считается исполненным |
| Новая ревизия во время старой публикации | Старый ACK не стирает её; новая ревизия публикуется |
| 520 обязательств, первые восемь страниц не проходят | Следующий проход обрабатывает оставшиеся записи |
| Удаление личности | Удаляется и очередь публикации |

**331** выбранный Flutter/Dart тест прошёл: 300 регрессионных и 31 проверка
групп, делегаций, документов и границы commit.
`flutter analyze --no-pub`: **0 замечаний**.
Проверены также отсутствие эха зеркальных строк, сохранение очереди после
повторного открытия, повтор после отказа, дедупликация уже сохранённого события,
разовая миграция, остановка владельца и обезличенная диагностика.

Обычный Android arm64 debug APK собран с `lib/main.dart` и основным application
ID. В готовом APK найдены маркеры новой production-логики и не найдены тестовые
entry points. Все три native-библиотеки совпали с результатом штатного strip
текущих staged sources. Внешний build-диск оставался отдельной файловой системой.

## Границы

Native стенд проверяет настоящие независимые процессы, контейнеры, подписи и
синхронизацию группы. Результат звонка подаётся через существующий debug API и
test-only writer: звук и видео не запускаются. Новых production-переключателей
для имитации сбоя нет. Это не квалификация Windows 10, физического телефона,
качества речи/видео или всей матрицы из 63 сценариев.

Уже потерянную до обновления ревизию, которой больше нет ни в локальной
ограниченной истории, ни у доступного устройства, миграция восстановить не может.
Прежние пределы хранения и принятый компромисс live-only доставки своим
устройствам сохраняются.

После прогонов стендовые процессы и их группы завершены, временные контейнеры
удалены. Пользовательские приложения и их данные не открывались. APK на телефон
не устанавливался. SDK Veil и hidden-volume не изменялись; push, релиз и
обновление серверов не выполнялись. Исходный незакоммиченный каталог
`multi-device-2026-10-17` не менялся.

[summary.json](summary.json) содержит только результаты, счётчики и хеши ПО.
Сырые журналы, runtime-пути, адреса, ключи и идентификаторы остаются вне репозитория.
