# Первые TCP-данные после смены сети не наблюдаются на Core

Разбор сохранённого [handover-захвата](../child-pressure-2026-11-07/README.md).
Новых звонков в этом раунде нет: Poco сейчас не виден ADB. Core был на SDK
`97dc1295`, оба клиента — на `c6699c28`; код и исходный захват не менялись.
NETCALL-01 остаётся открытым. Новое доказательство относится к **неудачным
переподключениям**, а не устанавливает причину первоначальной потери медиапотока.

## Сопоставление

Все 35 socket observations телефона после Cellular → Wi-Fi имеют ровно один
кандидат во **всём** PCAP по наблюдаемому исходному порту; повторного использования
такого порта в захвате нет. Каждому соответствует ровно одно серверное handshake
observation того же flow. Один наблюдаемый адрес телефона; raw tuples/ports/IDs
приватны. Никакой remap NAT или совпадение только по времени не предполагается.
У 11 успешных handshake количество прочитанных/записанных байтов взаимно
совпадает на обеих сторонах. Это дополнительный контроль соответствия.

| Исход на телефоне | TCP sockets | Наблюдение на Core |
|---|---:|---|
| Obfs4 handshake завершён, socket выбран | 11 | Handshake завершён, payload есть в PCAP |
| Handshake не завершён, socket закрыт | 22 | Прочитано 0 байт; TCP payload в PCAP отсутствует |
| К концу телефонного наблюдения исход ещё неизвестен | 2 | Прочитано 0 байт; TCP payload в PCAP отсутствует |

`incomplete` само по себе не различает отмену, ошибку и timeout. Именно три
повторных dial после canonical-close сопоставлены с их deadline: каждый имел
primary + delayed backup, всего **6 TCP sockets**. На Core нет payload ни одного
из шести; это три попытки подключения, а не шесть независимых retry-бюджетов.
Последние два незавершённых клиентских socket не объявлены timed out.

На всех 22 закрытых неуспешных клиентских socket:

- положительное число bytes принято локальным TCP; ровно столько осталось
  в очереди неподтверждённых данных;
- `notsent_bytes=0`, `unacked_packets=1`, retransmission counter 2–5;
- серверный handshake прочитал 0 байт, а PCAP не содержит ни одного client
  payload packet для соответствующего TCP flow.

То есть это не только молчание прикладного reader на Core: первые байты не
наблюдаются уже в интерфейсном захвате сервера. Счётчики Android доказывают
локальное принятие и неподтверждённую передачу, **не физический выход через NIC**.
Где именно байты исчезают — стек/драйвер телефона, Wi-Fi/NAT/маршрут или другое
оборудование — эти данные не устанавливают. DPI и провайдер причиной не названы.

11 успешных socket не доказывают пригодность canonical session в конце вызова:
обфускационное рукопожатие ещё не означает доставку медиа и включает отдельные
вспомогательные подключения. Определять роль socket только по его успеху нельзя.

## Проверка самого разбора

Независимый `tcpdump -nn -tt -r` с tuple filter подтвердил число пакетов и
наличие/отсутствие payload во всех **35 flows**, без временного фильтра,
который мог бы скрыть повтор порта. Анализ отвергает пустые observations,
отсутствующий flow, неоднозначный порт и повтор socket observation.
PCAP и Core journal проверены против сохранённых исходных SHA; все входы
неизменны после анализа. PCAP покрывает период от −316,761 до +92,518 с
от команды Wi-Fi; последний серверный handshake result — около +64,129 с.
Захват сообщает 0 kernel drops; это не обещание отсутствия любых потерь захвата.
Raw packet bytes, адреса, порты, ключи, IDs и SHA остаются приватными.

[Анонимные агрегаты](summary.json) содержат только счётчики и границы вывода.

## Следующий контроль

Подготовлены конфигурации **двух независимых Core**, соединённых только между
собой, без общего discovery/PEX/compiled-in seeds. Read-only preflight на
серверах подтвердил работающий production и свободные QA-порты/ресурсы.
Перед фактическим стартом preflight надо повторить; также нужны native config
validation и проверка, что прежние QA-идентичности не используются живым стендом.

QA APK подготовлен с двумя seed entries. Побайтово проверено, что кроме двух
bootstrap assets frontend/AOT, все native ZIP payloads и прочие несигнатурные
данные неизменны; signer совпадает. Native SDK не пересобирался. Это подготовка
контрольного эксперимента на прежних клиентах, не квалификация новой SDK.
APK на телефон не устанавливался, Core не развёрнуты, production не менялся.

Цель: при готовом исходном звонке и P2P denied повторить переход и проверить
восстановление реального RX через второй Core. Один Core в прежнем опыте не
позволяет судить о production failover. До этого дефект не закрывается;
таймауты, размер аудиопакетов и защита handoff не менялись. Последний требует
подтверждения через основной канал; разрешение same-URI warm probe само по
себе не устраняет потерю основного канала и здесь не включалось.
Push/релиза нет; в этом раунде удалённых QA-процессов не запускалось.
