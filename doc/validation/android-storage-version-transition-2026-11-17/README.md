# Android: прежний контейнер и tagged hidden-volume 2.8.0

## Что проверено

В отдельном ARM64 Android 14/API 34 эмуляторе установлен официальный предыдущий
стабильный APK xVeil **0.13.101**. SHA установленного APK и извлечённой storage
библиотеки сопоставлены с проверенным исходным APK. Компонент hidden-volume
2.8.0 скачан из Android ARM64 артефакта tagged CI `44137568864`, artifact
`14353481265`, source `8f8fc35103a2457f53a2bfb042b3fa39ff70b6a6`.
Проверены размер/SHA архива GitHub, ARM64 ELF и все 50 текущих UniFFI checksums.
Это самостоятельный компонент тега, а не библиотека из ещё собирающегося APK.

Гостевой C-reader использует фактические UniFFI entrypoints и общие layouts
из generated FFI header. Каждый method получает собственный clone handle;
base handle и выходные RustBuffer освобождаются. Создание, чтение, запись
и повторное открытие выполняются отдельными процессами без UI и app hooks.
Данные и пароли — только синтетические fixtures в собственном эмуляторе.

| Этап | Результат |
|---|---|
| Создание прежней библиотекой из установленного 0.13.101 | Два параллельных hidden-пространства с разными паролями; один и тот же KV key содержит разные точные payload |
| Открытие tagged 2.8.0 | Оба прежних payload прочитаны побайтно; SHA контейнера до/после чтения совпал |
| Запись tagged 2.8.0 | В каждое пространство записан отдельный новый payload; прежние сохранены |
| Новый процесс с tagged 2.8.0 | Все четыре payload прочитаны побайтно, без смешения пространств; SHA не изменился от чтения |
| Неверный третий пароль | Отказ открытия во всех проверяющих фазах |

Обычный constructor сохраняет legacy hidden padding; для fixture использован
Argon default, а не test-min. Проверка нового explicit-padding API отдельно
присутствует в 50-method ABI inventory. Сам по себе ABI inventory не заменяет
перечисленные операции с сохранёнными байтами.

## Границы

Это проверка совместимости хранения **2.7.2 из прежнего APK → tagged 2.8.0**
в выбранном двухпространственном сценарии, а не прохождение полной миграции
личности через UI. Новый xVeil APK ещё требует независимой установки, проверки
всех извлечённых native bytes и запуска AOT. Этот контроль не закрывает исходную
жалобу о двух переставших работать паролях, power-loss, сжатие или всю
master/child/multi-device матрицу.

Использованы отдельный loopback ADB и только guest filesystem; физическим
телефонам команды не посылались. Камера/микрофон эмулятора отключены, окна
хоста не открывались. После последующих update/fresh-install проверок весь
собственный install-стенд завершён: emulator/ADB вышли, порты закрыты, временный
AVD/образ с fixtures удалён. [Итог выпуска и границы](../release-0.13.102-2026-11-17/README.md).
