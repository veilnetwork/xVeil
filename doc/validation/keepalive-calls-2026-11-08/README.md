# Keepalive/FIFO: физическая проверка Poco ↔ Mac

SDK **`04584523`** проверен на обоих клиентах и двух изолированных QA Core.
Исправление [собственной пробы в нейтральной FIFO](../keepalive-neutral-2026-11-08/README.md)
прошло физический smoke, но **NETCALL-01 не закрыт**. В этой серии прежнего
накопления перед выбором отправки на Core не наблюдалось; остались паузы
приёма, включая одно неуспешное финальное окно. Ускорение по сравнению
с предыдущими сериями причинно не доказано: это не A/B.

## Сборки и условия

- Android/aarch64, macOS/arm64 FFI и Linux/x86_64-musl Core собраны из одного
  неизменённого SDK `04584523`. Проверены HEAD и SHA 1109 файлов исходников
  и конфигурации до/после сборок и испытания.
- Обе FFI собраны в release с флагами приложения
  `allow-empty-seeds,node-embedded,packet-tunnel`. Android ABI сохранил 208
  экспортов и 16-КиБ выравнивание. В QA APK изменена только FFI: AOT,
  media engine, hidden-volume, seeds и signer проверены отдельно.
- Mac использовал прежнее стендовое приложение с внешней новой FFI;
  проверены SHA после codesign, подпись и фактически отображённая процессом
  библиотека. Это не квалификация всех накопленных frontend-изменений.
- Оба QA Core исполняли один проверенный ELF без динамического загрузчика,
  с отдельными identity/unit/state и проверенными binary/config SHA.
  Они знали только друг друга и клиентов стенда: builtin discovery,
  bootstrap и PEX отключены; own advertise проверен для каждого Core.
- Poco X6 5G, Android 16, SIM и Wi-Fi; отдельный известный QA-профиль.
  Неизвестный прежний корневой QA-контейнер не открывался и не изменялся.
  Windows в серии не участвовала.
- P2P запрещён, наблюдаемые активные media samples — relay. Два отдельных
  звонка с телефона, в каждом Wi-Fi → Cellular → Wi-Fi, по 60 с наблюдения
  после каждого переключения. Первый Wi-Fi baseline — 35 с, второй — 20 с.
  Harness и условия зафиксированы до старта, после результата не менялись.

Микрофоны работали с окружающим звуком/DTX. Человеческая слышимость,
непрерывная речь, AEC, шумоподавление и mouth-to-ear задержка не проверены.

## Все результаты, включая неуспешный

Финальный критерий сохранён: последние пять native RX ages каждого конца
не старше 1000 мс, RX counter продвинулся, call/process прежний,
целевая сеть validated, media relay. Промежуточные паузы учитываются отдельно
от этого критерия. **5/6 окон passed; первое Cellular-окно — failed**:
свежесть не выполнена на обоих концах, хотя счётчики продолжали расти.
Окно не заменялось дополнительной успешной попыткой.

| Звонок / этап | Максимум native RX age Poco, мс | Mac, мс | Финальное окно |
|---|---:|---:|---|
| 1: Wi-Fi baseline | 374 | 367 | passed |
| 1: Wi-Fi → Cellular | 1781 | 2114 | **failed** |
| 1: Cellular → Wi-Fi | 958 | 1508 | passed |
| 2: Wi-Fi baseline | 354 | 373 | passed |
| 2: Wi-Fi → Cellular | 1328 | 1406 | passed |
| 2: Cellular → Wi-Fi | 362 | 365 | passed |

На первом Cellular-этапе RX counter Poco стоял не менее **1579 мс**,
при Mac native TX **+4** в строго внутреннем интервале. Независимый
телефонный collector дал два внутренних среза с тем же неизменным RX counter.
На Mac два интервала неподвижного RX — **1565/1583 мс**; локальные срезы Poco
внутри каждого независимо подтвердили рост native TX **+4**. Host-срезы
видели +3/+2: это разные времена выборок, а не расхождение самих счётчиков.

Это подтверждает остаточные паузы при выдаче пакетов источником, но не
измеряет слышимую тишину или непрерывную речь. Native age тоже нельзя
автоматически считать временем отсутствия речи. Телефонный collector:
**619/619** HTTP-срезов успешны, максимальное время запроса 410 мс,
максимальный интервал начала выборок 1140 мс. ADB/host polling не является
единственным источником наблюдения пауз.

## Привязка конкретных RTP-клеток

Operator trace сопоставлен по полной SHA непрозрачной клетки и RTP headers
после аутентификации получателем. Эти метаданные остаются только в private
артефактах. Эпоха сама по себе не используется как признак audio RTP.

| Направление | Source payload-RTP cells | Core ingress | Core selection к получателю | Полная received-cell SHA + authenticated RTP |
|---|---:|---:|---:|---:|
| Poco → Mac | 2363 | 2319 | 2319 | 2319 |
| Mac → Poco | 3223 | 3223 | 3223 | 3139 |

Для Poco → Mac совпадают **сами наборы** ingress/selection/receipt,
а не только их размеры. Из оставшихся 44 клеток ни одна не наблюдалась
на Core ingress: у 24 нет relay-queued witness, у 20 он есть. Admission
источником не доказывает приём NIC, прохождение отдельной transport copy
или потерю на проводе.

Для Mac → Poco все 3223 клетки имеют Core ingress и selection к телефону.
У 83 нет RTP receipt witness. Ещё у одной совпали RTP headers, но отсутствует
полная received-cell SHA; она **исключена из строгого receipt-набора**.
Таким образом, разница 3223−3139 не объявляется 84 доказанными потерями.
`transport_selected` тоже не означает успешную отправку handle, NIC egress
или получение другой стороной.

### Что теперь известно об ожиданиях

В полных журналах обоих Core **0 `independent_fifo_wait`**; trace limit и
обрезания journal tail не зафиксированы. В предыдущем захвате были клетки
с ingress без наблюдаемого selection; в текущем все наблюдаемые ingress
обоих направлений имеют selection. Это отрицательный результат новой серии,
не причинная A/B-атрибуция прежнего накопления Keepalive-исправлению.

По часам каждого Core отдельно, для сопоставленных пар direct-source ingress
→ target selection медианы **0,140–0,168 мс**, максимальное наблюдаемое
ожидание **4,214 мс**. Число пар по двум направлениям/двум Core:
2264/3196 и 2291/3223. Это время участка внутри Core, не всего маршрута
и не каждой дублированной transport copy.

На Poco sealing → send pump максимум 1,044 мс; → IPC socket-written
1,463 мс; → daemon-read 7,931 мс; → handler-enter 7,970 мс;
→ relay-queued 8,006 мс. Покрытие разное: 2363/2363/2363/2362/2339
клеток соответственно; пропуски witness не подменяются нулевым временем.
Для сопоставленных Poco → Mac клеток, с отдельно измеренной неопределённостью
часов, наиболее медленная sealing → authenticated RTP receipt —
**2130–2171 мс**. Это не RTT и не mouth-to-ear.

Полного разложения приёмной IPC-ветки пока нет: daemon/SDK age наблюдался
только у **44/2319** строгих Poco → Mac receipts и **59/3139** Mac → Poco;
у остальных значение неизвестно. Daemon queue age неизвестен для всех этих
receipts. Небольшие времена у покрытой части не исключают локальное
ожидание у непокрытой. На Core не наблюдались `read_timeout` и
`partial_record_expired`; новое ограничение сборки record не объявляется
причиной изменения результата.

## Следующий участок и статус

**NETCALL-01 остаётся подтверждённым активным дефектом.** Прежние 8,6/2,7 с
в этой серии не повторились, но паузы порядка 1,6 с и неуспешное финальное
окно не позволяют закрыть случай.

Следующий захват должен связать конкретную клетку после `transport_selected`
с выбранным child/очередью, фактической попыткой записи и приёмом до
dispatcher. Отдельно нужно закрыть пробел timestamps приёмной IPC-ветки.
У исходящих Poco-клеток без Core ingress остаётся симметричный участок после
локального admission и до наблюдаемого dispatcher. Новые таймауты, изменение
neutral FIFO/приоритетов или отключение проверок без воспроизведения
конкретного механизма по этим результатам не вводились.

## Восстановление и артефакты

Сборки контролировали отдельный внешний filesystem target и свободное место.
Проверены 28 хешей исходного harness и 26 хешей capture harness; private
manifest фиксирует 200 файлов наблюдений/анализаторов и SHA. В старом
унаследованном summary-helper строка `arm` осталась `record-read-candidate`;
она не используется как доказательство версии: SDK определяется immutable
build/source/proc/library provenance. Raw capture/harness не переписывались.

Звонки, collectors и observer завершены, их точные процессы проверены.
Mac потребовал SIGKILL после grace; это зафиксировано, штатный graceful exit
не объявляется. Собственный runtime и app debug log убраны, подпись Mac
повторно проверена. Телефонные collector directories/keys удалены.

Восстановлены QA APK, microphone permission, sampling property, P2P,
настройки питания и исходная validated сеть. Хеши обычного и QA APK,
а также неизвестного корневого QA-контейнера совпали с исходными.
Свои forwards/порты освобождены. Оба QA Core полностью убраны; независимый
повторный preflight подтвердил прежние production PID/restart counts,
binary/config SHA и отсутствие тестовых unit/state/портов.

В публичном отчёте нет ID, адресов, портов, токенов, RTP metadata и сырых
хешей захвата. Anonymous export не расширялся. Source-код в этом раунде
не изменён; push/релиза и sibling mailbox нет.
