# R30: проверка находок и подготовка релиза

Исходная точка: xVeil `1f9ab27d`, Veil `c46d94db`, hidden-volume `1ea2366`.
Отчёт проверяется по действующему коду; повторение утверждения в нескольких
итерациях аудита само по себе не считается подтверждением.

## Проверка медиадвижков перед выпуском

На исходной ревизии `ENGINE_RELEASE` указывал на [engine-2026.10.25](https://github.com/veilnetwork/xVeil/releases/tag/engine-2026.10.25). Все семь sidecar-записей
проверены: это исходники Veil `351647d2`, отличающиеся от текущих тремя native
файлами. Среди отсутствующих изменений — результат управления микрофоном,
проверка недоступного audio device module и диагностические полосы уровней.
Совпадение exported ABI не проверяет реализацию этих функций.

Производители Linux/Android/Windows теперь записывают SHA-256 дерева `src`
медиаплагина (имена + байты файлов, LF-нормализация); все три release-consumer
ветки сверяют его отдельно от binary SHA/символов. Старый sidecar без поля
отклоняется. Следующий engine release должен быть новым immutable pin,
собранным из текущего submodule; переупаковка старого бинарника не подходит.
Дополнительно восстановлено дерево native source из зафиксированной старой
ревизии: даже с добавленным корректным полем digest guard отвергает старые
исходники при сравнении с текущими. Это проверка содержания, а не только наличия
нового поля. Итоговый pin — опубликованный технический prerelease
[engine-2026.10.31.2](https://github.com/veilnetwork/xVeil/releases/tag/engine-2026.10.31.2);
его проверки описаны в дополнении и итогах ниже.

## Дополнение: обязательные проверки перед публикацией

Релизные проверки обнаружили две гонки multi-device. Редактирование возвращало
управление до durable публикации в журнал устройств; немедленное закрытие
прерывало публикацию. Теперь локальная операция и ACK входящего редактирования
ждут локальной записи. Удаление могло вызвать закрытый publisher, заменённый
за время commit: durable намерение теперь остаётся для повтора текущей привязкой.
Оба дефекта воспроизведены красными регрессиями до исправлений.

На текущем дереве **138 целевых тестов прошли**, analyzer чистый. Нативные
case 3/8 и case 20 прошли отдельно (38,498 и 62,489 с). Во втором сценарии
проверяется durable редактирование до отключения A, затем удаление на B и
сходимость после reconnect. Это три нативных узла на одном Mac, не физическая
Windows/Android-квалификация. После прогонов собственных процессов узлов нет.

Oracle стенда исправлен отдельно: sovereign device message log является
compactable LWW state, а не плотной числовой цепочкой. Его доверенный manifest
задаёт эту семантику; дубли и разрывы control-цепочек по-прежнему запрещены.
Сценарии дополнительно требуют полный ожидаемый набор ID, включая исходную
историю: одинаковая потеря строки на обоих устройствах не считается сходимостью.

Семь медиадвижков пересобраны и проверены под новым immutable pin
`engine-2026.10.31.2`: binary SHA, native source digest и exports/архитектура.
Первый engine pin этого дня оставлен как superseded prerelease: проверка
поймала платформенно-зависимую сортировку имён исходников в digest. Сортировка
теперь основана на относительных POSIX-строках, отдельная регрессия прошла.
Это build inputs; выпуск xVeil 0.13.94 по-прежнему следует после Veil 0.11.47.

Veil обновлён до `f20ebf28`: локальный runtime/dispatcher/DHT — **1276 passed,

аудита чистые. Проверяются libz-sys 1.1.31 и zstd-sys 2.1.2 без audit exceptions;

Теги Veil/app на момент этого дополнения ещё не опубликованы: source CI и

На xVeil `d5ba77e8` полный CI прошёл: **6763 passed, 222 skipped**,

Полный Veil CI на `f20ebf28` дал **7037 passed / 1 failed / 48 skipped**.
Единственный отказ — предусловие sim-теста explicit K-closest replication:
документ самой работающей личности уже автоматически находился у всех пяти
