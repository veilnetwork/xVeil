# Отложенное удаление и offline sibling — 24 октября 2026

База `decdaabf`, продолжение пунктов 19/20 и 62/63 multi-device матрицы.
Найден самостоятельный пропуск: peer delete, пришедший раньше сообщения,
применялся локально, но не вызывал `onMessageDeleted`. `_store` уже сохранял
оригинальный `msgMirror`, поэтому второе наше устройство могло получить из
device journal исходное сообщение без соответствующего `msgGone`.

## Подтверждение на native стенде

A и B принадлежат X, C — Y. Три настоящих встроенных узла, отдельные encrypted
контейнеры и три процесса локальных реле. Frontend-устройства работают в одном
Dart процессе; это не квалификация независимых OS-процессов или телефонов.
Используется настоящий provider graph, signer, group fold и транспорт.

После привязки B и установления контакта C устройство B выключается. C
отправляет один подлинный кадр delete через native transport. Стенд сначала
подтверждает его приём на A, затем делает доступным целевое сообщение. C
выключается; приложение C не повторяет delete и не может замаскировать
отсутствующий собственный event поздним ретраем. При возврате B доступен A.

На базе A выполнило локальное удаление, но за неизменённые **20 секунд**
`msgGone` не появился в его durable device log. На исправлении этот барьер
проходит; B получает tombstone при offline C и сохраняет удаление после
перезапуска. Дополнительно C без device group успешно удаляет свою локальную
копию: отсутствие группы не считается отказом записи журнала.

Первый пробный запуск некорректно создавал строку C до проверки pending:
фоновая догрузка доставляла её на A раньше ожидаемого. Этот отказ не засчитан
дефектом продукта. Порядок исправлен до baseline и положительных сравнений.

## Исправление

* Оба пути материализации pending delete — обычное сообщение и own-device
  mirror — завершают удаление через общий helper. Peer-only операция после
  проверки направления публикуется своим устройствам; операция из их уже
  подписанного журнала не переизлучается.
* `onMessageDeleted` принимает `FutureOr<void>`. Peer ACK и завершение local
  delete ждут локального durable результата `postDeviceEvent`; сетевой fan-out
  остаётся независимым. Отказ публикации не помечается завершённым в cache.
* Повтор исходного сообщения с уже сохранённым tombstone завершает неудавшиеся
  scrub/publication перед ACK. Успешное завершение кешируется в прежнем bounded
  наборе, чтобы повтор не перепубликовывал удаление и не повторял тяжёлую работу.
* Локальное стирание выполняется независимо от успеха journal publication;
  интерфейс уведомляется о нём даже при ошибке последующей публикации. Контент
  не сохраняется ради ожидания журнала. Исходный seq остаётся в pending-delete
  tombstone; shared wire format не меняется.

Новые unit-тесты проверяют ожидание callback, прямой и mirrored post после
pending, публикацию после tombstone на повторе post, прямой delete ACK,
local-delete completion, локальное UI-уведомление при отказе журнала и отсутствие
обратного echo для own-device tombstone. Используют настоящий Dart storage
mapping поверх FakeHvContainer; это не измерение физического scrub.

## Открытая находка завершения работы

Последующее исправление и повторная проверка описаны в
[`group-shutdown-2026-10-24`](../group-shutdown-2026-10-24/README.md).
Ниже сохранён результат исходной итерации.

Положительные native-прогоны выявили поздние `storage is locked` при закрытии
B сразу после его перезапуска. Стеки указывают на незавершённые чтения
`GroupService.load` из admission/mirror bootstrap и `nudgeGroupSyncAll`.
Ошибка **не устранена в этой итерации**. Тестовый fixture по прежнему контракту
собирает её после остановки boot; opt-in `XVEIL_E2E_LATE_ERROR_STACKS=1`
добавляет стек к тестовому логу. В production эта вставка не попадает.

Поэтому состояние удаления проверено, но чистое завершение и вся crash
consistency матрица не объявляются пройденными. Native reader закрывает
контейнеры и все owned процессы завершаются, что проверено отдельно;
это не отменяет поздних исключений. Числа по каждому прогону, cleanup и хеши
текущих исходников/библиотек — в `summary.json`.

Сохранён быстрый отказ от повторного применения уже имеющегося own-device
tombstone при startup replay: каждый старый delete не запускает новый полный
scrub. Восстановление scrub, сорвавшегося в этом отдельном mirrored пути,
здесь не квалифицировано. Также не проверены часы/дни offline, все fault
границы, Windows и физический Android. Полная матрица 63 пунктов остаётся открытой.
