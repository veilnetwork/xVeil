# Каталоги моделей от нескольких устройств — 2026-10-29

## Подтверждённые дефекты

После исправления маршрута запрос получали оба устройства контакта, однако
служба передавала их каталоги по отдельности. Диалог заменял прежний результат
последним: модель первого устройства исчезала после ответа второго.

При разборе также подтверждены связанные ошибки жизненного цикла:

- обработчик входящих запросов создавался только после открытия настроек
  моделей; до этого даже контакт с включённым разрешением не мог ответить;
- рассылка продолжала начинать новые запросы после закрытия службы личности;
- лимит ожидающих контактов проверялся только после завершения всей рассылки,
  поэтому незавершённая отправка оставляла превышение в памяти;
- все вопросы получали время начала всей рассылки: медленная предыдущая
  отправка могла сделать ответ на только что отправленный вопрос просроченным.

На прежнем коде упали 11 из 12 новых проверок службы. Отдельный тест настоящего
`XVeilApp` воспроизвёл отсутствие обработчика без посещения настроек.

## Исправление

Для каждого ожидающего контакта хранится объединение каталогов его устройств.
Повтор одинаковых объявленных метаданных — kind, направление и размер — не
добавляет строку и не публикует результат повторно. Разные размеры сохраняются:
в протоколе нет хеша или версии, поэтому одинаковое направление не доказывает
одинаковое содержимое пакетов.

Общий результат одного контакта ограничен прежними 32 строками. При превышении
сохраняются первые 32 по стабильному порядку метаданных независимо от порядка
ответов устройств. Во время слияния таблица также не превышает 32 записи.
Подписчики получают отдельный неизменяемый список: старый снимок не меняется,
а его получатель не может переписать следующие результаты.

Новый вопрос сбрасывает локальное объединение только этого контакта.
При обработке очередного запроса/ответа просроченные и вытесненные вопросы
удаляются вместе с кэшем; отдельного таймера очистки нет. Лимит 64 вопросов действует
перед ожиданием каждой отправки; время окна берётся для конкретного вопроса.
Закрытие службы очищает обе таблицы и не допускает запуска следующего вопроса.
Уже начатую транспортную операцию это не отменяет.

Служба моделей теперь создаётся вместе с другими службами приложения и следует
провайдерам активной личности. Для ответа не требуется открывать настройки.
Проверки принятого контакта, право не отвечать, окно 90 секунд и запрет
непрошеных предложений сохранены. Протокол, native-библиотеки, mailbox и
анонимизированный отчёт не менялись. Нового API или стендовых веток в продукте
не добавлено; каталоги остаются только в памяти.

## Проверки

Все **430 тестов в 15 файлах** прошли с включённой и выключенной диагностикой;
это один набор, а не 860 разных тестов. Добавлены 14 проверок: объединение,
дубли, разные размеры, порядок и общий лимит, неизменяемость снимков, обновление,
срок, память во время ожидания, остановка после dispose, отображение настоящего
диалога и запуск обработчика из `XVeilApp`. Анализ пяти изменённых Dart-файлов
не нашёл замечаний.

## Физическая проверка интерфейса

A — Android на Wi-Fi; B — его sibling, C — другая личность. B/C — два отдельных
клиента на одном Mac. Использованы прежние QA-профили и production-native
библиотеки Veil `4857bebc` / hidden-volume `1ea2366f`. Android собран в
AOT/profile, Mac — в debug. Нативные test hooks и пониженная сложность выключены.
Инвентари исходников QA-клиентов совпали с проверяемой рабочей копией.

На A/B после холодного старта уже присутствовал обработчик запросов — настройки
на них не открывались. В их изолированных каталогах QA созданы разные фикстуры
инвентаризации: aa → ab и ac → ad. Это файлы для проверки перечисления и размера,
а не модели для перевода; выполнение inference или отправка весов не проверялись.

На C через существующие `/navigate`, `/ui_tree`, `/scroll` и `/tap` открыт
настоящий диалог поиска моделей. Сначала доступен только каталог A: видна одна
строка aa → ab. Затем добавлен каталог B и в рамках того же вопроса выполнен
повтор живого запроса через существующий локальный VM service. В диалоге видны
обе строки, первая сохранена. Ещё один повтор оставил по одному экземпляру
каждой строки. Настройки разрешения отвечать не менялись.

Истории с телами и порядком остались равны на A/B/C: по **1829 записей**.
Все десять файлов фикстур и созданные для них каталоги удалены с проверкой
хешей; режимы анонимности восстановлены. Ранние попытки остановились на
ограничениях стендового чтения Future и временных semantics ID; их материалы
сохранены отдельно, приложения и фикстуры после них также очищены.

Независимый аудит **219** записанных групп процессов, Android-пакета и
ADB/VM-пробросов не обнаружил остатков стенда. Приватные пути, идентификаторы,
VM-адреса и дерево интерфейса не включены в [сводку](summary.json).
