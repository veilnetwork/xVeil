# Статус доставки после аварийного завершения отправителя

**Гипотеза о невосстановимой потере статуса не подтвердилась** в проверенном
сценарии. Запись `delivered` действительно предшествует callback, который
публикует статус собственным устройствам. Но отсутствие этого события не
означает потерю статуса: сверка истории учитывает доставку в fingerprint,
передаёт `historyDelivered` и исправляет уже существующую строку sibling.
Соответствующий путь — `messaging_own_history.dart`, а не только обработчик
`msgStatus` в журнале устройств. Продуктовая логика не изменена.

## Стенд и точная граница

macOS arm64, отдельные процессы приложения A/B одной личности и C другой,
настоящие контейнеры, ratchet и локальные Core. Использованы ранее проверенные
CLI/SDK 0.11.50 (`e963fbdb`) и локальная hidden-volume `293792d`; хеши native
inputs проверены перед запуском, исходники и inputs не менялись до завершения.
Discovery за пределы стенда отключён, публичные реле и пользовательские
контейнеры не используются.

[Сценарий](../../../test/e2e/message_status_crash_e2e_test.dart) выполняет:

1. C останавливается настоящим SIGSTOP **до** записи целевого сообщения.
   A и B уже имеют одну исходящую строку со статусом `sent`; B выключается.
2. C продолжает работу и отправляет обычное подтверждение. A останавливается
   после возврата реального `markMessageStatus(delivered)`, но до возврата
   управления messaging caller, то есть до вызова callback публикации.
   Наблюдаются маркер, принадлежность VM собственной группе и состояние `T`.
3. Собственная группа A получает SIGKILL. До холодного чтения проверяется выход
   самой VM. Независимый storage reader подтверждает `delivered` на диске A
   и всё ещё `sent` на диске выключенного B. C выключается.
4. Все прежние Core завершаются. Создаётся новый локальный остров: новые
   процессы, порты и пустые каталоги состояния. Это исключает восстановление
   за счёт старой очереди реле. Запускаются только A/B, с их прежними
   контейнерами и свежим подключением друг к другу.
5. B получает `delivered` для того же ID и тела без дубля. После завершения
   A/B независимый reader повторно подтверждает этот статус на диске B.

Контрольный прогон с прежним островом также прошёл. Основным результатом
считается усиленный сценарий с полностью новым островом: **1 native E2E
пройден, без skips**. Дополнительно прошли **5 unit-тестов** границ записи и
статуса, включая отказ продолжать при несовпадающем nonce. Targeted analyze
и `git diff --check` проходят.

Контрольные gates импортируются только fixture-кодом в `test/`, включаются
отдельной переменной окружения и работают только с arm-файлом собственного
стенда. В `lib/` не добавлено тестовых ветвей. Живой ACK, подписи, ratchet,
доставка и журнал собственных устройств не подменяются.

После усиленного прогона проверены выход всех 12 зарегистрированных процессов
и групп, освобождение 12 зарегистрированных портов и отсутствие test VM.
Пути, ID, nonce и сырые журналы не включены в публичный результат.

## Границы результата

Это один sender-crash сценарий с JIT-хостами и настоящими native-библиотеками.
Он дополняет receiver-append crash проверки; вся multi-device матрица этим
не закрывается. Середина native commit, потеря питания, ошибки записи статуса,
групповые сообщения и длительный offline этим прогоном не проверены.
Новый durable intent для публикации статуса не добавлен: ожидаемое
восстановление уже выполняется существующим механизмом истории.
