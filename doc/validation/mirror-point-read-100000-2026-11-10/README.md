# Лишнее точечное чтение при повторном зеркале — 2026-11-10

## Подтверждённый механизм

`_MessagingDeviceMirror._applyMessage` вызывал `_hasMessage`, который уже
читает и материализует строку через `loadMessageById`, затем немедленно
повторял тот же поиск для delivery-status. Теперь первое свежее чтение
используется одновременно для наличия и непосредственной проверки статуса.
Между получением строки и этой проверкой нет нового await.

Повторное свежее чтение после асинхронного допуска автора для ordering adoption
сохранено. Проверки sibling, binding/dispose, tombstone, блокировки, TTL,
условного изменения порядка и durable publication не удалялись. Межоперационный
кеш строк или авторизации не добавлен; форматы и mailbox не менялись.

Три проверки стоимости падали на прежнем коде: два варианта доставленного
дубля читали строку дважды вместо одного раза; вариант с adoption — трижды
вместо двух. После правки они проходят. Это счётчики обращений к хранилищу,
не тесты с временным порогом. 208 смежных тестов прошли; отдельно 32 проверки
статусов и тестового счётчика прошли на окончательном коде. Серии пересекаются
и не складываются. Анализатор четырёх изменённых Dart-файлов чист.

## Свежий профиль получателя

После релиза повторён архивный прогон на текущем Dart-коде: все 100001 строки,
оба cursor и cold retention прошли. CPU-профиль содержит 100298 физических
сэмплов после исключения дубликатов и конфликтов. Заметны путь mirror apply,
свежие routing/control folds и `_foldCritical`.

Учтены 21 chunk, 13178 повторных записей, 327 конфликтующих физических ключей,
862 усечённых стека, 10 unavailable-isolate responses и одна ошибка запроса
в конце жизни endpoint. Последние около 6 секунд активного окна не захвачены.
Профиль не capped; включённые стеки не превращаются в проценты wall time.
Инструментированный запуск не является сравнением скорости с серией ниже.
Raw CPU endpoints, стеки с локальными путями, IDs и журналы не публикуются.
