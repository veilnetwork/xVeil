# Сжатие: блокировка во время обновления ссылок — 2026-11-11

Продолжение [проверки двух пространств](../compaction-two-spaces-2026-11-11/README.md)
и [maintenance/wipe-проверок](../compaction-maintenance-2026-11-11/README.md).
Исходная жалоба на невозможность открыть контейнер обоими паролями остаётся
невоспроизведённой. В этом раунде подтверждены два дополнительных механизма
конкурирующего доступа в приложении; они исправлены локально.

## Подтверждено и исправлено

| Механизм | Воспроизведение до правки | Изменение |
| --- | --- | --- |
| Новый unlock конкурировал с ручным сжатием | При удержанном native-вызове либо remap после завершённого lock новый запрос входа достигал общей storage facade | Ручная операция закрывает admission новых unlock до завершения rewrite/remap; штатное восстановление сессии снова разрешено после них |
| Старый remap продолжался после lock | На gates после открытия пространства и чтения roster старый обработчик после lock открывал следующие пространства либо вызывал saveRoster | Lease проверяется после каждого асинхронного шага; потеря сессии прекращает проход, текущий handle закрывается, повторное открытие сессии не выполняется |

Барьер maintenance по-прежнему охватывает и штатное восстановление сессии.
Wipe ждёт его завершения. Native rewrite, уже принятый библиотекой, этим
изменением не отменяется. Автоматическое сжатие уже выполняется внутри
существующего admission одного unlock; новый gate относится к ручной операции.

## Доказательства порядка

`test/compaction_remap_lifecycle_test.dart` использует настоящий AppController,
HiddenVolumeStorage и синтетический многопространственный backend. Это тест
оркестрации приложения, не имитация native crash. Ожидания удерживаются явными
Completer-gates, без порогов времени.

Восемь сценариев: четыре точки остановки × наличие/отсутствие нового запроса
входа после lock. Точки: native backend, завершённое открытие первой личности,
чтение первого roster и чтение master roster перед записью. После завершения
maintenance новый запрос входа снова достигает facade — временный gate не
превращается в постоянную блокировку хранилища.

До правки: 1 passed / 7 failed. После: 8 passed / 0 skipped.

В каждом контроле отличается один production-файл; компиляционных ошибок
нет. Это проверки независимых защитных границ, а не только совпадения общей

## Дополнительный native crash-контроль

macOS, закреплённая hidden-volume 2.7.0, SHA-256 перед запуском:
`a1c9a791ca186a7aa432e736565da07c897087617397fe19cf24e9b87f290fa8`.
Rust не собирался; проверялась существующая библиотека.

Созданы два независимых пространства с различными синтетическими паролями,
Argon min, по 16 МиБ данных в каждом. Дочерний процесс выполнил native compact
и остановился сразу после возврата вызова. До SIGKILL подтверждены новый inode
основного файла, изменившиеся байты и отсутствие временного sibling: rename
уже опубликован. Процесс завершён SIGKILL, а отдельный свежий процесс открыл
оба пространства и побайтно проверил **33554432 байта**.

Это конкретная проверка после успешного возврата native rewrite, до дальнейшей
логики приложения. Она не проверяет потерю питания, участок внутри rename,
Android process-kill после rename или master roster с изменившимися ключами.
За сохранность всех состояний master/all-online при любом crash этот результат
не выдаётся. Пробелы проверки этих режимов остаются открытыми.
