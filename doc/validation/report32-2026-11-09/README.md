# Валидация R32 — 2026-11-09

Проверены утверждения report32_prepare, включая дополнительные R32-02/03,
четыре замечания без номера и перенесённый остаток прошлых аудитов. Оценки
критичности и заявленное покрытие внешнего аудита не считаются доказательством.
Исходный срез приложения: `13c1ce9a`; SDK: `v0.11.48`; hidden-volume: `v2.7.0`.

### Ограничения чтения файлов

Общий reader проверяет фактический размер предоставленных bytes, размер файла
до открытия и количество прочитанных байтов в потоке. Последний барьер защищает
от роста/подмены файла после stat; переполнение отменяет подписку. Чанки
копируются, поэтому переиспользование буфера производителем не меняет уже
принятые байты. Ошибка ограничения не содержит имени, пути или содержимого.

- Сертификат: `3 × 24 KiB + 3` байта, чтобы сохранить все поддерживаемые
  Unicode-обёртки прежнего лимита 24 KiB UTF-16 units, включая BOM. Лимиты
  синтаксического разбора и бинарного сертификата не увеличены.
- Целая исходная картинка пространства/стикера: 32 MiB, как у существующего
  image-preview ограничения. Это ограничение входного файла, а не обещание
  ограничить все внутренние буферы image decoder.
- Chat/group memory fallback: прежний `kMaxIncomingFileBytes`; большие файлы
  с обычным путём продолжают передаваться потоково.
- Пакет стикеров: следующая картинка читается после нормализации и сохранения
  предыдущей. Публикация манифеста остаётся общей для импорта.

## Повторно заявленный старый остаток

В отчёте написано «9 открытых», но перечислено 10 пунктов, причём часть уже
закрыта или не подтверждена. Повторная сверка не возвращает их в дефекты
только потому, что соответствующий участок кода существует.

| Пункт | Текущий вердикт |
|---|---|
| F-4 | Синхронный file-backed floor под mutex реален и сохраняет упорядоченную публикацию. Приложение использует memory floor с host checkpoint. Возможная оптимизация отдельного файлового режима, без нового доказательства дефекта или измерения ущерба. |
| R29-05 | DSACK ограничен реальным handoff, свежим RTT, recovery round, RTO и затуханием. Новый вредный контрпример не предоставлен; произвольный SRTT cap для переупорядоченных circuit не добавлен. |
| R29-06 | **Уже исправлено:** driver вызывает `discard_received_cell` до carrier handoff. Текущие регрессии onion-stream прошли, включая отмену repair, SACK и sequence wrap. |
| X-2 | Текст SocketException остаётся внутри локального исключения; анонимный журнал его не сериализует. Повторный тест реального экспорта с фиктивными LAN-данными прошёл. Утечка в отчёте не подтверждена. |
| R28-16 | `expect` следует из constructor/channel invariant. Вход, нарушающий инвариант, не показан; новый канал в гипотетическом будущем не является текущим удалённым crash. |
| R28-18 | Convenience `UdpRealm.recv_frame` выделяет буфер, но production mesh gateway уже держит один буфер вне receive loop. Приписанная runtime-аллокация на каждый пакет не подтверждается; рефактор API не нужен для исправления приложения. |
| R28-22 | Оба HV `last().expect` непосредственно следуют за `is_empty` без промежуточной мутации. Предложенный ранний `break` мог бы скрыть неполный repack. HV не менялся. |
| R28-31 | l10n scaffold — ручной developer CLI с инструкцией в README. Отсутствие вызова из приложения корректно. |
| R31-06 | Зеркальный `failed` намеренно не откатывает существующую собственную копию и её доставку/повторы. Проектное решение сохранено. |
| SleepAdvertisement | Подпись уже проверяется вне mutex ключей. Приём legacy сообщения сохраняет аутентифицированную наблюдаемость без mailbox side effects. Удаление проверки не является исправлением. |
