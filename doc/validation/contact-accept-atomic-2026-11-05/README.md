# Первичное принятие контакта — 2026-11-05

База `99a1a4aa`. Локальное исправление без push/релиза, изменений сидов,
engine pins, native ABI и mailbox для собственных устройств.

## Подтверждённый дефект

Действие пользователя «Принять» сначала сохраняло `accepted`, публиковало
изменение статуса и лишь затем сохраняло ответ `accept`. Отказ до записи
Outbox оставлял принятый контакт без обязательства доставить ответ. Это
сохранялось после повторного открытия контейнера. На другом конце контакт
мог оставаться неподтверждённым; наличие активных транспортных узлов не
исправляет такой локальный разрыв. Причина исходного Windows-репорта этим
не доказана.

Теперь статус, недостающий индекс контакта и адресный ответ сохраняются одной
транзакцией существующего KV/log backend. Текущие имя, настройки и остальные
поля контакта сохраняются. Все изменения contact index сериализованы; операции
присоединяются к закрытию хранилища, чтобы ожидающая запись не сменила личность.
При существующем идентичном ответе сохраняется его исходный возраст;
несовпадение адресата или wire отклоняется до изменения статуса.

При потерянном ответе на commit приложение проверяет точные peer/wire записи
Outbox, статус контакта и наличие его индекса под теми же блокировками. Только
полная проверка разрешает продолжение. Отсутствующая или нечитаемая часть
доказательства сохраняет исходную ошибку. Это не оптимистическое признание
любой ошибки успешной записью.

До durable admission не вызываются status callbacks, не разрешается live send
и не публикуется принятие в UI. Ошибка callback после commit не отменяет
сохранённую обязанность ответить и не пропускает первую сетевую попытку.
Отправка использует прежнюю bounded recipient queue, не добавляет ответ
повторно после ACK и сохраняет ограниченное ожидание первого live send для
вызывающей стороны. Dispose присоединяет незавершённое принятие; поздний commit
не публикуется через уже закрытый messaging service.

Отказы первичного принятия фиксируются как `contact-accept` с безопасной
категорией ошибки, project frames и числовым errno. Исходные exception text,
OS message, путь и FormatException.source не передаются даже в RAM error entry.
Ошибку по-прежнему получает вызывающая сторона.

## Проверки и границы

На исходной реализации получены **12 assertion-red**: шесть исходных режимов
на ordinary и worker/native HVS backend. Это реальные fault injections на
границе KV/log commit, а не имитация сбоя только верхнего метода Storage.
Режимы: штатный commit, удержание Outbox commit, отказ до записи/потеря ответа
после записи в contact- и Outbox-ветвях. Начальные compile failures и
незавершившиеся fixtures не засчитаны как red.

Финальные **20 scoped cases** включают дополнительные проверки закрытия,
ошибки status callback и отказа readback, cold reopen, contact index через
несколько shards, сохранности метаданных и возраста ответа, владения входными
wire bytes, конфликтующих записей и canary-приватности error entries. Десять
случаев используют явно выбранную worker/native HVS; ordinary backend является
контролем логики, не заменой native проверки. Expanded cases не объявляются
все двадцать красными на исходной реализации.

Сетевой transport и криптография в fault-тестах синтетические. Native A/B/C
process stand служит отдельной регрессией реального encrypted transport,
Outbox и own-device expiry. Его пять gates не являются воспроизведением сбоя
хранилища на пользовательском Windows.

Финальная control-серия с `XVEIL_DIAGNOSTICS=true` и явно выбранной HVS:
**440 passed, без skip**, 15 файлов; включает все 20 новых сценариев.
Широкая серия с явно выбранной HVS: **1884 passed / 3 conditional skipped**,
100 файлов. Пропуски не считаются пройденными. Analyzer пяти изменённых lib
и всего test чистый. Добавленные canaries проверяют, что текст отказа не
сохраняется в RAM записи `contact-accept` и не экспортируется.

Актуальный headless AOT собран штатным `dart build cli`; `--help` завершился
с кодом 0. Все 577 выбранных source/pub hashes неизменны при сборке. Это build/
argument smoke, не сетевой запуск daemon. Собственные 14 МБ build-артефактов
удалены после проверки SHA. Veil/HVS не пересобирались; provenance выбранных
библиотек проверена по отдельному source/artifact proof. Engine pins прежние.

Финальный process A/B/C на итоговом дереве прошёл все пять TTL/Outbox gates:
живые копии, очистка owner, native raw roots, новая доставка после замены и
cold B без A/C. Cleanup проверил **27 PID / 37 портов**: собственных процессов
и listeners не осталось, runtime удалён. Все 1463 frozen inputs и native SHA
неизменны; Veil/HVS source trees clean. Длительность 293,4 с — не замер скорости
контактного handshake и не сравнение производительности с прежними сериями.
Два более ранних процесса-контроля также прошли и завершены; к финальному
дереву относится именно эта серия после добавления readback/diagnostic changes.

Windows повторно недоступна по SSH (TCP timeout); физическая PC ↔ Android
проверка не объявляется выполненной. Подключённый телефон не переустанавливался.

## Остаток

Атомарность локального решения и ответа закрыта в указанных сценариях.
Crash-durable публикация решения другим собственным устройствам — отдельная
граница: callback DeviceSync сам по себе не доказывает обязательную доставку
при hard crash после локального commit. Общая сходимость контактных решений,
конкурентные accept/block, power-loss матрица, длительный offline, слышимость
звонка и причина исходного PC ↔ Android случая здесь не квалифицированы.
