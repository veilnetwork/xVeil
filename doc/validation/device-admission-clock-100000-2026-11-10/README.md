# Часы кешей допуска устройств — 2026-11-10

## Подтверждённый дефект

Три read-пути — `isMyDevice`, `_deviceGroupOwnerIfLinked` и
`_masterDeviceForAdmission` — проверяли 30-секундный RAM-кеш через `_now()`.
Это не простое чтение времени: функция резервирует следующий монотонный
mutation timestamp. Поэтому частые проверки тратили срок кеша без прошедшего
времени и сдвигали timestamps последующих подписанных сообщений.

Пять регрессий на старом коде:

- 64 member/owner-чтения сдвигают следующий подписанный timestamp на 64 мс;
- 64 admission-чтения сдвигают его на 192 мс;
- 31000 admission-чтений при замороженных часах заставляют четыре раза
  перечитать owner вместо одного;
- после отката wall clock старый кеш не перечитывается, хотя его lease
  относится к будущему времени.

Cache lookup и публикация cache timestamp теперь используют `_clockNowMs()`.
Срок остаётся 30000 мс; отрицательный возраст кеша вызывает свежее чтение.
Монотонный `_now()` сохранён для настоящих мутаций. Нового кеша авторизации,
снятых проверок подписи или обхода generation/revoke fences нет. Уже подписанные
записи не переписываются; изменения wire/storage/mailbox отсутствуют.

Пять новых проверок падали до исправления и проходят после. Полный related-набор:
**662 passed / 11 skipped**, включая GroupService, own-device history и stand
observer. Пропуски не считаются прохождением. Analyzer пяти Dart-файлов чист.

## Наблюдение ожиданий

`PrivateHistoryWorkProbe` теперь отдельно коалесцирует overlapping `ownDevices`
в один busy interval. Это тестовый наблюдатель вне product imports: только
фиксированные имена этапов, время и числовые счётчики, без IDs/ключей/содержимого.
Обычная квота 20000 сохранена; явно включённый stand получает ограниченную
квоту 65536, она записывается в header. Footer сохраняет dropped/active даже
при исчерпании бюджета. Проверены overlap, сохранение результатов/ошибок,
whitelist, границы бюджета и отсутствие файла при неверной квоте.

Первый диагностический native-кейс сохранил точную историю, но исчерпал старую
квоту: 20000 записанных границ и 30872 dropped. Он **не используется как полный
профиль или сравнение производительности**. Во всех трёх новых фазах ниже
трасса полна: четыре закрытых boot-сегмента, dropped=0, active=0.

## Где остаётся ожидание

В B однозначно связаны 730 из 782 межстраничных интервалов; 52 неоднозначных
исключены. Для каждого принятого интервала шесть последовательных частей
точно дают полный интервал. Поднаборы A/B/A различаются, их медианы нельзя
вычитать как причинный эффект правки.

| Часть интервала в B | P50, мс | P95, мс |
|---|---:|---:|
| Полный reply → первый apply callback | 54,354 | 155,616 |
| Apply busy interval | 43,076 | 106,107 |
| Последний apply → начало cursor write | 5,456 | 13,708 |
| Cursor write через storage adapter | 15,186 | 36,872 |
| Конец cursor write → следующий query у источника | 3,665 | 90,855 |
| Полный интервал | 167,927 | 262,927 |

Промежутки между apply-волнами в принятых интервалах равны нулю.
Медианы строк не складываются в медиану итога. При отсечении последующей
проверки cold reopen apply busy занимает 46,423 с; публикация 15,343 с уже
включена в него, cursor busy — 14,721 с. `ownDevices` busy — 62,050 с,
пересекается с apply на 17,299 с и с cursor на 7,638 с. Это overlapping
клиентские ожидания, не независимые CPU/fsync/authorization времена; их
нельзя складывать или целиком приписывать критическому пути.

Следующий участок — свежие routing/control journal reads и очередь до
первого callback. Догрузка всё ещё около двух минут, latency остаётся открыта.
NETCALL, физическая/AOT квалификация и остальная multi-device матрица этим
циклом не закрываются. Новые изменения без push/релиза; sibling mailbox
не включён. Owned процессы/listeners удалены после всех фаз. Cache 92→92,
новых kernel entries нет; raw журналы и локальные endpoint данные вне Git.
