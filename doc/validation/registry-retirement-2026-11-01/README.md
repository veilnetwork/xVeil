# NETCALL-01: принудительное закрытие при удерживаемом sender

Дата: 2026-11-01. SDK `8eab7507` на базе `5ded5aca`. Продолжение [EOF-фикса](../session-outbox-close-2026-11-01/README.md).
Исправлен ещё один подтверждённый механизм задержанного завершения сессии.
**Пауза аудио и медленный запуск медиа после смены сети остаются открытыми.**

## Подтверждение и граница исправления

`SessionTxBroadcaster.send_reliable_to` и другие ожидающие отправки захватывают
копию FrameSender до выполнения future. Удаление записи SessionTxRegistry само
по себе не закрывало каналы, пока такая копия существовала. Поэтому даже после
предыдущего фикса ожидания EOF административный unregister (в том числе mobile
NetworkChanged) мог не дать runner событие закрытия. Подтверждены два сценария
без временных порогов: удерживаемый producer с waker и ещё не опрошенная future
настоящего production-адаптера. Оба теста были красными на исходном коде.

Добавлен отдельный process-local канал принудительного закрытия глубиной 1.
Явные `unregister` и совпавший по owner `unregister_owned` посылают сигнал именно
удаляемому outbox. Его poll/try-recv закрывают все producer-входы; принятые кадры
сохраняют прежний порядок чтения перед EOF, затем runner использует штатный
teardown. Копия sender больше не удерживает очередь открытой после этого сигнала.
Позднее удаление с чужим owner по-прежнему не затрагивает новую регистрацию.
Отдельный regression проверяет этот отрицательный контроль и закрытие текущего
owner при сохранённой копии sender.

Обычная замена регистрации сохраняет поддерживаемую возможность завершить
ранее начатую отправку в прежний канал. Первый, более широкий кандидат закрывал
очередь также при простом drop/replacement записи — полный набор тестов выявил
регрессию, включая `direct_chunk_admission_binds_capability_and_sender_across_reconnect`.
Кандидат отклонён **до установки**. Первоначальный тест с требованием немедленно
закрыть обычную замену не является подтверждением дефекта и заменён проверкой
правильного owner. Ошибка импорта в самом первом запуске также не считалась
красным воспроизведением. Два неизменённых regression действительно падали по
непробуждённому ожиданию/отсутствию EOF.

Wire, C ABI, криптография, peer-admission, независимость источников и таймауты
не менялись. Сигнал локален и недоступен удалённому peer. Закрытие очереди не
обещает доставку её кадров на wire при принудительном teardown.

## Физическая проверка

Отдельные QA Poco ↔ Windows 11. На телефоне заменена только FFI в замороженном
AOT; manifest, wrapper, медиадвижок, остальные ZIP entries и signing certificate
проверены неизменными. Windows использует прежние опубликованные библиотеки.
Реле в этом цикле не изменялись.

- До смены сети — четыре последовательные свежие P2P-выборки обоих концов.
  После Wi-Fi cut — по 40 выборок за 41,7 с, один active call сохранён, свежий RX
  в конце. Максимальный sampled native age — **4053/6347 мс**. Непрерывный свежий
  audio RX не квалифицирован; значения разных media epoch не являются верхней
  границей всего перерыва.
- Отдельный новый вызов сразу после Wi-Fi cut: входящий на Windows через
  **1,085 с после place**, первые наблюдаемые свежие RX-срезы на телефоне/Windows
  только через **19,857/19,869 с после cut**, пять подряд — через **24,118 с**.
  Это подтверждает, что быстрое появление входящего не означает быстрого запуска
  звука. Cellular default проверен; условие одного активного узла не создавалось.

Это не A/B с фиксированным маршрутом, причинное ускорение от правки не доказано.
Речь человеком и слышимая громкость не проверялись; жалоба Poco → Windows не
закрыта. Дополнительный focus-check ошибочно прочитал раздел `dumpsys window
windows` без глобального focus-поля и не прошёл; последующая shell-команда
продолжила звонок. Отдельный полный dumpsys подтвердил QA foreground во время
разговора. Наличие foreground до cut по этому ancillary check не заявляется;
основные P2P/RX-предусловия и полнота 40-секундного наблюдения проверены отдельно.

Не получено отдельного доказательства, что зафиксированная на стенде пауза была
вызвана удерживаемым sender. Следующая граница атрибуции — наблюдение события
смены сети и фактического закрытия canonical/child transport для конкретной
попытки, затем прохождения уже принятых записей до первого реле. Таймауты не
повышались и переключение на другой источник для сокрытия паузы не добавлялось.

## Завершение

Оба QA остановлены, Windows scheduled tasks и listener отсутствуют, SSH-туннель,
собственный logcat и ADB-forward закрыты. Первый postflight Windows временно
не прошёл проверку listener; повторная независимая проверка подтвердила отсутствие
процессов, задач и listener через IPGlobalProperties. Первая попытка cleanup
телефона остановилась на guard активного звонка; после подтверждённого окончания
обоих endpoint cleanup выполнен полностью.

Прежний QA APK телефона восстановлен с проверкой SHA и оставлен остановленным.
Исходные Wi-Fi/mobile data/stay-awake и PID основного приложения сохранены;
его контейнер не открывался. Mac-стенд не запускался. Сиды, их бинарники и конфиги
не менялись. Push/релиза нет. Публичные [агрегаты](summary.json) не содержат
идентификаторов, адресов, путей пользователя, ключей или корреляционных digests.
