# Получатель после ACK и аварийного завершения

Три выбранных сценария прошли на текущих native-библиотеках: SIGKILL до
append, после append и после фактического delivery ACK у отправителя.
Новый post-ACK случай сохраняет данные без повторной доставки от источника.
Нового продуктового дефекта в этих сценариях не обнаружено; изменения
ограничены тестом и документацией. Push и релиза нет.

## Стенд и происхождение сборок

macOS ARM64, отдельный OS-процесс для A/B/C: A+B — личность X, C — личность Y;
три локальных Core. Production-код приложения — `9d2bedbd`, Dart SDK —
`51d54602`. Native SDK 0.11.51 соответствует проверенному producer
`952e0c292eb8`, hidden-volume 2.7.2 — `072b402de743`. SHA библиотек сверены
с сохранённым отчётом проверенной сборки до запуска. Во время окончательной
серии SHA исходников теста/приложения и всех выбранных native bytes не менялись.

Core CLI 0.11.51 собран отдельно из SDK `51d54602`: профиль **dev**, штатные
default features и явный `allow-empty-seeds`. Использован отдельный Cargo target
на проверенном внешнем filesystem с контролем монтирования/места. Это проверка
корректности, без выводов о скорости release-Core. Built-in seeds и meeting
points отключены в конфигурациях острова; production-реле не использовались.
Модель mailbox для собственных устройств не менялась.

## Контрольные точки

`before` и `after` используют прежний test-only storage adapter вокруг настоящего
зашифрованного append. Он останавливает VM до вызова родителя или после успешного
возврата, до продолжения обработчика. У отправителя ещё нет delivered.

В новом `acknowledged` нет arm-файла storage adapter и нет замены транспорта.
Родитель наблюдает durable delivered у A, проверяет принадлежность VM C своей
process group, посылает SIGSTOP, наблюдает состояние `T`, затем SIGKILL. Проверены
exit code `-9` и фактическое завершение VM до открытия контейнера.

Это **остановка наблюдателем после receipt**, а не контрольная инструкция сразу
после native ACK send. Не покрываются середина расшифрования/native commit,
частично записанный ACK, аппаратное отключение, Android и Windows.

## Результаты

| Проверка | До append | После append | После наблюдаемого ACK |
|---|---|---|---|
| Delivered у A перед аварией | Нет | Нет | Да |
| Целевая запись при cold-read до сети | Нет | Одна | Одна |
| Оба источника выключены при первом cold-read | Нет | Нет | Да |
| Три исходных ID/тела сохранены до возврата источников | Не этот сценарий | Не этот сценарий | Да |
| Исходный ID цели после восстановления, без дубля | Да | Да | Да |
| A/B сходятся по ID, порядку, seq и статусу | Да | Да | Да |
| Новый обмен C→X и X→C с подтверждениями | Да | Да | Да |
| Пять точных ID/тел при финальном cold-read C без A/B | Да | Да | Да |

Post-ACK проверка выключает A и B до первого холодного чтения. Проверяются три
конкретные записи: исходное hello, контроль и цель. У них три уникальных ID;
ID контроля сверены с состоянием до целевой отправки. После запуска C без
источников сравниваются те же ID и тела, затем A/B возвращаются. Исходные ID
дополнительно проверяются после восстановления источника. Для финальных пяти
записей проверяются известный набор тел, единственность ID и сохранность без
источников — равенство двух пустых либо одинаково неполных списков не проходит.

Окончательный прогон: **3 native cases, zero skipped**, **4 unit tests**, анализ
без замечаний. Два избыточных null assertions в тесте убраны; после уточнения
оракула все три native случая повторены на окончательном исходнике.

## Границы и очистка

Это дополнительное частичное покрытие пункта 62. Все 63 пункта, длительный
offline, power loss и пользовательский мобильный обрыв не объявлены закрытыми.
Последовательность сообщений обычного чата не заменяет проверки групп/файлов.

Проверены **33 зарегистрированных PID**, **21 process group**, **29 известных TCP
портов**: оставшихся процессов/членов групп/listeners нет. Три временных runtime
с контейнерами удалены. Большой Cargo target удалён отдельно после сохранения
проверенного test-only CLI. Raw logs, runtime IDs, PID, пути и подробная provenance
хранятся только в приватном кэше; в этот отчёт они не включены.
