# Текущие Android ↔ Windows: AV и проверка APK — 2026-11-12

## Подтверждённая ошибка комплектации

В отдельной QA-упаковке сначала отсутствовал локальный, не хранящийся в Git
`assets/prod/obfs4_psk.b64`. После добавления файла повторная закешированная
сборка завершилась успешно, но APK по-прежнему не содержал его. Это проверено
чтением ZIP, а не только состоянием исходного каталога. Сброс только собственного
кеша сборки восстановил включение файла; байты в APK совпали с выбранным входом.

Нативные проверки не замечали такой ошибки. Release gate теперь сравнивает
**наличие и точные байты** `seeds.json` и `obfs4_psk.b64` выбранной сети во всех
выпускаемых ABI. Отказ даётся при пропуске, старом значении и оставшемся в APK
файле, которого уже нет в конфигурации. Развёртывание без этих файлов остаётся
поддержанным, если их нет и в пакете. Проверка не требует общего PSK для частной
сети и не меняет runtime/discovery/доверие к узлам.

Ошибка сообщает ABI и относительное имя файла, без содержимого или хеша секрета.
Локальный ключ сети в Git не добавлен. Связь этой находки с пользовательской
жалобой по 0.13.96 не установлена.

Шесть assertion-red подслучаев на прежнем gate; после исправления проходят
четыре теста нового набора и три существующих ELF dependency tests.
`test-build-support.py` также прошёл. Оба профильных набора добавлены в CI.
На настоящем конечном APK прошли сравнение сети, проверка loader dependencies
и чтение всех экспортов media engine, которые запрашивает Dart.

## Происхождение тестовых сборок

- Android arm64: полный SDK `8e317b53` с production-seeds/node-embedded/
  packet-tunnel без default TLS-boring, как в Android Gradle; hidden-volume
  `29a87ef5`; media engine собран из текущих исходников. WebRTC pin,
  GN arguments, static-library SHA и private ABI headers проверены.
- Android APK — profile-AOT, runtime frontend из `3bc83941`. Приватные отличия:
  отдельные application ID/название, ограничение Gradle workers и локальный
  сетевой asset. Основной пакет телефона не заменялся.
- Windows 11 — новый profile-AOT с пятью актуальными runtime-файлами аватаров
  поверх проверенного checkout; 807 исходных файлов сверены во время сборки.
  Полные SDK/media/HV DLL соответствуют ранее проверенным текущим SHA.
  Использована отдельная холодная копия собственного QA-контейнера и prefs.

Управляющий HTTP hook включён явными compile-time opt-ins; media test hooks,
SDK-заглушки и ручная инъекция входящих сообщений не использовались.

Первая Android проверка равенства native SHA не засчитана: Gradle штатно
удаляет символы из `.so`. Доказано побайтное соответствие результату выбранного
NDK `llvm-strip --strip-unneeded`; окончательная упаковка проверяет SHA именно
этих производных библиотек. Исходные SHA и преобразование записаны отдельно.
Источники во время окончательных native/APK сборок не менялись.

## Физическая проверка

Blackview без SIM и доступная Windows 11. На телефоне настоящая первая
настройка отдельной личности: сертификат сохранён через DocumentsUI, создан
контейнер, после обновления QA APK та же личность открылась вновь.

Сначала на телефоне был **выключен Wi-Fi**. Два ожидания запроса контакта в таком
состоянии не квалифицируют доставку и не считаются дефектом клиента. Контроль
DNS/TCP с UID QA-приложения тоже не проходил; после включения Wi-Fi прошёл.
Для основного контроля узел запущен заново с доступной сетью. Поэтому этот
раунд не проверяет автоматическое восстановление после смены сети.

При доступной сети телефон установил релейные подключения. Принятие контакта
прошло в обе стороны; два контрольных сообщения проверены на обоих концах по
точным ID, тексту и статусу delivered у отправителя.

Прошли три настоящих видеозвонка с реальными микрофонами и камерами:

| Направление вызова и фактический транспорт | Интервал наблюдения | Windows: прирост audio RX / remote frames | Android: прирост audio RX / remote frames |
|---|---:|---:|---:|
| Windows → Android, P2P | 14,82 с | 76 / 171 | 74 / 122 |
| Android → Windows, P2P | 14,83 с | 101 / 104 | 95 / 123 |
| Android → Windows, relay | 14,44 с | 89 / 12 | 78 / 13 |

По восемь парных active-срезов каждого звонка: ожидаемый контакт, один call ID
и стабильная media epoch. В интервалах росли также audio TX, video TX и доставка
видео декодеру. Capture/playout start — success на обеих платформах; полосы
входного/выходного уровня ненулевые, worker-stalled флаги равны нулю.
Звонки завершены командами стенда, не объявлены пропавшими сами по себе.

Второй звонок первоначально ошибочно ожидался как relay: явное `allow` контакта
оставалось активным. Исходный transport assert упал. Его данные учтены только
как P2P после отдельной проверки фактического транспорта и приростов счётчиков.
Отдельный успешный relay-контроль использовал `deny` контакта на обоих концах;
relay подтверждён во всех наблюдаемых срезах. Политики продукта не изменялись.

## Границы и следующий участок

Это проверка цифрового тракта Windows 11 ↔ Blackview, а не Windows 10 или Poco.
Человек не слушал разговор, тестовая речь/PCM не подставлялись и не записывались.
Числа не доказывают слышимость речи или субъективное качество; исходная жалоба
Windows 10 остаётся открытой. Реальное обновление аватара в desktop GUI
этими звонками не проверено, хотя актуальные исправления вошли в AOT.

**Подтверждено измерение:** relay-видео в этой серии около **1 кадра/с** на обоих
концах, при Android capture около 30 кадров/с. Приложение удерживало заданный
video target 15 кбит/с, encoder target около 6,5 кбит/с; audio-buffer-pressure
был false. Уточнение после сверки native-поля: `target_bitrate_bps` — заданный
приложением video target, **не оценка пропускной способности сети**. Эти данные
не доказывают падения BWE. В последующем [длинном контроле](../relay-video-startup-2026-11-12/README.md)
качество выросло самостоятельно. Это другой звонок и маршрут; прежний короткий
случай не объявляется ни устранённым, ни доказанным дефектом алгоритма.

## Восстановление стенда

Android QA остановлен и удалён вместе с тестовыми данными; его новый сертификат
удалён из Downloads. SHA основного APK не изменился. Проверки работали в другом
UID и не открывали основное хранилище. Wi-Fi возвращён в исходное выключенное
состояние; собственные ADB/SSH forwards закрыты.

Звонки Windows закончились до остановки приложения. Позже сработал заданный
20-минутный лимит QA launcher: exit-file через 1200,25 с, exit -1; совпадающих
Windows Application Error событий нет. Поэтому последующая попытка `/lock`
уже не могла подключиться. Исходные QA-container/prefs не открывались новой
копией и сохранили SHA; временные копия/profile, runtime и task удалены.
Повторная проверка исходного стенда подтверждает 807 canonical frontend файлов,
native bundle, original QA container/prefs и отсутствие собственных apps/tasks.

Проверка приватных строк выполнена на всех распакованных членах Android APK,
а не только на сжатом ZIP: совпадений нет. В публичном результате нет адресов,
имён устройств, данных контактов, изображений, токенов и сырых трасс.
Завершённые собственные Cargo targets и лишний SDK archive удалены — 2,34 ГиБ;
выбранные библиотеки сохранены с повторной проверкой SHA.

Изменения локальные, без push/релиза. Immutable media pins всех платформ пока
не обновлены; эта Android arm64 сборка и текущие Windows библиотеки не заменяют
проверку остальных release-артефактов.
