# Проверка приватности перед публикацией

Проверены достижимые объекты веток и тегов трёх репозиториев: содержимое файлов,
сообщения коммитов, метаданные авторов и теги. Известные личные пути, логины и
адреса стенда заменены в старых отчётах и тестовых примерах; идентификаторы
участников в отчётах заменены согласованными синтетическими значениями.
Рабочая конфигурация сети и ключи подписания не заменялись.

При замене тестовых адресов сохранено их назначение: проверке глобальной
доступности нужен публичный референсный адрес, а не документационный диапазон,
который production dialability намеренно отвергает. Актуальные классификационные
fixtures используют общедоступный адрес резолвера без сетевого обращения;
отказы для документационных, частных и mapped-loopback адресов сохранены.

Повторная локальная проверка не обнаружила известных защищаемых значений.
Это проверка известных идентификаторов и секретов, а не доказательство отсутствия
любой возможной корреляции. Исходные значения, словарь замен и сырые результаты
остаются вне репозитория. Существующие несвязанные пользовательские файлы не менялись.

Ветки и теги GitHub обновлены с проверкой ожидаемых прежних значений. Независимые
свежие mirror-копии всех трёх репозиториев повторно проверены: совпадений нет,
крупные объекты содержимого не пропускались. Временное разрешение force-push
снято; исходная защита веток и состояния релизных workflow восстановлены.

Недостижимые старые объекты локально пока намеренно не удаляются. Проверка также
подтвердила доступность старых объектов GitHub по прямому хешу: обновление refs
не очищает серверное хранилище. Локальная очистка не удаляет эти внешние копии;
для них требуется отдельная операция на стороне площадки.

## Гейт артефактов

Во всех трёх релизных workflow перед публикацией запускается проверка по
приватному списку, хранящемуся в GitHub Actions secrets. Ранее существовавший
список не заменяется; дополнительный список дополняет его.

Сканер проверяет ASCII/UTF-16 строки, имена файлов и членов архивов, а также
цели ссылок TAR без их разыменования. Пустой вход, отсутствие шаблонов и ошибка
чтения архива проваливают проверку. В публичный вывод попадают только количество
совпадений и порядковый номер записи: найденный текст и имена не печатаются.

Семь регрессионных проверок проходят в каждой из трёх копий сканера. Они используют
синтетическую контрольную строку; реальные идентификаторы не нужны тестам.
