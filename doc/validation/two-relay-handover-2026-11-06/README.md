# Poco ↔ Mac: handover с двумя QA-реле

**Один звонок сохранился во всех трёх Wi-Fi → cellular → Wi-Fi циклах.**
Существующее предпочтение готовых source channels и локальная избыточная
отправка наблюдались на двух следующих узлах. Это положительный контроль
работающего обхода, **не доказательство устранения NETCALL-01**.

Продолжение [single-Core first-flight capture](../poco-obfs-first-flight-2026-11-06/README.md).
Анонимные агрегаты: [summary.json](summary.json).

## Что изменилось в стенде

- Те же Poco / Android 16 и MacBook, тот же SDK FFI `29ee0700`, AOT, media,
  HVS и свои подтверждённые QA-личности. Новых Rust/Flutter build нет.
- Добавлен второй QA-Core на другом сервере с **другой собственной QA
  identity**. Оба используют сохранённый CLI `ade3130a` и общий QA obfs4 PSK;
  production не подключается к QA. Конфиг второго Core взял только Identity
  из прежнего собственного line-testnet, остальные секции из свежего
  изолированного шаблона; старые связи линейного стенда не переносились.
- В QA APK изменены только два уже тестовых seed assets; Native/AOT/остальные
  ZIP payloads и signer сверены побайтно. Mac использует тот же подписанный
  bundle и проверенный внешний FFI через штатный override. Phone startup
  подтвердил `bootstrapPeers=2`, mapping FFI Mac проверен.
- До звонка `sessions list --verbose` **на каждом** QA-Core содержит оба
  ожидаемых transport NodeId в состоянии `active`. Наличие двух строк в
  конфиге или индикаторе отдельно не засчитывалось как подключение.
- P2P запрещён и перечитан на обоих endpoint. Actual media path — non-onion
  Delivery relay; private onion lifetime и direct P2P этой серией не проверены.

## Результаты

Один Mac → Poco звонок. Исходный bidirectional baseline — пять свежих срезов
подряд; затем три отключения Wi-Fi по 35 с и наблюдения по 20 с после его
включения. ОС cellular/Wi-Fi и validated state наблюдались отдельно.

| Цикл | Максимальный native RX age, Poco / Mac | Call state |
|---|---|---|
| 1 | 1046 / 1137 мс | Сохранился |
| 2 | 1073 / 1138 мс | Сохранился |
| 3 | 1397 / 4566 мс | Сохранился |

Media epoch **1 на обоих концах весь прогон**; улучшение максимумов не
объясняется пересозданием движка и сбросом его RX-счётчика. Последние пять
срезов перед командой hangup — fresh на обоих концах. Fresh всего 323/332
у телефона и 316/332 у Mac; это включает исходный разгон. Один отрицательный
age у телефона был до установления исходного приёма. Не все срезы свежие,
поэтому качество разговора не объявляется идеальным.

Native age не является акустической задержкой или оценкой разборчивости.
Слышимость человеком не проверялась. Новые исходящие звонки непосредственно
после переключения, включая прежний one-way RX случай, здесь не выполнялись.
Поздний дополнительный observer запустился уже после штатного hangup и
получил пустой call state; он **не засчитан** как отдельная проверка приёма
после transport failure.

## Свидетельства обхода и их пределы

Обычный send path уже ранжирует ready source channels перед warming, не
меняя допуск relay или wire class. Для небольших sealed primary cells он
разрешает две копии с одинаковым ciphertext/content ID; replay/dedup остаётся
у получателя. Это **существующий код**, не новая правка этого цикла.

Пассивная rt-trace с `local_slot=0` содержит положительный admission обоим
Core, сопоставленным с их конфигурированными NodeId:

| Endpoint | Первый Core: положительных sample rows | Второй Core: положительных sample rows |
|---|---|---|
| Poco | 150 | 138 |
| Mac | 168 | 168 |

Это число диагностических срезов, **не число пакетов**. Admission не
доказывает получение конкретной копии на конечном endpoint. Не проводилось
управляемого выключения одного пути; приписывать сохранность звонка только
второму Core причинно нельзя.

У телефона есть одна outer `obfs4 client handshake timed out` запись.
Отдельно новый observer зафиксировал 10002-мс incomplete Read: written 112,
read 0, kernel queue 112, notsent 0, unacked 1, retransmissions 4. Local port
этого сокета найден в 56 inventory rows, однозначно направленных ко второму
Core; в 28 из них send queue также 112. IP/port в публичный отчёт не попали.

Outer warning идёт на 1867 мс позже observation; общего connection ID в нём
нет. Connect path после ошибки может ждать NAT/SOCKS fallback перед записью
primary error. Поэтому две строки не склеиваются только по близости времени,
и не объявляется, что это отдельное новое нарушение или что все долгие
transport observations относятся к canonical session. Транспортный сбой
повторился, хотя весь разговор в этой серии сохранился.

На первом Core capture 30202 packets / 98 flow / 77 flow с client payload;
на втором 23236 / 188 / 88. У всех flow с client payload наблюдался ответный
server payload. У обоих kernel capture drops 0; capture остановлены вручную
до bound. Отсутствие ответа на стадии приложения не приписывается конкретному
network hop без дополнительных свидетельств.

## Вывод и следующий шаг

На том же SDK при двух доступных путях наблюдалась сходимость к свежему
bidirectional RX без rebuild и неожиданного отбоя в трёх циклах. Это
**не A/B**: другая топология, дополнительные handshake/DHT, другой момент
мобильной сети. Цифры нельзя использовать как причинную оценку ускорения
или основание требовать минимум два Core для работы приложения.

NETCALL-01 остаётся открыт в single-path и post-switch new-call вариантах.
Следующие проверки: управляемая потеря одного QA-пути при сохранённом другом;
отдельно regression на гонку уведомления между проверкой состояния peer и
постановкой ожидания reconnect. Последнее пока кандидат по чтению кода, не
доказанная причина физических пауз. Без такого теста stale backoff не
объявляется найденным дефектом. Аудиобуфер, таймауты и правила допуска не
менялись.

## Очистка

Оба QA сервиса/capture остановлены и удалены с state/runtime/config/binary/
unit/портами, PCAP скопированы со сверкой SHA. На обоих production PID,
executable/config SHA и NRestarts прежние. Своё socket sampling остановлено,
script и ADB forward удалены. QA APK восстановлен по SHA; основной APK и
прежний root QA-контейнер не менялись. Исходные Wi-Fi/mobile/awake/P2P
настройки восстановлены, validated Wi-Fi подтверждён. Свои приложения и Mac
runtime закрыты; после SIGTERM grace точному Mac PID потребовался SIGKILL.
Подпись исходного bundle повторно проверена после архивации runtime log.
Удалено 108335522 байт своих упаковочных промежуточных APK; final/rollback и
приватные свидетельства сохранены. Production-код/сиды, push и релиз не менялись.
