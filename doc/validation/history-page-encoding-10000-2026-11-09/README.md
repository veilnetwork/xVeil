# Догрузка: не сериализовать всю страницу после каждого сообщения

## Подтверждённая лишняя работа

Проверка предела 128 КиБ после каждого добавления сериализовала все уже
подготовленные события страницы. На странице из 128 сообщений первые строки
повторно проходили JSON escaping и UTF-8 много раз. Отдельный диагностический
профиль родителя `3f267c1e` показал 1723/1553 сэмпла JSON/UTF-8 внутри `_serve`
у источников A/E. Это сэмплы доступных isolate, не секунды или доля полного
wall time: некоторые завершённые isolate уже недоступны профилировщику.

Теперь каждое событие один раз учитывается как quoted JSON string в UTF-8.
Для текущего кандидата отдельно считается пустой envelope с настоящими
prefix/cursor metadata; добавляются элементы и запятые. Итоговый ответ всё
равно целиком кодируется и проверяется перед публикацией. Формат, 128-row cap,
128 КиБ/64 части, публикации по 64, ordinary coalescing по 16, current-device,
binding, visibility и durable cursor не меняются. Sibling mailbox не включён.

В отдельном диагностическом прогоне candidate JSON/UTF-8 внутри `_serve`
дал 67/80 сэмплов A/E. Эти профили не используются как A/B wall-time замер;
между ними добавлены только unit boundary probes и изменён сборщик страницы.
Остальные runtime inputs и native artifacts одинаковы. Недоступные isolate
указаны в агрегатах; по ним не предполагается нулевая работа.

## Границы и тесты

Шесть source-side проверок сравнивают реальные собранные bytes с одной полной
эталонной JSON+UTF-8 сериализацией: **128 КиБ−1, ровно 128 КиБ, +1**, с optional
prefix metadata и без неё. Есть Unicode, кавычки, backslash и управляющие
символы; учитывается cursor. Последний случай возвращает более короткую
страницу, а не превышает лимит. Все шесть прошли на родителе и candidate:
это сохранение поведения, не заявление о старой ошибке границы.

Искусственное завышение размера на один байт даёт **2 assertion-red / 4 green**:
обе exact-fit проверки замечают преждевременное окончание страницы. После
возврата candidate **266 related passed / 0 skipped**, включая **16 native HVS**;
analyzer чист. Остальные revoke, partial publication, record, byte/reassembly,
restart, privacy и concurrency проверки сохранены.

## Нативное сравнение на 10000 сообщений

Родитель → candidate → родитель, четыре независимых Mac/JIT процесса,
три изолированных Core, loopback TCP, реальные FFI/ratchet/контейнеры.
Два sibling-источника отдают одинаковый архив; оба первых authenticated ответа
пришли до release первого apply. Seed/gates вне apply-window. **Sampling и
timeline выключены во всех трёх фазах**, полный observer раз в 1000 мс.

| Apply release → наблюдаемая сходимость, мс | 25579 | 22234 | 24522 |
| Release file → post-page inventory у обоих источников, мс | 24899,286 | 22017,854 | 24339,858 |

| Коммиты сообщений | 157 | 157 | 157 |
| HistoryApply callbacks | 20002 | 20002 | 20002 |
| Worker RPC в наблюдаемом окне | 25503 | 25258 | 25310 |

Полные 10000 архивных плюс одна прежняя строка проверены по IDs, телам,
delivered, canonical positions и порядку; нет пропусков/дублей/лишних строк.
Оба conversation cursor завершены, cold boot без A/E/C сохранил все 10001.
Capture/census не обрезаны, каждый forward query связан с полным ответом.
Cursor commits в окне: 160/159/160; это не заявляется снижением числа записей:
наблюдение завершается при сходимости, а не после всех фоновых операций pull.
Встречная выдача также варьировалась; её bytes не приписываются этому изменению.

Второй временной показатель пассивный: сохранён mtime файла release и по
private request ID найдены первые полностью наблюдаемые `list` после последней
страницы каждого источника. По production-порядку следующий запрос следует
после apply и durable conversation cursor. Время включает доставку этого
запроса до источника; это **не точная метка сходимости UI или CPU-время**.
Он не добавляет запросов/записей в приложение и отдельно подтверждает разницу
около 2,3–2,9 с без округления основного 1000-мс observer.

Query-at-source → full-reply P50: parent 102–106 мс, candidate 73–76 мс;
по 78 наблюдений на источник, первый gate-crossing ответ исключён. Full-reply
→ next-query-at-source у candidate остаётся P50 167–168 мс (77 наблюдений).
Эти стадии включают разные ожидания и не суммируются как exclusive CPU/I/O.
Результат относится к данному локальному JIT стенду; AOT/мобильная сеть не
квалифицированы. **Latency остаётся активной: около 22,2 с на 10000 строк.**

## Происхождение и уборка

В A/B/A проверены 1525 frozen inputs: один различающийся production-файл,
остальные 1524 одинаковы. Native SHA/mappings проверены, Rust не собирался,
candidate восстановлен. Все фазы и оба диагностических прогона завершены,
runtime удалён, собственных процессов/listeners нет. Телефон, пользовательские
контейнеры и production не затронуты.

Kernel cache 92→92 во всех фазах, новых entries 0; место во время измерений
не чистилось. Приватные raw-профили и ID не попадают в агрегаты.
Следующий объём по указанию владельца — **100000 сообщений**, с проверкой
лимитов стенда и стоимости observer. NETCALL-01 и остальная matrix открыты.
Коммит unsigned, push/релиза нет. [summary.json](summary.json).
