## Подтверждение

На исходном `dc6b89b5` две gate-проверки воспроизвели разные границы:

- исходящий текст истекает, пока обязательный publisher ожидает завершения;

  `tryStoreFilePair`; post возвращал успех с истёкшим телом в журнале.

Gate парной записи расположен после успешного commit, не в fallback:
`paired == true` обязателен. В native проверке сегмент с исходным телом
читается у gate. Доменное время сдвигается ровно на TTL перед release.
Это проверка границы продолжения после I/O, не замер реальных 30 с fsync.
Первый запуск с `--plain-name` вместо regex не выбрал тесты и не засчитан.

Дополнительные два red-теста обнаружили независимый обход первой правки:
`_save` запускает фоновую отправку полного snapshot при появлении новых
локальных epoch keys. В snapshot попадало уже истёкшее тело, включая сценарий
отказа scrub. Fixture добавляет ещё не переданный ключ в локальный заголовок
при остановленном сервисе, затем запускает обычный sender. Первый запуск
этих тестов имел ошибку синтаксиса cascade и не считается подтверждением;
после исправления fixture оба упали именно на наличии старого тела.

## Изменение

После required publisher общий `_store` повторно проверяет TTL/tombstone.
Отказ вызывает прежнее scoped удаление и возвращает null; существующие
nullable guards прекращают дальнейшие send/уведомления/autofetch.

Пакет device events сохраняется без change-notice и без epoch-key snapshot.
После commit заново проверяется TTL. Удалённые тела заменяются журналом
с local sequence floors и durable scrub obligation; очистка завершается
до подтверждения пакета. Повторные проходы только удаляют строки, их число
ограничено конечным журналом. Рабочее состояние берётся из результата `_save`,
включая admitted control/receipts, а не из черновика.

Только после успешной проверки/очистки запускаются change-notice, обычная
репликация и независимый key-share из окончательного committed bundle.
Сетевой key-share остаётся фоновым: медленное устройство не удерживает ingress.
Остальные `_save`/compaction вызовы сохраняют прежние defaults. Флаг notify
не используется как неявный переключатель передачи ключей.

Ошибка очистки возвращает неуспех без публикации/mark-shared. Durable marker
остаётся для восстановления. Повтор того же события после восстановления
завершает очистку; свежая настройка затем публикуется нормально. Native случай
также проверяет удаление исходной conversation row на точной границе TTL:
strict prune получает cutoff + 1 microsecond, как основной sweep.

## Границы

Закрыты проверенные post-publisher и paired journal completion границы,
включая независимый запуск key snapshot во время этого commit. Это не полное
закрытие TTL: время может истечь позже внутри асинхронной подготовки/передачи
snapshot или native handoff; edit I/O, неполные persisted transfers,
explicit/shared downloads, legacy NACK, policy/clock skew и остальная матрица
требуют самостоятельной квалификации. Storage API cleanup не означает forensic
erase физического носителя. Mailbox для своих устройств, APK, engine pins,
публичные сиды, push и релиз не менялись.
