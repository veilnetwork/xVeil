# NETCALL-01: сопоставление candidate-клеток с шестью реле

Дата: 2026-11-01. SDK `8e3fe2ce`, приложение на `b1da1058`.
Исправлен подтверждённый пробел диагностики. **Перерыв аудио при смене сети
не устранён**, правило независимых локальных каналов и таймауты не менялись.

## Исправление диагностического пути

Существующая `media.cell.sample` знала sealed header, а роль-нейтральная трасса
реле — SHA-256 непрозрачного payload. RTP-witness связывал их только для RTP;
контрольная проба без RTP header оставалась без такой связи. Теперь sampled
endpoint-запись дополнительно содержит SHA-256 **зашифрованных** байтов. Это
не новые данные на wire, не plaintext и не классификация приложения на реле.
Хеширование выполняется только при включённом прежнем `rt_trace` и его sampling.

Изолированный процессный regression был красным на прежнем коде именно по
отсутствию witness. После изменения он проверяет matching digest непрозрачной
контрольной клетки, отсутствие plaintext и отсутствие записи при выключенном
trace. Прошли 334 FFI-теста, 2 ignored отдельно; 14 Flutter privacy-тестов и
9 Python-тестов агрегатора. Корреляционные digests явно проверены на исключение
из анонимного пользовательского отчёта/агрегата. Rustfmt и diff check чисты.

## Физический прогон

Poco ↔ Windows 11, отдельные QA, Wi-Fi → cellular внутри аудиозвонка.
Перед cut требовались четыре последовательные свежие P2P-выборки на обоих
концах; ожидание этого условия ограничено 30 с. Оба endpoint сохраняли один
active call на всех 40 выборках после cut (около 41,5 с); в конце свежий RX был
на обоих концах. Непрерывный свежий audio RX не подтверждён. Максимальный sampled
native age — 14453/14713 мс; значения разных media epoch не образуют верхней
границы полного перерыва. Живую речь и исходный случай с одним узлом не проверяли.

На телефоне изменена только FFI-библиотека внутри замороженного APK. Dart AOT,
медиадвижок, остальные ZIP entries и signing certificate проверены неизменными;
несигнатурные META-INF entries сохранены. На Windows прежние опубликованные
библиотеки, включён существующий operator gate opaque Forward trace при запуске.

## Что теперь установлено

Две ранние 60-байтовые candidate-клетки имеют точный endpoint witness. Отнесение
к соответствующей попытке подкреплено непосредственным соседством begin и
первой клетки candidate; один размер plaintext-класс не доказывает.

| Наблюдение в часах телефона | Candidate 1 | Candidate 2 |
|---|---:|---:|
| Source queue age до SDK sample | 112 мкс | 182 мкс |
| SDK sample → IPC handler enter | 329 мкс | 422 мкс |
| Локальные relay queue admissions | Не наблюдались | Две, через 605/654 мкс |
| Дальнейшие source-события | Не наблюдались | Одна `budget_admit`, одна `child_unavailable` |
| Matching opaque receive в захватах шести реле | Не наблюдался | Не наблюдался |
| Matching opaque receive Windows | Не наблюдался | Не наблюдался |

`child_unavailable` привязан к тому же sealed epoch/sequence и означает реальный
локальный discard одной копии: согласованный независимый child ещё недоступен.
Обе копии сначала локально приняты для двух известных relay-prefix. После
локального discard одной копии другая прошла `budget_admit` — это не
доказательство успешного `send_before` или отправки на NIC. Её ingress на
этих реле в захвате не наблюдался. Эта граница сужает следующий
участок к source queue/child/transport телефона до первого хопа. **Весь перерыв
одному discard не приписывается**; поступление первой клетки в handler само по
себе также не доказывает дальнейший admission.

В выбранных хвостах шести relay-файлов 5947 opaque-наблюдений. Файлы append-only,
поэтому счётчики могут включать ранние записи sink и не считаются per-PID
счётчиками текущего звонка; извлечение ограничено последними 64 МиБ каждого файла. Для 12 из 33 endpoint samples
телефона найдены точные relay-witnesses, включая другую исходящую relay-клетку.
Это положительный контроль корреляции, но не доказательство полноты всех logs.
Notices о достижении trace-limit не было. Изначальный journalctl-запрос дал ноль:
service направляет stderr в файл; эти нули не использовались как отсутствие
приёма. Данные извлечены из реальных log sinks процесса без дублирования sink.

Данные не доказывают сетевые потери и не указывают на задержку обработки реле.
Полнота console capture отдельно не квалифицирована. Межхостовые wall clocks
не вычитались. Это не A/B: временные перезапуски реле изменили маршруты и кэши.

Следующая проверка — фактический результат `send_before` второй копии и readiness/
lifetime локального независимого child после замены parent session. Нельзя
сертифицировать маршрут через другой канал или отменять изоляцию источников
на основании одного наблюдения недоступного child.

## Реле и завершение

Все шесть production-реле были на Veil 0.11.47; бинарники и node.toml не менялись.
Трассировка включалась последовательными временными drop-ins с заранее
поставленными независимыми 12-минутными rollback timers. Первые три сервера
применили выбранный RUST_LOG; у остальных EnvironmentFile сохранил свой filter,
но фактические opaque records присутствовали на всех шести. Трасса ограничена
штатным row-limit, непрозрачными Forward payload и длительностью окна.

После захвата настройки возвращены последовательно. Независимая postflight
проверила 6/6: healthy/active, исходный loaded binary, неизменный config, отсутствие
drop-in, выключенный gate, восстановленную среду, неактивный timer и 0 auto-restarts.
Root-only локальные операторские журналы не опубликованы и не являются анонимными
пользовательскими отчётами. Агрегаты — в [summary.json](summary.json).

Оба QA остановлены, tasks/forward/tunnel/listeners отсутствуют. Первый Windows
listener-check после завершения был временно отрицательным; последующие TCP,
netstat и независимая повторная проверка подтвердили отсутствие listener и процессов.
Телефонный QA возвращён к прежнему APK с проверкой SHA и оставлен остановленным.
Настройки телефона и PID основного приложения сохранились, его контейнер не
открывался. Mac-стенд не запускался. Отдельные внешние Cargo targets и mount-watchdog
проверены; диск оставался отдельной ФС во всех сборках/тестах. Промежуточные
unsigned/aligned APK удалены; проверенные candidate и rollback APK сохранены.
Push, релиза и постоянного обновления сидов нет.
