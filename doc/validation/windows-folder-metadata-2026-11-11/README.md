# Windows: точность версии файла — 2026-11-11

## Подтверждённый дефект

При квалификации полного Windows SDK обычная ABI-проверка прошла, но замена
файла с сохранением предыдущей версии закончилась `FolderSyncLocalChanged`.
Это отдельный файловый дефект, не доказанная причина жалобы на звук/камеру.
Стенд работает на Windows 11; исходный пользовательский компьютер — Windows 10.

Временная метка `dart:io` на Windows теряет дробную часть секунды. Нативный
издатель сравнивает миллисекунды на реально открытом объекте. Поэтому даже
неизменённый файл не проходит контроль версии; сканирование также передавало
неверный stamp в план синхронизации.

Детерминированная регрессия задаёт время через независимый системный setter,
сравнивает `stat` и `scan` с метаданными того же объекта из полного SDK.
На прежнем клиенте native возвращает `1700000000123`, а Dart `stat` —
`1700000000000`; assertion падает именно на этом сравнении. Обычная замена
600017 байт тоже воспроизводит отказ без сети и гоняющего файл процесса.

## Исправление

Windows-адаптер читает размер и точное время через `NtQueryFullAttributesFile`.
Его [контракт Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-zwqueryfullattributesfile)
возвращает статус самой операции: отдельное чтение `GetLastError` не требуется.
Тот же источник метаданных используется при сканировании и проверке перед
заменой. Поддержаны UTF-16 и extended absolute paths. Отсутствующий файл
возвращает отсутствие; другие ошибки остаются отказом чтения, без подстановки
пустой версии. Directory/reparse entries не становятся обычными файлами;
пропавший при сканировании файл отмечается unreadable.

Это только чтение метаданных. Прежние containment/admission gates, нативная
публикация, точное сравнение вытесненного объекта и сохранение `.previous`
остались на месте. Сравнение не округляется до секунд. Новая SDK ABI или
запасной pathname publisher не добавлялись.

При разработке пойманы два промежуточных края: setter `dart:io` сам теряет
дробные секунды, поэтому для fixture используются `SetFileTime`/`utimes`;
получение `GetLastError` оказалось неустойчивым в расширенном FFI-прогоне,
поэтому промежуточный Win32-вариант отвергнут. Итоговый NT-запрос возвращает
статус непосредственно; файловая операция остаётся non-leaf. Эти промежуточные результаты не считаются проверкой
финального исправления.

## Проверки и границы

На настоящей Windows DLL проходят три SDK-only теста без пропусков: штатный ABI
gate с отрицательным контролем, точность `stat`/`scan` и публикация/просмотр/
экспорт/явное удаление предыдущей версии. Экспорт проверяет все 600017 байт и
единственный `finish`; новая текущая копия остаётся доступной. FS-only fixture
не подставлялся вместо SDK. На Mac прошли 147 связанных folder tests без skip
на полном SDK; анализ девяти изменённых Dart-файлов чист.

Расширенная Windows-серия: **137 прошли, 3 skipped, 0 ошибок**. Два пропуска —
прежние Unix symlink fixtures; третий — interposition через переопределённый
Dart `stat`, который Windows metadata adapter не вызывает. Он не считается
проверкой Windows last-window race; соответствующие native publication races
квалифицированы отдельно. В переносимых fixtures исправлены basename для
обоих разделителей, POSIX-only `chmod` и ожидание Windows admission lockfile.
Если открытый Windows read descriptor запрещает замену, тест подтверждает отказ,
сохранность исходных байтов, успешную отдачу прежней версии и отсутствие ложной
грязной строки; запрещённая операция не объявляется состоявшимся edit.

Исходники и выбранные DLL сверены SHA. Пользовательские контейнеры/файлы и
production-реле не менялись. Тестовые GUI-процессы и SSH-forward закрыты,
временные Windows interactive tasks удалены. Новые бинарники не опубликованы.
Ранее собранный profile-AOT frontend предшествует этому Dart-исправлению:
итоговую упаковку нужно повторить. Реальный AV-звонок и Windows 10 жалоба
этим раундом не закрыты.
