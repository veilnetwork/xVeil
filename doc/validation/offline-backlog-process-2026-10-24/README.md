# Offline B: большая история между отдельными процессами

## Результат: дефект воспроизведён, ещё не устранён

Три независимых процесса приложения с настоящими native-узлами и отдельными
зашифрованными контейнерами: A/B — одна личность, C — другая. Сеть стенда
локальная; публичные сиды не используются. Используются прежние тестовые
настройки PoW и контейнера, поэтому это не замер производительности релиза.

| Этап | Online | Результат |
| --- | --- | --- |
| Связать B, затем выключить его | A/B/C, затем A/C | Контакт C перенесён на B |
| Последовательно отправить 1000 сообщений A → C | A/C | Все запросы подтверждены; C получил все 1000 ID в порядке A |
| Выключить C, запустить B | A/B | За 180 секунд B восстановил только 154 из 1000 новых сообщений |
| Остановить B посреди восстановления и продолжить | Не достигнут | Ожидание первых 250 сообщений закончилось таймаутом |

Первоначальное приветствие из запроса на контакт учитывается отдельно:
у A **1001** строка истории, у B при остановке **155**, включая приветствие.
Проверка учитывает `total` ответа API, а не только его окно последних 1000 строк.
Повторное появление приветствия не объявляется дублем нового сообщения.

## Локализованная причина

Полная переписка остаётся в обычном хранилище A. Журнал device-sync ограничен:
`msgMirror` и `msgStatus` делят окно в 250 событий; уплотнение запускается после
400 строк. При снятии состояния в журнале A осталось **185** зеркал — сообщения
с порядковыми номерами теста 815–999. Старых зеркал там уже нет.

Обычный group anti-entropy обменивает сохранившийся журнал. Полный history replay
существует для добавления устройства и явного запроса, но возвращение B в этом
сценарии его не запускает. После превышения окна одного обмена журналами
недостаточно для восстановления всей истории со всё ещё работающего A.

Это не согласованный компромисс «A и C оба offline»: A оставался online.
Это также не доказательство безвозвратной потери данных — оригиналы есть на A.
Оставшиеся зеркала доходили не полностью; отдельную причину этого хвоста данный
прогон не устанавливает. Следующий шаг — восстановление из истории своего
доступного устройства с ограничением нагрузки и продолжением после обрыва.
Увеличение окна журнала само по себе не решает неограниченную offline-историю.

## Исправления и ограничения тестового стенда

* Добавлен gated cross-process тест на 1000 сообщений, восстановление, crash B,
  сравнение ID/порядка и повторное открытие без A/C. Сейчас он **красный** на
  этапе догрузки; последующие этапы не квалифицированы.
* Первый диагностический прогон обнаружил таймаут `testWidgets`: рабочий
  процесс A завершался через 10 минут вопреки библиотечной аннотации 4 часа.
  Таймаут теперь передан явно; второй валидный источник продолжал работать.
* Ещё один предварительный прогон исправил неверное предположение теста об
  отсутствии сохранённого приветствия. Эти предварительные запуски не
  учитываются как результаты доставки.
* Производственный код, протокол, размер журнала, mailbox и маршрутизация
  в этом цикле не изменялись. Обычный запуск без native-окружения пропускает
  этот gated тест; для реального прогона нужны настройки из `test/e2e/README.md`.

## Физический стенд

Подготовлены отдельные QA package/profile и текущие native-библиотеки для
Mac/Android. Mac прошёл подготовку личности до настоящего native-стека;
543 исходных Dart-файла сверены с рабочим деревом, кроме приватного callback
сохранения тестового сертификата. Он находится только в отдельном scratch,
производственный экспорт сертификата этим прогоном не проверялся.

Android остался заблокирован системным PIN. Передача 32 МиБ с отключением
источника **не начиналась**. QA-пакет удалён, временная настройка питания и
ADB forward восстановлены/удалены. Mac закрыт, его QA-профиль перенесён из
пользовательского каталога в приватные артефакты. Исходный APK телефона не
изменился. Все процессы трёх native-стендов завершены, контейнеры удалены.
Звонки не запускались. Push и релиз не выполнялись.

Это отдельный незакрытый сценарий матрицы multi-device, не её полный результат.
[summary.json](summary.json) содержит только агрегаты и хеши исходников.
Журналы, адреса, ID, ключи, пароли и контейнеры не публикуются. Исходный
незакоммиченный каталог `multi-device-2026-10-17` не изменён.
