## Топология и действия

A/B — личность X, C/D — личность Y; четыре отдельных OS-процесса на одном Mac,
настоящие native-узлы и зашифрованные контейнеры. Три локальных relay-процесса,
публичные seeds/discovery отключены. После штатной привязки и общей начальной
истории admin bans закрывают **все** межсегментные соединения всех семи узлов,
включая прямые device links и relay-to-relay пути:

| Сегмент | Живые устройства | Реле |
|---|---|---:|
| Первый | A, C | 1 |
| Второй | B, D | 2 |

Session tables проверяются на отсутствие межсегментных и неизвестных peers.
Каждое устройство отправляет четыре новых сообщения. Обе половины реально
обмениваются ими, противоположная половина до healing их не получает.
Процессы/native caches во время partition и merge не перезапускаются.

Одновременно A редактирует прежний пост X→Y, B удаляет этот же ID; A/B меняют
или удаляют реакцию X, D добавляет реакцию Y. Все четыре устройства отмечают
прочтение своей видимой истории. Снимаются только bans и восстанавливаются
native links; прямого приложения/инъекции журнала нет.

## Ожидаемое и фактическое состояние

| Вариант | До соединения | После соединения |
|---|---|---|
| Локальное удаление | A изменяет пост; B локально удаляет свою копию для X | A/B — по 17 записей, C/D — по 18, включая одинаковый отредактированный пост. Локальное удаление X не удаляет историю Y. |
| «Удалить у всех» | Дополнительный oracle требует правку у A/C и отсутствие ID у B/D при всё ещё отсутствующих cross-сессиях | Все четыре держат по 17 записей; удалённого ID нет нигде. Поздняя правка его не восстанавливает. |

В обеих ветках проверяются **все 16** новых сообщений и их ID, ровно одна
копия каждого, порядок четырёх сообщений каждого отправителя, одинаковые
упорядоченные логические представления A/B и C/D. Усилен oracle: требуется
точное количество строк и наличие исходного reaction target, а не только
равенство двух потенциально неполных списков.

Реакции сходятся у всех четырёх без двух actor slots одной логической личности.
Реакция Y сохранена; конкурентная реакция/отмена X разрешается одним общим
результатом согласно фактическому порядку событий. Read markers совпадают
внутри каждой личности и не меньше максимума двух прочтений до слияния.
После совпадения выполняются повторные проверки состояния ещё не менее
10 секунд. PID-списки всех устройств до/после merge одинаковы.

### Холодный B после «удалить у всех»

После уже подтверждённой сходимости A/C/D штатно остановлены, их exit codes
проверены. B перезапущен. Identity и physical device ID прежние; все 17
сообщений, их ID/порядок/направления/текст, отсутствие удалённого ID и реакции
совпали с состоянием до остановки. Read marker не уменьшился. Реле остаются
работать, другие app-источники не запускаются.

Mailbox для собственных устройств не добавлялся. Этот шаг проверяет сохранность
уже полученного состояния, а не получение новых данных при недоступных источниках.

## Границы

Это protocol-level partition через native admin API, а не kernel firewall,
смена мобильной сети или часы/сутки offline. Логические дубли/сходимость
проверены в указанных историях; физическое число post-записей этого сценария
отдельно не измерялось. Проверены выбранные конфликты, не все перестановки.
Cold restart не подменяет crash-cuts внутри decrypt/DB/fsync/ACK. Файлы, звонки,
TTL/clock skew, отозванные устройства и другие платформы здесь не проверялись.

Общая latency и оставшаяся multi-device матрица ещё открыты. Push, релиза,
обновления APK, публичных сидов или конфигураций production-реле не было.
