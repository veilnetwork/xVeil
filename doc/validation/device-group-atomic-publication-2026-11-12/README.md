# Атомарная публикация ключа и группы устройств

> Продолжение: [восстановление исторической неполной копии credential](../device-owner-credential-repair-2026-11-12/README.md)
> сохраняет прежнего владельца и сериализует repair с принятием другой группы.

Продолжение проверки обнаружило, что последовательность «ключ, затем указатель»
недостаточна при замене уже активной семьи. Отказ записи `devices.gid` оставлял
старую группу с новым ключом владельца. Это воспроизведено двумя настоящими
hybrid-группами разных владельцев; тест падает на предыдущем коде.

Теперь encrypted credential и `devices.gid` публикуются одним финальным KV-коммитом.
Подготовленные chunks резервируют свои ID до публикации. Потеря ответа подготовки
оставляет прежнюю пару; потеря ответа финального коммита может оставить новую,
но не смесь. Повтор безопасен, учёт сборки мусора проверен. Нет последовательного
fallback для storage без атомарной операции. Формат контейнера и native ABI
не менялись; обычная запись файлов сохраняет прежний путь.

Публикации сериализованы; getter группы и reader ключа не принимают устаревшее
чтение, пересёкшее публикацию. Ошибка сбрасывает тёплые кэши для чтения durable
состояния. Тот же publisher используется при создании и восстановлении семьи.
Отдельный red обнаружил удаление уже опубликованного ключа после потери ответа
восстановления. При неизвестном исходе валидированный encrypted credential теперь
сохраняется для повтора; известный отказ до публикации по-прежнему откатывается.

## Проверка

- **570 unit-проверок, 0 skipped**: полный GroupService и наборы файловой
  публикации/lifecycle. Восемь новых storage-проверок включают остановку до
  публикации, отказ, потерю обоих ответов, повтор, пределы и close-drain.
- **Два process-сценария замены существующей семьи, 0 skipped**: B сначала
  принадлежит другому реальному владельцу. SIGSTOP/SIGKILL до публикации сохраняет
  старую пару, после — новую. Ключ открывает именно владельца активного manifest.
  Cold-open выполняется без остальных клиентов и через новые реле; затем исходное
  согласие завершается без нового QR, проверяются сообщения, ID, порядок и история.
- **Четыре process-сценария свежего adoption, 0 skipped**: прежние точки до/после
  активации и поглощения согласия повторены через атомарный storage API.
- Targeted analyze и `git diff --check` проходят. Исходники всех трёх зачтённых
  наборов совпадают с финальными; native-входы проверены по SHA до и после.

Первый process-прогон замены выявил отдельный дефект debug-проводки: она пыталась
перечитать другую identity вместо предусмотренного перезапуска узла. Debug теперь
следует условию GUI; native-проверка соответствия identity не ослаблена.
Этот промежуточный прогон не засчитан как успешный и не объявлен дефектом GUI.

Стенд: macOS arm64/JIT, CLI/SDK `e963fbdb`, hidden-volume `293792d`.
Замена проверена через поддерживаемое приглашение без переноса документа личности;
это не все варианты переноса документов. SIGKILL приходится на границы storage API,
а не внутрь native commit или аппаратного сбоя питания. Не квалифицирует другие
ОС, GUI, часы/сутки offline и всю multi-device матрицу.

После зачтённых наборов собственные процессы и группы завершены, test VM отсутствуют,
учтённые TCP/UDP-порты свободны. Пользовательские приложения и серверы не обновлялись.
Это дополнительное частичное покрытие пункта 63.
