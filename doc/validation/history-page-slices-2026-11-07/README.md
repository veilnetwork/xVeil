# Меньше частей в ответе own-device history

Агрегаты: [summary.json](summary.json). База — `dc8fff71`,
[предыдущий разбор подготовки страницы](../history-local-encoding-2026-11-07/README.md).

## Изменение и прямое доказательство

Каждая часть проходит отдельную свежую проверку устройства и отправку,
а затем отдельную обработку у получателя. Двоичная часть выросла с 2 до
**4 КиБ**: с base64 и envelope она помещается в прежние **6144 байт**
`MAX_AUTH_DELIVER_MSG_BYTES` (`veil-proto/src/ipc.rs`). Такой размер уже
используется datagram-выдачей файлов; новый класс транспорта не добавлен.

Контрольный тест передаёт одну и ту же страницу из 32 сообщений: **37 частей
на базе → 19**. На прежнем коде assertion-red (37 вместо ожидаемых 19),
на candidate проходит. Fake network отдельно проверяет размер **каждого**
application frame ≤6144; формат события, row count и переданные тела прежние.

Предел страницы **128 КиБ** теперь задан отдельно от размера и количества
частей. Иначе удвоение slice молча разрешило бы 256 КиБ. Проверка на стороне
отправителя и новый суммарный byte check на приёмнике удерживают прежний
предел. Превышающий part не занимает slot и не закрепляет его метаданные.
Приём до 64 частей сохранён; собственный отправитель укладывается в 32.

Base64 cap — 5464 символа, body guard — 6000 символов вместо 5000; это
позволяет принять корректный 4-КиБ part. Отдельный decoded cap обязателен:
4096 и 4097 байт имеют одинаковую base64-длину. Общие admission budgets
(1 МиБ / 512 frames, 256 КиБ на peer), 32 устройства, 32 строки страницы,
лимиты record/reassembly, таймеры и retries не увеличены. Кэш прав не добавлен;
fresh authorization перед каждой частью, приёмом, применением и durable
publication сохранён. Sibling mailbox не добавлен.

## Проверки границ

**96 related tests passed, skipped 0; analyzer/format/diff checks чисты.**
Существующие проверки revoke, binding replacement, потери/повтора частей,
reverse order, cursor, крупных records и отказов durable-записи прошли.

Новые проверки:

- Страница ровно **128 КиБ** принимается с 4-КиБ slices.
- Те же корректные JSON bytes плюс один whitespace byte отклоняются до
  применения и изменения cursor. Следующая корректировка последнего part
  того же запроса завершает исходную страницу: лишний part не удержан.
- Валидный JSON размером **4097 байт** в одном part отвергается; тот же slot
  принимает исправленные 4096 байт.
- Контрольная исходящая страница использует 4-КиБ slices в 6-КиБ wire bound.

Отдельные mutations без суммарного byte cap, без decoded-part cap и с
увеличенным page budget дали три assertion-red. Production source после
каждого восстановлен побайтно; в native-серию попала окончательная версия.

## Native crash/reconnect

Три процесса A/B/C на одном Mac, две личности, три loopback Core, реальные
SDK/ratchet/HVS, JIT/provider fixture без полного foreground SessionPipeline.
CPU/VM profiling выключен. Native libraries прежние; SHA и actual mappings
проверены. Windows и Poco не участвовали в этом history-прогоне.

При 624 наблюдавшихся строках B завершён `SIGKILL` (−9), оба источника
остановлены. До создания сети новый B прочитал **687** строк: все исходные
624 ID, тела/delivered и 574 уже canonical positions сохранились; дополнительные
63 in-flight строки принадлежат полному ожидаемому набору, дублей нет.
При offline A/C частичная история остаётся. После возврата только A все
**2000/2000** ID, тела, итоговый порядок/позиции и delivered сходятся.
Completed-history retries — 0. После ещё одного запуска B при снова offline
источниках все 2000 ID/тел/статусов/позиций сохранены **до сетевого старта**.

**Это не контролируемый A/B/A:** различаются crash/in-flight, объём работы,
кэши и scheduling. Encode A/B: 1343/188 → 1287/316; roster census A/B:
888/3737 → 1023/3474. Поэтому общий выигрыш и изменение суммарных lookup
нельзя приписать только slice. Прямо доказано уменьшение числа кадров
для одних и тех же bytes; на стенде median part count также снизился.

Следующий крупный интервал остаётся на стороне получателя: около **535 мс**
между last-part ingress и следующим source query. Он включает разбор,
допуск, приложение/storage, очереди и transport, не равен чистому CPU или
сетевому RTT. Догрузка остаётся активной задачей; безопасный дальнейший шаг —
разложить этот интервал, сохранив свежие admission/publication checks.
Ускорение WAN/мобильной сети и качество при потерях этой серией не доказаны.
