# Новая recovery-сборка: Poco, локальные наблюдения и handover

**NETCALL-01 остаётся активным.** SDK `5d89beb5` собран и проверен на Poco,
Mac и двух изолированных Core. Три завершённых QUIC-контроля не повторили
прежнюю паузу 5,6 с; это не доказывает её устранения. В отдельном TCP-звонке
Wi-Fi → Cellular повторил **8,598-с возраст последнего audio RX** на Mac.
Встречный переход прошёл без такой паузы. Один и тот же звонок сохранился.

## Сборки и границы проверки

Android arm64/API 24/NDK 28.2 и Mac FFI собраны с
`allow-empty-seeds,node-embedded,packet-tunnel`, без default features;
Core — статический Linux x86_64 musl с `testnet-seeds`. Все три guarded
release-builds успешны, внешний mount не терялся. SDK оставался чистым;
1533 tracked source files совпали с предварительным snapshot после прогонов.

ELF/архитектура, отсутствие внешнего ELF interpreter у Core, 208 C exports,
неизменность исходников C API и подпись Mac dylib проверены. Выбранные бинарники
отличаются от предыдущей сборки; проверены SHA фактического APK и отображённая
в процессе Mac библиотека. В APK обновлена FFI; для QUIC дополнительно изменены
только два seed assets. AOT, медиадвижок и HVS прежние, signer и 16-KiB alignment
проверены. Это квалификация нового SDK на замороженном frontend, не всех
накопленных Dart-изменений приложения.

Два QA Core: только явные peers/seeds, discovery/PEX отключены, own advertise
и адрес другого Core проверены. Настоящие listener PID/протокол и session URI
соответствуют фазе; до звонков оба Core видели другого Core и обоих клиентов.
P2P denied, во всех active samples media transport relay. Production не менялся.

Предыдущие **703 session + 173 transport passed / 8 ignored** относятся к
коммиту recovery-фикса и здесь не суммируются заново. В этом раунде исходники
SDK не менялись: выполнены три cross/native builds, packaging/ABI/provenance
checks и физические проверки.

## Прерванные попытки не засчитаны

Первая QUIC-попытка завершила один 60-с контроль; второй звонок после готовности
потерял control observation. Следующий отдельный прогон также остановился
из-за ADB. В обоих случаях телефон затем был виден с новым transport ID,
ADB forwards исчезли, но PID xVeil совпал с PID начатого logcat. ADB-сервер Mac
не перезапускался. Это не доказательство падения приложения или audio loss.

В первой попытке третий звонок не выполнялся; во второй не выполнялись второй
и третий. Два прерванных звонка не засчитаны ни как квалификация аудио, ни как
product failures. После каждого собраны остаточные наблюдения, подтверждены
прежний QA PID и восстановление ADB, завершены свои вызовы/стенды и выполнен
новый preflight. Timeout наблюдателя не использовался как повод перезапустить
ещё работающий процесс приложения.

Всего **7 начатых звонков**: 5 полностью наблюдавшихся, 2 с прерванным
наблюдением. Среди полных — четыре отдельных Cellular/QUIC-контроля (один из
первой попытки и три в последней) и один TCP-звонок с двумя сменами сети.

## Локальный наблюдатель телефона

Для последних двух фаз дополнительно запущен bounded collector на самом Poco:
GET `/call_state` через loopback, проверка неизменного QA PID, начало/конец
запроса по wall clock и uptime. Он не использует ADB для каждого sample.
Ключ — в private header file, не в argv; случайный каталог принадлежит shell,
mode 0700, файлы 0600. Lease ≤900 с и ограничение размера. Трафик приложения,
wire и native counters этим не меняются; диагностическая нагрузка добавлена,
поэтому A/B ускорение не заявляется.

В TCP-фазе получены **291/291** успешных локальных HTTP-записей, maximum request
100 мс, maximum sample-start gap 830 мс. В последней QUIC-фазе — **300/300**,
90 / 780 мс. Clock-probe intersections: 49,728 / 47,498 мс. Local RX counters
в каждом полностью содержащемся case window продвинулись без регрессии.
GET-only repair host forward никогда не повторяет mutating request; в двух
этих фазах repairs не потребовались. Реального ADB-разрыва в них не было,
поэтому survival локального collector при таком разрыве физически не заявляется.

## Завершённые случаи

После свежей пятисрезовой серии с ростом native RX counter — 60 с наблюдения
на каждый Cellular-контроль. TCP: 35-с Wi-Fi baseline и по 60 с после реального
отключения/включения Wi-Fi, с проверкой validated target network и прежнего
call ID/PID. Финальный критерий — последние пять samples с age ≤1000 мс
и ростом RX counter. **Он не означает отсутствие пауз внутри всего звонка.**

| Случай | Host-observed RX age max: Poco / Mac, мс | Финальный критерий |
|---|---:|---|
| QUIC, первый полный контроль | 1218 / 1193 | Пройден |
| QUIC, последняя серия №1 | 1319 / 1247 | Пройден |
| QUIC, последняя серия №2 | 967 / 1183 | Пройден |
| QUIC, последняя серия №3 | 720 / 913 | Пройден |
| TCP Wi-Fi baseline | 342 / 354 | Пройден |
| TCP Wi-Fi → Cellular | 1341 / **8598** | Пройден после восстановления |
| TCP Cellular → Wi-Fi | 367 / 357 | Пройден |

Локальные maximum RX ages Poco отличаются из-за другой сетки sampling:
1082 / 880 / 386 мс для трёх QUIC-контролей; 342 / 1330 / 420 мс для TCP-фаз.
Это независимые наблюдения одного counter, не улучшение между измерениями.
Краткие интервалы около секунды без двух строго внутренних peer TX samples
не объявлены доказанными сетевыми потерями или проблемой DTX.

В последней QUIC-серии в Core-логах не наблюдались recovery events. Таким
образом, это проверка работоспособности новой сборки в реальных звонках,
а не физическое доказательство исправления ложной отмены replacement.
Сравнение с прежней серией не является контролируемым A/B.

## Что установлено для 8,6-с паузы

Mac audio RX counter стоял во внутреннем интервале **8501 мс**, native RX age
достиг 8598 мс. Host observer внутри этого интервала видел 15 phone samples
с audio TX payload counter **+36**. Независимый local collector подтвердил
тот же **+36** по 12 полностью внутренним записям. Молчание источника и одна
лишь потеря USB-наблюдения этого эпизода не объясняют. TX counter всё ещё
не равен wire delivery каждой аудиодатаграммы.

С консервативными границами часов:

- Core A не видел phone-origin media-marker Forward внутри своего окна
  6539 мс. Core B видел 34 за внутренние 7660 мс; всем 34 найден единственный
  Mac-directed TX witness в пределах захвата.
- Mac observer видел 36 входящих media-marker Forward в RX-gap. В native
  stats при стоящем audio RX продолжал расти общий engine RX.
- Один sparse sender sample из отдельного **feedback sender** однозначно
  совпал с authenticated receive sample Mac по полному opaque payload SHA,
  epoch/sequence/длине. Он прошёл внутри паузы за **71,269–120,997 мс** с учётом
  clock bounds. Это реальный приём одного feedback packet, не только local
  admission на Core.

Следовательно, в эпизоде есть живая ветка обратной связи при отсутствии
прогресса audio RX. Это не означает, что все 34/36 marker frames были feedback
или аудио. Epoch не классифицирует их: feedback намеренно использует primary
cipher. Sparse RTP sampling не дало достаточной поклеточной связи для
недостающих audio payloads. Полный интервал нельзя приписать одному TCP flow,
реле, replay window или очереди без этой связи.

Следующий участок — **audio producer/send pump/admission/выбранный carrier
после handover**, отдельно от работающего feedback-пути, с endpoint RTP
witnesses и привязкой к реальному исходящему соединению. Общую исправность
сети по одному быстрому feedback packet не объявляем. Громкость, слышимость
человеком и акустическое эхо этим прогоном не проверены.

## Завершение стендов

Во всех четырёх попытках свои Core/capture/observer остановлены и их данные
собраны с SHA-проверкой каждого файла. QA units/config/state/runtime/binaries
удалены, порты освобождены; production PID/binary/config прежние. Journal tail
limit не достигнут, capture size bounds не сработали. На Mac точные процессы
завершены (после grace потребовался SIGKILL), runtime удалены, подпись проверена.

На Poco восстановлены QA APK, mic permission, Wi-Fi/mobile/stay-on/P2P;
unknown root QA container и основной APK побайтово прежние. Оба локальных
collector завершились, записи скопированы и сверены, private device directories
и header keys удалены. После cleanup отдельно проверены доступный ADB,
отсутствие своих collector commands и каталогов. Сырые журналы, адреса,
полные идентификаторы, epoch/sequence values и payload hashes в отчёт не включены.

Коммитов SDK сверх `5d89beb5` нет. Push/релиза и sibling mailbox нет.
