# Этапы family-send и повторная проверка Mac/Android — 2026-10-30

SDK `df6edab1`, Dart xVeil `cf9ffe7f`. Продолжение [сбоя обратного предложения
файла](../cert-slot-binding-2026-10-30/README.md) и [ограниченного параллельного
поиска сертификатов](../family-cert-concurrency-2026-10-30/README.md).

## Исправление диагностики

`ipc.send_slow` прежде не учитывал время family-ветки: после её неудачи журнал
мог показывать `path=unknown plan_ms=0 seal_ms=0`, хотя внутри прошло 30 с.
Теперь attempted family path записывается до вызова, а запись медленной отправки
содержит `family_resolve_ms`, `family_seal_ms`, `family_admission_ms` и
`family_certificates`. Это длительности и число найденных сертификатов, без
новых адресов/ключей/содержимого сообщений. Прежние поля сохранены.

`resolve` включает fallback на локальный кэш после deadline; `seal` включает
ожидание durable host reservation; `admission` — ожидание принятия исходящим
каналом. В mixed direct/family пути значения family не следует складывать с
параллельными direct-измерениями как последовательные интервалы. Порог записи
остаётся 1 с: отсутствие строки не доказывает отсутствие вызова.

Политика отправки, таймауты, ratchet-барьеры, wire/C ABI, mailbox и relay QoS не
менялись. Прошли **193 IPC unit-теста** (5 ignored), **326 FFI unit-тестов**
(2 ignored); внутренний subprocess не прибавлен, 5 ignored doctests отдельно.
IPC Clippy `--lib --tests -- -D warnings`, rustfmt и diff-check прошли.

## Физическая серия

Blackview по Wi-Fi и Mac — две разные личности. Второй Mac той же личности,
что телефон, оставался offline. После 30 с warmup отправлены пять новых файлов
по **3 145 979 байт в каждом направлении**, начиная с Android → Mac. На получателе
до загрузки проверено отсутствие локального файла; после — точное совпадение
SHA-256. Звонки не запускались. Для контактов на время серии сохранён `p2p=deny`,
глобальный anonymous routing выключен; файлы запрашивались через anonymous stream.
Это не означает, что вся управляющая доставка использовала одну family-ветку.

| Направление | Целые файлы | Загрузка: min / median / max | Предложение видно: median / max |
| --- | ---: | --- | --- |
| Android → Mac | 5/5 | 9,122 / 12,138 / 33,952 с | 1,574 / 2,117 с |
| Mac → Android | 5/5 | 6,798 / 9,075 / 37,042 с | 1,013 / 3,724 с |

Время загрузки включает API-запрос, наблюдение завершения и проверку хеша;
время предложения измерено отдельно, начиная перед API отправителя. Прежняя
недоставка предложения за 120 с **не повторилась**. Это не контролируемое A/B:
маршруты/состояние соединений не фиксировались между прежним и новым прогонами.
Нет доказательства, что именно правки сертификатов устранили тот сбой.

Десять `ipc.send_slow` записей обоих процессов дали максимум 4257 мс, без
ненулевых family-метрик. Медленная family-ветка в них не воспроизвелась; операции
быстрее 1 с эта диагностика вообще не записывает. Поэтому физическая серия не
доказывает ускорения именно `certs_for_instances` и не атрибутирует прежние 30 с.

## Продвижение байтов и оставшиеся ожидания

Вместо интерпретации записей 256-КиБ проверенных частей как сетевой тишины
использован [анализатор native prefix](../../../scripts/analyze_onion_stream_progress.py).
На каждом конце выбран ровно один process log, без дублирования logcat/stdout.
В каждом есть пять крупных Rx-наблюдений с продвижением больше 2 МиБ.

| Срезы | Android | Mac |
| --- | ---: | ---: |
| Native driver summaries | 311 | 315 |
| Наблюдаемые stream | 10 | 10 |
| Stream с RTO-событиями во всём окне | 2 | 2 |
| Максимальный RTO / SRTT | 10000 / 1062 мс | 10000 / 813 мс |
| Established zero-window samples | 0 | 0 |
| Максимальный промежуток наблюдаемого продвижения крупного Rx-prefix | 1063 мс | 1375 мс |

Максимальный промежуток между записями проверенных частей — 5,606 с; он не равен
сетевой тишине. Prefix-срезы также не доказывают непрерывность между наблюдениями
и не устанавливают место потери DATA/ACK. В отдельных RTO-срезах видны
`pending=8, inflight=0`: это может быть состояние сразу после rewind по RTO,
а не доказательство, что восемь байт никогда не отправлялись. Причина этих
ожиданий/закрытий ещё не установлена. Все причины жалобы «33%» не закрыты.

70 power-срезов внутри интервалов загрузок: QA foreground, Awake, charging,
оба Doze ACTIVE во всех 70. Это исключает Doze именно в этих наблюдениях;
жалоба о работе при выключенном экране остаётся отдельной проверкой.

Числа отдельных передач и агрегаты: [summary.json](summary.json). Публичная
сводка не содержит endpoint/content IDs, IP, путей профилей, паролей, ключей,
текстов сообщений или абсолютного времени. Raw evidence сохранён приватно.

## Происхождение сборки и завершение

Дерево Dart сверено по всем файлам с предыдущим current-source snapshot;
оно не изменилось. Новые release native-библиотеки собраны из чистой SDK
`df6edab1` с `--no-default-features --features
node-embedded,production-seeds,packet-tunnel`. Из target предварительно удалены
release-артефакты изменённых IPC/runtime, stream и FFI пакетов. Mount/device
внешнего target проверялись до и во время сборок.

В существующих Mac JIT / Android profile-AOT QA-артефактах заменена только Veil.
Все остальные распакованные Android ZIP payloads, включая Dart AOT и другие
native-библиотеки, совпали с предыдущим current-source candidate; сертификат
подписи QA сохранён. SHA и новый диагностический marker проверены на обеих
библиотеках, фактически загруженный Mac dylib сверён через `lsof`. Установленная
Android APK проверена по SHA до запуска. Это QA profile-AOT, не опубликованный
release APK и не Windows-квалификация.

Исходная QA APK восстановлена с точным SHA, основной клиент/данные не менялись.
Тестовые Mac/Android процессы и logcat завершены, API-порты свободны. Настройки,
debug property, ADB forward и прежний owner metadata восстановлены; тестовые
временные файлы на устройствах убраны. Реле не менялись. Коммиты без подписи;
push/релиза нет.

Открыты причина прежней односторонней недоставки, RTO/скорость файлов, Windows 10,
тихий звук, естественное завершение звонка около 25 с, sleep Android, legacy
group tails и оставшаяся multi-device матрица. Эта серия их не заменяет.
