# Аварийный перезапуск получателя большой истории

2026-11-03. Продолжение [проверки receive-cert и 2000 сообщений](../history-receive-cert-2026-11-03/README.md).

## Что проверено

Три отдельных native Mac/JIT стенда A/B/C: A и B одной личности, C другой.
В каждом A реально отправляет C 2000 сообщений; перед привязкой B проверены
полный набор на C и delivered на A. Это не заполнение через тестовый append.
B принудительно завершается SIGKILL во время догрузки. Сразу после перезапуска,
до открытия сети, отдельный инспектор читает его encrypted container: наблюдается
непустой, ещё неполный набор уникальных сообщений. После восстановления проверены
все ID, итоговый порядок, исходные позиции и delivered; повторов и пропусков нет.

Последняя часть каждого сценария: остановить A/C, нормально перезапустить B,
проверить полную историю на диске до сети и повторно через приложение. Новые
данные при одновременно offline обоих источниках не ожидаются. Mailbox для
собственных устройств не включён; relay transport остаётся допустимым.

| Фаза | Строк перед SIGKILL / на диске до сети | A/C при возврате B | Полная согласованность от возврата linkProcesses | После последнего рестарта без A/C |
| --- | ---: | --- | ---: | ---: |
| Первый прогон | 1272 / 1272 | Оба online | 57,565 с | 2000 |
| Источники остановлены | 1597 / 1597 | Оба offline, затем только A online | 203,447 с | 2000 |
| Отдельный инспектор | 1747 / 1747 | Оба offline, затем только A online | 203,570 с | 2000 |

Во всех трёх получен exit code **−9**, а не обычный выход. Завершившаяся до
порога передача, отсутствующий crash или пустой oracle проваливают тест.
В последних двух сценариях B сначала проверен через API при offline A/C:
1597 и 1747 строк соответственно; затем возвращается только A. C остаётся
выключенным до конца догрузки. Повторов уже delivered-истории в журнале — 0.

Время считается родительским Stopwatch после возврата linkProcesses, включая
остановки и перезапуски. Это не время от QR или первого сетевого кадра.
Опрос примерно раз в пять секунд; значения обозначают первые наблюдения,
а не точные внутренние моменты. Во второй фазе все ID уже видны на 193,204 с,
но позиции/порядок окончательно совпали на 203,447 с. В третьей оба критерия
совпали в одной выборке. Итоговая сходимость не означает неизменный промежуточный
порядок во время восстановления.

## Границы стенда

Первые два прогона читали pre-network witness через storage owner, который
затем использовало приложение. Это могло прогреть его projection cache.
В третьем fixture исправлен: отдельный inspector закрывается до создания
application storage owner. Прогрев OS/native файлового кэша этим не исключён;
это проверка сохранности после crash, не сравнение холодной производительности.
Ревизии fixture между сериями различаются; внутри каждой серии исходники
заморожены. Default-сценарий без opt-in crash flags сохранён.

Не моделировалась остановка на каждой отдельной инструкции fsync/ACK/ratchet.
Это SIGKILL процесса в наблюдаемой середине настоящей догрузки, а не полное
покрытие crash-consistency матрицы. Телефон, Android/AOT, revoke/partition и
длительный offline этим раундом не квалифицированы.

## Подтверждённая оставшаяся задержка

При возврате только A количество видимых строк B оставалось неизменным:

| Фаза | Видимых строк | Интервал последовательных одинаковых выборок | От готовности вернувшегося A до полной согласованности |
| --- | ---: | ---: | ---: |
| Источники остановлены | 1647 | 102,345 с | 153,587 с |
| Отдельный инспектор | 1772 | 117,662 с | 148,536 с |

Это **не сетевая тишина** и не потеря истории. В полном wire probe второй фазы,
без dropped probe records, после рестарта идут 253 уникальных запроса: два list
и **251 page**. Включая служебную предварительную строку, заново обходится
вся история по восемь записей, хотя большая её часть уже хранится на B.
Production путь при несовпадении inventory начинает page с начала и вызывает
обычный apply для удержанных строк. Это подтверждённая лишняя работа; вся
задержка не приписывается только сети или только диску. Ускорение этим циклом
не заявлено. Следующий шаг — безопасное подтверждение совпадающей части истории,
без пропуска несовпавших edits/status/позиций и без продвижения durable cursor
по одному лишь локальному предположению.

## Отдельный исправленный дефект сравнения порядка

Inventory digest учитывал ID, текст, emoji, edit frontier, delivered и reflected
edit, но не канонические координаты порядка. Равные тексты могли скрывать
промежуточную позицию echo; страницы ремонта тогда вообще не запрашивались.
Теперь digest включает `orderAuthor` и `orderSeq`. Использованы именно getters:
исправленная ordering metadata не должна подменять исходные raw author/seq.
Flag provenance сам по себе в fingerprint не добавлен.

Регрессионный тест ждёт завершённый durable inventory pass. До изменения —
**1 failed**: сообщение осталось с provisional order author вместо исходного
устройства. После — **1 passed**, нужная page запрошена, order исправлен, тело
и статус сохранены, raw author/seq не повышены до авторства оригинала,
поддельного source-device journal event нет. Дополнительный тест проверяет
обратную границу: уже исправленная canonical ordering при разных raw author/seq
не вызывает повторной передачи страниц. Его первый запуск не засчитан:
исправлена ошибка fixture, использовавшего неподдерживаемый copyWith argument.
Общая окончательная серия истории, backfill, mirror/ordering/ACK/concurrency:
**139 passed**. Analyzer пяти изменённых Dart
файлов — без ошибок. Этот fix исправляет корректность сравнения, не задержку
повторного обхода 251 страницы.

Три большие crash-серии выше выполнены **до** изменения digest. Их нельзя
объявлять физической квалификацией нового fingerprint; для него отдельно
проверен native oversized-record recovery на окончательном Dart-коде: три
записи, включая 160015 байт, восстановлены без C и без device journal на A.
Все ID/тела/source positions/delivered совпали, дублей 0; после отключения A
и повторного запуска B история сохранилась. Первая новая строка наблюдалась
через 2,616 с после API ready B, все три — через 14,553 с от запуска B,
включая 10,467 с его старта. Это функциональная квалификация wire-пути,
не воспроизведение provisional-order дефекта и не сравнение скорости.

## Происхождение и остановка

Использована та же SDK `b8647716`, новая Rust-сборка не делалась. Перед/после
каждого стенда сверены binary SHA CLI/FFI и HV с сохранённым build proof
(1524 tracked SDK files, lockfile, features, новый marker); внутри каждой
большой серии отдельно неизменны 1400 frontend/test/dependency файлов.
Три cleanup-проверки: **23/25**, **26/32**, **25/31** owned PID/портов;
живых owned процессов и listeners нет, runtime directories удалены,
SDK чистый, библиотеки не изменены. Сырые traces, идентификаторы, пути
контейнеров и ключи остаются в закрытых локальных evidence, в отчёт не включены.

Малый native-контроль также завершён: 21 PID и 21 порт, оставшихся owned
процессов/listeners нет, runtime удалён, 1400 source hashes и binary/HV SHA
сошлись. Изменений публичных сидов, push и релиза нет.
