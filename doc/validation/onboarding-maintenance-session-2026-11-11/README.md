# Создание личности после «Начать заново» и незавершённые операции

Продолжение [подготовки сжатия](../compaction-collection-session-2026-11-11/README.md).

## Подтверждённые дефекты

`completeOnboarding` не участвовал в допусках к общему хранилищу. После
`startOver` новый create мог заменить handle ещё выполняющегося password
probe. Два create также могли выполняться одновременно. В обратном
направлении unlock, probe и rewrite могли обращаться к незавершённому create.

До `_enterSession` создание не проверяло исходный lifecycle. Lock/startOver
в промежутках open → чтение → запись профиля → prefs → node config не
останавливали следующие операции. Откат ошибки мог после lock вернуть
`onboarding`, а ошибка подготовки внутри open оставляла принятый handle
незакрытым. Wipe не ожидал принятого create.

18 управляемых сценариев отвергли прежний контроллер. Контроль повторён
с окончательным тестовым файлом и заменой только `app_controller.dart` на
HEAD родителя; **0 passed / 18 failed**, без ошибок компиляции. Исправленный
файл восстановлен в finally с проверкой SHA-256.

## Изменения

- Create владеет хранилищем от допуска до завершения успеха либо cleanup.
  Конкурирующие создание, unlock, probe, begin и rewrite не принимаются.
- Lifecycle проверяется после асинхронных границ перед следующими записями
  и перед публикацией успеха. Отмена завершает Future ошибкой, чтобы вызывающий
  UI не продолжал применение архива как после успешного создания.
- В cleanup включён open, в том числе отказ после принятия native-handle.
  Закрывается захваченное хранилище; допуск снимается через finally.
- Откат не меняет phase и prefs завершившейся сессии. Удаляются только
  временные onboarding-intents; поздний cleanup не возвращает экран onboarding
  после lock.
- Барьер перед wipe также ожидает create и его cleanup. Забыть Future
  native-worker недостаточно, чтобы отменить его доступ к файлу.

Формат контейнера, Argon-политика продукта, список сохраняемых пространств
и native rewrite не менялись. Отмена не обещает откат уже принятого native IO:
создание пустого пространства может завершиться до обработки отмены.

## Управляемые проверки

`test/onboarding_maintenance_lifecycle_test.dart`:

- Lock/startOver на пяти этапах: до и после open, чтение конфигурации,
  запись профиля, запись node config.
- Отсутствие последующих записей/открытий, сохранение конечной phase,
  освобождение допуска и сохранность исходной личности.
- Новый create во время probe после startOver; два одновременных create;
  отказ после принятия handle и успешный повтор.
- Wipe при незавершённом create, lock во время rollback-close.
- Probe/rewrite во время отменённого create и create во время unlock.

В раннем wipe-fixture отсутствовал storePath в boot-конфигурации: приложение
не знало о синтетическом файле и закономерно не удаляло его. Fixture исправлен;
итоговый parent-red выполнен с известным приложению путём. Event-queue marker
проверяет ожидание без порога длительности. Новые тесты запрещают native-node
boot, даже при ошибке допуска; реальные сети не используются.

## Реальная hidden-volume / macOS

`test/native/onboarding_maintenance_lifecycle_test.dart`: два прогона
с настоящим `workerSpaceOpener`. Worker уже открыл контейнер под exclusive
flock и создал новое пространство, но его ответ удерживается до принятия
в `HiddenVolumeStorage`.

1. Lock: новый unlock не входит в opener. После освобождения ответа create
   отклоняется, handle закрывается, приложение остаётся locked. Свежий worker
   открывает исходный пароль: профиль и файл 70000 байт точны. Новый пароль
   открывает пустое пространство без профиля — уже принятое native-создание
   не выдаётся за полностью откатанную транзакцию.
2. Wipe: файл остаётся до освобождения worker; после cleanup wipe завершается
   без оставшихся объектов, файл отсутствует, facade закрыт.

Использована заранее собранная hidden-volume 2.7.0 macOS, SHA-256 проверен
перед запуском:
`a1c9a791ca186a7aa432e736565da07c897087617397fe19cf24e9b87f290fa8`.
В synthetic native-контейнере ArgonPreset.min: это проверка ownership и
сохранности, не скорости или Android KDF-параметров. Rust не собирался.

Исходная потеря доступа обоими паролями после сжатия по-прежнему не
воспроизведена. Это не её доказанная причина и не Android/crash-квалификация.

onboarded-маркер до `unlock` и может принять проигнорированный unlock за успех.
Его собственная граница допуска и rollback маркера — следующий участок;
текущая серия не объявляет весь onboarding/reopen атомарным.
