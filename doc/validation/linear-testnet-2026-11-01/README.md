# Стенд: звонок через линейный testnet из шести серверов

Запрос владельца от 2026-11-01. **Статус: подготовка; цепочка и звонки ещё не
квалифицированы.** Production-клиенты и текущие production-службы не являются
участниками этого стенда.

## Требуемые сценарии

Транспортная связность серверов должна иметь ровно пять рёбер:

`C1 — S1 — S2 — S3 — S4 — S5 — S6 — C2`

Нумерация S1…S6 закреплена в приватном deployment manifest по существующему
списку шести production-серверов. На каждом используются отдельный testnet
процесс, тестовая личность, каталоги, admin/IPC и новые listen-порты.
Существующие production и ранее работающие testnet службы не перенастраиваются.

1. При разрешённом P2P — C1 и C2 должны установить прямой media path после
   доставки signaling через testnet. Проверяется реально выбранный канал и
   приём payload, а не только предложение `p2p` в сигнале.
2. При запрещённом P2P — media должна идти через все шесть S-узлов по линии.
   Фактические сессии и транзитные наблюдения должны исключить shortcut.

Для первых проверок предполагаются изолированные профили Poco и Mac; это
не физическая квалификация Windows 10. Разборчивость живой речи не выводится
из одних пакетных счётчиков.

## Что уже сделано

- Шесть серверов прочитаны по SSH. Production active, NRestarts=0 на исходном
  срезе; PID, SHA запущенного бинарника и конфига сохранены приватно для сравнения.
- Собран отдельный статический Linux x86-64 binary с `testnet-seeds`, без
  default features. Использован отдельный внешний target, mount watchdog,
  снимок source tree. Повтор после test-fixture-only правки дал те же байты.
- Бинарник доставлен в отдельный каталог на каждом сервере. SHA и реальный
  `--version` smoke прошли **6/6**. Это не запуск тестовых узлов и не проверка
  их маршрутизации.
- Локально созданы шесть новых тестовых идентичностей с PoW 25; секретные
  конфиги имеют mode 0600 и не входят в репозиторий. Production-ключи не копируются.
- На S1 проверен IP-фильтр отдельной transient systemd-службы: контрольное
  соединение к собственному loopback listener проходит, с IPAddressDeny=any
  блокируется, с явным IPAddressAllow=localhost снова проходит. Службы probe
  завершены; production listener для этой проверки не использовался.

На трёх хостах свободно около 150 МБ RAM и 1 ГиБ диска. Перед запуском для
тестовых служб нужны отдельные memory/CPU budgets и контроль состояния
production. При недостаточном запасе не добавлять нагрузку на production
ради формального прохождения стенда.

## Оставшаяся подготовка и критерии

1. Сформировать и проверить конфиги соседей, отключить внешние meeting points,
   LAN discovery и PEX. Одного списка соседей недостаточно: learned peer не
   должен образовать прямую сессию через линию. Проверить per-service IP-политику
   на каждом хосте до запуска узла, включая отрицательный контроль non-neighbor.
2. Запускать тестовые службы последовательно, с ограниченным lease и отдельным
   teardown. Зафиксировать PID, SHA, readiness, список сессий и resource usage;
   сравнить production с исходным срезом.
3. Привязать C1 только к S1, C2 только к S6, отключить внешнее discovery и
   прежние remembered routes в тестовых профилях. Подтвердить network=testnet
   и происхождение native-библиотек; пустые списки сессий не считать успехом.
4. До звонка подтвердить все пять двусторонних S-рёбер и две клиентские
   привязки, отсутствие non-neighbor и production peers. Повторять снимки во
   время теста: начальная корректная топология сама по себе не доказывает её
   сохранение после route discovery.
5. Прогнать оба режима звонка и завершение. В relay-режиме сопоставить media
   с transit по всем шести узлам. Не считать успешный локальный enqueue,
   один только UI `active` или свежий comfort noise доказательством слышимой речи.
6. При отказе сохранить стадии signaling, dial/handshake, route selection,
   native TX/RX и per-hop транзит. Не ослаблять линию добавлением прямых связей
   ради прохождения ожидаемого сценария.
7. После проверки закрыть запущенные QA, убрать свои forwards/traces и
   остановить тестовые службы по окончании lease; проверить неизменность
   production. В публичный отчёт — только обезличенные агрегаты.

Звонки не выполнены; ни один из двух ожидаемых результатов пока не объявлен
пройденным. Полная задача остаётся активной.
