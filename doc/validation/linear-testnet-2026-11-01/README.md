# Изолированный линейный testnet: Mac ↔ Blackview

2026-11-01. **Стенд построен; звонки не прошли до начала media.**
Подтверждена остановка непрозрачных конвертов на транзитном участке свежей
цепочки. Порог репутации и другие admission gates не менялись.

## Условия и фактическая топология

`C1 (Mac) — S1 — S2 — S3 — S4 — S5 — S6 — C2 (Blackview)`

Нумерация S1…S6 закреплена приватным manifest по исходному списку шести
серверов. На каждом работала отдельная, не включённая в автозапуск служба
с lease 45 минут, новой тестовой идентичностью PoW 25, отдельными каталогами,
admin socket и портами. Production и прежние testnet-службы не перенастраивались.

- Core discovery и PEX выключены, заданы только соседи линии. Per-service
  IPAddressDeny=any разрешает loopback и соседей; крайним узлам добавлен IP
  клиентов. На каждом хосте прошли три независимых IP-filter контроля:
  соединение без запрета, отказ с Deny=any, успех с явным Allow.
- На всех core listeners задана точная allowlist идентичностей: соседи, а на
  S1/S6 ещё только назначенный клиент. Общий NAT клиентов не разрешает Mac
  подключаться к S6 или телефону к S1.
- У клиентов отдельные новые QA-профили, testnet SDK и единственный operator
  bootstrap peer: S1 / S6. В настройках выключены все meeting points, затем
  клиенты перезапущены. Клиентский PEX остаётся штатным; дополнительные
  соединения ограничены admission на core и проверены фактическими снимками.
- CLI health/sessions прочитаны от DynamicUser самой службы через её mount
  namespace; отказ root-UID не обходился изменением admin ACL.
- Проверены все **10 направленных core-связей**, обе клиентские привязки,
  отсутствие посторонних активных соседей, SHA загруженных конфигов и бинарников.
  Собственные node IDs обоих клиентов прочитаны через native IPC и совпали
  с их peer rows на S1/S6. Пустые списки не принимаются за успех.
- Полный снимок получен во время diagnostic relay-only звонка. При следующем
  P2P-разрешённом звонке один SSH probe S1 завершился banner timeout; его не
  засчитывали. Повторный полный снимок после звонка прошёл.

Blackview использовал Wi-Fi. Это проверка топологии, **не** повтор мобильного
handover Poco ↔ Windows и не физическая квалификация Windows 10.

## Результаты

| Проверка | Фактический результат | Вердикт |
|---|---|---|
| Контактный запрос C1 → C2 | На телефоне появился pendingIncoming | Доставлен |
| Подтверждение C2 → C1 | Телефон accepted, Mac оставался pendingOutgoing | Не сошлось |
| Первый звонок с allowAll | Входящего на Mac нет | Только наблюдение: listeners были созданы при прежнем denied |
| Звонок с denied | Входящего на Mac нет, вызывающий ждёт ring timeout | Не прошёл до media |
| Повтор denied с полной трассой | Тот же результат, 176 state samples за ~91 с | Воспроизведено |
| Повтор allowAll после полного перезапуска | lanListen=true; реальные native QUIC listeners привязаны к wildcard; входящего на Mac нет, 174 samples за ~90 с | Не прошёл до media |

Wildcard на Mac проверен по fd запущенного процесса, на Android — через
same-UID admin Listens. Список рекламируемых `srflx` адресов сам по себе не
использовался как доказательство bind. Предложенный P2P, локальный enqueue и
`source_accepted` не считаются ни звонком, ни доставкой.

Ожидаемые direct P2P media и media через все шесть серверов **не
квалифицированы**: signaling не достиг стадии входящего на Mac. Обходных
соединений для получения формально зелёного результата не добавляли.

## Локализация и исправленный пробел наблюдения

Первоначальный `opaque_forward_trace` видел только Delivery.Forward. Переход
в RecursiveRelay делал дальнейший путь невидимым, поэтому первоначальную
формулировку «за S5 ничего не пришло» нельзя считать точной.

Теперь opt-in наблюдение декодирует **одну ограниченную RecursiveRelay
обёртку** и вычисляет тот же digest внутреннего opaque payload. Метка
`wrapper=forward|recursive` относится к транспортному заголовку, не определяет
тип пользовательских данных. Предел 8192 байта, общий row cap, выключенный
по умолчанию режим и ограничения анонимного экспорта сохранены. Политика
маршрутизации, приоритеты, wire и C ABI не менялись.

Повторный захват связал **145 различных opaque witnesses** на телефоне и
участке `C2 → S6 → S5 → S4`: на S5 видна смена Forward → RecursiveRelay,
на S4 — вход обёртки; её дальнейшая отправка для этих witnesses не наблюдалась.
Это bounded capture непрозрачных конвертов; общего IPC send-ID для отдельного
CallOffer ещё нет. Всем недоставленным сообщениям и всем причинам отказа
этот результат автоматически не приписывается.

На S4 в DHT находились S3 и S5. После split-horizon остаётся S3, а
`forward_rr_to_closest` требует `can_transit`: текущий порог — **200**,
новая локальная репутация — **0**. Модельная проверка настоящего dispatcher
воспроизводит остановку с живой TX-очередью и обоими DHT-соседями; после 2000
синтетических credit в fixture (=200) тот же payload уходит ровно одному
соседу с уменьшенным hop budget. Смена replay ID исключает ложный отказ dedup.
Репутация на живых серверах **не подменялась**.

Таким образом, свежая строго линейная сеть сейчас сталкивается с действующим
транзитным барьером. Это подтверждённый провал ожидаемого сценария, а не
доказательство поломки P2P media или объяснение прежнего отсутствия звука на
Windows. Следующая работа — cold route discovery и обратный путь в такой
топологии с сохранением ограничений проекта; отключение репутации не выдано
за исправление.

## Проверки и происхождение

- Regression trace: **1 failed на прежнем коде → 5 passed** после изменения,
  включая malformed/truncated/oversized/nested формы и неизменность witness.
- Policy control: **1 dispatcher test passed**; отдельно **1 reputation test
  passed**. Первый запуск с ошибочным exact-фильтром дал 0 tests и не засчитан.
- Анонимная диагностика: **17 Flutter tests passed**, TMPDIR=/private/tmp/.
- Oracle топологии: реальный положительный capture + **6 отрицательных
  контролей** (в том числе пустой клиент, неполная линия, SHA/PID drift).
- Linux x86-64 static, Android arm64 и macOS SDK собраны отдельными testnet
  targets на внешней ФС с mount watchdog. Загруженные bytes проверены SHA.
- Trace source/test commit — `89ef6a2b`, локально. Client SDK — base `87912f6c`; AOT/JIT frontend и media/HV сохранены от
  прежней QA-контрольной сборки. Новый trace установлен только на отдельные
  тестовые core-службы. Это не квалификация всего текущего frontend.
- После Linux trace build добавлен только policy test в cfg(test) dispatcher;
  его production-код не изменялся. Точный trace source SHA и ELF SHA сохранены
  в [обезличенном результате](result.json); приватные исходные captures
  и deployment manifest в репозиторий не включены.

## Завершение стенда и открытый остаток

Все шесть тестовых служб остановлены, порты освобождены; production PID,
бинарник и конфиг на **6/6** совпали с исходными. Запущенные Mac/Android QA
закрыты, процессы проверены. Созданный только этим циклом Android QA package
удалён после приватной резервной копии своего профиля; прежние приложения
не переустанавливались. Wi-Fi/mobile settings сохранены, свои forward и
logcat закрыты. Закрытые конфиги тестовых служб сохранены для следующего
запуска; автозапуска нет.

**NETLINE-01 открыт:** на свежей строгой цепочке подтверждены односторонняя
доставка подтверждения контакта и недоставка входящего до media. Проверка
ожидаемых P2P и шестисерверного media path остаётся невыполненной по причине
этого отказа. NETCALL-01 и исходная жалоба о слышимости также не закрыты.
Коммиты локальные, unsigned; push и релиза не было.
