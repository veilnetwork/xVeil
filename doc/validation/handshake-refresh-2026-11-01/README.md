# Стадии холодного OVL1 и повторные peer-hints

2026-11-01. SDK `9c994f7f` добавляет metadata-only trace; `5339aa6d` сохраняет
незавершённый dial при неизменившемся peer-hint. Продолжение
[владения peer-задачами](../owned-peer-shutdown-2026-11-01/README.md).
**Общая задержка холодного подключения не устранена, ускорение не доказано.**

## Подтверждённая лишняя отмена

`claim_or_refresh_connector` будит существующий connector и при повторном
обнаружении того же peer. В pending-connect ветке любое такое уведомление
раньше уничтожало dial/OVL1 future: утверждение комментария «endpoint новый»
не проверялось. Так можно было потерять уже проделанный обмен без изменения
адреса или проверочных данных.

Теперь await-ветка refresh перепроверяет выбранную запись. При полном равенстве
она потребляет уведомление и ждёт следующее **внутри той же ветки select**;
сам pending-connect future остаётся жив. Изменение адреса, pin/nonce/других
параметров записи или удаление learned peer возвращает управление внешнему
циклу и отменяет устаревшую попытку. Backoff по-прежнему просыпается и от
неизменившегося hint; явный network-change сохраняет немедленную отмену.
Таймауты, проверка сертификатов, PoW, reputation и wire не изменены.

Регрессия использует production connector и удерживаемый transport dial на
виртуальных часах: одинаковый hint не должен создавать вторую попытку;
изменение адреса и затем nonce при прежнем адресе должны отменять и повторять.
На старом коде **0 passed / 1 failed**: одинаковый hint перезапускает dial.
После правки — **1 passed**. Полный runtime-набор: **791 passed / 11 ignored**,
включая прежний тест отмены dial при network-change. Это не временной порог
производительности реальной сети.

## Что дала трасса

`handshake.stage.*` включается существующим операторским RT trace. Она пишет
направление, тип кадра, elapsed time и итоговые локальные QUIC-счётчики.
Содержимое/размер plaintext body, ключи, адреса и identity не добавлены.
Локальный link ordinal нужен только приватному сопоставлению событий; он не
включён в публичный result. TX означает локально завершённый write/flush,
RX — достигший hook декодированный кадр, **не** подтверждённую авторизацию.

В исходной серии воспроизведён следующий фрагмент:

- transient rendezvous OVL1 завершился за 242 мс;
- соседняя app-added попытка дошла до отправки IdentityProof, но terminal-event
  у неё отсутствует; на S1 в близком окне обмен закончился ошибкой через 159 мс;
- следующий app-added dial записал только HELLO и завершился через 10 001 мс:
  `stream_received=0`, 6 PTO, UDP RX=18, сохранено 2388 stream bytes;
- повторный OVL1 завершился за 509 мс.

Это отделяет зависание **первого application stream** от долгой криптографической
обработки всего OVL1. Не установлен факт потери пакета или конкретный механизм
на сервере до ordinary OVL1. UDP RX включает другие части QUIC; local write не
доказывает сетевую доставку. Сопоставление времён соседних link не является
межхоповым криптографическим доказательством. Причина всех 10-с ожиданий не
приписывается исправленному hint.

## Физические серии

Mac и две изолированные службы S1/S2. Один SDK на обоих концах в каждой серии;
frontend/AOT, media, hidden-volume, конфиги и профиль заморожены. P2P-policy
allowAll не переключалась. Телефон, Windows, звонки и handover не проверялись.
Оракул требует local ACTIVE и одну соответствующую ACTIVE-сессию в admin S1,
с одним server link в нескольких срезах за ≥3 с; после lock проверяется её
отсутствие на сервере перед следующим boot.

| Boot | Trace-baseline `9c994f7f`: до двустороннего наблюдения | С hint-правкой `5339aa6d` |
|---|---:|---:|
| 1 | 2,774 с | 24,922 с |
| 2 | 2,675 с | 24,513 с |
| 3 | 14,789 с | 24,792 с |
| 4 | 14,239 с | 1,426 с |
| 5 | 40,031 с | 1,372 с |
| 6 | 2,940 с | 24,517 с |

**Это не A/B/A.** SSH polling входит во времена. Один дополнительный запуск
кандидата прерван из-за сброса SSH key-exchange, приложение остановлено;
он не засчитан. Первое квалифицированное наблюдение сохранено, затем серия
продолжена через переиспользуемое SSH-соединение. Это меняет цену наблюдателя,
поэтому сравнение чисел не доказывает ускорения или регрессии кандидата.

В исходных app-added spans — 16 begin и 5 без terminal-event до lock; у
кандидата — 14 begin и 0 без terminal-event. Это наблюдение согласуется с
сохранением попыток, но не доказывает причины каждого незавершённого span.
Неуспешные OVL1 остаются: 5 и 8 соответственно. В серии кандидата снова есть
записи HELLO без входящего stream и PTO. Исправлена лишняя отмена по hint,
а не все причины медленного подключения; release-квалификация задержки открыта.

## Состояние стенда

Все собственные Mac-процессы завершены. Все шесть тестовых служб остановлены,
порты освобождены; у двух временно обновлённых служб восстановлены исходные
бинарники с проверкой SHA. Trace drop-in удалён, исходное unit definition
проверено, оба rollback timer остановлены; собственный SSH master завершён.
Production PID/binary/config сохранены 6/6. Исходные QA/пользовательские
контейнеры и приложения телефона/Windows не менялись. Публичный результат
содержит только агрегаты и metadata кадров; raw logs остаются приватными.
Коммиты локальные, без push/релиза.

Следующий участок холодной задержки — получение первого QUIC application stream
на сервере/его приём до ordinary OVL1. NETLINE-01 и NETCALL-01 не закрыты.
