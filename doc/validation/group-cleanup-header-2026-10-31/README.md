# Повторная запись заголовка после выполненной очистки сегментов

Подтверждён и устранён лишний durable write при повторном приёме той же истории.
Заголовок группы сохранял `gd` — список заменённых сегментов на случай падения
между публикацией и удалением. После успешного удаления точный RAM-индекс уже
не содержал pending delete, поэтому очередной save убирал `gd` из заголовка.
Даже без изменения истории это стоило двух commit: новых chunks заголовка
и публикации его metadata. Следующий duplicate опять был идемпотентным.

Теперь индекс отдельно хранит опубликованный descriptor и фактические retries.
При неизменном наборе сегментов descriptor остаётся побайтно стабильным;
удалённые сегменты повторно не удаляются. Неудачные удаления повторяются.
При изменении сегментов завершённый descriptor заменяется текущим набором
retirement/failed deletes и не накапливается с историей. После перезапуска
очистка из header проверяется заново; старые сегменты не становятся live.

Новые сегменты по-прежнему записываются до header, удаления идут после него
и до завершения save. Никакой отложенной очистки, незаписанного ACK,
пропуска проверок подписей/ratchet/ACL или новой wire-схемы не добавлено.
Storage API, native SDK и приоритеты реле не менялись.

## Регрессии

Тест на исходном `05c64c0c` подтвердил: после replay snapshot все поля header,
кроме `gd`, равны, но полные bytes отличаются. На кандидате три повтора
оставляют bytes одинаковыми и не повторяют завершённые удаления. Fresh service
читает все 300 сообщений, один раз проверяет descriptor после рестарта и
не запускает эту проверку каждым следующим повтором.

Второй тест удерживает удаление старого хвоста ошибкой, дважды повторяет snapshot,
снимает ошибку и проверяет фактическое удаление. Новая ревизия заменяет descriptor
одной записью вместо накопления завершённых cleanup; fresh service читает 302
сообщения. Существующие проверки отсутствующих/испорченных сегментов,
перехваченного save, crash leftovers, shared parse, retention и epochs сохранены.

**483 теста прошли, 0 skipped/ignored** (9 служебных loading events исключены).
Это GroupService, chunks, overlay topology, receipt/source queues,
PostReceiptQueue, removed-member notices, epochs и atomic file publication;
native XVSB/XVRC действительно выполнялись. Targeted analyze: no issues.

## Измерение

Test-only adapter делит реальные file calls на header/segment и связывает их
с worker RPC через синтетический номер операции в Zone. Имена/содержимое/пути
файлов в события не записываются. Операции делегируются настоящему хранилищу;
продукт adapters не импортирует. Вложенные commits считаются по одному member
и file-operation, а не по похожему времени. При построении критической цепочки
используются точные RAM-сопоставления wire body/fid прежнего timing fixture.

Предварительный исходный capture: 48 новых сегментов (по одному commit),
36 удалений (по одному), 80 реальных замен header (по два), 125 идемпотентных
вызовов header без commit. Это 244 commit group files; 32 замены header
превышают 48 новых сообщений и соответствуют cleanup-only rewrite.

Пересечение file calls с критическим group handler измеряется как union
интервалов, с совпадающим frame и обрезкой по причинному участку. Это wall time
в API, включая ожидание диска/worker/file gate; нельзя приписать его целиком
физическому fsync или складывать перекрывающиеся интервалы других задач.

## Native A/B

Контроль `05c64c0c`, кандидат этой правки, одна frozen SDK `081bb6d1`;
Rust не пересобирался. Три пары A/B, одинаковые production-PoW identities,
свежие encrypted containers и instance keys, 12 native Leaf с DHT,
TCP full mesh, настоящие native signatures/ratchet/host authorization.
Legacy group без epoch encryption и out-of-band roster. Один Mac/JIT host,
общий диск; это не физическая multi-device/Android/relay квалификация.

Последовательно A1/B1/A2/B2/A3/B3. Первая видимость всем 12, мс:

Медианы A/B по порядку сообщений: **4254/4450, 2828/2248, 2251/2115,
2710/2753 мс**. Устойчивого ускорения всей доставки не заявляем: первое и
четвёртое сообщения по медиане медленнее, второе/третье быстрее; порядки
причинных ветвей и нагрузка диска варьируются. Следующие сообщения идут от
других авторов, это не строго тёплое повторение одной пары.

Во всех трёх парах замены header **80 → 48**, group-file commits **244 → 180**
(−26,2%). Новых сегментов по 48, фактических удалений по 36 в обеих версиях.
Таким образом устранены именно 64 лишних commit, а не необходимые удаления.
Количество group-data wire copies осталось 202 в каждом запуске; у каждой
ровно один enqueue/send/receive, все end успешны. Все 24 сообщения у всех
12 участников ровно по одному разу, без пропусков. Это не весь сетевой трафик.

Все шесть host-процессов завершились, по 12 listeners освобождены,
cleanup_errors пусты; временные контейнеры удалены. SHA source/helper/fixture
и frozen native library зафиксированы; rollback watcher завершился, итоговый
candidate восстановлен побайтно. Телефон и production-реле не использовались.

Следующий участок для атрибуции — холодная авторизация документа у хоста.
В A1 private stage trace: DHT document lookup ≤2 мс, registry ≤4 мс,
а document_authorization до 634 мс (включает ожидание durable host checkpoint).
Это не доказательство всех 1,9 с identity send и не повод обходить сохранение
негативных авторизационных данных. Требуется разделить ожидание опроса,
собственно commit и публикацию ack; cold send ещё не исправлен.

Приватные raw logs, реальные IDs, пути и граф участников не публикуются.
Общая задержка доставки остаётся открытой: устранён конкретный лишний write,
а не все причины секунд ожидания. Телефон и public relays не изменялись.
Без push/релиза.
