# Проверка report28 и исправления multi-device — 21 октября 2026

Исходный отчёт: `report28_prepare.md` в родительском рабочем каталоге.
Замечания проверены по исходникам и целевыми тестами; выводы автора и
предложенные патчи не принимались автоматически. Полная поштучная таблица —

## Решения по отчёту

27 замечаний получили правки кода/документации или hardening. R28-24 —
очистка локальных артефактов. R28-16/18/22 не подтверждены как дефекты,
влияющие на текущую работу продукта; причины отказа приведены в таблице.
Публичный v1 encoder hidden-volume и общая obfs4 PSK сохранены как часть
совместимости и модели проекта. Мёртвые ссылки на неопубликованный TASKS.md
убраны из EN/RU документации вместе с исключениями link checker; доступный
публичный аудит не выдаётся за полный исторический трекер.

Rustup использует архивный installer и SHA-256 по официальной
[процедуре ручной установки](https://rust-lang.github.io/rustup/installation/other.html).
Вендорённые quinn-proto/quinn-udp сравнены с архивами static.crates.io;
это сверка происхождения изменений, а не новый аудит всей реализации Quinn.

Дополнительно исправлены гонки привязки: старый сеанс с временной личностью B
больше не перекрывает актуальный master-authorized документ; позднее пустое
чтение devices.gid не стирает принятую группу. Adoption сериализован с ingest,
а после принятия группы немедленно запрашиваются пропущенные подписанные строки.
Это устранило наблюдавшуюся потерю начальной догрузки истории. Отправка delta
без манифеста остаётся включённой.

Модель доставки не расширялась: звонки и копии для собственных устройств
не добавлены в mailbox, публичным реле не сообщается тип медиа и не вводится
приоритет для звонка. Если все держатели исходящего сообщения offline,
мгновенное восстановление на B по-прежнему не обещается.

Проверка MD21-01 подтверждает устранение воспроизведённого дефекта при
подключённых verifier-узлах. Она не доказывает мгновенный revoke через любые
relay-only/partitioned топологии: до получения нового подписанного документа
удалённый verifier может знать старое состояние. Сценарии длительного split-brain
и все пути обхода отозванным устройством не сертифицированы этим повтором.
Native ACK-tracked SDK-запросы сохраняют прежний single-envelope tracker;
xVeil использует собственные durable app ACK.

## Проверки и границы

Финальные проверки:

- Flutter: **566 passed, 3 skipped** в затронутых scopes; `flutter analyze` без замечаний.
- Rust: crypto **166**, e2e **136**, IPC **175**, runtime **665**, proto **841**,
  routing **109**, session parser adversarial/proptest **2** — passed.
- FFI с node-embedded/packet-tunnel/test-low-difficulty: **320 passed, 11 ignored**;
  отдельно конфигурация без embedded: **138 passed**. Ignored media/codec сценарии
  этим обычным unit-прогоном не сертифицированы.
- hidden-volume: **208 library + 10 CLI passed**, 2 ignored; Clippy без замечаний.
- Затронутые SDK crates: Clippy `--all-targets -D warnings`, rustfmt,
  регенерация FFI header/ABI; hash контракта остался `57db2f7a39a07a8d…`.
- Linux: `cargo check` helper/FFI в изолированном контейнере и g++ syntax check
  runner helper с `-Wall -Wextra -Werror`. Привилегированный VPN не поднимался.
- Workflow pin gates всех трёх репозиториев, provenance Quinn, безопасные
  bootstrap paths и документация — локальные проверки passed.

Расширенный FFI-прогон выявил нестабильность существующего liveness-теста:
после отключения datagram он прекращал media send и сравнивал сохранённый
route object. В изолированном повторе тест проходил. Контроль уточнён:
отправка продолжается под потерями, поэтому проверяется реальный send/expiry
путь; порог 12 s не менялся. Полный повтор FFI с этим контролем прошёл.
В редком feature-наборе тестов также устранено предупреждение Clippy в codec fixture.

Очистка проверена независимо через список процессов и открытые staged dylib:
**0 оставшихся workers/relays**, проверено 6 native stages и учтено 48 стартов
workers. После раннего аварийного запуска найден и закрыт один orphan
flutter_tester; перед остановкой проверены его команда и загруженная библиотека.
Проверяемый итог — [cleanup-proof.json](cleanup-proof.json).

Логи текущего цикла находятся в локальном закрытом каталоге
`~/.cache/codex/xveil-report28-20261021/`; имена доказательств указаны в CSV.
Стенд использует независимые native-процессы A/B/C и отдельные контейнеры;
расширенный A/B/C/D использует production providers и реальные native media
packets. Это не субъективная проверка громкости/разборчивости живой речи.
Публичные реле, реальные пользовательские личности и телефон не изменялись.

Установка bootstrap от root, реальное удаление системных данных, публикация
релизов и GitHub workflows в облаке не выполнялись. Скрипты проверены локально;
сценарии с днями offline и физическим сетевым split-brain этим циклом не покрыты.
