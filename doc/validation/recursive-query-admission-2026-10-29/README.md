# DHT lookup: отказ очереди и отмена — 2026-10-29

База: xVeil `9cee6aff`, Veil `c9297488`, hidden-volume `1ea2366f`.
Исправление Veil: `1fbef225`.

## Подтверждённые дефекты

Обычный `recursive_dht_get` создавал pending-запись, вызывал `send_to` для
выбранных сессий, игнорировал результат постановки в очередь и ждал ответ.
Если все выбранные очереди переполнены либо сессии закрылись, ни один запрос
не отправляется, но вызывающий всё равно платит полный timeout. В частности,
`cache_stream_relay_directory` использует этот путь при построении onion-stream
и задаёт 3500 мс: локальный отказ очереди превращался в пустое сетевое ожидание.

Теперь lookup ждёт ответ только при постановке хотя бы одного запроса в
очередь. Выбор top-2, фильтрация DHT-участия и политика connected holder не
меняются. Отказ одного соседа не отменяет попытку второму. Никакого нового
дропа кадров, повторного цикла без паузы или увеличения очередей не введено.
Ответ `None` передаётся существующему вызывающему пути.

Второй дефект — при отмене будущего обычный lookup оставлял свою pending-запись.
Она могла исчезнуть после ответа или при следующей чистке закрытых каналов;
это **не** доказательство постоянного исчерпания лимита. Теперь оба варианта
lookup используют прежний RAII-guard многорепличного поиска: завершение,
отказ, timeout и отмена удаляют только ID, принадлежащие этому запросу.

Проверки подписей, привязки адресов, freshness и локального mirror-cache
остаются прежними. Общая функция по-прежнему передаёт сетевой ответ своему
проверяющему вызывающему коду; она не объявляет любые полученные байты
доверенными. Mailbox, wire-формат, приоритеты и политика реле не менялись.

## Проверки

Два регрессионных теста упали на прежней реализации, без ошибок компиляции:

- полная очередь: lookup остался Pending вместо немедленного Ready(None);
- отменённый lookup оставил свою запись рядом с чужой живой pending-записью.

После исправления эти тесты проходят. Отказ очереди проверяется для обычного
выбора и явно указанного connected holder. Третий тест заполняет очередь
первого соседа и получает ответ от второго: lookup остаётся Pending до ответа,
возвращает его байты и очищает своё состояние. Используются настоящие
SessionTxRegistry и ограниченные очереди, но ответы синтетические; это не
сквозная проверка сетевых подписей. Числовые пороги длительности не нужны.

Полный runtime: **735 passed, 11 ignored**. FFI с `node-embedded`,
`production-seeds`, `packet-tunnel`, без default features:
**326 passed, 2 ignored**. Ignored не считаются пройденными проверками.
Существующие проверки freshest-wins, неподлинных документов, durable host
authorization, перезапуска, отмены prefetch и выбора пиров входят в этот набор.

Release-библиотека Mac собрана с теми же feature-флагами, без test hooks и
test-low-difficulty. Отдельная файловая система внешнего target проверялась
перед Rust-командами и каждые 0,5 секунды во время них, отключений не было.

После сборки прошёл прежний opt-in стенд: 12 native leaf-узлов на одном Mac,
TCP-loopback, реальные подписи, отдельные зашифрованные worker-контейнеры,
ratchet и peer authorization persistence. Четыре сообщения видны всем ровно
один раз. Максимумы видимости по сообщениям: 9475/2361/2340/2845 мс; сравнения
скорости с прежней библиотекой в этом цикле нет. Стенд не создаёт насыщенную
session queue намеренно: новую границу отказа доказывает unit-регрессия.
Остаются прежние ограничения: один процесс, legacy-группа без шифрования
эпох членства, не AOT-квалификация Flutter и не физическая проверка провайдера.

Закрыты 12 контроллеров, повторно заняты/освобождены 12 TCP-listeners, cleanup
без ошибок. После выхода независимо проверено завершение test host и процессов
Rust-команд. GUI, камера, микрофон и телефоны не запускались. Push, релиз и
обновление реле не выполнялись. Публичная [числовая сводка](summary.json)
содержит только разрешённые поля; закрытые журналы и тестовые ключи не включены.

## Уточнения к независимому разбору

| Утверждение | Проверка текущего кода |
| --- | --- |
| FFI sender-мьютекс удерживается на протяжении resolve/seal | Не подтверждено. Вызов под ним кодирует и ставит кадр в bounded writer queue. Resolve/seal выполняется отдельной задачей в IPC-демоне. Давление writer queue может косвенно задерживать FFI, но это отдельная гипотеза, требующая измерения. |
| Новый prefetch делает два набора DHT-запросов вместо одного | При успешном адресном поиске два поиска были и раньше, последовательно. Выросла одновременность. Если документ невалиден/отсутствует, теперь может успеть начаться лишний ограниченный cert-prefetch, затем он отменяется. |
| Для старого осиротевшего хвоста достаточно запросить удалённые индексы | Недостаточно. `ackOutboxFrame` удаляет и индекс, и payload log подтверждённой части. Точной копии старого bundle в этом протоколе не сохраняется. Нужен источник полной копии, durable commit-receipt до ACK или отдельно доказанное восстановление состояния; ACK неподтверждённых байтов не добавлен. |

Последний пункт остаётся открытым. Не менялся исходный отчёт другого агента;
эта сверка фиксирует границы его предложений по текущей реализации.

Этот фикс устраняет лишнее ожидание **при отказе локальной очереди**.
Он не сокращает ожидание принятого сессией, но не отвеченного запроса и не
доказывает причину прежних 53/114,9 с либо пауз после 33% файла. Остальные
пользовательские случаи и неполная multi-device матрица остаются открытыми.
