# Подготовка файловой записи: отклонённое объединение чтений и профиль миграции

2026-11-01. Продолжение [квалификации Outbox](../outbox-enqueue-batch-2026-11-01/README.md).
Production-кандидат этого цикла **отклонён**, оба изменявшихся файла восстановлены
побитово. Устранение общей задержки начальной миграции не заявляется.

## Проверенный кандидат

В пределах сериализованной файловой операции предлагались свежие порции чтений:
метаданные пары, два признака on-disk tier и allocator/GC. Кэша между вызовами
не было, формат хранения, число/порядок коммитов и сборщик мусора не менялись.
Предварительная ошибка второго metadata-read не отменяла прежний short-circuit
по существующему первому файлу: сохранялся fallback к ленивым чтениям.

Исходный узкий набор: 4 passed / 7 failed на прежнем коде — в том числе новые
счётные и batch-length assertions, **не семь новых дефектов данных**. Кандидат
прошёл 164 связанных проверки, включая три дополнительных сценария отказа и
свежести. Эти тесты не доказывают ускорение; кандидатские assertions на batching
сохранены только в приватном архиве и не оставлены как красные тесты продукта.

## Native A/B/A

Один и тот же настоящий worker/HV, свежий контейнер на фазу. 32 замены пары
64/6 КиБ с retirement прежнего tail, затем 8 обычных записей и 8 частей файла.
После реального close/reopen все последние bytes совпали, прежние tail удалены,
восемь частей собраны. Оба production-файла проверены по SHA до/после каждой
фазы, A₁/A₂ идентичны; fixture и библиотека также сверены, кандидат восстановлен
в finally до принятия решения о его отклонении.

| Участок | Metadata RPC A₁ / B / A₂ | Коммиты A₁ / B / A₂ | Время A₁ / B / A₂ |
|---|---:|---:|---:|
| 32 пары | 256 / 160 / 256 | 64 / 64 / 64 | 1,165 / 1,206 / 1,200 с |
| 8 обычных файлов | 24 / 16 / 24 | 8 / 8 / 8 | 0,125 / 0,142 / 0,139 с |
| 8 частей | 32 / 24 / 32 | 16 / 16 / 16 | 0,263 / 0,281 / 0,286 с |

Metadata RPC — только get + getBatch; payload-read не исчезал. Время включает
саму операцию с подготовкой fixture-bytes. Сокращение запросов подтверждено,
выигрыш времени не получен, систематическое замедление также не установлено
по одной тройке. Этого недостаточно для переноса оптимизации в production.
Сохранён повторяемый native профиль без требований к выбранной стратегии.
Все три process group завершены, временные native-контейнеры удалены.

## Пассивная атрибуция

В test-only adapter отдельно считаются load/loadBatch, has/hasBatch,
store/storePair и delete для header/segment/other, включая вложенные worker RPC.
21 разрешённая метка фиксирована; имена файлов, ID, ключи, payload и ошибки
не входят в сводку. Неизвестная Zone-метка отбрасывается и adapter, и collector.
Reset обрезает ожидание уже начавшегося вызова по новой границе окна.

7 тестов census прошли, analyzer чист. Сохранённый native-профиль отдельно
повторно прошёл на окончательных test-adapter и прежнем production-коде,
с настоящим close/reopen и проверкой SHA библиотеки. Суммы ожиданий могут перекрываться:
родительский вызов, вложенный RPC и операции разных устройств нельзя складывать
как непересекающийся критический путь. Обёртки добавляют test-only async scopes;
диагностический прогон не служит причинным сравнением скорости с прежними.

## Межпроцессный диагностический прогон

2000/2000 сообщений сошлись на A/B/C по ID/порядку, на B все delivered,
старых retries 0. Полное количество впервые наблюдалось через **46,372 с**,
совпадение порядка и эффективных исходных позиций — через **51,503 с**.
Первые 75 несовпавших позиций все были provisional; в последнем снимке каждая
имела исходный ordering-overlay. Наборы ID в начальном полном и конечном
снимках одинаковы. Это конкретное подтверждение временного порядка при
догрузке, не доказательство судьбы прерванного исторического прогона.

Один Mac/JIT, current SDK и те же проверенные CLI/FFI/HV; public discovery/seeds
выключены, migration-only не выполняет пятиминутный offline или всю матрицу.
Production-код этого прогона — прежний, с отклонёнными изменениями восстановленными.
Диагностические обёртки меняют fixture: причинное ускорение или замедление по
сравнению с предыдущими 51 с не заявляется.

В чтении порций вложены 1770/2007 payload-read RPC на A/B, с суммой await
13,972/6,505 с. Это **часть** соответствующего file-call, не добавочные секунды.
Окна начинаются reset перед link и заканчиваются финальными inspection, на
A/B в разные моменты (точные размеры окон в result.json); таблица не обещает,
что все операции лежат внутри первых 51,503 с. Ожидания перекрываются. По этой
таблице нельзя сложением восстановить полную задержку или объявить сеть быстрой.

Главный следующий кандидат — повторное чтение актуального журнала, а не его
presence-проверка. В частности, `_postDeviceBatch` сохраняет рабочий bundle,
а последующий `broadcastDelta` снова вызывает load. Частота/причинный вклад
именно этой пары ещё не атрибутированы. Перед любым reuse требуется сохранить
проверку текущего состава, отзыва, целостности и независимость от draft: старый
снимок нельзя подставить вместо актуального только ради числа RPC.

Проверены завершение всех 18 собственных PIDs, отсутствие собственных
listeners на 18 захваченных портах, удаление runtime-контейнеров, неизменность
568 frozen-файлов и библиотек. Телефон, Windows и production-серверы не менялись;
push/релиза нет. Медленная начальная миграция остаётся активной.
