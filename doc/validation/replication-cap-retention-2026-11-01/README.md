# Переполнение очереди не удаляет незавершённую синхронизацию

2026-11-01. Подтверждён и исправлен разрушительный backpressure: проверка
лимита 256 pending state-кадров отказывала в новом snapshot и одновременно
асинхронно удаляла уже сохранённые копии этому адресату. Живое новое устройство
с частично принятой передачей теряло источник повторов. Теперь лимит запрещает
добавление новой копии, сохраняя имеющиеся до ACK или штатной возрастной очистки.
Ручной explicit purge, шестичасовая очистка state и обычные события не изменены.
Это admission-порог, а не обещание жёсткого предела каждого fragmented snapshot.

Регрессии на прежнем коде: три unit-сценария падали после ожидания фактической
очистки; отдельный частично принятый семичастный transfer после рестарта терял
все семь исходных частей. На исправленном коде полный повтор доставляет его один
раз, terminal ACK освобождает копии. ACK освобождает места в лимите; насыщенный
адресат не блокирует другого; обычные события сохраняются и при age sweep.
На настоящем worker/hidden-volume: до исправления из 257 кадров после закрытия
и открытия оставалось одно обычное событие; после — все 256 state и событие,
с теми же ID, peer и payload. Scoped-набор: **91 passed**, native **1 passed**,
analyzer без замечаний. Неверное имя одного test-файла и первый callback без
обязательного bool-результата исправлены до зачтённых запусков, не product red.

Новый process A/B/C прогон: 2000 сообщений сошлись по ID, порядку, effective
positions и delivered за **51,453 с** (наблюдение раз в пять секунд), старых
message retries 0. Это один Mac/JIT с private loopback-реле, не Android и не
вся матрица. Сквозное ускорение не заявляется: предыдущий baseline давал
51,503 и 72,408 с, кандидат с другой правкой — 46,649 с.

В исходном медленном baseline обнаружено удаление 258 state-кадров, когда B уже
принимал историю. У одной десятичастной передачи приняты только две части и
terminal ACK отсутствует. Точное соответствие этой передачи исходной дыре из
25 строк не установлено; исправление не объявляется единственной её причиной.

Стенд завершён. Живой collector процессов был пропущен, поэтому автоматическая
послестендовая проверка не выполнилась; независимая проверка по сохранённым
журналам подтвердила выход семи записанных PID, отсутствие семи сохранённых
TCP-listeners, команд с уникальным runtime-путём и самого runtime-каталога.
Полная историческая перепись потомков/портов в этом прогоне отсутствует.
Все 568 frozen-файлов и native-библиотеки неизменны. Телефон, Windows и
production-реле этим раундом не менялись. Push/релиза нет.
