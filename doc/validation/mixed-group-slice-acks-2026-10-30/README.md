# Полная копия при legacy slice ACK — 2026-10-30

База xVeil — `cd68c689`, Veil `c96bd930` не менялась. Продолжение
[атомарного transfer ACK](../group-transfer-commit-ack-2026-10-28/README.md):
новый отправитель маркирует chunks полем `a:1`, но старый получатель может
игнорировать это добавочное поле и отвечать отдельным ACK на каждый chunk.

## Дефект и воспроизведение

На исходном коде один такой ACK удаляет одну payload-копию из Outbox.
Остальные части остаются. Если получатель перезапускается и теряет RAM receipts,
он уже не может собрать бандл из оставшегося хвоста. Логическая история могла
быть успешно сохранена до ACK; дефект хвоста не доказывает потери сообщений.

Новые тесты воспроизводят это через настоящий MessagingService и
HiddenVolumeStorage/FakeKvLogStore. Семичастный бандл после первого ACK теряет
одну durable часть. Дополнительно legacy-ветка получателя выполняет apply,
пропускает к отправителю только первый ACK, перезапускается и получает повтор.
Чтобы воспроизвести старое игнорирование `a:1`, адаптер теста убирает поле при
декодировании, сохраняя transfer ID, frame ID и все payload bytes. Это настоящая
существующая legacy receive/ACK-ветка; старый бинарник в этом опыте не запускался.

## Исправление

Для **opted-in** canonical group transfer отдельные ACK считаются прогрессом
всей передачи. Durable payloads не удаляются до подтверждения каждого индекса.
Последний ACK проверяет полную авторитетную Outbox-копию, включая wire kind,
transfer ID, индекс/число частей, `a:1` и адресата, после чего использует прежнюю
атомарную `ackOutboxFrames`. Другая передача/адресат не входят в эту операцию.

В RAM два bitmap на transfer: известные durable индексы и полученные ACK.
Первый ACK читает metadata один раз; следующие enqueues обновляют известные
индексы. Финальное подтверждение делает ещё один авторитетный проход. Тест
проверяет эти два прохода и отсутствие per-slice удаления. Число transfer-state
ограничено 128, число индексов — существующим пределом group reassembly.
При максимальном текущем count bitmap занимают суммарно до 67 584 байт, без
учёта объектов и ключей. Повторный ACK не увеличивает счётчик.

Потеря RAM-прогресса при рестарте/вытеснении означает лишний повтор, а полная
копия остаётся на диске. Нового durable журнала receipts, schema или wire kind
нет. Нормальный `grpa:` ACK сохраняет атомарное завершение без ожидания отдельных
ACK. Настоящие старые queued transfers с `a:0` продолжают удаляться по частям;
при повторной отправке их режим не меняется.

ACK через alias своей личности учитывается только для адресата, заново
проверенного существующим isOwnDevice-путём. Чужой контакт не добавляет биты
другого адресата. Синхронная инвалидизация текущего flush-snapshot сохранена,
включая время ожидания первого чтения metadata. Чтение/подписи/ratchet,
контактные и membership gates, mailbox и правила реле не обходятся.

## Проверки

Шесть новых сценариев дали **6 failed** на исходном коде и **6 passed** на
исправлении:

| Сценарий | Проверяемое свойство |
| --- | --- |
| Первый ACK, затем рестарт отправителя | Все исходные wire bytes остались и собираются в исходный бандл |
| Чужие ACK и дубли | Не заменяют недостающий ACK; последний правильный завершает передачу |
| Legacy apply + потеря ACK + рестарт получателя | Получатель повторно собирает весь бандл; очередь отправителя очищается |
| Последний ACK с остановленной atomic operation | До commit все строки остаются; другая передача сохраняется |
| Alias личности | Нужна проверка конкретного sibling-адресата; частичные ACK не удаляют копию |
| Уже осиротевший opted-in хвост | Отсутствующий индекс не считается подтверждённым |

Общий прогон 13 файлов: **221 passed**, шесть целевых уже входят в это число.
Он включает group snapshot, receipt/source queues, Outbox flush invalidation,
peer lanes, durable re-drive, retention, endpoint expiry, собственные устройства
и storage idempotence. Analyze двух изменённых Dart-файлов — без замечаний;
format/diff check прошли. Одно прежнее утверждение теста изменено осознанно:
первый legacy ACK для **a:1** больше не удаляет одну строку. Контроль настоящего
**a:0** отдельно требует прежнего поштучного удаления.

## Что остаётся

Это защита полной копии **нового opted-in отправителя**, в том числе при
legacy ACK. Старый отправитель, успевший удалить часть payload до обновления,
не получает эти bytes обратно. Его `a:0` хвост остаётся отдельной проблемой.
Отсутствующие части не ACK-аются и missing-state не объявляется восстановленным.

Свойство durable apply по-прежнему зависит от контракта получателя: старые
версии, выдававшие все ACK до сохранения бандла, не становятся crash-safe от
этой правки. Поведение старого получателя после частичного ACK исправляется
сохранённой полной копией, но ACK всех частей сам по себе не доказывает apply
произвольного старого бинарника.

Физической mixed-version квалификации ещё нет; прежние пять файлов относятся
к Dart `7a225483`, не к этому изменению Outbox. Смешанные версии congestion
control/оверлея, старые осиротевшие передачи и вся multi-device матрица остаются
открытыми. Приложения/звонки/серверы в этом цикле не запускались. Raw logs
приватны; в отчёте нет реальных IDs, путей, IP или credentials. Коммит без
подписи; push/релиза нет.
