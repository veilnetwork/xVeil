# Уже доставленные строки не требуют повторного roster read

## Подтверждение и исправление

При догрузке ordinary mirror applier уже сохраняет исходный `delivered`
вместе с новой строкой или исправляет статус существующей. После этого
`_applyHistoryEvent` по `historyDelivered` заново читал список своих устройств
и строку ради того же статуса, хотя новой записи не требовалось.

Добавлена локальная проверка результата перед этим повтором. Если нет
`historyEditSeq`, а строки уже нет, она входящая или уже `delivered`, никаких
коррекций не остаётся. Проверяются текущие pull/binding, затем обработка
завершается. Следующий write/publication/checkpoint по-прежнему требует свежей
проверки членства. Completed membership/contact cache не добавлен.

Если коррекция ещё нужна, предварительно прочитанная строка **не используется
для записи**: остаётся исходная последовательность fresh admission → fresh row
read → edit/status write. Правки проходят прежним путём. Отказ, потерянный
ответ, удаление, TTL и изменение binding не объявляются успешной записью.

## Проверки

Новая проверка удерживает после публикации ответ roster callback. Для 32
изначально сохранённых delivered-строк parent запускает **32** таких чтения
вместо одного — assertion-red, без порога времени. На candidate остаётся
**1**, перед durable cursor: пока callback удержан, данные уже есть, но cursor
не завершён. После разрешения проверки он завершается, все статусы совпадают.

Штатный тестовый applier намеренно не переносит начальный delivered и позволяет
проверять repair. Новая проверка задаёт delivered в prepared append явно,
моделируя production bridge, который читает mirror `st`. Остальные тесты
сохраняют обычный repair-путь; он не подменён ради зелёного результата.

Вторая новая проверка отзывает источник после durable delivered append:
no-op не разрешает следующий checkpoint, cursor не продвигается. Связанные
проверки покрывают фактически нужную статусную коррекцию после revoke,
отказ статусной записи, held edits, конкурирующие зеркала, binding teardown,
удаления, TTL и native expiry с отказом/потерей ответа.

**254 history/storage checks + 60 mirror checks = 314 passed / 0 skipped**, включая
native expiry. Analyzer двух изменённых Dart-файлов чист.

## Native A/B/A на 100000 сообщений

Parent `e843a005` → candidate → parent. Один production variant,
`messaging_own_history.dart`; общие test inputs. Четыре Mac/JIT процесса,
три изолированных Core, настоящий FFI/ratchet/зашифрованное хранилище.
Два полных источника одного архива; оба первых authenticated ответа удержаны
до apply release. Seed завершён до измеряемого окна. Compact observer
каждые 5000 мс; CPU sampling, work trace и timeline выключены.

источников одинаков во всех фазах: новая строка перед 100000 архивными.

## Происхождение, уборка и остаток

**1532 frozen inputs**, один production variant и 1531 общий input;
те же SHA native-библиотек/ABI и реальные worker mappings. Candidate
восстановлен и сверён с квалифицированной фазой. Rust не пересобирался.

Cleanup проверил **37/41/36 PIDs** и **58/60/62 порта**. Owned процессов
и слушателей нет, runtime удалён. Cache **92→92** во всех фазах, новых kernel
entries 0; около 9,5 ГиБ, свободно около 149 ГиБ. Raw evidence приватен;
публичная сводка не содержит ID, адресов, путей пользователя или capabilities.

Latency остаётся активной — около 195 с на 100000 на этом локальном стенде.
Следующий участок: оставшиеся ожидания между страницами, source snapshots и
размер порции в прежнем byte/admission budget. Физическая/AOT квалификация,
NETCALL-01 и оставшаяся multi-device matrix не закрыты. Push/релиза нет.
