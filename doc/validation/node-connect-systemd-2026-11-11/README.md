# Установка узла через временный HTTPS-помощник — 2026-11-11

Продолжение [проверки сопряжения на Android](../node-connect-2026-11-11/README.md).
На изолированном Debian 12 с настоящим systemd выполнены установка Veil через
помощник, повторная установка, применение конфигурации и переустановка бинарника.
Два выявленных дефекта исправлены локально. Push и релиза не было.

## Подтверждённые дефекты

| Случай | До правки | Исправление и доказательство |
| --- | --- | --- |
| Неполная подготовка нового сервера | Bootstrap успешно показывал QR, но оставлял сервер без `curl`, необходимого для установки Veil | Проверяются и устанавливаются также curl, доверенные HTTPS-сертификаты и util-linux. Тест с исполнением настоящего bootstrap-пролога сначала упал для отсутствующих curl/flock; затем прошёл для всех трёх условий. На Linux исправленный bootstrap установил зависимости |
| Временные скрипты на `noexec` | Установка завершалась `flock: failed to execute …/provision.sh: Permission denied` ещё до скачивания Veil | Установка, обновление и применение конфигурации запускают root-owned скрипт через `/bin/bash` под тем же flock. Все три операции прошли при подтверждённом `noexec` на `/tmp` |

Права временных каталогов, проверка SHA-256, блокировка, проверка конфигурации
и порядок применения сохраняются. Параметры монтирования `/tmp` не менялись.

## Linux/systemd-стенд

Использован собственный контейнер Debian 12 / aarch64, systemd 252,
Python 3.10. Контейнер имел отдельное пространство cgroup и временные
файловые системы; доступ к помощнику опубликован только на loopback Mac.
Это настоящий systemd с действующим unit, пользователем `veil` и процессом
Veil, без подмены `systemctl`. Production-сиды и реальные клиенты не затронуты.

Bootstrap выполнен из root-консоли; установка и команды управления — реальным
Dart `NodeConnectClient` через проверяемый TLS-сеанс. Сервер имел явный маркер принадлежности стенду;
live-тест требует отдельные переменные окружения и по умолчанию пропускается.

Установлен опубликованный `veil-cli` v0.11.49 aarch64-musl. SHA-256 скачанного
бинарника и окончательно установленного файла независимо совпали с манифестом
этого релиза. Rust не собирался; дополнительные компоненты не устанавливались.

Последовательно подтверждены:

1. Пустая инвентаризация до установки и наличие зависимостей после bootstrap.
2. Установка штатным `buildProvisionScript`: служба `active` и `enabled`,
   возвращены node ID и bootstrap-приглашение.
3. Повторное выполнение того же установщика сохранило ID.
4. Штатная инвентаризация вернула тот же ID и активную службу.
5. Чтение и применение той же конфигурации с проверкой ожидаемого SHA-256.
6. Штатная переустановка того же опубликованного бинарника с рестартом службы.
   Это проверка пути обновления, не проверка перехода между версиями.
7. Помощник остановлен и запущен снова; новый claim и инвентаризация обнаружили
   уже установленный активный узел с bootstrap-приглашением.

Первый успешный install/redeploy/config/update-прогон — 15 с целиком;
fresh-helper/existing-node — около 1 с. Это длительность конкретных тестов,
а не обещание времени установки на произвольном сервере.

| Анализ изменённых Dart-областей | No issues found |

Ранний отказ нового Python-теста `no secondary download` после добавления curl
в список пакетов был ошибкой слишком широкого условия теста: он запрещал
даже упоминание зависимости. Условие уточнено до запуска curl/wget-команд;
проверка точного вложенного Python-исходника сохранена.

Сканирование камерой, внешний firewall/NAT, установка ogate/oproxy и обновление
между различными версиями этим прогоном не квалифицированы. Android и его
основное приложение в этом раунде не менялись. Исходное пользовательское
повреждение при сжатии остаётся невоспроизведённым.

## Очистка

Служба остановлена, systemd подтвердил `MainPID=0`. Помощник завершился и
удалил приглашение. Удалены собственный контейнер, оба собственных образа
стенда и локальная копия скачанного бинарника. Остальные контейнеры, образы и
служба Colima не останавливались. Приглашения, секреты, ID узла, адреса стенда
и сырые логи остаются вне репозитория.
