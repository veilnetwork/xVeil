## Подтверждённые ошибки рядом со сжатием

1. Список был привязан к отображаемой подписи с порядковым номером, а не к
   паролю/пространству. Повторный пароль выглядел второй найденной личностью.
   Теперь прямое добавление одного пароля/SpaceKeys под другой подписью
   отвергается. Legacy-метод добавления subordinate-ссылок сохранён.
   Native-вызов дедуплицировал пароли и раньше: это не доказанная причина
   повреждения. Отдельные скрытые пространства с одинаковым паролем native
   библиотека создать не разрешает.
2. Исключение compactStorageKeeping выходило из callback, оставляя busy и
   отключённые кнопки. Теперь показывается ошибка и можно закрыть окно;
   повторное сжатие/пробы требуют нового сеанса сбора. Контроллер уже
   попытался открыть контейнер в finally — повторный unlock из Cancel после
   такого отказа не запускается. Ошибки пробы также снимают busy. В журнале
   сохраняются этап и frames, без исходного текста исключения/пароля/пути.
3. barrierDismissible:false не запрещал системный Back. Диалог исчезал, а
   сессия оставалась остановленной. PopScope запрещает такой выход;
   явная «Отмена» проходит штатное восстановление.
4. Controller теперь отказывает до teardown/native I/O, если список не
   содержит пароль, которым он обязан открыть текущую личность после сжатия.
5. Ввод дополнительных паролей больше не обрезает краевые пробелы.

Красные проверки до исправления: повтор под другой подписью принимался;
ошибка rewrite не обрабатывалась; system Back удалял диалог; отсутствие
reopen-пароля доходило до следующего шага вместо явного отказа. Ошибка
mock-предусловия SharedPreferences исправлена отдельно и не считается
дефектом продукта. Проверки — `compaction_failure_dialog_test.dart` и
существующие compaction suites.
