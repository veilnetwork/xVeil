# Дополнительные пропуски речи из-за слишком малого jitter reserve

2026-11-02. Локальный SDK; push/релиза и установки пользователям нет.

## Подтверждённый механизм

На вход одного и того же настоящего Opus/NetEq поступают одни и те же пакеты,
включая переупорядочивание и скачки времени доставки. В lossless-профилях сеть
не удаляет ни одного пакета. Прежний RecoveringNetEq ограничивал адаптивную
цель значениями 100/120/140 мс для 20/40/60-мс пакетов и затем подрезал очередь,
которую NetEq пытался сохранить для компенсации jitter. Сам приёмник создавал
дополнительный played PLC и отбрасывал полезную речь.

Выделены связанные места:

1. Разрешена адаптация NetEq до **400 мс**, без навязывания такого target всем
   звонкам. Более строгий caller maximum сохранён, как и cap числа пакетов.
2. Hard catch-up и проверка возраста RTP используют общий jitter reserve:
   target и запас на два пакета для прихода/декодирования. Если оставить старую
   age-only ветвь, она всё ещё расходует этот запас. На хорошей сети прежний
   номинальный budget 120–200 мс остаётся достаточным; 16 дополнительных pulls
   за callback и защиты PLC/mute/error не отменялись.
3. В ConversationNetEqController полный packet headroom добавлен после
   max(target, measured jitter). Прежняя форма max(target, jitter + packet)
   могла убрать этот пакет, когда target доминировал. Отдельный component
   regression был красным на прежнем guard с реальными history/target.

Это **подтверждённый механизм дополнительных пропусков**, не доказанная
единственная причина жалобы Poco/mobile ↔ Windows/Wi-Fi. Размер исходящих
пакетов и сетевой протокол не менялись.

## Контролируемая модель

Существующая voice fixture WebRTC кодируется настоящим Opus, 24 kbit/s,
20/40/60 мс, FEC on, DTX off. Приём — stock NetEq и production factory на
одинаковых отсортированных traces и 10-мс render ticks. Есть wrap sequence,
проверки packet insertion, формата декодирования и ненулевого PCM. Физических
устройств, сети, PCM export и порогов elapsed wall time в этой модели нет.

30 с симуляции, 1,5 с startup исключены из сравниваемых метрик. **Played PLC**
считается по фактически возвращённым render frames, включая PLC-CNG/mute;
concealed samples внутренних дополнительных pulls учтены отдельно.
Это не SPL, MOS и не буквальная длительность слышимой тишины.

| Пакет / синтетический профиль | Played PLC до → после | p95 локальной очереди до → после |
| --- | --- | --- |
| 40 мс, без jitter | 0 → 0 мс | 51 → 51 мс |
| 60 мс, без jitter | 0 → 0 мс | 76 → 76 мс |
| 40 мс, jitter 0–200 мс | 1160 → 0 мс | 145 → 184 мс |
| 60 мс, jitter 0–200 мс | 500 → 0 мс | 179 → 202 мс |
| 40 мс, периодические задержки 250 мс | 4350 → 580 мс | 164 → 283 мс |
| 60 мс, периодические задержки 250 мс | 4160 → 590 мс | 194 → 301 мс |

Дополнительный буфер при плохом jitter — **осознанная цена непрерывности**.
Остаточный PLC первых непредсказанных всплесков не объявляется устранённым.
Stock NetEq — контроль, не реализация другого мессенджера.

Финальный A/B/A: A₁ и A₂ равны по всем 36 строкам; отдельные временные include
roots для прежних и новых заголовков, свежие сборки каждого исполняемого файла.
[Baseline](baseline.csv), [candidate](candidate.csv), [агрегат](summary.json).
Проектный regression проходит **108 decoder runs / 54 пары** на трёх seed;
дополнительный probe — 90 пар на пяти seed. Эти повторные/перекрывающиеся
прогоны не складываются в число уникальных сценариев.

Промежуточные кандидаты не скрыты: только поднятый target cap оставлял
повторные потери; одного пакета reserve было мало; два пакета в hard-budget
без согласования age-only guard тоже оставляли лишние 20 мс played PLC в
одной 60-мс трассе. Финальный reserve не даёт дополнительного played PLC
против stock во всех проверенных lossless-парах. Профиль с реальной потерей
3% измеряется отдельно, универсальный zero-loss результат не заявляется.

## Проверки и границы

- Red исходной модели — избыточный played PLC, не ошибка сборки. После фикса
  проходит расширенная матрица. Component guard также имел отдельный red.
- Recovery/lag/controller suite проходит: actual packet waiting time,
  ограниченные pulls, fallback, stricter caller bounds, RTP reset/reorder,
  DTX/DTMF и timescale cooldown сохранены. Nominal catch-up проверен отдельно
  от полезного adaptive reserve.
- В анонимный direct media sample добавлен **целочисленный jitter target**,
  диапазон −1..60000. Строки, дробные значения, bool и посторонние поля не
  экспортируются. 32 scoped diagnostic tests и AOT privacy gate прошли;
  analyzer двух файлов без замечаний. Group peer maps в отчёт не копируются.
- Платформенные engine pins ещё не обновлялись. Исторический NETCALL-handover
  и исходная слышимость Poco ↔ Windows этим стендом не квалифицированы.
- Нужна отдельная проверка видео при длительном большом reserve: существующие
  правила восстановления competing sources могут удерживать рост видео,
  пока audio target/queue высоки. Эти правила здесь не ослаблялись, улучшение
  видео при jitter не заявляется.

## Отдельно о PCM-стенде групп

Прежний трёхсторонний стенд использовал периодические тоны как markers свежей
речи. С новыми AEC/NS он не проходил критерий числа marker frames **и на
контрольной, и на новой библиотеке**; выключение одного NS не помогло.
Изолированные source builds с прежним AGC-only прошли 15/15 marker frames
на обоих вариантах receiver. Это не основание ослаблять порог восстановления.

Только test-only group codec factory теперь явно выключает AEC/NS для этого
спектрального oracle. Ни критерии 200 мс / 12 из 15 frames, ни production
настройки DSP не менялись. Default-on AEC/NS отдельно проверяются ordinary
engine constructors/live controls и реальной speech/APM-моделью; codec-tone
результат не выдаётся за квалификацию слышимости или акустики с DSP on.

Финальный native стенд также прошёл:

- isolated group-codec: 15/15 fresh marker frames, первый через два render ticks
  после resume, возраст около 172 мс; исходные пороги 200 мс / 12 из 15 сохранены;
- ordinary direct/group constructors и NS on/off/on сохраняют production AEC/AGC
  и живые send-stream/ADM;
- `call_planes_smoke` без аргументов: Opus при удержанных video queues, bounded stats,
  muted lifecycle, восстановление и teardown;
- default pair PCM suite с production DSP on: оба режима capacity прошли прежние
  gates, поздние markers около 109–123 мс; это decoded PCM на synthetic ADM,
  **не физическая слышимость речи**.

Библиотеки собраны заново из финальных исходников; source/binary hashes и
проверки промежуточных контролей хранятся приватно. Все запущенные native
процессы завершились, телефон/реле/приложения пользователей не изменялись.
