# NETCALL-01: связь логического dial с TCP handshake

**Закрыт пробел операторской диагностики.** Новый локальный connect context
связывает выбранную строку peer с основным/запасным TCP-сокетами obfs4 и
вспомогательными dials этого родителя. Восстановление звука и индивидуальная
атрибуция прежних мобильных потерь этим не объявляются исправленными.

## Зачем и как

В [предыдущем захвате](../call-partial-reconnect-wake-2026-11-18/README.md)
получены согласованные агрегаты незавершённых first flights и TCP flows без
payload. NAT заменяет source ports, а у трёх Core одинаковый destination port.
Временное соседство строк не связывает конкретный сокет с выбранным Core.

При включённом прежнем TCP trace gate NodeServices выделяет непрозрачный
process-local номер для dial. Операторская запись `transport.connect.context`
содержит этот номер, **ожидаемый локальный peer_slot**, scheme и monotonic_us.
Это диагностическая ссылка на строку вызывающего runtime, не доказательство
удалённой личности или доставки. Таблицу slot → target надо сохранять вместе
с захватом; неизвестные/сменившиеся строки нельзя домысливать по близкому времени.

Метаданные передаются через TransportContext. В `tcp_handshake` номер
присутствует с первого наблюдения. Разделены три области:

- `connect_context` — логический dial/родитель, общий также для его auxiliary;
- `attempt` — одна транспортная попытка с её основной и запасной ветками;
- `connection` — один физический TCP-сокет.

Клонированный контекст сохраняет origin для auxiliary dials, созданных обычным
StreamParallelHandle. Следующий вызов NodeServices получает свежий номер.
При выключенном trace унаследованный context очищается, новый не выделяется;
отключение также подавляет записи уже начатого handshake. Родитель, созданный
до включения trace, может остаться без context: захват надо включать до новых
dials, а не приписывать ему последующую метку.

В wire, handshake transcript, KDF, socket options, timeouts, backup-политику,
admission и авторизацию ничего не добавлено. Нет новых задач, таблицы состояний,
персистентности, адресов, ключей, payload или обозначений роли трафика.
Обычный Debug новых типов скрывает сам номер. Это приватная операторская
диагностика, не поле анонимного отчёта.

## Проверки

- Весь veil-transport на macOS release: **185 unit + 5 integration + 2 doc-tests
  passed**, без ignored. Реальная обвязка удерживает молчащую основную ветку,
  принимает запасную с настоящим obfs4, затем открывает дополнительное
  соединение через настоящий factory. Все три сокета имеют один context,
  разные connection IDs и правильную основную/запасную выборку. Новые поля
  есть уже в start; полезная нагрузка проходит без добавочных байтов.
- Настоящий NodeServices с отказником до сети: выключено/два включённых dial/
  выключено. Четыре context-входа равны None/разным новым значениям/None;
  унаследованная метка не используется. Только две операторские mapping-записи,
  без адреса и ключей. Этот stub-контроль не объявляется сетевой доставкой.
- **8 runtime-проверок passed / 0 skipped**: новая проводка и семь связанных
  canonical/auxiliary resume, admission и NetworkChanged retirement проверок.
- **25 Dart-тестов passed**. В анонимный JSON не попадают context, peer_slot,
  их числовые значения и сырые mapping-строки. Запрещённый lazy-object не
  обходится ради сериализации.
- Python artifact-тест прошёл: настоящие host AOT-executables с диагностикой
  и без неё не экспортируют эти поля. Это один harness с двумя режимами,
  не Android AOT-квалификация.
- Clippy release/tests с `-D warnings`, Rust formatting, whitespace и staged
  privacy checks прошли. Исходники хешированы до/после проверок. Повторные
  прогоны и отфильтрованные binaries с нулём тестов не суммируются.

## Подготовленный Android probe

Для изоляции подготовлен отдельный Network Call QA: baseline SDK `53fbbe34`
с ровно пятью diagnostic-only source changes. Это не квалификация всех
изменений текущего native HEAD. Старые Dart AOT, Flutter, media, storage и
assets сохранены побайтно; изменяется только SDK внутри прежнего QA APK.
Основной xVeil и его данные не заменяются.

SDK собран в отдельном worktree и отдельном внешнем target. Mount проверялся
до и непрерывно во время Cargo; source SHA после сборки совпали, оба маркера
найдены в библиотеке. Неизменные FFI declarations и тот же набор 217 C exports
сверены, PT_LOAD выровнены на 16 КиБ, debug signing certificate совпал, zipalign
и подпись проверены. Проверка ELF loader dependencies также прошла: несистемные
зависимости присутствуют в APK. Полная загрузка на Android ещё требует проверки.

Дополнительный raw-file privacy scan сработал на уже разрешённых crypto/locale
подстроках. Проверены все 14 printable contexts. Независимо выполнены **оба**
набора literal/regex patterns после маскирования только существующих literal
allow-substrings, без удаления остального содержимого строк: совпадений нет,
домашнего абсолютного пути нет. Обычная archive-policy проверка SDK также
прошла. Исключения и правила scanner не расширялись. Это аудит библиотеки,
не утверждение о публикации приватного testnet APK.

Перед установкой Poco исчез из ADB и USB; три повторных проверки подтвердили
отсутствие. Установка **не начиналась**, новые permissions, forward, native
node и окна не запускались. Сохранены SDK/APK и provenance; собственный
worktree и dedicated build target удалены, освобождено примерно 1,63 ГиБ.
Общий release cache и прежние Flutter cache entries не удалялись.

Следующий шаг — загрузить SDK в QA на Poco и выполнить захват с mapping-записями,
снимками peer slots и измеренными границами соответствия часов телефона/реле.
Без этого прежние first-flight потери индивидуально не атрибутируются.
NETCALL-01 остаётся активным. Push/релиза нет.

## Офлайн-отбор временных кандидатов

Добавлен [analyze_tcp_connect_candidates.py](../../../scripts/analyze_tcp_connect_candidates.py).
Он принимает нормализованный приватный JSON одного процесса телефона и одного
захвата. Ничего не подключает, не включает trace, не меняет сеть/таймауты и не
читает реальные контейнеры. Это инструмент проверки гипотезы, не исправление
мобильной паузы и не доказательство тождества потоков.

```sh
python3 scripts/analyze_tcp_connect_candidates.py /private/evidence.json
```

Вход имеет schema `xveil-tcp-connect-evidence/1`, `single_process_capture: true`
и следующие поля. Все времена — целые наносекунды; process-local IDs и target
labels действуют только внутри этого входа, target labels не являются адресами.

| Поле | Содержание |
|---|---|
| `clocks.phone` | `kind: monotonic`, `samples`, `drift_ppb`, `resolution_ns` |
| `clocks.cores[]` | То же, но `kind: realtime` и локальный label `target` |
| `samples[]` | `local_before_ns`, `local_after_ns`, `reference_before_ns`, `reference_after_ns` |
| `slot_targets[]` | Наблюдавшиеся пары `slot`, `target`; отсутствующий/изменившийся slot не используется |
| `contexts[]` | `id`, `slot`, `start_ns`, `fixed_target_direct_only` |
| `connections[]` | `id`, `context` (или null для старого родителя), `start_ns` первого handshake observer |
| `flows[]` | `id`, `target`, `syn_ns`, `synack_ns`, `client_payload_bytes` |

Для phone local clock нужен **CLOCK_MONOTONIC**, совпадающий с native trace;
`/proc/uptime`/BOOTTIME не подходит. Для PCAP local clock — время захвата Core.
`reference_*` — границы удалённого чтения по **одним и тем же монотонным часам
сборщика**, а не оценка по середине RTT и не время из NTP. Нужны независимые
калибровки до и после событий. Их длительности целиком входят в погрешность;
допуск относительного изменения clock offset задаётся явно в ppb. Противоречивые
и непокрытые калибровкой события отклоняются. Точность исходного timestamp
(`resolution_ns`, например микросекунда) также расширяет границы. Это не
способ обнаружить любое временное изменение часов между двумя пробами;
при подозрении на suspend/clock step нужен новый ограниченный захват.

Нормализация должна сохранять все конкурирующие client connections и серверные
SYN/SYNACK flows выбранного окна. Родители/auxiliary, созданные раньше включения
trace, не получают выдуманный context. Неизвестный, изменившийся или не полностью
проверенный target остаётся неизвестным. `fixed_target_direct_only` допустим
только при независимо проверенной фиксированной цели без NAT-traversal/proxy/
другого fallback в наблюдаемом dial: исходный peer_slot сам по себе этого не
доказывает. Неудачный TCP connect без handshake observer может оставлять лишний
серверный flow; равенство чисел потоков не требуется.

Отбор сохраняет только временно допустимые пары по ожидаемой цели:
`origin context ≤ server SYN ≤ server SYNACK ≤ client handshake start`.
Порты через NAT, ближайшее время, packet sizes и выдуманное окно RTT не служат
ключом. Результат `mutually_unique_temporal_candidates` означает **ровно одного
кандидата у обоих концов**. Сокет без context/проверенного target также блокирует единственность, если
временные границы допускают его участие; исключение из атрибуции не удаляет
конкурирующее наблюдение. При общем кандидате у двух сокетов оба остаются
неатрибутированными; жадного назначения и принудительного разрешения по порядку
строк нет. Даже единственный кандидат не доказывает удалённую identity,
доставку, принадлежность медиа или причину звуковой паузы.

Вывод содержит только агрегатные счётчики и явные ограничения. Нет исходных
ID/слотов/адресов/портов/timestamps, unknown metadata не копируется. Ошибки
CLI не раскрывают приватный путь или содержимое ошибочного JSON. Отсутствие
данных с обеих сторон отмечается явно, а не засчитывается как успешная проверка.
Сам JSON и его нормализатор пока остаются приватной операторской обвязкой;
этот скрипт не является парсером произвольного PCAP/native log.

Проверки: **20 новых unit/CLI-тестов passed**, плюс **6 queue timing + 8 shaper
timing passed**. Покрыты разрешение timestamp, RTT-границы, явный drift,
несогласованные/перевёрнутые часы, отсутствие калибровки, общий кандидат,
parallel/auxiliary неоднозначность, неизвестный target/fallback, пустой захват,
неэкспорт приватных полей и безопасные ошибки CLI.

При повторном ответе владельца «готов подтвердить» снова выполнен безопасный
launcher, но телефон ещё отсутствовал в ADB и USB. Отказ произошёл на get-state
**до установки**; последующая адресная проверка также не нашла Poco. APK,
forward, разрешения и приложения не менялись, фоновые стенды не запускались.
Следующая физическая проверка по-прежнему ожидает доступный телефон.
