# Аватар: ответ после смены версии и настоящий native обмен — 2026-11-11

## Подтверждённый дефект

Ограничение ответов на запрос аватара сохранялось десять секунд после ответа
со старой картинкой. Смена картинки, её удаление или применение нового значения
из device journal не сбрасывали ограничение. Новый запрос в этом окне не
получал новую версию, даже если её разовая live-рассылка была потеряна.
Это один подтверждённый механизм пропуска обновления, а не доказанная причина
исходной жалобы Windows 10.

После успешной записи **изменившегося** собственного аватара сбрасывается
история ответов прежней версии. Запрос новой версии может получить ответ сразу.
Повторы одной версии и idempotent apply по-прежнему ограничены; неудавшаяся
запись не достигает сброса. Контактное согласие, проверки владельца, sender
provenance и порядок device journal сохранены. Mailbox, Outbox и наблюдение
за присутствием для аватаров не добавлялись.

## Регрессионные проверки

Три сценария — локальное изменение, применение зеркального значения и удаление:

- Запрос получает исходное значение, немедленный повтор подавляется.
- После изменения запрос получает точное новое значение.
- Следующий повтор и повтор после no-op apply снова подавляются.

На прежнем коде **3 assertion-red**, на исправленном — проходят.
Итоговая связанная серия: **118 passed, 0 skipped на macOS и 118 passed,
0 skipped на Windows 11**. Включены настоящие worker/container проверки
владения пространством, paired exchange, consent races, виджеты, shutdown
и settings backfill. Анализ трёх изменённых Dart-файлов чист.

Первый локальный связанный прогон без opt-in native-owner группы содержал
100 тестов. Он не подменяет итоговый 118-тестовый прогон с включённой группой.

## Два настоящих sovereign узла

Добавлен opt-in `test/native/profile_avatar_native_pair_test.dart`:
две свежие независимые личности, настоящие encrypted containers и worker,
production RealVeilStack, QUIC loopback, FFI transport, ratchet persistence
и peer authorization. Нет fake transport, ручной инъекции входящих сообщений,
публичных сидов или изменения реле.

Проверены принятие контакта, обмен двумя картинками, изменение, удаление,
полное закрытие второго узла и повторное открытие его контейнера с той же
личностью. После открытия сохранены контакт, картинка собеседника, собственная
запись удаления и ratchet conversation. Затем проверены **новый подписанный
ответ на новый запрос** и обычное текстовое сообщение с точным ID и телом.
Совпадение старого кэша или предшествующая рассылка не засчитываются за ответ.

В итоговом захвате новое изображение сначала пришло как `Claimed` после
холодного открытия. Проверка подтвердила, что оно **не заменило** сохранённую
картинку. Запрос затем получил то же новое значение как `Signed`; после этого
кэш обновился. Это ожидаемая граница безопасности: восстановленные ключи
переписки не восстанавливают актуальное право устройства говорить от имени
личности. Авторизация не подменена историческими ratchet данными.

Полный native сценарий прошёл. У обоих узлов сохранена conversation;
профильные кадры посчитаны отдельно от подтверждённых, с ограниченной
атрибуцией по номерам синтетических картинок. Изображения, адреса, instance ID,
ключи и сырые трассы в опубликованный результат не входят.

Раннее предположение стенда, что transport device ID должен совпадать с
identity ID, было неверным и снято. В окончательном сценарии адреса контактов
берутся из sovereign invite/document и задаются production identity bindings.
Ещё один предварительный контроль совпадения кэша не доказывал новый ответ;
он заменён отдельным требованием нового `Signed` кадра.

## Сохранность и границы

Native библиотеки проверены по SHA и исходной версии до запуска; источники
не изменились во время проверок. SDK и hidden-volume в этом раунде не менялись.
После native сценария оба узла остановлены, runtime leases освобождены,
QUIC/metrics порты повторно привязаны, собственный временный каталог удалён.
Независимая проверка не нашла процессов его группы.

Windows-проверка временно подставляла 15 исходных файлов отдельного QA checkout.
Они восстановлены с проверкой SHA; добавленные тестовые файлы удалены при
восстановлении. Повторная полная проверка подтвердила неизменность исходного
QA контейнера, preferences, 807 канонических frontend файлов и native bundle;
собственных приложений и стендовых задач нет.

Это native интеграция двух узлов на одном Mac и unit/widget проверки Windows 11,
не физическая квалификация Windows 10, Android, публичной сети или нового AOT
bundle. Исходная жалоба Windows 10 остаётся открытой. Новая упаковка frontend
и обновление immutable media pins перед релизом по-прежнему нужны.
Push и релиз не выполнялись.
