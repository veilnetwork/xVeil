# Ограниченное объединение message append

2026-11-01. Продолжение [разбора Outbox и миграции](../outbox-ack-retirement-2026-11-01/README.md).
Подтверждённая цена прежнего пути: отдельная транзакция на каждую из 2000
записей принимаемой истории, даже когда несколько небольших сообщений одного
автора уже готовы к сохранению одновременно. Исправление нацелено на эту
локальную работу; остальные причины задержки догрузки остаются в учёте.

## Изменение

`appendMessage` объединяет **соседние ещё не начатые** записи одной пары
conversation/author, максимум **16**. Требуются уже заданные author и seq и
не более **1800 UTF-8 байт полностью закодированной записи**. Пачка занимает
не более 28 800 байт payload; более крупные сообщения сохраняют существующий
путь с фрагментами. Нет таймера накопления или ожидания дополнительных строк.

Это не новая проверка доверия к author/seq: прежняя аутентификация вызывающей
стороны не меняется. Локально выделяемые seq, крупная запись и команды в той
же author-очереди сохраняют отдельный ход и закрывают ожидающую пачку. Wire
seq не двигают локальный курсор, как и прежде. Общая очередь глобальных log ID
выделяет пачке непрерывный внутренний диапазон; авторские позиции не меняются.
Другая conversation/author продолжает работать независимо после первой
публикации общего shard-маркера.

Payload фиксируется при принятии в пачку; список inline emoji копируется.
На старте пачка закрывается до первого await. Общий helper публикует данные
и все новые shard-маркеры одной транзакцией, включая переход границы shard.
Он используется также прежним fragmented-путём. Все append futures ждут
полного durable commit; недействительный/неопределённый ответ не становится
успехом. Возможные данные после потерянного ответа включаются в live-fold,
как и в существующем одиночном пути.

Пачки остаются в `_withConvSequence` и `_trackLogWrite`: close/erase завершают
уже принятую работу на прежнем space, новые append во время fence отвергаются
до попытки присоединиться к ожидающей пачке. Схема хранения, подписи,
ratchet/checkpoint, tombstone, политики доступа и сетевые ACK не менялись.
Storage API не получил dedup: две прямые записи одного ID остаются двумя
post; защита mirror-versus-mirror находится уровнем выше.

## Детерминированные проверки

Зачтённый первоначальный red: **6 passed / 5 failed**. Это проверки нового
batch-контракта (40 отдельных commits вместо 16/16/8, раздельные результаты
ошибок, несоединённые shard-маркеры), а не пять новых объявленных дефектов
корректности старого одиночного API.

Первый fixture независимых авторов завис на общей first-use публикации shard:
это ожидаемый барьер. Он исправлен предварительной записью в другой разговор;
тот timeout исключён из red/green доказательства. После этого исходный код
проходит положительные контроли, а счётные/batch-assertions остаются красными.

Финальные 13 unit-сценариев проверяют размеры пачек, implicit-seq барьер,
all-or-none при отказе до commit и потере ответа после commit, live/cold fold,
сохранение seq-курсора, ожидание durable записи, закрытую начавшуюся пачку,
close/erase с поздним producer, независимые conversation/author, два shard
в одной транзакции, крупный fragmented post, UTF-8 byte bound и поля файловой
записи, clear-barrier и отсутствие нового storage-level dedup.

Связанный набор — **192 passed**. Analyzer production-файла и двух новых
fixture чист. Native-набор — **10 passed**: шесть новых проверок настоящего
worker-backed контейнера плюс крупные incompressible post/edit/delete и
предыдущий ACK-Outbox набор. Прежние несвязанные форматные строки большого
production-файла сохранены; новые тесты отформатированы, diff-check чист.

## Native A/B/A

Неизменный fixture, 128 небольших сообщений с готовыми seq одной author-очереди.
Измеряется только append; затем реальные close/reopen, все ID, порядок,
delivered и high-water 128 без holes проверяются отдельно. Для каждой фазы
создаётся новый зашифрованный контейнер, используется тот же HV по SHA.

| Фаза | Data commits | Строк в commit | Время append |
|---|---:|---|---:|
| A₁, прежний код | 128 | по 1 | 2354,317 мс |
| B, кандидат | 8 | по 16 | 245,510 мс |
| A₂, прежний код | 128 | по 1 | 2400,256 мс |

A₁/A₂ побитово одинаковы, native fixture не меняется, кандидат восстановлен
в `finally`. Это цена одновременно готовых записей, **не** обещание такого
же выигрыша всей миграции. Первый candidate-native набор запускал несколько
тестов параллельно и дал 522,541 мс; он квалифицирует корректность, но для
таймингов используется только изолированная A/B/A-таблица.

## Межпроцессная начальная миграция

A/B одной личности и C другой: отдельные процессы, worker-backed контейнеры
и три локальных реле на одном Mac. Текущий SDK `eb644a83`; CLI/FFI/HV по тем
же SHA, без public seeds/discovery. Только initial migration на новое B;
пятиминутный offline, revoke/split-brain/crash этим режимом не выполняются.

A₁ — предыдущая серия с ACK-исправлением, B — текущий кандидат, A₂ — обратный
контроль. Все **568 frozen-файлов A₁/A₂ совпали**; от B отличается только
`hidden_volume_storage.dart`, остальные 567 одинаковы. SDK и native артефакты
не меняются. Контроллер восстанавливает кандидат после A₂ в `finally`.

| Фаза | Первое полное наблюдение | Message-log commits B | Outbox commits A |
|---|---:|---:|---:|
| A₁, прежний код | 72,220 с | 2001 | 970 |
| B, кандидат | 51,548 с | 432 | 1082 |
| A₂, прежний код | 77,953 с | 2147 | 1072 |

Message-log колонка включает также статусные/ordering-записи, Outbox — enqueue
и retirement. Это не количество только новых сообщений или только ACK.
В каждой фазе все **2000 ID/порядок A/B/C совпали**, на B все delivered;
retry старых message ID **0**. На кандидате 2001 append со служебной строкой,
ноль повторных успешных append пары в окне, ноль ошибок, лимит учёта не достигнут.

Улучшение подтверждено для **этой local/JIT A/B/A-серии**: сокращена измеренная
цена записи, принимающий клиент выполняет меньше message-log транзакций,
время полного наблюдения ниже обоих baseline. Опрос около 5 с, отсчёт после
link-подготовки; это не точное время последнего пакета. Не заявляется такой
же эффект на Android/AOT, другом провайдере, длительном offline или всех путях
доставки. Расхождение 2001/2147 baseline message-log коммитов отдельно не
атрибутировано; лишние служебные записи и оставшиеся 51,5 с ещё требуют разбора.

Кандидат: **1 E2E passed**, 247,428 с с подготовкой/teardown; **18 PIDs /
19 портов** проверены независимо. Обратный контроль: **1 E2E passed**,
274,261 с; **18 PIDs / 18 портов**. Исходники/native артефакты проверены до/
после, оба runtime-root удалены, собственных процессов/слушателей нет.
Четыре native test process groups и два пассивных наблюдателя также завершены,
временных native-контейнеров нет.

В первоначальном teardown-collector был дефект: пустой набор живых PID
превращался в lsof без фильтра и захватывал чужие порты. Затем отдельная проверка
обнаружила законное повторное использование одного порта новым A₂-стендом.
Collector исправлен: учитываются только строки собственных PID и локальные
порты, повторное использование другим PID не выдаётся за утечку старого стенда.
Старые PIDs отсутствовали во всех проверках; чужие процессы не останавливались.
После завершения контроля обе полные независимые проверки прошли, исходники
кандидата восстановлены. Этот сбой учёта не используется как product red.

[Публичный результат](result.json) содержит только агрегаты. Raw logs,
локальные IDs, private tail-снимки и полные source/binary proofs не публикуются.
Production-серверы, телефон и Windows не менялись. Догрузка остаётся активной;
полная multi-device матрица и остальные сетевые/звуковые случаи не закрыты.
Коммит локальный, unsigned, push/релиза нет.
