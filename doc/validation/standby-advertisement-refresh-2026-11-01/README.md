# Снятый запасной endpoint оставался в hot-standby

2026-11-01. SDK `026dd915` → `eb644a83`.
**Подтверждено и исправлено в коде.** После нового принятого handshake
`auto_set_alt_uri_from_transports` возвращал `None`, если peer больше не
объявлял пригодный alternate, но прежняя запись оставалась в `auto_alt_uris`.
`alt_uri_for` продолжал возвращать старый listener для автоматического
переключения. После снятия ручной настройки старый learned endpoint также
неожиданно возвращался.

Это отдельный дефект обновления транспортных сведений, найденный при разборе
[QUIC/obfs4-контроля](../quic-proxy-nic-control-2026-11-01/README.md). Его связь
с прежними физическими паузами **не доказана**. Автоматический hot-standby
по умолчанию выключен (`HotStandbyConfig`); в приложении и на стендовых
серверах его здесь не включали. Правка не является исправлением текущего
холодного QUIC startup или NETCALL-01 и не добавляет automatic TCP fallback.

## Изменение

Непустой новый список advertised transports заменяет learned-набор. Если
после прежних parse/local-capability/primary-проверок нет пригодного alternate,
удаляется только `auto_alt_uris` этого peer. Если кандидат есть, сохраняется
прежний выбор и bounded insertion.

Ручной `alt_uri` остаётся в отдельной карте и имеет прежний приоритет. Другие
peers не меняются. Пустой список не является доказательством снятия listeners:
runtime уже пропускает его для отсутствующего TLV, например при legacy/resume.
Поэтому такая пустая передача сохраняет прежнее знание и в самом helper.
Политики enabled, flap damping, handoff, подписи и wire не менялись.

Runtime вызывает helper при commit уже принятого handshake, после admission
проверок. Этот барьер не переносился; отказанный handshake не получает новой
возможности менять learned-карту. Замена адреса не объявляется криптографическим
отзывом доступа или device revoke.

## Регрессии

На прежнем production-коде **0 passed / 3 failed**, без сетевых таймингов:

1. Выучить alternate → новый список содержит только primary → старый endpoint
   всё ещё возвращается. После исправления его нет, `try_auto_trigger` не
   запускает probe по снятому listener.
2. Выучить alternate, задать ручной, обновить список до primary-only → ручной
   остаётся; после его удаления прежний learned не должен возвращаться.
   Настройка другого peer при этом сохраняется.
3. Новый непустой список содержит только некорректный URI и недоступный локально
   webtunnel → прежний learned тоже не должен оставаться кандидатом.

Дополнительный положительный контроль: пустой список сохраняет прежний
alternate. Действующие тесты выбора новой замены, ручного приоритета, handoff,
rotation и flap damping прошли вместе с полным session-набором.

## Проверки и границы

- `veil-session --lib`: **683 passed / 8 ignored**. Четыре новых теста входят
  в этот счёт; отдельным повторным числом passed их не складываем.
- Runtime `peer_handshake` filter: **22 passed / 784 filtered out**; это
  ограниченная повторная квалификация вызывающего пути, не весь runtime.
- `rustfmt --check` изменённого файла и `git diff --check` прошли.
- Cargo target на внешней ФС; mount проверен до запуска и watchdog не отметил
  его потери. После команд собственные Cargo/test process groups завершены.
- Native release-библиотека/QA-приложение под новый SDK не пересобирались и
  не устанавливались. Прежние physical results относятся к своим зафиксированным
  версиям; это изменение квалифицировано host-тестами.
- Stand-приложения в этом цикле не запускались, production/testnet серверы,
  телефон и Windows не менялись. Сырые логи тестов приватные; публичный result
  не содержит node IDs, адресов, ключей или пользовательских путей.
- Коммиты локальные, unsigned; push и релиза нет.

Общий список незакрытых случаев остаётся в [сводке](../open-findings-2026-10-28/README.md).
Холодный QUIC, мобильный handover, слышимость речи, догрузка большой истории и
расширенная multi-device матрица этим исправлением не закрываются.
