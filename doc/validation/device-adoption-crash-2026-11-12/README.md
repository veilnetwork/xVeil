# Восстановление привязки устройства после завершения процесса

Четыре точки аварийного завершения целевого устройства прошли проверку:
сохранённые документ личности и согласие на присоединение соответствуют границе
записи, физический ключ устройства сохраняется, история восстанавливается без
дублей. Новый дефект в этих сценариях не обнаружен; производственный код не
менялся. Это дополнительное частичное покрытие link/crash из пункта 63 общей
multi-device матрицы.

## Проверенные границы

| Остановка целевого B | Холодное состояние контейнера | Продолжение |
|---|---|---|
| До записи документа семьи | Прежняя личность B, согласия нет | Повтор с исходным токеном, обычный restart |
| После записи документа семьи | Документ семьи сохранён, согласия нет | Повтор с исходным токеном |
| До записи согласия | Документ семьи сохранён, согласия нет | Повтор с исходным токеном |
| После записи согласия | Документ и точное согласие сохранены | Исходный snapshot принимается без повторного сканирования |

Устройства A/B/C работают в независимых OS-процессах с настоящими узлами Veil,
зашифрованными hidden-volume контейнерами и production providers/services xVeil.
A — источник личности, B — первоначально отдельная личность, C — внешний контакт.
Перед привязкой A отправляет C контрольное сообщение, которого у B ещё нет.
Транспорт работает через существующий изолированный loopback-стенд; установленные
пользовательские приложения и публичные серверы не используются.

Тестовая storage-обёртка B останавливает процесс SIGSTOP непосредственно до
`storeFile` либо после завершения настоящей записи. После публикации свидетеля
нет await, позволяющего операции продолжиться. Родитель проверяет принадлежность
реального VM нужной process group, завершает группу SIGKILL и ждёт выхода VM.
Обёртка подключается только в process fixture по отдельному тестовому флагу;
в приложении новых endpoint или fault flags нет.

## Проверка холодного состояния

Источник A выключается до проверки контейнера и холодного запуска B. Поэтому
он не может восстановить потерянное состояние при этих проверках. Старый runtime
B удаляется после выхода процесса; ключи и данные контейнера не пересоздаются.

Родитель отдельно открывает зашифрованный контейнер прежним паролем. SHA-256
сохранённого значения сверяется со свидетелем конкретной записи: до store нового
значения нет, после store присутствует именно оно. Для согласия дополнительно
проверяется полный исходный token, включая group/source/manifest binding.
В точках без согласия пусты оба его места хранения — файл и legacy setting.
Секретный материал не включается в свидетель: он содержит только digest.

B сохраняет исходный physical device ID. До записи документа он запускается
с прежней identity, после неё — с identity семьи. До получения snapshot группа
ещё не материализована. После возврата A он держит первоначально подготовленный
group ID. В трёх точках B повторяет операцию с тем же свежим токеном; в четвёртой
этот повтор не выполняется. Новый токен и новая source-side церемония не нужны.

## Проверка после восстановления

После обычной передачи исходного snapshot B принимает первоначальную группу
и старую контрольную запись. Затем B отправляет новое сообщение C, а C отвечает
семье: сообщения видны на A и B. Для всех трёх контрольных сообщений проверяются
единственность, одинаковые ID и итоговый порядок на A/B/C. Это исключает замену
сохранившегося сообщения новой записью с похожим текстом. Ratchet после crash
проверяется новым обменом в обе стороны.

Финальная усиленная серия — **4 passed, 0 skipped**. Предварительная серия также
прошла четыре точки, но источник ещё не выключался при cold-open и проверка
ограничивалась единственностью текста; эти дополнительные свойства подтверждает
именно финальная серия. Снимок исходников и SHA выбранных native-входов до/после
финального запуска совпали. Targeted analyze и `git diff --check` проходят.

После финальной серии подтверждены выход 34 учтённых процессов/групп, отсутствие
test VM и освобождение 33 зарегистрированных портов по TCP/UDP. Синтетические
контейнеры удалены штатным teardown. Предварительная серия очищена независимо.

## Запуск и границы

Тест: `test/e2e/device_adoption_crash_e2e_test.dart`. Нужны готовые согласованные
`XVEIL_E2E_VEIL_CLI`, `VEIL_FFI_DYLIB`, `HIDDEN_VOLUME_FFI_DYLIB`, приватный каталог
`XVEIL_E2E_EVIDENCE_DIR` и `XVEIL_E2E_DEVICE_ADOPTION_CRASH=1`. Запуск —
`TMPDIR=/private/tmp/ flutter test --no-pub --concurrency=1 test/e2e/device_adoption_crash_e2e_test.dart`.

Квалификация выполнена на macOS arm64/JIT, CLI/SDK `e963fbdb`, локальной
hidden-volume `293792d`. Это SIGKILL вокруг двух завершённых storage API, а не
потеря питания внутри native commit. Путь вызывается через существующий debug
caller; GUI-сканирование на Android/Windows этим тестом не квалифицируется.
Часы/сутки offline, истечение токена и crash при применении/поглощении snapshot
остаются отдельными участками. Полного покрытия пункта 63 или всей матрицы нет.

Совместимость старых версий и relay mailbox для собственных устройств в эту
проверку не добавлялись. Нового выпуска или push нет.
