# Незавершённое чтение всех сегментов одного заголовка

2026-11-01. Продолжение [профиля групповых файлов](../file-write-profile-2026-11-01/README.md).
Найден и исправлен повтор уже прочитанных волн сегментов параллельным поздним
читателем. Это производственная правка read-path, не отключение проверок и не
кэш принятого журнала между запросами.

## Механизм и границы

До исправления разделялась только отдельная активная волна из восьми файлов.
Когда первый load прочитал её и ждал следующие сегменты, поздний load снова
платил за первые восемь. Gated-тест воспроизвёл ровно два чтения каждого из
первых восьми сегментов вместо одного. Это счётная проверка, без порога времени.

Теперь для группы разделяется незавершённое чтение записей по **точно тем
же байтам заголовка**. Каждый load отдельно декодирует свой header и создаёт
свои domain-объекты, проверяет manifest, ключи и прочую авторизацию по прежнему
пути. Общие разобранные JSON-записи сегментов уже были допустимым входом прежнего
per-wave sharing; новая область не хранит GroupBundle или signature-verdict.
Список строк принадлежит каждому caller, mutable signature/key bytes в моделях
не разделяются. Публичные API, wire, порядок коммитов и durable барьеры не менялись.

Область удаляется при завершении/ошибке, save, purge и shutdown. Новый заголовок
не присоединяется к старому, позднее завершение старой операции не удаляет новую.
Завершённое чтение не маскирует последующее удаление/повреждение/восстановление.
Read, перешедший к прямому чтению после таймаута ожидания write, также обходит
эту область: потенциально незавершённый view не должен стать общим.

## Проверки и промежуточный кандидат

- Red прежнего кода: **0 passed / 1 failed**, восемь счётчиков были 2 вместо 1.
- Три concurrency-контроля проходят: late wave, новый header при заблокированном
  старом и завершение старого при ещё незавершённом новом.
- Дополнительно воспроизведён край собственного первого кандидата: timeout-view
  присоединялся к общему read. Red **0/1**; добавлен bypass при активном write,
  отдельный контроль прошёл. Предварительный native-замер не смешивается с финальным.
- Сохраняются проверки независимости mutable моделей, повторного чтения после
  завершения, отдельных signature-verdict, отказа при missing/corrupt segment,
  repair, legacy/oversized segment и retry заголовка, который обогнал save.
- Окончательный scoped-набор: **400 passed / 3 skipped**, analyzer без замечаний.
  Три пропуска не считаются пройденными; повторные узкие прогоны не прибавлены
  как уникальные тесты.

Первый повторный запуск native-runner не начался: при архивировании
промежуточных файлов glob захватил сам runner. Он восстановлен; этот отказ
не засчитан ни как product red, ни как прошедшая фаза.

## Окончательный native A/B/A

Реальный worker/HV и native signatures, 128 строк, 9 сегментов. В каждой фазе
12 одиночных чтений и 12 пар: первый reader удерживается перед второй волной,
второй начинает после завершения первой. Gate — постановка сценария, не часть
протокола. Ни потери сети, ни реального multi-device здесь нет.

| Режим | Payload-read RPC A₁ / B / A₂ | Metadata-batch RPC A₁ / B / A₂ | Время A₁ / B / A₂ |
|---|---:|---:|---:|
| 12 одиночных | 120 / 120 / 120 | 48 / 48 / 48 | 0,376 / 0,363 / 0,372 с |
| 12 пар | 240 / 132 / 240 | 96 / 48 / 96 | 0,708 / 0,358 / 0,686 с |

Парный участок примерно вдвое быстрее в этом сценарии; одиночный не стал читать
больше payload. Header get RPC в парах остались 48 во всех фазах. Прошли сравнение
всех строк, независимость возвращённых моделей и реальный missing/repair с
последующей проверкой native-подписей. A₁/A₂ source идентичны; библиотека,
fixture, storage и timing-adapter проверены по SHA до/после каждой фазы.
Кандидат восстановлен в finally. Это выигрыш участка, не всей доставки.

## Сквозная квалификация

Migration-only A/B/C с 2000 сообщениями, current SDK/CLI/FFI/HV и усиленным
observer ID/порядка/эффективных позиций/delivered прошёл во всех трёх фазах.
Один Mac/JIT, private loopback-реле; public discovery/seeds выключены.
A₁ — предыдущий диагностический прогон, A₂ — новый обратный контроль; все
568 frozen-файлов A₁/A₂ совпадают, в B отличается только group_service.dart.
Библиотеки и timing-adapter одинаковы. Файл кандидата восстановлен в finally.

| Фаза | Первое полное наблюдение сходимости | Payload-read RPC сегментов A / B |
|---|---:|---:|
| A₁ | 51,503 с | 1770 / 2007 |
| B | 46,649 с | 1397 / 1592 |
| A₂ | 72,408 с | 4905 / 5182 |

В каждой фазе на A/B/C совпали полные 2000 ID/порядок, на B все delivered,
старых message retries 0. Сам B прошёл быстрее обоих контролей, но **устойчивое
сквозное ускорение не доказано**: обратный контроль имеет большой разброс и
другую длительность восстановления недостающих строк. Опрос раз в пять секунд
также ограничивает точность времени готовности. Полное количество и исходные
позиции не смешиваются: у A₁ 2000 ID были раньше полного ordering, у B/A₂
полное наблюдение сразу совпало.

В A₂ при уже полученных более поздних сообщениях не хватало одной непрерывной
порции из 25: count=1975 оставался с 46,854 до 62,187 с в наблюдениях, затем
1982 на 67,296 с и 2000 на 72,408 с. Причина задержки этой порции не установлена;
факт не означает доказанную потерю сети, ошибочный ACK или конкретный retry.
Это следующий предмет разложения. Многократные полные load в этом контроле
также не объяснены одним лишь размером истории.

Счётчики file scopes заканчиваются финальными inspection, в разные моменты на
устройствах; окна приведены в result.json. Ожидания могут перекрываться,
родительский call и вложенный RPC нельзя складывать как отдельные секунды
критического пути. Это не Android/AOT, пятиминутный offline или вся матрица.

В новых B/A₂ проверены выход 18 собственных PIDs в каждой фазе, освобождение
20/21 захваченных портов от собственных listeners, удаление runtime-контейнеров
и неизменность всех 568 frozen-файлов/библиотек внутри каждой фазы. Native
A/B/A также завершил свои процессы и удалил временные контейнеры. Production-реле,
телефон и Windows не менялись; push/релиза нет. Остальные активные дефекты и
полная multi-device матрица этим изменением не закрываются.
