# Докачка файла Mac → Poco после аварийного завершения источника

## Результат

Проверка на физических устройствах пройдена: файл **8 МиБ** получен полностью
за **95,581 с**, SHA-256 исходного и полученного файла совпал. Источник был
принудительно завершён после записи **4 МиБ**, оставался выключенным 10 секунд
и запустился с той же личностью. На приёмнике не нажимали загрузку повторно.

| Участок | Фактическое наблюдение |
| --- | --- |
| Начало | Штатный запрос контакта и подтверждение сошлись на обоих устройствах |
| Транспорт | P2P запрещён для тестового контакта; журнал подтверждает anonymous stream |
| Обрыв | Отдельная process group источника завершена через `SIGKILL`; старый процесс отсутствует |
| Пока источник выключен | Записанный размер остаётся 4 МиБ |
| Возвращение | Та же личность источника; принят запрос `contentReoffer`, манифест восстановлен из сохранённого источника |
| Продолжение | Второй stream-запрос содержит `resume=4194304`, то есть продолжает с 4 МиБ |
| Завершение | Получены все 8 МиБ, хеш совпал; завершение произошло после запуска источника |

Сценарий проверяет реальное продолжение с сохранённой позиции, а не получение
оставшихся байтов из уже заполненного буфера. После обрыва сработал штатный
20-секундный таймаут отсутствия payload, затем повторный запрос и докачка.

## Условия и воспроизведение

1. Установить отдельный debug QA-пакет на Android и запустить отдельный профиль
   на Mac; создать две тестовые личности без использования пользовательских
   контейнеров. В этой проверке использована обычная производственная сложность
   PoW и публичная сеть.
2. Через API приложения отправить запрос контакта и принять его на другом
   устройстве. Проверить возможность обмена на обеих сторонах.
3. Запретить P2P для контакта на обеих сторонах; отправить случайный файл 8 МиБ
   штатным `send_file`, затем начать `download_file` в отдельный тестовый файл.
4. После фактической записи 4 МиБ остановить только process group источника.
   Проверить завершение процесса, выждать 10 секунд, запустить тот же профиль
   и открыть его контейнер.
5. Проверить неизменность личности, запрос повторного манифеста, ненулевой
   offset повторного stream-запроса, завершение после перезапуска и SHA-256.
   Граница наблюдения для итогового прогона — 180 секунд.

Телефон работал через **Wi-Fi и VPN**; мобильная сеть этим прогоном не проверена.
Настройка анонимной маршрутизации личности была выключена на обоих устройствах;
отдельный файловый транспорт при этом использовал anonymous stream, что
подтверждено его журналом. Настройки сети телефона не менялись.

QA-сборка использует Dart-исходники коммита `e3a64bc2` и текущие native-библиотеки.
Единственное отличие Dart-кода в приватной копии — callback сохранения
тестового сертификата при onboarding. Он ограничен тестовым
профилем и отсутствует в репозитории продукта. Этот прогон не проверяет
системный диалог сохранения сертификата.

## Предварительный прогон и ограничения

Первый прогон с файлом 32 МиБ остановлен: `SIGTERM` прекратил передачу, но
процесс Mac оставался жив, поэтому тестовый драйвер не выполнил перезапуск.
Его результат не засчитан как проверка докачки. Итоговый сценарий использует
`SIGKILL` и явно проверяет отсутствие старого процесса.

Результат закрывает этот сценарий возврата источника. Он не доказывает
исправление всех причин жалобы «остановилось на 33%», работу при окончательном
удалении исходного файла, длительный offline, гигабайтные файлы, Windows,
мобильного провайдера или восстановление после перезапуска получателя.
Звонки и звук здесь не проверялись.

## Завершение стенда

* Тестовые контейнеры заблокированы, приложения закрыты.
* Проверены все три process groups Mac, включая прежние источники: живых
  процессов нет. QA-процесс Android завершён, отдельный QA-пакет удалён.
* Тестовый профиль Mac убран из пользовательского каталога профилей.
* Удалено созданное ADB-перенаправление, восстановлена исходная настройка
  удержания экрана включённым. SHA-256 APK основного Android-приложения
  совпадает с исходным.
* Зашифрованные тестовые профили сохранены в приватном рабочем каталоге.

Отчёт содержит агрегаты и хеши программ. Runtime ID, адреса, имена файлов,
ключи, пароли, контейнеры и сырые журналы не публикуются.
