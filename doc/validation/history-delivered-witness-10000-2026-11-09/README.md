# История 10 000: отклонённый delivered-witness и встречная выдача

## Проверенный кандидат

После successful prepared append со статусом delivered история повторно читала
roster и строку ради delivery correction, которая уже записана. Прототип
запоминал только результат текущей вставки: `appended`, совпавшие chat+ID,
исходящее направление и durable delivered. Existing/suppressed/unsupported,
обычный callback и исправления текста оставались на прежнем пути. Никакого
кеша authorization или завершённых операций не добавлялось; fresh commit
admission и отдельный durable checkpoint сохранялись.

Прямой контроль на 64 новых строках: прежний код дал **64 post-apply reads**,
candidate — **0**. Девять экспериментальных проверок покрыли new/existing,
старый callback без передачи статуса, oversized fallback, выигравшую вставку,
сохранение edit revision, revoke, замену binding и ошибку callback после записи.
Для legacy-path исходная оценка ожидала одно чтение, но фактически там три:
цель, чтение внутри status API, проверка результата. Исправлено ожидание
фикстуры; это не новый дефект приложения.

Candidate прошёл **211 tests / 0 skipped**, включая **16 native HVS**;
финальный analyzer чист. Это результаты **эксперимента**, а не добавленных
в итоговый продукт регрессий: прототип и его девять проб после измерений
полностью убраны из production/test tree. Они сохранены только в частном
исследовательском наборе. Продукт возвращён побайтно к `ef64c976`.

## Измерение native A/B/A

Тот же стенд: A/B/E одной личности, C другой; четыре Mac/JIT процесса,
три изолированных Core, 10 000 архивных плюс одна прежняя строка.
Оба первых authenticated ответа получены до release первого apply. Размер
публикации **64 во всех фазах**, seed источников по 16 вне timing; 1000-мс
опрос, sampling/timeline выключены. Подтверждены native SHA/OS mappings.

A₁/A₂ используют `ef64c976`; B — один изменённый production-файл. Остальные
1523 из 1524 frozen inputs совпадают. Все ID/тела/delivered/canonical positions/
порядок и cold boot при offline источниках проверены полностью: 10001 строка,
без дублей, пропусков или посторонних записей. Оба проверяемых cursor закончены,
wire/census не обрезаны. Runtime SDK и HVS не пересобирались.

## Встречная выдача — новый измеренный участок

В захватах обнаружена дополнительная работа B как **источника** для A, хотя
контроллер заранее наполнил A полным архивом перед стартом догрузки B:

| Наблюдение | A₁ | Candidate | A₂ |
|---|---:|---:|---:|
| Уникальные page-запросы, принятые B | 157 | 74 | 34 |
| Соответствующие полные ответы, полученные A | 157 | 74 | 34 |
| Эти же ответы, полученные E | 0 | 0 | 0 |
| HistoryEncode callbacks B в выбранном census | 9984 | 4673 | 2113 |

Каждый ответ связан с запросом по private request ID; все индексы частей
0..n-1 получены, provenance authenticated, close-footers dropped=0. IDs и
содержимое не экспортируются. Последние полные snapshots A/B равны по всем
сохранённым полям. Census-window может окончиться раньше последнего ответа,
поэтому число encode callbacks не считается числом окончательно доставленных
уникальных сообщений. Покадровой привязки к точным message IDs пока нет.

Это подтверждённая встречная выдача на стенде; **причина всей задержки ею
не доказана**. Вариативность числа страниц сама по себе не является эффектом
candidate. Объяснение-кандидат: A видит inventory частично догруженного B;
проверка только первого `count` локальных строк не узнаёт sparse prefix+tail,
а крупные prefix hints не подходят к маленькой истории B. Затем A продолжает
читать растущий B. Нужен детерминированный контроль с таким составом строк и
связью query cursor → rows, прежде чем менять prefix/resume алгоритм.

Следующий разбор: отделить эту работу от page-cycle latency, уточнить
времена полного reply/применения/следующего запроса и источники оставшихся
316 cursor commits. Простой отказ от durability или проверок доступа не
используется как ускорение.

## Завершение и статус

Cleanup A₁/B/A₂: **37/36/37 PID**, **48/54/60 портов**; своих процессов/
listeners нет, runtime-контейнеры удалены, native artifacts не изменились.
Production и исходные тесты возвращены к предыдущему квалифицированному
коммиту; в этом цикле сохраняются только результат исследования и сводка.
Новых Rust-сборок, SIGKILL или физической Android/AOT/WAN квалификации нет.
Телефон, пользовательские контейнеры и production-реле не затронуты.

Большая догрузка и NETCALL-01 остаются активными, полная multi-device matrix
не закрыта. Отложенные жалобы/ограничения статус не меняют. Sibling mailbox
выключен по решению владельца. Push/релиза нет. Публичная
[summary.json](summary.json) содержит только агрегаты, без машинных путей,
private IDs, сетевых адресов, payloads или секретов.
