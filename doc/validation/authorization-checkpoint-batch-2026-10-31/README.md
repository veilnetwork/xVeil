# Пакетное сохранение авторизации хостом

Подтверждён источник лишнего I/O в холодной отправке: каждый изменённый документ
авторизации записывался отдельным commit, хотя native revision подтверждается
хостом лишь после сохранения всего snapshot. В предварительном native-захвате
серия из трёх commit занимала до 309 мс внутри `replacePeerAuthorization`.
Это не поиск по сети: данные уже переданы хосту для durable checkpoint.

Теперь независимые документы записываются ограниченными пакетами: **до 64 ops,
включая layout marker**. Один документ вместе со всеми удалениями старого хвоста
никогда не делится между commit. Сначала заканчиваются удаления отсутствующих
обычных записей, затем публикуются замены; любой сохранённый префикс остаётся
в лимите 512 записей. Решение о допустимых отсутствиях по-прежнему принимает
native snapshot; revocation-policy не менялась.

При отказе любого пакета caller получает ошибку, revision не ACK-ается.
Повтор сохраняет оставшиеся изменения; уже записанные bytes идемпотентны.
Проверка полного старого состояния перед первой записью, копирование входных
буферов, encrypted namespace, signed verification и durable host barrier
сохранены. Формат, ABI, wire, native SDK, polling interval и реле не менялись.

## Проверки

Исходный код: 11 небольших документов требуют **11 commit**; регрессионный
тест с требованием одного ограниченного пакета красный. Кандидат: **1 commit**.

Дополнительно проверены:

- 20 документов максимального размера 16 КиБ: каждый находится в одном пакете,
  ни один пакет не превышает 64 ops.
- Полная замена 512 записей другими 512: после каждого commit хранилище читается
  и укладывается в restore budget.
- Отказ второго пакета при замене/укорочении 80 документов: после отказа каждый
  документ целиком старый либо новый, ACK отсутствует; повтор завершает запись.
- Прежние случаи повреждённых/лишних chunks, mutable input, отказа restore/ACK,
  изменения revision во время I/O, закрытия и сосуществования с ratchet keys.

**146 тестов прошли, 0 skipped**: authorization persistence, ratchet persistence,
chunk cache, whole forget, send reservation/fail-closed, cleanup budget,
export growth, ABI contract и rollback anchors. Loading events не посчитаны
как тесты. Targeted analyze пяти изменённых source/test файлов: no issues.

**3 нативных теста прошли, 0 skipped**. Два прежних проверяют подписанный
revocation floor после перезапуска native/контейнера и изоляцию авторизации
между двумя runtime. Новый storage-тест пишет 20 несжимаемых случайных blobs
по 16 КиБ в настоящий encrypted container, отказывает второму пакету,
проверяет целостность old/new, повтор, reopen и удаление хвостов при сокращении.
Эти blobs — непрозрачные storage fixtures, не подписанные identity documents;
тест не подменяет проверку native-подписей.

Черновик failure-теста ошибочно передавал два массива напрямую в `anyOf`.
Ошибка matcher исправлена; она не считалась дефектом продукта или красным
воспроизведением batching. Зачтённый красный тест — 11 commit против одного.

## Разложение ожидания

Test-only adapters измеряют вызов `flush`, настоящий storage API и вложенные
worker RPC. Синтетические номера операций связывают их с export/ACK native
revision; наблюдение не делает дополнительных native reads. Имена, документы,
ключи и пути в timing events не попадают. Анонимный отчёт продукта не расширен.

Наблюдения трёх основных A/B-пар, мс:

| Интервал | Контроль: медиана / максимум | Кандидат: медиана / максимум |
|---|---:|---:|
| Вызов flush → export snapshot | 0,148 / 400,028 | 0,150 / 190,372 |
| Storage replace | 158,784 / 508,240 | 121,590 / 374,147 |
| Storage завершён → native ACK завершён | максимум 0,093 | максимум 0,090 |

Первый интервал включает очередь за прошлым flush и native read/export; его
нельзя целиком назвать сетевой задержкой или задержкой timer. Storage interval
включает также чтение прежних rows и ожидание worker, не только fsync.
Суммы I/O всех параллельных узлов не равны задержке одного сообщения.

Отдельный тест с виртуальными часами и мгновенным fake store воспроизводит
**999 мс** ожидания: revision меняется через 1 мс после предыдущего tick,
сохранение/ACK наступают на следующем tick 1 с. Это характеризует polling-only
путь, а не атрибутирует все runtime-задержки. **Опрос в production остаётся 1 с**.
Следующий кандидат — уведомление хоста о pending revision; обходить durable
checkpoint или постоянно ускорять idle polling этой правкой не стали.

## Основной native A/B

Контроль frontend `73e80657`, один frozen SDK `081bb6d1`, без Rust rebuild.
12 отдельных native личностей, production-PoW fixtures, свежие encrypted
containers/instance keys, TCP full mesh и DHT. Настоящие transport crypto,
ratchet и peer authorization. Один Mac/JIT host/диск; legacy group без epoch
encryption, roster передан вне сети. Это не multi-device/Android qualification.

Первая видимость всем 12, мс; четыре разных автора, поэтому следующие
сообщения нельзя считать строго прогретым повтором одной пары:

| Фаза | 1 | 2 | 3 | 4 | Auth commits | Chunk ops без marker |
|---|---:|---:|---:|---:|---:|---:|
| A1 | 4440 | 2116 | 2137 | 2624 | 64 | 64 |
| B1 | 4399 | 2504 | 2165 | 2862 | 40 | 64 |
| A2 | 4230 | 2690 | 1582 | 2682 | 64 | 64 |
| B2 | 4067 | 2585 | 2429 | 2694 | 40 | 64 |
| A3 | 4874 | 2440 | 2071 | 2561 | 64 | 64 |
| B3 | 3965 | 2585 | 2178 | 2911 | 41 | 64 |

Медианы A/B: **4440/4067, 2440/2585, 2071/2178, 2624/2862 мс**.
Все три холодных сообщения быстрее, но последующие чаще медленнее.
Устойчивое ускорение всей доставки **не доказано**. Количество snapshot-волн
немного меняется с расписанием; chunk ops остаются теми же 64. Все записи
авторизации основных шести запусков завершились ещё на первом сообщении.

## Дополнительный прогретый A/B/A

Чтобы проверить возможную регрессию следующих сообщений, отдельный fixture
после тех же четырёх post и паузы 2 с делает ещё четыре post от последнего
автора. Библиотека, identities и схема хранилища те же; контейнеры свежие.
Это заданная пауза, не доказательство полной тишины всех фоновых задач.

| Фаза | Post 5 | 6 | 7 | 8 |
|---|---:|---:|---:|---:|
| A1 | 3231 | 2983 | 3489 | 3568 |
| B | 2583 | 3049 | 4017 | 3038 |
| A2 | 2932 | 2877 | 3253 | 3382 |

В интервалах этих четырёх post нет ни одного auth commit. Два post B быстрее
обоих контролей, два медленнее; равномерная регрессия не подтверждена.
Выборка мала, причинное дерево может меняться, общего выигрыша не объявляем.
В расширенном A1 один auth commit завершился уже в окне второго post;
утверждение «все auth writes в первом» относится только к основной серии.

Во всех девяти запусках **48 сообщений** присутствуют у всех 12 ровно один раз.
Wire-сопоставления и критические пути проверены отдельно, timing drops нет.
SHA production/helper/fixture и frozen native library зафиксированы;
rollback watchers завершились, конфликтов нет, кандидат восстановлен побайтно.
Все девять host завершились, по 12 listeners освобождены, cleanup_errors пусты;
временные контейнеры удалены. Телефон и production-реле не менялись.
Приватные IDs, пути, raw logs и топология не экспортированы в этот отчёт.
Без push/релиза. Общая задержка и multi-device матрица остаются в очереди.
