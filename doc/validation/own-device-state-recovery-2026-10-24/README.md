# Восстановление редакций и подтверждений доставки между своими устройствами

## Подтверждённые дефекты

| Находка | Доказательство до исправления | Исправление |
| --- | --- | --- |
| B держит исходный текст, хотя A уже отредактировал сообщение, а событие редакции недоступно | Новый тест с одинаковым ID на A/B завершился таймаутом; сверка сравнивала только ID | Хеш учитывает текст, inline emoji и версию редакции; страница переносит её вместе с текущим текстом |
| B продолжает показывать «отправлено», хотя A знает о доставке | Второй тест с одинаковым ID также завершился таймаутом; зеркало не переносило подтверждение | Страница переносит положительное подтверждение доставки исходящего сообщения |
| Поздняя ошибка отправки отменяет уже полученное подтверждение | Прежний тест явно ожидал переход `delivered → failed`; журнал выбирал последнюю запись | Подтверждение сохраняется при последующих временных статусах, включая чтение старых записей после запуска |

Редакция применяется только при известной, строго большей версии. Старый ответ
не заменяет более новую локальную редакцию; удалённая строка не воскресает.
Одинаковый текст с изменившимися inline emoji тоже обновляется. При первом
восстановлении отредактированного сообщения сохраняются отметка редакции и её
версия. Исходное время сообщения и порядок не меняются.

Текст и версия читаются согласованно: если версия изменилась во время чтения,
снимок повторяется с ограничением числа попыток. Курсор страницы фиксируется
после записи редакций и статусов; отказ записи оставляет страницу для повтора.
Ошибки этого обмена не включают текст или идентификаторы из входящих данных.
Mailbox, размер device-sync журнала и разрешения устройств не расширялись.

## Проверки

* Два новых теста воспроизвели расхождения на предыдущем коде.
* 88 проверок истории, статусов и хранилища: пропущенная редакция, доставка,
  запрет отката, редактирование во время чтения, inline emoji, удаления, отказ
  записи статуса, продолжение после запуска, отзыв устройства, сроки жизни.
* 354 регрессионные проверки: обычная доставка и повторная отправка, outbox,
  зеркала, история, удаления, исчезающие сообщения, wire, presence, привязки,
  диагностика и идемпотентность записей.
* Полный `dart analyze`: замечаний нет.
* Усиленный native-прогон A/B/C пройден: B восстановил оба состояния за
  **10,148 с**, C был выключен. ID и порядок совпали с исходными, дублей нет.
  После выключения A и перезапуска B состояние осталось прежним; отдельное
  открытие контейнера подтвердило версию редакции **1000** и `delivered`.
* После прогона проверены 8 process groups и 11 PID: живых участников нет,
  контейнеры стенда удалены. Исходники native-прогона совпадают с итоговыми.

## Границы результата

Native-сценарий использует настоящий транспорт, отдельные OS-процессы,
зашифрованные контейнеры и локальные реле. Ускоренная тестовая сложность PoW
не позволяет переносить время прогона на пользовательскую сеть.

Чтобы изолировать восстановление от обычной доставки device-sync, редакция
и подтверждение подготовлены в контейнере остановленного A только из тестового
кода. Подтверждение в этом сценарии контролируемое: это не проверка получения
нового сообщения C. Перед изменением контейнера все его владельцы остановлены.
Производственных тестовых переключателей или новых API не добавлено.

Сценарии одновременно сделанных редакций с одинаковой версией, реакции,
длительный offline с реальным ожиданием суток и дней, Windows и вся матрица
multi-device этим результатом не закрываются. Прошлый прогон на 1000 сообщений
описан [отдельно](../own-device-history-pages-2026-10-24/README.md); здесь он
повторно не запускался. Физический телефон в этом цикле отсутствует в ADB.
Звонки, установка приложений, push и релиз не выполнялись.

Отчёт и summary содержат только агрегаты и хеши исходников. Рабочие журналы,
адреса, ID, ключи, пароли и контейнеры не публикуются.
