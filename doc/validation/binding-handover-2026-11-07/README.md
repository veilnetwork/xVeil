# Poco ↔ Mac: повтор handover на SDK 4f441329

**NETCALL-01 остаётся открытым.** Четыре звонка сохранили состояние до
управляемого отбоя, но стабильность аудиопотока всей серии не подтверждена.
Наибольший возраст последнего принятого аудиопакета — **13,314 / 12,160 с**
(Poco / Mac) — наблюдался при **возврате с cellular на Wi-Fi**.
Агрегаты: [summary.json](summary.json).

## Стенд и происхождение

Poco X6 5G / Android 16 с SIM и MacBook; отдельные ранее подтверждённые
QA-личности. Пользователь включил USB debugging, после чего установка
QA-сборки прошла без отказа. Обычный xVeil и его контейнеры не открывались.

Mac FFI, Android FFI и отдельный Linux Core пересобраны из чистого Veil
`4f441329`, включая [независимые ACK flights](../ordered-binding-progress-2026-11-07/README.md).
Все **1533** tracked SDK inputs проверены до/после, actual `veil-session`
rebuild подтверждён в каждом логе. Внешняя ФС контролировалась на всём
протяжении трёх builds, mount loss не было. Проверены 208 прежних C exports,
ABI, ELF architecture и окончательный SHA подписанной Mac FFI. Линкер Linux
выдал предупреждение о deprecated optimization setting; build exit 0.

**Frontend изолирован от native-изменений:** сохранены прежние подписанные
Mac/Android QA AOT, media и HVS. Android APK отличается новой FFI и выбранным
QA seed, остальные ZIP payloads и signer сверены. Mac bundle не переподписан:
новая отдельно подписанная FFI выбрана явным override, actual process mapping
подтверждён. Это не квалификация самого последнего Dart frontend.

Один отдельный testnet Core через obfs4/TCP, собственный service/config/state/
порты и 30-минутный runtime bound. Discovery и builtin seeds выключены;
взаимодействия с production-сетью нет. До звонка CLI JSONL/TSV разобран по
заголовку: оба точных transport peer находятся в `active`. Actual `/proc/exe`
Core сверён по SHA. P2P запрещён и перечитан с обеих сторон. Проверяется
**non-onion Delivery relay**, не private onion и не P2P.

## Звонки

Времена считаются от начала запроса звонка. «Первый совместный fresh» —
первый парный срез active + running + без worker stall, с положительным RX
counter и native RX age 0–1000 мс на обоих устройствах. Устойчивый baseline
требует пяти таких последовательных срезов.

| Сценарий | Входящий | Первый совместный fresh RX | Пять fresh RX |
|---|---:|---:|---:|
| Poco → Mac, уже validated cellular | 2,194 с | 11,506 с | 22,076 с |
| Mac → Poco, затем два переключения, разговор 1 | 3,194 с | 38,955 с | 41,119 с |
| Mac → Poco, затем два переключения, разговор 2 | 12,598 с | 15,578 с | 17,781 с |
| Poco → Mac сразу после команды Wi-Fi off | 2,098 с | 6,210 с | 11,274 с |

Все четыре baseline достигнуты; после них велось дополнительное наблюдение.
Первый сценарий начинается только после OS-подтверждения validated cellular.
В последнем входящий может использовать ещё живой прежний attachment:
время команды off не является временем готовности нового default network.
Сохранность call ID проверялась на всех срезах, неожиданных отбоев не было.

### Два действительных handover внутри разговора

35 с наблюдения после Wi-Fi off, затем 16 с после Wi-Fi on. Таблица содержит
**maximum observed native RX age**, не оценку акустической задержки и не
доказательство непрерывного PCM-молчания. Порядок — Poco / Mac.

| Разговор | Wi-Fi → cellular | Cellular → Wi-Fi |
|---|---:|---:|
| 1 | 561 / 1234 мс | **13314 / 12160 мс** |
| 2 | 1146 / 1607 мс | 289 / 674 мс |

Первый validated cellular срез — через 1,112 / 1,009 с после команды off;
validated Wi-Fi — через 1,676 / 2,484 с после on. Это дискретные OS-срезы,
не точная граница готовности маршрута конкретного TCP-сокета.

**Граница oracle:** driver выставил `allCasesPassed=true` за сохранность
состояния звонков после пройденного baseline. Его `observe` не требует
свежего RX на каждом срезе. Этот флаг **не принят за успех аудиосерии**.
Независимая проверка последних пяти срезов показывает:

- Mobile-control и второй handover — свежий RX у обоих.
- Первый handover — нет пяти финальных fresh у обоих.
- Post-switch new call — нет пяти финальных fresh у Mac (max age 1514 мс).

Это разные по величине наблюдения; единичный возраст около 1,5 с не
приравнивается к 13-с остатку первого возврата. Всего **386 срезов на endpoint**,
API observation errors 0, maximum within-case sample interval 1398,9 мс.
Непрерывность media epoch и слышимость человеком не доказаны. Нет A/B:
ускорение относительно прежних серий и причинный вклад ACK-фикса не заявляются.

## Транспортные данные и следующий участок

Полный app-specific Android log содержит **126 уникальных** incomplete obfs4
handshake observations ≥1 с именно к порту QA-Core. Из них 118 короче 4 с,
четыре ≥9 с. Во всех 126 — Read, read bytes 0, один unacked packet,
queued bytes равны written, notsent 0; есть TCP retransmissions. Bridge-копии
дедуплицированы по исходным полям observation. Это не число независимых ошибок:
сюда входят отменённые проигравшие primary/backup и внешние binding deadlines.
Нельзя приписать каждый incomplete наблюдаемому аудиоразрыву.

Следующая атрибуция — конкретный canonical/child и primary/backup вокруг
**cellular → Wi-Fi**, отдельно от холодного запуска 22–41 с. Трёхсекундную
отмену дочернего binding нельзя считать десятисекундным canonical timeout.
Возврат Wi-Fi здесь наблюдался только 16 с: следующий целевой прогон должен
держать его не менее 60 с, чтобы пересечь прежнее окно liveness 20–25 с,
зафиксировать восстановление либо настоящий timeout и проверить конечный RX.
Контроль syscall/сокета и полного захвата нужен до следующей транспортной
правки; менять аудиобуфер или liveness timeout по этим данным оснований нет.

### Неполный PCAP исключён

Capture был ограничен QA TCP-портом, snaplen 192, десятью минутами,
RAM/file/CPU budgets. Но cleanup удалил remote staging **до терминального
завершения SCP**. Скачивание затем упёрлось в 60-с timeout. Сохранился только
неполный файл; открытого remote FD для восстановления уже не было.
Это ошибка порядка уборки, а не сетевой результат звонка.

Полные endpoint и Core file logs сохранены. Неполный PCAP явно помечен и
**исключён из атрибуции потерь/отсутствия пакетов**, его SHA не выдан за
совпавший с исходником. Для следующего запуска private cleanup требует
отдельный successful-copy marker с проверенными size/SHA перед удалением
стейджа; copy deadline увеличен, а захват повторно не запускался задним числом.

## Очистка

QA APK восстановлен из свежей копии и сверён по SHA. SHA обычного APK и
прежнего root QA-контейнера совпали. Именованные QA-профили получили тестовые
звонки; их побайтный возврат не заявляется. Прежние P2P values **и stored
values** совпали после восстановления. Wi-Fi/mobile/awake settings возвращены,
validated исходный Wi-Fi подтверждён.

Свои apps/probe/logcat завершены, exact процессы и локальные ports проверены;
Mac потребовал SIGKILL после SIGTERM grace. Временный Mac runtime удалён,
добавленный debug-log сохранён приватно и убран из собственной копии bundle;
строгая проверка подписи после уборки прошла. Capture остановлен, QA-Core/
config/state/runtime/binary/unit/ports удалены. Production PID, executable,
config SHA и NRestarts прежние. Windows не использовалась. Публичные
артефакты содержат только агрегаты, без адресов, ключей, ID или raw logs.
Push, релиза, обновления production-сидов и sibling mailbox нет.
