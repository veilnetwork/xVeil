# Политика доступа живого файлового источника — 2026-10-30

После [исправления владения проверенным дескриптором](../verified-serve-handle-2026-10-30/README.md)
проверен соседний fallback. Базовая xVeil — `0e3f1852`; SDK `c96bd930` не менялась.

## Подтверждённые механизмы

* Stream server получал отказ `_openVerifiedServedSource`, затем брал
  `live.source`. При отзыве доступа это обходило проверку папки. При изменении
  содержимого могло обходить и проверку CID.
* Datagram server непосредственно читал живой источник, не спрашивая снова,
  действует ли делегировавший его доступ к папке.
* При ошибке записи `served:` сведения о разрешавших папках не оставались в
  живой записи. Отказ постоянного хранилища превращал источник в неограниченный
  RAM fallback, хотя это должно было означать только потерю restart durability.
* 1:1 регистрация копировала mutable roots после первого await. Очистка списка
  вызывающей стороной во время contact lookup снимала маркер делегирования:
  источник ошибочно становился личным и обходил отказ авторизации.

В исходных тестах получатель действительно увидел file bytes после отзыва
доступа, через обе разновидности транспорта. Повторная проверка окончательной
матрицы на исходных production-файлах дала **9 failed / 1 passed**. Это девять
сценариев нескольких связанных механизмов, не девять отдельных уязвимостей.

## Исправление

Правила источника находятся в `_ServedContent.sourceRecord` вместе с самим
источником. Roots копируются до await и сохраняются одинаковыми в RAM и durable
record. При неудаче persist они продолжают действовать до удаления живой записи.
Refresh, reoffer и сохранение активного источника при повторной отправке не
теряют и не заменяют его правила правилами другого handle.

Обе выдачи используют общий выбор источника. Отказ делегированной авторизации
не разрешает читать RAM handle. Перед и после асинхронного чтения payload для выдачи проверяется
действующая авторизация; отзыв во время I/O не выпускает возвращённые bytes.
Это о выдаче новых bytes: уже поставленные в сеть данные отозвать нельзя.

Если путь picker исчез, личный живой источник всё ещё может работать. После
неудачного reopen он хешируется через собственный handle и используется только
при совпадении CID. Изменённые RAM bytes не обходят отказ durable-проверки.
Полный проход RAM-bounded, дополнительные постоянные копии не создаются.

Независимая, уже проверенная копия в локальном blob store остаётся доступной:
ограничение чтения папки не превращается в отзыв ранее полученной копии.
Для такой выдачи запрещённый оригинал не читается. Старый handle передаётся
в существующий механизм retirement, чтобы его не потерять при смене записи и
не закрыть под другим активным потоком.

У datagram response теперь собственный проверенный handle с finally-close.
Rehydrate восстанавливает metadata и не открывает лишний невладеемый handle.
Перед обработкой content-GONE проверяется dispose. Wire, ratchet/ACK,
политика mailbox и поведение реле не менялись.

## Проверки

Окончательная матрица **10/10 passed**:

| Транспорт | Сценарий | Требуемый результат |
| --- | --- | --- |
| Регистрация | Caller очищает roots во время первого await | Делегирование сохраняется, отказ авторизации не обходится |
| Datagram | Отзыв при наличии durable record | GONE, без piece bytes |
| Datagram | Ошибка записи record, затем отзыв | То же, политика сохранена в RAM |
| Datagram | Отзыв внутри чтения, opener отсутствует | Прочитанные bytes не отправлены |
| Stream | Отзыв при живом кэше | Исходник не выдаётся |
| Stream | Durable record удалён, затем отзыв | RAM не теряет правила |
| Stream | Отозван оригинал, есть независимый blob | Копия выдаётся, исходник не читается |
| Stream | Исчез личный picker path, живые bytes верны | Выдача продолжается |
| Stream | Подменены durable и live bytes | Подмена не отправляется |
| Stream | Отзыв во время чтения owned handle | Bytes не выдаются, lease закрывается |

Прошли **158 связанных тестов** из 11 файлов и отдельно **28 API-тестов** по
фильтру `file|root|source|grant`. Десять целевых уже входят в 158 и повторно не
прибавляются. Analyze шести production-файлов и двух тестовых файлов — без
замечаний; production format-check и diff-check прошли. Числа и хеши именно
проверенных исходников — [summary.json](summary.json).

В полном прогоне уточнены три прежние проверки вспомогательных счётчиков.
Регистрация и чтение теперь тоже спрашивают авторизацию, поэтому вместо общего
числа 1/2 проверяются правильные path/roots у всех запросов и новый запрос после
отзыва. Datagram response получает отдельный lease: тест дескрипторов требует
две независимые проверки/владения, удержание serving handle до выдачи bytes и
его close после выдачи; исходная проверка отсутствия bytes подмены сохранена.
Это не ослабление правил содержимого или отказа при отзыве.

## Границы

Это service/HTTP integration с in-memory transport и локальными файлами,
TMPDIR `/private/tmp/`. Новая Dart-правка ещё не квалифицирована физически на
Android/Windows; прежние 14 передач ей не засчитываются. SDK, основные приложения
и серверы не менялись, стендовые приложения и звонки не запускались.

Не заявляются устранение начальных 5,5 с, всех «33%», все причины односторонней
доставки, полный multi-device/revoke audit или защита от любых последующих
in-place writes. При провале durable persist восстановление после restart всё
ещё не гарантировано; исправлено сохранение политики живого источника.
Raw test logs приватны; в отчёте нет реальных путей, node/content IDs и времён.
Коммит без подписи; push/релиза нет.
