# Сохранение очереди незавершённых загрузок

## Подтверждённый дефект

На исходном `b1dc5cd2` весь реестр незавершённых загрузок сохранялся одним
settings KV значением `pending_downloads`. Размер одного такого значения
ограничен контейнером. Ошибка записи подавлялась, а изменённый список оставался
только в памяти: текущий сеанс видел все запросы, следующий — старый список.

Проверка через production `MessagingService.downloadContent` и настоящий
hidden-volume контейнер воспроизвела потерю: приложение подтвердило **24**
запроса к offline-держателю, после закрытия/повторного открытия восстановились
только **10**. Сетевые узлы и реальная передача байтов в этом тесте не нужны.
Это подтверждение дефекта реестра, а не доказательство причины полевого
зависания одного файла на 33%.

## Изменения

* Реестр хранится в chunked FileStore внутри того же зашифрованного контейнера.
  Все блоки записываются до публикации новой метаинформации; незавершённая
  замена не должна делать прежний реестр пустым. Нового namespace нет.
* Существующий JSON-реестр читается при миграции. Маркер нового размещения
  ставится после записи файла. Новый файл имеет приоритет; старый JSON
  заменяется маркером и не возвращает отменённую загрузку при следующем boot.
* Перед запуском явно запрошенной загрузки API ждёт сохранения её намерения.
  Ошибка записи больше не означает успешное начало загрузки. Приёмный sink
  закрывается, публикуется событие ошибки, чат показывает «Не удалось сохранить
  файл». Шаблоны диагностики не содержат исходного текста исключения или пути.
* В памяти публикуется только успешно сохранённая версия. Неудачная запись
  не меняет прежний список и не останавливает очередь следующих операций.
* Отмена удаляет намерение в той же последовательной очереди, что и запись.
  Проверка существования выполняется после предыдущих операций; запись,
  завершившаяся во время отмены, не оживает после перезапуска. Приём потока
  останавливается до ожидания сохранения отмены.
* Повреждённый или недоступный актуальный реестр не заменяется новым пустым.
  Фоновое чтение сообщает фиксированную ошибку и остаётся без действий;
  новые запросы отказываются перезаписывать неизвестное состояние. Ошибка
  чтения не кэшируется: последующий запрос может восстановить работу.
* Прежние сроки хранения намерений, источники файлов, проверка хешей частей,
  stream/range протокол, mailbox и политики маршрутизации не менялись.

## Проверки

| Сценарий | Результат |
| --- | --- |
| Настоящий контейнер, 24 запроса и обычное повторное открытие | До исправления 10/24, после исправления 24/24 |
| Отмена одного запроса и ещё одно открытие | Восстанавливаются остальные 23; отменённого нет |
| SIGKILL независимого процесса после подтверждения всех запросов, без dispose/close | Новый процесс восстанавливает 24/24 |
| Сохранение намерения остановлено барьером | До завершения записи нет reoffer и API не подтверждает запрос |
| Отказ финального metadata commit | Старый реестр сохранён; новый запрос не отправлен; следующая запись проходит |
| Старый реестр → миграция → отмена/очистка → новый сервис | Отменённые записи не восстанавливаются |
| Повреждённый/отсутствующий актуальный реестр | Состояние не перезаписано; после восстановления чтения запрос проходит |
| Отмена во время сохранения plaintext-загрузки | Нет позднего запроса или записи в sink; sink закрыт, очередь пуста |

**115** регрессионных Flutter/Dart тестов прошли. Включены **6** новых проверок
сохранения, отмены и отказов, а также прежние потоки, кредит, авто-возобновление,
reverse pull, purge и small-file transfer. Два native теста проверяют настоящий
контейнер; второй запускает отдельный процесс с тем же production API и
принудительно завершает его после подтверждения запросов.

Native тесты используют известные фиктивные данные и бесшумный offline
transport. ArgonPreset.min используется только в test-файлах. Новых production
флагов для имитации ошибок нет. Процесс/группа writer завершены, тестовые
контейнеры удалены. Пользовательские приложения и данные не открывались.

Обычный Android arm64 debug APK собран с `lib/main.dart`. В нём проверяются
новая логика, основной application ID, отсутствие тестовых entry points и
совпадение упакованных native-библиотек с текущими staged sources после strip.
Сборка использует наблюдаемый внешний target; Flutter — `/private/tmp/`.

## Границы

Это проверка сохранения запросов и жизненного цикла загрузки. Она не измеряет
сеть проблемного провайдера, скорость 32 МиБ, поведение Windows 10 или реальную
передачу файла на физическом телефоне. Сетевые зависания остаются отдельной
проверкой. Ранее потерянные намерения, которых уже нет в контейнере,
автоматически восстановить нельзя; файл можно снова запросить вручную.

Veil и hidden-volume не изменялись. APK не устанавливался; push и релиз не
выполнялись. Исходный незакоммиченный `multi-device-2026-10-17` не изменён.

[summary.json](summary.json) содержит только счётчики, результаты и хеши ПО.
Логи, адреса, идентификаторы, пути загрузок, пароли, payload и APK остаются
в приватных артефактах вне репозитория.
