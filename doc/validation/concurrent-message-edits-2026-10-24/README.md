# Сходимость одновременных редакций на A/B/C

## Подтверждённые дефекты

| Находка | Проверка до исправления | Исправление |
| --- | --- | --- |
| Две редакции одной версии оставляют разные тексты в зависимости от порядка доставки | Два порядка записи дают разные результаты; пять начальных тестов завершились ошибкой | Общий порядок: версия, затем SHA-256 канонического текста с inline emoji |
| Журнал своих устройств выбирает более позднее время вместо большей версии редакции | Поздняя версия 7 вытесняет версию 8 | Свёртка и уплотнение журнала используют тот же порядок редакций |
| Старый одинаковый frame ID скрывает другую редакцию той же версии | Второй вариант не применяется | Приём различает содержимое старых edit-кадров; ACK сохраняет исходный wire ID |
| Два новых исходящих edit-кадра получают одинаковый ID | Проверка независимых редакций обнаруживает коллизию | Компактный ID зависит от сообщения, версии и содержимого редакции |
| Сверка истории обнаруживает одинаковую версию, но не исправляет различающийся текст | Отдельная проверка завершается таймаутом | Восстановление истории использует общий порядок и при равной версии |

Дополнительно проверены сохранение версии отложенной редакции до получения
исходного сообщения, изменение только inline emoji и все шесть порядков трёх
конкурирующих значений. Редакции в хранилище сериализованы, чтобы параллельные
операции не обходили проверку и выделение версии.

Публикация редакции своему устройству читает текущий победивший текст вместе
с версией: запоздавший callback больше не подписывает старый текст новой версией.
Повреждённое поле разговора не может вытеснить корректную редакцию в свёртке;
для этого случая отдельно получен отрицательный результат до исправления.

## Проверки

* **503 проверки в 26 файлах** прошли: доставка, outbox, история и gapfill,
  редакции, удаления, исчезающие сообщения, зеркала, хранилище и диагностика.
* Полный `dart analyze`: замечаний нет; `git diff --check` пройден.
* Native-сценарий использует три отдельных процесса, настоящий SDK,
  зашифрованные контейнеры и изолированные локальные реле.
* A/B — устройства одной личности, C — другой. Два сообщения проверяют
  противоположные порядки доставки. Во всех трёх контейнерах выбран один текст,
  ID и порядок совпадают, дублей нет.
* Подписанный журнал своих устройств сохраняет того же победителя после
  настоящего уплотнения с удалением избыточных записей и возвращения B online.
* Перезапущены все три устройства; затем обычная новая редакция через API
  приложения сошлась на A/B/C. После остановки процессов отдельное открытие
  каждого контейнера подтвердило одинаковую версию и текст.
* Проверены **12 process groups и 16 PID**: живых участников нет,
  контейнеры стенда удалены. Исходники во время прогона не менялись.

Предварительный усиленный прогон остановился на проверке непустой работы
уплотнения: живой обмен уже убрал избыточные строки. Это не засчитано как
успешное уплотнение. В итоговом сценарии B остановлен на время добавления
избыточных записей; отдельно проверено фактическое уменьшение журнала.

## Границы результата

Конкурирующие редакции и старые frame ID подготовлены тестовым кодом в
контейнерах **остановленных** A/B. Затем их доставляют штатные durable-очереди.
Это контролируемая проверка конфликта, а не имитация пользовательских кликов
при естественном разделении сети. Последующая новая редакция выполняется
обычным API приложения. Новых производственных тестовых API или переключателей
для этого сценария не добавлено.

При равной версии выбор по хешу детерминирован; он не означает, что выбран
хронологически последний пользовательский ввод. Разрешения устройств,
доступ к истории и политика mailbox не расширялись.

Результат не закрывает всю матрицу multi-device, все маршруты восстановления
через собеседника, длительный offline с ожиданием суток, Windows или качество
физических звонков. Проверка передачи файла на физическом телефоне проводится
отдельно. Релиз и push в этом цикле не выполнялись.

Публичные материалы содержат только агрегаты и хеши программ и исходников.
Журналы стенда, адреса, runtime ID, ключи, пароли и контейнеры не публикуются.
