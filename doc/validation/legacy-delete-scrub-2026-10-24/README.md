Третий кандидат в Rust — повтор одного log id внутри **одной** транзакции —
снят: `commit_tx` уже coalesce-ит записи до кодирования. Первоначальное
ожидание нового scrub в этом тесте было ошибочным. Тест теперь проверяет
правильное отсутствие лишней очистки; два подтверждённых partial-batch
негативных кейса не ослаблены.

## xVeil

Отсутствие completion checkpoint означает, что старое пространство ещё не
прошло миграцию. Проверяется только наличие строк в ограниченном наборе log
namespaces, включая retired namespace 3 и shard 118. Не полагаемся на
`msg_next_id`: после сбоя он может быть неполным. Пустое пространство получает
checkpoint без vacuum; пространство с историей очищается один раз. Текст всей
истории для этого namespace probe не материализуется.

Checkpoint записывается после успешного space-wide vacuum. Если vacuum,
metadata probe или запись checkpoint отказывают, миграция остаётся повторяемой.
Открытие по паролю/ключам выполняет её до возврата, sync/async views — перед
первым чтением истории. Новый pending-флаг продолжает обеспечивать recovery
последующих удалений. Обе процедуры используют тот же scrub gate.

Перепаковка частичных блоков использует обычные durable transactions и может
значительно увеличить commit seq. Поэтому перед startup vacuum сохраняется
pre-maintenance reading. Проверка rollback/fork использует его, затем только
для принятой истории записывает **текущий** root/seq. Подозрительный reading
сохраняется для повторных проверок, внешний anchor не меняется. Отказ записи
внешнего anchor остаётся видимым и допускает retry. Снимок сбрасывается при
закрытии и при повторном открытии другой личности на том же handle.

## hidden-volume

`vacuum_data_batches` прежде пропускал любой batch с хотя бы одним живым
указателем. Теперь первый проход разбирает текущие Log-kind указатели и
перепаковывает только блоки с устаревшими записями. Сохраняются последние
значения действующих log id. После публикации новых указателей заново
вычисляется reachability, затем старые блоки стираются.

Каждая перепаковка ограничена одним decoded batch; pointer pages и bitmap
обработанных slots ограничивают память. Уже прочитанная pointer page повторно
используется для соседних записей. Payload остаётся в существующих zeroizing
контейнерах; нормальный Tx обеспечивает публикацию до стирания. Ошибка, в том
числе `PublishUncertain`, прерывает проход до стирания старых блоков. Сохраняются
read-only и unreadable-newer-state guards. Формат контейнера и function
signatures не меняются; commit history при перепаковке продвигается, что
документировано в core/FFI/Dart API.

UniFFI metadata checksum метода изменился при обновлении документации.
Fail-closed проверка Dart отказалась загружать новую FFI со старой таблицей;
таблица перегенерирована штатным скриптом и проверена для всех 43 методов.
Проверка совместимости не отключалась и не расширялась для старого бинарника.

## Проверки

* **231 Dart/Flutter тест, без пропусков**, включая 16 native storage-кейсов.
  В трёх новых native-кейсах старый payload и живой сосед записаны в один
  настоящий DataBatch, затем один log id заменён старым tombstone без новых
  флагов. После миграции число реально reclaimed slots положительно, соседняя
  строка сохранена и `verifyIntegrity` проходит. Clean reopen не вызывает
  повторный vacuum.
* Rust: **208 core unit passed / 2 ignored**, **30 integration passed**
  (vacuum, namespace kind, scrub, peak memory), **33 FFI unit passed**.
  После перевода новых fixture на RAII temp directories 11 vacuum-кейсов
  повторены успешно. Clippy core/FFI с `-D warnings` и `cargo fmt --all --check`
  проходят. Ignored core-тесты не объявляются проверенными.
* Native A/B/C: три встроенных узла, отдельные encrypted-контейнеры, три
  процесса локальных реле. A/B одной личности, C другой. При delete-before-post
  B offline; после выключения C B восстанавливает удаление от A и сохраняет
  его после перезапуска. Поздних ошибок 0. Frontend работает в одном Dart
  процессе — это не три независимых GUI/OS устройства.
* Все owned процессы этого стенда завершены, его root и native fixture roots
  удалены. Пользовательские приложения/телефоны, микрофон, личности и внешние
  реле не использовались.

Rust target только `/Volumes/cfb/target`: отдельный filesystem проверялся
перед каждой командой и мониторился до её завершения; mount не пропадал.
Flutter запускался с `TMPDIR=/private/tmp/`. SDK не менялся; новый HV FFI
собран локально, frozen для тестов, checksum согласован с Dart bindings.
Software SHA, агрегаты и cleanup — в `summary.json`. Сырые логи, stack traces,
пути стенда и идентификаторы остаются в private cache.

Это проверка реальных контейнеров и native vacuum, не аппаратного стирания
носителя или forensic-анализа снапшотов диска. Производительность очень больших
профилей и Windows/физический Android с этой библиотекой здесь не измерялись.
Полная multi-device матрица остаётся открытой.
