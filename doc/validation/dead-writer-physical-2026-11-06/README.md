# NETCALL-01: физическая проверка SDK efe1c4ca

**Шесть звонков Poco ↔ Mac сохранились до команды завершения стенда,
включая три Wi-Fi → cellular → Wi-Fi. Паузы приёма сохраняются;
NETCALL-01 открыт.** Пять последних срезов каждого звонка на обоих концах
показывают свежий native audio RX. Это проверка цифрового тракта,
слышимость речи человеком не проверялась.

Агрегаты и provenance: [summary.json](summary.json).

## Условия

На обоих клиентах FFI из чистого `efe1c4ca`; предыдущая правка —
[отказ от drain после терминального keepalive](../dead-writer-grace-2026-11-06/README.md).
Использован замороженный QA frontend: заменены native SDK и два QA seed
asset в Android. Остальные AOT/native payload и подписант APK сохранены;
Mac использует проверенный внешний dylib, его отображение в процессе
подтверждено. Это не квалификация всех текущих Dart-изменений.

Один изолированный testnet Core на неизменённой SDK `ade3130a`.
Точные транспортные адреса обоих клиентов обнаружены в его active sessions
до звонков. P2P явно выключен на обоих; фактический медиапуть — обычный
Delivery relay, не приватная onion-цепочка. Сервер отличается от серии
`aa51cc13`; A/B-сравнения нет, вклад одной правки во весь звонок не доказан.

## Результаты

Время входящего считается от начала API-команды вызова; наблюдатель
опрашивает состояние, поэтому это время обнаружения, не точная дата пакета.
Максимальный возраст RX — `audio_rx_native_age_ms` из mediaStats,
не время между проверенными частями файла и не акустический замер.

| Сценарий | Входящий, с | Максимальный возраст RX Poco / Mac, с |
|---|---:|---:|
| Poco → Mac, подтверждён cellular | 0,604 | 0,301 / 0,410 |
| Mac → Poco, переключение сетей №1 | 0,562 | 7,486 / 6,119 |
| Mac → Poco, переключение сетей №2 | 1,075 | 12,512 / 13,140 |
| Poco → Mac сразу после команды Wi-Fi off | 6,671 | 1,135 / 1,177 |
| Poco → Mac после подтверждения cellular ОС | 0,607 | 0,354 / 0,514 |
| Poco → Mac, переключение сетей №3 | 1,081 | 6,076 / 1,806 |

В трёх handover-сценариях cellular наблюдался около 35 с перед возвратом
Wi-Fi. Первая post-switch попытка не доказывает cellular attachment в момент
начала вызова: это отдельно закрывает следующий сценарий с проверкой ОС.
Перед каждым наблюдением получены пять подряд парных срезов со свежим RX:
правильный call ID, active/running, worker не stalled, пакеты есть,
native age не более 1000 мс. Прохождение сценария означает сохранность
звонка, а не непрерывное аудио без пауз.

Во втором handover `mediaStats.media_epoch` обоих клиентов изменился
5 → 7, были срезы `media_repairing`. Поэтому нельзя заявлять непрерывность
того же медиадвижка или приравнивать один max-age к полной длительности
молчания. Остальные пять звонков имеют по одному наблюдаемому media epoch.
Поле `epoch` в native cell trace для этой проверки не использовалось:
оно относится к криптографическому контексту, а не к жизненному циклу media.

В полных финальных devlog обоих концов нет `livenessTimeout`;
родная трасса телефона также не содержит такого события. Завершения
выполнены стендом после наблюдений, до cleanup. Журнал телефона включён
после unlock, до звонков; полнота первоначального запуска не заявляется.

## Что удалось отделить

Один terminal keepalive-close → session-ended занимает **1 мс** по часам
телефона с тем же приватным peer prefix. Это положительная физическая
проверка снятия прежнего дополнительного writer grace на этом пути,
не доказательство устранения всех пауз.

При одном возврате Wi-Fi: network-change force reconnect, одна явная
retirement, затем конец сессии QA Core через **5002 мс**, новый configured
session-open через **5759 мс** от уведомления. Это другой путь закрытия —
OutboxClosed. Он дал следующую отдельную регрессию и
[исправление явного retirement](../explicit-retirement-2026-11-06/README.md).
Новая правка в описанные шесть звонков ещё не входила.

На NIC QA Core: 309 TCP flows / 42588 пакетов. Из 128 flows с payload
127 имеют server payload, наблюдаемый первый ответ 0,183–0,836 мс.
Один flow с 151 байтом client payload ответа payload не имеет и получает
server reset; односторонний захват не устанавливает причину. Точная
привязка мобильной неудачной попытки к NAT flow здесь не доказана.
Эти числа не исключают потери перед NIC и не объясняют все RX-паузы.

## Восстановление стенда

Приложения остановлены, точные PID проверены; Mac после grace потребовал
SIGKILL. QA APK возвращён и сверён SHA, основной APK и неизвестный старый
QA-контейнер неизменны. Исходные Wi-Fi/mobile/awake настройки и политики
восстановлены; перед отключением Poco ОС подтверждала cellular.
ADB forward и свои порты освобождены, runtime удалён, добавленный Mac log
архивирован вне репозитория и убран из bundle, strict codesign проходит.

Изолированные Core/capture units и их собственные файлы удалены.
Production PID, binary/config SHA и NRestarts совпадают с baseline.
Сырые журналы, PCAP, адреса и ключи находятся только в приватном кэше.
Push и релиз не выполнялись.
