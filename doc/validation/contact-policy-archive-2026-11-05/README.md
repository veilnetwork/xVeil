# Контактные политики при переносе архива — 2026-11-05

База `c487b330`. Локальная работа без push/релиза, APK, engine pins,
изменений публичных сидов, Rust/native ABI и mailbox для своих устройств.

## Подтверждённые механизмы

1. Экспорт включал disappearing policy только в metadata snapshot с архивным
   fill-clock. При более новом имени на получателе metadata целиком отвергалась,
   хотя собственная версия TTL была новее. Два assertion-red до правки:
   обычное хранилище и worker/native HVS.
2. Экран переноса выбирал transport ID вместо ID активной личности. В настоящем
   process-стенде sibling отверг архив как `otherIdentity`; отдельный widget
   test с прежним экраном подтвердил неверный header при разных identity/device IDs.
   Первоначальное зависание этого widget fixture было ожиданием stream вне
   `tester.runAsync`, исправлено до зачтённого assertion-red.
3. Настройки отсутствующего контакта применялись до создающего его status.
   В отличие от live sync, архивные строки не лежат в group fold для replay.
   Process-стенд подтвердил: после завершения импорта новый контакт accepted,
   но name отсутствует и policy stamp равен нулю; за две минуты это не меняется.
   Уже известный контакт одновременно получил новую политику и сохранил alias,
   block и локальный P2P. Это отдельное assertion-red на настоящем GUI bridge.

## Изменения

Новая policy переносится отдельным `contactUp/d:` событием с исходной версией.
Явное выключение переносится; ненастроенное значение с нулевой версией не
стирает действующую политику. Версии metadata, consent и policy независимы.

Новые архивы создают contact status перед metadata/policy. Offline registry
ждёт только slot предложенного события; live listeners сохраняют прежнее
неблокирующее поведение. Последующая проекция больше не обгоняет создание
контакта. Общие signature, consent, ratchet и durable gates не обходятся.

Экран использует ID доверенной активной личности для export/import. При
операции также захватывается собственный transport ID: importer может принять
старый архив, созданный именно этим устройством. Это явный необязательный
параметр доверенного caller, не список устройств из архива/сети. Другие ID
по-прежнему отвергаются до применения данных. Существующие byte-equality
проверки node config/credential и IdentityLease вокруг picker/dialog сохранены.

## Проверки

Scoped: **76 passed**, включая четыре worker/native policy-сценария,
active/off/older/default, повторный импорт, отсутствие echo и сохранность
локальных полей. Legacy owner guard отдельно проверяет отказ чужого/неизвестного
ID до записи и применение profile при точном собственном legacy ID. Widget
проверяет фактический header из настоящей кнопки экспорта, finish и смену
личности во время picker. Обычная broad-серия заново не запускалась.

Control: **790 passed, без skip**, 38 файлов, `XVEIL_DIAGNOSTICS=true` и явно
выбранная проверенная HVS. Включены CallService/realtime, request/accept,
mailbox commit, device sync, archive format и round-trip guards. Это контроль
регрессий; он не воспроизводит исходный Windows ↔ Android звонок.
Analyzer восьми изменённых lib/test inputs чистый. Headless AOT собран через
`dart build cli`, help завершается с кодом 0; 579 source/pub inputs неизменны.
Это build/smoke, не AOT сетевой прогон. Native зависимости не пересобирались.

## Сквозная квалификация и границы

Финальный A/B/C process-стенд на одном Mac прошёл все **13 gates**, включая
десять прежних durable/contact-policy проверок и три новых: импорт, повтор,
холодный запуск B. A/B — одна личность, C — другая. A остановлен на время
импорта; исходная архивная policy записана без sync-intent. Неизвестный B
контакт создан только архивом. Live sync не может удовлетворить этот oracle.
Известный контакт сохранил newer alias/block/P2P, получил исходную policy
версию; новый получил alias/accepted/policy. После restart B проверены те же
поля и версии. Ошибок применения импорта нет; unconfirmed appliers по-прежнему
пять и не объявлены подтверждёнными.

Серия: 161,714 с целиком, не latency benchmark. Заморожены **1476** source,
test и dependency inputs; source/lock/features и native/HVS SHA сверены,
исходники не менялись во время прогона. Teardown проверил **48 PID / 54 порта**,
собственных процессов/listeners нет, runtime удалён. Все три предшествующих
неуспешных стенда тоже штатно закрыты, cleanup проверен отдельно.

Предшествующие неуспешные серии сохранены отдельно: identity refusal;
ошибочный oracle с требованием нуля unconfirmed appliers; затем настоящий
assertion-red на пропавших полях нового контакта. У production registry пять
обработчиков без settle callback — это не пять ошибок применения. Контактные
поля проверяются фактически, без объявления всех прочих group/cloud
обязательств подтверждёнными.

Перенос старых архивов с прежним порядком contact rows, распространение
импортированных полей на третье устройство, Android/Windows и вся multi-device
матрица отдельно не квалифицированы. Это проверка контактных проекций новых
архивов, не заявление о полноте восстановления любых данных.

Исходный [репорт ПК ↔ Android](../user-pc-android-calls-2026-11-05/README.md)
этими архивными механизмами не атрибутирован. При повторной проверке SSH снова
недоступен; новый физический Windows звонок не выполнялся. Закрытое хранилище
и вводящий в заблуждение текст relay-deposit уже исправлены предыдущими
локальными коммитами; отсутствие входящих вызовов остаётся активным случаем.
