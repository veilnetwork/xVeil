# Подтверждение одного дочернего канала блокировало весь пул

**Подтверждён и исправлен локальный дефект** `ordered_lanes::worker`.
Veil-коммит: `4f441329`. Итоги: [summary.json](summary.json).

## Причина

После проверки incoming proof общий worker выполнял `child.finish().await`
внутри ветки `select!`. Этот вызов пишет и flush-ит ACK в независимый
TCP/obfs4-канал; запись ограничена прежним трёхсекундным bind timeout.
Пока она ожидала сокет, worker не принимал другие уже проверенные каналы,
не обрабатывал завершения исходящих попыток и не выполнял периодическую
очистку пула. Таймаут отдельного канала становился общим ожиданием.

Теперь bounded ACK flights завершаются независимо, результаты публикуются
по готовности. Их не более **восьми**, как и прежний directional connection
budget. Proof/exporter verification, parent authority, фактический transport
lease, bind timeout и выбор нейтральных duplex-слотов остаются прежними.
При завершении worker отменяет и дожидается всех ещё выполняющихся ACK
flights, освобождая их transports/leases до своего возврата.
Ни wire, ни C ABI, ни настройки аудио/таймаут звонка не менялись.

## Воспроизведение и регрессии

Два теста используют production worker и `ParallelRegistry`. Реальный
obfs4 parent даёт транспортный offer и connection budget; дочерние потоки —
детерминированные duplex pipes с настоящими parent/exporter-bound proofs.
Writer первого ACK намеренно возвращает Pending. Это модель локальной
блокировки I/O, а не воспроизведение потерь мобильного провайдера.

На базе `b9b88bb7` оба финальных теста **assertion-red**, без timeout:

- Второй уже допущенный канал: **0 готовых вместо 1** до истечения таймера.
- Восемь допущенных proofs: **1 начатая запись ACK вместо 8**.

На исправленном коде оба проходят. До продвижения виртуальных часов второй
канал публикуется и передаёт точную зашифрованную запись. Затем virtual
timeout первого освобождает только его lease; второй остаётся активным и
зарегистрированным. Девятое соединение отклоняется прежним transport budget.
Retirement родителя освобождает все восемь незавершённых flights; active
connection counter становится нулём, ни одного канала в пуле не остаётся.

Проверка немедленной готовности выполняется на current-thread executor
при paused time и runnable yields; watchdog чтения не используется как
измеренный порог производительности. Перед red assertion worker явно
завершается, поэтому зависание не заменяет доказательство дефекта.

Ранний compile-only отказ из-за типа счётчика не засчитан как red. При
усилении fixture исправлены два ошибочных наблюдения: accepted endpoint
публикует канал в `slots`, а не в `incoming`; отправка новых records после
искусственного скачка только Tokio time смешивала его со std monotonic
TTL. Финальные тесты заново прогнаны на базе и кандидате. Production не
подстраивался под эти ошибки fixture.

## Проверка и пределы

Полный `cargo test --offline --locked -p veil-session`: **694 passed,
0 failed, 8 ignored**; один doc-test ignored отдельно. Новые два теста
включены в эти 694. `rustfmt --check` и `diff --check` чистые. Проверены
995 неизменных Rust/manifest/lock inputs и SHA реально запущенного test
binary, в нём присутствуют оба новых теста. Build/test использовал текущий
checkout без dependency override; внешняя ФС проверялась непрерывно,
потери mount не было. Все cargo/test процессы завершились.

**NETCALL-01 остаётся открытым.** Это снятый локальный механизм ожидания,
его вклад в наблюдавшуюся паузу Wi-Fi → cellular не установлен. Последняя
[физическая серия](../reconnect-wake-physical-2026-11-06/README.md) использовала
более раннюю SDK. Сетевые TCP/obfs4 first-flight потери она также наблюдала;
новая правка не является доказательством их устранения. Poco на момент
этого цикла отсутствовал в `adb devices`; новой проверки звонка нет.

Новые FFI/APK в этом цикле не собирались и не устанавливались. Windows,
телефон, реальные профили и production-сиды не изменялись. В публичных
артефактах только агрегаты, без peer/device IDs, адресов, ключей или raw logs.
Коммиты локальные, без подписи, push и релиза.
