# Одиночное событие больше страницы own-device history

2026-11-03. Подтверждён и исправлен оставшийся случай после byte-budget фикса:
одна строка сама не помещалась в страницу. На исходном коде из трёх строк
приходила только первая короткая; большое событие и следующая строка
оставались недоступны. Воспроизводитель завершался по записи ошибки,
а не по порогу скорости.

## Изменение

Страница возвращает descriptor большого события: позиция, длина и digest.
Устройство запрашивает части по 64 КиБ через `op: record`. Ответ по-прежнему
ограничен 128 КиБ и 64 транспортными slices. Каждая порция проходит прежние
ratchet/provenance и актуальные проверки устройства. После сборки проверяются
длина, digest, ID/время, затем обычный mirror/status applier с его TTL и binding
guards. Digest не является разрешением на доступ.

Durable cursor остаётся перед событием до полного apply. Частичная сборка
живёт только в RAM. Источник пересобирает актуальный event на следующем
запросе: изменение digest сбрасывает частичные байты и возвращает запрос к
тому же cursor. При restart повторяется только незавершённое событие.

Один record ограничен 1 МиБ (существующий application-frame bound), все
частичные records — общими 4 МиБ, по одному на sibling pull. Размер
резервируется до выделения массива; отказ бюджета оставляет cursor на месте
и назначает повтор. Credits освобождаются при завершении, ошибке, замене
binding и close; через durable apply они остаются занятыми. Это отдельный
budget, не оценка всей памяти приложения.

Stored message event уже ограничен 512 КиБ. Ранний тестовый seed на 1,5 МБ
был отклонён хранилищем по его контракту и не считается дефектом приложения;
stress-проверка использует допустимые 500000 байт. Это также позволило
сохранить logical-record cap в 1 МиБ вместо первоначального кандидата 2 МиБ.

## Регрессии

**153 tests passed / 0 skipped**, analyzer чист: own-device history,
history backfill, device sync/brick4/slot, large-frame codec и обычная доставка
больших сообщений. Девять новых tests проверяют:

- большое событие между короткими, точные ID/тела/порядок/source positions,
  delivered и revision правки;
- restart после первой порции: cursor остаётся перед событием, следующий
  fetch начинается с offset 0, сохранённый префикс повторно не применяется;
- изменение источника между порциями без смешения ревизий;
- истечение TTL посреди передачи без восстановления просроченного текста;
- девять digest-failure подряд без apply/advance, затем успешную передачу
  500000 байт: освобождённые credits доступны повторно;
- пять sibling-дескрипторов по 1 МиБ: только четыре получают продолжение,
  после смены binding пятый тоже может начать;
- oversized descriptor: отказ до record-fetch, durable cursor неизменен;
- отзыв источника у получателя и замену binding без apply старого префикса;
- актуальную source-side авторизацию даже для корректного запроса record,
  с положительным контролем после восстановления допуска.

Обычные short-page, malformed-input, queued-revoke, shutdown, delivery/cursor
write failure и admission регрессии также прошли. Каждая test-network посылка
остаётся ≤6144 байт; crypto и production-сеть unit-стенд не моделирует.

## Native-проверка

Три отдельных OS-процесса A/B/C с реальными app providers, native signing,
worker/HV и локальным relay island. A/B связаны; B уже знает accepted contact C.
Затем B и C останавливаются. Через тестовый file-protocol live storage owner A
сохраняет три синтетические исторические строки, средняя — **160015 байт**.
Эта подготовка моделирует данные вне bounded journal: local-send taps не
вызываются, group rows и Outbox-копии не создаются.

| Этап | Ожидание | Факт |
| --- | --- | --- |
| До запуска B | Проверочные строки отсутствуют в device journal A | 0 mirrors |
| Возврат B, C offline, A online | Все три строки доступны через live own-history | 3/3 с точными ID/телами/порядком/позициями/delivered |
| После получения | Полная копия не переиздавалась в device journal | По-прежнему 0 mirrors |
| A/C offline, B перезапускается | Уже сохранённые строки доступны локально | 3/3, дублей 0 |

Получение заняло **40,792 с**, включая запуск B. Это одиночная квалификация,
не A/B и не stage decomposition; ускорение не заявляется. До исправления
такая строка не помещалась ни в одну страницу, что отдельно показал red test.
Стенд не является воспроизведением естественной compaction или реальной
отправки большого текста контакту: данные подготовлены прямо в собственном
зашифрованном хранилище тестового устройства.

CLI/FFI заморожены на проверенном SDK `eb644a83`, HV одинаков; последние
transport-правки `8dac85ce` этим не квалифицированы. CPU-профайлер, публичные
seeds/discovery выключены. SHA native artifacts и 1398 source-файлов совпали
до/после, исходники во время стенда не менялись. Тест завершился с кодом 0;
независимо проверены выход 21 собственного PID, освобождение 22 портов,
удаление runtime-контейнеров. Raw synthetic evidence приватны.

## Оставшееся

Это новый app-level operation: для больших records нужны обе обновлённые
стороны. Совместимость со старыми версиями исключена владельцем из релизных
условий. Mailbox не подключается, постоянные частичные копии не вводятся.
Медленная догрузка, физические Android/AOT/mobile-network серии, остальные
части crash/revoke/split-brain матрицы сохраняют свой статус. Push, релиза,
установки на пользовательские устройства и обновления публичных реле нет.
