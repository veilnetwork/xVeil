# Микрофон в Windows AOT и приватность путей — 2026-11-12

## Проверка исправления в приложении

Новая Windows profile-AOT собрана из runtime frontend `3e78499a` и media source
`83a54e35`. Сверены 807 файлов canonical frontend, включая все текущие `lib/*.dart`,
и четыре изменённых SDK-файла — всего 811 build inputs. Двадцать отличий от
сохранённой canonical копии внесены только на время сборки. AOT SHA изменился;
в новую отдельную bundle включена проверенная свежая media DLL. Rust FFI и
hidden-volume оставлены прежними проверенными библиотеками: Rust-исходники
этой правкой не менялись. Native/source/binary SHA зафиксированы отдельно.

На Blackview использован прежний отдельный QA APK; Windows-правка выбора входа
не меняет его аудиоуправление. Основные приложения не заменялись. Телефон прошёл
настоящий onboarding нового QA-профиля; контакт принят в обе стороны и два
контрольных сообщения проверены по точным ID/тексту/delivered.

В холодной Windows QA-копии перед запуском задано имя заведомо отсутствующего
микрофона. Проверена правильная типизированная запись внутри schema v1 prefs,
а не посторонний JSON-ключ. Ниже — настоящие звонки Windows 11 ↔ Blackview:

| Этап | Парные срезы / интервал | Windows audio RX / remote frames | Android audio RX / remote frames |
|---|---:|---:|---:|
| Отсутствующий сохранённый вход → системный, звонок с Android | 9 / 16,57 с | 92 / 227 | 85 / 142 |
| Переключение на физический вход в том же звонке | 6 / 10,36 с | 56 / 306 | 52 / 205 |
| Восстановление выбранного входа, следующий звонок с Windows | 9 / 16,55 с | 97 / 202 | 335 / 94 |
| Явный возврат к системному входу | 6 / 10,39 с | 55 / 307 | 162 / 209 |
| Системный вход на следующем звонке с Android | 9 / 16,47 с | 88 / 163 | 85 / 159 |
| Mute → выбор системного входа → unmute | 6 / 10,44 с | 56 / 305 | 61 / 204 |

Это **три звонка и шесть этапов**, не шесть звонков. Во всех 45 срезах active,
ожидаемый peer/call ID, стабильная media epoch внутри этапа, capture/playout
success и workers без stalled. Audio TX, RX, video TX и декодированные удалённые
кадры росли в обе стороны на каждом этапе. Фактический транспорт — P2P;
relay/onion этой серией не квалифицировались. Звонки закончены командами стенда.

Первый отсутствующий выбор корректно дал `system-default`; затем подтверждены
конкретный вход на новом звонке и системный вход после явного возврата.
После серии ключ сохранённого микрофона отсутствует в собственном QA prefs —
очистка настройки проверена на диске. При выборе роли во время mute микрофон
оставался выключенным до явного unmute.

Человек речь не слушал. Тестовая речь/PCM не подставлялись и не записывались.
Физическое извлечение USB-устройства не выполнялось: его отсутствие моделировала
сохранённая настройка только в QA-копии. Windows 10, слышимость речи и аватары
в GUI этим не проверены; исходная пользовательская жалоба остаётся открытой.

## Новая подтверждённая находка приватности

В **локальном Windows QA app.so** обнаружены 1827 абсолютных домашних `file:`
URI: 601 к исходникам приложения, 493 к Flutter SDK, 733 к Pub-кешу. Исполняемый
файл и свежая native media DLL прежний профильный scan прошли. Это не обосновывает
приватность AOT: C++/Rust prefix remapping не переписывает Dart source URI.

Проверка прежнего локального Android QA APK выявила ещё **1316 домашних URI в
libapp.so**. Первоначальный фильтр был ограничен известными строками/форматами
и пропускал этот вид пути. Его вывод «совпадений нет» в прежней записи исправлен.
В сохранённой локальной macOS profile-AOT тот же checker нашёл 1290 домашних
URI. Это общий остаток AOT-подготовки трёх платформ, а не Windows-only случай.
Эти QA-сборки не публиковались и не добавлялись в Git. Публичные релизные
артефакты этим измерением не проверены.

Добавлен `scripts/check_aot_source_paths.py`: распознаёт синтаксис домашнего
`file:` URI без списка конкретных владельцев; проверяет отдельный AOT-файл,
каталог или распакованные в памяти члены ZIP/APK. Вывод содержит только количества,
без пути входного артефакта и совпавших строк. Ошибка чтения, повреждённый архив,
пустой набор и превышение лимита не дают ложного clean. Проверка не изменяет
входы и не извлекает ZIP-пути на диск.

Семь regression tests прошли и добавлены в CI. На настоящем Windows AOT и
Android APK утилита завершает работу **кодом 1** с указанными совпадениями;
на Android просмотрены все 609 членов. Это проверка обычных byte-encoded URI,
не универсальный поиск секретов, иных кодировок или вложенных архивов.

Удаление путей из самой сборки ещё **не выполнено**. Инструмент пока отдельный;
автоматический packaging gate не заявляется. Следующий шаг — приватные нейтральные
пути для исходников, SDK и Pub-кеша с повторной бинарной проверкой. Обфускация
или потеря читаемых debug stack traces не приняты как готовое решение.

## Восстановление и границы

Во время подготовки обнаружены ошибки собственного стенда: неправильное имя
архива в wrapper и оставшийся пустой staging-каталог; попытки не засчитаны.
Сборка после исправления проверила inputs и восстановила исходные source/bundle.
Нажатие скрытой ниже viewport кнопки onboarding также не считалось успешным
переходом: экран проверен и прокручен до реального продолжения.

После звонков оба QA-приложения заблокированы через POST `/lock`, свои процессы
остановлены. Android QA удалён, основной APK сохранил SHA, Wi-Fi возвращён
в исходное выключенное состояние. ADB/SSH forwards закрыты, временные ключ
и пароль удалены. Windows cold-copy/profile/task удалены; исходные QA данные,
canonical frontend и native bundle повторно сверены. Новая bundle с приватными
AOT URI оставлена только в приватном каталоге стенда для исправления сборки.

Immutable media pins не обновлены; push/релиза нет. Приватных имён, адресов,
идентификаторов и сырых трасс в этой записи нет.
