# Догрузка 1000 сообщений после аварийного завершения получателя

2026-11-03. Проверка текущего Dart на трёх отдельных OS-процессах A/B/C.
A и B — одна личность, C — другая. Настоящие провайдеры приложения,
native signing, worker/HV и изолированное loopback-реле. Это host/native
квалификация; Android/AOT и последние transport-изменения SDK не проверялись.

## Усиление проверки

`offline_backlog_process_e2e_test.dart` теперь читает полную выборку через
владельца открытого хранилища в worker. Ограниченный HTTP-хвост больше не
может скрыть прежнюю строку или дубль за пределами последних 1000 сообщений.
Проверяются точные ID, соответствие тела каждому ID, порядок, исходные
`orderAuthor/orderSeq` на B и конечный `delivered`. Отдельно сохраняется
исходная строка приветствия. Пустые списки не удовлетворяют этим условиям.

Наблюдатель добавлен только в тестовый file-protocol; production API и
экспорт диагностики не расширялись. Короткий native-тест отдельно проверяет
представление автора: C хранит identity собеседника, B — позицию исходного
устройства A. Это предусмотренная модель, а не расхождение собственных
устройств.

## Результат полного прогона

| Этап | Состояние и действие | Ожидание | Факт |
| --- | --- | --- | --- |
| Накопление | B stopped; A отправляет C 1000 сообщений | C имеет все ID и порядок, A — durable delivered | 1000/1000 до отключения C |
| Начало догрузки | A online, C stopped, B запускается | B получает часть пропущенного | 250/1000 при наблюдаемом прерывании |
| Аварийное завершение | SIGKILL группе процессов B | Следующий запуск восстанавливает недостающую историю | 1000/1000, точные ID/тела/порядок/source positions, все delivered |
| Локальная сохранность | A stopped, C stopped; B ещё раз перезапускается | Полученная история доступна без других устройств | Все 1000 и исходная строка сохранены, дублей нет |

Предусловие частичной догрузки выполнено: перед SIGKILL было именно 250,
а не уже все 1000 сообщений. Восстановление не использовало C. A оставался
online до полной сходимости B. Это фактическая проверка прерывания и
продолжения из сценария 16, а не clean stop после завершения синхронизации.

От первого запуска B до полной сходимости после аварийного перезапуска —
**122,101 с**, включая оба запуска и саму догрузку. Отправка исходных 1000
заняла 182,220 с. Это одиночная квалификация, без A/B и отдельной временной
декомпозиции; ускорение не заявляется. Догрузка большой истории остаётся
активной задачей.

## Неудачные попытки и границы доказательства

Два ранних запуска не засчитаны: сначала наблюдатель вызвал extension-геттер
`MessageStatus.name` через dynamic, затем oracle ошибочно требовал одинакового
автора на C и A. В первом случае исправлен тип `List<Message>`, во втором
учтено документированное представление автора у собеседника. Обе ошибки были
в стенде, обе возникли до проверяемого crash. Короткий native-preflight
после этих исправлений прошёл, затем прошёл полный сценарий выше. Analyzer
трёх изменённых тестовых файлов чист.

Это не проверка kill внутри конкретной транзакции БД, ratchet-checkpoint или
ACK-стадии; не crash отправителя посреди первичной публикации истории; не
revoke/split-brain, часы/сутки offline или миграция файлов и звонков.

По [решению владельца](../multi-device-policy-2026-11-03/README.md) mailbox
между собственными устройствами не подключается. Получение отсутствующих
данных при одновременно offline всех их держателях не требуется. Последний
этап проверяет сохранность уже полученных данных, а не такую доставку.

## Происхождение и завершение стенда

CLI/FFI заморожены на ранее проверенном SDK `eb644a83`, HV одинаков;
CPU-профайлер и публичные seeds/discovery выключены. SHA артефактов и 1396
файлов source manifest совпали до/после, исходники во время прогона не
менялись. Текущий SDK `8dac85ce` этим тестом не квалифицирован.

Полный тест завершился с кодом 0. Независимый cleanup подтвердил выход 23
собственных PIDs, освобождение 33 портов и удаление runtime-контейнеров.
Короткий preflight также завершился и очищен: 18 PIDs, 21 порт. Публичная
запись содержит только агрегаты; raw synthetic evidence хранится приватно.
