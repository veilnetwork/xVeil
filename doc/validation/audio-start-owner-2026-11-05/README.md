# Запуск аудио после ожидания должен принадлежать текущему движку

2026-11-05. Подтверждена отдельная гонка в
`VeilCallMediaController.start`: выбор сохранённых аудиоустройств и ожидание
аудиомаршрута позволяли продолжению запуска пережить stop или замену движка.
Это не установленная причина пользовательского отсутствия звука или всей
паузы NETCALL-01.

## Воспроизведение

Настоящий controller со своим start/stop, тестовыми transport/engine и
SharedPreferences. Completer отмечает вход в перечисление микрофонов,
динамиков или установку начального mute. До продолжения await выполняется
отбой, начинается другой звонок либо заменяется engine того же звонка.
Timeout служит только защитой от зависания теста; порогов длительности нет.

| Граница | Старое продолжение после stop / замены | После исправления |
|---|---|---|
| Сохранённый микрофон | выбор входа и mute на disposed engine | false без обращений к старому engine |
| Сохранённый динамик | выбор выхода и mute на disposed engine | то же |
| Ожидание аудиомаршрута | startAudio на disposed engine | то же |
| Те же три границы без stop / замены | штатный запуск | сохранён, выбор устройства корректен |

Baseline: **9 assertion-red, 3 положительных control**. Контролируемый engine
записывает каждое обращение после dispose и бросает исключение, как native
обёртка для закрытого handle. Тест проверяет и отсутствие устаревших вызовов,
и чистый false старого start, и успешный startAudio нового владельца ровно
один раз. Замена движка того же call ID проверяется отдельно от нового звонка.

## Исправление

После каждого из этих await сверяются media epoch, конкретный engine и call
ID. Проверка находится также внутри восстановления предпочтений, между
перечислением устройств и их выбором. Поэтому устаревшая операция не меняет
выбранный ID и не доходит до сброса liveness/timer состояния преемника.
Отмена возвращает false; cleanup нового владельца не запускается.
Production-параметров для fault injection не добавлено.

## Проверки и границы

Новые 12 случаев прошли; контроль восьми call/media файлов — **345 passed,
без skip**. После исправления одного замечания analyzer в новом тесте
повторён весь файл start — **41 passed**, не складываются с контрольными
345; analyzer двух изменённых файлов чистый.
Все Flutter-запуски — `TMPDIR=/private/tmp/`. Процессы тестов завершились.

Это controller-проверка на macOS с подставным ADM, без физического звонка.
Desktop-случаи перечисления устройств явно skipped на Android/iOS; на этом
Mac они выполнены. Windows повторно доступна по SSH с авторизацией; Android
по ADB пока отсутствует. Слышимость речи и физический mobile handover этим
не квалифицированы. Rust/C++/engine pins, сиды, push и релиз не менялись.
Raw logs и credentials в репозиторий не добавлены.
