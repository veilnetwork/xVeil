# Аварийное завершение получателя до и после записи сообщения

Продолжение на native SDK 0.11.51 / hidden-volume 2.7.2:
[повтор этих контролей и падение после наблюдаемого ACK](../message-ack-crash-2026-11-13/README.md).
Границы исторического прогона ниже остаются прежними.

Две выбранные границы receive/decrypt/DB/ACK проверены на native A/B/C:
после обработки входящего сообщения перед записью и после возврата записи,
до продолжения обработчика и подтверждения доставки. В обоих сценариях
обычный повтор отправителя завершает доставку с тем же ID и без дубля.
Последующий обмен работает в обе стороны.

Это частичное покрытие пункта 62 исходной multi-device матрицы, а не проверка
всех стадий внутри расшифрования, native-транзакции или отправки ACK.
Агрегаты: [summary.json](summary.json). Этапы: [cases.csv](cases.csv).

## Стенд и контрольные точки

macOS arm64, A/B — личность X, C — личность Y; отдельный OS-процесс каждого
клиента и три loopback Core. CLI/SDK 0.11.50, SDK source `e963fbdb`,
hidden-volume `293792d`. Production-код приложения соответствует `74277174`;
новый тест и его fixture — `e4612be2`. Выбранные исходники и native bytes
сохранялись неизменными во время зачтённой серии. У native клиентов
выключены bundled seeds и meeting points, Core имеют проверенные политики
`never`/`off`. Политика own-device mailbox не менялась.

Тестовый storage adapter наследует настоящую `HiddenVolumeStorage`, сохраняя
worker opener и остальные возможности родителя. Он ставится только на C
по отдельному e2e-флагу и останавливает один заранее выбранный incoming body:

- `before`: родительский `appendMessage` ещё не вызван;
- `after`: его Future уже успешно завершился, но вызывающий `_store`
  ещё не получил результат и не продолжил `publishStored`/ACK.

Marker публикуется синхронно, затем VM получает SIGSTOP. Родитель теста
проверяет реальное состояние `T` и принадлежность VM собственной группе,
после чего посылает SIGKILL. Exit code группы — `-9`; перед открытием
контейнера отдельно проверяется завершение самого VM-процесса. На A в этой
точке ещё нет статуса delivered для целевого сообщения.

Adapter, сигналы и файловые controls существуют только в `test/`; обычное
приложение их не импортирует. Wire, native transport и повтор Outbox не
подменяются. Сценарий: [message_append_crash_e2e_test.dart](../../../test/e2e/message_append_crash_e2e_test.dart).

## Результаты

| Проверка | До append | После append |
|---|---|---|
| Строка в реальном контейнере после SIGKILL, до запуска сети | Отсутствует | Одна, с точными ID и body |
| Обычный повтор Outbox после возврата C | Создаёт одну строку | Подтверждает существующую строку |
| ID восстановленной строки | Исходный ID отправителя | Исходный ID отправителя |
| Delivered на A и его sibling B | Да | Да |
| Следующее сообщение C→X и новое X→C | Доставлены | Доставлены |
| Согласованность A/B | Одинаковые ID, порядок, seq и статусы | Одинаковые ID, порядок, seq и статусы |
| Все пять строк при новом cold-read C без A/B, до сети | Сохранены | Сохранены |

Пять ожидаемых строк — исходное `hello` от процедуры знакомства, контрольное
сообщение, целевая crash-строка, ответ C и следующее сообщение A. Для каждой
проверяется единственность ID; неизвестная лишняя строка не заменяет ожидаемую.
После чтения контейнера до сети C запускается ещё раз, API возвращает тот же
набор ID и тел. Это проверяет пригодность ratchet после повторной доставки,
не только наличие старой строки на диске.

Два unit-теста проверяют положение adapter относительно реального метода
append на memory-backed storage; два process e2e прошли с настоящими
контейнерами и OS-сигналами. Пропусков нет. Targeted analyze — без замечаний.

Первый запуск не зачтён: ожидаемый набор не учитывал исходное `hello`;
в другом сценарии cold-open получил Busy без проверки завершения VM.
Исправлен oracle и добавлено ожидание наблюдаемого выхода VM, а не задержка
по таймеру. В повторной полной серии Busy не наблюдался; его первоначальный
владелец не установлен и исправлением продукта это не объявляется.

## Границы и очистка

Не проверены этим запуском середина расшифрования/native commit, crash после
отправки ACK, аппаратное отключение, Android/Windows и прочие пункты матрицы.
Историческая разметка всех 63 пунктов сохраняется.

Проверены 18 зарегистрированных PID и 18 TCP listen ports; собственных
процессов/VM/listeners не осталось. Оба временных runtime с контейнерами
удалены. Raw markers, IDs, PID и подробные logs остаются в приватном кэше.
Телефон, Windows и production-реле не использовались. Push и релиза нет.
