# Собственные устройства: отзыв после crash автора

## Подтверждённая граница

Усилен существующий OS-process сценарий A/B/C: A и B — устройства одной
личности, C — контакт. A сохраняет настоящий подписанный отзыв B, но теряет
ответ записи и завершается до обновления group-control журнала. После
холодного запуска точный новый документ публикуется, однако ещё валидный
старый журнал продолжает перечислять B.

На SDK `53fbbe34` новая проверка упала: `addressableOwnDevices()` автора
вернул B после самостоятельной публикации сохранённого отзыва. Это
подтверждённый выбор запрещённого адресата, **не новое доказательство
доставки plaintext, обхода native-фильтра или прослушивания аудио**. Ранее
исправленный realtime admission остаётся отдельным барьером.

## Изменение

Перед выдачей адресатов своего sovereign device-group приложение свежим
чтением получает сохранённый документ. Подписанный tombstone исключает
соответствующий физический адрес, даже если group-control удаление ещё не
успело сохраниться. Документ не берётся из периодического verifier cache.
История и roster не переписываются; отсутствие tombstone не создаёт новых
прав. Группы без sovereign material сохраняют прежнюю маршрутизацию.

Новый stateless native helper проверяет полный документ и привязку к
владельцу группы, затем отвечает только на вопрос об явном отзыве. Ошибка
верификации — отдельный отказ, а не «устройство не отозвано». Strict-чтение
не скрывает ошибку текущего файла переходом на legacy setting. Прежняя
семантика чтения material у остальных callers сохранена.

Проверка после await сохраняет существующие generation/dispose guards.
Незавершённое чтение можно разделять, завершённый результат не кешируется.
API добавлен в native header; для следующих app-сборок нужна пересборка SDK.
Wire, mailbox и существующие transport/ratchet authorization не менялись.

## Квалификация

- Baseline: ожидаемый assertion-red после реального crash/cold-open; старый
  журнал и исходящая адресация содержат B. Все процессы завершились.
- Candidate SDK `26c0a8a5`: действующий B адресуем до отзыва; после crash
  журнал по-прежнему содержит B, а outgoing routing его исключает. Полный
  A/B/C сценарий прошёл: точный документ перепубликован без ручного retry,
  durable checkpoint контакта наблюдался, сообщения и вызов разрешённым
  участникам работают. Новые offer/reply не появились на B; окна наблюдения
  входящего отказа и исходящей недоставки — около 30 и 8 секунд отдельно.
- **384 Rust FFI passed / 2 ignored**, вложенный child-test не прибавлен
  повторно. Clippy всех FFI targets с `-D warnings` прошёл. Production-feature
  SDK/CLI собраны при непрерывном контроле внешнего mount; точные выбранные
  SHA и новый экспорт проверены перед стендом.
- **546 групповых тестов passed / 0 skipped** с явно выбранными SDK и native
  storage; focused analyze пяти изменённых файлов — без замечаний.
- Генератор C header/Rust/Dart ABI contracts идемпотентен. Исходники и native
  bytes не менялись во время E2E. Все **44** отслеженных процесса завершены,
  **28** портов освобождены; отдельный повторный аудит процессов чист.

Первые неудачные попытки не считаются пройденными: в новом Rust fixture
исправлен выбор типа master secret; stale ABI hash пойман полным тестом и
исправлен штатным генератором. Flutter-запуск без заданного native storage
не зачтён; итоговая серия выше использует qualified библиотеки. Проверка
числа чтений теперь учитывает отдельное чтение документа отзыва.
[Машинная сводка](summary.json) не содержит приватных идентификаторов/логов.

Все контейнеры и процессы принадлежат отдельному локальному стенду. Mac
окна/ввод, пользовательские профили, Android APK и production-сиды не
затрагиваются. Это выбранная crash/revoke граница, не вся multi-device
матрица, Android/AOT или power-loss квалификация. NETCALL-01 не закрывается.
Нового push или релиза нет.
