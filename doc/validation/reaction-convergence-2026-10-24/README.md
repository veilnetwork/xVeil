Локальная следующая версия не меньше текущего clock и строго больше уже

пользовательские изменения при откате часов. Конкурентные устройства с одинаковым
временем всё равно используют общий deterministic tie rule.

Очередь закрывается после завершения уже принятого inbound. Начатые локальные
действия удерживают хранилище до вызова callback и записи outbox; сетевой live leg
не занимает очередь read/modify/write. Новые локальные действия закрытого
сервиса отклоняются, late mirrored events не пишут в закрытое хранилище.
Новый production test seam не добавлялся.

## Хранилище и совместимость

`rx2:<conversation>` содержит версию формата, значения и timestamps одним
зашифрованным FileStore blob. Он становится видимым через финальный metadata
commit; прежняя полная версия доступна до публикации новой. Старые `rx:`/`rxat:`
читаются из файлов или settings до первого успешного переноса. Затем legacy
копии удаляются; неудачная очистка не отменяет уже опубликованное состояние,
не мешает outbox и повторяется при следующем изменении.

Старые timestamps и removal floors сохраняются, поэтому поздний старый кадр
не восстанавливает удалённую реакцию. Некорректный authoritative snapshot не
заменяется пустой legacy-копией при мутации. Откат на старый бинарник после
миграции не квалифицирован: прежний клиент не читает `rx2`. Wire schema не
меняется; смешанные версии этим циклом не сертифицированы. Для старых кадров
без timestamp сохранена прежняя семантика, новая гарантия порядка относится к
версионированным реакциям.

## Native-стенд: найдено новое открытое расхождение

Четыре независимых application/native workers (A/B=X, C/D=Y), три изолированных
локальных реле, разделение A/C и B/D с живыми процессами. Повторно использована
совместно собранная CLI/FFI-пара текущего неизменённого SDK; loopback test builds
не имеют compiled public seeds, используют `--no-default-features` и
`test-low-difficulty`. Это не релизные артефакты.

В сохранённом live snapshot все 16 новых сообщений присутствуют по одному разу,
реакции совпадают на четырёх устройствах, маркеры чтения совпадают в каждой
личности. Но **A/B имеют разные seq у четырёх одних и тех же сообщений**, хотя
ID, текст, направление, timestamp и edit state совпадают. Видимый порядок истории
расходится. Прогон исчерпал прежний четырёхминутный convergence gate и завершился
FAIL. Порог не менялся, неуспех не исключался из результата.

Это **MD24-01, открыт**. Причина конкретного пути потери/переназначения seq ещё
не установлена: текущий device mirror payload уже передаёт author/seq, поэтому
простого утверждения «поля вообще не передаются» недостаточно. Нужно проверить
peer-history ingestion и выбор первой копии. Убирать причинную сортировку по
seq для прохождения теста не предлагается.

Native snapshot предшествует последнему добавлению очистки legacy записей;
полный native PASS финального исходника здесь **не заявляется**. Хеши обеих
версий исходников разделены в `summary.json`.
