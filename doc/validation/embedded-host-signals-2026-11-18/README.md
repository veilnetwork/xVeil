# Встроенный SDK сохраняет обработчики сигналов host

**Подтверждено и исправлено локально. Не выпущено.** На фоновом QA Mac после
успешного lock/stop встроенного узла SIGTERM оставлял приложение живым.
Наблюдение из [подготовки NETCALL-стенда](../netcall-background-stand-2026-11-18/README.md)
затем воспроизведено без Flutter, интерфейса, профиля приложения и медиа.

## Причина и изменение

Оба FFI-конструктора запускали общий foreground loop. Помимо команды stop,
он устанавливал process-wide обработчики SIGINT/SIGTERM и SIGHUP reloader.
Уничтожение Tokio signal streams не возвращает прежние обработчики host.
Поэтому даже после завершения node thread процесс продолжал перехватывать
сигналы. Это также неправильная граница владения для нескольких узлов в host.

Veil `53fbbe34` разделяет standalone и embedded entrypoints. CLI и Windows
service сохраняют прежние OS signal handlers. Embedded запуск не создаёт
ни shutdown signal streams, ни SIGHUP reloader: его останавливают host token
или authenticated admin command. Никакого сброса глобальных обработчиков
при stop не добавлено — такой сброс мог бы затронуть другой узел или host.
Обе разновидности deferred запуска используют общий код и по-прежнему
передают placeholder marker. Его прежний source guard обновлён на общий
вызов и обе публичные обёртки.

Не менялись C ABI, wire, bootstrap/crypto/авторизация, storage, media и retry.
SDK-host, которому нужны OS-команды, сам владеет обработкой сигналов и вызывает
явный stop/reload API; standalone CLI продолжает принимать сигналы напрямую.

## Воспроизведение и проверки

[C++ host](../../../test/native/embedded_host_signals.cpp) устанавливает свои
обработчики, загружает точную SDK и действительно запускает узел. После
настоящего admin health RPC parent разрешает снять состояние обработчиков.
Проверяются работающий узел и завершившийся `veil_node_stop_timeout`.
В положительном случае все три сигнала также отправляются host после stop;
его обработчик должен получить каждый. Это проверка фактического kernel
состояния и вызова, без порога времени как критерия ускорения.

[Повторяемый runner](../../../test/native/run_embedded_host_signals.py) требует
отдельные SDK/CLI пути и ожидаемые SHA-256. Он использует одноразовую публичную
test identity, короткие private runtime directories и loopback listener.
Целевой конфиг явно задаёт `builtin_seed_policy=never`, `meeting_points=off`,
`bootstrap=false`. Никаких deployment-конфигов или настоящих личностей не нужно.
Дедлайны ограничивают ожидание readiness/stop, не оценивают производительность.

| Контроль | SDK до исправления | Финальный candidate |
|---|---|---|
| Config constructor: обработчики до/после stop | Все три заменены | Все три сохранены |
| Deferred constructor: обработчики до/после stop | Все три заменены | Все три сохранены |
| CLI SIGINT → штатный exit | Прошёл | Прошёл |
| CLI SIGTERM → штатный exit | Прошёл | Прошёл |
| CLI SIGHUP → подтверждённый reload → SIGTERM | Прошёл | Прошёл |

Автоматический runner на прежних bytes дал **два assertion failures и три
пройденных CLI-контроля**; это не setup/timeout failure. При изменённых
обработчиках probe не вызывает их повторно, поэтому baseline поле
`hostReceivedAfterStop=false` не является отдельным тестом доставки сигнала.
На финальной сборке все пять сценариев прошли, включая фактическую доставку
host signals. Первый candidate также прошёл, но финальный повтор выполнен
после сборки из чистого коммита с заново проверенными SHA.

Связанные Rust library suites: **1201 passed, 13 ignored** отдельно.
Вложенный subprocess case не прибавляется повторно к числу тестов.
Clippy обоих пакетов/all-targets прошёл с `-D warnings`. External mount
watchdog действовал при всех Cargo-командах, источник библиотеки зафиксирован
до её выбора. [Машиночитаемая сводка](summary.json).

## Повтор на настоящем Mac host

В прежнем скрытом QA-приложении заменена SDK, остальные App AOT и профиль
сохранены. Процесс действительно отобразил новую библиотеку, открыл прежнюю
тестовую личность и остановил native stack через lock. Теперь обычный SIGTERM
завершил host: **SIGKILL не понадобился**, четыре известных порта освободились,
подпись проверена. Это повтор наблюдавшегося случая, а не только модель.
Окна/ввод пользователя и основной xVeil не затрагивались.

Проверено на macOS ARM64. Работающая телефония, Android/Windows runtime и
полная multi-device matrix этим не квалифицируются. **NETCALL-01 остаётся
открытым**: это отдельный lifetime-дефект, не причина доказанной аудиопаузы.
Установка QA на Poco по-прежнему ожидает разрешения ОС/подтверждения владельца.
Нового push, релиза или обновления сидов нет.
