# Текущий медиадвижок Windows и пути компиляции — 2026-11-11

## Что проверено

Доступный стенд работает на Windows 11. Исходная жалоба относится к Windows 10;
она **не закрыта** результатами другого компьютера. Установленное приложение,
профили и контейнеры не заменялись. Работа выполнена отдельными CLI-пробами,
без сетевого звонка и проверки аватаров в GUI.

Windows x64 DLL собрана из текущих media-исходников на закреплённом WebRTC
`4ef980bc2c70834276c791e71e7834b8809f24ad`. SHA скачанного SDK-архива,
внутреннего webrtc.lib, профиль GN, target и все переданные файлы проверены.
Компилятор взят из SDK; Microsoft include/lib directories разрешены для
установленного x64 toolchain. Перед/после компиляции исходники и архив библиотеки
совпали. Без test hooks и CC trace. Все **107 функций**, запрашиваемых Dart,
присутствуют в PE export table; source/binary provenance проверена отдельно.

На настоящей DLL через C ABI проверены:

- чтение списка устройств без сохранения имён или ID в отчёте;
- отказ для отсутствующего, отрицательного, переполненного и частично числового ID;
- выбор системных input/output, mute и переключение шумоподавления;
- старт capture, unmute, выбор numeric input и возврат к default **при работающем
  захвате**, затем штатная остановка;
- создание video send stream, старт камеры и получение локальных кадров;
- сохранность COM apartment/context вызывающего потока после destroy.

Принимающая заглушка на границе транспорта подтвердила Opus RTP и VP8 RTP от
настоящего кодера. Никакой SDK fixture не установлен в приложение и не принят
его ABI gate: это отдельный процесс с явно тестовым transport DLL, принимающим
и считающим пакеты только в памяти. Приём собеседником, расшифрование, playout,
слышимость и network handover не проверены. PCM, кадры, имена устройств и адреса
не записывались. Итоговые результаты содержат только числа, коды и boolean.

Первая проба с настоящим установленным SDK использовала **несуществующий канал**
без узла. Input level и кадры камеры были доступны, но `audio_tx_pkts` оставался
нулём. Первоначальное требование положительного TX в этом fixture было ошибкой
драйвера, а не доказательством дефекта: ABI законно отвергает unknown channel.
Для проверки выхода кодера использована принимающая локальная заглушка.
Повторная проба после исправления путей также прошла; нулевая отправка в
несуществующий канал не переобъявлена исправлением продукта.

## Подтверждённый дефект сборки: локальный путь в бинарнике

В локальных Windows и macOS media binary оставался абсолютный путь к собственному
`pacing_controller.cc`: native `__FILE__` включал каталог учётной записи.
Артефакты были только в приватном стенде, в Git и публикацию не добавлялись.

Во все пять compiler wrappers добавлен `-ffile-prefix-map` (для clang-cl через
`/clang:`). Локальный корень заменяется на нейтральный `/src/veil-media`, имя
файла и номер строки сохраняются. Кодеки, выбор устройств, сетевые данные и
runtime-конфигурация не менялись. Source digest C++-дерева остался прежним;
изменились команды компиляции и SHA бинарников.

Регрессия использует **настоящие Python command generators из shell builders**,
компилирует маленькую TU и проверяет результат исполнения и байты бинарника.
До правки все четыре Unix-варианта дали assertion failure с исходным частным
путём; после правки четыре случая проходят. Это один unittest с четырьмя
subtests. Android/Linux/iOS здесь проверены на host-генерации команд, не как
полные платформенные engine builds.

Полностью пересобраны Windows x64 и macOS arm64. Ранее обнаруженные локальные
учётные записи в новых binary отсутствуют; имя исходного файла сохранено.
Windows повторно прошла capture/input-switch/camera/encoding probe, exports и
provenance. Это проверка конкретных корней стенда, не заявление об отсутствии
любых возможных приватных данных во всех сторонних библиотеках.

Дополнительно прошли 13 существующих Python guard-тестов provenance/staging;
CI теперь также исполняет новый compiler regression. Bash syntax checks чисты.
Сборочный SDK дополнен unsigned коммитом `8e317b53`.

macOS AOT app повторно собрана с движком без обнаруженного частного корня.
Исходные входы во время финального прохода не менялись, подпись проверена.
Direct/group init, noise controls, mute и destroy повторены уже над библиотеками
из app bundle. Это прежняя ad-hoc конфигурация без VPN и GUI, не публикация.

## Границы среды и продолжение

SDK setup требует PowerShell 7; установленный Windows PowerShell 5.1 неверно
обрабатывает outer array в ConvertFrom-Json. На стенде исправлена только копия
скрипта генерации compile metadata (убрана лишняя outer array), оригинал из
архива сохранён. Это workaround стенда, не изменение GN/profile или WebRTC ABI.
Первый setup-failure не считается прошедшей компиляцией.

Дальше остаются новый frontend и полный актуальный SDK в Windows-приложении,
реальная доставка медиа между клиентами и исходный Win10-сценарий. Новые
immutable pins и другие платформенные артефакты не опубликованы. Телефоны,
пользовательские приложения и production-реле не менялись. После проверки отсутствие процессов в обоих выделенных каталогах и временных
интерактивных задач подтверждено отдельным read-only запросом. Push/релиза нет.

## Полный Windows SDK и сборщик приложения

Следующий проход собрал полный `veilclient-ffi` из SDK `8e317b53`: locked/offline,
release, Windows x64, `node-embedded,production-seeds`, все 1560 переданных
исходных файлов сверены до и после. TLS и проверки ABI не отключались.

Первый приватный результат содержал ещё 243 ASCII и 60 UTF-16 вхождений имени
сборочной учётной записи, теперь в BoringSSL/AWS-LC. Rust remap не меняет
нативный `__FILE__`, а clang-cl игнорирует обычный `-ffile-prefix-map`.
Windows Cargo-шаги сборщика теперь выбирают target-scoped `clang-cl` и передают
remap через `/clang:`. Остальные платформы сохраняют GNU-форму; чужие compiler
options сохраняются. Путь с пробелом проверяется отдельно.

На реальном Windows-компиляторе обе регрессии дали assertion failure на прежнем
сборщике: выбор драйвера и narrow/wide `__FILE__`. После исправления все три
теста проходят без skip. Первоначальные ошибки подготовки fixture (нерабочий
ярлык Python и неполный набор входов) в этот red-run не включены. На Mac проходят
два переносимых теста, Windows-компиляция отдельно помечена skipped. Также
прошли 21 Flutter build-entrypoint test, 13 provenance/staging tests и четыре
Unix command-generator subcases из предыдущего раунда. CI запускает новую
проверку и непосредственно на Windows.

Повторная полная DLL собрана в отдельном target-каталоге: обнаруженные 303
вхождения отсутствуют, SHA проверен после скачивания. Исходники не менялись.
Это проверка известных частных корней, не универсальная гарантия приватности
всех сторонних строк. Оба результата остаются приватными стендовыми файлами;
в Git и публикацию они не добавлялись.

Для приложения подготовлены текущий frontend, новый SDK, текущий медиадвижок,
проверенная hidden-volume DLL и пересобранный VPN helper. Windows profile-AOT
собрана в отдельном каталоге, SHA исполняемого файла/AOT/native DLL проверены
перед запуском. Для установленного MSVC использованы существующие ATL headers
через явно отмеченную локальную CMake-правку. Нерабочие глобальные Rust-ярлыки
обойдены прямыми путями к уже установленному toolchain; глобальная установка
и настройки машины не менялись.

На Mac profile-AOT с двойным opt-in контрольного интерфейса прошла обычное
создание отдельной тестовой личности и подключилась к шести узлам настоящего
стека. Первоначальная попытка использовать release для QA была отклонена:
release закономерно исключает hook, эту защиту не ослабляли. Обычный release
bundle восстановлен из проверенной копии.

На Windows процесс и контрольный интерфейс стартовали, но на момент записи
автоматизация видела защитную шторку неактивного окна. Это не засчитано как
прохождение onboarding, запуск Windows-узла или звонок. Сквозной приём медиа,
слышимость, GUI аватаров и исходная Windows 10 жалоба остаются открытыми.
Пользовательские приложения/контейнеры, public pins и production-реле не менялись.

При проверке полного SDK найден отдельный отказ файловой публикации на границе
секундного Dart `stat` и миллисекундного native stamp. Он исправлен и проверен
отдельно: 137 Windows tests прошли, 3 явно пропущены; 147 Mac tests прошли без
пропусков. [Разбор](../windows-folder-metadata-2026-11-11/README.md).
Ранее собранный frontend ещё не содержит последнего Dart-исправления; итоговый
AOT нужно повторить. Запущенные GUI-процессы/SSH-forward остановлены, отсутствие
временных Windows interactive tasks проверено. Push/релиза нет.
