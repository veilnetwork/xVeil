# NETCALL-01: физические звонки после разрешения установки QA

**Установка отдельного QA APK на Poco прошла. NETCALL-01 остаётся открыт.**
Релейные звонки пережили смену сети, но для начального P2P воспроизведены
длительная потеря аудио и два завершения по liveness timeout. Исправление
причины этими проверками не заявляется. Производственный код не менялся.

## Стенд и происхождение

Продолжена [подготовка скрытого стенда](../netcall-background-stand-2026-11-18/README.md).
Телефон с SIM работал через Wi-Fi и мобильную сеть. Отдельное Android
приложение создало настоящую зашифрованную QA-личность; контакт согласован
в обе стороны. Mac принимал аудио без микрофона. Это проверка свежего native
приёма Android → Mac, **не двусторонней слышимости человеком**. Аудиозаписей нет.

Замороженная profile/AOT приложения происходит из `927d8e94` с ранее
объявленными QA overlays и Android default-Network observer. Android использует
точные native libraries опубликованной 0.13.102: все 11 SHA проверены внутри
установленного отдельного APK. Mac использует SDK `53fbbe34`, совместимую с
этой AOT, и прежние qualified storage/media. Подпись и native/AOT SHA сверены.
Позднейшие group/revoke-правки в этой замороженной AOT не квалифицируются.
Новых native сборок, тестов Rust/Flutter и обновления media pins не было.

Использованы три существующих testnet Core с obfs4/TCP. Production не менялся;
на testnet выполнялось только чтение состояния и журналов. Mac запускался
напрямую с `TMPDIR=/private/tmp/`, prohibited activation и невидимым окном:
активация, управление вводом и запрос разрешения микрофона не выполнялись.

Для отдельных случаев единственный Core обеспечивался **локальными ручными
банами остальных двух Core только в QA-клиентах**. В раздельном варианте
выбраны разные Core; в общем — один и тот же. Native sessions подтверждали
ограничение, прямое соединение собеседников не запрещалось. Это более строгая
политика, чем один настроенный bootstrap: эквивалентность такому обычному
конфигу не доказана. Результат нельзя без этой оговорки переносить на все сети.

## Результаты

Возраст последнего native audio RX измерялся примерно каждые полсекунды.
Это наблюдаемый возраст, а не точная длительность полной сетевой тишины.
Время «после default» отсчитывается от первого обнаружения нового default
Network опросом, не от точного системного callback. Ноль означает свежий
приём уже в первом таком срезе. Все значения относятся к этой серии; A/B нет.

| Исходный путь и доступные Core | Проверка | Результат |
|---|---|---|
| Relay, три Core | Два цикла cellular → Wi-Fi → cellular в одном звонке | Вызов сохранён; максимальный наблюдавшийся возраст RX 1,903 с |
| Relay, разные единственные Core | Один цикл cellular → Wi-Fi → cellular | Вызов сохранён; максимум 1,208 с |
| Relay, разные единственные Core | Два новых звонка немедленно после команды выключения Wi-Fi | Входящий на Mac через 171/440 мс от начала dial; первый свежий RX через 7,357/11,061 с |
| P2P, разные единственные Core | Два независимых Wi-Fi → cellular | Приём остановился; оба вызова завершились по liveness timeout. Последние наблюдавшиеся возрасты RX на Mac 24,011/23,212 с |
| P2P, три Core | Wi-Fi → cellular → Wi-Fi | Вызов сохранён; максимальный возраст RX 5,213/0,660 с |
| P2P, один общий Core | Wi-Fi → cellular → Wi-Fi | Вызов сохранён; максимальный возраст RX 21,658/1,354 с. Первый свежий RX после обнаружения cellular — через 23,620 с |

В двух новых relay-звонках dial ставился сразу после возврата команды
выключения Wi-Fi, без ожидания reconnect. Первый исходящий native payload
наблюдался через 7,085/5,112 с от dial. Во втором случае до первого Mac RX
после этого прошло ещё около 5,9 с. Поэтому всю начальную задержку нельзя
приписать ни доставке offer, ни только запуску захвата.

В остальных стартовых helper-измерениях stopwatch запускался после ответа
`call_place`: их короткое время ожидания ringing **не является полным
dial → ring** и не включено в таблицу как таковое.

Снимки native sessions в relay-контролях подтвердили замену link/nonce
телефона при смене сети, а не только изменение значка подключения. В случаях
с тремя Core P2P-контроль также подтвердил замену прямого peer link. Счётчик
сессий сам по себе не принимается за пригодность пути.

## Что локализовано в двух завершившихся вызовах

До отключения Wi-Fi оба клиента имели active P2P и свежий native RX на Mac.
После отключения создавались relay-кандидаты, но sealed echo не подтверждал
доставку: три ограниченные попытки завершались отказом квалификации. Старый
direct оставался выбранным. Mac в обоих захватах явно фиксировал
`liveness timeout`. В первом захвате свой timeout зафиксировал также телефон
(23/24 с тишины в журналах двух сторон); во втором телефон позднее получил
end от Mac. Команда операторского отбоя в этих захватах не отправлялась;
приложения оставались `ready`, `realStack=true`.
Это **событие при смене сети**, не атрибуция прежнего отложенного 25-с случая.

Во втором захвате дополнительно включена endpoint `rt_trace`. Первая
sampled sealed control-cell телефона размером 60 байт прослежена через
socket write, daemon read, handler и локальный relay enqueue. Это admission,
**не доставка собеседнику**. Ещё две первые sampled cells новых epochs видны
до handler без наблюдавшегося relay enqueue. По размеру/sequence нельзя
различить собственно path probe и source preparation: они используют тот же
размер и seal, а plaintext не записывался.
Без полной покадровой/межхоповой корреляции нельзя объявлять их потерянными
на конкретном участке: sampling остаётся разреженным, ответы и повторы
не обязаны попадать в него.

Независимые снимки показали исчезновение прямых sessions и admission у обоих
клиентов. На телефоне новый Core link сначала появился, затем тоже исчез.
Read-only журнал соответствующего Core подтверждает authenticated resume
с заменой точного предшественника, новый session open, локальные первые
отправки через independent ordered transport, затем keepalive timeout
примерно через 9 с жизни этой сессии. Телефон отдельно зафиксировал timeout
своего нового Core runner примерно через 12 с. Интервалы вычислены внутри
часов каждого хоста; точный межхостовый порядок не утверждается.

Контроль без смены сети полезен: в отдельном стабильном Wi-Fi P2P-звонке
тот же diagnostic relay-recovery прошёл с настоящим sealed echo, сохранил
вызов и свежий RX. Проверка запасного пути не является безусловно сломанной.
С другой стороны, длинная пауза с одним общим Core не позволяет объяснить
всё только разными Core. Root cause пока не доказан.

Следующий контролируемый захват должен различить новый canonical transport
и его independent source после resume: обе стороны TX/RX, generation и
пакеты на интерфейсе testnet Core. Отдельно нужен однопировый конфиг без
ручных банов. Таймаут liveness, требования sealed echo и правила допуска
не ослаблялись; слепое переключение на неподтверждённый путь не добавлялось.

## Ошибки обвязки и завершение

В первом P2P-захвате helper назвал исчезновение вызова «изменением call ID».
Сохранённая исходная строка показывает null на Mac и прежний active call на
телефоне, а не новый вызов. Классификация helper исправлена; повтор отдельно
завершился именно на terminal-state guard. Обратный переход в обоих этих
захватах **не выполнялся**, это не две успешно законченные пары направлений.
Первый `adb exec-out` для duplex admin не передавал stdin; заменён на
`shell -T`. Первая cleanup-попытка получила 405 из-за GET вместо POST lock;
исправленная повторная очистка прошла. Эти ошибки не считаются сбоями продукта.

QA-вызовы завершены, оба приложения locked и native stack остановлен.
Android QA force-stopped, его службы отсутствуют, выданные только ему
разрешения микрофона/уведомлений отозваны. Пакет оставлен остановленным с
фиктивным профилем для следующей проверки. Основной APK телефона побайтно
не изменился; исходные Wi-Fi/mobile-data settings восстановлены.
Добавленные QA-баны сняты с точной сверкой исходного набора, per-contact P2P
вернулся к deny, trace выключен с обеих сторон. Mac завершился обычным
SIGTERM; его оставшиеся TCP listeners и созданный ADB forward освобождены.
Сырые журналы, адреса, пароли, ключи и device/call IDs сохранены только
в private workspace. [Анонимная машинная сводка](summary.json).

Push и релиза нет. Установка больше не блокирует физическую проверку;
задержка начала аудио и восстановление P2P при смене сети остаются открытыми.
