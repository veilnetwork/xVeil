# Рост Flutter test cache: очистка и устранение причины

## Подтверждение и очистка

Во время длинной кампании в `build/test_cache` накопилось примерно 164 ГиБ.
Большинство файлов — примерно 106-МиБ tracked Dart kernels. На внутреннем
диске оставалось около 3,4 ГиБ. Ответственность за накопление — тестовые
запуски кампании; это не пользовательские контейнеры.

Удалён **1511** старый сгенерированный kernel, примерно **156,16 ГиБ**
allocated blocks. Свободное место после очистки — **158,83 ГиБ**. Очистка
ограничена обычными принадлежащими пользователю файлами с именами
`32-hex.cache.dill.track.dill` в конкретном build cache, без обхода symlink.
Сохранены 64 самых новых, все моложе часа и открытые файлы; перед unlink
повторно проверены inode/mtime. Manifest остаётся частным.

Исходники, `.git`, пользовательские данные/контейнеры, артефакты приложения,
native библиотеки, общий исследовательский кеш и внешний Cargo target не
удалялись. GC не запускался. Глобальные настройки Flutter не менялись.

## Причина и исправление

Каждый ProcessDevice выбирает свободный loopback-порт. Раньше он передавал
его в `--dart-define=XVEIL_DEBUG_HOOK_PORT=...`: новый порт менял конфигурацию
компиляции и создавал отдельный большой kernel cache для одинакового worker.

Порт теперь передаётся worker через process environment и конструктор
`DebugSoakHookHost`. Compile-time opt-in `XVEIL_DEBUG_HOOK=true` остаётся
общим для всех worker. У обычного приложения override отсутствует, поэтому
сохраняется выбор порта из define/платформенного default. Override сам по
себе не включает hook: release остаётся выключенным, profile требует прежних
двух opt-in. Listener остаётся exclusive loopback с обязательным per-run key.

Это устраняет отдельную компиляционную конфигурацию на каждый случайный порт,
а не обещает фиксированный размер всего Flutter cache при любых новых тестах.

## Native-проверка

Новый отдельный gated case запускается один, без других компилирующихся в том
же checkout тестов. Он поднимает три независимых worker через реальные
CLI/FFI/HVS, проверяет `realStack`, три разных API-порта и HTTP 401 без ключа
на каждом. Старый порт первого worker временно резервируется после stop,
чтобы следующий старт гарантированно получил другой порт.

**Три worker создали один новый kernel cache entry.** Перезапуск на другом
порту создал **ноль дополнительных entries**; keyed API снова доступен.
Это проверка фактических файлов cache, а не равенства строк с аргументами.
Пути/ключи/порты не экспортируются. Заданный gate задерживает worker только
до наблюдения выбранных native библиотек в OS mappings трёх процессов;
в обычном самостоятельном запуске внешний наблюдатель не требуется.

Native SHA и 1525 frozen inputs проверены, cleanup: **18 PID / 14 портов**,
своих процессов/listeners нет, runtime удалён. Все три worker и перезапуск
прошли; это отдельный native case, не skipped-тест. Hook gate/params/purge
также прошли 26 проверок. Итоговая общая серия: **233 passed / 0 skipped**,
включая 16 native HVS; analyzer чист. Cache-reuse native case учтён отдельно.

Очистка пришлась между фазами другого стенда на 10 000 сообщений. Его проверки
полноты/порядка/сохранности остаются действительными, но **времена той серии
не используются как сопоставимое A/B/A**: изменились свободное место и I/O
условия. Их нельзя объявлять доказанным ускорением алгоритма истории.

Телефон и production не затронуты. Commit локальный unsigned, push/релиза нет.
[summary.json](summary.json) содержит только агрегаты.
