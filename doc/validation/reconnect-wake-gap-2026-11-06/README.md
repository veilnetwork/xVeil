# Переподключение: потерянное уведомление перед backoff

**Подтверждён и исправлен локальный дефект connector:** смена сети или
свидетельство восстановления исходящей связи могли попасть между отказом
попытки подключения и созданием подписки retry-wait. Connector оставался
ждать обычный backoff. Это не доказанная причина потери первой TCP-посылки
на мобильном пути и не закрытие NETCALL-01 целиком.

## Воспроизведение

Новый тест проходит через настоящий `spawn_outbound_peers`, `NodeServices`
и транспортный реестр. Dial-only транспорт возвращает контролируемый
`io::Error`. Его второе форматирование происходит уже после выбора Err
в connector, до постановки ожидания backoff. В этой точке fixture посылает
`notify_waiters`: о смене сети либо о connectivity gain. Производственных
test hooks нет.

На исходном SDK `29ee0700` оба положительных сценария assertion-red:
второй dial не начинается. Контроли без события и с действующим баном
проходят. Это **2 failed / 2 passed**, не ошибка компиляции и не нулевая
выборка. Свойство проверяется по oneshot начала следующего dial на
current-thread executor, без порога измеренной задержки. Десятисекундный
watchdog ограничивает только зависание fixture; backoff задан 60 с.

## Исправление

Подписки создаются в начале каждого прохода connector, до проверок
состояния peer и попытки подключения. Ожидания занимают эти уже созданные
futures, поэтому `notify_waiters` в промежутке не теряется. Та же подписка
на смену сети используется для отмены незавершённого dial.

- Connectivity gain по-прежнему будит только retry-wait и **не отменяет
  чужой выполняющийся dial**.
- После собственного успешного подключения подписка gain создаётся
  заново: собственный сигнал не снимает защитную паузу при немедленном
  закрытии сессии соседом. Подписка смены сети при этом сохраняется.
- Бан, проверка существующей сессии, directional dedup, правила допуска,
  backoff и wire не ослаблены. Пробуждение возвращает к обычным проверкам.

## Проверка края успешного подключения

Отдельный контроль выполняет настоящий TCP/OVL1 handshake с собственной
тестовой identity и немедленно закрывает peer. Следующий dial наблюдается
на границе `Transport::connect`; сама пауза не сокращается ради теста.
С правкой контроль проходит. При намеренном удалении только повторной
подписки gain он assertion-red: собственный успех отменяет паузу и
немедленно запускает следующий dial. После проверки код восстановлен.

Первый вариант этого дополнительного теста ошибочно ждал очистки
`live_sessions`: её guard выполняется **после** паузы. Этот запуск не
является доказательством дефекта. Финальный oracle наблюдает снятие
TX-регистрации **до** паузы, затем даёт connector завершить текущий poll;
мутационная проверка подтверждает чувствительность именно этого oracle.
Ранний compile-only отказ из-за неверного импорта fixture также не
засчитывается как красная регрессия.

## Границы и следующий шаг

SDK-коммит: `aa51cc13`. Финальный runtime: **810 unit + 8 integration passed**,
11 unit и 2 doc ignored. FFI: **397 passed / 11 ignored**, отдельный дочерний
тест 1 passed, 5 doc ignored. Дочерний запуск не прибавляется к числу
различных основных FFI-тестов. Formatting и `diff --check` чистые.

После локальных тестов пользователь вернул Poco. Последующий
[физический прогон новой SDK](../reconnect-wake-physical-2026-11-06/README.md)
**снова воспроизвёл обрыв внутри разговора**. Доказанный локальный дефект
подписки исправлен, но не объясняет весь NETCALL-01. Новый звонок после
Wi-Fi off прошёл, пять свежих RX-срезов собрались лишь через 18,397 с.
Предыдущий двухрелейный прогон использовал `29ee0700` и не является A/B.

Следующий физический контроль — смена Wi-Fi/cellular во время разговора
и новый звонок сразу после переключения, с раздельными показателями
подключения, native RX и причины завершения. Отдельно остаётся наблюдавшееся
ожидание первой TCP-посылки без ACK: сохранение уведомления не доказывает
исправление потери байтов в сетевом пути.

Сводные результаты: [summary.json](summary.json). Приватные исходные логи
остаются вне репозитория. Локальные регрессии не запускали приложения и
реле; их последующая физическая проверка и очистка описаны отдельно.
Push и релиз не выполнялись.
