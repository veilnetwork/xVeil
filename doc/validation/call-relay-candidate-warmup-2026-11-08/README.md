# NETCALL-01: новые короткие проверки одного relay-кандидата

## Наблюдение и изменение

В [предыдущей физической серии](../call-handover-current-aot-2026-11-08/README.md)
Poco закрывал relay-кандидата после одной неподтверждённой проверки. Старый
direct sender сохранялся до следующего retry/local rebuild, и приём на Mac
останавливался до 11,844 с. Три control cells из 600-мс наблюдения дошли до
Mac и были расшифрованы; первая — примерно за 185 мс, следующие позже срока.
На обратном пути есть подходящие по размеру/времени поздние control cells,
но без plaintext-token witness они **не объявляются точно соответствующими
echo**. Причина отказа кандидата полностью не атрибутирована.

Теперь переход P2P → relay сохраняет уже открытый кандидат максимум для
трёх последовательных коротких наблюдений вместо немедленного закрытия.
Каждый вызов штатного SDK начинает **новую** challenge с новым nonce и своим
прежним 600-мс budget. Старый просроченный ответ не становится успешной
проверкой следующей попытки. Максимум наблюдений — 1,8 с вместо 0,6 с;
подготовка/open до них не менялись. Это явный обмен: до 1,2 с дополнительного
ожидания неработающего кандидата за возможность квалифицировать уже
прогретый путь до следующего service retry. P2P upgrade остаётся с одной
проверкой.

После каждого await проверяются тот же call, peer/device, engine, epoch,
исходный channel и transport. Hangup/замена call не запускают следующую
попытку и не позволяют commit даже успешного позднего результата. Native
proof, consent, deadline, replay и endpoint binding не менялись; при полном
отказе кандидат закрывается прежним finally, старый engine не заменяется.
Liveness timeout и пятисекундный service retry не менялись.

## Проверки

Одна прежняя проверка вынесена в используемую production-функцию без изменения
поведения, затем выполнен red-run: три assertion failures (ранний выход,
пропуск второго успеха, отсутствие фиксированного лимита из трёх). Первый
запуск с ошибкой импорта не засчитан как red. После ограниченного цикла
**303 related tests passed, 0 skipped**, analyzer трёх изменённых файлов чист.
Gate-тест удерживает каждую попытку отдельным completer; время не является
oracle. Покрыты отказ всех попыток, успех первой/второй/третьей, отсутствие
повтора P2P upgrade, закрытие owner во время обоих исходов и native exception.

## Физическая квалификация `f19b9b7b`

Собраны полные profile AOT обоих клиентов. Runtime revision/digest/mode,
реальный canonical Mac App.framework/FFI mapping и SHA установленного APK
проверены до звонка. Frozen native overlays/private QA seeds сверены по байтам.
Оба последовательных звонка начали с фактического двустороннего P2P-аудио
на Wi-Fi, прошли Cellular 120 с и возврат Wi-Fi 45 с. На Cellular хост не
опрашивал телефон: состояния и native logcat писались локально на Poco.

| Звонок | Native epoch (Mac / Poco) | Max observed audio RX age на Cellular | При возврате Wi-Fi |
|---|---|---|---|
| Первый | 1 / 1, без пересоздания | 4676 / 4681 мс | 6332 / 4172 мс |
| Второй | 3 / 3, без пересоздания | 11449 / 6291 мс | 4231 / 4016 мс |

Оба звонка сохранились до штатного окончания скрипта. На обоих endpoints
нет снимков с пропавшими native counters во время этих интервалов. Слышимость
человеком не проверялась; это показатели цифрового приёма, не SPL и не MOS.

**Дополнительные попытки действительно выполнены**, не только скомпилированы:
во втором звонке на Mac, относительно завершения команды выключения Wi-Fi:

1. Observation 1 началась на +5,030 с, не подтвердила путь.
2. Observation 2 — на +5,641 с, также не подтвердила.
3. Observation 3 — на +6,249 с; отдельный новый native challenge получил
   `matches=true`, `Pending` → qualified, RTT **167324 мкс** при прежнем
   budget 600000 мкс. В +6,428 с — `route handover relay kept engine`.

Native trace содержит три отдельных begin; nonce/token в публичный отчёт
не включены. Это доказывает сохранение одного кандидата до успешной третьей
свежей проверки. Старый однократный код на этом исходе первой попытки вернул
бы false и закрыл его. Значение RTT взято из внутренних часов одной native
попытки; это не сравнение часов телефона с сервером.

**NETCALL-01 остаётся открытым.** Во втором звонке после relay commit приём
возобновился и счётчик аудио вырос; максимум 11449 мс возник лишь около
+26,6 с после switch, уже в следующем периоде отсутствия входящего аудио.
Он не приписан ожиданию первых трёх проверок. Общее устранение пауз, причина
первого liveness timeout прежней серии и ускорение относительно старой сборки
не заявляются: это не A/B, маршруты/кэши различаются. Следующий участок —
остановка устойчивого RTP после успешной квалификации и первоначального приёма.

## Завершение и воспроизводимость

SDK остались frozen: Android `bbcd967a`, Mac `c8f4929b`, два временных Core
`e974cebe` (разница диагностическая). Исходники staged отдельно, Flutter
собирался с `TMPDIR=/private/tmp/`, Rust builds отключены; внешний Cargo
target не использовался. Compile identities и SHA сохранены приватно.

Первое скачивание уже собранного архива Core B не завершилось успешно.
Повторно скачан **тот же** архив, сверены размер, SHA и все члены; Core/apps
не перезапускались. После этого завершены все проверки cleanup: собственные
процессы/collectors/ports/runtime и оба Core удалены; production PID/binary/
config независимо неизменны. QA APK, основной APK/старый QA-контейнер,
permissions, P2P choice, Wi-Fi/mobile settings и debug properties восстановлены
со сверкой хешей/состояний. Ошибка первого cleanup не затёрта нулевым exit;
отдельный resume proof подтверждает окончательное восстановление.

SDK/Rust не менялись и не пересобирались. Push/релиза нет.
