# История без временных ограничений: убрать бесполезный обход

## Подтверждённая лишняя работа

Источник каждой страницы строил свежую видимую историю. Даже при выключенных
TTL, retention и hide-after-read он читал timestamp каждой строки и часы,
только чтобы получить `true` из фильтра. На архиве 100000 это повторялось
при каждой странице, отдельно от нужной проверки wire-порядка и выбора cursor.

Теперь результат **свежего** чтения политики различает отсутствие временных
ограничений. Только тогда пропускается per-row visibility predicate. Список
по-прежнему копируется перед сортировкой, fold/редакции читаются заново;
межзапросного кэша истории или авторизации нет. При активном TTL, retention
или положительном read watermark действует прежний фильтр с текущими часами.
Read-clock lookup при включённом hide-after-read также сохранён.

Membership/revoke, consent, binding/erasure, подготовка по 64 строки,
durable publication и checkpoint не менялись. Лимиты страницы остаются
256 строк / 128 КиБ / 64 части. Sibling mailbox не включён.

## Проверки

Два assertion-red на parent, без таймингового порога, через настоящий source
handler и instrumented timestamps:

| Fixture на 100000 | Parent timestamp reads | Candidate bound |
|---|---:|---:|
| Уже упорядоченный архив, последняя страница | 200272 | ≤101000 |
| Новая строка перед архивом, слияние двух runs | 400274 | ≤301000 |

В счёт входят вся source-обработка, сортировка/слияние, binary cursor lookup,
encode и metadata. Обе проверки также сравнивают точные ID и позиции 128 строк
ответа, отсутствие next и ошибок. Это не helper-only microbenchmark.

Три новых сценария запрашивают страницу **без ограничений → с ограничением →
снова без ограничений**. Отдельно проверены TTL, retention и read watermark:
средний ответ пуст, крайние содержат обе ожидаемые строки. Таким образом,
первый быстрый ответ не закрепляет старую политику для следующих запросов.

**331 related checks passed / 0 skipped**, включая обычные/fallback reads,
native expiry, свежий revoke/block/TTL перед подготовленной публикацией,
byte-boundary, sparse-prefix, edit, replay, restart и durable cursor failure.
Analyzer двух изменённых Dart-файлов чист. Первоначальная новая fixture имела
ошибку имени метода записи setting; compile failure сохранён отдельно, имя
исправлено на существующий `putSetting`, focused и полный набор выполнены
повторно. Этот отказ не считался product regression или успешной проверкой.

## Native A/B/A на 100000

Parent `9ce27cdd` → candidate → parent. Четыре Mac/JIT процесса, три
изолированных Core, настоящий FFI/ratchet/HVS. Два источника одной личности
отдают один архив третьему устройству; первые полные authenticated ответы
обоих источников получены до apply release. Seed вне измеряемого окна,
compact progress каждые 5 с; CPU sampling/work trace/timeline выключены.
Append order источников прежний: одна новая строка перед 100000 архивными.

**Устойчивое ускорение всей догрузки не доказано.** Разница основного времени
91–486 мс мала относительно разрешения конечного наблюдения; passive witness
лучше на 790–1053 мс, но это одна A/B/A серия. Медиана query-at-source → full
reply у A: 94,269 → 88,335 → 93,183 мс, у E: 92,147 → 84,769 → 90,790 мс.
Это полные участки с сетью/очередями, не exclusive CPU. Обратный участок
full reply → next query остаётся около 239–248 мс на 256 строк. Медианы
перекрывающихся стадий нельзя складывать в wall time. Разницу RPC total,
включающего фоновую работу, одному убранному predicate не приписываем.

Во всех трёх фазах **100000 архивных + 1 прежняя строка** совпали по ID, body,
delivered, canonical positions и порядку, без пропусков/дублей/лишних строк.
Оба cursor завершены. Отдельное холодное открытие до сети при offline всех
источников сохранило полный набор. Wire capture/census не обрезаны.

## Происхождение, уборка и остаток

Во всех фазах **1532 frozen inputs**, один production variant, 1531 общий
input; native artifacts и реальные worker mappings сверены. Candidate
восстановлен с проверкой frozen inputs. Rust не собирался. Cleanup проверил
**39/37/37 PIDs** и **53/57/64 порта**; owned процессов/слушателей нет,
synthetic runtime удалён. Cache **92→92** во всех фазах, новых kernel entries
0; около **9,5 ГиБ**, свободно около **148 ГиБ**. Raw evidence приватен,
ID, адреса и пользовательские пути в публичную сводку не включены.

Latency остаётся активной: около 149 с на 100000 сообщений в этом локальном
JIT-сценарии. Следующий участок — receiver apply/storage/checkpoint и ожидания
между страницами; этот результат не доказывает их конкретную причину.
Физическая/AOT квалификация, NETCALL-01 и остальные пробелы multi-device matrix
не закрыты. Push/релиза нет.
