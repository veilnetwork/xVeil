# Подтверждение реакции после записи — 24 октября 2026

Новая находка при продолжении проверки пунктов 19 и 62/63 multi-device
матрицы. Предыдущая атомарная публикация реакции и её ordering floor защищала
само содержимое `rx2`, но общий inbound gate отправлял ACK и запоминал frame ID
**до** этой записи. Отказ контейнера оставлял пустую реакцию у получателя,
удалённый durable frame у отправителя и занятый dedup slot для повтора.

## Воспроизведение и исправление

На базовом `71d9c43f` три fault-теста получили ACK до завершения/при отказе
записи. В отдельном тесте с двумя настоящими `MessagingService` очередь
отправителя уже оказалась пуста, хотя получатель отказал записи. Это тесты
прикладного протокола поверх управляемого транспорта и настоящего Dart
storage adapter с `FakeHvContainer`, а не физического диска или native сети.

`WireKind.reaction` теперь проходит существующий gate отложенного подтверждения.
Frame ID запоминается и ACK отправляется после публикации значения и версии
реакции и вызова существующего sibling callback. При отказе записи кадр
остаётся пригодным для повтора. Уже применённый повтор получает ACK без новой
публикации и повторного callback. Авторизация принятого контакта остаётся
перед ACK/dedup; claimed-копия не занимает слот подлинной доставки.

## Проверки

Новые шесть тестов проверяют:

1. Пока запись удерживается хранилищем, нет ACK и sibling callback.
2. Отказ до записи, повтор того же ID, успешное применение и следующий duplicate.
3. Отказ после завершённой записи удаления реакции, закрытие и новое открытие
   хранилища, повтор; старая реакция не преодолевает сохранённый floor.
4. Потерю ACK после успешной публикации: повторный ACK без повторного эффекта.
5. Claimed-доставку перед подлинной копией с тем же ID.
6. Действительную durable очередь отправителя: отказ получателя сохраняет
   кадр, `flushOutbox` после восстановления записи доставляет его и получает ACK.

Выбранные существующие проверки реакций, UI, outbox, re-drive, provenance и
отложенного ACK disappearing setting записаны в `summary.json`. Исходный
обработчик отдельно возвращался для отрицательного контроля sender-outbox
теста; исходник исправления восстановлен после выполнения.

## Границы

Это не полная квалификация crash consistency: SIGKILL на каждой границе
receive/decrypt/native commit/ACK, ratchet recovery, edits/deletes/clear и
синхронизация реакции между отдельными native процессами здесь не выполнялись.
Synchronous callback не является подтверждением завершения фоновой записи
device journal. Матрица из 63 пунктов остаётся открытой.

Ни mailbox-политика, ни native ABI, ни SDK/HV не менялись. Телефон, микрофон,
установленное приложение и реле не использовались. Flutter запущен с
`TMPDIR=/private/tmp/`; тестовые services/storage закрываются teardown.
В git только synthetic tests, агрегаты и SHA-256 исходников. Сырые журналы
остались в приватном cache; untracked отчёт 17 октября не изменялся.
