# Профиль получателя на 100000 сообщений — 2026-11-10

Диагностический прогон текущего кода `d3f7dd49` после объединения metadata RPC.
Production-код в этом раунде не менялся. Рабочая нагрузка — **100000 архивных
сообщений**, не 10000; одна ранее существовавшая строка проверяется отдельно.
Размер задаётся runtime-переменной `XVEIL_E2E_HISTORY_OVERLAP_ROWS=100000`;
обычный короткий smoke по умолчанию не превращён в большой benchmark.

## Корректность и условия

Тот же local Mac/JIT native стенд: три устройства одной личности, два источника
истории, отдельный собеседник, настоящие FFI/ratchet/hidden-volume и три Core.
Оба authenticated ответа получены до снятия apply barrier. **100001 точная
строка**: ID/body/delivered/canonical/order, без пропусков и дублей; оба cursor
завершены. После остановки всех источников и cold reopen получателя сохранность
проверена до включения сети. Не используется равенство двух пустых выборок.

200002 history callbacks, 782 message commits, 784 cursor commits, 393 allocator
commits. Receiver census и wire capture не обрезаны. 1537 frozen source inputs
и фактически загруженные native libraries проверены; во время прогона они не
менялись. Sibling mailbox не включался, durable ACK/ratchet guards не менялись.

Время apply release → финальная проверка **144199 мс при включённом CPU sampler**.
Это отдельная диагностика, **не A/B и не доказательство замедления или ускорения**
относительно прежних примерно 134 с без профиля. Здесь нет квалификации Android,
AOT, удалённой сети или батареи. Во время части записи выполнялся read-only
запрос графа кода; он не используется как контрольный performance run.

## Что действительно видно

| Наблюдение | Количество |
|---|---:|
| Worker RPC | 128171 |
| Own-device read contexts | 227971 |
| Header loads / message segment batch loads | 24165 / 24165 |
| `GroupService._readOwnDeviceAddresses`, inclusive samples | 4809 |
| `GroupService.load`, inclusive samples | 3323 |
| `GroupService._deviceSyncStateOfBundle`, inclusive samples | 2523 |
| `GroupService._deviceAnnouncementStateOfBundle`, inclusive samples | 2154 |
| `GroupService._messagesOfBundle`, inclusive samples | 2130 |
| `__fcntl`, exclusive physical samples | 26881 |

Один наблюдаемый native stack связывает `__fcntl` с `File.sync_all` → `Tx.commit`
→ `SpaceHandle.commit` → `HvSpace.commit` → `HvKvLogStore.commit`. Это свидетель
синхронной записи контейнера, а не самостоятельное доказательство, что её можно
удалить или что она объясняет всю задержку. Inclusive counts перекрываются;
они не суммируются в проценты wall time. Async ancestry также не означает
непрерывную загрузку каждого родительского метода.

Следующий кандидат для разбора — свежий read path состава собственных устройств:
он всё ещё проходит через загрузку bundle и обработку его сообщений. Профиль
показывает работу этого пути, но **не доказывает**, что проверки подписи/состава
лишние. Любая оптимизация требует отдельного red/cost guard и native A/B/A;
кеш авторизации или ослабление revoke/erase/lifecycle барьеров не предлагаются.
Профиль не даёт полного wall-time разложения оставшихся 134 с. Latency открыт.

## Границы сбора и очистка

23 перекрывающихся chunk, 96922 физических sample keys; после дедупликации
13441 повторов и исключения 78 конфликтующих ключей остаётся **96844** samples.
Все имеют thread ID, вне запрошенных окон — 0; усечённых stack — 3088.
Активное окно 149484,284 мс, непрерывно покрыто 147074,495 мс; начало покрыто,
последние 2409,789 мс не покрыты. 12 isolate-ответов недоступны. Один terminal
RPC error при завершении bound endpoint; capture не достиг byte/disk cap.
Это неполный профиль, границы не скрыты. Никакого утверждения «всё CPU-время
измерено» нет. Повторный анализ с архивированных исходников дал тот же summary.

Cleanup проверил 49 принадлежащих стенду PID и 84 порта: своих процессов и
listeners не осталось, runtime roots удалены. Кеш остался около 9,5 ГиБ,
свободно около 146 ГиБ. Новые случайные Dart defines не создавались.
Двенадцать собственных raw CPU JSON сжаты без потерь: 406,24 → 17,99 МиБ,
SHA-256 распакованных байтов проверен до удаления оригиналов. Сырые профили,
VM URI, PID, служебные адреса и пути остаются вне Git; summary содержит только
агрегаты и имена функций. Общий private evidence после сжатия около 93 МиБ.

Нет push/релиза. NETCALL и оставшаяся multi-device матрица этим прогоном
не квалифицированы. Продолжение работы — отдельная проверяемая оптимизация
read path, затем повтор сопоставимых прогонов на 100000.
