# Для адреса устройства не требуется проверять последующий чат

База — `180ede6a`, [CPU-профиль предыдущего раунда](../history-request-wake-2026-11-07/README.md).
В 2541 из 5444 main-isolate samples присутствовал `_readOwnDeviceAddresses`,
в 2018 — `verifyGroupMessage`. Это inclusive frames, не складываемые доли
времени. Routing получал полный device-sync fold и проверял сообщения чатов,
появившиеся уже после последнего объявления адреса.

## Граница оптимизации

Новый частный view используется только двумя ветками `addressableOwnDevices`,
которым нужны `identityDoc`. Public device-sync state/records, ingestion,
admission priming и другие folds сохраняют полный журнал.

Оптимизация применяется к sovereign device group с V1 cleartext messages,
32-байтовыми author keys и только membership control ops. Unverified bodies определяют **объём проверки**,
не адрес и не право: для каждой пары `(author, canonical writer scope)` берётся
максимальный seq среди всех распознаваемых `identityDoc`, включая будущие и
непригодные кандидаты. Используется тот же scope, что у обычного fork/chain
fold; ключи двух устройств одной личности не смешиваются.

Для нужного scope рассматривается prefix до последнего кандидата включительно:

- Если хотя бы одна строка имеет `prevHash`, сохраняется **весь** этот prefix.
- Если все строки unchained, сохраняются объявления и **все варианты** каждого
  потенциально конфликтующего seq. Уникальные строки другого вида не могут
  быть предшественниками или образовать fork и не влияют на адрес.

К выбранным строкам применяется прежний полный verifier/fork/chain/retention/
ACL и clock fold. Raw duplicate сам по себе не объявляется fork: одна из двух
подписей может быть недействительна. Исходные control rows, cuts, receipts и
остальной контекст bundle сохранены. Заголовок читается заново для каждого
нового lookup; completed view/authorization не кэшируется. Bytes в хранилище
и public device-sync state/records не меняются.

Почему допустима граница: развилка в scoped per-author/writer chain убирает
свой seq и последующий suffix, но не более раннее объявление. Развилки **до
или на** последнем кандидате сохраняются. В linked chain отсутствие либо
недействительность предшественника, неверный anchor и downgrade к пустому
prevHash по-прежнему скрывают объявление. В полностью unchained prefix нет
таких зависимостей; его unique non-announcement slots не влияют на результат.
Sovereign producer действительно пишет unchained LWW rows, чтобы superseded
записи можно было компактировать (`_postMessage` и присвоение prevHash).

Legacy, encrypted/другие message versions, некорректная длина ключа и иные
control ops используют полный прежний путь. Длинный некорректный ключ не
кодируется в scope раньше прежнего verifier. Space/lifecycle scopes этой
оптимизацией не обрабатываются.

## Регрессионные проверки

33 новых сценария используют реальный GroupService, валидный sovereign
control log и fake storage/signer. Raw message rows намеренно записываются
в fixture без snapshot sanitation: чтение должно само увидеть forks, gaps и
непригодные подписи.

- Work census: две свежие выборки читают заголовок дважды и каждая проверяет
  **2** необходимые строки вместо **66**, сохраняя bytes журнала.
  Для unchained журнала с поздним объявлением и подозрительным slot —
  **3 из 66** (объявление и оба варианта slot), для двух независимых writer
  keys одного автора — **1 из 129**.
- Разные авторы имеют независимые ceilings; посторонний автор с правильной
  формой подписи не получает membership.
- Полный fold служит oracle для gap, bad predecessor, forks до/на/после
  объявления, нового объявления, плохой подписи, будущего события,
  retention anchor, неверного anchor, отсутствия объявления и strict downgrade.
  Проверяются и linked, и unchained формы с их прежней семантикой.
- После каждого completed lookup изменение verifier повторно проверяется
  новым вызовом; прежний адрес не превращается в сохранённый grant.
- Legacy/encrypted/oversized-key controls подтверждают прежний полный путь.

На прежнем production source **4 assertion-red и 29 green controls**.
Девять независимых mutations проверяют chain/downgrade, наличие fork evidence,
проверку подписей fork, общий verifier, legacy/encrypted fallback, ceilings и
раздельные writer scopes, key-shape fallback: десять assertion-red, без timeout.
Candidate после каждой восстановлен побайтно. **651 related tests passed / 11 skipped**,
analyzer двух файлов чистый; skipped не считаются пройденными.

При добавлении новых проверок блок сначала попал не в ту часть большого
файла и вызвал ошибку компиляции. Размещение исправлено; эта подготовительная
ошибка не засчитана как red/control доказательство.

## Промежуточный вариант

Первый вариант только отрезал suffix после объявления. Он прошёл native
crash qualification: 687 записей до сети и все 2000 после сходимости. Но
между страницами осталось median 333,223 мс; после `start(A)` — 25,695 с
против прежних 25,683 с. Общий выигрыш не заявлен. У новой личности объявление
стоит после старых mirrors, поэтому большая часть prefix оставалась. Этот
вариант сохранён в private evidence, но не принят как окончательное решение.
Уточнение unchained scopes описано выше.

## Native qualification: A₁ / B₁ / A₂ / B₂

Один Mac, три process hosts A/B/C с настоящими SDK/ratchet/контейнерами,
три Core в loopback testnet. B получает часть истории из 2000 сообщений,
принудительно завершается SIGKILL; A/C выключаются, B запускается без них;
затем возвращается только A. После полной сходимости ещё один cold boot B
без источников проверяет сохранённое содержимое, delivered и canonical
positions. Во всех фазах включено одинаковое CPU profiling.

| Фаза | Частично принято до SIGKILL / после запуска до сети | После возврата `start(A)` | Median last-part → next-query | Inclusive `verifyGroupMessage` / main samples |
|---|---:|---:|---:|---:|
| A₁, прежний код | 751 / 751 | 25,683 с | 349,677 мс | 2018 / 5444 |
| B₁, до key-shape guard | 751 / 751 | 20,476 с | 304,025 мс | 110 / 3411 |
| A₂, прежний код | 623 / 623 | 25,687 с | 329,709 мс | 1841 / 5284 |
| B₂, финальный код | 643 / 643 | 25,681 с | 260,387 мс | 140 / 3838 |

Финальная строка квалифицирует именно окончательные bytes с key-shape guard;
результат B₁ ему не приписывается. Во всех четырёх фазах **2000/2000** ID,
тел, статусов и итогового порядка совпали; completed-history retries 0.
Частичная и полная история пережили перезапуски без источников. Промежуточные
порядок/позиции ещё сходились — итог проверен отдельно.

**Общее ускорение не доказано:** B₂ по полному времени равен A₁/A₂. Между
фазами различаются объём уже принятой истории и обратная работа: B₂ выполнил
1736 historyApply и 458 historyEncode callbacks против 1343/272 в A₁.
Это не одинаковая нагрузка для причинного вывода о полном времени. CPU samples
inclusive, окна разной длины, счётчики не являются exclusive wall time.
Прямая work-census проверка и профили подтверждают устранение лишних crypto
проверок; холодные запросы, обратная синхронизация и оставшееся ожидание
между страницами требуют дальнейшей декомпозиции.

[Анонимные агрегаты](summary.json) содержат все фазы и исключения wire-выборки.
Во время каждой серии заморожены 1509 source inputs, native inputs одинаковы,
реальные dylib mappings подтверждены после аварийного перезапуска. Стенды
остановлены: 34 собственных PID на фазу, 52–57 портов; cleanup проверен.
Слышимость, Android/AOT, WAN handover и полная multi-device матрица здесь не
заявлены. NETCALL-01 остаётся открытым. Нового mailbox, wire-изменений,
push или релиза нет.
