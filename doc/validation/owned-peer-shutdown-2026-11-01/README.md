# Peer-connector не должен переживать остановку узла

2026-11-01, SDK `41d2b435`. Продолжение
[QUIC lifetime](../canonical-quic-lifetime-2026-11-01/README.md).
Подтверждён и устранён дефект владения динамическими connector-задачами.
Общая задержка холодного подключения остаётся открытой.

## Причина и изменение

Шесть мест запуска динамических peer-подключений отбрасывали JoinHandle:
IPC BootstrapJoin, сохранённые discovered peers, PEX, rendezvous и две
mesh/gateway-ветки. Комментарий «следит за shutdown watch» был недостаточен:
когда connector ждёт `SessionRunner::run()`, он не опрашивает этот watch.
`NodeRuntime::stop` отменял и ждал известные задачи, затем писал `node.stop`,
а забытый connector продолжал держать активный stream. FFI останавливал весь
Tokio runtime уже после возвращения node teardown. Это отличается от прежнего
дефекта QUIC: явное закрытие в SessionGuard не помогает, пока его владелец жив.

Все производственные места запуска peer-connector используют один
`NodeServices::spawn_owned_outbound_peers`. JoinHandle остаётся у runtime;
LAN-кандидат получает AbortHandle для своего удаления, а node shutdown
по-прежнему ждёт завершения самой задачи. Завершённые handles периодически
очищаются. IPC dial-drain также зарегистрирован у runtime.

Постановка задачи и её регистрация выполняются под одним task-registry lock.
После публикации shutdown старый producer не может добавить connector за
снимком teardown; начавший раньше зарегистрирует задачу до взятия этого снимка.
Старый shutdown-контекст после остановки не принимает новые задачи. Backoff,
таймауты, admission/PoW/reputation и wire не изменены.

## Проверка

Регрессия проходит через настоящий `load_discovered_peers`, TCP и полный OVL1.
Удалённый собеседник удерживает установленный stream; после `node.stop`
проверяется удалённый EOF. Локальный список сессий не используется как oracle:
`finalize_stop_state` очищал его и при живом забытом connector.

На прежнем коде **0 passed / 1 failed** по открывшемуся и оставшемуся живым
удалённому сокету. После правки — **1 passed**; дополнительно проверен запрет
новой задачи через старый shutdown-контекст. Полный runtime-набор:
**790 passed / 11 ignored**. Ограничение ожидания EOF — deadlock guard,
а не требование к скорости сети.

Первый запуск с неверным exact-фильтром выполнил ноль тестов, а ранний fixture
попал в штатный фильтр loopback discovery. Они не засчитаны как воспроизведение.
Fixture исправлен на localhost-имя; production-фильтр не ослаблялся.
Mac FFI и Linux CLI собраны из чистого SDK checkout с mount-watchdog внешнего
Cargo target. У Linux linker одно предупреждение о deprecated optimization
setting, не ошибка сборки. Mac library SHA сверена после codesign.

## Физические серии

В обеих сериях — прежний изолированный Mac-профиль, S1 и S2; остальные четыре
тестовые службы выключены. Frontend/AOT, media и hidden-volume заморожены.
На Mac P2P-policy не переключается: она остаётся allowAll, чтобы изменение
настройки не создавало дополнительный reload. Телефон, Windows, звонки и
мобильный handover здесь не проверяются.

Oracle проверяет **обе стороны**: local ACTIVE к S1 и ровно одну ACTIVE-сессию
этого Mac в текущем admin sessions S1, с сохранением одного server link в течение
≥3 с. Перед каждым boot сервер не содержит предыдущей сессии Mac. После lock
отдельный admin-опрос проверяет отсутствие сессии до следующего запуска.
Пустые/односторонние списки не считаются успехом. CLI/SSH polling включён во
времена ниже; это верхние границы обнаружения после native-ready, не точные
времена завершения handshake.

### Изоляция изменения клиента

Mac `41d2b435`, серверы `4f9c85f2`:

| Запуск | Первое двустороннее наблюдение | Двусторонний stable-гейт |
|---|---:|---:|
| 1 | 3,622 с | 6,924 с |
| 2 | 3,032 с | 6,090 с |
| 3 | 2,815 с | 5,868 с |
| 4 | 25,662 с | 30,260 с |

Во всех четырёх после lock серверная сессия отсутствовала уже при первом
опросе. Проверка этого факта занимала 1,09–1,23 с, включая SSH; это не измерение
доставки QUIC close с такой точностью. В четвёртом запуске локальная трасса
сохранила два OVL1 timeout по 10 с, а устойчивая `session.open` появилась на
+23,740 с. Значит, исправление stop-lifetime не закрывает холодный handshake.

### Текущий SDK на обоих концах

В отдельной серии только две изолированные службы временно получили Linux
binary SDK `41d2b435`, с проверкой SHA/config/readiness и сохранением исходных
бинарников. Production-службы не обновлялись.

| Запуск | Первое двустороннее наблюдение | Двусторонний stable-гейт |
|---|---:|---:|
| 1 | 13,764 с | 18,212 с |
| 2 | 2,848 с | 5,864 с |
| 3 | 3,046 с | 7,404 с |
| 4 | 2,822 с | 7,227 с |

И здесь после всех четырёх stop серверная сессия отсутствовала при первом
опросе (1,09–1,23 с, включая SSH). Итого **8/8** корректных удалённых teardown.
Но первый current/current boot сохранил один OVL1 timeout 10 с и соседний
`read OVL1 frame header: connection lost`; оба транспорта установились быстро.
Устойчивая локальная `session.open` появилась на +11,737 с от native-ready.
Снятый lifetime-дефект не объясняет это оставшееся ожидание. Следующий участок —
стадии обмена OVL1 на обоих концах, а не ещё одно уменьшение таймаута.

Все восемь Mac-процессов завершены, восемь собственных runtime-каталогов удалены.
Все шесть тестовых служб остановлены, порты освобождены. У двух временно
обновлённых служб восстановлены исходные бинарники с проверкой SHA; конфиги
не менялись, staging-копии удалены. Production PID/binary/config сохранены 6/6.
Телефон/Windows не менялись; P2P-policy прежняя. Результаты — в `result.json`.
Локальные коммиты без подписи; push/релиза нет.

Это не A/B/A и не оценка причинного ускорения: состояние кэшей и серверов между
сериями менялось. Исправление владения задачами подтверждено независимым
красным тестом и удалённым отсутствием сессий после stop. Причина всех холодных
ожиданий, прежних 58,690 с и NETCALL-01 не установлена этой серией.

[Следующий цикл](../handshake-refresh-2026-11-01/README.md) добавил metadata-only
стадии OVL1 и исправил лишнюю отмену по неизменившемуся refresh. Первый входящий
QUIC stream иногда всё ещё не наблюдается до timeout; задержка не закрыта.
