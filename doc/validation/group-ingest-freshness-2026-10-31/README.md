# Ingest: свежесть уведомлений без повторного хеширования истории

База `90e5ae5a`, native SDK `c46d94db` без изменений. Устранена подтверждённая
лишняя работа при обработке каждого snapshot/delta. **Медленная догрузка в целом
остаётся открытой.** Временные стадийные замеры находятся только в QA-копии вне
репозитория; product-файлы не содержат этих probes.

## Исправление

Для определения новых уведомлений ingest хешировал все уже принятые сообщения,
затем хешировал их снова при сравнении с результатом merge. На тесте с 120
неизменными legacy-строками и одной новой строкой выполнено 180 дополнительных
вычислений canonical payload. Тест был красным на базе, после исправления их 0.

Теперь baseline уведомлений — identity-set объектов принятой истории текущего
ingest. Merge сохраняет старые объекты и добавляет новые; повторная входящая
копия отсекается прежним полным signed digest, а не identity-set. Оба fold
по-прежнему заново проверяют подписи, цепочки, форки и lifecycle. Протокольные
hash-chain вычисления сохранены, кеш авторизации между операциями не добавлен.

Дополнительно проверены сохранение всех 121 строки, повторный snapshot из
новых JSON-объектов без второго уведомления и gap-fill: сначала скрытый suffix,
затем ровно два уведомления после предшественника; повтор полного snapshot
остаётся тихим. Тесты существующих форков/retention/Spaces остаются в suite.

## Два физических прогона

A — Mac и B — Android одной личности, C — Mac другой; три device ID различны.
Mac-код фиксирован на базе; на Android сначала база с временными probes, затем
кандидат с теми же probes. APK profile/AOT, один native SDK и signer, данные
профилей движутся только вперёд. Кандидат после удаления точно перечисленных
QA-вставок побайтно совпадает с итоговым product-файлом.

В каждой серии B остановлен; A создаёт 20 сообщений, C — ещё два. A/C получают
все 22, затем C остановлен и B возвращён при online A. Все 22 появляются на B
**до возвращения C**, с одинаковыми ID/порядком и без дублей. Это короткий offline,
не повтор прежнего пятиминутного сценария со 100 сообщениями и не восстановление
при одновременно offline A/C.

Первое полное наблюдение B — **63,961 с на базе и 91,115 с на кандидате**,
шаг опроса около 10 с. **Сквозного ускорения нет.** Маршруты не закреплены,
остаточные transport/outbox работы различались, история росла; это не A/B
скорости. Часть подготовки базовой серии пересекалась с host-тестами. Эти
условия не позволяют приписать разницу времени одной правке.

Стадии завершённых ingest за участок C-offline; время — медиана мс:

| Стадия | База | Кандидат |
|---|---:|---:|
| Чтение под gate, отдельный замер | 609,6 | 962,4 |
| Принятая история до merge | 232,1 | 107,1 |
| Принятая история после merge / freshness | 129,0 | 92,5 |
| Сохранение и его ожидания | 876,5 | 520,2 |
| Подготовка device-admission | 7,1 | 7,3 |

База: 12 завершённых кадров, 359–374 сохранённых строки, 96 входящих и 84
уведомляемых device-event строки. Кандидат: 26 кадров, 359–363 сохранённых
строки, 139 входящих и 43 уведомляемых; **22 кадра без новых уведомляемых строк**.
Это счётчики device-group, а не числа логических сообщений 1:1. Отсутствие
`fresh` само по себе не доказывает byte-identical duplicate: возможны свои,
непринятые или уже известные строки. Для такой атрибуции нужен отдельный счётчик
реального merge/dedup; новая причина задержки этим не объявляется доказанной.

Максимум стадии save: **3,055 / 3,322 с**. Стадия включает ожидания и работу
сохранения, поэтому это не «три секунды fsync»: очереди, чтения и commit ещё
не разделены. Вложенные времена чтения не суммируются с общим критическим
путём. Меньшие медианы отдельных стадий не доказывают ускорения всего ingest
при разном числе и составе кадров; прямое доказательство исправления здесь —
устранённые лишние hash-вызовы при сохранённых проверках и результатах.

## Проверки и состояние стенда

- 432 group/device-sync/crypto/native теста прошли, 0 skipped. На итоговом
  файле дополнительно 11 targeted проверок; analyzer двух файлов без замечаний.
- Отдельный native TCP-стенд: четыре сообщения всем 12 узлам, каждое ровно
  один раз и одно событие на получателе. Настоящие подписи, encrypted stores,
  ratchet и durable peer authorization; legacy-группа без epoch encryption,
  один Mac/JIT process, не публичные реле и не multi-device матрица.
  Все узлы остановлены, 12 listeners освобождены, cleanup errors=0.
- Попытки отдельного benchmark с изолированными package maps не дали зачтённых
  результатов (ошибка смешения типов, затем discovery/Xcode setup); они
  остановлены и в цифры/число пройденных тестов не включены.
- Все физические QA-процессы завершены, свои ports/forward освобождены,
  runtime-каталоги удалены; исходный QA APK восстановлен по SHA. Данные
  сохранены, основное Android-приложение не менялось. Избыточные APK удалены.
- Rust не пересобирался; Flutter outputs на внешней ФС с mount-watchdog.
  Шесть native Android-библиотек, выравнивание 16 КиБ и signer проверены.
  Mac Runner/плагины прежние, новых Mac release-сборок нет.

Следующий участок — save: разделить ожидание storage gate, повторные чтения,
новые записи и фактические commit; отдельно атрибутировать кадры без `fresh`
и их место в очереди. Нельзя пропускать admission/ACK durability ради быстрого
результата. Полная multi-device матрица и прежние отложенные жалобы этим раундом
не закрываются. Нет push/релиза; публичный артефакт содержит только агрегаты
и SHA исходников/сборок, без личностей, адресов, payload и пользовательских путей.
