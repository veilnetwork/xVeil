# Отмена группового медиа до выхода из очереди — 2026-11-05

ПОДТВЕРЖДЕНО: `VeilGroupCallMediaController.stop()` только ставил очистку за
незавершённым start в `_locked`. Отбой во время permission или IPC не менял
его право на запуск: после ответа прежний start открывал каналы участникам,
вызывал native `startAudio` и возвращал true, затем очередь наконец выполняла
stop. Следующий start аналогично сначала позволял завершиться прежнему.
Это отдельный подтверждённый дефект; исходная жалоба Windows/Poco и вся пауза
NETCALL-01 ему не атрибутированы.

## Воспроизводитель и исправление

Настоящий production controller с подставными transport/engine, существующими
injection points разрешений/network activity и прежним foreground-service
test override. Новых production fault switches или параметров не добавлено.
Completer удерживает одну из шести стадий:

| Стадия | После отбоя требуется |
|---|---|
| Microphone permission | не создавать engine и каналы |
| Чтение локальной identity | то же |
| Acquisition сетевой активности | освободить grant/engine без capture |
| Запуск Android foreground grant | то же |
| Получение room secret | очистить секрет, не открывать каналы |
| Первый channel open | закрыть поздний channel один раз, не подключать его к engine и не открывать следующий |

Для каждой стадии проверены штатный запуск, отбой, замена engine того же
звонка и очередь `start → start → stop → start`. Всего **24 случая**.
Baseline с production из `64a268c7` на том же финальном oracle дал
**18 assertion-red / 6 passed**. В обычном stop oracle фиксирует не только
неверный true, но и **один startAudio после запроса stop**; при замене было
два старта вместо одного. Пятисекундный timeout — только deadlock guard;
порогов сетевого времени нет.

Поколение запроса меняется синхронно при публичном start/stop, до ожидания
очереди. Устаревший start не входит в работу либо возвращает false после
текущего await. Уже созданный engine/grants очищаются под прежней очередью,
до допуска преемника. Во время получения секрета и открытия peer channel
проверяется тот же lifetime; поздний channel не добавляется в engine.
Все существующие derivation/sealing и очистка ключей сохранены.

Первый кандидат очищал microphone intent вместе с отменённым engine.
Дополнительная проверка same-call replacement поймала **4 assertion-red**:
новый engine начинал capture с mic-on вместо выбранного mute. В финале
очистка незавершённого start сохраняет intent. Явный stop, прошедший свою
очередь, завершает его lifetime; отдельная проверка очереди требует, чтобы
звонок после этого stop начал с собственными настройками.

## Проверки и границы

Финальные 24 новых случая прошли; общий контроль 13 файлов — **420 passed,
без skip**. Включены direct/group media, обе FSM, group teardown, слот,
маршрутизация, camera/microphone intent, network activity и foreground helper.
Analyzer двух изменённых файлов чистый. Проверяются отсутствие позднего
capture, успешный преемник, однократный dispose/close позднего channel,
нулевые возвращённые room-secret буферы и снятие platform grants при stop.
Baseline/candidate и тесты зафиксированы SHA; исходник после baseline
восстановлен побайтно. Промежуточные результаты не складываются с финальными.

Это controller/fixture квалификация на Mac, без физического ADM, Android
foreground service или мобильной сети. Не заявляется мгновенная отмена уже
начатого OS/IPC Future: старый start прекращает работу после его завершения,
а cleanup по-прежнему сериализован. Проверка не квалифицирует каждый camera/
screen await и все варианты teardown активной сессии. Телефон в ADB отсутствует;
физические слышимость и handover остаются открытыми.

Все Flutter-запуски — `TMPDIR=/private/tmp/`, процессы тестов завершились.
Rust/C++/native pins не менялись, сборок и установок на устройства не было.
Raw logs и ключи не добавлены в репозиторий; push, релиза и изменений сидов нет.
