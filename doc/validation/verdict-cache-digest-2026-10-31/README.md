# Verdict cache: границы полей и стоимость повторной проверки — 2026-10-31

## Результат

Исправлен воспроизведённый дефект crypto-helper: некорректная длина Ed25519
ключа/подписи могла получить положительный ответ из уже прогретого кэша.
Одновременно уменьшена измеренная стоимость вычисления ключа кэша.
**Ускорение полной доставки или догрузки этим раундом не доказано.**

База приложения `0d5b27cf`, SDK `c46d94db`; SDK и native-библиотеки не менялись.
Исходные данные и журналы оставлены локально. Здесь только агрегаты и SHA
исходников/артефактов, без идентификаторов личностей/устройств, адресов,
содержимого переписки, секретов и путей пользовательских данных.

## Воспроизведение и исправление

Старая функция строила cache key из `publicKey || signature` без границы между
ними, а native shape-check выполнялся лишь при cache miss. В тесте с настоящим
документом делегированного устройства успешная проверка пары 32/64 байта
прогревала кэш; перенос последнего байта ключа в начало подписи давал те же
байты и ошибочный `true` для пары 31/65. Перенос в обратную сторону — 33/63 —
также проверяется. Тест был красным на точном исходнике базы и зелёным после
исправления.

Теперь размеры проверяются **до обращения к кэшу**. Новый cache index также
содержит длины полей, момент проверки, признак документа и его fingerprint.
Отсутствующий/повреждённый документ и иной момент проверки не наследуют
положительный результат. Подпись и право устройства по-прежнему проверяет
native verifier; авторизация, durable ratchet и протокольные хеши не менялись.

Это подтверждённый дефект контракта helper. Текущие сетевые обработчики также
проверяют длины до вызова helper, в частности abuse-report/decision paths;
удалённый обход этих обработчиков **не продемонстрирован**.

CPU-профиль предыдущего физического раунда выделил `_verdictKey` среди горячих
функций. Только для isolate-local индекса verdict-кэша двойной pure-Dart BLAKE3
заменён одним SHA-256 через существующий `veil_sha256`; при недоступной
библиотеке/символе используется chunked Dart SHA-256. BLAKE3 адресов, документа
и протокола сохранён. Части хешируются без дополнительного склеенного Dart
plaintext-буфера; временные native-копии очищаются перед освобождением.

## Физическая догрузка: A + B одной личности, C другой

A — Mac, B — Android, C — второй Mac; три различных device ID проверены.
На всех текущий Dart, native SDK одинаковый с предыдущим раундом. B остановлен
не менее пяти минут; A и C создают три ранних сообщения, затем A отправляет
ещё 100. Перед возвращением B остановлен C; A остаётся online.

- Через 120,934 с после готовности B: **24/100 и 0/3 ранних**.
- За 150 с история полностью не сошлась. Затем возвращён C.
- Итог: **103/103 у каждого**, одинаковые ID и порядок, без дублей.
- Полное восстановление без C **не доказано**: C вернулся до завершения sync.
- Принятие 100 исходящих запросов заняло **175,186 с** против 44,935 с в
  предыдущей отдельной серии. Это отрицательный сигнал, а не доказанная
  регрессия конкретного изменения: сравнение не A/B, состояние и маршруты
  различались. Улучшение физической догрузки не заявляется.

Дополнительный контроль отправителя: один профиль A движется только вперёд,
старая → новая → старая версия, код получателя C фиксирован; B offline. После
одного прогревочного сообщения в каждой фазе приняты и доставлены шесть
измеряемых сообщений, ID/порядок совпали, receipt получен. Медианы приёма
исходящего API: **366,5 / 308,5 / 276 мс**. Это не показывает устойчивой
регрессии кандидата относительно обоих контролей и не доказывает ускорения.
Первый драйвер завершил A1, но не дошёл до B; причина в сохранённых данных не
установлена. Повторный завершил B и остановился до A2 на локальной проверке
порта (`EADDRINUSE`); завершённые фазы собраны отдельными запусками.
C между ними перезапускался с тем же кодом и данными. Это ограниченный
контроль малых отправок, не непрерывный A/B/A и не повтор 100-сообщенного burst.
Эти 21 дополнительные сообщения проверены только на A/C; B оставался offline.
