# Ключ владельца перед активацией группы устройств

Подтверждён и исправлен порядок записей при присоединении устройства: `devices.gid`
становился активным до сохранения отдельной зашифрованной копии ключа владельца.
Отказ записи или завершение процесса между этими операциями оставляли указатель
новой группы без её локального credential. Штатный reader ключа возвращал null.
Сам bundle оставался внутри сохранённого snapshot, поэтому это не доказательство
безвозвратной потери ключа, но завершение adoption требовало ремонта.

Теперь при наличии bundle сначала завершается его сохранение, затем публикуется
`devices.gid` и обновляются кэши активной группы. Отказ записи credential сохраняет
прежний указатель. Формат контейнера, подписи, token/manifest binding, ACL и wire
не менялись. Поддерживаемая ветка без переносимого bundle сохраняет прежний путь.

## Воспроизведение

Два unit-теста используют настоящий hybrid XVSB и native-проверку подписей,
но управляемый отказ storage API перед записью credential. Они проверяют свежий
указатель и ранее заданный указатель с прежним credential. На исходном порядке
оба теста падают: указатель уже заменён, хотя сохранение ключа закончилось ошибкой.
После исправления предыдущие значения сохраняются, повтор adoption проходит,
а ключ присутствует до публикации нового указателя и открывает нужного владельца.

Отдельное воспроизведение на настоящем hidden-volume: целевой VM остановлен
сразу после записи `devices.gid`, затем его process group завершена SIGKILL.
В холодном контейнере сохранён правильный group ID и исходный bundle внутри
header группы, но отдельного credential нет. Этот red падает именно на null
из штатного reader, до проверки сообщений или восстановления сети.

## Прерывание применения snapshot

Новый process-тест останавливает B до/после записи активного указателя и до/после
поглощения pending admission. До восстановления выключаются A и C, прежние реле
останавливаются, B запускается с пустым runtime через новые реле. Старые очереди
и relay cache не могут заменить проверку холодного состояния.
Тест находится в `test/e2e/device_snapshot_adoption_crash_e2e_test.dart`;
прежние четыре точки — в `test/e2e/device_adoption_crash_e2e_test.dart`.

В контейнере проверяются точный manifest/group ID, ожидаемое наличие согласия
и его исходный token. Для активной группы credential совпадает с исходным bundle
и открывается штатным секретом в native RAM с тем же owner. После cold boot
состав активной группы совпадает с составом источника, снятым до crash. При ещё
не опубликованном указателе группа остаётся неактивной до повторного snapshot.
Новый QR или новая церемония не выпускаются.

Если сохранённые строки snapshot содержат принятие внешнего контакта или историю,
активная группа обязана применить их при выключенных источниках. Наличие этих
строк записывается отдельно для каждого случая. Начальный snapshot не обязан
содержать историю: backfill идёт отдельным потоком. После возврата источников
история догружается, затем проверяется новый обмен B→C и C→A/B, единственность,
общие ID и итоговый порядок трёх контрольных сообщений.

Первый промежуточный green-прогон остановился на неверном предусловии теста:
оно требовало историю уже в первом snapshot. Четыре новых случая этого прогона
не засчитаны как пройденные. Ошибка предусловия не объявлялась дефектом продукта;
холодный red на отсутствующем credential относится к другой, более ранней
проверке и остаётся действительным.

## Объём проверки

Полный набор GroupService — **500 passed, 0 skipped**, включая два новых теста
отказа credential. Targeted analyze и `git diff --check` проходят.

Финальный process-набор — **8 passed, 0 skipped**: четыре прежних точки вокруг
документа/согласия и четыре новые вокруг активации/поглощения согласия. Во всех
трёх новых случаях с активной группой ключ совпал с bundle и открыл правильного
владельца; восстановились исходные участники и сохранённое принятие контакта.
В четвёртом случае указатель ещё не опубликован, поэтому контакт остаётся
неприменённым до завершения adoption. История в начальных snapshot этих четырёх
случаев отсутствовала; она проверена после возврата источников, не объявляется
проверкой холодного восстановления уже сохранённых сообщений.

Исходники и выбранные native-входы не менялись во время каждого зачтённого
прогона. После unit-прогона усиливался только отдельный native-тест; продуктовые
и unit-исходники остались теми же. После финальной process-серии подтверждены
выход 86 учтённых процессов/групп, отсутствие test VM и освобождение 85
зарегистрированных TCP/UDP-портов. Промежуточные серии очищены отдельно.

Стенд использует macOS arm64/JIT, CLI/SDK `e963fbdb` и локальную hidden-volume
`293792d`. Gate подключается только к synthetic process fixture по
`XVEIL_E2E_DEVICE_ADOPTION_CRASH=1`; application fault flags и endpoints не
добавлялись. Это SIGKILL на границах storage API, а не аппаратная потеря питания
внутри native commit. GUI и другие ОС этим запуском не квалифицируются.

Это частичное покрытие link/crash пункта 63. Прерывания отдельных последующих
порций истории, часы/сутки offline и вся multi-device матрица остаются отдельными
участками. Process-сценарии используют свежий B: они не доказывают атомарность
замены уже активной семьи при отказе записи самого `devices.gid`.
Установленные пользовательские приложения и серверы не обновлялись.
