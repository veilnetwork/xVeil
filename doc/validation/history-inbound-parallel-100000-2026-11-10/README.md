# Ограниченный параллельный приём частей истории — 2026-11-10

## Подтверждённый механизм

Все history-кадры после обычного durable ingress проходили одну `_inbound`
цепочку. Один приостановленный свежий roster lookup не давал даже начать
обработку готового следующего кадра. На больших страницах каждый отдельный
part платил за это последовательное ожидание.

Теперь одновременно обрабатываются не более четырёх принятых history-кадров.
Ожидающие получают освободившийся слот FIFO. Все waiting/in-flight payloads
остаются под прежним InboundAdmission: 512 frames / 1 MiB globally и 256 KiB
на известный peer. Replay coalescing, provenance/identity/device binding и
свежие `_allowed` проверки не удалялись. Законченный verdict не кешируется.
Существующий GroupService умеет разделять только unfinished fresh lookup;
перекрытие вызовов теперь позволяет использовать это на ingress.

Crypto/consent/ratchet handling остаётся в прежней durable lane до этой очереди.
Части уже поддерживают переупорядочивание по index/request ID. Само применение
страниц по разговору, проверки перед durable publication и cursor checkpoint
сохраняют прежние последовательность и барьеры. Запросы serve подчиняются
прежним ограничениям; mailbox для собственных устройств не включался.

Начало работы отложено на microtask, как прежний `Future.then`: admission и
владелец регистрируют задачу до вызова пользовательских resolver callbacks.
`finally` передаёт слот старейшему waiter либо освобождает его. Ошибка/close
не отравляет очередь; закрытые/устаревшие задачи пропускаются и возвращают
свои byte/frame leases. Production debug API или test hooks не добавлялись.

## Регрессии и исправление самого теста

Две проверки падали на прежнем коде без временных порогов:

- восемь принятых запросов при закрытом gate начинали только один свежий
  lookup вместо ограниченного перекрытия четырёх;
- готовый следующий live-запрос не мог ответить, пока первый lookup удержан.
  Обычный chat post служит барьером: live dispatcher уже прошёл enqueue.

В первой версии второго теста использовался `deliverInbound`, то есть mailbox
admission. Этот API намеренно отбрасывает deviceHistory. Проверка падала и на
исправлении; это ошибка теста, а не новый product-дефект. Тест переведён на
настоящий live transport и повторно воспроизвёл parent-red. Mailbox guard не
ослаблялся; исходный ошибочный прогон не считается доказательством.

169 own-history tests прошли: reorder/replay, expiry, revoke, binding replacement,
shutdown с flood/coalesced frames и ошибки roster reads. Отдельно все 13
InboundAdmission tests прошли. После форматирования шесть выбранных проверок
также прошли; эта серия пересекается с остальными и не суммируется с ними.
Analyzer двух изменённых Dart-файлов чист.

## Трасса и границы атрибуции

Все три raw traces полны: четыре закрытых boot-сегмента, dropped=0, active=0.
Записей A1/B/A2: 51196 / 28256 / 50562; прежний bounded budget 65536 не изменён.
При отсечении cold-reopen проверки ownDevices busy spans:
55,867→41,224→57,844 с; число spans 23551→12112→23238. Это overlapping
ожидания, не чистые CPU/disk/fsync времена и не величины для сложения с apply.

Старый анализатор постраничной временной корреляции связал в B только
692 из 782 интервалов при прежнем пороге 700 и остановился. Порог сохранён;
**полный постраничный профиль по нему не квалифицирован**. Raw-trace completeness,
whole-window unions и passive EOF witness проверяются отдельно и не требуют
догадки о принадлежности cursor соседней странице. Поднабор из 692 строк не
используется как полный профиль или основание для причинных процентов.

Догрузка остаётся около 109 с: следующие кандидаты — ожидания внутри apply,
свежие обращения к device journal и подготовка страниц на источниках.
NETCALL, остальная multi-device/crash матрица и физическая/AOT квалификация
статус не меняют. Все owned процессы/listeners удалены; cache 92→92, новых
kernel entries нет. Raw IDs/пути/endpoint данные остаются вне Git.
Новые изменения локальные, без push/релиза.
