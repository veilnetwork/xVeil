# Отбор границы checkpoint на 100000 сообщений — 2026-11-10

## Что проверялось

Conversation apply lane удерживается не только до завершения всех row callbacks
и durable публикации страницы, но и до checkpoint конкретного источника.
В искусственно удержанном cursor-write второй источник не мог применять свою
готовую страницу того же разговора. После отказа записи очередь уже умела
продолжаться; бесконечное отравление очереди или потеря данных не установлены.

Кандидат освобождал conversation lane после полного применения страницы,
оставляя каждому pull обязательный fresh/durable checkpoint до следующего
запроса. Барьеры публикации, свежий admission, lease и wire limits не снимались;
mailbox не добавлялся. Две gate-проверки падали на parent и проходили на кандидате:
удержанная запись и её последующий отказ не паркуют второго источника.
Третий тест подтверждал, что shutdown всё ещё ждёт незавершённый cursor-write.
Всего на кандидате прошли 206 related tests, analyzer чист.

Это квалификация варианта и fault-injection модели, а не объявление новой
причины пользовательской задержки. По результатам ниже **вариант отклонён**,
production diff и его новые тесты убраны. Кандидат, тесты и сырые доказательства
сохранены только в частном evidence-каталоге. Текущий product/test код совпадает
с HEAD до эксперимента; в этом цикле нет нового production fix.

## Что меняет следующий шаг

В active window union own-device lookup spans остаётся 40,85 / 40,60 / 42,04 с,
а history-apply — 43,38 / 42,40 / 43,22 с. Ожидания могут перекрываться, их нельзя
складывать или выдавать за чистое CPU/fsync/critical-path время.

Текущий код свежей inline batch-загрузки отдельно запрашивает metadata через
`getBatch`, затем payload через `readLogGroups` в том же storage worker.
Следующий предмет проверки — ограниченное объединение этих обращений с
сохранением tier precedence, first-failure semantics, свежести и byte/record caps.
Это направление анализа, ещё не реализованная оптимизация и не обещание ускорения.

Догрузка на сохранённом коде около 103 с, проблема остаётся открытой. NETCALL,
остальная multi-device/crash матрица и прежние жалобы статус не меняют.
Все owned процессы/listeners завершены, runtime удалены. Cache 92→92 в каждой
фазе, новых kernel entries нет. Raw IDs/пути/endpoint данные вне Git.
Новых push/релизов нет; CHANGELOG не получает записи об исправлении.
