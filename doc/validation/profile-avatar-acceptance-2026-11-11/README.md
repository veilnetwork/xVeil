# Аватар в уже открытой карточке контакта — 2026-11-11

## Подтверждённый сценарий

Если `IdentityAvatar` открывался до принятия контакта, исходный запрос картинки
правильно отклонялся consent gate. После принятия контакта виджет оставался
смонтированным и **не запрашивал картинку снова**. Повторное открытие чата
устраняло этот локальный пробел, поэтому поведение зависело от навигации.

Два widget-теста воспроизводят отсутствие запроса: обычный `acceptContact`
и решение, полученное через `applyMirroredContactStatus`. В обоих случаях
контакт принят, прежний widget element остаётся на месте, но число avatar
requests равно нулю вместо одного. На исходном коде оба теста дали именно
эти assertion-red. Это конкретный механизм пропущенного обновления, но не
установленная причина пользовательского Windows 10 репорта.

## Изменение

MessagingService сообщает о сохранённых переходах отношений через отдельный
локальный stream. Видимая карточка реагирует только на accepted своего контакта.
При смене identity service старая подписка снимается, при уничтожении виджета —
закрывается. События прежнего сервиса не запускают новую операцию в его имени.

Событие — подсказка интерфейсу, не авторизация. Фактический запрос проходит
прежнюю проверку текущего consent revision и минутный rate limit. Для mirrored
решений не вызывается callback локального журнала: новый stream не создаёт
цикл зеркалирования. Уведомления публикуются после успешного сохранения решения.

Обычные сообщения/догрузка истории не являются триггером запроса. Не добавлены
таймер, опрос присутствия, mailbox, durable avatar-очередь или автоматическая
рассылка всем контактам. Невидимые карточки не инициируют запрос через этот stream.

## Проверки

- После правки оба прежних widget element запрашивают картинку без remount.
  При передаче валидного avatar frame тот же `CircleAvatar` получает `MemoryImage`
  с точными ожидаемыми байтами.
- Дополнительный контрактный тест в контролируемом KV и настоящем worker
  проверяет соответствие уведомления сохранённому статусу, отсутствие mirror echo
  и завершение stream при закрытии MessagingService.
- На macOS **54 related tests прошли без skips** с обязательной, проверенной по
  SHA HV-библиотекой. Включены предыдущие consent races, формат/размер картинки,
  image cache, смена service и новые widget/controller проверки.
- На Windows 11 **20 tests прошли без skips**: avatar/widget серия и consent/
  notification сценарии в обоих storage режимах. Анализ пяти Dart-файлов чист.

Новые widget-сценарии используют контролируемое хранилище и transport; реальные
worker-сценарии отдельно проверяют сохранение статуса и notification contract.
Это не native-network или end-to-end GUI свидетельство. Ответный кадр в
widget-тестах подаётся явно, потеря/переупорядочивание кадров ими не моделируются.

На Windows восемь исходных файлов собственной QA-копии временно заменялись
учтённым snapshot. После серии прежние байты восстановлены, добавленные файлы
удалены. Повторный полный контроль подтвердил неизменность frontend sources,
packaged DLL и исходного QA-контейнера/prefs; приложений/tasks не осталось.
В этом раунде приложения и звонки не запускались.

## Границы результата

Запрос по-прежнему live-only и может потеряться в сети, в том числе при
переупорядочивании с подтверждением контакта. Исправлен **отсутствующий запуск**,
гарантия сетевой доставки не добавлена. Все причины непостоянного обновления
аватаров на пользовательской Windows 10 этим не объявлены устранёнными.

Новая Dart-правка ещё требует AOT-упаковки; прежний desktop AV bundle её не
содержит. Исходный Windows 10/Android, сетевой обмен новым изображением и его
показ в работающем приложении остаются до квалификации. Пользовательские
контейнеры и production-реле не изменены; push/релиза нет.
