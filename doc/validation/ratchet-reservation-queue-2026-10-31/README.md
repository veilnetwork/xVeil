# Готовый резерв ratchet не ждёт чужой I/O

Проверка 2026-10-31. Без push/релиза; SDK остаётся `c46d94db`.

## Подтверждённый механизм

Каждый `reserveBeforePublish` входил в общий per-container ratchet gate,
даже если все текущие sending positions уже покрыты записанными marks.
На настоящем 12-узловом стенде в предыдущей серии 401 вызов резервирования
имел медиану 97,9 мс и максимум 1,147 с. Это включало ожидание чужих
snapshot/reservation операций, не только собственную запись.

Красный тест удерживает commit резерва другого peer. Отправка уже покрытому
peer не завершает precheck до освобождения чужого commit. На исправленном
варианте она завершает precheck за event-loop barrier при всё ещё закрытом
I/O gate; ни новый floor, ни новое разрешение для другого peer не возникают.
Тест не использует порог скорости и не подменяет криптографическую гарантию
таймером.

## Изменение и границы

У активного journaling attachment с `RatchetPublicationGuard` проверяются
свежие native conversation keys и все live sending positions. Когда каждый
покрыт durable cache, precheck возвращает без storage transaction. Это reuse
уже записанных marks: новый floor здесь не устанавливается, ciphertext не
выдаётся. Отсутствующий ещё conversation/send chain также остаётся за native
проверкой первого seal.

Native остаётся окончательной проверкой эпохи, цепи и позиции под lock при
расходовании ключа. Конкурентная ротация после precheck не может заимствовать
старое разрешение. Не покрытые позиции, новая sibling-цепь, исчерпанный резерв,
retired/superseded/closing owner и degraded binder не используют быстрый путь.
У незащищённого legacy handle сохранён прежний сериализованный путь.
Новые marks, сохранение state, rollback anchor attempt и выдача native floor
по-прежнему выполняются прежней последовательностью.

Отдельный gate-тест удерживает anchor attempt ПОСЛЕ записи marks: cached
precheck может вернуться, но native всё ещё отказывает seal. Ciphertext
разрешён только после завершения исходной reservation операции. Проверены
ротация, sibling, исчерпание, закрытие владельца, scoped owner epochs и
сохранение legacy gate; исходные crash/failed/uncertain commit проверки сохранены.

Не добавлены production-логи, обход ACK, сетевые приоритеты или распознавание
содержимого на реле. Новый per-peer тайминг находится только в private test
fixture; наблюдатель сохраняет synthetic stand indices, без raw node IDs в
публичном отчёте.

## Native A/B готового резерва

A — `RatchetPersistence` из `0d56012c`, B — новый путь. Меняется только этот
Dart source; остальные source SHA и новый пассивный per-peer fixture совпадают.
В обеих фазах SDK `c46d94db`, один и тот же подписанный library SHA и одна
hidden-volume библиотека. Источник и SHA после codesign проверены; Rust не
пересобирался. После временных source swaps восстановлен ровно кандидат.

12 разных production-PoW fixture личностей, свежие encrypted containers,
обычные MessagingService/ratchet/host-authorization/fragmentation/ACK.
TCP loopback/DHT; один JIT process/Mac/shared disk, legacy group без epoch
encryption, roster подготовлен отдельно. Это не multi-device/Android/Windows,
не публичные onion hops и не квалификация AOT. Разные группы/расписания могут
менять критический путь; одинаковое дерево и I/O schedule не фиксировались.

Ни один reserve peer в новой трассе не потерян, все записанные вызовы успешны.
Декомпозиция logical-hop сохранена; peer-атрибуция reserve сама по себе не
сопоставляет каждый precheck конкретному wire copy при параллельных вызовах.

данные активного окна, не доказанная доля критического сообщения. Они выделяют
host checkpoint/I/O вместе с очередями как следующий участок разбора;
локальный handoff→callback нельзя называть сетевым RTT.

## Проверки и состояние

254 unit/security теста прошли, 0 skipped: reservation, persistence,
peer authorization, rollback anchor, outbox, receipts, cleanup, ABI contract.
4 native ABI теста прошли, включая обе retained V4 chains/recovery.
Scoped project analyze: no issues. Ошибочный путь одного теста в ранней команде
не считался пройденной проверкой; исправленный полный набор прошёл.
Analyzer, запущенный для private fixture вне package root, не нашёл package
imports; это не app failure. Fixture отдельно скомпилирован через flutter test
с выключенным gate (skip не засчитан), затем действительно прошёл native серию.

В 12 stand (6 poll + 6 gate A/B) все **48 сообщений** у всех 12 по одному
разу: по одной строке истории и 44 visible events каждого запуска, включая
поздние до teardown. Timing dropped=0, cleanup errors=0, 12 listeners каждого
запуска освобождены, host processes exited, временных stand roots не осталось.
Телефон и production-реле не менялись.

**Остаток:** несколько секунд начальной доставки, хвостовые ratchet/I/O
ожидания и оставшаяся multi-device матрица. Исторические невоспроизводимые
жалобы не возвращаются в активную очередь по этому эксперименту.
