# Догрузка истории своего устройства после offline

## Исправление

В [предыдущем прогоне](../offline-backlog-process-2026-10-24/README.md)
B получил только 154 из 1000 новых сообщений за 180 секунд. Оригиналы были
на работающем A; старые зеркала уже вышли из ограниченного device-sync журнала.

Добавлен отдельный live-обмен между действующими устройствами одной личности:
сначала сверка количества и хеша ID, затем страницы недостающей переписки.
Страница содержит до восьми сообщений; ограничены число фрагментов, размер
ответа, число параллельных устройств и частота ответа. Совпадающая переписка
не пересылается заново. Журнал не расширяется и не наполняется старой историей.
Mailbox и durable outbox в этом обмене не участвуют.

Запросы привязаны к аутентифицированному физическому отправителю, текущему
списку устройств и активному владельцу привязок. Ответ принимается только
на свой незавершённый запрос. Отзыв устройства и смена привязок останавливают
старый обмен. Курсор сохраняется в зашифрованном хранилище после записи всей
страницы; ошибка записи страницы или курсора оставляет её для повторной загрузки.
Применяются существующие правила удаления, скрытия после чтения и срока жизни.
Отдельная отметка срока жизни не позволяет задержанному ответу вернуть уже
истёкшее сообщение, даже если на получателе ещё нет новой настройки TTL.

## Проверки

* 72 проверки: протокол, существующие presence и привязки, старые оригиналы,
  перестановка и повтор фрагментов, рестарт с курсора, ошибки записи страницы
  и курсора, смена привязок, отзыв устройства, отказ чужим запросам и mailbox,
  TTL, обход десяти переписок и повторная сверка без пересылки совпадающих сообщений.
* Полный `dart analyze`: замечаний нет.
* Ещё 170 регрессионных проверок: существующие зеркала, удаления, история,
  порядок, device-sync, исчезающие сообщения, вложения и диагностика.

## Native A/B/C: пройдено

Отдельные OS-процессы, настоящие SDK и зашифрованные контейнеры; локальные реле,
пониженная тестовая сложность PoW. Публичная сеть не используется. Это проверка
корректности, а не обещание скорости в пользовательской сети.

| Действие | Online | Фактический результат |
| --- | --- | --- |
| Отправить 1000 сообщений A → C при выключенном B | A/C | C получил все 1000 ID в порядке A |
| Выключить C, включить B | A/B | B получил 250 новых сообщений, догрузка ещё не закончена |
| Принудительно завершить B, затем включить | A/B | B восстановил 1000/1000, ID и порядок совпали, дублей нет |
| Выключить A, перезапустить B | Только B | Вся восстановленная история сохранилась |

Догрузка, включая принудительное завершение и запуск B, заняла **267,618 с**.
Тестовый порог продолжения после прерывания — 5 минут; он не увеличивался.
Первоначальное приветствие учитывается отдельно. Проверка API `total` не даёт
дублям скрыться за окном последних 1000 строк. Зафиксировано реальное прерывание
частичной догрузки, а не только повторное открытие уже готовой истории.

Все восемь записанных process groups и 11 PID проверены после завершения:
живых участников этих групп нет, контейнеры native-стенда удалены.
Исходники приложения оставались неизменными на протяжении native-прогона.

## Телефон

Poco был доступен по ADB. Две установки отдельного QA-пакета отклонены Android
с `INSTALL_FAILED_USER_RESTRICTED`; QA-приложение не запускалось, ADB forward
и настройки питания не менялись. Передача файла и звонки не начинались.
К заключительной проверке телефон отключился от ADB, поэтому повторная сверка
APK и состояния телефона после этого недоступна. Этот физический сценарий
остаётся открытым.

## Границы результата

**Следующий цикл:** [восстановление редакций и подтверждений доставки](../own-device-state-recovery-2026-10-24/README.md)
расширяет сверку состояния. Ниже сохранены ограничения первоначального прогона
с ID; его результаты и хеши не переписывались.

Это восстановление отсутствующих сообщений из доступного своего устройства.
Сверка ID сама по себе не проверяет совпадение текста уже имеющейся строки,
реакций и статусов: их существующие механизмы требуют отдельных сценариев.
Для нового обмена обеим сторонам нужна обновлённая версия; старая его игнорирует.
Если все источники offline, этот обмен не создаёт удалённую копию истории.
Медиа передаются существующим механизмом по запросу; сверка истории не доказывает
скачивание каждого вложения. Полная матрица multi-device и Windows этим циклом
не объявляются пройденными.

Опубликованные результаты содержат только агрегаты и хеши исходников.
Рабочие журналы, сетевые адреса, ID, ключи, пароли и контейнеры не публикуются.
Push и релиз в этом цикле не выполняются.
