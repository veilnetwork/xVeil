# Начальный ответ own-device history после перезапуска

2026-11-03. Продолжение [ready-notice qualification](../history-ready-notice-2026-11-03/README.md).
Mailbox для собственных устройств по решению владельца не подключается.

## Подтверждённая и исправленная гонка

Исходящая history-задача проверяла host/roster, затем ожидала локальный ID
устройства и без повторной проверки отправляла запрос. При detach либо замене
host за время ожидания старый запрос всё равно уходил. Два gate-теста
воспроизвели лишнюю отправку на прежнем production-коде: одна после detach,
вторая после запуска нового host, уже отправившего свой запрос.

Теперь задача сохраняет ID и содержимое своего запроса; после async-проверки
roster и после чтения device ID проверяет readiness, owner, текущий pull и ID
его фазы. Завершённая задача не может отправить старый запрос или заимствовать
следующую страницу текущего pull. Admission, durable apply/cursor, проверки
документов и ratchet не менялись. Это отдельный подтверждённый дефект;
причиной задержки начального ответа он не объявляется.

**164 tests passed / 0 skipped**: own-device history и новый наблюдатель — 51;
history backfill, device sync/brick4/slot, detach, large-frame и доставка
больших сообщений — 113. Analyzer пяти изменённых Dart-файлов чист.

## Пассивный наблюдатель

Включается только в native test fixture явным флагом, после основной
подписки приложения и до ready-notice. Использует существующий broadcast
stream SDK: не подменяет транспорт, callback или возможности клиента.
По умолчанию отключён, в production-приложение не включён.

Приватный JSONL содержит локальное время, непрозрачный ID запроса, операцию,
номер части, размер и provenance. Нет текста, тела/байтов вложения, peer ID
или произвольных полей запроса. Лимит — 2048 наблюдений за запуск; счётчик
пропусков сохраняется при закрытии. Непрозрачные ID предназначены только для
локального сопоставления и не входят в анонимный пользовательский экспорт.
Unit-тест проверяет лимит, отсутствие содержимого, сохранность основной
подписки после закрытия наблюдателя и обработку ошибок транспорта: отдельная
подписка не должна добавлять необработанную копию ошибки или сохранять её
текст. Последний сценарий также был красным до исправления наблюдателя.

## Native: задержка остаётся на текущем SDK

Сценарий прежний: A/B одной личности и C другой; B/C выключены, в live
encrypted storage A подготовлены три строки вне device journal, средняя
160015 байт. B возвращается при online A/offline C. Затем A выключается,
B перезапускается один. Во всех зачтённых запусках: **3/3**, точные ID,
тела, порядок/source positions и delivered; дублей 0; проверочных mirrors
в journal A до/после 0; данные B сохраняются без источников.

| Native SDK / production | Ready B от запуска, с | Первая строка от запуска, с | Первая строка после ready, с | Все три от запуска, с |
| --- | ---: | ---: | ---: | ---: |
| Замороженный `eb644a83`, до текущего guard | 9,290 | 24,086 | 14,796 | 25,610 |
| Текущий `8dac85ce`, до текущего guard | 5,237 | 20,001 | 14,764 | 21,484 |
| Текущий `8dac85ce`, окончательный guard | 10,065 | 16,817 | 6,752 | 17,835 |

Это три одиночных наблюдения с включённым локальным trace, а не A/B/A-оценка
ускорения. Различаются стартовые состояния соединений и длительность boot;
уменьшение последнего времени не приписывается guard или новому SDK.
Миграция 2000 сообщений и Android/AOT этим малым сценарием не квалифицированы.

Сопоставление непрозрачного ID на входах A и B уточнило прежнюю неоднозначность:
**первый запрос доходит быстро, задерживается ответ**. Отсчёт ниже от открытия
наблюдателя B перед готовностью host; он отличается от времени запуска процесса.

В первом зачтённом запуске текущего SDK один и тот же inventory-запрос приходит
A на +0,576 / +2,476 / +6,478 / +14,478 с. Копия на +2,476 имеет только claimed
provenance и не допускается к истории; остальные signed. A начинает локальный
вызов отправки 420-байтового ответа на +0,594 / +6,521 / +14,527 с. B впервые
видит ответ этому запросу на +14,541 с. Следующие ответы начинаются примерно
через 36–202 мс после прихода соответствующих запросов A.

Важно: `live send` пишется **перед** вызовом транспорта. Он доказывает начало
локальной попытки, но не её завершение, queue admission, передачу пакета или
приём другим устройством. Между Dart-вызовом и native admission нет общего
ID для этих обычных history-кадров. Поэтому фраза «ответ уже ушёл в сеть» по
одному этому логу была бы слишком сильной.

На A keepalive закрывает старую сессию того же physical recipient около
+12,392 с; следующий signed retry получает ответ быстро. В окончательном
запуске закрытие наблюдается раньше, около +1,791 с: claimed-копия на +2,440 с
также не допускается, а signed retry на +6,443 с получает ответ на +6,511 с.
Это согласуется с гипотезой старого прямого соединения и retry-лестницы, но
не доказывает, что каждый из ранних ответов попал именно в его очередь.
Таймауты/повторы для маскировки симптома не сокращались; авторизация не ослаблялась.

## Происхождение сборок и очистка

Текущий SDK собран заново в отдельном external Cargo target с контролем
монтирования и свободного места. До/после проверены HEAD `8dac85ce`, чистота
SDK и содержимое 1523 tracked-файлов. CLI/FFI/HV SHA зафиксированы приватно;
две текущие native-серии используют одни и те же артефакты. Во время каждого
run сверены 1400 файлов fixture/application/Flutter dependencies, native/HV
не менялись. Публичные реле и пользовательские приложения не затронуты.

Первая попытка текущей серии не засчитана: orchestrator не создал каталог
evidence, worker-тесты получили PathNotFoundException. После их явного отказа
прогон остановлен; после SIGINT Flutter вернул 0 при незавершённом тесте —
это не принято за успех. Оставшиеся собственные workers завершены, runtime
удалён, порты проверены. Повторные прогоны дополнительно требуют `passed`
в oracle и штатный `All tests passed`, одного exit code недостаточно.

Оба корректных текущих запуска завершены с test/cleanup code 0. Финальная
очистка проверила 23 собственных PID и 20 портов: живых процессов/listeners
нет, runtime-контейнеры удалены; probe drops 0. Raw evidence остаются приватными.

## Остаток

Начальная недоставка ответа остаётся подтверждённой на текущем SDK. Следующий
участок — результат native admission каждой ранней попытки и конкретная
регистрация прямой сессии, с сохранением обратного пути при её замене.
Общая длительная миграция и расширенная multi-device матрица остаются в работе.
Mailbox, push, релиз и обновление публичных узлов в этот цикл не входят.
