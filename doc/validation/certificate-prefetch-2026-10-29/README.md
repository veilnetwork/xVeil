# Холодная отправка: параллельное получение сертификата — 2026-10-29

База: xVeil `12632fa3`, Veil `d19923f5`, hidden-volume `1ea2366f`.
Исправление Veil: `c9297488`.
Исправление касается адресата с уже известным instance ID. Другие причины
долгой доставки и пользовательские репорты не объявляются закрытыми.

## Подтверждённое ожидание

В `walk_cert_for_instance` запрос документа личности завершался **до** начала
запроса сертификата устройства. Оба DHT-адреса уже известны. При молчащей
реплике каждый поиск ждёт свой трёхсекундный deadline, даже если другие
ответили. Два независимых запроса могли занимать два последовательных окна.

Теперь документ и ограниченный набор байтов сертификата запрашиваются
параллельно. Получение байтов не авторизует ключ: перед его использованием
по-прежнему нужны проверенный документ, его durable authorization checkpoint,
проверка подписи/срока сертификата и соответствие instance ID. Опрашиваются
те же реплики с прежними пределами и deadline. Выбирается самая свежая
проверенная запись после ожидания ответов, а не первая пришедшая.
Недействительный документ отменяет незавершённый prefetch и освобождает его
pending-query записи. Fallback и поиск без известного instance ID сохранены.
Пиковое число запросов такого поиска возрастает с одного набора до двух;
общий лимит pending-запросов остаётся прежним.

Регрессионный тест на прежнем коде упал: запрос сертификата ещё не был
поставлен в session queue, пока ожидался документ. Исправление проверяется
наблюдением обеих очередей до любого ответа, без порогов времени. Ещё три
теста проверяют отказ поддельным документам/подписям, ожидание надёжной записи
авторизации хостом и отмену незавершённого prefetch. Первый тест также
проверяет, что поздняя свежая реплика побеждает раннюю старую.

Runtime: **732 passed, 11 ignored**. FFI: **326 passed, 2 ignored**.
Ignored не считаются пройденными. Release-библиотека Mac собрана с
`node-embedded`, `production-seeds`, `packet-tunnel`, без default features,
test-low-difficulty и native test hooks. Отдельная файловая система внешнего
target проверялась до сборки и каждые 0,5 секунды во время неё; отключений
не было. Анализ двух Dart-файлов и diff прошли без замечаний.

## Измерение на 12 native-узлах

Opt-in стенд дополнен пассивными отметками sender, native transport callback,
входа GroupService, видимости, worker RPC и ratchet reserve/flush. Обёртка
сохраняет batch-read и rollback-anchor интерфейсы настоящего worker store.
Новые измерители находятся только в `test/`, содержат числа и категории,
не пишут ключи или значения записей.

Исправлена проводка стенда: PeerAuthorizationPersistence восстанавливается
и запускается перед привязкой приложения, как в основном клиенте. DHT теперь
включена по desktop-умолчанию; `GROUP_OVERLAY_DHT=0` — отрицательный контроль.
Ранее все участники не обслуживали DHT, отдельного core-узла нет. Прежняя
проверка связности действительна, но её времена не являются эталоном штатной
сети. Новый стенд также состоит из leaf-клиентов, без операторского реле.

Последовательные прогоны с теми же тестовыми личностями, новыми сессиями и
контейнерами. Максимум видимости по 11 получателям, миллисекунды:

| Библиотека | Сообщение 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| Прежняя, до кандидата | 16803 | 2329 | 2440 | 2375 |
| С исправлением | 12093 | 2153 | 2529 | 2857 |
| Прежняя, повтор после кандидата | 12696 | 1436 | 2731 | 2322 |

В каждом прогоне все четыре сообщения видны всем 12 участникам ровно один
раз. Разброс прежней библиотеки велик; таблица **не доказывает общего
ускорения доставки**. Более пяти секунд разрешение ключей занимало в 11/38,
3/33 и 10/46 зарегистрированных медленных seal-вызовах соответственно. Это
выборка только вызовов от одной секунды, не всех отправок. Процент ускорения
из неё не вычисляется. Некоторые вызовы кандидата всё ещё занимали более
шести секунд; все пути fallback и очереди этим не оптимизированы.

В дополнительном диагностическом прогоне новой библиотеки зарегистрированы
64 адресных поиска, максимум 3894 мс, один miss, ни одного свыше пяти секунд.
Это отдельная трасса, а не дополнительная точка сравнения скорости.

В исходной подробной трассе первый native callback пришёл через 3581 мс
после sender. Первый локальный sender начался через 72 мс после действия.
На получателях callback → вход группы занимал не более 127 мс, вход группы
→ видимость — не более 296 мс для этого сообщения. Поздние получатели ждали
дополнительные переходы; эти максимумы не складываются в полный путь.
В отдельном прогоне с журналом Dart повторов Outbox до первого callback нет.
Отключение devLog константой `dart.vm.product` не убрало холодную паузу;
это тестовый JIT-хост, **не** квалификация Flutter release AOT.

Разложение прежних физических 53/114,9 с ещё не закончено. Worker RPC
относятся ко всем 12 узлам, включают проверочные чтения стенда и пересекаются
с ratchet таймерами; их суммы не равны задержке одного сообщения.

## Воспроизведение и границы

Запуск: `test/native/group_overlay_live_test.dart`, `GROUP_OVERLAY_LIVE=1`,
обе native-библиотеки, `TMPDIR=/private/tmp/`, `umask 077`, отдельный каталог
`GROUP_OVERLAY_EVIDENCE` с правами 0700. Весь вывод сохранять в закрытый файл:
подробные native-журналы содержат тестовые адреса. Публичная
[числовая сводка](summary.json) экспортирована по разрешённым полям, без
сырых журналов, адресов, PID, ключей и содержимого сообщений.

Ограничения: один процесс и Mac, TCP-loopback, legacy-группа без шифрования
эпох членства, начальный состав передан вне сети, парных контактов нет.
Native-шифрование, подписи, ratchet и надёжное сохранение не подменены.
Смешанные версии, смена состава, долгий offline и физические устройства
остаются отдельными проверками. Во всех трёх прогонах завершены 12 узлов,
заново заняты/освобождены 12 TCP-listeners, cleanup без ошибок, хосты вышли.
GUI, камера и микрофон не запускались. Push, релиз и обновление реле не
выполнялись.
