# Повторы по устаревшему снимку исходящей очереди

## Подтверждённые случаи

В `3cca412e` проход исходящей очереди сначала выбирал до 16 кадров, затем
последовательно отправлял их. Пока первая попытка ждала транспорт, подтверждение
могло уже снять следующие кадры с очереди. Проход всё равно отправлял сохранённые
копии. То же происходило после снятия кадра во время проверки адресата или
завершения сервиса. Повторное использование ID могло выпустить прежнее тело.

Шесть управляемых сценариев воспроизвели проблему на прежнем коде. Чужой ACK
не снимал очередь и до исправления; эта проверка сохранена.

Дополнительные проверки обнаружили связанные условия:

- пауза и счётчик повторов назначались при планировании, поэтому к моменту
  фактической попытки пауза уже могла истечь;
- выбранная проверка молчащего узла считалась выполненной, даже если попытку
  отменили. Следующая проверка могла откладываться на длинный интервал;
- устаревший возраст захваченной строки не должен удалять новую строку с тем
  же ID после её повторной постановки.

Эти три проверки падали на промежуточной реализации до её доработки.

## Изменение

Каждый проход теперь отслеживает действительность захваченных строк по паре
«адресат, ID». Снятие или новая постановка кадра отменяет ещё не начатую работу
с его прежним снимком. Проверки действительности стоят перед решениями об
удалении, после ожидающих проверок адресата и непосредственно перед отправкой.
Атомарное снятие частей по подтверждению всей передачи сохраняется.

Изменения учитываются и во время чтения исходного списка. Список изменений
ограничен 256 ключами и оценкой памяти 64 КиБ. При переполнении отменяется
только этот проход; сохранённые строки остаются для следующего чтения.
Параллельный проход не запускается, а ошибка чтения освобождает проход для
следующей попытки. Состояние снимка не переживает проход или завершение сервиса.

Счётчик попыток, время последней отправки и проверка молчащего узла теперь
фиксируются при начале фактической попытки. При планировании резервируется
только место в текущем проходе, в том числе не более одной проверки одного
молчащего узла. Перед отправкой заново проверяется актуальная пауза. Значения
интервалов, jitter, ограничение 16 кадров и правила доступа не ослаблены.

Уже начатая отправка не прерывается. Отмена относится к повторным попыткам
этого прохода Outbox; устранение всех источников повторных пакетов и сетевых
задержек этим изменением не доказано. Mailbox и приоритеты реле не менялись.
Veil `4857bebc` и hidden-volume `1ea2366f` не менялись.

## Проверки

В восьми файлах прошли **159 тестов**, включая 13 новых сценариев. Анализ
изменённых файлов не обнаружил замечаний. Новые проверки покрывают:

- снятие кадра, уже выбранного за заблокированной отправкой;
- снятие во время подготовки и чтения снимка;
- повторную постановку ID с новым телом и сохранение новой строки вопреки
  старому возрасту захваченной копии;
- настоящее входящее подтверждение всей передачи, атомарно снимающее части;
- отказ чужому подтверждению с сохранением кадров другого адресата;
- завершение сервиса до начала оставшихся попыток;
- посторонние и массовые изменения во время чтения, а также восстановление
  после ошибки чтения без потери сохранённых строк;
- отсчёт паузы от реальной попытки и сохранение неиспользованной проверки
  молчащего узла после отмены старой строки.

Другие тесты проверяют прежние интервалы повторов, ограничение числа отправок,
сохранение очереди после перезапуска, авторизацию ACK, сбои атомарного удаления,
части снимков и очередь подтверждений. Новых тестовых веток, таймеров или
наблюдателей в продукт не добавлено.

## Физическая регрессия

A — Android на Wi-Fi, B — Mac той же личности, C — другой Mac другой личности.
Все online, профили с историей сохранены. Android работает в AOT/profile,
Mac — в debug; нативные test hooks и пониженная сложность выключены.
На время измерения анонимный режим выключен, прикладной P2P между личностями
запрещён. Это не исключает прямые соединения нативной сети. Прежние режимы
и политики после проверки восстановлены.

A отправляет 12 сообщений, C — шесть, включая большие тексты с обеих сторон.

| Наблюдение | Результат |
| --- | ---: |
| Все 18 сообщений видны на A/B/C | 43,5 с |
| Очередь частей синхронизации пуста | 112,3 с |
| Схождение редактирования большого текста | 9,2 с |
| Схождение удаления | 15,4 с |
| Одинаковая история после холодного открытия | 1741 запись |
| Подтверждённые исходящие тестовые сообщения A / B / C | 11 / 11 / 6 |
| Дубли логических ID | 0 |

Тела больших сообщений, идентификаторы и порядок совпали. Остальная история
после удаления сохранилась. На B один исходный обычный пакет C был получен
повторно; видимое сообщение осталось единственным. Повторы частей снимков
также остались. Это отдельные сетевые наблюдения, а не доказательство
исправления всех причин повторов или долгой доставки.

В предыдущем прогоне получены 66,8/134,2 с. Сравнение последовательных прогонов
с растущей историей и меняющейся сетью не доказывает ускорение. Устранение
повтора по уже снятому снимку проверено отдельно управляемыми тестами.
После мутаций на B оставался один служебный кадр `p2p`; пустая очередь частей
не означает пустую очередь всех кадров.

Приложения закрыты. Независимый аудит **195** записанных групп процессов,
Android-пакета и его ADB/VM-пробросов не нашёл оставшихся процессов или
пробросов стенда. При первой проверке старый номер группы был повторно
использован системной службой macOS; её принадлежность проверена отдельно,
служба завершилась сама. Условия итогового аудита не ослаблялись.

Сводные значения приведены в [summary.json](summary.json). Приватные журналы,
идентификаторы и тела сообщений в документацию не включены.
