# Последовательное ожидание сертификатов семейства — 2026-10-30

Базовая SDK `bdd149c4`, исправление `2511c796`. Продолжение разбора [недоставленного предложения файла
Android → Mac](../cert-slot-binding-2026-10-30/README.md). Подтверждён отдельный
дефект масштабирования поиска сертификатов; связь с той физической недоставкой
ещё не доказана.

## Что воспроизведено

Обычная отправка на личность через `send_family_relay_copies` использует общий
30-секундный source deadline. До передачи она ждёт `resolve_device_certs`.
При неполном кэше тот вызывает `fetch_verified_certs`: документ, реестр и
затем сертификаты экземпляров. Последние запрашивались **последовательно**.
Даже при локально сохранённых валидных записях каждый поиск сравнивает ответы
доступных реплик, чтобы не предпочесть старый материал более свежему.

В регрессионном тесте все подписанные записи есть локально, один зарегистрированный
держатель принимает запросы, но не отвечает. Реестр содержит максимальные
разрешённые **16 экземпляров**; это синтетический реестр, не 16 физических устройств.
Настоящий resolver на прежнем коде **не завершает поиск за 30 виртуальных секунд**.
Отмена по deadline очищает pending. Реальный IPC, ratchet seal и доставка кадра
в этом тесте не запускаются: проверена именно стадия поиска, ожидаемая IPC.

Последовательная структура даёт два metadata-окна и 16 certificate-окон: при
трёхсекундном step timeout это 54 с без внешней отмены. Это расчёт по структуре
прежнего пути, а не измеренная длительность исходного физического сбоя.

## Исправление

До **четырёх** независимых certificate-walk выполняются одновременно.
`buffered(4)` сохраняет порядок реестра в возвращаемом результате. Задачи не
отделяются от вызывающего future: отмена сбрасывает все активные walks, их
RAII guards удаляют только собственные pending IDs. Подписи, привязка к DHT-слоту,
freshest-wins в каждом слоте, mirror repair, сохранённые сертификаты и счётчики
expired/unknown сохраняют прежнюю обработку.

Число запросов завершённого поиска не увеличивается; увеличивается одновременность.
Один поиск семейства держит до четырёх certificate-walk, каждый с прежним лимитом
до восьми реплик: до 32 pending certificate queries вместо восьми при полном
fan-out. Глобальный лимит pending не менялся. Это ограниченная дополнительная
нагрузка на DHT, которую ещё нужно квалифицировать под параллельными отправками.
Timeouts, admission, wire/C ABI, ratchet-барьеры, mailbox и relay QoS не менялись.

В описанном тесте новый код завершает поиск всех 16 сертификатов за **18
виртуальных секунд**: два metadata-окна и четыре волны certificate-walk. Это не
обещание 18 с для сети: checkpoint хоста, локальные очереди, дальнейшие seal/send,
общая нагрузка и иные этапы здесь не измеряются. Поиск одного экземпляра не
ускоряется этой правкой. Результаты и ограничения: [summary.json](summary.json).

## Доказательства и проверки

Три финальных регрессии проверены на прежнем production-коде и затем на исправлении:

| Проверка | Прежний код | Исправление |
| --- | --- | --- |
| Шесть экземпляров, запросы до первого ответа | Только один запрос; проверка падает | Волны 4 + 2, превышения лимита нет |
| Отмена ожидающего поиска | Активен один слот вместо четырёх; проверка падает | Четыре активных слота очищаются при отмене, store пуст |
| 16 экземпляров и молчащая реплика | Истекает source budget 30 с | Все 16 результатов за 18 виртуальных секунд, pending пуст |

Первый тест отвечает в обратном порядке. Для каждого слота удалённая подписанная
v2 побеждает локальную v1, mirror содержит правильную v2, итоговый вектор следует
реестру. Наблюдение очередей выполняется после всех немедленных self-wake polls:
один ручной `poll` не гарантирует запуска всех futures из-за cooperative yield
в `FuturesUnordered`. Финальные стражи перепроверены на baseline с этим же
исполнителем; они не используют wall-clock пороги или sleeps.

Прошли **51 resolver-тест**, **745 runtime-тестов** (11 ignored отдельно),
**326 FFI unit-тестов** (2 ignored отдельно). Внутренний subprocess FFI не
прибавлен; 5 ignored doctests отдельно. FFI flags: `--no-default-features
--features node-embedded,production-seeds,packet-tunnel`. Добавлен только
test-only feature `tokio/test-util` для управляемых часов. Rustfmt, diff-check
и Clippy runtime `--lib --tests -- -D warnings` прошли. Внешний target проверялся
по mount и device до/во время сборок; исчезновения mount не было.

Физические приложения, телефон и реле в этом цикле не запускались/не менялись.
Проверки через мобильного провайдера, параллельной нагрузки и актуальной обратной
доставки остаются впереди. Не закрыты «33%», Windows 10, quiet audio, естественное
завершение звонка около 25 с, Android sleep, legacy group tails и полная multi-device
матрица. Push/релиз не выполнялись.
