# Windows: камера в текущем приложении и права публичного комплекта

Исходная жалоба Windows 10 остаётся открытой: одна выбранная камера, звук и
аватары работают, видео с ПК не приходит. Доступный физический стенд — Windows 11,
а не устройство пользователя. Его результат не доказывает устранение жалобы.

## Подтверждённый механизм

В текущем Windows frontend камера не открывалась: local/encoded/remote frames = 0.
Тот же native engine отдельно захватывал кадры. Добавленная operator-only
диагностика показала отказ `IMFActivate::ActivateObject`, HRESULT `0x80070490`,
до захвата и отправки видео. Перечисление камеры не доказывало доступность захвата.

Тестовый комплект лежал в каталоге с ACL только для пользователя. Контроли
с одинаковыми EXE/AOT/native-байтами дали следующую картину. Каждый звонок
наблюдался 22 с, камера выключалась и включалась снова; снимки счётчиков
асинхронные, поэтому их разность не трактуется как число сетевых потерь.

| Контекст файлов программы | Сторона Windows | Encoded Windows | Decoded Mac | UI-кадры Mac |
|---|---|---:|---:|---:|
| Только пользователь, исходный каталог | Вызывающая | 0 | 0 | 0 |
| Копия с обычными правами пользовательского каталога | Вызывающая | 150 | 148 | 148 |
| Возврат в исходный каталог, только пользователь | Вызывающая | 0 | 0 | 0 |
| Исходный каталог + SYSTEM ReadAndExecute для программы | Вызывающая | 128 | 127 | 126 |
| Те же права | Принимающая | 148 | 147 | 146 |

Добавление SYSTEM read/execute **только bundle** восстановило захват в исходном
каталоге. Контейнер, профиль, исходники и ключи не получали этих прав. Подтверждена
зависимость активации камеры от доступа SYSTEM к программе на этом стенде;
внутренний путь Windows FrameServer отдельно не трассировался.

Тот же шаблон найден в release-export: `_publish_directory` применял к готовой
программе owner-only защиту исходной workspace. Исправлен только экспорт
проверенного публичного комплекта: пользователь сохраняет FullControl, SYSTEM
получает наследуемый ReadAndExecute без записи. Приватные workspace и debug
symbols по умолчанию сохраняют прежнюю owner-only ACL. При отказе ACL старый
результат не заменяется.

В физическом контроле права bundle менялись отдельно оператором; новый export
helper проверен настоящими Windows ACL-тестами, а не полным повторным выпуском.

## Квалификация и границы

- Windows frontend — исходники `077282bb`, 1484 проверенных входных файла.
  AOT собрана заново, runner source относительно сохранённого EXE не менялся.
  После компиляции AOT home-source URI = 0.
- SDK — выпущенная native Rust библиотека; её Rust-исходники не отличаются
  от текущей SDK. HV — отдельная сборка совместимого prepared API. SHA реально
  загруженных трёх библиотек проверены.
- Windows media DLL: `297d656288105d2c9992920e5f767e6b681a4b0405b10696e3be33094c08c47b`.
  Native source digest:
  `493231cb7058a85befc03719df306ac338bf0e962f17a49c689cb703a9cf9891`.
  Новая DLL отличается от прежней квалифицированной версии диагностикой, без
  изменения ABI и формата пакетов. Полная native-компиляция прошла.
- Приёмник Mac — сохранённая AOT другого frontend, с выпущенными native
  библиотеками. Это проверка текущего **Windows** frontend, не обоих текущих
  клиентов. Камера Mac и микрофоны выключены; кадры/звук не записывались.
- Три положительных звонка прошли проверку роста кадров после OFF/ON и
  сохранности call ID. Все фактически работали через relay. Разрешённый P2P
  в последнем звонке перешёл на relay; P2P этим раундом не квалифицирован.
- Два отрицательных контроля квалифицированы как отказ захвата, не как
  успешные видеозвонки. Три независимых C ABI контроля захвата дали 47/49/47
  preview-кадров, включая GUI-сеанс и запуск audio перед camera.

Настоящий Windows ACL-тест на старом экспортере: **11 PASS / 1 FAIL / 0 ERROR**,
отказ именно по отсутствию SYSTEM ReadAndExecute у каталога и файла. После
исправления: **18 PASS / 0 skipped** (export + private workspace), включая
отсутствие SYSTEM Write и сохранение предыдущего результата при отказе ACL.
На Mac: **17 PASS / 1 skipped**; пропущена Windows-only проверка отказа ACL.
Проверки native provenance: **6 PASS**. Подготовка отдельного контейнера
приёмника: **1 PASS**; это fixture-проверка, не дополнительный видеозвонок.

Первые попытки подготовки Windows Python-теста не засчитаны: системный alias
не был интерпретатором, затем не хватало pubspec fixture для планов builder.
Для зачтённого baseline использованы настоящий Python и полный набор fixtures;
12 тестов выполнились, единственным отказом стала проверка SYSTEM ACL.

Две новые категории native-лога — отсутствие mounted video source и отказ
активации с числовым HRESULT; также отмечается отсутствие выбранного источника.
Имена/ID устройств в эти записи не добавлены. Лог включается только существующим
`VEIL_MEDIA_DIAG_PATH`, остаётся приватным операторским файлом и не включается
в анонимный diagnostic export. По умолчанию этот файловый лог выключен.

Полная release-сборка с новым экспортером в этом раунде не выпускалась.
Попытка экспортировать приватный QA-комплект корректно остановлена действующим
privacy gate: 13 home-path совпадений вне Dart AOT (одно в сохранённом plugin DLL,
12 в журнале собственного стенда). Этот комплект не считается
публичным release-артефактом; проверка AOT сама по себе недостаточна. Перед
публикацией нужны обычный neutral builder, artifact scan и обновление media pins.

Собственные приложения, probes и туннели завершены; PID/группы и порты проверены,
свои Scheduled Tasks и временные профили удалены. Mac-приложения после восьмисекундного
ожидания потребовали SIGKILL; это остановка стенда, не проверка graceful shutdown.
Удалено около 2 ГБ Windows build cache и 104 МиБ Mac-копий.
Установленные пользовательские приложения и production-узлы не менялись.
Исходный Win10 остаётся предметом повторной проверки с его камерой и новой сборкой.
