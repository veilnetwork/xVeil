# Ожидания между страницами архива на 100000 сообщений

## Измерение

В предыдущем native A/B/A интервал между полным ответом страницы и следующим
запросом у источника оставался около 167–169 мс. Эта величина включала приём,
ожидание очереди разговора, проверку/применение, публикацию, durable cursor,
подготовку следующего запроса и доставку; называть её временем БД было неверно.

Добавлен **только stand-наблюдатель** `PrivateHistoryWorkProbe`. Он принимает
три фиксированных имени этапов: `historyApply`, `historyPublish`,
`historyCheckpoint`. Параллельные row callbacks превращаются в один busy span
от первого начала до последнего завершения. Перекрывающиеся ожидания 64 строк
не суммируются как затраченное wall time. Тестовый storage adapter оборачивает
настоящую запись курсора, сохраняя её значение, ошибки и границу завершения.

Opt-in: `XVEIL_E2E_HISTORY_WORK_TRACE=B` вместе со storage census и приватным
evidence directory. Наблюдатель не принимает идентификаторы, пути, тексты,
payload или исключения. Бюджет — 20000 границ интервалов на boot, с явным
счётчиком dropped и активных операций в footer. Закрывается после messaging,
stack и storage. Production imports, protocol, авторизация, publication cap,
durable cursor и запрет sibling mailbox не менялись.

## Native-кейс

Четыре Mac/JIT процесса, три изолированных Core, настоящий FFI/ratchet/HVS.
Три устройства одной личности, два независимых полных источника архива;
первое применение удержано до authenticated ответов обоих источников.
Архив — 100000 сообщений плюс одна прежняя строка. Observer — компактный,
каждые 5000 мс. CPU sampling и VM timeline выключены.

**100001 строка совпала полностью**: IDs, текст, delivered, canonical positions,
порядок, отсутствие пропусков/дублей/лишних строк. Оба cursor завершены.
Отдельный cold boot без всех источников сохранил тот же полный набор.
200002 historyApply callbacks, 1563 message commits; по 782 страницы каждого
источника. Apply release → финальная проверка — **235512 мс**. Это один
диагностический запуск, не A/B и не доказательство дальнейшего ускорения.

## Разложение интервала

Приватные request IDs существующего wire probe связывают ответ с последующим
запросом. Из 1564 page intervals однозначно связаны **1520**. Ещё 44 исключены:
когда временные границы не дают однозначного соответствия, оно не достраивается.
Для каждого принятого интервала сумма шести последовательных частей точно
равна полному интервалу.

| Часть интервала | P50, мс | P95, мс |
|---|---:|---:|
| Полный ответ → первый apply callback | 33,614 | 155,288 |
| Busy intervals apply callbacks | 50,364 | 134,112 |
| Промежутки между apply-волнами | 5,636 | 19,544 |
| Последний apply → начало записи курсора | 4,237 | 18,542 |
| Запись курсора через storage adapter | 14,947 | 26,978 |
| Конец записи курсора → следующий query у источника | 4,247 | 78,046 |
| **Полный интервал** | **164,566** | **237,974** |

Медианы строк не складываются в медиану итога. Интервалы разных источников
перекрываются: суммы по всем страницам не являются wall time всего кейса.
До первого callback включены сборка/проверка ответа, authorization и очередь
разговора; после cursor — подготовка и доставка. Это не чистые CPU/fsync/
сетевые метрики. Все часы — наблюдения одного host; clock uncertainty не
выдаётся за микросекундную точность сетевой доставки.

В полном measured window apply busy spans заняли около **107,8 с**; вложенные
публикации — **61,1 с**, cursor spans — **26,3 с**. Публикации уже включены
в apply, поэтому складывать эти три числа нельзя. Подтверждено, что cursor
не объясняет всё ожидание. Следующий участок — подготовка/очередь до callback
и работа внутри apply; свежие проверки доступа остаются обязательными.

## Проверки и уборка

**221 related passed / 0 skipped**, включая семь новых проверок: overlapping
callbacks, сохранение результата/ошибки, whitelist имён, cap/footer, неверный
бюджет без открытия файла, idempotent close и реальные cursor writes без
утечки значений. Analyzer чист. Первый выбор тестов содержал два неверных
пути; исправленный набор выполнен полностью, ошибки загрузки не засчитаны
как пройденные тесты. Отдельный native-кейс прошёл.

Все четыре boot-сегмента work trace закрыты, dropped=0, active=0;
12522 записи занимают около **1,09 МиБ**. Wire/census также не обрезаны.
**1529 source inputs** заморожены и перепроверены; native SHA/mappings прежние,
Rust не собирался. Cleanup проверил 38 PID/59 портов: owned процессов/listeners
нет, synthetic runtime удалён.

Cache snapshot после запуска driver и итог: **92→92**, новых entries 0;
это не замер состояния до старта driver. Кэш не чистился во время прогона.
Свободно около 149 ГиБ. Только агрегаты в [summary.json](summary.json),
raw evidence приватен. Latency остаётся активной; физическая/AOT квалификация,
NETCALL-01 и оставшаяся multi-device matrix не закрыты. Push/релиза нет.
