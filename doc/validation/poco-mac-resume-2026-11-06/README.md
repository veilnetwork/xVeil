# Poco → Mac: физическая проверка ticket resume и смены сети

Продолжение [native-исправления допуска resume](../relay-resume-predecessor-2026-11-06/README.md).
Windows отключена владельцем. Проверены Poco / Android 16 и MacBook,
настоящие независимые QA-личности, скрытые контейнеры, подтверждение контакта.
Оба клиента и отдельное QA-реле используют Veil `ade3130a`.
**NETCALL-01 остаётся открытым:** замена predecessor работает на реальном
подключении, но длительная пауза внутри звонка сохранилась.

## Стенд и границы

- Один отдельный Core с obfs4/TCP, собственными ключом транспорта, identity,
  конфигом, портами, state и systemd-unit. Нет связей с production-реле.
  На том же сервере production PID, executable/config SHA и NRestarts
  проверены до/после установки, работы и удаления QA-сервиса.
- Android profile/AOT и Mac profile/AOT из текущего frontend. Операторский
  peer-файл Mac и seed-assets Android содержат только QA-Core; native Android
  собран с `allow-empty-seeds,node-embedded,packet-tunnel`, без builtin seeds.
  Mac отклонил общий поиск узлов, получил отдельный операторский peer.
  На обоих контактах заранее запрещён P2P; call state показывает relay.
- ABI hidden-volume проверяется самим opener. Сначала по ошибке была выбрана
  прежняя Mac-библиотека без `read_log_groups`: runtime отказал до открытия.
  Она пересобрана из чистого `eceb9158` в отдельном внешнем target;
  после этого контейнер и настоящий узел успешно открылись.
  Неудачный запуск не засчитан как проверка сети.
- Сохранены SHA выбранных native-библиотек, APK и AOT, source/feature proofs.
  Оба маркера нового resume проверены в клиентских и серверном артефактах.
  Внешняя ФС проверялась watchdog; mount не терялся.
- Mac запускался с `TMPDIR=/private/tmp/`, ad-hoc подписью и отдельными
  QA-entitlements без неиспользуемого в этом стенде Network Extension.
  Production entitlements не менялись.

## Ограничение аудиопроверки

Первый исходный контроль **не прошёл**: Mac принимал аудио телефона, но
ожидал системное разрешение на собственный микрофон и не отправлял аудио.
Отсутствие двустороннего baseline не принято за успешный тест.

Последующий прогон — **телефон → принимающий Mac**, не двусторонняя проверка
звука. Во время этого прогона микрофон Mac явно выключен через обычный
call-service path, уже после начального baseline; точные действия сохранены
в приватных журналах. Baseline требует свежий native RX на Mac и свежую
постановку TX на телефоне пять последовательных срезов. Проверяются также
тот же call ID, active, running и отсутствие worker stall. Человеческая
слышимость и захват микрофона Mac не проверены. Из-за этой границы и отсутствия
A/B результаты не доказывают улучшение или регрессию к прежним Windows-сериям.

## Результаты

| Наблюдение | Значение |
|---|---:|
| ОС телефона: validated cellular после команды Wi-Fi off | 1,345 с |
| Наибольший наблюдаемый интервал без fresh native RX на Mac | 18,458 с |
| Начало этого интервала после Wi-Fi off | 3,861 с |
| Начало пяти последовательных fresh RX после этого интервала | 22,319 с |
| Максимальный наблюдаемый native RX age | 12 944 мс |
| Новый звонок сразу после Wi-Fi off: входящий на Mac | 2,243 с |
| Новый звонок: окончание пятисрезового baseline | 18,113 с |

Оба сценария завершены; во всех срезах наблюдался ожидаемый call ID.
Звонки завершены командами стенда, неожиданный отбой не наблюдался.
В возврате на Wi-Fi ОС вновь подтвердила validated WIFI.

Пара ранних пакетов после отключения Wi-Fi **не** принята за восстановление:
после них RX снова остановился. В длинном интервале счётчик RX стоял,
native age рос, затем media running временно стал false; восстановление
сопровождалось сменой media epoch 7 → 9. В devlogs обоих концов присутствуют
`silent relay receive — local repair`. На Mac повторный permission preflight
также ждал свой трёхсекундный предел. Этим событиям не приписывается вся пауза:
почему существующий канал не продолжил приём до локального ремонта, неизвестно.

В ограниченном журнале QA-Core: **3 `session.resume_replace`**, все с префиксом
тестового телефона, **0 `session.dedup`**. Это физическое подтверждение работы
узкой ветки нового допуска, а не доказательство доставки каждого аудиопакета.
Нет общей поклеточной атрибуции или синхронизации часов реле с endpoint.
Все интервалы таблицы — часы одного Mac, monotonic; ОС-сеть опрашивалась
отдельно примерно раз в секунду, media — примерно раз в полсекунды.

Следующий участок NETCALL: разделить восстановление сессии, пригодность
старого datagram-канала и локальный media repair. Повторить с заранее
разрешённым микрофоном Mac, чтобы исключить ожидающий OS prompt и получить
двусторонний baseline. Таймеры молчания не уменьшались для маскировки паузы.

## Исправленный дефект диагностического интерфейса

На настоящем Mac profile/AOT запрос `/screenshot` падал с
`LateInitializationError` из `RenderObject.debugNeedsPaint`:
это свойство Flutter инициализирует только внутри assertions.
Теперь profile-hook ждёт кадр без чтения assertion-only свойства;
в debug сохранена проверка dirty tree. На пересобранных profile-клиентах
получены настоящие PNG, включая экран onboarding; на Mac первый контрольный
PNG — 34 558 байт. Пять существующих screenshot/gate-тестов прошли,
analyzer без замечаний. Unit-тесты не объявляются воспроизведением profile-падения;
red/green здесь — реальный profile endpoint до/после.

## Завершение и приватность

- Прежний QA APK телефона восстановлен и сверен по SHA; SHA основного APK
  с исправленным отпечатком и старого QA-контейнера не изменились.
  Wi-Fi, mobile data и awake-setting восстановлены; validated WIFI проверен.
- Свои процессы закрыты, ADB forward удалён, локальные порты освобождены.
  Mac сначала получил SIGTERM; ожидающий разрешения процесс не завершился
  за grace, затем остановлен адресным SIGKILL после проверки PID/executable.
  Пользовательские приложения не закрывались.
- QA relay остановлен; собственные state/runtime/config/binary/unit и upload
  staging удалены, порты освобождены. Production PID/бинарник/конфиг и
  NRestarts остались прежними. Production-реле не обновлялись.
- Удалён свой frontend build staging (~2,9 ГБ до выделения сохранённого app)
  и временный runtime. Сохранены артефакты/доказательства в приватном cache.
  При архивировании runtime-created debug log вынесен из app; main bundle
  переподписан для хранения, native/AOT SHA до/после совпали.
  Этот архивный executable не выдаётся за побитно тот же подписанный executable,
  который участвовал в звонках; оба SHA записаны отдельно.
- Здесь нет ключей, node/device/call IDs, адресов, сертификатов или сырых
  журналов. Push, публичного релиза и изменения engine pins нет.
