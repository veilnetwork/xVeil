# Отклонённое увеличение частей own-history и разложение задержки

2026-11-04. Продолжение разбора медленной первичной догрузки. Mailbox для
собственных устройств не добавляется; доступный держатель истории необходим.
Все стендовые данные синтетические, здесь только агрегаты.

## Подтверждённая стоимость

В предыдущем native crash/reconnect прогоне на текущей HVS все 73 входящих
запроса последнего запуска A сопоставились с полными ответами на B:
2 inventory и 71 page, 143 части. По часам одного Mac:

| Интервал | Сумма | Медиана | Максимум |
| --- | ---: | ---: | ---: |
| Запрос у A → первая часть у B | 12,805 с | 169,21 мс | 476,89 мс |
| Первая → последняя часть ответа у B | 0,745 с | 10,24 мс | 18,10 мс |
| Последняя часть → следующий запрос у A | 30,883 с | 450,57 мс | 494,51 мс |

Последний интервал включает обработку/сохранение B, проверки текущих устройств
и подготовку/доставку нового запроса. Это не эксклюзивное CPU-время или чистая
сетевая задержка. Главное остаточное ожидание находится здесь; размер частей
сам по себе не объясняет весь дефект.

## Проверенный и отклонённый вариант

Временный кандидат делил payload по 3072 вместо 2048 байт, с проверкой полностью
закодированного carrier против безопасного inline-лимита 4500 байт. 4 КиБ
не использованы: base64 и framing превышают эту границу. Общая страница
независимо ограничивалась прежними 128 КиБ; проверки списка устройств,
revocation, durable cursor и отдельные record/admission budgets сохранялись.

В контрольной странице с восемью длинными сообщениями требовалось 17 вместо
25 частей. 127 связанных тестов и analyzer прошли. Точный page budget также
проверен: 128 КиБ приняты, один лишний байт отвергнут; при временном удалении
sum guard этот контроль падал из-за сохранённого cursor.

Но на реальной короткой истории восемь событий всё равно не помещались в одну
часть. Финальная native-серия на тех же замороженных библиотеках показала:

| Показатель | Предыдущий 2-КиБ прогон | Временный 3-КиБ прогон |
| --- | ---: | ---: |
| Строк после crash до сети | 1594 | 1572 |
| Ответов последнего boot A | 73 | 75 |
| Частей этих ответов на B | 143 | 147 |
| Все строки после готовности A | 45,992 с | 46,092 с |
| Полная сходимость после готовности A | 51,111 с | 56,315 с |

Это не строгий performance A/B: частичные копии различались, poll около пяти
секунд. Ускорение не обнаружено, причинная регрессия тоже не доказана.
В обоих случаях все 2000 ID/порядок/source positions/delivered сошлись,
retention после запуска без A/C чистый, completed-history retries ноль,
invalid snapshot не наблюдался. SIGKILL, sparse-копия и prefix fallback реально
выполнены. Кандидат проверен без изменения production native artifacts.

**Изменения размера carrier и их тесты возвращены к исходной версии.**
Diff и точные исходники кандидата сохранены только как частное свидетельство.
В рабочий протокол увеличение частей не включено. Общая latency остаётся
открытой, а следующий участок — обработка/проверки между полным ответом и
новым запросом, а не доставка поздних частей.

Teardown кандидата успешен: 27 собственных PID, 37 портов, процессов/listeners
не осталось, runtime удалён, 1406 frozen source/dependency files и native SHA
сошлись. Реальные пользовательские контейнеры не открывались.

## Следующий замер

Добавлены только test-fixture обёртки настоящих `ownHistoryApply` и
`ownHistoryEncode`, с фиксированными allowlist-метками. Они сохраняют результат,
исключение и завершение production callback, следуют за rebind провайдера и
не добавляют альтернативный applier. В snapshot попадают inclusive timings
и RPC, не события, ID, тексты, пути или ошибки. Вложенные контексты нельзя
суммировать как эксклюзивное CPU/I/O-время.

Первый прогон атрибуции восстановил все 2000 ID/позиций/delivered и retention,
но **не прошёл полный стендовый qualifier**: sparse-копия после SIGKILL не
наблюдалась. Это не объявляется прохождением ветки с дырой и поздним хвостом
или ускорением прежнего случая. Обёртки действительно выполнялись:

- A: 403 `historyEncode`, суммарный inclusive await 15,902 мс.
- B: 403 `historyApply`, inclusive await 6640,017 мс; внутри — 454 завершённых
  `kv.commit` с inclusive await 6494,431 мс.
- B: 1142 `ownDevices`, inclusive await 16 393,453 мс; 1132 grouped payload RPC
  из этого контекста — 6533,495 мс. Эти интервалы могут перекрываться.

Итак, plaintext encode не оказался большим расходом. Время applier почти
полностью находится в durable commit; одновременно велика стоимость свежих
own-device lookups. Подмена этих проверок кэшем разрешений не выполняется.
Физические I/O/fsync и CPU/fold нуждаются в дальнейшем разборе.

## Зачтённый повтор атрибуции

Повтор на неизменных исходниках прошёл весь строгий qualifier: после SIGKILL
до сети B удержал 1598 строк, включая сто поздних provisional rows за дырой.
A/C были offline при запуске B, затем вернулся только A; prefix fallback
реально использован. Все 2000 ID, порядок, source positions и delivered сошлись,
invalid snapshot не наблюдался, completed-history retries ноль. После нового
запуска без A/C все данные сохранились. Сходимость после готовности A — 46,023 с.
Размер частей исходный, production-код не менялся; причинного ускорения здесь
нет, время нельзя приписывать диагностическим обёрткам.

| Вызовы в recovery window | Количество | Inclusive await |
| --- | ---: | ---: |
| A `historyEncode` | 559 | 22,405 мс |
| B `historyApply` | 559 | 7612,557 мс |
| `kv.commit` внутри B `historyApply` | 510 | 7365,272 мс |
| B `ownDevices` | 1751 | 23 880,486 мс |
| Grouped payload RPC внутри B `ownDevices` | 1633 | 9340,377 мс |

72 запроса A сопоставились с 72 полными ответами, 142 части. Сумма
request→first part — 11,584 с; first→last part — 0,760 с;
last part→next request — 29,486 с. Это подтверждает направление разбора,
но включающие интервалы и контексты нельзя складывать в физическую стоимость
CPU или диска. Следующий участок — повторное свежее чтение и материализация
device journal; отдельно остаётся цена durable apply. Общая latency не закрыта.

12 тестов fixture/census/wire probe прошли; analyzer четырёх изменённых
test-only файлов чистый. Проверены сохранение результатов/исключений callbacks,
reset во время ожидания и отбрасывание произвольных диагностических меток.
В зачтённом native-прогоне обязательны ненулевые реальные encode/apply counters
и RPC из apply-контекста. Измерение не принято по одному факту зелёного теста.

Независимый teardown: 27 собственных PID и 29 портов проверены, процессов и
listeners нет, runtime удалён. 1406 frozen source/dependency files и native SHA
не изменились. Все три стенда цикла закрыты; первый замер атрибуции остаётся
отдельно помеченным как не прошедший sparse-предусловие.

Граф кода обновлён AST-only. Инструмент сохранил 10 старых узлов от существующих,
но исключённых фильтрами файлов и сообщил о 1139 файлах без извлечённых узлов;
полнота графа не использовалась как доказательство. Все приведённые механизмы
проверены непосредственно по исходникам и runtime evidence.

Mailbox, push, релиз, engine pins и APK не меняются. Production-файлы `lib/`
и зависимости совпадают с началом цикла; новые изменения — только тестовые
измерения и этот разбор. Mac/JIT не квалифицирует Android/AOT и полную матрицу.
