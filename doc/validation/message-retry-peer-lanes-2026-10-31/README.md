# Независимые контакты и жизнь незавершённого повтора

2026-10-31. База `55a7ad2d`, native SDK `c46d94db` не менялся.
Без push/релиза.

## Три подтверждённых механизма

После отделения control Outbox оставшийся conversation pass всё ещё обходил
контакты и сообщения последовательно. Один медленный send или ожидающая
публикация собственного журнала держали всех следующих адресатов.

Кроме того, `boundedLiveLeg` ограничивал только ожидание, не отменяя transport
future. После дедлайна цикл начинал следующее сообщение тому же контакту, хотя
предыдущая отправка ещё выполнялась; следующий pass также мог добавить работу.

Наконец, `backgroundStashPaused` проверялся только при входе в проход.
Звонок, начавшийся во время awaited записи собственного журнала, не удерживал
последующую отправку обычного сообщения.

На прежнем коде семь сценариев новой группы тестов были красными: независимый
контакт, порядок при удерживаемой первой отправке, четыре параллельных контакта,
два варианта late settlement, ожидание собственного журнала и поздний media
pause. Один контроль concurrent callers уже проходил; его не считаем красным.
Готовые microtasks проверяются event-loop barrier при закрытом gate, без
ожидания штатного 10-секундного дедлайна. Lifetime-тесты используют тестовый
нулевой deadline; product deadline не менялся.

## Изменение

До **четырёх worker jobs** обслуживают разные разговоры. Внутри одного контакта
порядок сообщений остаётся последовательным. Ошибка чтения одной истории не
бросает оставшиеся разговоры: первая ошибка сохраняется и возвращается после
завершения остальных принятых jobs.

Каждый начатый ordinary send удерживает per-peer token до фактического
завершения `_send`, включая следующее durable сохранение ratchet. После
таймаута ожидания job прекращает эту полосу; следующий pass не накладывает
новую отправку тому же адресату. Поздний успех и поздний отказ освобождают
только свой token, ошибки по-прежнему обрабатывает bounded live leg.

Четыре — предел одновременно ожидающих conversation jobs, **не общий предел
всех поздних transport futures**. Они могут пережить deadline; для них действует
одна незавершённая попытка на адресата, как в control Outbox. Новые контакты,
пакеты, таймеры или relay-visible приоритеты не создаются.

Перекрывающийся timer/reconnect/manual pass не запускает ещё четыре jobs.
Если проход уже занят, повторный вызов быстро выходит без новых conversation
jobs; исходный вызов продолжает владеть работой. Это сохраняет прежний контракт
восстановления собственного журнала.

Проверки dispose/media pause добавлены после ожиданий и до следующего send.
`prepareStoredRetry` перед публикацией сохранён. Возрастное завершение и
reconnect maintenance выполняются **до** отказа из-за занятого адресата, чтобы
долгий transport future не отключал обработку старых сообщений.

Control ceiling 16, четыре control lanes, backoff 3–24 с обычных сообщений,
control ladder и mailbox cadence не менялись. Это клиентский coordinator;
реле не узнают новый тип/приоритет трафика. ABI и wire не изменены.

## Проверки и пойманная регрессия кандидата

**320 тестов прошли, 0 skipped**, scoped analyze: no issues.
Из них 11 новых: независимые адресаты, порядок внутри контакта, предел четырёх
jobs, late success/failure после deadline, возрастное завершение при занятом
адресате, несколько concurrent callers, отказ четырёх историй с прогрессом
последующих, durable journal barrier и pause во время ожидания.

В первом широком запуске поймана собственная регрессия: coalescing возвращал
повторному `flush` future занятого прохода, из-за чего старый тест восстановления
журнала ждал удерживаемую запись и истекал через 2 с. Исправлено быстрым выходом
повторного вызова. Затем прошли targeted 23 теста и итоговые 320.
Промежуточный failed run не засчитан зелёным. Ранний hardening fixture также
имел ошибку сигнатуры test override; он не считался выполнением тестов.

Итоговый набор включает прежние outbox lanes/lifetime/invalidation,
retention/jitter/expiry, сообщение/edit/delete/ACK, journal recovery,
ratchet, realtime signals и group receipt/source queue проверки.

## Native-опыт с удерживаемой первой отправкой

Три **разные личности**, три embedded native-узла в одном Mac/JIT process,
локальный TCP fullmesh/DHT, настоящие ML-KEM/ratchet/host checkpoints и
encrypted worker-контейнеры. Accepted contacts подготовлены отдельно:
это не проверка contact handshake и **не multi-device A/B одной личности**.

У отправителя обычный receive/retry timer не запускался, чтобы второй timer
или конкурентный manual pass не обошли проверяемый порядок. Получатели
использовали обычный `MessagingService`. История отправителя с delivery ACK
этим опытом не квалифицируется; получение проверялось по сохранённым входящим
сообщениям двух получателей.

Первый разговор принудительно шёл первым в штатной сортировке по свежести.
Тестовый adapter удерживал его transport send **до native handoff**.
Вторая отправка могла пройти к настоящему native transport только после
входа в этот gate. Её plaintext сравнивался через обычную сохранённую историю,
а не счётчик mock transport.

Для опыта `liveLegDeadline=60 с`, окно наблюдения закрытого gate — 15 с:
продвижение нельзя объяснить таймаутом первой попытки. В продукте остаётся 10 с.

| Ветка | Второй получатель при закрытом первом gate | После снятия gate |
|---|---|---|
| База `55a7ad2d` | Не получил за 15006 мс; expected red assertion | Оба получили ровно по одному сообщению |
| Кандидат | Получил примерно за 218 мс; gate всё ещё закрыт | Оба получили ровно по одному сообщению |

Это **один gate-контроль на ветку**, не медиана скорости обычной сети, не опыт
потери radio/пакетов и не доказательство причин прежних физических 53/114,9 с.
218 мс включает polling истории получателя. Библиотеки, fixture и остальные
lib/test-support файлы заморожены по SHA. После переключения исходник кандидата
восстановлен побитово; итоговый тестовый запуск прошёл уже на нём.

В итоговой паре оба native host завершены, по три listener освобождены,
cleanup errors=0, оба временных root удалены. Ранняя пара до добавления точной
сверки текста также очищена; её наблюдение 196 мс не подменяет итоговые 218 мс. Адреса, ключи и correlation ids остаются в закрытом
каталоге QA; публичны только агрегаты и source/artifact SHA.

## Остаток

Не менялись 16-attempt control ceiling, retry/mailbox cadence и ожидания
внутри group handling/cold native path. При четырёх одновременно медленных
conversation jobs следующие ждут свободную полосу: этот bounded-work предел
не отменён. На телефоне, Windows и публичном onion-маршруте новая правка ещё
не квалифицирована; требуется физическая серия с текущим SDK/frontend.

Длительная доставка остаётся активной, затем — полная multi-device матрица.
Исторические 25 с / 120 с / «33%» остаются отложены до повторения.
