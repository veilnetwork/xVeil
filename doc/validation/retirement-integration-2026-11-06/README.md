# NetworkChanged: полный путь от retirement до нового шифрованного кадра

Локальная интеграционная проверка дополняет
[исправление 54c64c03](../explicit-retirement-2026-11-06/README.md):
при заблокированной записи старой сессии уведомление NetworkChanged
освобождает её транспорт, запускает новый dial без оплаты таймера,
после чего новый TCP/OVL1-сеанс передаёт аутентифицированный кадр.

**Это квалификация клиентского механизма, не мобильной сети.**
Настоящий интерфейс ОС в этом тесте не переключается; Poco отключён
пользователем. NETCALL-01 и паузы приёма звука остаются открытыми.
Новых изменений production в этом раунде нет.

SDK-коммит: `bbeaf3a9`. Результаты: [summary.json](summary.json).

## Что проверяется

Тест запускает NodeRuntime без внешних seed/discovery, один production
outbound connector и настоящий TCP-listener на loopback. Первая сессия
проходит настоящий OVL1 handshake с подписью и получением ключей.
Рассчитанная PoW-сложность снижена только тестовыми фичами.

После успешной авторизации gate блокирует запись уже установленного
первого транспорта; до этого все TCP read/write идут обычным путём.
Тест дожидается реального входа writer в заблокированный poll_write.
Удалённый конец остаётся открытым, заимствованный producer — живым.
EOF, обрыв peer и закрытие всех producer не заменяют исследуемое событие.

Далее вызывается настоящий MobileEventForwarder::network_changed с Cellular.
Виртуальные часы остановлены только на границе retirement → redial.
На current-thread executor выполняются runnable yield, без продвижения
времени. Следующий вызов Transport::connect должен наблюдать уже
освобождённый старый transport: одного удаления записи из registry мало.
Таймер writer grace и обычный 60-с backoff не могут выдать ложный успех.

После этой проверки часы возвращаются в обычный режим. Второй TCP-сеанс
проходит OVL1; тест проверяет новую live TX-регистрацию, отличающиеся
session ID и ключ, затем читает настоящий ordered frame с wire и открывает
его через SessionCipher с новым ключом/AAD. Успех не сводится к локальному
enqueue или записи в реестр сессий.

## Контроль и очистка

Отрицательный контроль удаляет только production-отмену старого writer
в explicit-retirement ветке, сохраняя тот же тест. Он должен падать на
отсутствии повторного dial без продвижения часов. Production-файл затем
возвращается побайтно; контроль не меняет пороги или криптографию.

В fixture есть внешний watchdog, который не является критерием скорости.
Успешная проверка, отрицательный контроль, timeout и panic проходят общую
очистку: свои connector handles отменяются и await-ятся, NodeRuntime
останавливается, временная конфигурация удаляется с проверкой отсутствия.
Виртуальные часы восстанавливаются и при panic внутри наблюдения.
Production test hooks и новые зависимости не добавлены.

Окончательная fixture: отрицательный контроль **0 passed / 1 assertion-red**,
после восстановления production полный runtime **811 unit + 8 integration passed**,
11 unit / 2 doc ignored. Исследуемый тест явно присутствует среди passed.
Внешняя ФС проверена и контролируется watcher на протяжении сборок;
другой checkout/dependency override не использован. Результаты в summary.
Пропущенные и отфильтрованные тесты не считаются пройденными.
Новые APK/FFI не устанавливались, приложения macOS не запускались,
production-реле не менялись. Push и релиз не выполнялись.

## Библиотеки для следующей телефонной проверки

Новые Mac и Android arm64 FFI собраны из чистого `bbeaf3a9` с фактической
пересборкой veil-session. Это тот же production-фикс `54c64c03`;
новый коммит добавляет только интеграционный тест. SHA отличаются от efe1c4ca,
у обеих сохранены 208 C exports. У Mac проверены возвращаемый ABI contract
и ad-hoc подпись, у Android — архитектура AArch64 и ожидаемый ABI hash marker.
Android ABI-функция на самом телефоне в этом раунде не исполнялась.

Библиотеки сохранены вне репозитория вместе с build receipts. Общий Cargo
cache не считается доказательством происхождения: проверены чистый commit,
фактическая пересборка зависимости, скопированные байты, exports и ABI.
Внешняя ФС оставалась смонтирована; watcher контролировал обе сборки.
На устройства ничего не устанавливалось.
