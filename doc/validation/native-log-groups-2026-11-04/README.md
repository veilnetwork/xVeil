# Ограниченное native-чтение групп журнала — 2026-11-04

## Подтверждённый механизм

Dart worker уже объединял exact-ID чтения, но native слой заново расшифровывал
и распаковывал один DataBatch для каждой запрошенной записи. На прогретом
индексе 32 записи из общего batch давали 64 чтения chunks и при отдельных
чтениях, и при наивном групповом API. Это лишняя работа внутри одного вызова,
а не сетевое ожидание и не доказанная причина всех секунд догрузки.

HVS `0cd7f6316d37037cdbe1af592b25aa23eac93b29` добавляет exact-ID группы с
общим **только на время вызова** кэшем расшифрованных batches. Worker xVeil
использует эту возможность через `HvKvLogStore`; scalar fallback и виртуальные
переопределения async-адаптера сохраняют прежний контракт.

Ограничения: 8 групп / 64 запрошенные записи, отдельный byte ceiling каждой
группы, точный порядок и дубли ID. Отсутствующая/слишком большая запись
останавливает вызов до чтения последующих ID. Range scan не используется.
Существующий кэш ограничен 64 batches / 8 МиБ; частичные результаты и decoded
batches обнуляются при освобождении. Output заранее резервирует ограниченный
объём, максимум 64 максимальных payload, без realloc незачищенного plaintext.
Каждая свежая индексная ссылка проверяется по фактическому digest сжатых
байтов, включая cache hit после legacy-ссылки. Между вызовами кэш не живёт;
авторизация, ratchet и durable ACK не менялись.

## Проверки

- Красный контроль: 64 chunk reads против 64 у scalar; усиленный тест требует
  экономии минимум 31 чтения для 32 записей и падает на наивной реализации.
  Первый слабый контроль экономил лишь прогрев индекса и **не зачтён**.
- После изменения: 660 Rust core тестов прошли, 2 ignored; 35 FFI тестов
  прошли. Проверены sync/async и явный multi-space, изоляция одинаковых ID,
  ранний отказ и digest на cache hit. fmt/clippy/API inventory чистые.
- Flutter plugin: 122 теста прошли на выбранной native-библиотеке;
  analyzer чистый, checksum-таблица проверена (45 entries).
- xVeil: 621 тест прошёл, 3 skipped; analyzer затронутого кода чистый.
  Четыре отдельные native-проверки hash integrity прошли, включая настоящий
  worker с повреждённой второй ссылкой в уже декодированном batch.
- Первая попытка plugin-теста выбрала посторонний cached dylib и была
  остановлена ABI-проверкой до открытия контейнера. Она **не зачтена**.
  Последующие запуски явно проверяют provenance выбранной библиотеки.

## Изолированные измерения

Одна библиотека, одни данные, последовательность scalar → groups → scalar,
все байты проверены на каждой итерации. 32 записи, 60 повторов:

| Данные | Scalar A₁ | Exact groups | Scalar A₂ |
|---|---:|---:|---:|
| Сжимаемые | 285,400 мс | 80,690 мс | 272,120 мс |
| Псевдослучайные | 124,512 мс | 100,384 мс | 119,539 мс |

Через настоящий worker и AsyncFileStore: три файла по 60 000 байт,
50 повторов; 347,158 → 169,444 → 331,388 мс. Отдельных payload RPC 150 → 0 → 150,
групповых 0 → 50 → 0. Дополнительно проверены свежесть изменённого файла,
отсутствующий файл и отказ по byte ceiling. Это замер **чтения**, не всей
миграции истории; проценты глобального ускорения из него не выводятся.

## Полный native crash/reconnect

Зачтён реальный A/B/C native stand: 2000 сообщений, SIGKILL B при неполной
догрузке (1532 строки до kill; 1549 после локального восстановления). Сохранились
85 поздних записей за дырой, с временными provisional positions. Сначала A/C
offline, затем вернулся **только A**. Выполнен непустой fallback-prefix запрос.
Все 2000 ID, порядок, авторские positions и delivered сошлись; лишних completed
history retries — 0. После нового перезапуска B результат сохранён без A/C.
Недопустимых snapshots не наблюдалось.

После готовности A до полной сходимости — **51,122 с**. В предыдущем прогоне
было 46,023 с; это не одинаковые объёмы работы и не A/B: после crash тогда
оставалось 1598 строк / 100 поздних, сейчас 1549 / 85. После restart B выполнено
616 history-apply против 559 ранее и 2777 own-device lookup против 1751.
Глобальное ускорение **не подтверждено**, latency остаётся открытой. Inclusive
await этих контекстов может перекрываться: его нельзя суммировать как CPU/I/O.
Компонентный A/B/A выше подтверждает снятие повторной распаковки, но не объясняет
все секунды и разницу между двумя большими прогонами.

Независимый teardown: 27 owned PID завершились, 36 портов проверены,
оставшихся listeners нет, runtime root удалён. 1406 frozen input files,
исходники зависимостей и native SHA не менялись во время stand.

## Границы

Проверена частная macOS-библиотека и исходники. Добавлен FFI-метод, поэтому
Dart bindings и native artifacts должны собираться вместе на всех целевых
платформах перед публикацией. ABI checksum gate сохранён; старый dylib с новыми
bindings отвергается. Контейнерный формат и сетевой wire не менялись.
Android/AOT и вся multi-device матрица этим измерением не квалифицированы.
Owned Rust target очищен с проверкой отдельной внешней файловой системы
и маркера принадлежности; освобождено около 749 МБ. Частная выбранная библиотека
сохранила SHA, после очистки повторно прошли 5 native cases (4 hash + FileStore).
Удалён только собственный изолированный checkout; основной submodule чистый.

Mailbox для собственных устройств не добавлен. Push, релиза, установки APK,
обновления engine pins и production-реле в этом цикле нет.
