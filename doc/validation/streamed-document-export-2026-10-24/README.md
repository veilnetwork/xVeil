# Потоковый экспорт архива в выбранный документ — 24 октября 2026

Продолжение проверки сохранения сертификатов из R29. Найден самостоятельный
дефект в «Данные и хранилище → Экспорт»: этот экран всё ещё вызывал
`FilePicker.saveFile` без `bytes`. Закреплённый file_picker 11.0.2 на Android/iOS
выбрасывает `ArgumentError` до открытия диалога. Вызов находился вне `try`.
Возвращённый мобильным провайдером документ также нельзя считать обычным
путём для `File.openWrite`.

## Исправление

* Экран передаёт результат настоящего `DataExporter` прямо в выбранный документ.
  Канал передаёт порции не более 256 КиБ, следующая запись ждёт завершения
  предыдущей. Архив целиком не собирается в RAM и не сохраняется в приватный
  plaintext cache приложения. Это ограничение транспортной порции, а не оценка
  всей памяти экспортера: существующий источник файлов читает окна до 1 МиБ.
* Android использует `ACTION_CREATE_DOCUMENT` и `ContentResolver` на одном
  IO executor; URI остаётся в native. iOS выбирает папку и удерживает
  security scope и accessor `NSFileCoordinator` на всё время записи, используя
  именно URL из accessor. Существующие документы в папке не перезаписываются.
* Desktop пишет соседний случайный partial и переименовывает после flush/close.
  Если разрешение SavePanel охватывает только выбранный файл, применяется
  непосредственная запись туда; отказ из-за нехватки места не включает эту
  замену. Отмена удаляет только собственный незавершённый вывод.
* Успех появляется после подтверждения закрытия, ошибки выбора/записи видны
  рядом с действием через SnackBar. Повторный экспорт заблокирован на время
  диалога и записи. Источники захвачены до модальных UI; lease проверяется
  вокруг записи. Уход с экрана закрывает вывод даже при зависшем чтении
  источника. В platform errors и журнал не попадают URI и сообщения провайдера.

Android проверен отдельным минимальным Flutter-приложением с точными копиями
production Dart writer и Kotlin exporter; SHA-256 зафиксированы в `summary.json`.
Приложение имеет другой application ID и не читает профиль xVeil. Первая
сборка fixture не компилировала file_picker из-за AGP 9/Kotlin-конфигурации;
после применения уже существующей в основном проекте политики сборка прошла.
Это не квалификация полного релизного APK xVeil. Системный установщик Xiaomi
потребовал подтверждения установки этого fixture; постоянная настройка
разрешений не менялась.

## Границы и очистка

Системный диалог iOS на устройстве не проверен. Файловая проверка Swift на Mac
не заменяет этот прогон. Ручной Save сертификата в macOS SavePanel по-прежнему
отложен по просьбе пользователя; эта итерация не объявляет его пройденным.
Уже исправленный exporter небольшого сертификата не менялся.

Отмена выполняет best-effort удаление выбранного partial и сообщает отказ,
когда он доступен операции отмены. Нет обещания удаления после SIGKILL,
потери питания или отказа внешнего document provider. При sandbox fallback
desktop замена выбранного существующего файла не атомарна. Эти ограничения
не создают приватную plaintext staging-копию в приложении.

Сохранённый синтетический файл удалён после точного readback. Fixture
force-stop, отсутствие его PID, uninstall и отсутствие целевого файла проверены.
Сырой UI XML, serial, native logs и бинарные fixture остаются в локальном
приватном cache. В git только код, synthetic tests и агрегаты/хеши.
Рабочие личности, установленная xVeil, микрофон, сеть и публичные реле не менялись.
SDK/HV не менялись; полная multi-device матрица не объявляется пройденной.
