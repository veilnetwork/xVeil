# NETCALL-01: возврат на уже допущенную direct-сессию

## Подтверждённый локальный механизм

После восстановления сети `_checkLateP2P` заново ждал endpoint exchange перед
проверкой допуска точного устройства. Если exchange удерживается старым
refresh, даже уже допущенная direct-сессия не могла начать переключение.
Теперь только после relay recovery сначала читается текущий локальный допуск
answering device. `true` позволяет пропустить discovery; `false`, unknown и
ошибка оставляют прежний путь. Первоначальный relay setup не менялся.

Snapshot сам не разрешает переключение: после него остаются свежий exact-device
admission, policy/consent, датированная peer readiness, durable announcement,
sealed native qualification и commit gate. После await проверяются call и
поколение; завершённый вызов не может воспользоваться поздним результатом.

## Проверки

Gate-тест держит discovery незавершённым независимо от времени. На прежнем
коде true-контроль падал по transport=relay вместо P2P; false/unknown проходили.
Добавлены исчезновение допуска после snapshot и hangup во время его чтения.
Первый запуск последнего теста имел ошибочное имя метода и не засчитан как
регрессионный результат. После исправления: **308 passed, 0 skipped** в шести
связанных файлах. Переформатирование посторонних старых тестов исключено.
Анализатор двух изменённых файлов чист. Физическая квалификация — ниже.

## Отдельная атрибуция предыдущей паузы

Второй звонок [предыдущей AOT-серии](../call-relay-candidate-warmup-2026-11-08/README.md)
дал поздний максимум audio RX age 11449 мс уже после успешного relay commit.
Разбор полного phone native log установил четыре sampled RTP payload кадра,
точно совпавшие с локальным `child_unavailable`; соответствующих RTP на Mac
нет. В окне +20…25 с телефон продолжал создавать RTP, но ни один из двух
Core не зарегистрировал их dispatch; обратное направление продолжалось.

Это подтверждает локальный сброс четырёх конкретных кадров при недоступном
независимом source channel. Это не доказательство причины недоступности всех
каналов и не утверждение, что четыре samples исчерпывают потерю. IPC admission
и живое canonical-соединение не доказывают пригодность независимого source
child. Параллельные warmup dial и их backoff остаются гипотезой, не основанием
ослаблять разделение каналов или менять concurrency без проверки.

Direct-сессия открылась раньше, но session.open не доказывает exact-device
admission. Поэтому текущая Dart-правка не объявляется причиной устранения
того захвата. Нужен новый полный AOT прогон; слышимость человеком не проверена.
Raw traces, соответствия RTP и адреса остаются только в приватном cache.
SDK/HV не менялись, push/релиза нет.

## Полные AOT звонки на Poco и Mac (`f1792537`)

Два звонка с фактическим двусторонним P2P-аудио до переключения, затем
Wi-Fi → Cellular (120 с) → Wi-Fi (45 с). Source revision/digest/profile mode,
установленный APK и canonical Mac AOT/FFI mappings проверены по runtime и SHA.
Оба вызова сохранили свой call ID до штатного завершения скрипта.

| Звонок | Epoch Mac / Poco | Max observed audio RX age Cellular, Mac / Poco | Возврат Wi-Fi, Mac / Poco |
|---|---|---|---|
| 1 | 1 / 1 | 7049 / 5303 мс | 5060 / 3958 мс |
| 2 | 3 → 5 / 3 | 16555 / 13176 мс | 5743 / 4271 мс |

Новая ветка `already admitted; endpoint refresh not needed` выполнена на
**обоих endpoints по два раза в каждом звонке**. Следом наблюдаются успешные
P2P qualification/commit. Это реальная проводка production-кода, не только
наличие строки в бинарнике. В первом звонке engine сохранялся на обоих концах;
во втором Mac один раз пересоздал relay engine. В Cellular-окне второго звонка
у Mac **три среза без native counters**; они не интерполируются. Возраст приёма
— метрика цифрового тракта, не слышимость человеком и не MOS. Это не A/B:
общее ускорение и устранение NETCALL-01 не заявлены.

### Остаток точнее локализован

Во втором звонке Poco дважды не подтвердил relay-кандидата (около +5,67 и
+12,67 с после команды выключения Wi-Fi), а commit состоялся около +21,23 с.
В сохранённом покадровом захвате на +5…20 с есть 82 source RTP с ненулевым
payload и стадией `direct_send`, без соответствующего received-RTP на Mac.
На +20…25 с уже 53 relay RTP сопоставлены на Core A и Mac. Это локализует
этот период к сохранению старого direct sender во время неуспешных relay
qualification. Почему первые кандидаты не подтверждались, пока не доказано.
Последующий возврат на P2P не объясняет первую паузу: bypass snapshot на Mac
зафиксирован лишь на +26,82 с, P2P commit — +35,40 с.

Единственный **sampled** `child_unavailable` нового захвата связан с RTP,
который всё же получен Mac. Он не объясняет эту паузу. Причина четырёх
неполученных RTP предыдущего захвата не переносится на новую серию по одному
названию счётчика. Следующая цель — прохождение свежих qualification control
cells на первых двух неуспешных кандидатах, включая готовность source children.
Старый sender пока сохраняется до проверенного альтернативного пути; требования
подтверждения и таймеры liveness не ослаблялись.

### Границы стенда и завершение

В первом звонке Mac frame subscriber запущен на 8,24 с позже placement, но
**до первого network handover**; native collectors и runtime/APK proofs были
готовы до placement. Установление первого звонка этой серией не квалифицируется.
У второго звонка все эти наблюдатели готовы заранее. На Cellular хост не
опрашивал телефон; полные native и state logs собраны локально на Poco.

Первый SCP upload тестового бинарника прервался до запуска Core. Продолжена
передача в тот же проверенный owner-каталог; финальные бинарники сверены по
SHA до запуска. Это не ошибка звонка и не изменение production. Два временных
Core остановлены и удалены; production PID/binary/config независимо неизменны.
Оба архива проверены целиком и по членам. QA и основной APK, старый корневой
QA-контейнер, permissions, P2P choice, сеть и debug properties восстановлены
со сверкой. Own apps/collectors/ports/runtime закрыты и проверены.

SDK остаются frozen (Mac `c8f4929b`, Android `bbcd967a`, Core `e974cebe`);
HV не менялся. Rust builds не выполнялись, external Cargo target не трогали.
Удалены только собственные промежуточные build-каталоги после проверок;
квалифицированные app/APK и приватные исходные наблюдения сохранены.
Push/релиза нет. Сводные числа — в [summary.json](summary.json).
