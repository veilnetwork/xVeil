## Разделение сети: четыре устройства, две личности

X=A+B, Y=C+D. Перед разделением положительные сообщения и reaction присутствуют
на всех четырёх устройствах. Три реле и четыре клиента разделены на половины
A/C и B/D; отсутствие cross-сессий проверено. Каждое устройство отправило
четыре сообщения, всего 16. Edit на A конфликтовал с глобальным delete на B;
также изменялись reactions и read position. До восстановления половины
действительно сохраняли разные состояния и не видели чужих новых сообщений.

После unban/join без перезапуска workers:

- Все четыре вида содержат ровно 17 строк; 16 новых сообщений встречаются
  однократно, с сохранённым порядком отправки каждого автора.
- Канонический порядок, body и edit сходятся A=B и C=D. Направление сообщения
  локально личности, поэтому побайтовое равенство всех четырёх видов не требуется.
- Глобально удалённое сообщение отсутствует у всех; reactions и read markers
  сходятся в соответствующих проекциях.
- Состояние стабильно десять секунд; исходные PID workers сохранены.
- После остановки A/C/D холодный перезапуск B сохраняет те же 17 строк,
  удаление, reactions, read position и прежнюю identity/device.

Первое совпадение наблюдалось через 22,605 с, стабильное окно — 10,149 с,
весь recovery — 32,754 с. Интервал включает административные unban/join:
это не чистая задержка доставки и не A/B оценка скорости.

## Отзыв: прогретая сигнализация и сообщения

Положительные предусловия: C звонит обоим устройствам X; B звонит и пишет C.
Затем B выключается, A отзывает B, C наблюдает актуальный документ, B
возвращается с сохранённым старым ключом. Процесс и прогретые кэши C не
перезапускаются.

После document barrier B не получает свежий offer, не вызывает ringing C,
не доставляет новое сообщение и не создаёт новую запись звонка. Отрицательное
наблюдение — 60,397 с, 151 опрос. Разрешённый A по-прежнему доставляет сообщение
и вызывает звонок: результат не объясняется отказом всей сети. Media не
запускалась; проверена сигнализация, а не слышимость.

## Отзыв: прогретое владение файлом

До отзыва B скачивает 96 КиБ с точным совпадением байтов, прогревая mapping
источника C. После отзыва и document barrier разрешённый A скачивает новый
96-КиБ файл полностью. B возвращается со старым ключом; нового offer у него
нет. Тест явно даёт B новый content ID и ограничивает попытку 15 секундами:
успех не заявлен, получено **0 байт**, нового payload нет. Процесс источника
и его кэш сохранены.

Оба revoke-гейта требуют, чтобы C уже получил актуальный документ. Мгновенная
глобальная отзывность при изолированном C не заявляется.
