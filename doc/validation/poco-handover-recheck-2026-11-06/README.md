# Повтор Wi-Fi ↔ cellular: Poco и Windows

NETCALL-01 **воспроизведён на текущем Android QA**. Два звонка прошли без
самопроизвольного завершения, но Wi-Fi → cellular внутри разговора оставил
примерно 17-секундный перерыв в получении аудиопакетов на обоих концах.
Это физическая проверка транспорта и native-счётчиков, не прослушивание речи.
Новых production-исправлений в этом цикле нет.

## Стенд и происхождение

Poco / Android 16 с включёнными Wi-Fi и мобильными данными, Windows 11 по Wi-Fi.
Production-сеть, отдельные QA-контейнеры. Основной xVeil не использовался.
На Android — свежий profile/AOT из xVeil `efdb4d0e` и SDK Dart `70478463`,
включая worker для network-change dispatch и последние lifecycle-исправления.
Windows — фиксированный ранее квалифицированный profile/AOT `3e8cea24` с
актуальным C++ engine, **не** пересобранный из самого последнего Dart.

Veil/HVS native взяты из ранее квалифицированных артефактов `b8647716` /
`eceb9158`; разница SDK до `70478463` не меняет Rust/C++. Все 74 media inputs
совпали с source proof ранее собранных ELF/DLL. Android APK после сборки
проверен по замороженным Dart inputs, трём native SHA и подписи прежнего QA.
Windows exe/AOT/Veil/HVS/media SHA проверены до запуска и после остановки.
Rust не пересобирался; Android Flutter использовал `VEIL_SKIP_CARGO=true` и
`TMPDIR=/private/tmp/`, build staging находился на внутреннем диске.

Прежний QA-профиль Poco не открылся известным паролем. Он не удалялся: через
настоящий onboarding создан отдельный именованный профиль, переданный через
Dart entrypoint args. Его собственный пароль сохранён только локально.
Сертификат скопирован штатной кнопкой с автоматической очисткой clipboard;
файл в Downloads не создавался. Обе личности открыли настоящий native node,
`realStack=true`, сеть prod. Запрос переписки дошёл, consent выполнен на Windows,
`accepted` наблюдался с обеих сторон до звонка. QA выдан RECORD_AUDIO; разрешения
обычного приложения не менялись.

## Наблюдения

Перед переключением каждого разговора требовались один и тот же call ID,
состояние active и пять последовательных срезов свежего native audio RX на
**обоих** концах. Свежесть: running=true, worker_stalled=0, packets>0,
возраст последнего payload 0–1000 мс. При смене сети эти поля наблюдались,
а не подменялись одним статусом active.

| Сценарий | Результат |
|---|---|
| Новый звонок по Wi-Fi | Входящий через 0,626 с от запроса; первый совместный fresh RX через 2,054 с |
| Выключить Wi-Fi внутри active | Call ID сохранился; максимальный native RX age 16,816 / 16,808 с; первый fresh RX после перерыва через 17,636 с от команды |
| Включить Wi-Fi обратно внутри того же разговора | Звонок продолжился; максимум native RX age 3,433 / 3,467 с; в конце RX свежий |
| Выключить Wi-Fi, сразу начать новый звонок | Входящий через 7,319 с; первый совместный fresh RX через 11,727 с от запроса; затем 25 с наблюдения без потери call ID |

Порядок чисел — Android / Windows. В первой серии по 174 среза на endpoint,
во второй по 59. Максимальные интервалы между наблюдениями 835 и 587 мс;
неожиданных/пропавших call ID нет. Это дискретные наблюдения с HTTP/SSH
накладными расходами, не точная one-way latency и не проверка каждого PCM gap.
Пять fresh-срезов для admission baseline достигнуты через 4,147 / 13,889 с:
эти времена включают ожидание стабильности и **не** являются первым аудио.

`dumpsys connectivity` подтвердил validated Wi-Fi перед тестом, validated
cellular во время передачи и validated Wi-Fi при возврате. Сразу после `svc
wifi disable` ОС ещё показывала прежний Wi-Fi — время команды не выдаётся за
время готовности cellular. Точная граница готовности нового default network
не измерена непрерывно. После завершения отдельно проверен validated Wi-Fi,
прежние значения wifi_on/mobile_data/stay_on_while_plugged_in сохранены.

[Числовая сводка](summary.json) содержит только агрегаты. Рост packet counters
не доказывает слышимость: это могла быть и тишина/CNG. Эхо, громкость, шум,
разборчивость речи и видео в этом прогоне не квалифицированы. Маршруты не
фиксировались (наблюдались relay/P2P переключения), A/B нет; ухудшение или
ускорение относительно прежних 12–20 с не заявляется.

## Остаток и кандидат следующей проверки

Телефон зарегистрировал network-change; первая новая `session.open` после
Cellular наблюдалась через 1325 мс в часах самого телефона. Это произвольная
сессия overlay, не доказательство готовности маршрута конкретного звонка.
В том же cellular-интервале зарегистрированы 30 `peer.connect.interrupted`.
Время до аудио не объясняется одним лишь первым восстановленным соединением.

В коде найден конкретный кандидат: `runtime/ipc_server.rs` после каждого
BootstrapJoin вызывает общий `force_reconnect_notify.notify_waiters()`, тогда
как `outbound_connector.rs` использует тот же сигнал для **отмены текущего dial**
как при реальной смене сети. Обновление одного peer способно прервать попытки
других; уже есть отдельный per-peer refresh watch. Но эти 30 событий ещё не
сопоставлены с конкретными BootstrapJoin, регрессионного теста этого кандидата
в этом цикле нет. Он не объявляется доказанной причиной 17-секундной паузы.
Следующая граница — wake idle retries против отмены действительно устаревшего
in-flight dial, плюс фактическое восстановление media-route выбранного peer.

## Уборка и ограничения

Первая Windows-попытка запуска попала в неинтерактивную SSH-сессию; её процесс
остановлен, звонки в ней не выполнялись и она не квалифицирована. Зачтённый
запуск — отдельная Interactive scheduled task. Ошибка первоначального poll
contact_info (flat status прочитан как nested) исправлена до звонков;
оба accepted и media admission наблюдались настоящими ответами API.

После звонков QA-контейнеры закрыты, приложения остановлены, отсутствие PID
проверено. Windows task и собственный runtime/staging удалены, frozen bundle
не менялся. SSH tunnel и ADB forward убраны, оба локальных порта свободны.
На Poco возвращён прежний QA APK с побайтной сверкой SHA, исходный большой
QA-контейнер имеет прежний SHA; новый отдельный тестовый профиль оставлен для
повтора. Основной APK `0.13.94-fingerprint.2` побайтно не менялся, его контейнер
не открывался. Сырые логи, адреса, ключи, идентификаторы и recovery-материал
остаются в private cache. Push, релиза, изменения сидов или own-device mailbox нет.
