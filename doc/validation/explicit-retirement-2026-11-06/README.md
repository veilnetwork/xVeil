# Явное отключение сессии больше не ждёт зависший writer

Последующая [сквозная квалификация](../retirement-integration-2026-11-06/README.md)
проверяет настоящий connector/TCP/OVL1 и передачу нового AEAD-кадра после
retirement. Это локальный контроль; телефонная проверка ещё не выполнена.

**Подтверждён второй источник лишнего writer grace при смене сети.**
Исправлен локально; новой физической проверки этой правки нет:
после завершённой серии пользователь отключил Poco.
NETCALL-01 остаётся открытым.

SDK-коммит: `54c64c03`. Результаты и границы: [summary.json](summary.json).

## Причина

При network-change `SessionTxRegistry::unregister` отправляет явный сигнал
retirement. Такой же сигнал использует совпавший `unregister_owned`.
FrameOutbox отличал его от обычного освобождения владельца регистрации,
но сохранял это различие только для диагностики. После EOF runner в обоих
случаях вызывал graceful `stop_writer`: зависшая отправка добавляла до 5 с
до возврата connector и начала следующей попытки.

В [телефонном захвате efe1c4ca](../dead-writer-physical-2026-11-06/README.md)
наблюдались force reconnect с одной удалённой регистрацией, явный retirement
и session-ended QA Core через 5002 мс. Этот захват отдельно подтверждает
наличие барьера после предыдущего terminal-keepalive исправления.
Он не связывает с этим барьером все наблюдаемые паузы аудио.

## Изменение

FrameOutbox сохраняет приватную причину retirement. После явной команды
отключения runner отменяет writer и ожидает его завершения через прежний
cleanup; оставшийся wire-buffer старого подключения не досылается.
Обычная замена владельца регистрации, sender EOF, idle и rotation
сохраняют graceful drain. Нет нового wire/API, изменений nonce, порогов
liveness, разрешений или ослабления проверок владельца регистрации.

Важно различать принятые операции: явное административное отключение
может отменять wire-работу старой сессии. Надёжная доставка приложения
продолжает опираться на ACK/повторы, как и после потери транспорта.
Обычная замена сама по себе не является такой командой.

## Регрессии

Настоящий SessionRunner, SessionTxRegistry, FrameOutbox и owned writer.
Оба таймера runner выключены, read всегда Pending; gate блокирует запись,
а отдельный producer остаётся живым. До unregister проверено, что writer
реально дошёл до blocked write. После unregister обе ветки должны вернуть
runner и освободить транспорт без продвижения виртуальных часов.

До правки: **2 assertion-red / 3 passed**. После: **5 passed**.
Положительные контроли: обычная замена регистрации дожидается открытия gate,
передаёт весь исходный frame, сохраняет новую регистрацию; обычный writer
shutdown передаёт весь blob через однобайтовый duplex. Ранее добавленная
terminal-keepalive регрессия также проходит. Production test hooks нет.

Полный `veil-session`: **692 passed / 8 ignored**, 1 doc ignored.
Пропуски не считаются пройденными. Внешняя ФС проверена, watcher действует
на протяжении сборок; другой checkout/dependency override не использован.
Runtime: 810 unit + 8 integration passed, 11 unit / 2 doc ignored.
FFI: 397 passed / 11 ignored, отдельный child 1 passed, 5 doc ignored.
Дочерний запуск не прибавляется к числу различных основных FFI-тестов.

Следующий физический шаг — тот же handover на Poco с новой FFI и раздельными
метками явного retirement, конца runner, нового подключения и свежего RX.
Не заявляется, что весь звонок ускорится ровно на пять секунд.
