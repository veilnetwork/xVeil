# Конкурентная очистка прямых правок после TTL — 2026-11-04

База исправления: `ad862f99`. Изменение локальное, без push/релиза, обновления
APK, движков или сидов. Mailbox собственных устройств не добавлялся.

## Подтверждённые дефекты

- Между первой проверкой tombstone и чтением исходного сообщения конкурентное
  удаление могло убрать строку. Пустой результат либо удержанная старая строка
  разрешали отправку уже удалённой правки. Проверено и при выключенном TTL:
  durable tombstone остаётся авторитетным.
- Второй вызов для той же правки возвращал success до окончания текущей
  очистки и терял её ошибку. Отказ замены и отказ scrub после успешной замены
  воспроизведены отдельно.
- Повтор `sendDurable` до enqueue мог застать идентичное старое тело уже в
  Outbox. Ранняя TTL-проверка добавляла пустой slot, но оставляла прежнее тело.
- Завершение MessagingService не дожидалось локальной работы очистки,
  запущенной вне фонового sweep.

Первоначально шесть ordinary и шесть настоящих native-HVS проверок упали
на assertion прежнего кода. Затем отдельно добавлены native scrub-failure
и ordinary/native held-row проверки; их красные результаты сохранены.
Это свидетельства механизмов, не атрибуция прежних сетевых жалоб.

## Исправление

Операции по одному peer/frame ждут общего Future очистки и получают её
настоящий результат. Другой payload того же ключа после ожидания получает
свежий verdict; другой ключ продолжает работать независимо. Перед решением
повторяется tombstone-read. Повторная отправка учитывает уже сохранённую
копию, CAS сохраняет точные wire bytes и исходный возраст очереди. Pending
scrub завершается и тогда, когда старый кадр уже заменён/отсутствует.
Dispose присоединяет локальные проверки и запись, не ожидая сетевой доставки.
Wire, домен replacement ID и native ABI не менялись.

Новый тест поймал регрессию промежуточного кандидата: дополнительный последний
read tombstone стоял ПОСЛЕ проверки времени. Во время этого ожидания TTL мог
истечь, после чего edit всё равно попадал в transport.send. Обе версии fixture
(ordinary/native HVS) дали assertion-red. В окончательном коде время проверяется
после последнего чтения. Удержание future и изменение domain clock задаются
явно; latency thresholds для решения pass/fail не используются.

## Проверки и границы

[Fixture](../../../test/outbox_concurrent_expiry_test.dart) содержит девять
сценариев на каждом backend: пустой lookup, удержанная старая строка, TTL во
время последнего tombstone-read, совместный success/failure/scrub-failure,
повтор сохранённого кадра, новый payload того же ключа и dispose.
Проверяются отсутствие старого edit на границе transport, один bodyless slot
с прежними seq/age, точный retry после отказа и независимый адресат. Native
проверки дополнительно читают остановленные raw Outbox roots и cold reopen.

Scoped native серия с явно заданной библиотекой: **33 passed, без skip**
(17 настоящих HVS cases и 16 ordinary). Неверный первоначальный путь к одному
старому test-файлу дал loading error; тот запуск не засчитан, исправленный
список выполнен заново. Analyzer чистый.

Широкая серия: **1463 passed / 30 conditional skipped** в 81 файле; skip не
считаются пройденными. Native cases отдельно выполнены явно, как указано выше.

Финальный native process A/B/C regression прошёл все пять gates: живая правка
сначала точно была в очереди, background cleanup заменил её при offline C,
после остановки в raw roots нет старого тела, startup C очистил собственную
копию до старого periodic timer, durable void ACK и свежее сообщение доставлены.
Все собственные процессы завершены, проверены **23 PID / 27 порта**;
runtime удалён. Все 1456 frontend/test/dependency hashes и native SHA
не изменились во время запуска. SDK и hidden-volume clean. Прогон занял
122.049 с целиком; это не метрика доставки и не A/B ускорения.
Предыдущий промежуточный process-контроль также прошёл, но после clock-правки
финальная квалификация выполнена заново в отдельном evidence-каталоге.
Сам A/B/C — проверка сохранения обычного пути, не физическое воспроизведение
каждой управляемой storage-гонки.

Не закрыты другие native transport/fragmentation ожидания, early ACK вне
проверенного пути, неполные persisted transfers, смена TTL policy/системного
времени и вся multi-device матрица. Это границы проверки, не автоматически
подтверждённые дефекты. Общая latency остаётся отдельным фронтом.
