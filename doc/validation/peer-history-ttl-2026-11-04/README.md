# TTL при прямой догрузке истории — 2026-11-04

## Подтверждённые дефекты и изменения

На исходном `afc0565a` четыре отдельных проверки воспроизвели выдачу уже
истёкших данных без предположений о сети. Фоновый prune намеренно недоступен:
сервис должен соблюдать TTL и в этом состоянии.

| Путь | До изменения | После изменения |
|---|---|---|
| Gap-fill собственного журнала | Старые post и более поздний edit исходного сообщения уходили повторно | Возраст определяется исходным post; после durable удаления отправляются bodyless sequence slots |
| Старый файл | Ответ содержал имя/запрос legacy файла | Истёкшее предложение не выдаётся, живое сохраняется |
| Возврат собственной истории через собеседника | Ответ `own-echo` содержал истёкший post | Истёкшие строки исключаются до пагинации; чужие авторские slots не объявляются удалёнными |
| Возврат собственной правки | Старый отредактированный текст возвращался с живым временем edit | TTL проверяется по исходному post, а не времени правки |

Дополнительно исключены keys/hashes истёкших сообщений из исходящего
own-echo запроса. После ожидания предыдущей отправки проверяется следующий
конкретный event: срок мог закончиться во время ожидания. Это проверка перед
application handoff, не гарантия очистки уже принятых транспортом байтов.

Отказ локального удаления/чтения не становится доказательством удаления:
такая строка откладывается, живые продолжают отправляться. Потеря ответа уже
законченного удаления разрешается чтением durable tombstone. При отсутствии
исходного post и включённом TTL не угадываются ни возраст, ни void. Отключённый
TTL сохраняет обычную выдачу старой истории. Подписи/ratchet/ACL, round limits,
маршрутизация и wire-формат не менялись.

В анонимном отчёте доступны постоянные категории `peer-sync-expiry-read`,
`peer-sync-expiry-erase`, `peer-sync-expiry-origin` и тип ошибки; тест проверяет
отсутствие исходного текста ошибки, тела, путей, peer ID и timestamps при
соответствующем режиме экспорта.

## Потерянный reconnect при startup cleanup

Широкая проверка обнаружила старое падение Case-A wipe recovery. Оно отдельно
повторено на точном архиве HEAD до текущих product-изменений: восстановление
оставляло пустую историю. Первая гипотеза о пятисекундном anti-storm throttle
не подтвердилась; пробное изменение fixture-clock удалено.

Трасса показала отсутствие beacon вообще. Вызов reconnect во время initial
cleanup пропускал conversation recovery, после очистки автоматически
возобновлялись только durable controls/own-history. Теперь явный reconnect
дожидается owned cleanup и выполняет свою conversation pass. Периодический
cadence обычных повторов не менялся; call controls/presence не ждут этот
барьер. Gate-тест красный до фикса: reconnect завершался при удерживаемом
prune. После освобождения cleanup проходит beacon, expired body не уходит;
при disposal ожидающий reconnect завершается без отправки. Case-A снова
проходит без изменения исходной fixture.

## Сквозная регрессия A/B/C

Три отдельных процесса на локальном relay island с production providers,
подписями/ratchet, native workers и настоящими контейнерами. A/B принадлежат
одной личности, C — другой. При остановленном A устройство B восстановило
все 100 конфликтующих правок через C. После cold reopen сохранены reflected
revisions; reflected body не выдаётся как собственное authored evidence.
Повторная волна при online A/B/C тоже сошлась: B расшифровало 100 различных
ответов C. Затем при offline C возвращённая авторская история A подтвердила
все те же значения на B. Дублей 0, ответные ratchets остаются под identity,
а не physical device address. Все обязательные result gates прошли.

Полное исполнение 439,841 с; восстановление первой волны 23,021 с. Это не A/B
и не заявка об ускорении. Этот normal-history прогон — регрессия транспорта и
сходимости; отказ bulk prune и TTL гонки проверены отдельно unit/native.
Test/driver/cleanup 0/0/0: проверены 40 своих PID и 56 портов, процессов и
listeners не осталось, runtime root удалён. 1444 source/package inputs
неизменны в течение теста, native SHA совпали до/после; зависимости чистые.
Новая native библиотека не строилась и на устройства не устанавливалась.

## Границы

Это исправление источников прямой истории, не полная TTL/clock-skew матрица.
Ingress обычного peer post/edit, partial transfers, ожидания внутри транспорта
и изменение политики во время I/O требуют отдельной квалификации. Новых
mailbox-механизмов для собственных устройств нет. Общая latency не измерена
парным опытом. Android/Windows, APK/engine pins, production seeds, push и
релиз этим циклом не менялись.
