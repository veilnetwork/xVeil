# Цена durable-коммитов при догрузке — 2026-11-04

## Что измерено

Прошлый qualified worker trace оставил 568 commit RPC с 8,98 с обработки
handler. Это включало adapter/FFI/native, а не исключительно fsync.
Добавлен **stand-only probe**, который устанавливается только в отдельный
чистый detached HVS worktree фиксированной версии. Основная зависимость HVS,
её публичный API, формат, код приложения, SDK и pins не меняются. Приватная
измерительная dylib имеет отдельное имя и пометку `mustNeverShip`.

Probe разделяет тело `commit_tx` на неперекрывающиеся этапы и отдельно измеряет
существующий `File::sync_all`. Все операции, барьеры, padding/churn и возвраты
сохранены. Никаких задержек, искусственных отказов или отключения sync нет.
Содержимого, namespace, ключей, ID и путей в строках probe нет. Begin marker
разделяет процессы; максимум 25 000 завершённых записей, cap делает анализ
недопустимым. Агрегатор возвращает только фиксированные числовые категории.

## Контроль измерителя

- Source manifest включает все изменённые и новые Rust-файлы private checkout;
  SHA собранной и выбранной dylib совпали. При отсутствии внешнего mount
  сборка останавливается watchdog. UniFFI checksums — все 45 прежние.
- 35 FFI тестов прошли. Реальный worker control также прошёл: 40 RPC сопоставлены
  с 40 handlers, из них четыре commit. Native probe увидел пять commits,
  включая один явный prelude до начала VM capture: 20 sync calls. Эти разные
  окна не объявляются взаимно однозначной атрибуцией.
- В контрольных пяти commits: body 69,869 мс, из них sync 66,660 мс (~95,4%).
- Шесть Python-тестов parser/install protections прошли обычным Python и с
  `-O`. Пустые/capped/неполные/неизвестные поля не принимаются. Реальные
  временные Git fixtures проверяют отказ primary/dirty checkout и проверку
  всех source anchors до первой записи.
- В первой попытке installer ошибочно ожидал exit 0 от `git symbolic-ref`
  для detached HEAD. Это исправление самого инструмента. Он не успел ничего
  изменить. После сборки предохранители дополнительно переведены с assert
  на явные исключения; их нельзя отключить флагом `-O`.
- Private target очищен; около 367 МиБ возвращено. Сохранена только отдельно
  проверенная измерительная dylib и provenance. Нормальная библиотека не заменена.

## Полная native multi-device серия

На изолированном A/B/C island выполнен тот же sparse crash/reconnect:

- B принудительно завершён при 1572 наблюдавшихся строках. При локальном
  восстановлении без A/C сохранены 1572, есть поздний provisional tail.
- Вернулся только A. Prefix fallback реально выполнен; все 2000 ID,
  порядок, source positions и delivered сошлись. Дублей и completed-history
  retries нет. Результат сохранился после запуска B без обоих источников.
- После готовности A — 41,726 с. Это не A/B с предыдущими 36,513 с:
  прежний B сохранил 1672 строки, текущий — 1572; объём восстановления иной,
  библиотека дополнительно измерительная. Ускорение/регрессия не устанавливаются.
- Driver/teardown завершились с 0. Проверены 31 PID, 45 портов, отсутствие
  listeners и удаление runtime. Во время прогона 1420 выбранных inputs,
  instrumented source manifest и native SHA не менялись. Позже installer и
  parser усилены, их capture-revision отдельно сохранены в private evidence.

Профилирование включалось только для B. Его лог содержит четыре begin-секции:
подготовка, процесс до SIGKILL, восстановление и финальная retention-проверка.
Ни одна из секций не capped. Приведённые ниже числа относятся к завершённым
native calls **всего процесса восстановления**, а не к обрезанному VM-окну.

| Этап | Наблюдение |
|---|---:|
| Успешные native commits | 694 |
| Ошибки commits / hardening | 0 / 0 |
| `File::sync_all` calls | 2776 — четыре на commit |
| Измеренное тело commits | 10,283 с |
| Из него непосредственно `sync_all` | **9,845 с (95,7%)** |
| Остальная измеренная работа | 0,438 с |
| Кодирование/размещение log batches | 0,040 с |
| Изменение индекса | 0,078 с |
| Padding / churn без их sync | 0,109 / 0,105 с |

`sync_all` включает планирование и filesystem/device waiting. Это не замер
только физического диска. Sync — подмножество времени фаз; его нельзя
прибавлять к ним повторно. Body не включает FFI decode, внешнюю Dart-работу,
cleanup параметров и вывод строки probe. Сумма native commits также не равна
всему времени догрузки. SIGKILL-процесс может не записать незавершённый call;
его строки не используются как доказательство полноты.

## Вывод для следующей правки

В этих 694 commits **нет ни одного** успешного случая без padding и без reuse.
Поэтому идея убрать четвёртый sync только при отсутствии hardening-записей
дала бы здесь ноль пропущенных sync. Она не внедрена как якобы ускорение.
Остальные барьеры также не удалялись; порядок durable publication и маскировка
записей остаются прежними.

Следующий существенный участок — число отдельных транзакций на стороне
applier. Нужен ограниченный batch с подготовкой строк и атомарным durable
сохранением, затем cursor/сигнал об успехе. Требования для такой правки:

1. Общая реализация live/history merge: tombstones, pending edits/deletes,
   delivered и verified ordering не должны расходиться между путями.
2. Проверка текущего binding/revoke между подготовкой строк и перед commit;
   без параллельного применения ещё не подтверждённых строк.
3. Очереди одного message key, фиксация storage session, fences close/erase и
   ограничение записей/байтов остаются обязательными.
4. Cursor не проходит ни несохранённую строку, ни отказ. После SIGKILL или
   отказа сохранения безопасно повторяется весь незавершённый набор.

Это план следующей реализации, а не готовая batching-оптимизация. Общий
latency-дефект и расширенная multi-device матрица остаются открытыми.
Mailbox для собственных устройств выключен по решению владельца. Push,
релиза, смены APK, двигателей и production-реле нет. Android/AOT не проверены.
