# Ограниченная запасная попытка obfs4

**Veil `dd6129b0`: молчащий obfs4-handshake получает один запасной TCP-кандидат
через 1 с, в пределах прежнего общего 10-секундного handshake-дедлайна.**
Проверены модель, настоящий TCP/obfs4 и реальный Mac-клиент с embedded node.
Проверки новой SDK на телефоне **не было**: Poco исчез из ADB и USB до
установки подготовленного APK. NETCALL-01 остаётся открытым.

Анонимные агрегаты: [summary.json](summary.json).
Предыдущий мобильный результат: [SDK aa51cc13](../reconnect-wake-physical-2026-11-06/README.md).

## Почему выбран этот участок

В предыдущем Android capture новое подключение после Cellular успешно
открывалось, затем keepalive закрывал сессию без ACK. Повторный dial иногда
ждал ещё 10 с ответа obfs4. Соседние потоки к тому же Core могли пройти быстро.

Дополнительный разбор связывает два успешных obfs4-handshake с последующими
writer traces **по локальному TCP-порту в пределах того же процесса и
временного окна**. У первого потока queue росла до 10283 байт, unacked до 14;
у второго — до 43107 байт, из них 34452 notsent, unacked до 14, наблюдались
ретрансляции. Совпадение writer с конкретным canonical SessionRunner отдельно
не доказано: outer `peer.connect.success` не несёт общего connection ID.

Это свидетельство проблем уже после upgrade, а не только первого пакета.
Новая правка уменьшает ожидание следующего handshake при наличии пригодного
другого потока; устранение самого зависания установленного TCP не заявляется.

## Поведение и границы

- Быстрый успех или быстрый отказ primary возвращается как прежде; запасной
  кандидат не открывается. На границе задержки готовый primary имеет приоритет.
- Если primary ещё pending через 1 с, открывается ровно один backup к тому же
  host/port с прежними PSK и wire variant. Оба проходят полную проверку obfs4.
  Следующие OVL1 / parent-bound auxiliary proof остаются обязательными.
- Ошибка одного уже запущенного кандидата не отменяет другой. При двух
  отказах сохраняется ошибка primary. Медленный исправный primary сохраняется.
- Одновременно не более двух transport-кандидатов; третий не создаётся.
  Существующий последовательный перебор DNS-адресов внутри TCP connect
  не менялся. Цена — дополнительный сырой TCP-кандидат для медленных попыток.
  Это не дополнительный зарегистрированный peer или authenticated child.
- Оба кандидата находятся под общим прежним deadline. Нет фоновых spawned
  tasks: отмена, timeout или выбор результата освобождают проигравший stream.
  Правило едино для canonical и auxiliary obfs4, без роли приложения на wire.

Приватная `rt_trace` теперь связывает connection с локальным attempt и
primary/backup и отмечает выбранный stream. Группировка не передаётся peer,
без trace новый observer не хранит состояние. Поля отсекаются allowlist
анонимного журнала; canary-проверки включают новые поля.

## Локальные проверки

Характеризация прежнего **однопопыточного поведения**: helper делегировал
неизменённому `primary.await`. Новые требования дали 4 assertion-red / 2 pass
на виртуальных часах. Это проверка новой recovery-политики, не утверждение
о четырёх отдельных нарушениях прежнего контракта транспорта. Compile-only
ошибки промежуточных fixtures не засчитываются как красное воспроизведение.

После реализации все 10 новых проверок проходят: delayed backup, предел
двух кандидатов, fast success/error, медленный primary, ошибки обоих
направлений, исходный общий deadline, отмена caller и реальные сокеты.
Реальный fixture удерживает первый flow без ответа, завершает второй obfs4,
проверяет зашифрованный roundtrip, закрытие проигравшего и соответствие
metadata/exporter выбранному сокету. Другой fixture отклоняет malformed
backup и успешно завершает нетронутый primary.

- Transport: **171 unit + 5 smoke + 2 doc passed**.
- Runtime: **810 unit + 8 integration passed**, 11 unit / 2 doc ignored.
- FFI: **397 passed / 11 ignored**, отдельный child 1 passed, 5 doc ignored.
  Дочерний запуск не прибавляется к числу различных основных FFI-тестов.
- Dart diagnostic journal: **19 passed**; Python artifact canary: **1 passed**.
- Formatting и diff checks чистые. Rust builds/tests наблюдались с контролем
  отдельной внешней ФС; потери mount не было. Удалён один свой уже не
  используемый предыдущий runtime-test executable; receipts сохранены.

## Проверка реального Mac-клиента

Обе клиентские FFI собраны из чистого `dd6129b0`, SHA и происхождение
проверены; transport реально пересобран, бинарники отличаются от aa51cc13.
208 C exports и Mac ABI contract прежние. AOT/media/HVS и signer сохранены.
Android APK дополнительно содержит замену только двух QA seed assets.

Прежний сервер не отвечал по SSH; один изолированный QA-Core развёрнут на
другом сервере, с прежними QA identity/PSK и бинарником `ade3130a`. Production
не подключён к этой сети. **Это другой сетевой путь, не A/B.**

После исчезновения Poco использован loopback raw TCP proxy для одного
собственного Mac-клиента. Первый flow принимается и читает bytes, но
не получает ответа и не пересылается на Core. Следующие flow прозрачно
пересылаются к QA-Core; proxy не знает PSK и не подменяет handshake.
У proxy свой предел времени и числа соединений.

В первом attempt, отобранном по proxy-port и связанном внутренним attempt ID:

| Кандидат | Итог |
|---|---|
| Primary | 86 байт отправлено, 0 получено; incomplete при отмене через 1316 мс |
| Backup | Полный obfs4 за 314 мс, затем selected |

Proxy принимает второй flow через 1000,180 мс после первого и наблюдает EOF
первого через 1314,828 мс. CLI-снимок Core содержит **конкретный transport ID
своего Mac в active**, не пустое сравнение состояний. Это проверка реальных
FFI, embedded connector, obfs4 и node admission. Локальный proxy ACK-ает TCP:
он моделирует отсутствие ответа obfs4, **не** мобильный unacked TCP packet.

Сохранены файловый журнал Core и QA-port-only PCAP с проверкой SHA. Capture:
903 packets / 27 flows, 14 с client payload, у всех 14 есть server payload,
kernel drops 0, остановка вручную до bound. Потоки без payload не объявляются
потерями в сети. Capture также включает свой первоначальный Mac startup;
весь трафик не приписывается одному controlled attempt.

## Что осталось и очистка

Звонков и аудио на новой SDK не проверяли. Последний реальный телефонный
результат остаётся прежним: самопроизвольный call-end после handover и
18,397 с до пяти свежих срезов нового звонка. Следующий шаг — Poco ↔ Mac
на готовых артефактах, с отдельной оценкой уже установленного TCP и нового
handshake. Слышимость, echo/noise и акустическое качество здесь не оценивались.

Свои Mac-инстанции и proxy закрыты, PID/порты проверены, временные runtime
удалены. Добавленный debug log сохранён приватно и удалён из своего bundle;
строгая проверка подписи снова проходит. QA bootstrap восстановлен.
Установка на телефон не начиналась, действий изменения его данных не было.
Удалено 153302943 байта своих упаковочных промежуточных файлов; final/rollback
артефакты сохранены. QA capture/Core/unit/config/binary/state/runtime удалены;
production PID, executable/config SHA и NRestarts прежние. Push и релиза нет.
