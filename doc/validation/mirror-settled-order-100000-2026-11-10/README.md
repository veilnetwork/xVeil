# Повтор уже сохранённой позиции сообщения — 2026-11-10

## Подтверждённый механизм

При повторном outgoing mirror `_MessagingDeviceMirror` уже получает свежую
строку для проверки существования и доставки. Даже когда её effective
`orderAuthor/orderSeq` совпадали с зеркалом, выполнялись асинхронный допуск
автора и ещё одно точечное чтение ради исправления порядка, которое не нужно.
Это касалось исходной канонической позиции и уже применённой ordering overlay.

Теперь совпавшая позиция завершает только ordering-ветку без новой записи.
Delivery merge выполняется прежде и сохраняет собственное свежее чтение
в status-writer, если действительно нужно изменить статус. Неизвестная или
отличающаяся позиция проходит прежние проверки автора и повторное чтение
после await. Content/time/provenance не переписываются. Peer/binding/dispose,
исторический admission, serialized mirror key, conditional adoption и durable
publication не изменены. Новый кеш авторизации или строк не добавлен;
mailbox для собственных устройств не включался.

## Регрессии

Четыре cost-проверки падали на parent: исходная/исправленная позиция × уже
доставленный/ещё отправленный статус. После правки требуется одно point read
для полного no-op или два при реальном status update (второе принадлежит
самому status-writer). Удаление строки во время author admission по-прежнему
исключает последующую коррекцию и восстановление тела. Нужная adoption
сохраняет повторное чтение; готовая позиция не подавляет delivery repair.

В ходе подготовки уточнены ожидания тестов: учтено собственное чтение
status-writer, timestamp сравнивается по epoch вместо зоны DateTime.
Итоговые cost-проверки повторно воспроизведены на неизменённом parent.
203 смежных теста прошли, 0 skipped; analyzer двух изменённых файлов чист.
