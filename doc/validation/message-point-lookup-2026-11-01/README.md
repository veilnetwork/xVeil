# Точечный поиск при зеркалировании и мутациях

2026-11-01. Подтверждён и устранён лишний обход истории в `messaging_mutations.dart`.
`hasMessage`, `isIncomingFrom` и `_findInConversation` загружали через
`loadMessages` весь разговор и перебирали его ради одного ID. Первый helper
вызывается для каждой зеркальной копии и при peer gap-fill; остальные — при
входящем edit/delete. При большом backlog это повторные полные проекции и
сортировки уже сохранённой истории.

Все три проверки используют существующий `Storage.loadMessageById` по паре
**conversation ID + message ID**. В production storage это та же текущая
incremental fold с map lookup и прежними status/signature overlays, вместо
project/filter/sort всей истории. Оба ID остаются обязательными. Глобальный
поиск по одному ID для прежнего UI API не менялся. Tombstone, авторство,
допуски контактов, pending mutations и durable append/ACK не менялись.
В production не добавлено test-переключателей, новых кэшей или формата хранения.

fold и durable commits по-прежнему нужны; ноль проекций не означает ноль I/O.

## Межпроцессная начальная миграция

A/B — одна личность, C — другая, отдельные процессы и worker-backed контейнеры
на одном Mac. Три локальных реле, публичные seeds/discovery выключены,
прямые локальные соединения разрешены. Native SDK/CLI **`f7a4fb97`** и HV
побитово сохранены от прежнего контрольного стенда: изолируется Dart-изменение.
Это не физическая квалификация всех накопленных SDK-правок `eb644a83`.
565 Dart/fixture-файлов проверены до/после запуска без изменений.

В существующий E2E-fixture добавлен **отдельно названный migration-only режим**:
перенести ненулевую исходную историю и завершить проверку перед offline-этапом.
Без test-only environment flag остаётся полный прежний сценарий. Migration-only
требует минимум одну строку, чтобы равенство пустых списков не стало успехом.
Пятиминутный offline/reconnect этим запуском не выполнялся и не засчитывается.

Результат: **1 native E2E passed**, исходные **2000/2000** сошлись по всем ID и
порядку на A/B/C, на B все 2000 имеют delivered, повторных message-retry старых
ID **0**. Дубли/некорректные snapshots не наблюдались. Первое полное наблюдение —
**77 121 мс** после link-подготовки; 1944 строки были видны на 72 004 мс.
Интервал опроса около 5 с: это верхняя граница наблюдателя, не точное время
последней записи. Полное время с подготовкой и teardown — 269,560 с.

Предыдущая отдельная серия дала 72,610 с. **Сквозное ускорение не доказано**:
это не A/B/A, различаются история очередей/маршрутов и остальной Dart-срез.
77,121 с не объявляется ни исправленной догрузкой, ни доказанной регрессией
из-за point lookup. Прямая цена лишних проекций снята; остаток требует
разложения между поступлением кадров и durable-применением строк.
