# Текущий Dart на Mac и Android — 2026-10-30

Проверяется xVeil `7a225483` с неизменённой Veil `c96bd930`. Это первые физические
передачи после исправлений verified source handle, live source policy и
времени жизни datagram-выдачи. Прежние 14 файлов с более старым Dart к этой
квалификации не прибавляются.

## Происхождение сборок

Все файлы `lib/` обоих QA-workspace побайтно совпадают с текущим HEAD до и после
сборки. Mac — debug/JIT, Android — profile/AOT; APK не содержит kernel_blob.
Нативная Veil переиспользована по SHA-256 из проверенной production-feature
сборки `node-embedded,production-seeds,packet-tunnel`, без test-low-difficulty и
native test hooks. Библиотека до macOS-подписи и реально упакованная библиотека
после подписи имеют отдельные хеши. Загруженная dylib проверена через lsof и SHA;
установленный QA APK — по хешу фактического base.apk.

Приложение телефона — отдельный QA package. Исходный QA APK сохранён для точного
восстановления; сертификат подписи и versionCode кандидата совпадают с ним.
Основное приложение и его данные не изменялись. QA-контейнеры/ratchet не
откатывались. Телефон — Blackview на Wi-Fi; P2P для тестового контакта запрещён,
использованы анонимные stream-цепочки. Правила приоритета реле не менялись.
Во всех 89 срезах внутри stream-download API телефон был активен,
с включённым экраном и Doze ACTIVE.

## Четыре stream-передачи

| Направление | Payload | Полное время download API | SHA-256 |
| --- | --- | --- | --- |
| Android → Mac | 3 МиБ + 251 байт | 13,150 с | Совпал |
| Mac → Android | 3 МиБ + 251 байт | 29,328 с | Совпал |
| Android → Mac | 64 МиБ + 251 байт | 91,106 с | Совпал |
| Mac → Android | 64 МиБ + 251 байт | 81,407 с | Совпал |

Всего четыре файла, 140 510 188 payload-байт. У всех восьми endpoint-завершений
зафиксированы EOF, собственный FIN req/sent/acked и courtesy linger. В endpoint
mux суммарно 158 408 полученных cells, Full/Closed/unknown/invalid — нули.
Это не счётчики всех промежуточных реле.

В медленном 3-МиБ Mac → Android потоке максимальный **наблюдённый** consecutive
RTO равен 2; были recovery и ожидание gap. Значит, прочие причины ожидания
DATA/ACK остаются, несмотря на целый файл. На больших файлах sampled consecutive
RTO — 0. Один ProbeRTT завершился; между окружающими false-срезами около 1001 мс,
что является верхней скобкой наблюдения, а не точной длительностью пробы.

Интервалы продвижения native receive prefix, включая начало: до 6505/4078 мс
на малых файлах и 527/1685 мс на больших (Android → Mac / Mac → Android).
Диагностика выборочная: самый большой интервал между срезами достигает 4001 мс,
поэтому это не доказательство непрерывной сетевой тишины. Записи проверенных
256-КиБ частей рассматриваются отдельно. Начальные задержки не объявляются
устранёнными; ускорение относительно прежней серии при разных путях не доказано.

## Datagram fallback

Для отдельного Mac-получателя собран тот же HEAD с существующим production
переключателем `XVEIL_PLAIN_FILE_STREAM=false`. Android APK тот же, что в серии
выше. Это намеренная проверка fallback, не сравнение его скорости со stream.
Файл 1 МиБ + 251 байт доставлен Android → Mac за **12,108 с**, SHA-256 совпал.
В журнале отправителя одна выдача 257 chunks: 11022 мс, из них read 784 мс,
send 6661 мс, batch 2. В обеих native-трассах ноль stream-driver records;
путь действительно был datagram. Размер целевого файла при выборочном stat
оставался нулевым до конца; это не интерпретируется как отсутствие передачи.
Прогон короче 50 секунд: физическое пересечение границы дедлайна не доказано,
его по-прежнему квалифицирует service red/green с 80-секундной виртуальной
выдачей. [Точные результаты](summary.json).

## Завершение стенда

Первый сценарий сбора журналов ошибся: в новую приватную папку не был перенесён
collect_stage_logs.py. Его finally прервался до очистки, а SIGTERM не закрыл Mac.
После этой попытки lock API Mac ответил `Peer authorization state unavailable`.
Причинная связь с исправлениями файлов не доказана; обычное закрытие после
повторного запуска QA завершилось успешно. Это отдельная граница наблюдения,
не потеря файла или доказательство пользовательского обрыва звонка.

Очистка выполнена отдельным проверенным восстановлением: настройки обоих QA
клиентов возвращены, rt_trace и Android debug property восстановлены, процессы
Mac/телефона/logcat остановлены, ADB forward удалён, порты освобождены. Исходный
QA APK возвращён с проверкой фактически установленного хеша. Первый сценарий
не зачтён как успешная автоматическая очистка. У отдельного
fallback-прогона сбор журналов и автоматическая очистка уже завершились успешно;
хеш исходного QA APK и отсутствие процессов/forward перепроверены после него.
Восемь локальных синтетических source/download файлов удалены только после
проверки их SHA-256; исходные файлы пользователя не затрагивались.

Raw logs, реальные адреса/идентификаторы/пути, clock epochs и credentials
остаются приватными. Публичный [summary.json](summary.json) содержит только
обезличенные результаты. Проектный код в этой квалификации не менялся;
коммит документации без подписи, push/релиза нет.

## Что это не закрывает

Обычная передача не воспроизводит отзыв fileRoots и подмену байтов во время I/O:
те сценарии доказаны service-тестами, но не этой физической серией. Проверка
fallback сама по себе не заменяет red/green тест границы 50 секунд. Не закрыты
все «33%», Windows 10, мобильный провайдер, Android с погашенным экраном и вся
multi-device матрица. Начальная задержка и участок оставшихся потерь DATA/ACK
требуют продолжения разбора.
