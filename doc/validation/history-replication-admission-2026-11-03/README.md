# История должна считать уже поставленные в очередь порции

2026-11-03. Исправлена гонка между локальным commit и replication admission.
Без push/релиза, новых engine pins и установки на пользовательские устройства.

## Подтверждение

В сохранённом предыдущем контроле медленной миграции обнаружена строка отказа
поставить group snapshot при **258 неподтверждённых кадрах**. Именно та серия
показывала недостающий диапазон из 25 сообщений при уже полученных последующих.
Однако конкретный отказ и конкретный диапазон по старым журналам не связаны:
это не доказанная атрибуция всей той паузы.

Путь имеет воспроизводимую гонку. `postDeviceEvents` дожидался сохранения в
локальный групповой журнал, но запускал `broadcastDelta` в фоне. History replay
затем считывал pending Outbox для backpressure, когда предыдущая порция ещё
не была поставлена туда. Такая проверка недооценивает будущую очередь; позже
обычный предел replication может отказать в добавлении очередной порции.

Gate-тест на настоящем `GroupService` удержал callback durable admission:
старый код уже возвращал успешный результат history batch. Тест упал по
`true` вместо `false`, не по таймауту или ошибке сборки. Очередь удерживается
явным Completer; очередь готовых microtasks исчерпывается без latency threshold.

## Изменение

Только bulk API, используемый history replay, ожидает local save **и** очередь
репликации. Существующий host callback `sendSyncResponse` завершает работу
после durable enqueue, не после первой сетевой попытки. Теперь последующая
проверка pending учитывает предыдущую порцию. Все production-хосты уже
предоставляют этот callback; у простого legacy-хоста без него остаётся обычный
sender fallback.

Одиночные live `postDeviceEvent` сохраняют фоновую отправку. Лимит порции 64,
порядок постов, подписи, membership checks, durable/ratchet-барьеры и пределы
Outbox не меняются. Не увеличен лимит и не выключен backpressure. Отказ
admission не удаляет уже committed локальные строки; следующий batch не
застревает в отравленном drainer. Нет нового accepted-bundle cache или
переиспользования старой авторизации ради сокращения чтений.

Проверены held admission, отдельный live control, queue failure с сохранностью
строк и продолжением drainer, порядок history/live, bounded input, отмена,
mirror/appliers и source enqueue. Итог: **490 passed, 3 skipped**, analyzer
чист. Первый широкий запуск содержал ошибочный путь к отсутствующему test-файлу;
он не считается прошедшим набором или продуктовым дефектом. Исправленная команда
полностью прошла. Диагностические вставки в production-код не добавлялись.

## Native A/B/A

Три процесса A/B/C, реальная Riverpod-проводка, native signatures, worker/HV,
изолированное loopback-реле, 2000 исходных сообщений. Один Mac/JIT, только
начальная миграция. Public discovery/seeds выключены. Проверяются точные ID,
порядок, effective source positions и terminal delivery, а не только количество.

Native SDK/CLI/FFI **заморожены на ранее проверенном `eb644a83`**, HV одинаков:
это квалификация изменения Dart, не последних transport-правок. A₁/A₂ совпали
по всем 573 frozen-файлам; в B отличается один production-файл. Хеши библиотек
проверены до/после, исходники внутри каждого прогона не менялись. Кандидат
восстановлен и независимо сверён после обратного контроля.

Во всех фазах конечная история сошлась. A₁ ещё один опрос ждал effective
positions при уже полном количестве. В B отказов не наблюдалось; A₂ повторил
отказ. Один цикл A/B/A и опрос раз в пять секунд не дают устойчивой оценки
процента ускорения. Повторных чтений не стало меньше — в B их даже больше,
поэтому изменение не объявляется сокращением I/O. Эти счётчики включают
финальные inspection и перекрывающиеся scopes, не складываются в критический
путь и не объясняют сами по себе все секунды ожидания.

Backpressure visibility исправлена отдельно от общего остатка задержек.
**Миграция всё ещё медленная**: около 46 секунд на 2000 сообщений в новом
host/JIT прогоне. Следом нужно разбирать повторные полные чтения/обработку
журнала и оставшиеся ожидания до ingest. Не закрыты пятиминутный offline,
Android/AOT, часы/сутки offline и вся multi-device матрица. Пользовательские
репорты о мобильных звонках, холодный QUIC и слышимость речи статус не меняют.

В каждой фазе проверен выход 18 собственных PIDs и освобождение 19/20/20
захваченных портов. Временные runtime-контейнеры удалены; приватные синтетические
журналы/ключи/идентификаторы не опубликованы. Телефон, Windows, публичные реле,
сиды и пользовательские контейнеры не менялись.
