# Два одновременных источника собственной истории

Native-квалификация исправления `f50f56e5`:
[подготовка строк и очередь страниц разговора](../history-preparation-2026-11-07/README.md).
В этом цикле production-код не менялся. Агрегаты: [summary.json](summary.json).

## Сценарий и наблюдаемое перекрытие

Четыре независимых Mac/JIT provider-процесса: A/B/E одной личности, C другой.
Связывание устройств и контакт проходят штатные церемонии. В отдельных
контейнерах A и E тестовый worker через живого владельца Storage создаёт
одинаковый архив из **512 текстовых строк** с каноническими позициями и
delivered. Во время подготовки второго источника первый выключен. Для этих
строк нет device-journal mirrors: получатель должен использовать own-history,
а не восстановить тот же набор обычным групповым replay. C далее выключен.
Это синтетический архив, а не 512 новых пользовательских отправок.

Одноразовые барьеры существуют только в `test/`. Сначала оба источника
останавливаются перед кодированием первой архивной строки. После их
освобождения B удерживается перед первой подготовкой этой строки. Пассивный
wire-наблюдатель подтверждает получение **всех частей обоих ответов**:
request сопоставлен на источнике с authenticated запросом B, а ответ на B —
с authenticated физическим устройством A или E. В этот момент в архиве B
**0 строк**, первая apply-подготовка вызвана **один раз**. Следовательно,
страницы действительно прибыли до освобождения apply, а не последовательно
после завершения предыдущей догрузки.

После освобождения B оба source cursor заканчивают разговор; первая строка
проходит callback дважды, по одному разу от каждого источника. Итог —
**512/512** ID, тел, delivered, canonical positions и порядок совпадают;
дублей, ошибок history apply и недействительных наблюдавшихся snapshots нет.
Прежняя строка B тоже сохранена. Все барьеры освобождены контроллером,
ни один не завершился lease timeout или потерей binding.

## Сохранность и границы результата

A/E/B штатно остановлены. При повторном старте только B инспектор открывает
настоящий HVS **до создания сети**: все **513/513** строк, тела, delivered и
канонические позиции сохранены. Живое чтение затем подтверждает тот же
порядок при offline A/E/C. Это проверка restart-retention после сходимости;
аварийный SIGKILL внутри этой серии не выполнялся — он проверен в отдельной
[предыдущей серии](../history-crash-retention-2026-11-07/README.md).

Результат квалифицирует работу окончательной очереди с двумя реальными
источниками. Он не является native-воспроизведением deadlock промежуточного
кандидата: его red/control доказательства остаются protocol-тестами из
предыдущего цикла. Также это не A/B скорости, Android/AOT/Windows,
WAN/mobile handover, длительный offline или полная multi-device матрица.
Время всего теста 130,865 с включает pairing, подготовку архива, барьеры и
перезапуски; выдавать его за время догрузки нельзя. Mailbox собственных
устройств не добавлен. Остаточная задержка обработки истории остаётся активной.

## Проверки и очистка

**41 helper/oracle tests passed**: пять барьеров, два wire-наблюдателя,
десять crash-retention и 24 convergence checks. Analyzer семи изменённых
Dart-файлов чистый; native process-test прошёл один раз, без skip.
Барьер имеет минутный lease и прекращается при stop/retired binding;
наблюдатель ограничен 2048 записями. Идентификаторы источников доступны
только в явно включённом private test snapshot; публичные агрегаты их не
содержат, содержимое сообщений wire-наблюдатель не сохраняет.

Во время теста заморожены **1509** frontend/test/dependency inputs.
Выбранные SDK/CLI/HVS SHA проверены до старта, реальные OS mappings FFI/HVS
подтверждены у трёх работающих sibling workers после достижения барьера.
После теста sources и native artifacts неизменны, SDK чистый. Cleanup exit 0:
проверены **38 PID / 43 порта**, owned процессов и listeners нет, runtime
directory и одноразовые контейнеры удалены. Телефон, Windows, реальные
профили и публичные сиды не изменялись. Push/релиза нет.
