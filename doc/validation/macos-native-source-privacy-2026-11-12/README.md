# macOS: AOT и нативные пути сборщика — 2026-11-12

Продолжение [проверки нейтральных Windows/Android сборок](../aot-source-privacy-2026-11-12/README.md).
Проверена настоящая arm64 profile-сборка macOS; релиз не публиковался.

## Подготовка исходников

`scripts/aot_workspace.py` создаёт новую физическую копию входов в нейтральном
каталоге. На POSIX каталог имеет mode 0700, на Windows — защищённый ACL текущего
владельца. Копирование включает platform sources, assets и подготовленные native
libraries. Git-метаданные, старые build/Cargo/Gradle/Pods кеши и plugin links не
переносятся. Это обычные копии, не hard links; изменения при сборке не меняют
оригиналы. Для каждого файла сверены SHA; вычисляется fingerprint набора входов.
При отказе удаляется только созданный этой попыткой каталог.

Для текущего проекта перенесены **3120 файлов / 570,7 МиБ**. Locked offline pub
setup, `aot_package_roots.py` и Flutter config прошли. Xcode собрал profile AOT
в этой копии. Полная SDK workspace доступна для PacketTunnel; его Cargo target
отдельный и относится только к этой копии. Внешний диск не использовался.

Пять проверок workspace прошли на macOS и Windows 11, включая реальный Windows
ACL, сохранность исходников, очистку ошибки, бюджет и отказ следовать внешнему
directory alias. Первая попытка подготовки правильно отказала на старых plugin
links; `.symlinks`/ephemeral добавлены к исключениям, новые links создаёт pub.

## Почему одного Dart URI scan недостаточно

В новом `.app` домашних Dart URI стало **1290 → 0**, но дополнительный scan
фактического домашнего пути обнаружил **1873 совпадения в 27 файловых путях**,
включая повторный просмотр внутренних framework aliases:

- Сохранённая прежде Rust FFI содержала пути в строках кода и native debug
  records. Она не была заново собрана при первоначальном AOT-опыте.
- У plugin frameworks пути находились в native `SO` records.

Поэтому нулевой результат URI checker не принят за полную приватность `.app`.
Добавлен `--check-current-home`: дополнительно проверяет фактический путь
текущего сборщика, slash/URI-представление и UTF-8/UTF-16 LE/BE. Выводит только
количества. Путь и совпавшие строки не печатаются. Это не универсальный поиск
секретов или любых других аккаунтов. Девять checker tests прошли на macOS и
Windows; настоящая начальная `.app` при нуле URI не проходит новый native check.
Тесты поймали двойной подсчёт сдвинутых UTF-16 представлений; он устранён.

## Устранение нативных путей

Rust FFI пересобрана из текущей SDK-копии, с теми же production/node/packet-tunnel
features, что у предыдущей библиотеки. Применены home/source prefix maps для
Rust **и C/C++**, а не только Rust. Экспортируемые символы совпали с сохранённой
библиотекой. После этого остались десять `OSO` ссылок на путь установки Rust
stdlib — данные линковщика, которые Rust source remapping не переписывает.

Добавлен `scripts/strip_macos_debug_info.py`: перед подписью удаляет **только
native debug records** через `strip -S`, проверяя неизменность exported symbols.
Обычные символы и код сохраняются; runtime strings этим не очищаются.
Внешние dSYM не меняются. Bundled dSYM, внешний/битый link и ошибка чтения не
дают успешного результата. Framework aliases обрабатываются один раз.

Release-ветка `bundle-macos-dylibs.sh` вызывает helper перед существующей
последовательностью подписей leaf/framework/PacketTunnel/host. Debug-ветка
не изменена. Полный release bundler с новыми immutable media pins ещё не
квалифицирован; в опыте helper выполнен прямо над новой QA `.app`.

Три проверки helper прошли на macOS. Настоящая C-библиотека после обработки и
подписи сохранила exported и локальную функцию, UUID и внешнюю dSYM; вызов через
FFI вернул 42. Linux CI отдельно считает Apple-проверку skipped; добавлен macOS
job с настоящими clang/dsymutil/strip/codesign. Исправлены две ошибки собственного
fixture: split `SO` directory/filename и автоматическая bundled dSYM при
совмещённом compile/link; они не объявляются product red-тестами.

## Артефакт и запуск

В настоящей `.app` обработаны **22 уникальных Mach-O**. Полный scan после
повторной подписи и QA-запуска: **124 члена / 150 845 442 байта**, домашних URI
**0**, фактического домашнего пути сборщика **0**.

Для запуска задан отдельный QA bundle identifier, профиль, runtime directory и
холодная копия синтетического тестового контейнера. Исходная QA-копия на Windows
оставалась закрытой; её SHA сохранился. Основные приложения/личности не открывались.
Два запуска прошли `locked → ready` с `realStack=true`, затем POST `/lock`.
Во втором запуске список загруженных образов подтвердил SDK и hidden-volume
именно из новой `.app`; SHA этих файлов записаны перед завершением.

Это проверка открытия контейнера и живого узла, не звонка, слышимости, видео,
VPN или исходной жалобы Windows 10. QA-приложение ad-hoc, без VPN extension.

После опытов собственные процессы завершены, QA support directory/копия и
runtime удалены. Свои нативные Cargo caches удалены; приложение и доказательства
сохранены. Ничего не пушилось и не публиковалось.

## Дополнительный контроль Windows

Усиленный native check нашёл шесть путей в появившемся **после QA-запуска**
`xveil-debug.log` рядом с EXE. Это приватный runtime log, не новая строка AOT/DLL.
Лог перемещён за пределы bundle с проверкой SHA; повторный scan комплекта
41 файл прошёл по URI и фактическому домашнему пути. Приватный лог не публикуется.
