# Догрузка не отклоняет целую страницу из-за суммы размеров сообщений

2026-11-03. Подтверждён и исправлен дефект `_MessagingOwnHistory._serve`:
страница выбиралась по числу строк (до восьми), затем весь ответ отклонялся,
если его UTF-8 представление превышало 64 × 2048 = 131072 байта. Несколько
отдельно помещающихся сообщений могли вместе превышать лимит. Повтор того
же запроса снова строил такой же непригодный ответ и не продвигал догрузку.

Теперь сервер собирает помещающийся префикс страницы. Проверяется размер
полностью закодированного ответа: строки событий вложены в JSON ещё раз,
поэтому кавычки и обратные слеши увеличивают размер повторно. UTF-8 также
нельзя оценивать числом символов. Курсор указывает на последнюю включённую
строку и продолжает запрос даже при странице короче восьми сообщений.

Лимиты частей, строк, reassembly и admission сохранены. Проверки membership,
отзыва, identity binding, TTL и durable cursor применяются прежними путями.
Own-device mailbox не подключается; wire vocabulary не менялся.

## Проверки

Два новых воспроизводителя на прежнем коде получили **0/17** строк и запись
ошибки вместо продолжения. Ожидание завершалось по факту ошибки, а не по
порогу скорости. Это real MessagingService и HiddenVolumeStorage с проверяющим
FakeKvLogStore; native-сеть этим воспроизведением не моделируется.

После исправления оба набора получили **17/17**: ASCII-тексты по 20000 байт
и строки с UTF-8/кавычками/обратными слешами. Проверены ID, тела, порядок,
source positions и delivered. Ответы собирались из частей в обратном порядке
с повтором части; для каждого ответа проверен фактический byte cap, для
длинных страниц — разбиение на несколько ответов короче восьми строк.

Третья регрессия останавливает следующую page-request после сохранения
byte-limited префикса и перезапускает B. Первый новый запрос продолжает
точный durable cursor, все 17 строк получены, число вызовов apply равно 17.
Уже сохранённый префикс повторно не применяется.

**115 tests passed**, без skipped, в `own_device_history_test`,
`device_history_backfill_test`, `device_sync_test`, `device_sync_brick4_test`,
`device_group_slot_test`. Analyzer изменённых production/test-файлов чист.

## Границы

Этот фикс касается суммы нескольких сообщений. Если одно закодированное
событие само превышает 128 КиБ, текущий протокол по-прежнему не может вместить
его в страницу: ошибка остаётся явной, курсор не перескакивает через строку.
Обработка одиночных слишком больших событий требует отдельной проверки и
решения. Ускорение обычной короткой истории и полное устранение медленной
догрузки не заявляются.
