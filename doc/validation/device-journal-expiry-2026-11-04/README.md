# Очистка истёкших тел из журнала устройств — 2026-11-04

[Следующий цикл](../device-outbox-expiry-2026-11-04/README.md) проверил
transport Outbox: complete snapshot/delta copies теперь очищаются отдельно.
Неполные передачи и вся гарантия TTL по-прежнему не закрыты.

## Что подтверждено и исправлено локально

| Находка | Доказательство | Изменение |
|---|---|---|
| Device journal продолжал хранить текст после TTL переписки, включая author head и текст правки | Два новых теста на прежнем продукте красные: вместо пустого журнала остался head; вместо одного независимого setting остались mirror, edit и setting | Удаление проверенных истёкших mirror/edit rows; прежний разговорный tombstone препятствует повтору |
| Для удаления author head требовалось отделить sequence allocation от тела | Reopen и следующий подписанный post; проверка foreign edit head | Локальный монотонный `deviceMessageSeqFloors`, из уже проверенных записей. Он не является prefix cut: старые независимые settings не скрываются |
| Inventory guard не видел явного detach `ownHistoryApplyPrepared` | **Продуктовый дефект не подтвердился:** setter `ownHistoryApply = null` уже сбрасывает prepared callback | Добавлен явный парный detach для инвентаризации; он идемпотентен. Новые TTL bindings также отсоединяются под прежним owner guard |

Новый проход работает только с **точным локально принятым sovereign device
group**, проверенными подписями и текущим membership. Непринятая marker group
не получает права менять переписку. Unknown kinds и пока непроверяемые строки
не удаляются этим правилом. Политика контакта, tombstones и исходный timestamp
решают expiry; редактирование не продлевает жизнь сообщения. Удаляются точные
hash-идентичности строк, а не любые записи с таким же author/seq.

Очистка включена в существующий общий disappearing sweep с периодом 30 секунд.
Приём snapshot и штатный live/history publisher также фильтруют истёкшие тела
до сохранения device bundle. В incoming callbacks передаются только оставшиеся в
committed bundle строки. Для независимых обычных групп новый обход не нужен.

Сначала применяется прежняя TTL-очистка переписки; для неизвестной истёкшей
копии сохраняется bodyless разговорный маркер. Для известной допустимой позиции
он сохраняет gap-fill slot. Новым маркером живая строка того же ID не заменяется. Новый header
одновременно публикует local sequence floors и обязанность завершить scrub.
Потом удаляются старые сегменты, вызывается `scrubDeleted`, и только после
успеха снимается обязанность. Отказ header, удаления сегмента или vacuum
переживает reopen и повторяется, даже если в новом журнале уже нет ни строки.
Remote snapshot не может установить ни floor, ни scrub obligation: берутся
только значения из собственного предыдущего durable bundle. В wire их нет.

## Проверки

627 основных Flutter tests прошли, 3 native-conditional tests без FFI gate
отмечены отдельно как skipped. В наборе:

- 7 journal cases: expired head/reopen/next sequence; mirror+foreign edit
  и сохранность независимого state; отказы header, vacuum и segment deletion
  с reopen/retry; отсутствие local metadata в wire и отказ её подделке;
  отсутствие side effects от unadopted marker group.
- 2 background-sweep cases: journal hook вызывается один раз за общий проход,
  включая отсутствие expired conversation rows; отказ не выключает повтор.
- Group-binding inventory, прежние mirror admission, история, sync, storage
  и compaction checks. Прежние авторизация/подписи не заменены заглушками в
  продукте; unit-набор пользуется своим существующим fake signer.

После основного прогона условие stale-snapshot теста усилено отключением TTL
перед повтором уже отвергнутой записи; все 7 journal cases повторно прошли.
Продукт после сквозного прогона не менялся. Analyzer четырёх изменённых lib
файлов и всего `test/` — без замечаний.

Native A/B/C — отдельный OS process, настоящий HVS worker/container, signer,
сеть embedded nodes, провайдеры приложения и локальный relay island:

1. A/B — одна личность, C — другая; TTL 30 секунд заранее принят всеми.
2. B выключен. C→A и A→C действительно видны у источников, с разными ID,
   пока ещё живы; оба исходных тела действительно есть в journal A.
3. После реального истечения существующий background sweep удаляет их из
   journal A. Проверка не вызывает ручной sweep.
4. A перезапущен; записи отсутствуют и после чтения native durable bundle.
   B включён, новое A→C сообщение действительно получено B и C: sequence,
   подпись и догрузка продолжают работать после очистки head.
5. C выключен; старые ID отсутствуют в conversation и journal B в серии
   наблюдений. Затем A выключен, B холодно перезапущен — старые ID также
   отсутствуют. На этом участке TTL остаётся включённым.

Финальный test/driver/cleanup — 0/0/0. Проверены 28 PID, 33 порта; своих живых
процессов/listeners нет, runtime удалён. 1427 выбранных source/package inputs
не менялись во время исполнения, native SHA проверены до/после. Библиотеки
обычные, Veil `b8647716` и HVS `eceb9158`; private commit-stage probe не выбран.
144,109 с — длительность всего сценария с реальным ожиданием TTL и несколькими
запусками, не скорость доставки. Очистка не обещает ровно нулевую задержку после
TTL: это существующий фоновый период плюс выполнение I/O.

Ранний процессный прогон также прошёл функционально, но после него исправлена
пойманная census-тестом регрессия: hash witness строился и для обычных групп,
давая лишнее хеширование каждого старого payload. Guard перенесён перед его
построением; счётчик снова нулевой. После этого повторены основной и сквозной
прогоны, приведённые выше. Предварительный вывод о реальной утечке callback снят после проверки setter;
падение inventory guard само по себе этого не доказывало. Промежуточная ошибка частичного форматирования
тестового файла исправлена; её не считают продуктовой находкой или green run.

## Что ещё не закрыто

Этот цикл закрывает хранение истёкших тел **в текущем device journal при
известной локальной политике**, а не всю гарантию TTL для каждой копии данных.
Старые serialized snapshots/chunks в transport Outbox требуют отдельной
проверки и очистки: текущие replication frames могут включать оригинальные
device rows. Наличие plaintext в конкретной оставшейся очереди и её дальнейшее
поведение после TTL в этом прогоне отдельно не извлекались и не измерялись.

Также не квалифицированы порядок «mirror раньше политики», полный clock skew,
каждый peer-wire ingress, резервные копии/экспорты, Android и часы/сутки offline.
Независимая форензика носителя не проводилась: проверены native storage API,
удаление текущих bundle rows и контракт вызова/retry scrub. Нельзя выдавать
этот результат за очистку всех физических и транспортных копий на всех узлах.

Только локальные commits, без mailbox собственных устройств, push, релиза,
смены APK, движков и сидов. Публичный отчёт содержит агрегаты и имена кода;
сырые IDs, адреса, ключи, тела реальных сообщений и native-логи не публикуются.
