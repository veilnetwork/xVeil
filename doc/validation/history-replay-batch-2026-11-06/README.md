# История использует размер durable-пачки приложения

Агрегаты: [summary.json](summary.json).

## Что установлено

После сокращения отдельных metadata commit общая догрузка 2000 сообщений
оставалась около 32 с. Журналы показали следующий регулярный расход:
источник выдавал историю по 25 событий, а получатель 79–80 раз принимал
именно такую порцию. Между завершениями полных порций в первом контроле
медиана — 333 мс. Это интервал завершений ingest, не измерение сетевой тишины.
Каждая порция повторяла загрузку, проверку и сохранение группового журнала.

Приложение использовало консервативный default replay-helper, хотя его
`GroupService.postDeviceEvents` уже поддерживает durable turn до 64 событий,
а sender выполняет штатную snapshot fragmentation. Это вопрос настройки
существующего producer, не увеличение протокольного предела.

## Изменение

`deviceSyncBridge` явно использует `GroupService.kDevicePostBatch` (64).
Дополнительно установлен бюджет 32 КиБ подготовленных body/attachment
данных. Helper считает фактические UTF-8 байты JSON-обёртки с теми же
body/legacy attachment полями, которые будут подписаны. Это бюджет данных
до signature и остальных полей GroupMessage, не предел размера wire-frame.

Пачка отправляется при достижении количества или байтов. Если следующий
элемент превысит бюджет, предыдущая пачка проходит прежние durable admission,
cadence и backlog gates, затем начинается новая. Один oversized элемент
остаётся целым и передаётся отдельно; fragmentation остаётся у транспорта.
Сохранены порядок, счётчики только принятых событий, остановка после частичного
отказа и отмена. Generic default 25 и поведение host без postBatch прежние.

Политики не менялись: replication cap 256 frames, room threshold 128,
минимальный интервал 150 мс и перекрытие этого интервала с durable save.
Подтверждение caller по-прежнему ждёт локальную запись и admission в Outbox.
Mailbox для собственных устройств не добавлялся. Форматы, ACL, подписи,
retention, ratchet и authorization barriers прежние.

## Проверки

**48 history replay tests и 5 group admission tests passed, skips нет.**
Проверены идентичность событий/порядка/вложений, большие UTF-8 строки,
JSON escaping, превью файлов, oversized singleton, отмена при byte-flush,
удержание следующей строки до освобождения backlog gate, частичный отказ,
недопустимый бюджет, cadence и durable completion. Analyzer/diff чисты.

Mutation-контроль удалил центральную cancellation-проверку у flush:
тест стал assertion-red (`2` публикации вместо `1`). Код восстановлен
побайтно. Отдельная дополнительная проверка после flush оказалась избыточной
из-за уже существующей центральной защиты; она удалена, её passing mutation
не засчитана как красное доказательство.

## Native A/B/A и окончательная квалификация

Три Mac/JIT процесса, две личности, три loopback Core, настоящие
transport/ratchet/HVS; provider fixture без полного foreground SessionPipeline.
Во всех фазах один stand/instrumentation и одинаковые immutable native
artifacts. Каждая фаза имеет свежие identities/caches и свой scheduling.

| Фаза | Размер | Полная сходимость 2000 строк | Group commit у B, census | Все commit handler у B, закрытое VM-окно |
|---|---|---:|---:|---:|
| A₁, прежний `5d12637f` | 25 | 32,755 с | 300 | 838 / 17,686 с |
| B, первая проба | 64 | 21,583 с | 170 | 505 / 9,712 с |
| A₂, возврат прежней настройки | 25 | 28,032 с | 298 | 717 / 14,717 с |
| Финал, с byte budget | до 64 / 32 КиБ | 21,373 с | 174 | 514 / 10,217 с |

Group commit — сумма header/segment/pair, без двойного счёта. У источника A
они также уменьшились: 302/296 в контролях против 175 в финале; Outbox commit
174/182 против 82. Все 2000 ID, итоговый порядок, canonical positions и
`delivered` сошлись, потерь/дублей нет, retries завершённой истории — 0.

Состав порций подтвердил применение настройки: в контролях 79/80 полных
ingest по 25; в первой пробе 31 по 64; в финале 30 по 64 и меньшие порции.
Финальная byte-bound версия квалифицирована отдельно, её результат не
подменён измерением первой пробы.

Разброс A₁/A₂ заметен: message commit при прежнем коде тоже меняется из-за
гонки источников и последующих ordering corrections. Поэтому разницу всех
commit не приписываем только настройке. Снижение повторных group merge/save
подтверждается более устойчивыми отдельными счётчиками и обеими пробами.
Число принятых wire-chunk log-событий не уменьшилось (908 против 950 в первой
пробе); это не измерение ускорения или экономии сетевого канала.

Наблюдаемое время улучшилось на этом стенде; точный коэффициент для
пользовательской сети не заявляется. Опрос около 5 с, один Mac/JIT,
loopback/TCP. VM handler включает native/FFI и Dart worker adapter, это не
чистый fsync. Census/VM имеют разные окна; пересекающиеся RPC await не
суммируются как wall time. Все четыре VM-трассы имеют строгое FIFO-соответствие,
непрерывные sequence и точные суммы фиксированных commit-категорий.

## Границы и очистка

SDK `b9b88bb7` и HVS `eceb9158` не менялись. SHA FFI/CLI/HVS проверены,
1504 source/package inputs каждого run неизменны во время выполнения,
CPU samples положительные. Обратный контроль восстановил candidate точно;
финальная версия проверена своим frozen-source run. В трёх новых run OS mappings
подтвердили выбранные библиотеки у трёх клиентов.

После каждого run проверены по 22 PID и 34/35/36/38 портов соответственно:
своих процессов/listeners нет, runtime roots удалены. Сырые IDs/адреса/trace
остаются приватными; наружу вынесены только агрегаты. Пользовательские
контейнеры, телефон и production не менялись. Push/релиза нет.

Девять синтетических CPU-профилей трёх новых run сжаты без потери данных:
decompression/SHA проверены перед удалением исходного JSON, освобождено
452 МиБ cache. Профили сохранены в gzip, proof с исходными SHA — приватный.

Мобильная квалификация, foreground call latency во время миграции,
прерывание догрузки crash/restart, длительный offline и полная multi-device
матрица этим сценарием не закрыты. Остаток доставки остаётся активным;
следующий шаг — прерывание частичной догрузки и проверка восстановления
при временно offline источниках, без sibling mailbox.
