# История: публикация короткой страницы и 10 000 сообщений

## Подтверждённая лишняя работа

Страница истории уже вмещает до 64 событий, но публикация коротких сообщений
и исправлений позиции делила её на четыре транзакции по 16. На архиве
10 000 сообщений это давало 625 коммитов данных и повторные admission/read
проходы между частями одной страницы. Предыдущая no-op правка эту цену
не сняла: её A/B/A на том же размере оставался около 49 с.

Общий `preparedMessageBatchMaxRows` теперь разрешает до 64 подготовленных
записей или bodyless ordering corrections. Хранилище и история используют
один предел. Обычная coalescing-очередь живых сообщений/одиночных ordering
обновлений сохраняет свой отдельный предел 16.

Предел одной encoded storage-записи остаётся 1800 байт: не более 115200
payload-байт в prepared-транзакции плюс служебные операции. Сетевые лимиты
страницы (64 события, 128 КиБ), индивидуальных событий и частей не менялись.
Unsupported/oversized запрос по-прежнему возвращает null без частичной
записи, затем клиент использует обычный durable путь.

## Барьеры сохранены

Подготовка ограничена одной публикацией; порядок событий и границы между
post/ordering семействами сохраняются независимо от окончания чтений.
Источник/личность/привязка, отзыв устройства и актуальная политика видимости
перепроверяются перед native commit; erasure fence, повторная admission после
публикации, завершение row futures только после durable результата и отдельный
durable cursor checkpoint сохранены. Политика не кешируется между операциями.

Смена семьи может оставить короткую транзакцию. В регрессии 16 новых posts
уже durable, затем revoke запрещает 48 ordering corrections той же страницы:
старые raw-позиции остаются, курсор страницы не продвигается. При revoke/block/
TTL/retention перед первой публикацией ни одна из 64 строк не записывается.
Блокировка во время чтения read-clock также запрещает весь пакет.

## Регрессионная проверка

Возврат трёх production-файлов из parent дал **6 assertion failures** в
проверках полного prepared-пакета и публикации/ordering короткой страницы.
Ошибки именно Expected/Actual, не сборка или отсутствие native gates.
Candidate восстановлен после контроля. Первичная проверка 64-row append
на старом коде отдельно вернула unsupported null.

Финальная серия: **202 passed / 0 skipped**, включая **16 native HVS tests**;
анализатор чист. Покрыты большие/неподдерживаемые хвосты без prefix write,
дедупликация/тумбстоны, разделение conversation+ID, смешанные write families,
потеря ответа после atomic commit, отказ до commit, abort/teardown и overlapping
sources. Новый размер проверен для append и ordering.

Native-проверка держит commit полного пакета из 64 строк: future не завершён,
сырой message log пуст; после release весь пакет переживает reopen. Повтор после
потери ответа не создаёт дублей. Отдельная полная prepared-транзакция с длинными
inline-телами пересекает границу shard: после reopen видны все 64 тела/ID,
high-water без дыр. Проверяются реальные worker, FFI и encrypted container.

Первая попытка analyzer нашла два отсутствующих блока у многострочных if;
исправлены до финальной зелёной серии. Ошибок продукта это не добавляло.

## Native A/B/A на 10 000 сообщений

A/B/E — одна личность, C — другая; четыре независимых Mac/JIT процесса,
три изолированных loopback Core. A/E имеют одинаковые полные архивы;
оба первых authenticated ответа получены до release первого apply.
Setup источников использует прежние пакеты по 16 и находится вне timing.
Во всех фазах 10 000 архивных плюс одна прежняя строка, одинаковые native
CLI/FFI/HVS, VM sampling/timeline выключены, наблюдение раз в 1000 мс.

A₁/A₂ — parent; B — candidate. Различаются ровно три production-файла,
остальные **1521 из 1524 frozen inputs** одинаковы. SHA и OS mappings native
библиотек проверены, runtime SDK не пересобирался. Нынешний SDK delta касается
Windows VPN helper, не Mac runtime. Наблюдатели не обрезали записи.

| Метрика | A₁: parent | B: candidate | A₂: parent |
|---|---:|---:|---:|
| Apply release → сходимость, мс | 48760 | 34874 | 49729 |
| Encode release → сходимость, мс | 49258 | 35521 | 50242 |
| Коммиты сообщений | 625 | 157 | 625 |
| Коммиты history cursor | 316 | 316 | 316 |
| Резервы global log ID | 157 | 159 | 158 |
| Worker RPC | 61668 | 32739 | 61760 |
| HistoryApply callbacks | 20002 | 20002 | 20002 |
| Status API calls | 0 | 0 | 0 |
| Строк после boot без источников | 10001 | 10001 | 10001 |

На этом локальном стенде candidate быстрее среднего двух контролей на **29,18%**
и уменьшает message commits примерно на 75%. Возврат к parent возвращает
время к 49 с; это сравнение одной изолированной правки, не сравнение разных
поколений SDK. Три запуска не дают статистики флота/Android/WAN.

Все ID/тела/delivered/canonical positions/порядок совпали полностью, без дублей,
пропусков или посторонних строк; оба проверяемых conversation cursors завершены.
Cold boot при offline A/E/C сохранил весь архив. Источники действительно
предъявляли overlapping страницы: в каждом запуске 20002 apply callbacks.
Timing начинается после намеренного apply gate, не включает полный onboarding
или offline→reconnect путь. Завершающие empty-list checkpoints могут попадать
в census; это не обещание завершения всех фоновых inventory запросов.

## Остаток и завершение

**Большая догрузка остаётся активной:** 34,9 с на 10 000 сообщений ещё заметны.
Не изменились 316 cursor commits; рядом с 157 message commits остаются 159
allocator reservations и 32739 worker RPC. Следующий разбор — цена page/
checkpoint и оставшихся свежих чтений; эти счётчики сами по себе не доказывают
причину всего остаточного времени. Объединять их await-времена нельзя:
параллельные операции перекрываются.

Результат не закрывает NETCALL-01, Android/AOT/мобильную сеть, полную matrix
revoke/split-brain/crash/длительный offline. Нового SIGKILL-прогона здесь нет;
ошибки atomic commit и lost reply проверены отдельно и не названы SIGKILL.
Отложенные жалобы и ограничения сохраняют прежний статус. Sibling mailbox
не включён по решению владельца.

Cleanup A₁/B/A₂ проверил **36/38/39 PID** и **57/54/55 портов**; своих живых
процессов/listeners нет, временные runtime-контейнеры удалены, native artifacts
не изменились. Candidate восстановлен побайтно. Телефон, пользовательские
контейнеры и production не затронуты; push/релиза нет. В публичной
[summary.json](summary.json) только агрегаты, без private IDs, адресов,
payloads, секретов и машинных путей.
