# Истёкшие копии из журнала устройств — 2026-11-04

Статус хранения в журнале ниже зафиксирован на момент этого прогона. В
[следующем цикле](../device-journal-expiry-2026-11-04/README.md) добавлена
очистка текущего принятого journal и новый сквозной oracle; транспортные копии
TTL и полная матрица остаются отдельной работой.

## Результат

| Находка | Статус | Подтверждение |
|---|---|---|
| Поздний `msgMirror` записывал уже истёкшее тело в переписку | Подтверждено, локально исправлено | До правки оба теста — incoming и outgoing — получили `true` вместо отказа. После правки проверены пустой tombstone, исходная позиция и отсутствие тела/медиаполей в message log. |
| Тело остаётся в подписанном журнале собственных устройств после TTL переписки | **Подтверждено, открыто** | Отдельные процессы действительно получили исходные тела из device journal после истечения TTL; те же записи сохранились после cold restart. Это не исправлено фильтрацией проекции. |

Обычный mirror admission раньше не применял TTL до `appendMessage`. Отдельный
own-history путь уже имел фильтр, а sweep после приёма маскировал этот пробел.
Теперь неизвестная копия проверяется по действующей политике контакта и
нормализованному исходному времени до записи тела. Существующий предел будущего
времени не изменён. Истечение включительно: `timestamp + TTL <= now`.

Вместо сообщения сохраняется только локальный tombstone. Он препятствует
повторному появлению ID после отключения TTL и отката часов. Подтверждённая
пара author/sequence сохраняется как пустой слот gap-fill; для legacy-копии
без пары новая исходящая sequence не выделяется. Маркер не создаёт обязательство
удаления у собеседника и не заменяет уже имеющееся живое сообщение. Сохранение
идёт через прежние durable commit и fences close/erase. Отказ записи и потеря
ответа после commit безопасно повторяются.

## Проверки

- 325 основных Flutter tests прошли: storage, история, mirror, удаления,
  подтверждения и TTL. Включены 7 новых admission cases: обе стороны,
  точная граница и свежая копия, TTL-off/restart/откат часов, future clamp,
  legacy-позиции и медиаполя.
- 4 новых native tests прошли на настоящем HVS worker/container: пустой
  durable слот и повтор после reopen, отказ до commit, потеря ответа после
  commit, сохранность существующей живой строки. Никаких skip в этих запусках.
- Analyzer для трёх изменённых lib-файлов и всего `test/` — без замечаний.
- Отдельный native A/B/C process test прошёл. A/B — одна личность, C — другая.
  TTL 30 секунд заранее принят всеми. B выключен; C→A и A→C действительно
  видны у источников с двумя разными ID до истечения TTL, а A держит их mirrors
  в подписанном журнале. После реального истечения C выключен, B включён.
  B получил оба исходных journal mirror, но их ID отсутствуют в conversation
  storage в серии чтений без ручного sweep. Затем TTL отключён, A выключен,
  B перезапущен: исходные journal entries по-прежнему есть, оба сообщения
  по-прежнему отсутствуют. На B зафиксированы три отказа expired admission;
  этот агрегат сам по себе не является per-ID атрибуцией.

Использованы неизменённые обычные native-библиотеки, без private commit-stage
probe. Veil `b8647716`, HVS `eceb9158`; SHA артефактов проверены до и после.
1427 выбранных source/package inputs были неизменны во время process-прогона.
Driver/test/cleanup завершились с 0; проверены 24 PID и 25 портов, оставшихся
процессов/listeners нет, runtime-каталог удалён. 114,137 с — длительность всего
теста с запуском процессов и ожиданием TTL, не метрика доставки.

## Открытые границы

Сохранение исходного тела в device journal противоречит заявленной гарантии
TTL о байтах, поэтому остаётся отдельным активным дефектом. Журнал подписан,
а его compaction сохраняет author heads; произвольно переписать тело или
удалить head без сохранения chain/sync инвариантов нельзя. Требуется отдельный
разбор хранения и очистки. Эта правка не обещает forensic erasure из журнала.

Не квалифицированы все прямые peer-wire пути поздней доставки, приход зеркала
до получения TTL-политики, истечение во время долгого append, весь clock-skew
сценарий с тремя различными часами, TTL на часах/сутках и Android. Проверки
с injected clock охватывают только перечисленные ветви; часы ОС не менялись.
Матрица 56–59 целиком не закрыта. Общая latency также не измерялась.

Mailbox для собственных устройств не добавлен. Синхронизации по-прежнему нужен
доступный держатель копии. Push/релиза/обновления APK, движков и сидов нет.
Публичный отчёт содержит только агрегаты; сырые journal bodies, реальные ID,
адреса, пути контейнеров и native-логи в него не включены.
