# Догрузка: хэширование только кандидатов новой порции

**Подтверждено и исправлено лишнее хэширование сохранённого журнала при
каждой новой порции device-событий.** Проверка точного durable membership
сохранена. Накопленная задержка догрузки остаётся активной.

Результаты и provenance: [summary.json](summary.json).

## Причина и изменение

После сохранения принятой порции GroupService строил множество полных
commitments всех `committed.messages`, затем проверял в нём только `fresh`.
Для очередных 25 событий это снова сериализовало и хэшировало уже принятую
историю. В контрольном тесте — 1025 полных хэшей для 25 свежих строк.
Даже при пустой порции выполнялась лишняя работа.

Теперь дешёвый синхронный индекс `(author, seq, signature)` отбирает возможные
совпадения среди сохранённых строк. Для каждого кандидата вычисляется прежний
SHA-256 от canonical bytes и подписи. Перед materialize/stream каждого свежего
события по-прежнему проверяется точное совпадение полного commitment.
Один совпавший slot сам по себе не разрешает публикацию другого payload.

Сканирование метаданных сохранённого списка остаётся линейным. Сокращена
сериализация/хэширование payload, а не чтение всей истории или все проверки
подписей. Авторизация и принятие группы до этого участка, lifecycle/retention,
проверка успешного сохранения и порядок stream не менялись. Нет кэша вердиктов
между await, новых wire-полей, ослабления durable barriers или own-device mailbox.

## Проверки

Исходный индекс механически вынесен в helper без изменения алгоритма.
До оптимизации два ресурсных контроля assertion-red: 1025 вместо 25 хэшей,
100 вместо 0 при пустом ingress; четыре проверки точного совпадения проходили.
После изменения восемь focused проверок проходят, включая мутацию ID/подписи,
изменение nonce/ciphertext/MAC, competing rows одного slot и duplicate candidates.
Это проверка отбора, не замена signature verifier тестовым hash.

Связанные GroupService/history/backfill suites: **555 passed / 11 skipped**.
Последующий native запуск: **12 passed / 0 skipped**, включая восемь focused
и настоящие проверки native/Dart SHA-256 chain и signature-verdict boundary.
Пересекающиеся наборы не складываются в число различных тестов.
Analyzer трёх изменённых Dart-файлов — замечаний нет.

Контролируемый AOT A/B/A использует настоящий `veil_sha256`, одинаковые
2000 сохранённых encrypted rows и 25 свежих кандидатов; 20 точных совпадений
и пять изменённых payload должны различаться во всех фазах. В каждой фазе
80 повторов, включая неизменённую проверку хэша каждого fresh-события:

| Фаза | Время этапа | Полных хэшей |
|---|---:|---:|
| A₁, прежний индекс | 1,908 с | 162000 |
| B, отбор кандидатов | 0,092 с | 4000 |
| A₂, прежний индекс | 1,897 с | 162000 |

Это замер конкретного локального этапа. Он не означает двадцатикратного
ускорения сообщений, синхронизации или всего приложения.

## Два native-прогона большой истории

Три отдельных процесса A/B/C одного Mac: A/B одной личности, C — другая.
Настоящие контейнеры и SDK/CLI `bbeaf3a9`, обычная HVS `eceb9158`.
Все узлы ограничены loopback island, builtin seeds/discovery выключены.
Frontend JIT, включены одинаковые CPU/storage/history observer параметры.

| Наблюдение | До | После |
|---|---:|---:|
| 2000 ID уже видны | 32,857 с | 32,842 с |
| Полная сходимость ID/порядка/позиций/delivered | 38,091 с | 32,842 с |
| Доставленных сообщений | 2000 | 2000 |
| Completed-history retries | 0 | 0 |
| Invalid snapshots | 0 | 0 |

Наблюдатель опрашивает примерно раз в пять секунд; первая полная выборка
не является точным временем последнего commit. Это по одному прогону,
с разными свежими контейнерами/сессиями, без macro A/B/A. Ускорение всей
миграции не объявляется. В обоих прогонах одинаковы native bytes, источник
и параметры HVS; все выбранные source inputs заморожены на время своей серии.
У трёх candidate device-workers дополнительно проверены exact dylib mappings.

Baseline B CPU-window — 40,832 с, main 3899 samples; canonicalBytes 705
inclusive ticks. Это не exclusive I/O или доля wall time. В baseline также
431 message-log и 732 other commit RPC; в candidate 337/725. Разницу числа
коммитов не приписываем этой hash-правке: коалесцирование и порядок потоков
вариативны. Значимая цена durable I/O и оставшейся проверки истории сохраняется.

## Ошибки оснастки и cleanup

Первый запуск до измерений не прошёл: выбранная старая HVS была проверена
по старому SHA, но не содержала нового метода `read_log_groups`. ABI gate
отказал в загрузке, контейнер не открылся. Это не регрессия приложения и не
зачтённая серия. После полного teardown выбрана обычная текущая HVS с
проверенными source/bytes и всеми 45 checksum-функциями bindings.
Первый вызов AOT compiler с неверным расположением `--packages` также
не считается исполнением benchmark; исправленная команда выполнилась штатно.

Все три стенда завершены. Квалифицированные серии: проверены 22 PID / 32
порта и 22 PID / 33 порта; собственных процессов/listeners нет, runtime
удалены. Неуспешный startup также имеет успешный cleanup. Сырые профили,
логи, временные ключи и пути хранятся только в приватном кэше.
Телефон, Windows, публичные реле и пользовательские контейнеры не менялись.
Push и релиз не выполнялись.
