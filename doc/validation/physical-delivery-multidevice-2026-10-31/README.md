# Физическая доставка и первые multi-device сценарии

2026-10-31. Приложение `fbfe9b4e`, Veil `c46d94db`.
**Новый подтверждённый случай: медленная догрузка истории на Android.**
Изменений product-кода, push и релиза в этом раунде нет.

## Стенд и происхождение сборок

A — Mac; B — физический Android той же личности; C — второй Mac другой
личности. API подтвердил три различных device ID и прежние личности. Контакты
и связь A/B уже существовали: создание/привязка новой личности этим опытом
не проверяются. На телефоне имелась большая предыдущая QA-история: около двух
тысяч сообщений в разговоре, а не пустой профиль.

Android — свежая ARM64 profile/AOT сборка текущего Dart-кода и SDK. Cargo target
для Android не содержал прежней библиотеки; внешняя файловая система проверялась
до сборки и watchdog во время неё. APK проверен по SHA, наличию AOT и отсутствию
kernel blob; подпись совпала с прежним QA APK. Native media, translation и
hidden-volume библиотеки оставлены побитово прежними.

На обоих Mac текущие Dart assets и SDK помещены в прежний QA Runner с прежними
плагинами; ad-hoc подпись проверена. Это **не квалификация заново собранного
macOS релиза**. Фактически отображённая dylib сверена с упакованной.

Публичная сеть, `anonymous=false`, без закрепления маршрутов. Включено
диагностическое логирование. Нет старой/новой A/B пары; измерения не доказывают
ускорение или регрессию относительно релиза. Не квалифицировались Windows 10,
исходный проблемный мобильный провайдер, звук и видео.

## Результаты

| Проверка | Результат | Граница вывода |
|---|---|---|
| C → A/B при всех online | Обе копии доставлены, один ID | Две отправки в исходной серии |
| A → C и B → C при online sibling | Исходящая копия появилась на sibling | По две отправки с каждого устройства |
| B offline минимум 5 минут; C остановлен перед возвратом B | Догрузка медленная: 0/3 исходных проверочных сообщений за 120 с расширенного наблюдения | A оставался online; C затем вернули |
| Пока B offline, A отправляет C 100 сообщений | Все приняты за 44,935 с; на B после 120,178 с наблюдения — 19/100 | Позже все 100 получены; срок полного восстановления не измерен непрерывно |
| Одновременные отправки A и B на C | 20/20 у всех, одинаковые ID и порядок | Во время диагностического CPU-профилирования; не тест скорости |
| Итоговая сверка всех серий | **129/129 у каждого**, одинаковые ID/порядок, без дублей | Конечная согласованность, не отсутствие временных пропусков |

В исходной online-серии шесть сообщений наблюдались у собеседника за
примерно 0,8–3,6 с от API-команды, на sibling — до 6,349 с. Это верхние границы
по polling сохранённой истории, включающие очередь команды, запись и чтение;
не RTT транспорта. В десяти одновременных парах отправители иногда ждали долго;
все двадцать копий были видны примерно через 210 с от начала всей серии, а не
через 210 с после каждой отдельной отправки.

**Проверка offline не прошла по скорости.** Полное восстановление после возврата
C не доказывает доставку без C: такой результат отдельно не заявляется.
Не обнаружено необратимой потери этих 129 сообщений, но это не закрывает
остальные сценарии матрицы и не доказывает отсутствие потерь вообще.

## Что показали журналы и профиль

Mac подготовил ответы own-device sync с примерно 205 строками в четырёх
крупных кадрах, по 20–22 транспортные части. В очереди наблюдалось 259
неподтверждённых кадров. Это снимок нагрузки, не доказательство её причины.

На телефоне между записью о начале обработки group entry и уведомлением
`ingest streamed` регулярно проходило несколько секунд. Следовательно, есть
наблюдаемая задержка внутри клиентской обработки; всю длительность догрузки
нельзя приписать прохождению сети. Разделение чтения, проверки, записи и ACK
ещё требуется. Объяснение «планировщик посылает только один кадр за проход»
не подтверждено: trace показывает серии быстрых постановок нескольких частей.

После первой offline-серии телефон штатно перезапущен с разрешённым локальным
VM-профилированием; в отдельной concurrent-серии сняты 14781 CPU samples main
isolate. Включительные счётчики:

| Функция | Samples |
|---|---:|
| `_validMessageFor` | 2410 |
| `_messagesOfBundle` | 2337 |
| `_verdictKey` | 1467 |
| `_writeLogFile` | 252 |

Эти величины **не складываются**: вложенные вызовы пересекаются. Они не являются
долями wall-clock задержки и не измеряют ожидание worker/native I/O. Профиль
указывает на обходы истории и повторное вычисление криптографического ключа
кэша даже при сохранённом verdict; он не доказывает единственную причину паузы.
Синхронный диагностический лог также имеет стоимость. Нельзя переносить числа
этой QA-сборки на обычную сборку с выключенным логированием без контроля.

Сырые VM samples, адреса, сообщения, device/identity IDs и журналы остались
только в закрытом QA-каталоге. Публичны [агрегаты и SHA артефактов](summary.json).

## Ошибки наблюдателя и незачтённые сценарии

После добавления ста сообщений хвост истории из 60 записей перестал охватывать
первые три сообщения теста. Отдельный наблюдатель расширен до 250 записей:
через 120,178 с он видел 19 из ста и ни одного из трёх ранних сообщений. Поэтому
отрицательное наблюдение не основано только на прежнем коротком хвосте.
Ранний автоматический summary с пустыми списками и vacuous equality
не засчитан как прохождение: итог сверял все 129 настоящих записей и ID.

Попытка сценария принудительного завершения посреди догрузки была остановлена
предусловием: к этому моменту на B уже имелись все 100 сообщений. Приложение
не завершалось этим драйвером; сценарий 16 **не выполнен**. Последующий перезапуск
для профилирования сделан уже после полной догрузки и его не подменяет.

Оба источника offline при возврате B, новый device с прежней историей,
revoke/split-brain/crash, звонки/файлы, часы/сутки offline и остальные пункты
матрицы в этом раунде не выполнены. Совместимость со старыми версиями исключена
из активной очереди пользователем.

## Завершение и следующий участок

Начатые Mac/Android QA процессы остановлены, порты проверены повторным bind,
собственные ADB forwards и временные runtime-каталоги удалены. На телефоне
восстановлен исходный QA APK с точной сверкой SHA, приложение оставлено
остановленным. Основной Android пакет не менялся; профили и новые durable
состояния сохранены, отката истории не было. Резервные копии исходных профилей
остались приватными. Два избыточных полных CPU capture удалены; один сжат.

Активно: разложить многосекундную обработку одной device-group записи на
чтение/валидацию/сохранение/ACK, затем проверить изменение на той же большой
истории с контролем стоимости диагностики. Долгая доставка не объявлена
исправленной; найден воспроизводимый физический сценарий для следующего раунда.
Исторические 25 с / 120 с file offer / «33%» по указанию пользователя остаются
отложенными до повторения.
