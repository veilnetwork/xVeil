# Сжатие, блокировка и удаление контейнера — 2026-11-11

## Подтверждённые случаи

| Случай | Доказательство | Изменение |
|---|---|---|
| Авто-сжатие открывает пространство после lock | Реальный контроллер, gate на close; после завершившегося lock старый обработчик отказа повторно вызывает open | Проверки исходной авторизации на этапах авто-сжатия и в восстановлении после отказа |
| Старый unlock начинает авто-сжатие после lock | Gate перед фактическим open: lock завершён, старый opener отпущен; backend сжатия получает один вызов вместо нуля | Проверка исходного lifecycle после open и чтения roster; поздно открытый handle закрывается |
| Удалённый файл возвращается после native rename | Реальная библиотека: процесс остановлен перед rename, исходный путь удалён, процесс продолжен; файл появился снова, оба пароля и 33554432 байта данных читаются | Wipe ждёт завершения принятого ручного/автоматического сжатия, включая remap/recovery, затем удаляет файл |
| Временные копии после прерывания не входили в wipe | Предыдущие SIGKILL-прогоны оставили native temporary siblings; wipe удалял только основной файл и blob tier | Точный отбор temporary siblings этого контейнера, удаление и свежая проверка отсутствия; отдельные сообщения о survivor/невозможности проверки |

Исходная жалоба на чёрный экран и невозможность открыть контейнер обоими
паролями **не воспроизведена** и этим раундом не объявляется устранённой.
[Предыдущие проверки](../compaction-two-spaces-2026-11-11/README.md).

## Владение операцией

- Ручное и автоматическое сжатие имеют общий барьер завершения. Другая
  compaction не заменяет запись уже принятой работы и не запускается поверх неё.
- Wipe заявляет владение до первого await; повторный запрос получает ту же
  операцию. Новые unlock и compaction во время wipe не принимаются.
- Lifecycle отзывается сразу. Старое сжатие после этого не открывает сессию.
  Native rewrite уже в работе не отменяется; wipe ждёт его quiescence без
  таймаута, который позволил бы сообщить успех до позднего rename.
- Native-отказ тоже завершает барьер: он не препятствует дальнейшему удалению.
- `containerCompactorProvider` — зависимость для одного external FFI-вызова.
  Production по-прежнему вызывает `hv.compactKnownAsync`; тест может удержать
  publish, не меняя защиты или ABI native-библиотеки.

## Временные файлы

Распознаются только текущие native-имена рядом с конкретным контейнером:
`.<имя>.hv-compact.<16 lowercase hex>.tmp` и вариант `hv-rotate`.
Имя контейнера экранируется как литерал. Другие контейнеры, похожие префиксы,
неполные nonce и backup-расширения не удаляются. Подкаталоги не обходятся,
symlink удаляется как ссылка без удаления target. Неожиданная директория с
таким именем сохраняется и попадает в отчёт о незавершённом удалении.

После cleanup выполняется новый inventory. Ошибка его чтения — отдельный
статус unknown, а не пустой список. Сообщения для обеих ветвей доступны в
RU/EN/ES. Прямые пути и имена файлов в новый отчёт wipe не добавлены.

## Проверки причинных границ

- Начальный красный auto-close сценарий повторно открывал пространство после
  lock. Парный контроль без lock сохраняет штатное восстановление.
- Дополнительный красный initial-open сценарий вызвал backend после lock;
  после исправления поздний opener закрывается и backend не запускается.
- Wipe на удержанном external backend раньше возвращался до его завершения:
  красные обе ветви — последующая публикация и отказ backend. Проверка через
  явные gates и `Future.any`, без порога длительности. Это app-ordering тест
  с контролируемой зависимостью, не подмена физической native-квалификации.
  Ошибка extends/implements в первом тестовом VPN-backend исправлена до
  зачётного красного прогона и не включена в число дефектов продукта.
- Три single-file behavioural rollback-контроля: отмена auto-guard'ов отвергнута
  тремя lock-сценариями при трёх проходящих live-session контролях; удаление
  ожидания wipe — двумя сценариями при двух проходящих остальных; отключение
  очистки temporaries — двумя при двух проходящих остальных. Эти контроли
  относятся к конкретным проверкам защитных границ, не ко всей родительской
  версии приложения. Новый initial-open тест проверен красным отдельно позже.
- Реальный native control: удаление только **после** завершения rewrite не
  приводит к повторному появлению файла. В raw-прогоне нет AppController:
  механизм native rename и правильный порядок приложения квалифицированы
  отдельными, дополняющими друг друга проверками.

Native-прогон: macOS, закреплённая hidden-volume 2.7.0,
SHA-256 `a1c9a791ca186a7aa432e736565da07c897087617397fe19cf24e9b87f290fa8`,
Argon min, два пространства, синтетические данные. Новая Rust-сборка не нужна.
Это не проверка потери питания, Android process-kill или чужого процесса,
самостоятельно работающего с тем же файлом.

## Статус Android

Отдельный Compaction QA на Blackview, Android 11. Настоящий AOT и native stack,
прежний fixture через «Начать заново», обычные Android Argon-параметры.
Входы native побайтно сверяются с APK 0.13.95 (hidden-volume 2.7.0); это
изоляция изменений приложения, а не квалификация всего нового Veil/media SDK.
Синтетические device configs заранее добыты, nonce-generation не проверяется.
Основное приложение и его контейнер не открываются.

- Обычное сжатие: оба пространства в списке по одному разу, дубликат пароля
  отклонён; примерно 60 с до успешного результата. После операции и отдельного
  холодного запуска оба профиля, файлы по 70000 байт и последняя настройка
  совпадают, оба идентификатора сохранены. Это один контроль, не замер ускорения.
- Во второй операции QA-процесс остановлен при временном файле **1052672 байта**.
  Перед `am force-stop` процесс приостановлен, проверены прежний source inode
  и исходный SHA. После остановки source inode и все байты прежние. Свежий
  процесс открыл оба пароля; профили, файлы, настройки и идентификаторы совпали.
  Это конкретная проверка Android process-kill **до rename**, не потеря питания
  или прерывание после публикации нового файла.
- Через настоящую кнопку «Удалить все данные» и ввод фразы подтверждения
  удалены основной файл и реальный orphan прерванного rewrite. Контрольное имя
  другого контейнера осталось. Два явных последующих open прежними паролями
  отвергнуты, контейнер заново не создан. Контрольный файл стенд затем удалил.
- Два сбоя наблюдателя (раннее нажатие при автоматической пробе пароля и
  единичный pidof до появления нового процесса) не зачтены как продуктовые
  дефекты или успешные прерывания. Проверка продолжена из подтверждённого
  состояния: повторный rewrite/второй процесс для обхода ошибки не запускались.

Две попытки сборки остановлены политикой macOS, запрещавшей запуск SDK
gen_snapshot с меткой quarantine. Подпись Flutter проверена; метка временно
снята только с этого инструмента и восстановлена побайтно после сборки,
байты SDK не менялись. Это ошибка окружения, не прохождение проверки и не
дефект приложения.
