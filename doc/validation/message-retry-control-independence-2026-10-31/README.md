# Повторы сообщений не ждут управляющую очередь

2026-10-31. База `6fe8b42f`, SDK `c46d94db` не менялся. Без push/релиза.

## Подтверждённый механизм задержки

`_MessagingMessageDelivery.flush` полностью ожидал `_flushOutboxFrames`,
а только затем начинал reconciliation обычных разговоров и повторы сообщений.
Управляющая очередь уже имела четыре независимые полосы адресатов, но это
не освобождало следующий этап: ожидание одного control live leg с обычным
дедлайном **10 с** удерживало все обычные сообщения. Медленное чтение control
Outbox давало ту же блокировку ещё до начала сетевой попытки.

Два gate-теста на прежнем коде воспроизвели отсутствие отправки обычного
сообщения при закрытом gate другой очереди. Один удерживал чтение Outbox,
второй — отправку control frame другому принятому контакту. Готовые microtasks
пропускались через event-loop barrier; 10-секундный timeout не ожидался и
не засчитывался за независимый прогресс. В обоих красных случаях ожидалось
одно отправленное сообщение, фактически было ноль.

Теперь control job и conversation job запускаются независимо через
`Future.wait<void>`. Общий проход завершится только после обеих задач, в том
числе при ошибке одной из них. Нет fire-and-forget поверх новых задач,
снятия durable frame без ACK или второго драйвера повторов.

Control ceiling **16 попыток**, **4 полосы адресатов**, per-peer lifetime
занятости, дедлайны и backoff не менялись. Внутри conversation job порядок
разговоров и сообщений также прежний. Пауза фоновой работы во время звонка,
проверка принятого контакта и `prepareStoredRetry` перед публикацией сохранены.
Реле не получают новых признаков/приоритетов.

## Проверки

Итоговый набор: **309 passed, 0 skipped**. Включены durable redrive/outbox,
полосы и invalidation/lifetime очереди, retention/jitter/expiry, обычные
отправки/редактирования/ACK, барьер собственного журнала, ratchet и обработка
сигналов звонка/групповых receipt/source очередей.

Четыре новых проверки: независимый прогресс при удерживаемом чтении и отправке
control; сохранение media pause; ошибка conversation job не завершает проход,
пока control job остаётся активным. После освобождения gate ошибка передаётся
вызывающему, durable control row остаётся до подтверждения. После поправки
только стиля targeted набор снова прошёл 4/4; scoped analyze: no issues.

Финальный native regression stand: 12 отдельных production-PoW личностей,
один Mac/JIT process, TCP/DHT, encrypted worker-контейнеры, native seal/ratchet,
host authorization и настоящие MessagingService/group fragmentation/ACK.
4/4 сообщения дошли всем 12 без дублей; host exited, 12 listeners освобождены,
cleanup errors=0, timing dropped=0, временный root удалён.
Это legacy-группа без epoch encryption; контакты/roster стенда подготовлены
отдельно. Этот прогон проверяет регрессию групповой доставки, **не воспроизводит
сам gate обычного сообщения против control и не является A/B ускорения**.
Причиной прежних физических 53/114,9 с новый механизм не объявляется.

## Отрицательный эксперимент чтения metadata

Перед этим fix отдельно разбирался остаток group handling. Пассивная
классификация worker-запросов обнаружила 1352 проверки group disk-tier,
983 чтения metadata header и 829 segment metadata в одном профиле. Внутри
конкретных group frames чтения и записи занимали большую часть ожиданий.
Это API timings с worker queue; суммы перекрываются между 12 узлами и
не являются временем одного сообщения или чистым fsync.

Подтвердилось отдельное повторное чтение metadata при `storeFile`: sync/async
писатель уже прочитал metadata, а затем снова читал её внутри `loadFile`
для сравнения старых байтов. Два новых red-теста фиксировали 2 чтения вместо 1.
Кандидат переиспользовал только локальные metadata данного вызова, без
межвызовного cache. 120 storage/streaming/GC/atomicity тестов прошли.

Но в трёх A/B-парах четвёртое сообщение каждый раз стало медленнее:

| Показатель, медиана трёх прогонов | A | B |
|---|---:|---:|
| Первое сообщение всем 12, мс | 3896 | 3771 |
| Второе, мс | 1676 | 1669 |
| Третье, мс | 1671 | 1515 |
| Четвёртое, мс | 2138 | 2498 |
| Все `get` в окне | 7283 | 7079 |
| Group header metadata `get` | 978 | 772 |

В сравнении менялся только `file_store.dart`, остальные lib/test-support,
fixture и native libraries были заморожены по SHA. После каждого запуска
происхождение проверено, candidate восстановлен; затем **кандидат исключён**,
`file_store.dart` побитово возвращён к базе. Probe и его тесты сохранены только
в закрытом каталоге эксперимента. Изменение расписания само по себе не доказывает
корень ухудшения; уменьшение числа чтений не заменяет проверку задержки.
Пакетирование KV-чтений в продукт не добавлялось.

Все 24 сообщения A/B дошли всем 12 без дублей и с чистым teardown. Исходный
дополнительный attribution profile также доставил 4/4; он не является скоростным
контролем (часть времени параллельно шёл отдельный короткий unit-контроль).
С учётом финального regression stand всего **32 сообщения в 8 native stand**.
Приватные адреса, ключи и correlation ids не включены в публичные агрегаты.

## Остаток

Длительная доставка остаётся активной. Внутри conversation job разные
разговоры пока обслуживаются последовательно; медленный обычный адресат может
задерживать следующих. Это следующий кандидат на gate-проверку, не результат
нового теста. Также не сняты прежние 16-attempt/3-секундная cadence и backoff
управляющей очереди и mailbox cadence; их цену надо квалифицировать физически.

Новая правка не квалифицирована на телефоне/Windows, публичных onion-реле
или полной multi-device матрице. Исторические 25 с / 120 с / «33%» остаются
отложены до повторения по указанию пользователя. Следующий этап после задержек —
запрошенная multi-device матрица; непроверенные случаи не объявлены дефектами.
