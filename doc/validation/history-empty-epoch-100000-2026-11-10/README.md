# Не сворачивать control log ради пустого ключевого материала

## Подтверждение и исправление

Потоковый CPU-профиль получателя на 100000 сообщений указал на
`GroupService.load` → `_mergeEpochMaterial` / `_acceptedControl` при чтении
адресов своих устройств. Загрузка всегда вызывала восстановление group/channel
epoch material. Даже когда не было ни локальных ключей, ни сохранённых или
входящих конвертов, выполнялась свёртка управляющего журнала. Свёртка одного
merge могла обслужить второй через существующее bundle-local memo, но при
следующем свежем `load` работа повторялась.

В обеих функциях пустые три входных коллекции теперь сразу дают свежие пустые
результаты. Любой ключ или конверт оставляет прежний путь проверки descriptor,
commitment, подписи, получателя и открытия. Кэш авторизации не добавлен.
Проверки manifest/sovereign bundle при загрузке сохранены; свежая проверка
членства на маршрутизации не удалялась. `load` и прежде возвращал исходные
control rows: пустой merge не был границей допуска этих строк.

## Регрессионные проверки

Две новые проверки на parent падают по счётчику работы: **6** helper folds
при пяти plain loads и **3** при трёх device-journal loads вместо нуля.
В первом числе учтена попавшая в окно фоновая работа; тест требует отсутствие
ненужных свёрток, а не точное число на parent. На candidate обе дают ноль.
Проверяется непустой управляющий журнал при пустых group/channel keys/envelopes.
Отдельно проверено, что прогретое чтение адресов не переживает revoke.

Третья новая проверка оставляет по очереди только ключи и только конверты
настоящей epoch E2EE-группы: свёртка выполняется, сообщение читается.
Полный связанный набор включает защищённые каналы, ротации, cold start,
signature/admission, revoke и гонки маршрутизации.

Существующий тест двух последовательных routing reads ожидал четыре проверки
каждого control entry — load и routing на каждое чтение. Теперь ожидает
**две**, по одной свежей routing-проверке; два чтения durable header и проверка
неизменности сохранённого журнала остаются. Первоначальный отказ этого старого
cost expectation сохранён, не засчитан как прохождение.

**750 related passed / 0 skipped**, отдельно **6 native read/crypto checks**;
analyzer трёх изменённых Dart-файлов чист. Одна native segment-проверка сначала
была явно skipped из-за отсутствующего пути identity fixture, затем выполнена
отдельно с проверенной библиотекой и штатным тестовым fixture — passed.

## Native A/B/A на 100000 сообщений

Parent `193b0361` → candidate → parent. Те же четыре Mac/JIT процесса,
три изолированных Core, FFI/ratchet/зашифрованные контейнеры, два источника
полного архива. До apply release удержаны первые authenticated ответы обоих.
История seed до измерения; compact observer каждые 5000 мс; CPU sampling,
work trace и timeline выключены. Общее test-only instrumentation счётчика
одинаково во всех фазах; один production variant — `group_service.dart`.

Allocator не менялся; разница одного allocator commit в census не атрибутирована
и не засчитывается как устранённый I/O или причина различия времени.

По 782 page queries на источник, **0 повторов**, одинаковые **54217516
application-frame bytes** каждого источника. Это не весь сетевой трафик.
Query→reply P50 около 70–74 мс; reply→next-query P50 около 142–145 мс —
материального изменения этих стадий нет. Дальнейший приоритет — оставшиеся
чтения/применение/сохранение на получателе и очереди, с прямыми измерениями.
Свежий membership cache ради сокращения чтений не добавлялся.

Все **100000 архивных + 1 прежняя строка** совпали по ID, содержимому,
delivered, canonical positions и порядку, без потерь/дублей/лишних строк;
оба cursor завершены. Холодное открытие получателя до сети, при offline всех
источников, сохранило весь набор. Wire/census без обрезания. Исходный append
order у обоих источников во всех фазах одинаков: новая строка перед архивом,
две sorted runs 1 + 100000. Fixture не менялась ради быстрого пути.

## Происхождение и уборка

Заморожены **1532 inputs**: один production variant, 1531 общий input.
Проверены SHA native-библиотек, ABI и реальные worker mappings; новый Rust build
не требовался. Candidate восстановлен, все его frozen inputs сверены.

Проверены соответственно **37/44/39 PIDs** и **59/62/56 портов** — живых
owned процессов/слушателей нет, runtime удалён. Cache **92→92** во всех фазах,
новых kernel entries 0, около 9,5 ГиБ; свободно около 149 ГиБ. Сырые журналы
остаются приватными; публичная сводка не содержит адресов, ID и VM capabilities.

Latency остаётся активной: на этом стенде всё ещё около 200 с на 100000.
Физическая/AOT квалификация, NETCALL-01 и остальная multi-device matrix этим
циклом не закрыты. Push/релиза нет.
