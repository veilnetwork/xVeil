# Фоновые self-ad lookup без onion first hop

Подтверждён и исправлен источник лишнего расхода DHT: приёмный stream-worker
искал собственные rendezvous-объявления, когда все подключённые соседи явно
не поддерживали onion transit. Поиск читал восемь слотов у независимых реплик,
затем выяснял, что circuit построить не через кого. Повторные попытки тратили
тот же бюджет запросов, который нужен разрешению ключей сообщений.

## Исправление и тест

В `PublishedRendezvous` перед lookup снимается snapshot peer ID из TX registry
и применяется существующий фильтр `ANONYMITY_RELAY`. Пустой набор возможных
первых хопов сразу даёт `NoRelays`. Блокировка registry отпущена до чтения
capabilities. Неизвестная capability допускает обычное обнаружение. Новая
capability/регистрация читается на следующей попытке; отрицательного кэша нет.
Режим validation min-routing не менялся.

Это способность переносить circuit, а не согласие участвовать в DHT. Приоритеты
реле, wire, таймауты, freshest-of-replicas, подписи и durable host authorization
не менялись. При возможном carrier поиск собственных ads сохранён.

Новый тест использует настоящие NodeRuntime/NodeServices, SessionTxRegistry,
FrameOutbox и `open_inbound_circuits` в отдельном child-процессе. При явно
выключенной relay-capability прежний код оставлял future pending и ставил
**8 запросов собственных слотов**. Исправление немедленно возвращает `NoRelays`
без запросов. В том же runtime capability меняется на relay, затем становится
неизвестной: обе ветки снова начинают поиск с настоящими query frames. Отмена
чистит pending-ID. Нет порогов wall-clock времени; runtime закрыт до проверки
ожидаемого красного результата.

Первый запуск попал в модуль за `test-low-difficulty` и выполнил ноль тестов —
он не засчитан. Самостоятельный модуль работает с production-фичами без low-PoW:
до исправления один тест выполнен и упал. После — **39 FFI stream-тестов passed,
0 ignored, 297 filtered out**. Отфильтрованные не считаются пройденными.
Test-only sentinel child-процесса отсутствует в release-библиотеке.

## Чередование на 12 узлах

Контроль уже содержит [публикацию в новую DHT](../reload-live-dht-2026-10-31/README.md).
Fixture и tracing одинаковы, каждый прогон — свежие контейнеры/instance ID.
Self-ad ключи классифицированы точной domain-separated функцией. Таблица считает
исходные query frames, принятые локальной очередью, не wire-пакеты с пересылками.

| Исправление B1 | 0 | 5346 | 3626 / 3213 / 3264 |
| Контроль A2 | 1784 | 8126 | 2529 / 2101 / 3684 |

| Контроль A3 | 1776 | 8299 | 2711 / 1638 / 3010 |
| Исправление B3 | 0 | 5297 | 2308 / 2155 / 2705 |

Контроль делал 224 slot lookup за фазу; исправление — ноль. Все candidate query
frames: 4304 / 4264 / 4256 в A, 2392 / 2408 / 2392 в B. Повторы ключевых
запросов при прежней политике: 204 / 187 / 164 против 82 / 83 / 84. Это не
подсчёт отказов лимитера: причины всех молчащих веток не установлены.

Медиана первого сообщения **8126 → 5297 мс**; каждый B быстрее каждого A.
Выборка мала и локальна. Следующие сообщения меняют отправителя и не являются
строгим тестом прогретого sender/recipient. Во всех шести фазах 4/4 сообщения
пришли на все 12 узлов ровно один раз.

Условия: один Mac/JIT-процесс с настоящими native nodes, TCP-loopback/full mesh,
12 одинаковых production-PoW личностей, DHT включена у всех. Настоящие
GroupService/MessagingService, подписи, ratchet и peer authorization persistence.
Группа legacy без epoch encryption, roster provisioned без парного handshake.
Все узлы leaf, onion-реле нет. Это ограничение замеров, а не модель обычного
production-маршрута: DHT-участие само по себе не делает leaf onion-реле.

## Положительная проверка

Отдельный native-прогон финальной библиотеки: **3 Core onion-реле и 9 leaf**
на loopback. Core стартуют с полными private fixture-конфигурациями, leaf —
через deferred boot. Роли/capabilities переданы настоящим handshake; ручной
установки confirmed-флагов или понижения PoW нет.

У всех девяти leaf наблюдается `PINNED CIRCUIT opened (PublishedRendezvous)`:
production-код подтвердил входящие регистрации после появления пригодных
первых хопов. Всего открытие сообщили 12 разных узлов. Четыре групповых
сообщения также сошлись без дублей: 5523 / 4034 / 3329 / 2841 мс. Эти времена
не смешиваются с A/B из-за других ролей. Это проверка доступности circuit,
не файловой скорости, речи или всей multi-device матрицы.

Во всех семи фазах 12 узлов остановлены, 12 слушателей освобождены, выход host
проверен. Библиотеки проверены по SHA после codesign и снимку исходников перед
сборкой. Watchdog внешнего target mount не терял. Телефоны и production-реле
не менялись. Сырые node ID, сертификаты и журналы приватны; здесь только
агрегаты: [summary.json](summary.json). Без push и релиза.

**Остаток:** холодная доставка 4,5–5,3 с требует дальнейшей работы. Размещение
реплик после появления сессий, последовательные metadata-окна и остальные
молчащие ветки ещё не объявлены устранёнными. Затем — multi-device матрица
по очереди пользователя. Совместимость со старыми версиями отложена.
