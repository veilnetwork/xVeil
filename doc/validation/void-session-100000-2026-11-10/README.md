# Void-запись остаётся в своей личности и не дублируется

## Подтверждение

`applyRemoteVoid` записывает занятый слот авторской последовательности:
маркер без текста/ID сообщения, нужный gap-fill после удаления события.
Он влияет на синхронизацию, хотя не отображается как сообщение. Метод
вызывается authenticated inbound `voidSeq` и обработкой истёкших событий.

Проверка занятости слота читала журнал до записи. Вся операция не входила
в принятую очередь stream, которую `open`/`close`/`eraseSpace` присоединяют.
После приостановленного чтения другой backing space мог быть уже открыт,
и commit брал новый `_as`. Unit parent-red обнаружил seq 2 первой личности
в журнале второй. Это нарушение изоляции метаданных в storage API; копирование
текста или потеря пользовательских сообщений этим случаем не доказаны.

Второй parent-red: два одновременных повтора прочитали один незанятый слот
и оба записали void. `loadEventsSince` вернул **[2, 2]** вместо **[2]**.
Это дубли служебных событий, не два видимых сообщения. Воспроизведения
используют gate и виртуальные microtasks, не временные пороги.

## Исправление

Подготовительное чтение, проверка idempotency, commit и patch fold выполняются
в одном существующем `_withConvSequence(conversationId, author)` turn.
Он привязывает операцию к исходному storage session и учитывается maintenance
до замены backing. Повтор того же stream видит уже записанный слот. Разные
авторы остаются независимыми; глобальный scan gate на всё чтение не захвачен,
поскольку `_patchCache` присоединяет его отдельно.

Новые вызовы после fence отклоняются. Ошибка записи возвращается вызывающему,
освобождает turn и не мешает закрытию. Автор/seq по-прежнему приходят из
прежнего authenticated dispatch; ACL, durable receipt, wire/storage format,
mailbox и криптографические ключи не меняются. ACK остаётся после await
storage operation, раннее подтверждение не добавлено.

## Проверки

Шесть новых unit checks: изоляция при open, конкурентная идемпотентность,
прогресс другого автора при удержанном первом, close/erase с отказом поздних
вызовов и освобождение close после отказа commit без записи void. Прежние
10 erasure lifecycle checks также проходят. **700 related checks passed /
1 skipped** в 41 файле, включая mutation ACK-after-commit, inbound expiry,
native expiry и полное hidden-volume storage поведение. Пропущен явно
включаемый roster lifecycle probe, он не засчитан пройденным. Analyzer
production-файла и обоих изменённых тестов чист. Native smoke на 512 строк
прошёл для delete/clear/prune/void с cold reopen второй личности.

Native negative control на 100000: два отдельных настоящих worker-backed
контейнера, один экземпляр HiddenVolumeStorage, завершённое старое чтение
удерживается gate. Старому коду разрешено завершить открытие второго до release;
в нём после cold reopen остаётся **одна foreign void-запись**. Все 100000
канареечных ID/body/conversation/status/author/seq/canonical/timestamp-ms
значений при этом целы. Контроль ловит именно метаданные, а не совпадение
числа видимых сообщений.

Candidate не закрывает старый backing до release и успешно завершает принятую
операцию в первой личности. После cold reopen во второй ровно **100000/100000**
точных уникальных канареек и **0 foreign events**. Повторное открытие первой
проверяет единственный void seq 2 без body и сохранность исходного поста.
Negative control намеренно задаёт опасный порядок; фикс не может завершить
такое открытие до release. Это не performance A/B.

1514 nonvariant lib/test/config inputs зафиксированы; native SHA и mapping
проверены. Production candidate восстановлен и проверен после контроля;
по три собственных процесса каждого full прогона завершились, оба runtime
каталога удалены. Четыре smoke runtime тоже удалены. Сырые журналы, пути
и process evidence не входят в Git.

## Границы

Это квалификация storage API на Mac/JIT и связанного ACK/expiry поведения,
не доказательство эксплуатации на пользовательских данных и не полный
Android/AOT multi-device стенд. Все fsync/crash/partition/revoke окна не покрыты.
Кеш сохранил 92 файла / около 9,5 ГиБ, новых kernel entries нет.
Latency, длительный anti-entropy обход, NETCALL и остальная matrix остаются
в работе. Push/релиза нет.
