# FFI-пул маршрутов: свидетель TX-регистрации и Blackview reconnect

SDK `9421b3e8` исправляет подтверждённый пропуск предыдущей правки `4de50051`.
Native DataCircuit уже проверял конкретную живую TX-регистрацию, однако семь
проверок FFI-пула ещё использовали общий close-counter session runner.
Файловая пауза после reconnect **остаётся** на новой сборке.

## Механизм и исправление

После замены TX-entry старый runner мог ещё не выйти: counter не изменился,
FFI выбирал старый circuit, но native уже правильно отвергал его. Обратный
порядок — поздний выход старого runner — делал diagnostic counter несовместимым
со свежим circuit. Это два разных порядка одной гонки.

Выбор, reuse, remap, eviction и cooldown-recovery теперь используют
`data_circuit_session_current`. Старый счётчик остаётся только диагностическим
свидетелем. Если регистрация сменилась между выбором и enqueue, send-failure
удаляет устаревший handle без карантина нового соединения/реле. Свежий handle
того же rendezvous не удаляется за отказ прежнего. Привязка активного stream к
получателю, ACL, ratchet, wire и приоритеты реле не менялись.

Регрессионный тест на настоящем SessionTxRegistry заменяет живую регистрацию
без изменения close-counter. На `4de50051` он упал на ошибочном FFI-признании
старого маршрута пригодным (0 passed / 1 failed). Вторая ветка проверяет, что
одна лишь диагностическая разница не отвергает актуальный circuit. Дополнены
проверки сохранения свежего пути, настоящих cooldown и непринятых striped cells.
Тесты не снимают receiver-binding guards и не объявляют enqueue доставкой.

Прошёл полный набор: 391 FFI-тест, 11 ignored отдельно; дочерняя изолированная
проверка также прошла. Clippy `--all-targets -D warnings` чистый. Unit-фикстуры
используют `test-low-difficulty`; физические библиотеки ниже — без этой feature.
Rustfmt с edition 2024 и `git diff --check` чистые.

## Физическая серия на возвращённом Blackview

В обоих направлениях использованы существующие отдельные QA-личности. P2P для
контакта запрещён; bulk использует circuit backend. Это не обещание отсутствия
прямых mesh-транспортов. Начальные Wi-Fi/data включены; default route/провайдер
не зафиксирован. На трети проверенного файла обе radio отключались, затем
возвращались в прежнее состояние. Выключение радиосвязи — часть приведённых времён.

Frontend намеренно заморожен: xVeil `48a2d436`, Dart plugin SDK `ea7e8388`.
Менялись только native-библиотеки с production-фичами
`node-embedded,production-seeds,packet-tunnel`, без circuit-trace/test hooks.
Это native-квалификация, а не прогон всего последнего дерева, не свежей личности
и не матрицы смешанных релизов. Реле в этом цикле не обновлялись.

Сначала оба конца получили предыдущий native SDK `4de50051`:

| Направление | Размер | Обрыв | Загрузка | Первая проверенная часть | Максимальный интервал проверенных частей | SHA-256 |
|---|---:|---|---:|---:|---:|---|
| Mac → Android | 3 МиБ + 251 Б | Нет | 5,636 с | 2,359 с | 1,096 с | Совпал |
| Android → Mac | 3 МиБ + 251 Б | Нет | 25,895 с | 2,031 с | 4,564 с | Совпал |
| Mac → Android | 32 МиБ + 251 Б | 9,058 с | 127,093 с | 2,319 с | 22,638 с | Совпал |
| Android → Mac | 32 МиБ + 251 Б | 8,280 с | 135,154 с | 6,577 с | 16,405 с | Совпал |

На Mac receive-prefix файла стоял 14,016 с при OO за дырой до 3964 Б.
По локальным часам Mac: интервал 39,693–53,709 с от начала загрузки; команда
возврата radio завершилась на 46,929 с. Команда не доказывает фактическое
восстановление сессий. На Android зафиксирован один `payload idle after`.

После фикса FFI оба конца получили SDK `9421b3e8`:

| Направление | Размер | Обрыв | Загрузка | Первая проверенная часть | Максимальный интервал проверенных частей | SHA-256 |
|---|---:|---|---:|---:|---:|---|
| Mac → Android | 32 МиБ + 251 Б | 9,021 с | 84,473 с | 3,469 с | 17,940 с | Совпал |
| Android → Mac | 32 МиБ + 251 Б | 8,275 с | 70,753 с | 5,074 с | 19,410 с | Совпал |

Обе загрузки продолжились автоматически. Но на Mac receive-prefix **файлового
payload** стоял 15,653 с при OO за пропуском. Отдельный 16,337-с стоячий prefix
на Android относится к обратному, малому потоку запроса (его receive delta около
4 КиБ), поэтому он не выдаётся за паузу приёма самого файла на Android.
На Android нет `payload idle after`, но загрузка Mac → Android всё равно
использовала два последовательных stream. Максимальный consecutive RTO у старого
отправляющего Mac stream — 5, RTO до 10 с. Причина именно его завершения этим
счётчиком не устанавливается. Локальный blocked-cell age на Android до 29,105 с
включает время отключённой сети и не равен времени одной enqueue-операции.

В новой серии зарегистрированы три удаления устаревшего handle на Android,
ни одного quarantine `after send failure: NoRelays` на обоих концах. Последнего
события не было и в предыдущей серии: нельзя утверждать, что найденная тестом
гонка вызвала эти физические паузы. Ускорение между таблицами не приписывается
правке: нет A/B/A и фиксированного маршрута. Интервалы проверенных 256-КиБ частей
не означают сетевую тишину; byte-level prefix приведён отдельно.

## Что остаётся

Прежнее «само зависло на 33%» не атрибутировано. Здесь обрыв был намеренным,
все шесть файлов целы, четыре передачи после обрыва восстановились сами.
Подтверждённый остаток — восстановление старого stream/недостающего диапазона,
RTO и большой локальный blocked-cell age после reconnect. Удаление
устаревшего circuit не доказывает наличие пригодной замены для уже привязанного
stream. Следующий замер должен разделить ожидание совместимого пути и отказ
native enqueue, не ослабляя receiver binding и не подменяя это сокращением
таймаута. Звонок около 25 с, mixed-версии и multi-device матрица не проверялись.

## Происхождение и возврат стенда

Сборки выполнены из чистых зафиксированных SDK heads. Mount внешней ФС проверялся
до и во время Rust builds. Проверены SHA упакованных библиотек и APK; на Mac
проверен mapped path и SHA **после codesign**. Остальные APK entries побайтно
равны frozen frontend, кроме подписей. Исходный реально установленный QA APK
сохранён до каждой замены и восстановлен со сверкой хеша.

Первая попытка запуска до первой серии остановилась на занятом порте ещё до
старта приложений/файлов. После проверки выбрана свободная пара вне ephemeral
диапазона; чужие процессы не завершались. Эта попытка не считается прогоном.

Приложения, logcat и API ports закрыты; настройки контакта/анонимности, preferences,
radio, debug property, whitelist и metadata launcher возвращены. Основной xVeil
не менялся. Активный QA-контейнер штатно продвинул ratchet; он **не откатывался**.
Synthetic files удалены только после успешной SHA-проверки. Сырые журналы,
адреса, IDs, пути пользователя и ключи в отчёт не включены.

SDK-коммит локальный, без подписи, push или релиза. Сопутствующий Android-репорт
разобран [отдельно](../android-long-runtime-2026-10-30/README.md).
