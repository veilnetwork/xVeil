# Холодная доставка по шестисерверной линии

2026-11-01. **Два механизма исправлены, звонки через relay и P2P прошли.
Большая задержка холодной доставки остаётся; NETLINE-01 целиком не закрыт.**

Продолжение [первого физического стенда](../linear-testnet-2026-11-01/README.md).
Те же изолированные профили и линия
`Mac — S1 — S2 — S3 — S4 — S5 — S6 — Blackview`, телефон на Wi-Fi.
Production-службы, настройки основной xVeil и её контейнеры не менялись.

## Подтверждённые механизмы и изменения

| Механизм | Проверка до изменения | Изменение |
|---|---|---|
| Ответ discovery не возвращается по холодной цепочке: промежуточный узел не сохраняет вход запроса, а обратного маршрута ещё нет | Два packet-driven теста настоящих dispatcher с шестью core: нет маршрута без PoW; с PoW challenge не достигает requester | Ограниченные обратные пути запроса и nonce-bound пути challenge/solution/accept; проверенный ответ учит транзитный маршрут |
| Requester не знает ключ далёкого issuer и не может проверить PoW challenge | Отдельная модель unknown-key | Подписанный контекст challenge с request ID; незнакомый ключ проверяется по хешу transport node ID, известный — прежним verifier; локальный запрос обязателен перед solver |
| Обычная family-копия выбирает проверенное устройство, но адресует конверт sovereign identity; холодный core не имеет такой session alias | Реальный IPC → relay → ratchet endpoint: очередь следующего устройства пуста | Конверт адресуется выбранному проверенному transport device с прежним точным instance tag; ratchet по-прежнему связывает личность и instance |

Reputation 200, PoW, contacts/introduction-only gates, durable authorization,
ratchet и проверка отзыва не отключались. Не создавались доверенные alias
identity → device на основании одного входящего пакета.

Возвратные пути ограничены: 60 секунд от исходного запроса, 1024 запроса
с общим/локальным/peer cap, 256 challenge; повторы не продлевают lease и не
меняют первый ingress. Валидация транзитной подписи не записывает ratchet keys
или authorization. Новая транзитная запись маршрута создаётся только по
проверенному RouteResponse для сохранённого запроса. Невалидный ответ не
уничтожает путь для настоящего.

Контекст `RDP1` — расширение wire challenge с domain-separated подписью.
Подмена/удаление контекста не проходит проверку, включая уже известный ключ.
C ABI не менялся. Старые/новые версии не квалифицированы; совместимость ранее
исключена владельцем из текущих условий. Все шесть тестовых core и оба клиента
получили discovery-правку перед физическим повтором.

## Физическая последовательность

1. Только discovery-правка (`7af77372`): 33 opaque payload digest сопоставлены
   на телефоне, всех шести core и на Mac. Подтверждение контакта ещё не сошлось,
   relay-звонок не дал входящего за окно 90 секунд. Digest сам по себе не
   определяет CallOffer. На Mac отдельно зарегистрирован отказ claimed offer;
   этот отказ авторизации не обходился.
2. После family-адресации (`2152c9f9`) повторный реальный `acceptContact` дошёл
   до Mac за 24,351 секунды: оба устройства показывали accepted. Ручного
   изменения статуса в БД не было.
3. Прогнаны следующие звонки, с ответом обычным API приложения:

| Режим | Входящий от начала скрипта | Наблюдение после 5 свежих samples | Максимальный RX age Mac / Android |
|---|---:|---:|---:|
| P2P denied | 1,378 с | ещё 20,8 с, relay на обоих концах | 350 / 56 мс |
| allowAll после полного перезапуска | 4,447 с | ещё 20,5 с, p2p на обоих концах | 292 / 38 мс |
| denied после следующего полного перезапуска | **50,999 с** | ещё 20,5 с, relay на обоих концах | 347 / 33 мс |

Все post-qualification samples были active с RX age ≤1000 мс. Количество
samples и границы сохранены в [машинной сводке](result.json). Это пакеты,
а не проверка разборчивости живой речи или громкости на Windows.

Для allowAll реальные UDP listeners проверены на wildcard: fd процесса Mac
и same-UID admin Listens телефона. Native peer IPC подтвердил на обоих концах
**ровно назначенный seed и точное встречное устройство**, без чужих соседей.
Для повторного denied реальные listeners обоих клиентов были loopback-only,
native peer IPC — только S1/S6.

Core graph oracle прошёл: все 10 направленных связей, обе клиентские привязки,
никаких лишних core-соседей, ожидаемые SHA конфигов/бинарников и исходный
production PID/бинарник/конфиг на шести серверах. Полные core-срезы сняты
внутри активных allowAll и повторного denied. Endpoint peer snapshots взяты
отдельно; они не выдаются за синхронный сетевой захват. Ограничения listeners
и per-service IP ACL прежние. Relay-медиа подтверждено состояниями приложения
и RX в принудительной линии; отдельной per-cell криптографической трассы
каждого media-пакета на всех шести серверах в этой серии нет.

Два тестовых сообщения отправлены в противоположных направлениях при denied,
одновременно с повторным звонком. В итоге оба видны у получателя по одному
разу с тем же message ID. Но Mac → Android не появился в первоначальном окне
45 опросов; Android → Mac наблюдался через 34,423 секунды. Поздний срез
подтвердил обе копии. Это **подтверждение большой задержки**, а не успешный
latency-гейт. Причина 51-секундного setup и всей задержки сообщений ещё не
атрибутирована: следующий участок — очередь route miss/resolve и admission
после перезапуска, с сопоставлением стадий реальной отправки.

## Проверки, происхождение и уборка

- Discovery: 299 dispatcher + 842 proto + 117 routing passed. Модель шести
  core охватывает no-PoW, известный и неизвестный issuer key; после ответа
  opaque Forward проходит семь связей без RecursiveRelay и synthetic credits.
  Это проверка маршрута, не модель полной E2E-переписки.
- Runtime: 785 passed, 11 ignored; FFI: 334 passed, 2 ignored.
- Family regression: **1 failed (Empty) до изменения → passed после**;
  весь IPC: 200 passed, 5 ignored. App delivery проверяется как Signed;
  другое устройство/instance не получает копию. Первый тестовый compile
  failure и запуски с нулём тестов не считаются красным воспроизведением.
- Linux, macOS, Android собраны с прежними testnet production features,
  выделенными внешними Cargo targets и watchdog mount. SHA источников,
  включая новые файлы, и артефактов сохранены приватно. Mac SHA фиксировался
  после codesign; Android установленный native и APK сверены с кандидатом.
- Frontend/AOT, медиадвижок и hidden-volume заморожены; при repack сохранены
  несигнатурные META-INF и остальные байты APK. Инкрементальная Android
  установка не извлекла QA wrap.sh: тот onboarding/prod запуск не засчитан.
  Повтор `--no-incremental` дал настоящий testnet и прежний профиль.
- Собственные QA-профили сохранены приватно; временный пакет, отсутствовавший
  до стенда, удалён после сверки SHA и backup. Mac/Android/logcat завершены,
  свой ADB forward снят. Шесть тестовых служб остановлены, порты освобождены;
  production PID/бинарник/конфиг сохранены 6/6. Автозапуска testnet нет.
- Коммиты unsigned; push, релиза и обновления production-бинарников нет.

NETCALL-01 (мобильный handover), пользовательская слышимость Windows ↔ телефон
этой Wi-Fi-серией не закрываются. Ошибка быстрого входа по отпечатку на другом
Poco остаётся жалобой: по указанию владельца отложена в пользу доставки.
