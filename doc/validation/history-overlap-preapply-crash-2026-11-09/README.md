# Падение получателя до применения двух ответов истории

Агрегаты: [summary.json](summary.json). Это проверка после публикации
xVeil 0.13.95; production-код в этом цикле не менялся, новых push/релизов нет.

## Проверяемый промежуток

Ранее отдельно проверялись частичная догрузка с SIGKILL и два одновременных
источника с последующим штатным restart. Здесь проверено их другое сочетание:
два полных authenticated ответа уже находятся у получателя, но применение
первой архивной строки ещё удерживается test-only барьером.

Четыре независимых Mac/JIT процесса: A/B/E одной личности, C другой.
A/E имеют одинаковый синтетический архив из 512 строк с canonical positions
и delivered; этих строк нет в device journal. У B есть одна прежняя строка.
Контакт и linking проходят штатные церемонии; C далее offline. Три Core
образуют изолированный локальный остров, runtime discovery выключено.

| Этап | Online/offline и действие | Фактический результат |
|---|---|---|
| До аварии | A/E/B online, C offline; два ответа полностью приняты, первый apply удерживается | Два authenticated источника, 0 архивных строк на B |
| Авария | B завершён SIGKILL, затем A/E остановлены | Exit −9; барьер не освобождался |
| Первый restart | Источники A/E/C offline; инспектор читает контейнер B до создания сети | Прежняя строка сохранена по точному ID, телу, delivered и canonical position; архивных строк 0 |
| Восстановление | Возвращается только A; E/C остаются offline | Все 512 архивных + 1 прежняя строка сошлись; активный source cursor завершился |
| Проверка диска | A снова offline; B штатно перезапущен при offline A/E/C | До сети сохранены все 513 ID, тел, delivered и canonical positions; обычное чтение подтверждает порядок |

Ожидается повторная догрузка неприменённых ответов от доступного источника,
без потери прежней истории и без дублей. Все проверки прошли: отсутствующих,
посторонних и повторных ID нет, тела/статусы/позиции/порядок совпали.
Равенство пустых снимков не принимается: source oracle содержит 512 известных
архивных строк, а первоначальный retention oracle — непустую прежнюю историю.

Witness служит только для сравнения. Inspector не добавляет записи из него
и открывает контейнер до запуска node/transport/providers. ID, тела и content
witnesses остаются в private fixture/evidence; публичные агрегаты их не содержат.

## Происхождение и проверки

Production Dart совпадает с тегом v0.13.95. CLI/FFI собраны согласованной парой
из SDK v0.11.48 с `allow-empty-seeds`; ABI-контракт сверён с текущими bindings.
Использована подписанная опубликованная HVS 2.7.0. Выбранные SHA проверены
до/после, реальные OS mappings подтвердили загрузку FFI/HVS у живых workers.

**42 helper/oracle tests и один native process-сценарий прошли без пропусков.**
Целевой analyzer/format/diff checks чисты. За время native-прогона неизменны
1471 frontend/test/dependency input и выбранные native-библиотеки.

Весь сценарий занял 181,722 с, включая linking, подготовку архива, барьеры,
kill, перезапуски и cleanup. От начала `start(A)` до сходимости — 13,376 с.
Это не A/B и не измерение чистой скорости истории; ускорение не заявляется.

## Границы и очистка

Проверен один crash-момент. Это не Android/AOT/Windows, WAN, аппаратная потеря
питания, часы/сутки offline или полная revoke/split-brain/crash матрица.
Сценарий не обещает новую доставку при одновременно offline всех источниках
и не включает sibling mailbox. Долгая догрузка и NETCALL-01 остаются открытыми.

Cleanup exit 0: проверены 45 owned PID и 65 портов, живых своих процессов
и listeners нет. Одноразовые контейнеры, runtime и witnesses удалены.
Телефон, реальные профили и production-сиды этим тестом не изменялись.
