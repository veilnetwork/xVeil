## Проверки

- **112 Flutter tests passed**: экспорт документа/вложений, экран архива,
  приглашения/чат, permission tile, notification session/actions и microphone
  foreground, локальное имя/аватар и анонимная диагностика. Это общий итог уникального финального запуска, не сумма повторов.
- Export проверяет точные байты для multi-chunk файла, отмену без чтения,
  permission failure на open/write/finish, short read, смену identity при picker
  и чтении. Системные сообщения/URI/пути не удерживаются в исключении.
  Начальная запись plaintext destination также показывает отказ, а не теряет
  исключение. Длина выгрузки берётся из хранилища, не из размера в offer.
- Android Kotlin и merged main manifest собираются; analyzer без замечаний.
- Native UI-стенд использует те же CallScreenActivity, VeilDaemonService и
  CallActionCapability, но отдельный package, тестовый Host и фиктивный звонок.
  Контроль A₁: full-screen intent в уведомлении есть, Activity не открылась.
  B: окно поверх keyguard, ответ принят по capability, keyguard остаётся
  showing/occluded, показан только экран разговора; отбой убрал Activity и
  активное уведомление. A₂ при возврате только прежнего notification-path снова
  не открыл окно при активном incoming notification и keyguard showing.
  Счётчик общей истории уведомлений не принимается за активное уведомление.
  Основные xVeil/контейнеры телефона не устанавливались и не изменялись.
  После добавления opt-in Host повтор B₂ на финальных исходниках также прошёл
  показ, ответ и отбой. [Воспроизводимый probe](../../../test/native/android_call_screen_probe/README.md)
  хранится отдельно от production-кода. На финальном оформлении дополнительно
  прошли варианты с аватаром/без него, имя и статус, скруглённые кнопки,
  приём caller-data до доставки Service и отказ запоздалому update после отбоя.
  Имя/аватар берутся из захваченного identity storage, без сетевого поиска;
  перед публикацией повторно проверяется текущий вызов/identity. Native хранит
  только один scoped caller в RAM, ограничивает имя и размеры картинки;
  caller-data не добавляются в PendingIntent, логи или preferences.
  Для групп показывается локальная презентация инициатора. Отдельно проверен
  финальный circular bitmap drawable для одинакового отображения в GPU и
  software-render; тестовое приложение удалено после повторного ответа/отбоя. Промежуточная
  ошибка типа LayoutParams и слишком ранний observer до семисекундного
  тестового таймера исправлены до финальной квалификации, не product red.
- Это **не полный медиазвонок xVeil**: Dart-действия и MainActivity-host проверены
  тестами/компиляцией, но на физическом устройстве вызывался тестовый Host.
  Новые mic/camera permissions по-прежнему могут потребовать открытия приложения.
- Preview вкладок просмотрен при ширине 390; отдельная визуальная fixture не
  включается в число 112. Копирование/парсинг контактов и импорт peers сохранены.

## Попутный дефект WSS

Проверка команд инструкции на существующем CLI действительно отклонила
`wss://…:443/veil` как missing port. Библиотека URL нормализует стандартный
порт в None; TransportUri принимал только явный url.port(). Теперь используется
port_or_known_default(): WS/WSS получают 80/443, прочие транспорты без порта
по-прежнему отклоняются. IPv6 и round-trip включены в регрессию.
Red: 0/1; green: **157 transport tests passed**, без ignored, fmt чистый.
Внешняя ФС проверялась до сборки и watchdog'ом во время неё.

Инструкция использует 9443, чтобы работать и до выпуска этой правки. На прежнем
CLI прошли config set, WS bind/WSS advertise, validate и invite/decode round-trip.
Обнаруженная в прежнем руководстве неверная позиционная форма bootstrap
join/decode заменена на --uri. `nginx -t` на Debian в этом раунде не запускался;
это явно не объявляется production-развёртыванием.

Источники платформенных контрактов: [Android SAF](https://developer.android.com/training/data-storage/shared/documents-files),
[Android 14 FSI](https://developer.android.com/about/versions/14/behavior-changes-14),
[nginx WebSocket](https://nginx.org/en/docs/http/websocket.html).

## Что этим не закрыто

Новые аудиожалобы активны: эхо при громкой связи Windows, фоновый шум и пропуски
речи в паре Poco/mobile ↔ Windows/Wi-Fi. Маршрут звука самого Poco неизвестен.
В текущем helper CallAudioProcessingConfig явно включён AGC2; AEC/NS там не
включены. Это направление проверки, а не доказательство причины слышимого эха
или корректного render-reference. Обработка звука, packetization и jitter
этим раундом не менялись; переключатель NS и физическая звуковая квалификация
ещё не сделаны. Прежние network-handover, холодный UDP и остаток миграции/матрицы
также не объявляются исправленными этим UI-раундом.
