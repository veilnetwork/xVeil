# Позиция сообщения при компакции и переносе истории — 24 октября 2026

Продолжение MD24-01 после `ece69fdd`. Исправлен отдельный путь потери уже
восстановленной позиции: временный own-message echo мог вытеснить её в
свёрнутом device journal. Два прежних успешных partition-прогона не проверяли
удаление проигравшего mirror и привязку следующего устройства после этого.

## Подтверждение

До изменения тест с реальными `deviceMirrorOf` и `foldDeviceSync` выбирал
временную позицию вместо исправленной. Разные порядки входных событий давали
того же неправильного победителя: поля au/sq участвовали в JSON tie break,
но происхождение номера в модели не было представлено.

Контрольный возврат старого comparator также уронил regression с настоящей
`GroupService.compactStateLogs`: исходная позиция удалялась, новый экземпляр
сервиса читал временную. Тест гарантирует, что ни одна из двух копий не осталась
случайно сохранённой как обязательный writer head: после них пишется новая
строка, а после компакции остаётся ровно один mirror этого сообщения.

## Исправление и модель доверия

* `Message.positionVerified` сохраняет происхождение позиции: true — исходная
  позиция, false — временная нумерация recovery-копии, null — старая запись без
  сведений о происхождении. Это **не** признак подписи текущего текста.
* Собственная обычная отправка фиксирует исходную позицию; собственное сообщение,
  возвращённое контактом, явно остаётся временной копией. Признак сохраняется
  в контейнере и переносится одним builder через device history и архив.
* Восстановленная через подписанный device journal пара `Message.ordering`
  имеет проверенное происхождение. Старый raw author, даже совпадающий с
  физическим self, сам по себе не повышает unknown provenance: такой ряд мог
  попасть сюда через прежний backfill. Ни identity, ни device ID не заменяют
  отсутствующие сведения о происхождении.
* Для исходящих msgMirror сравнивается сначала происхождение: verified выше
  legacy/unknown, а legacy выше explicitly provisional. Внутри класса сохранены
  прежние timestamp и JSON tie break. Это один total-order comparator для fold,
  live gate и компактора. Даже конфликтующие peer/direction в одном ключе не
  создают зависимость от порядка обхода.
* Новый verified marker без корректных author/seq отклоняется до локального
  выделения номера; такой payload не может вытеснить пригодную legacy-копию
  при компакции. Старые записи без нового признака продолжают читаться.
* Предварительная копия не может использовать свои номера для repair уже
  имеющейся записи. Сохраняется предыдущая проверка принадлежности исходного
  author своему физическому устройству и запрет воскрешения удалённых сообщений.

Признак идёт внутри уже аутентифицированного device journal; внешний контакт
не получает возможности назначать его через обычное сообщение или own echo.
RTCP, media policy, relay priority и mailbox policy этим изменением не затронуты.

## Native: новый получатель после компакции

Четыре независимых application/native процесса: A/B/E — после привязки одна
личность, C — другая. Три отдельные локальные relay, настоящее контейнерное
хранилище и production providers. Созданы две обычные исходящие записи.
Через существующий debug API авторизованное своё устройство публикует две
контрольные конкурирующие копии: старого формата и explicitly provisional.
Их event timestamps новее исходных, а номера заведомо временные.

После действительной компакции B и C выключаются. E привязывается к A и
получает историю **только от доступного A**, затем перезапускается. Проверяются
ID, направление, текст, timestamp, seq и порядок обеих записей, а также точные
выбранные позиции и времена в device journal. Новых production test hooks нет;
контрольные данные и публикация fixture находятся в test/e2e.

После удаления legacy-author inference оба native-теста окончательного
исходника прошли. E получил исходные позиции при выключенных B/C и сохранил
их после перезапуска. В live partition первая сходимость наступила через
**20 142 ms**, стабильное состояние удерживалось ещё **10 377 ms**, весь recovery
занял **30 520 ms**. Сохранены прежние 16 сообщений, edit/delete/reactions/read,
convergence timeout 4 min и окно стабильности 10 s. Хеши исходников совпали до
и после финальных прогонов; агрегаты — в `summary.json`.

Это дополнительное ограниченное покрытие пунктов 5/21/47; оно не подтверждает
все типы истории, медиа и звонки с тремя устройствами одной личности. Полная
матрица 63 пунктов не объявляется зелёной.

## Совместимость, окружение и данные

Новый признак аддитивен; старая запись без него имеет unknown provenance.
Смешанные версии не квалифицированы: старый компактор не знает нового
приоритета. Уже утраченная исходная позиция не восстанавливается из воздуха;
для её повторной публикации нужен держатель исходной записи или ранее
подтверждённой позиции.

SDK `de769239`, HV `c4ba1fa8` не менялись. Использована ранее совместно собранная
CLI/FFI-пара, сверенная по SHA-256; compiled public seeds отключены, test-low-
difficulty ограничен закрытым loopback-островом. Это не релизные артефакты.
Телефон, пользовательские личности, установленное приложение и публичные реле
не менялись.

В git только агрегаты и хеши исходников/артефактов; сырые логи, dummy IDs,
API snapshots и ключевые контейнерные данные остаются в приватном локальном
cache. Завершение owned процессов и удаление их временных контейнеров
проверяются отдельно в `cleanup-proof.json`. Чужие каталоги и untracked-отчёт
17 октября сохранены.
С учётом предварительных проверок закрыты все 33 worker boots и 15 relay
boots; late async errors нет, открытых owned native libraries не осталось.
