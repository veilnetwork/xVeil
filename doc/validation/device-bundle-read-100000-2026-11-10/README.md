# Свежий заголовок и сегменты device journal одним чтением — 2026-11-10

## Подтверждённая лишняя работа

При свежем чтении собственного журнала GroupService отдельно загружал header,
затем делал bounded batch его message segments. Во время native догрузки
100000 сообщений это повторялось примерно 24500 раз на получателе.

Теперь для собственного device group остаются только имена максимум семи
сегментов. Следующий запрос заново читает header и эти файлы существующим
StoredFileBatchReader (до восьми файлов, по 128 КиБ). Из полученных байтов
используются исключительно сегменты, названные **текущим** декодированным
header. При новых ссылках читаются новые файлы; при отказе, отсутствии или
превышении ceiling действует обычный свежий путь. Legacy settings, большие
header/segments и группы с большим числом сегментов сохраняют прежний reader.
Собственная запись сбрасывает подсказку, shutdown запрещает поздний fallback.

Байты живут только в текущем acquisition; незавершённые чтения разделяются
как раньше. Нет сохранённого принятого bundle, verdict или разрешения.
Проверки manifest, control, сообщений, roster и revoke остались свежими.
Write-wait timeout и повтор header после save-overtaking-read сохранены.
Максимум одна подсказка имён на identity service, очищается при shutdown.

## Проверки

Parent-red на реальном GroupService call-site: два физических file-вызова
вместо одного совместного; регрессия проверяет операции, а не секунды.
На окончательном fixture parent-red повторён, затем восстановленный candidate
прошёл три focused checks. Прототипные ошибки типов и fixture matcher не
считались красными регрессиями.

Проверены свежие байты после завершённого lookup, недоступный/отказавший batch,
повреждение/удаление/восстановление сегмента, слишком большой header,
повреждение/восстановление header и revoke. Отдельно другой writer меняет
header, а старые файлы остаются читаемыми: совместный batch действительно
получает старые speculative файлы, но итог содержит новый event из текущего
header. Ещё один gate проверяет, что поздний отказ batch после shutdown
не запускает fallback против следующей сессии storage.

**1085 related passed / 0 skipped**, 23 файла. Анализатор двух файлов —
0 issues. Имеющиеся in-flight sharing, concurrent-save, свежая проверка
подписей/роутов, отзыв и lifecycle проверки включены.
