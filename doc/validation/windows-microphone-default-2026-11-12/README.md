# Восстановление микрофона Windows — 2026-11-12

## Подтверждённый дефект

Нативный код сохраняет выбранный числовой индекс микрофона между движками.
xVeil хранит пользовательский выбор по названию, но при исчезновении этого
названия не делал нового выбора. После отключения USB прежний индекс мог стать
другим входом: следующий звонок использовал бы его, пока интерфейс не показывал
причины. Без сохранённой настройки тоже не было явного возврата к роли ОС.

Дополнительно desktop picker при отсутствии подтверждённого выбора отмечал
первый вход как выбранный. Первый элемент списка не доказывает фактический
системный выбор. Для выхода эта проблема уже была решена; вход отставал.

## Исправление

Windows native enumeration теперь предлагает `system-default` также для входа,
если у ADM есть микрофоны. Это уже существующая роль native input selector:
communications default с прежним fallback к обычному default. C ABI не менялся;
политика выбора системного микрофона не переопределена. Числовые устройства
остались доступными. Другим платформам новая роль не приписывается.

xVeil сначала восстанавливает найденное сохранённое название. Если его нет,
выбирает объявленную native роль ОС, сбрасывая старый индекс. Название отсутствующего
устройства остаётся сохранённым: его можно восстановить при последующем
переподключении. Явный выбор «Системный микрофон» очищает сохранённое название
только после успешного native переключения; отказ не меняет выбор.

В интерфейсе отдельные подписи «Системный микрофон» и «Системный выход», с
английским, русским и испанским переводами. Desktop больше не выдаёт неизвестное
устройство за нулевое. Android сохраняет прежнее представление своего списка;
эта правка не меняет его управление аудиоустройствами.

SDK commit: `83a54e35`.

## Проверка

- До правки пять новых Flutter assertions воспроизвели отсутствие возврата к
  системному входу, сохранение неправильной настройки и неверную отметку/подпись
  picker. Сохранённый доступный микрофон проходил уже на прежнем коде.
- После правки весь набор startup/controller и device picker: **79 passed**,
  без skipped. Анализ четырёх изменённых Dart файлов — без замечаний.
- Native runner компилирует точные production тела input-selection FFI,
  enumeration и list-input FFI с управляемым ADM. До правки Windows assertion
  о доступной роли падал; после — **65 non-Windows + 67 Windows checks** прошли.
  В том числе отсутствие микрофонов, сохранение числовых ID, ошибки переключения,
  rollback, незапущенный/muted capture и возврат к системной роли.
- Соседний output-selection runner: **25 + 20 checks** прошли.
- Свежая Windows x64 media DLL собрана из 67 проверенных файлов wrapper source
  с закреплённым WebRTC SDK. SHA статической библиотеки и pacing ABI проверены;
  источники совпали до/после сборки. В готовой DLL приватных строк не найдено.
- Отдельный Windows 11 C ABI probe загрузил именно эту DLL и проверенный полный
  SDK. Три создания/уничтожения движка: native enumeration содержит роль входа
  и числовые устройства; выбор numeric → system-default успешен, COM-контекст
  вызывающего потока сохранён. Захват, запись и сеть тестом не запускались.

Первая попытка native build остановилась из-за управления стендом: внешнее
перенаправление stderr под Windows PowerShell превратило диагностическое
сообщение clang в terminating error. Повтор без этого перенаправления успешно
собрал те же проверенные исходники; код builder не менялся. Первая попытка
не засчитана как сборочная квалификация.

## Границы и состояние

Это доказательство конкретной ошибки восстановления выбора и проверка настоящего
Windows ADM. **Физическая недоступность сохранённого USB-микрофона, слышимость
речи и Windows 10 этим не проверены.** Причина пользовательского случая
«Windows 10 → телефон: нет звука/камеры» не объявляется установленной. Камеру,
аватары и сеть эта правка не исправляет.

На момент исходного unit/native раунда AOT ещё не была пересобрана. Последующий
[контроль новой Windows AOT](../windows-microphone-aot-2026-11-12/README.md)
прошёл три видеозвонка с этой правкой. Immutable engine pins не обновлены. Native DLL использовалась только в отдельном probe, не
подменяла библиотеки основного приложения или сохранённого QA bundle.
Probe завершился, процессов из его каталога не осталось; временная копия SDK
и probe удалены. Исходный Windows QA-container/prefs, canonical frontend и
native bundle повторно проверены. Основное приложение телефона не затрагивалось.

Приватные имена устройств, адреса, пути, идентификаторы и сырые логи в эту
запись не включены. Изменения локальные, без push/релиза.
