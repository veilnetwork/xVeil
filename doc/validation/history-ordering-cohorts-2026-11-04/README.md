новые короткие сообщения уже записывались пакетами, но исправление ранее

Существующий строгий FIFO-анализатор квалифицировал его post-restart worker

В закрытом окне около 37,2 с commit handlers занимают 3,695 с, grouped reads

Обрезанный SIGKILL trace не использован вместо полного.

## Изменение

Обычный mirror merge проверяет исходную позицию и автора, затем может
приостановиться непосредственно перед `adoptMessageOrdering`. До 16 таких
подготовленных исправлений сохраняются одной атомарной транзакцией с прежним
форматом bodyless ordering-record. Новые вставки и исправления разделяются
последовательными границами публикации; порядок переходов между ними сохранён.

Storage проверяет прежнюю пару raw author/seq, исходящее направление и
отсутствие уже принятой canonical position. Исправление не вставляет пост,
не меняет тело, статус, attachment или raw authorship и не создаёт экспортируемый
sender sequence. Уже исправленная, удалённая или отсутствующая строка не
становится новой записью сообщения. Подготовленный список замораживается до
ожиданий; дубли ключей отвергаются, число запросов и размер payload ограничены.

Перед commit сохраняются свежие admission/binding/visibility проверки и
защита от начавшейся очистки. Stream/scan/session fences и ожидание durable
commit остаются. Message key удерживается до конца обычного merge; курсор
страницы ждёт публикации и всех продолжений. Если store не поддерживает
пакетную коррекцию или payload не подходит, выполняется прежняя последовательная
запись с теми же compare-and-adopt условиями.

Mailbox для собственных устройств не добавлен. HVS/Veil, wire format,
криптография, fsync/padding/churn, native ABI и engine pins не менялись.

## Контроль на одинаковом образе контейнера

Три отдельные копии одного закрытого исходного контейнера с 64 одинаковыми
сообщениями. Перед открытием проверяется равенство bytes исходного образа;
каждая фаза получает новый настоящий storage worker. A/B/A меняет только API
записи исправлений. Логическое состояние после каждой фазы совпадает, body/raw
position прежние, ложных canonical send events нет.

| Фаза | Ordering commits | Ожидание всего adapter-пути |
|---|---:|---:|
| A₁, по одной коррекции | 64 | 1280,086 мс |
| B, пакетами по 16 | 4 | 133,365 мс |
| A₂, по одной коррекции | 64 | 1139,109 мс |

Это один native A/B/A, не статистическая серия и не замер всей догрузки.
Время включает adapter/worker/native; оно не является отдельным измерением
диска или fsync. Сокращение числа commit проверяется независимо от времени.

## Сквозная квалификация

Первая полная серия прошла функциональный oracle: B восстановил 1545 строк
без A/C, затем от одного A получил все 2000 с правильным порядком/positions/
delivered и без completed-history retries. Retention без источников прошёл.
От готовности A до полной сходимости — 36,718 с; это не парное сравнение с
предыдущими 26,077 с, где у B уже было 1847 строк.

Однако её driver завершился с 1: старый дополнительный критерий требовал хотя
бы один RPC из per-row `historyApply` Zone. После пакетирования их там нет;
по завершении строки читают тёплый fold, а durable publication выполняется
вне приостановленных строк. Все остальные критерии отдельно перепроверены,
продуктовый код после этого запуска не менялся. Первый запуск не выдаётся
за прошедший весь driver. Cleanup был успешен: 31 PID, 41 порт, runtime удалён,
1424 inputs/native SHA неизменны во время запуска.

В stand-only census добавлена отдельная фиксированная `historyPublish` Zone
для реальной пакетной storage operation. Её проверка проходит через настоящий
adapter surface: два пакета по 16 дают два data commits с этой меткой, а не
32 выдуманных RPC. Результаты/errors/reset и privacy allowlist проверены.
Driver теперь требует реальный publication context, commit RPC и успешные
ordering batches; функциональные gates не ослаблены.

Повторный запуск прошёл и Flutter oracle, и весь driver:

- B принудительно завершён при 1572 наблюдавшихся строках. Без A/C после
  восстановления сохранены те же 1572; реально наблюдался sparse provisional
  tail, prefix fallback источника тоже выполнен.
- Вернулся только A. Все 2000 ID/порядок/source positions/delivered сошлись,
  completed-history retries — 0, некорректных/дублированных snapshots нет.
  Повторный запуск B без источников сохранил результат.
- После готовности A все строки видны за 26,178 с; полная позиционная модель
  сошлась за 31,395 с. Общий таймер миграции — 80,320 с, включая остановку и
  рестарты. Период опроса наблюдателя учитывается; разность времён не считается
  отдельным измерением CPU/диска. Парного контроля полной latency нет.
- В B зарегистрированы 7 успешных preparedOrderingBatch и 23 preparedBatch,
  по одному `historyPublish` context на вызов. Зафиксированы 60 настоящих commit
  RPC в publication context. Это не 60 отдельных сообщений: резервирование
  внутренних IDs и data commit различаются; методы и RPC не взаимозаменяемы.
- Driver/cleanup — 0/0, 29 PID и 39 портов проверены, своих listeners и
  процессов нет, runtime удалён. Во время прогона 1424 выбранных inputs и SHA
  обычных native-библиотек неизменны; обе зависимости чистые.

AST обновлён без LLM. Известные коллизии имён в Dart parts ограничивают полноту
графа; доказательства опираются на исходники, native контроль и исполнение.

Push, релиз, смена APK/движков и обновление сидов не выполняются. Общая latency
и расширенная multi-device матрица этим изменением не объявляются закрытыми.
