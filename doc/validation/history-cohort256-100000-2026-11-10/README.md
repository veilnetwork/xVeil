# Целая короткая страница в одной durable publication — 2026-11-10

## Механизм и границы

Wire-страница уже допускала 256 коротких сообщений, но локальный prepared
adapter публиковал её двумя группами по 128. Row ceiling поднят до 256:
одна подходящая страница получает одну атомарную запись. Одновременно
подготавливается до 256 строк (ранее 128). Обычное live-coalescing не расширялось. Отдельные лимиты **1800 байт на запись**
и **115200 байт на набор** сохраняются, поэтому полный row-count набор
не обязательно помещается по байтам.

Отказанный без записи набор делится на упорядоченные половины до 64 строк,
затем действует прежний single-row fallback. Меньшие adapters получают
256→128→128 или 256→128→64→64→128→64→64. Каждая часть заново проверяет admission;
никакая строка не завершается до её durable publication. Ошибка второй части
оставляет уже сохранённый prefix и прежний cursor. Порядок write families,
ordering CAS, mirror slots, serialization страниц одного разговора, revoke,
consent, TTL, binding и erasure gates сохранены.

Резервы внутренних log ID сохраняют максимум 256; авторские sequence numbers
не расходуются этим резервом. Wire page: 256 строк / 128 КиБ / 64 части;
формат storage/transport, sibling mailbox и модель свежей авторизации прежние.

## Почему проверяли публикации

Новый профиль baseline `eadc1c79` снят после предыдущего объединения header и
segments: 100000 сообщений, настоящие FFI/ratchet/HVS, точная история и cold
retention проверены. Production-код оставался неизменным во время профиля;
его состояние аттестовано до правок кандидата. В 26066 физических exclusive
samples `__fcntl` присутствует `File.sync_all`, в 26058 — и HvKvLogStore.commit.
Это свидетель синхронной записи контейнера, не вся причинная диаграмма latency
и не разрешение убирать durable barriers. Inclusive counts не складываются
в проценты wall time. Профиль также показывает работу fresh own-device
projection и message fold; они этим кандидатом не объявлены устранёнными.

Границы профиля: 21 chunk, 91552 nonconflicting physical samples, 11852
повторов удалены, 286 conflicting keys исключены, 811 truncated stacks.
Active window 143171,940 мс, покрыто 137310,502 мс; начало покрыто, хвост
5861,438 мс не покрыт. 13 isolate replies unavailable, один terminal endpoint
error, byte cap не достигнут. Это диагностический прогон с sampler, не A/B.
Девять собственных raw файлов сжаты 367,75→16,27 МиБ со сверкой распакованного
SHA; повторный анализ архивов дал тот же результат. URI/адреса/сырые стеки
не публикуются. [Агрегаты профиля](profile-summary.json).

## Регрессии и реальные транзакции

Два parent assertion-red через обычную history-доставку: incoming/outgoing
256-row страница давала `[128,128]` вместо `[256]`. Это проверка числа
публикаций и полного результата, без временного порога. На окончательном
fixture reds повторены, затем восстановленный candidate прошёл четыре
focused checks, включая оба меньших adapters.

Прежние 128-row byte-boundary случаи сохранены, для 256 добавлены posts
и ordering при **115199 / 115200 / 115201** байтах. Размер взят из настоящего
encoder probe; проверяются результат, число commit/admission и полные строки.
Превышение 257 строк и oversized payload отвергаются без публикации.
Native HVS наборы 64/128/256 проверяют ожидание durable commit, retry после
отказа, потерянный post-commit reply, cold reopen и отсутствие дублей.
Частичный отказ/revoke у меньших наборов сохраняет cursor и восстанавливается.

**1187 related + 89 guards = 1276 passed / 0 skipped**, анализатор восьми
Dart-файлов — 0 issues. Включены allocator/ratchet reservations, immutable
inputs, ordering/status, lifecycle, revoke/TTL, expiry/erase и guard/profiler
проверки. Опт-ин VM check выполнен с включённым VM service; первоначальная
ошибка его запуска без сервиса не считалась прохождением.

## SIGKILL после данных, до курсора

При одном атомарном 256-row наборе короткая страница не имеет частично
записанного тела. Fault перенесён **после durable publication выбранной строки,
но до завершения page callback/checkpoint**. Сохраняется строгий oracle:
реальные durable данные должны опережать оба ранее сохранённых cursor,
а не быть только давно завершённой страницей.

Выбрана строка 50080; ожидаемый опубликованный prefix — **50176**. SIGKILL
дал exit −9. При всех источниках offline cold B сохранил ровно этот prefix,
прежнюю контрольную строку и оба cursor byte-for-byte. Затем один источник
завершил восстановление: все 100001 строки exact, без дублей, включая
повтор страницы, записанной до падения. Ещё один cold reopen при offline
всех источников сохранил полный набор и cursor strings. Тот же candidate,
все 1540 source inputs и native SHA совпадают с B сравнения.
Это конкретный crash window, не полная crash/revoke/split-brain матрица.

## Очистка и остаток

A/B/A проверили 40/39/40 PID и 61/56/55 портов; crash — 45 PID/55 портов.
Own процессов/listeners не осталось, runtime roots удалены. Cache во всех
фазах 92 entries, новых kernel entries 0, allocated delta около +0,46 МиБ;
кеш около 9,5 ГиБ, свободно около 145,6 ГиБ. Двенадцать собственных snapshots
сжаты без потерь 226,20→10,06 МиБ, SHA распакованных данных проверен до
удаления исходников. Агрегатный анализ после сжатия подтверждён; сырые IDs,
адреса, VM capabilities, cursor strings и пути остаются вне Git.

Latency всё ещё открыта: примерно 125 с на 100000 строк и около 172 мс
между full reply и следующим query. NETCALL и остальная multi-device matrix
не квалифицированы этим раундом. Нет push/релиза, обновления APK/сидов,
sibling mailbox или утверждения о полной проверке всех старых жалоб.
