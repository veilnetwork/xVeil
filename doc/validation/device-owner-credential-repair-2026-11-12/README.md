# Восстановление ключа владельца из активной группы устройств

> Продолжение: [атомарный импорт recovery certificate](../certificate-recovery-publication-2026-11-12/README.md)
> закрывает гонки импорта с adoption и частичную установку ключа.

## Подтверждённые дефекты

`openLocalSovereign` считал отсутствие отдельного файла credential признаком
новой личности. При историческом неполном сохранении группы файл мог отсутствовать,
хотя активная подписанная группа уже содержала исходный зашифрованный XVSB/XVRC.
Для XVSB правильная или другая допустимая фраза создавала новый гибридный ключ
с другим владельцем. Для XVRC попытка открыть исходный код восстановления
попадала в создание phrase-backed ключа и отказывала.

Кроме того, два одновременных первых открытия могли создать разные гибридные
ключи. Оба вызова возвращали signer, но сохранялся только один владелец.

На прежнем коде десять проверок восстановления дали **7 FAIL / 3 PASS**;
отдельная проверка одновременного первого открытия — **1 FAIL** с разными owner ID.
Это воспроизведение механизма на синтетическом состоянии, а не доказательство
причины отдельной пользовательской жалобы.

## Изменение и границы

- При отсутствии dedicated credential читается копия из явно активной группы.
  Manifest проверяется штатным verifier, хеш зашифрованной копии — штатным load.
  Входящий snapshot без adoption не становится источником локального владельца.
- Native signer открывается прежним секретом; до записи проверяются algorithm,
  owner и полный genesis public key. Read-only открытие работает без записи.
  Неправильный секрет, другой владелец или недоступная активная группа не создают
  replacement key. Повреждённая существующая копия не заменяется fallback-копией.
- Поддерживаемый переход Ed25519 → hybrid сохраняется: проверяется совпадение
  Ed25519-части, затем существующий link/mint переносит состав в новую группу.
  Новая личность без группы по-прежнему может создать свой credential.
- Открытие/создание/repair и атомарная публикация активной группы используют одну
  очередь. Readers ждут её завершения; identity shutdown дожидается принятой записи.
  Неподтверждённый signer закрывается при ошибке или shutdown.

Это восстановление **в GroupService при операции с ключом**, не изменение boot
root-choice и не автоматический ремонт контейнера при unlock. Если потеряны обе
копии, hybrid-владелец не создаётся заново. Нечитаемый существующий файл требует
отдельного разбора; скрывать такое повреждение автоматической заменой нельзя.
Wire, mailbox, ABI и правила отзыва устройств не менялись.

## Проверки

- **588 PASS / 0 skipped**: полный GroupService и пять наборов storage publication/
  lifecycle. Включают 18 новых сценариев, а не дополнительные к ним 18 проверок.
- Новые сценарии: XVSB/XVRC, read-only, неверный секрет, существующая повреждённая
  копия, dangling active pointer, другой владелец, разрешённый Ed25519 upgrade,
  concurrent first opens, отказ записи/потеря ответа/повтор, shutdown и adoption race.
- В двух из 18 сценариев используется настоящий hidden-volume через worker.
  После полного закрытия storage открываются новые service/worker/native space;
  восстановленный ключ подписывает добавление устройства. Второе cold-open
  подтверждает сохранение encrypted credential и активного gid. Это close/reopen,
  **не SIGKILL внутри native commit и не аппаратный сбой питания**.
- Targeted analyze: 0 issues; `git diff --check` проходит.

Native crypto: Veil Rust core `e963fbdb`; hidden-volume `293792d7`.
Все native-входы проверяются по SHA до и после; media engine не используется.
Данные тестов и журналы остаются вне репозитория.

Дополнительно **2 PASS / 0 skipped** в process-сценариях замены уже существующей
семьи: принудительное завершение до и после атомарной публикации, cold inspection
без помощи исходного процесса, повторное согласие и сходимость истории. Это
регрессионная проверка очереди публикации на текущих исходниках; историческое
отсутствие dedicated credential моделируют отдельные 18 сценариев выше.

После стенда подтверждены выход 31 учтённого PID/группы процессов, отсутствие
тестовых VM и освобождение 30 зарегистрированных TCP/UDP-портов. Пользовательские
приложения, контейнеры и серверы не менялись. Native-библиотеки не пересобирались.

Исправления локальные, без push/релиза. Не закрывают всю multi-device матрицу,
часы/сутки offline и жалобу на исходящее видео исходного Windows 10.
