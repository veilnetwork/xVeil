# Соответствие локального медиадвижка исходникам — 2026-11-11

## Подтверждённый пробел упаковки

Release workflow уже проверял SHA скачанного движка и digest текущего `src`.
Локальный `bundle-macos-dylibs.sh` проверял только функции. Старый движок с тем
же ABI мог попасть в новую app-сборку. Если движок отсутствовал или проверка
функций его отвергала, прежняя копия в уже существующем app bundle также не
удалялась. Это дефекты локальной упаковки, не установленная причина жалобы
Windows 10 на звук/камеру/аватары.

## Исправление

- Канонический алгоритм `xveil-media-source-v1` перенесён в SDK
  `flutter/veil_media/source_provenance.py`; release verifier использует его
  же. Формат digest, порядок POSIX-имён и нормализация CRLF не изменились.
  На настоящем текущем дереве digest до/после переноса побайтно совпал.
- macOS builder снимает digest до компиляции и проверяет его после успешной
  линковки. Запись `.provenance` связывает исходники и SHA полученного бинарника;
  смена исходников не перезаписывает прежнюю запись успешной сборки. Запись
  заменяется через отдельный временный файл, без путей, логинов и параметров.
- Staging проверяет source digest, ровно один корректный binary SHA и функции,
  затем ещё раз проверяет скопированные байты перед заменой целевого файла.
  Ошибка останавливает упаковку. Права файла сохраняются. Отсутствующий
  необязательный движок удаляет прежнюю bundled-копию; сборка без медиа
  остаётся поддерживаемой.
- Для отдельной Rust-сборки PacketTunnel добавлен
  `XVEIL_PACKET_TUNNEL_TARGET_BASE`: архитектуры по-прежнему изолированы,
  обычный FFI target не используется. Это позволяет выбрать диск с местом,
  вместо неявного обращения к checkout `target`, который может быть symlink.

## Проверки

13 Python-проверок прошли: digest/CRLF/имена, неизвестная или неоднозначная
запись, изменённый бинарник, смена исходников, отказ symbol gate, изменение
бинарника во время staging, сохранение прав и удаление старой optional-копии.
Symbol gate в portable staging-тестах подменён отдельным контролируемым
процессом; они не объявлены проверкой настоящего ABI. CI запускает оба файла.

Настоящая сборка текущего macOS arm64 движка выполнена без test hooks и CC trace.
107 экспортируемых функций совпали со 107 lookup Dart. Сборочная запись
проверена по обоим digest. С настоящими файлами staging отверг старый движок
без записи, принял новый и удалил прежнюю копию при отсутствии optional engine.

Полный SDK пересобран на текущем SDK-коммите с `production-seeds,node-embedded,
packet-tunnel`, без dependency override. Настоящие SDK и media загружены вместе:
создание/удаление direct и group engines, mute и noise suppression off/on
прошли. Захват, playout и сетевой звонок не запускались — это инициализация и
управление, не доказательство слышимости. Контролируемый production FFI input
selection test также прошёл для Windows и non-Windows ветвей.

Пять Flutter-проверок Apple tunnel/network rule прошли. Новый subprocess-test
проверяет реальный shell builder с контролируемым cargo: каталог с пробелом,
architecture suffix, production features и отказ от общего FFI cache. Analyzer
изменённого Dart-теста и bash syntax checks чисты.

## Ограничения и среда

Первый media build не нашёл SDK по старой generated-ссылке после обновления
Xcode. Повтор выполнен с установленным SDK; временная ссылка восстановлена,
исходники WebRTC и compile metadata не менялись. Это host-среда, не дефект звонка.

Первый app build остановился на отдельной PacketTunnel Rust-сборке: dyld
отверг stripped proc-macro LINKEDIT. Как и в предыдущей SDK-квалификации,
контроль использует `CARGO_PROFILE_RELEASE_STRIP=none`, только в окружении
host-сборки. Cargo.toml и release CI profile не менялись. Дальнейшая сборка
использует отдельный root-disk cache и watchdog свободного места/дедлайна.
Неуспешный проход не считается квалификацией приложения.

## Итог app/AOT

Финальный macOS arm64 AOT-проход завершился успешно, без изменения исходных
входов во время сборки. Промежуточный успешный проход, во время которого
дополнялся staging и документация, не использован как окончательный источник
provenance: выполнена повторная сборка с неизменными входами. Нет debug hook,
медиатестовых hooks и диагностики. `codesign --verify --deep --strict` прошёл;
версия в Dart image совпала с pubspec. Это ad-hoc сборка **без VPN**, а не
нотаризованный или опубликованный дистрибутив.

Библиотеки проверены уже из собранного app bundle. Два opt-in SDK-сценария
прошли через штатный ABI gate: publish → list → export 600017 байт → explicit
discard, текущий файл и scan сохранены. Дополнительно настоящие bundled SDK и
media вместе прошли direct/group init, noise off/on, mute и destroy. Эти
проверки выполнялись в host-процессах над библиотеками из app; Flutter GUI и
сетевой звонок не проверялись. Они не заменяют физическую проверку AOT UI.
Ранее лежавший локальный media binary после сборки восстановлен со сверкой SHA.

Публичные immutable пины Android/Linux/Windows не обновлялись. Физическая Windows 10 жалоба, проверка
готовых платформенных артефактов и публикация остаются отдельными задачами.
Пользовательские контейнеры, телефоны и реле не менялись; GUI не запускался.
Push/релиза нет.
