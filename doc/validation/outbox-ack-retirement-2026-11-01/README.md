# ACK Outbox: неопределённый результат и соседние удаления

2026-11-01. Продолжение [профиля большой истории](../mirror-apply-race-2026-11-01/README.md).
На исходном срезе отправитель миграции выполнял 1070 коммитов с Outbox;
это включает enqueue и retirement, не 1070 ACK-коммитов и не доказательство
их положения на критическом пути.

## Подтверждённый дефект

Одиночный `ackOutboxFrame` удалял payload и индекс атомарно, но при потере
ответа **после успешного commit** оставлял старую запись в RAM-кэше.
`pendingOutboxFrames` возвращал уже удалённый кадр, тогда как повторное
открытие того же хранилища его не содержало. Это ложное обязательство могло
породить лишнюю повторную отправку. Причиной прежних пользовательских
задержек или потерь это не объявляется.

Существующий пакетный `ackOutboxFrames` уже обрабатывал неопределённый
результат: сбрасывал кэш и перечитывал all-or-none состояние индекса. Оба API
теперь используют один critical helper с этой обработкой. Неудача загрузки
индекса возвращает ошибку, а не ложный успех одиночного ACK.

Первый red: **4 passed / 3 failed**. Один отказ — stale RAM после потерянного
ответа; два других — счётные проверки объединения (64 коммита вместо одного,
129 вместо трёх). Ошибка до commit оставляет обе строки, ошибка после commit
удаляет подтверждённые строки; оба исхода сравниваются с повторно открытым
хранилищем. Native-проверки повторяют оба варианта поверх настоящего worker.

## Ограниченное объединение

Соседние одиночные ACK одного peer могут разделить ещё не начатую очередь
retirement, максимум 64 разных ID. Начавшаяся обработка закрывает набор **до
первого await**. Enqueue, чтение pending, прямой batch API, invalidation или
другой peer разрывают объединение. Общая очередь Outbox сохраняет порядок:
ACK → enqueue того же ID → ACK остаётся двумя удалениями.

Нет таймера накопления или нового ожидания. Future каждого вызова завершается
после общего durable commit. Проверка назначения остаётся per-peer, чужая
строка не удаляется. Индекс авторитетен; существующий лимит 1024 payload
tombstones и последующая bounded cleanup сохранены. Wire, формат хранения,
ratchet/checkpoint, подписи, ACL и правила повторов не менялись.

Тесты дополнительно проверяют ошибки общей транзакции, повтор после отказа,
100 одинаковых ACK, порядок чтения между ACK, неправильного peer и приход
следующего ACK во время удержанного commit. Набор проверяет именно
all-or-none результат и ожидание записи, без тайминговых порогов.

## Native A/B/A

Один worker-backed зашифрованный контейнер создаётся заново для каждой фазы.
Перед измерением подготовлены 64 кадра одного peer и один посторонний.
Измеряется только одновременное retirement 64 кадров; посторонняя строка
проверяется после настоящего close/reopen.

| Фаза | Retirement commits | Индексов удалено | Время участка |
|---|---:|---:|---:|
| A₁, прежний код | 64 | 64 | 1063,671 мс |
| B, кандидат | 1 | 64 | 27,134 мс |
| A₂, прежний код | 64 | 64 | 1105,362 мс |

Исходники A₁/A₂ побитово одинаковы, fixture не меняется, кандидат восстановлен
после серии в `finally`. HV сверён по прежнему SHA до/после; новая native
библиотека не собиралась. В тесте нет переключателя поведения production.

Это цена **одновременно доступных ACK**, не обещание 40-кратного ускорения
миграции. Когда ACK приходят по одному и первый уже начал commit, следующий
будет отдельной транзакцией. В исходном микробенчмарке кандидат отдельно дал
24,261 мс; для сравнения используется только зачтённая A/B/A-таблица.

## Проверки

- Связанный Flutter-набор: **107 passed**, включая 11 новых сценариев.
- Native: **5 passed**, включая lost-reply, отказ до commit, большой
  incompressible Outbox и большую правку сообщения.
- Analyzer production-файла и двух новых тестов чист. Первая ошибка
  конструктора нового native fixture исправлена до запусков; не засчитана
  как product red. Format новых тестов и `git diff --check` прошли;
  несвязанные прежние форматные участки большого production-файла сохранены.
- Все пять native test process groups завершились, временных ACK-контейнеров
  нет. Production-серверы, телефон и Windows не менялись.

## Сквозная миграция и обратный контроль

2000 исходных доставленных сообщений, A/B одной личности и C другой,
раздельные процессы/worker-контейнеры, три локальных реле. Текущий native SDK
`eb644a83`, те же CLI/FFI/HV по SHA, публичные seeds/discovery отключены.
Исполняется только начальный перенос на новое B; пятиминутный offline,
revoke/split-brain/crash этим запуском не засчитываются.

A₁ — предшествующий контроль на текущем SDK, B — кандидат, A₂ — возврат
прежнего кода. Проверено равенство всех **568** frozen-файлов A₁/A₂. От B
отличается ровно `hidden_volume_storage.dart`; другие 567 файлов одинаковы.
Контроллер восстанавливает кандидат в `finally`, после стендового teardown.

| Фаза | Первое полное наблюдение | Outbox commits A | Message-log commits B |
|---|---:|---:|---:|
| A₁, прежний код | 103,068 с | 1070 | 2149 |
| B, кандидат | 72,220 с | 970 | 2001 |
| A₂, прежний код | 77,309 с | 1082 | 2150 |

Outbox-колонка включает enqueue и retirement. В каждой фазе **2000/2000**
совпали по всем ID и порядку, на B все delivered, повторов старых message ID
ноль. На кандидате 2001 append (со служебной строкой), без повторных успешных
append одной пары в окне, без ошибок и некорректных снимков. Источники/native
артефакты не менялись во время каждого прогона.

**Общее ускорение не установлено**. Повторный baseline намного быстрее
первого и тоже не задержался на 1976 строках; исчезновение старой хвостовой
паузы нельзя присвоить ACK-правке. Микрозамер доказывает экономию в ACK-burst,
сквозная серия показывает сохранность истории и меньшие счётчики конкретного
прогона. Дополнительные message-log записи baseline (2149/2150 против 2001)
этим циклом причинно не атрибутированы. Опрос около 5 с; это верхние границы
наблюдения после link-подготовки, а не время последнего пакета.

Пассивный наблюдатель читал уже созданные fixture-снимки без новых RPC. Он
записал счётчики append и отсутствие конкретных строк для последующего
приватного сопоставления. В A₂ при 1950 видимых строках 13 append ещё ждали
завершения; после следующего опроса все 2000 присутствовали. Старое стояние
1976 в этих двух сериях не возникло, его причина этим наблюдением не доказана.

Кандидат: **1 E2E passed**, 264,190 с с подготовкой/teardown; независимо
проверены **18 PIDs / 19 портов**. Обратный контроль: **1 E2E passed**,
268,482 с, **18 PIDs / 18 портов**. Ни процессов, ни слушателей нет,
оба runtime-root с контейнерами удалены. Пассивные наблюдатели завершились.
Публичный [result.json](result.json) содержит только агрегаты; raw logs,
локальные IDs и полные source/binary proofs остаются приватными.

Догрузка большой истории остаётся активной: подтверждённая цена message-log
и служебных операций ещё велика. Следующее направление — ограниченное
объединение message append с сохранением выделения seq, durable-результата и
maintenance-барьеров; это пока направление, не реализованный фикс. Полная
multi-device матрица, NETCALL/NETLINE и слышимость речи этим циклом не закрыты.
Коммит локальный, unsigned; push и релиза нет.
