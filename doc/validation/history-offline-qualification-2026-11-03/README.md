# Большая история и пять минут offline на текущем Dart

2026-11-03. Квалификация `13f24dd5` после исправления history-room. Production
код в этом цикле не менялся. Без push/релиза, новых engine/native pins,
установки на телефон и обновления публичных реле.

## Проверяемое состояние и усиление oracle

Три отдельных OS-процесса A/B/C: A и B — одна личность, C — другая.
Настоящие Riverpod-провайдеры, native signing, worker/HV и изолированное
loopback-реле. Сначала A ↔ C имеют 2000 доставленных проверочных сообщений,
затем B связывается и получает историю. После этого B останавливается,
A отправляет C ещё 100 сообщений, B отсутствует не менее пяти реальных
минут. C останавливается до повторного запуска B; A остаётся online.

В тест восстановления добавлено сравнение `orderAuthor/orderSeq` новых 100
сообщений с source snapshot A. Source oracle должен содержать ровно 100
позиций; пустой список не может подтвердить сходимость. Готовность требует
точных ID, порядка, позиций и delivered одновременно. Полное количество
само по себе не завершает ожидание. Analyzer прошёл; усиленный native-тест
выполнился целиком, без skip.

## Результаты

| Этап | Online/offline и действие | Ожидание | Факт |
| --- | --- | --- | --- |
| Добавление B | A/C online, B связывается с A | B получает 2000 строк и исходные позиции/status | Полная сходимость за 35,994 с после link |
| B отсутствует | B stopped; A → C, 100 сообщений | A/C сохраняют одинаковые ID и порядок, A получает delivered | 100/100 доставлены до возврата B |
| Возврат B | C stopped до запуска B, A online | 100 own-outgoing mirrors на B без участия C | 100/100 за 5,322 с после ready, 16,244 с от запуска |
| Конечное состояние | После сходимости B возвращается C | Проверочные ID и порядок совпадают | На B сохранены исходные 2000 и новые 100; A/C также сохраняют оба набора |

В первом этапе все 2000 delivered, нет повторов завершённой истории,
промежуточных полных выборок с иным порядком или source positions не
наблюдалось. Во втором этапе новые 100 на B имеют точные IDs/порядок,
source positions и delivered. Конечные ID/порядок исходных 2000 проверены
после восстановления; их source positions сверялись при начальном linking,
отдельного повторного сравнения старых позиций после offline нет.

B не имел процесса примерно **301,2 с до запуска**. Готовность после запуска
заняла 10,921 с; от исходной остановки до ready — 312,075 с. Это разные
границы: время до ready нельзя выдавать за доказанный интервал отсутствия
всех сетевых соединений. Проверены реальные stop/restart, не сдвиг часов.

В recovery было два наблюдения: 0 строк через 0,210 с после ready, затем
100 полных строк со статусами и позициями через 5,322 с. Опрос раз в пять
секунд задаёт точность. В логе B одна retry-попытка до наблюдения общего
`delivered=100`, после этого наблюдения — ноль. Это не логический дубль:
конечные ID/порядок на C сохранены. Пер-сообщенческое сопоставление момента
этой попытки с её собственным delivered не выполнялось; не заявляется
«ни одной сетевой повторной отправки во всём сценарии».

Текущие 35,994 с — одиночная квалификация, не A/B. Из неё не выводится
ускорение относительно предыдущих 41,5/46 с и не приписывается эффект
исправлению адресации history-room. Полная миграция по-прежнему занимает
десятки секунд и остаётся активной проблемой.

## Границы матрицы

Подтверждены текстовая история при добавлении B и возврат после пяти минут
с 100 outgoing-копиями, когда C уже offline. Это часть базовых сценариев
4/5 и backlog-сценария 15 на host/native-стенде.

**A оставался online.** Получение копий при одновременной недоступности A и C
не проверено. Также не проверены часы/сутки offline, kill посреди догрузки,
полная revoke/split-brain/crash матрица, файлы/voice/reactions в миграции,
Android/AOT и физический мобильный handover. Чистый stop B не является
crash-consistency тестом. Никакие эти пункты не объявляются исправленными
или автоматически дефектными.

## Происхождение и cleanup

SDK/CLI/FFI намеренно заморожены на ранее проверенном `eb644a83`, HV одинаков.
Это проверка текущего Dart на том же native-контроле, а не последних
transport-изменений. CPU-профайлер выключен. Публичные seeds/discovery выключены.
1395 frozen-файлов и native artifacts сверены до/после; исходники во время
стенда не менялись. Пассивный внешний наблюдатель только читал file-responses
live worker; не открывал контейнер и не отправлял дополнительных запросов.

Тест завершился успешно. После него независимо проверены выход 24 собственных
PIDs и освобождение 33 захваченных портов. Живых собственных процессов и
слушателей нет, runtime-контейнеры удалены. В публичную запись не попали IDs,
адреса, payload, ключи и correlation hashes. Raw synthetic evidence остаётся
приватным. Пользовательские контейнеры и устройства не менялись.
