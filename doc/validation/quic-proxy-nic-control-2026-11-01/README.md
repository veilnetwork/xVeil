# QUIC: совмещённый proxy/NIC-захват и контроль obfs4

2026-11-01. Продолжение [NIC/send-error цикла](../quic-nic-send-errors-2026-11-01/README.md).
Код приложения и SDK не менялся. Mac SDK `026dd915`, сервер SDK `c8bdfd97`,
те же frozen frontend/AOT, профиль, две изолированные службы и серверные
конфиги. Пять запусков, production не используется для трафика стенда.

**Новый результат:** в одной и той же медленной попытке short-header datagram
успешно переданы локальным proxy в UDP socket ОС, но отсутствуют в capture на
NIC тестового сервера. Это локализует проблему до серверного QUIC/OVL1, не
называет конкретный фильтр или виновного оператора. Исправление задержки в
коде проекта не заявляется.

## Совмещённый захват

Proxy сохраняет байты, IP TOS/ECN и проверяет размер результата каждой
отправки. TLS, OVL1, bootstrap key/nonce не подменяются. Каждый Mac source
получает отдельный upstream socket. Proxy и capture имеют независимые
ограниченные deadlines. Перед двумя запусками capture уже подтвердил
готовность; после обоих завершён явно, удалённый capture PID проверен.

Двусторонний ACTIVE с одним server link не менее трёх секунд достигнут через
**37,595 / 38,322 с**. Начало отсчёта — готовность узла после unlock, а не старт
процесса; времена health/onboarding сюда не включены.

| Наблюдение | Неудачная попытка 1 | Неудачная попытка 2 | Успешный однозначный контроль |
|---|---:|---:|---:|
| UDP datagram, отправленных proxy | 33 | 32 | 110 |
| Найдено на NIC сервера | 4 | 4 | 110 |
| Из них short-header, отправленных proxy | 29 | 28 | 99 |
| Short-header найдены на NIC | 0 | 0 | 99 |
| Server STREAM RX | 0 | 0 | 1 |
| Результат ожидания первого потока | timeout | timeout | ready |

Принадлежность попыток сопоставлена через зашифрованные server-send samples,
также полученные proxy. У этих трёх строк нет неоднозначности по proxy-flow или
NIC-flow в пределах захвата. Другой успешный flow дал 109/109 UDP-совпадений,
но содержит две server connection; его нельзя представлять как однозначный
поконнектный контроль. Остальные server-соединения, не сопоставленные proxy,
не приписаны Mac.

В pcap **1008 записей**, 1009 received-by-filter, **0 kernel drops** по tcpdump.
Анализ GRO/coalescing ищет ciphertext внутри записей, не считает кандидатные
сегменты доказанными границами wire-пакетов. Положительные sampled-контроли:
**39/39 server RX** и **32/32 server TX** найдены на NIC. Поиск по всем пакетам
proxy, в отличие от прежнего 1/16 socket sampling, позволяет сравнить все 29/28
отправленных short-header datagram с pcap. IPv4-фрагментация в захвате не
наблюдалась. Отсутствие capture drops не исключает потери до NIC/capture.

Локальный proxy получил успешный результат syscall, а не скрывающий ошибки
`quinn_udp::send` API. Но это всё ещё не Mac NIC capture: ОС может отбросить
пакет после успешного syscall. Поэтому вывод ограничен участком **Mac kernel /
локальная сеть / промежуточная сеть / инфраструктура до NIC сервера**. Нельзя
приписывать его провайдеру телефона или объявлять общую причину NETCALL-01.

Read-only снимок сервера не показал активных XDP/tc/BPF фильтров и firewall
правил nft/iptables; видна обычная qdisc. Это ограниченный снимок, не доказательство
отсутствия защиты у облачного оператора. Один запрос tc использовал неверное имя
интерфейса и не засчитан; отдельный `bpftool net` вернул пустые attachments.
Маршрут Mac к серверу не использует utun; это не исключает всякий локальный
фильтр или политику VPN. VPN и системная защита не отключались.

## Контроль через известный obfs4 endpoint

В отдельной серии из трёх запусков выбран **существующий obfs4/TCP listener
того же S1**, с ключом из собственного testnet. Схема endpoint и testnet PSK
переданы штатными настройками, а не встроены в production-код. Серверные
конфиги и бинарники не менялись. Трафик не туннелировался через SSH/proxy.

До двустороннего ACTIVE: **1,515 / 1,530 / 1,534 с** от готовности. Для каждого
запуска observer требует `obfs4-tcp://` в локальной и серверной ACTIVE-строке,
один link и ≥3 секунд устойчивого наблюдения. Все три проверки прошли; быстрый
QUIC или чужая сессия не могли удовлетворить этот oracle.

Это показывает работоспособность разрешённой TCP-альтернативы на данном пути.
Это **не A/B/A ускорение кода**, не automatic fallback из QUIC и не причина
каждого из прежних холодных ожиданий. Listener/PSK выбраны явно для проверки;
нельзя угадывать TCP endpoint для произвольного QUIC bootstrap или обходить
пользовательский запрет транспорта. В текущем outbound-пути после отказа есть
условные NAT/SOCKS fallback, но они не означают произвольный переход на TCP.

## Происхождение и уборка

- Mac native SHA и codesign проверены перед каждым запуском; Linux candidate
  SHA совпал с ранее проверенным `c8bdfd97`. Source SDK остался `026dd915`.
  Cargo/Flutter сборки и тесты в этом цикле не повторялись: production-код
  неизменён, повторена именно физическая квалификация.
- Пять собственных Mac-процессов завершены, runtime-каталоги удалены; во всех
  пяти серверная строка отсутствовала уже при первом опросе после lock.
  Это новое наблюдение, не ретроспективное устранение прежней строки после lock.
- Proxy/hasher, packet capture и оба SSH observer завершены. Bootstrap-list
  proxy-серии восстановлен. Raw pcap, токены корреляции и журналы приватные.
- После каждой серии все шесть test services остановлены, порты освобождены;
  S1/S2 возвращены на исходные test binaries, trace drop-in удалены,
  исходные unit definitions сверены, autorollback остановлен. Независимые
  финальные preflight подтвердили исходное состояние и неизменность production
  PID/binary/config **6/6** в каждой серии.
- Телефон и Windows не менялись. Только локальный unsigned-коммит документации;
  push и релиза нет. В публичном result нет адресов, node IDs, wire CIDs,
  fingerprint-полей, ключей или пользовательских путей.

**Остаются открыты:** NETLINE-01 в полном шестисерверном сценарии, NETCALL-01
при смене сети, слышимость речи, остаточная догрузка большой истории и расширенная
multi-device матрица. Наблюдаемый QUIC startup на данном внешнем пути не следует
лечить изменением ratchet/Outbox или сокращением handshake timeout. Для следующего
различающего эксперимента нужен исходящий Mac NIC capture либо другой сетевой
путь; независимо доступна работа над локальной стоимостью догрузки истории.
