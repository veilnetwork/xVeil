# Восстановление незавершённого удаления — 24 октября 2026

## Подтверждённый дефект

Локальное удаление сначала стирало сообщение, затем публиковало удаление своим
устройствам. При отказе второй операции строка уже исчезала, а новая попытка
останавливалась на отсутствии строки. После перезапуска восстановить публикацию
было не из чего. Для «Удалить у всех» этот же отказ не позволял поставить команду
собеседнику в долговременную очередь.

Три регрессионных теста на исходном коде воспроизвели: потерю повторной локальной
публикации, отсутствие команды собеседнику и отсутствие восстановления после
перезапуска. Каждый из трёх тестов падал по соответствующей проверке поведения.

## Исправление

Решение пользователя и обязательства завершить его записываются **атомарно с
удалением сообщения**, в существующую запись tombstone. Незавершённые этапы:
публикация своим устройствам, передача команды собеседнику в durable outbox,
очистка состояния раздачи вложения. Успешный этап снимает только свой флаг.

Команда собеседнику передаётся в существующий механизм durable send независимо
от состояния журнала своих устройств. Сначала она сохраняется, затем выполняется
ограниченная по времени попытка live-отправки. Ожидание общего прохода очереди не
добавлено. **DEL не использует mailbox.** Повтор использует тот же frame ID.

Восстановление запускается при старте, подключении обработчика multi-device и
периодическом повторе доставки. Пакет ограничен 64 решениями; отказ в первой
странице не блокирует последующие. Завершение messaging дожидается начатого
локального удаления до освобождения хранилища. Повторная публикация уже стёртого
текста не требует нового полного scrub на каждой попытке.

Новая запись восстановления не содержит тела, истории редактирований, подписи
файла, его имени или пути. Она сохраняет существующие conversation/message ID,
author/seq и флаги этапов. Для незавершённой очистки раздачи временно сохраняется
content ID вложения; после очистки он удаляется с обязательством физического
scrub, переживающим перезапуск. Эти поля локальны для зашифрованного контейнера;
gap-fill по-прежнему передаёт удалённый слот как пустой void без message ID/тела.
Удаления, полученные от собеседника или своего устройства, не создают нового
локального решения и не зацикливают публикацию.
