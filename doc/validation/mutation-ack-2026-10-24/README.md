## Восстановление без нового persistent pending store

Если целевой строки ещё нет, peer edit/delete помещается в bounded RAM cache,
но не получает ACK. Ответственность остаётся у существующего durable outbox
отправителя. Тесты действительно создают два `MessagingService`, вызывают
пользовательские `editOwnMessage`/`deleteForEveryone`, проверяют сохранённую
очередь, заново открывают обе стороны, доставляют исходное сообщение и вызывают
штатный `flushOutbox`. Только после применения приходит ACK и очередь пустеет.

Нового plaintext файла или постоянной таблицы pending-метаданных нет. Лимит
cache остаётся общим для обеих категорий отправителей. Пока ни одного
держателя queued операции нет online, она недоступна; mailbox fallback не
добавлен. Старые кадры без frame ID не приобретают durable гарантию.

## Проверки и ограничения

Базовый набор из 12 тестов дал **11 отказов**: ранние ACK, пропуск повторного
scrub, потеря pending после restart и изменение outgoing через контактный
pending. Исправленные проверки включают удержание/отказ записи, отмену по
reader policy с тем же ACK, сохранение ask-before-clear, оба порядка смешанных
pending, завершённый tombstone под новым frame ID и две durable очереди после
перезапуска отправителя и получателя. Точные итоговые количества, отрицательный
контроль и software SHA-256 — в `summary.json`.

Транспорт управляемый; storage — настоящий Dart mapping поверх
`FakeHvContainer`. Проверка scrub доказывает повторный вызов и успешное
завершение операции, а не физическое затирание native файла. Не выполнялись
SIGKILL на каждой границе native commit/ACK, новый физический/Windows прогон,
все peer/device races и весь набор из 63 сценариев. Callback зеркалирования
остаётся асинхронным по прежнему контракту; его вызов не означает завершение
записи signed device journal. Уже ACKed/потерянные кадры старой версии не
восстанавливаются этим изменением из воздуха.

SDK/HV, wire format, mailbox policy и настройки реле не менялись. Приложения
Mac/Android, микрофон и native nodes не запускались. Все Flutter-запуски с
`TMPDIR=/private/tmp/`; services/storage закрываются teardown. В git только
synthetic tests и агрегаты; сырые журналы остаются в приватном cache.
