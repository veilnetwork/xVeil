# Poco ↔ Mac: проверка SDK с сохранённым reconnect wake

**NETCALL-01 остаётся подтверждённым и открытым.** На SDK `aa51cc13`
исправленная локальная гонка уведомления не устранила самопроизвольное
завершение звонка при Wi-Fi → cellular. Отрицательный результат сохранён;
успех нового звонка не подменяет проверку уже идущего разговора.

Локальные регрессии: [reconnect wake gap](../reconnect-wake-gap-2026-11-06/README.md).
Анонимные агрегаты: [summary.json](summary.json).

## Стенд и происхождение сборок

- Poco с SIM, первоначально validated cellular и выключенный Wi-Fi; MacBook.
  Windows не участвовала. Только свои ранее подтверждённые QA-личности.
- Обе FFI собраны из чистого SDK `aa51cc13` после коммита; watcher проверял
  отдельную внешнюю ФС весь build и не зафиксировал её потери. Mac / Android
  build receipts, SHA, signer и provenance сохранены вне репозитория.
- Frozen QA frontend, AOT, media и hidden-volume побайтно прежние. Android
  APK перепакован только с новой FFI, signer сохранён. Mac использует прежний
  подписанный bundle с новым внешним FFI; actual mapping проверен через lsof.
  Все 208 C exports совпадают с базой; ABI contract совпадает на Mac.
- Один отдельный QA-Core с прежним бинарником `ade3130a`; production к нему
  не подключается. До звонка CLI-снимок содержит оба точных transport NodeId
  клиентов в состоянии active. JSONL message с TSV-таблицей разобран явно,
  а не принят по наличию ID в произвольной строке.
- P2P запрещён и перечитан на обоих концах. Это non-onion Delivery relay,
  не private onion/PinnedRoute и не direct P2P.

## Что выполнено

| Сценарий | Incoming от начала запроса | Пять свежих RX-срезов на обоих концах | Результат |
|---|---:|---:|---|
| Poco → Mac, исходно cellular | 0,610 с | 7,299 с | Baseline и последующее наблюдение прошли |
| Mac → Poco, исходно Wi-Fi | 0,125 с | 3,679 с | Baseline прошёл; затем выполнен network cut |
| Poco → Mac сразу после Wi-Fi off, отдельный запуск | 0,088 с | 18,397 с | Baseline и последующее наблюдение прошли |

Fresh — active call с ожидаемым call ID, running media, без worker stall,
положительный native packet count и native RX age от 0 до 1000 мс. Срезы
собирались примерно каждые 0,5 с. Это пакетный контроль, не акустическая
задержка и не подтверждение слышимости человеком.

### Смена сети внутри разговора — повторный отказ

Wi-Fi off вернулся в +31,240 с от начала harness; первый OS-срез validated
cellular — +31,874 с. В +54,619 с у Mac уже отсутствует ожидаемое состояние
звонка; только затем harness отмечает failure и приступает к cleanup.
Итого **23,379 с после возврата команды Wi-Fi off**. В журнале Mac есть
один `livenessTimeout`; телефон в последнем парном срезе ещё active.

Наблюдались native RX age до 10463 мс у телефона и 11108 мс у Mac.
Эти максимумы срезов не объявляются продолжительностью всей сетевой тишины:
не доказана непрерывность media epoch на всём интервале.

Планировались два network-cut цикла, но **выполнен только первый**:
скрипт остановился на потере call state. Второй цикл и обратный переход
в том же разговоре не засчитываются. После этого отдельно выполнен
новый звонок сразу после Wi-Fi off.

### Новый звонок после отключения Wi-Fi — граница вывода

В отдельном запуске команда off вернулась в +8,258 с; входящий уже виден
в +8,346 с. Первый OS-срез validated cellular появляется лишь в +9,131 с.
Поэтому нельзя утверждать, что сигнал входящего уже прошёл именно через
cellular: он мог воспользоваться ещё живым прежним attachment.
Пять свежих двусторонних срезов достигнуты в +26,655 с, через 18,397 с
после начала запроса, уже при наблюдавшемся cellular. Ускорение не заявляется.

## Транспортное свидетельство и пределы

В app-specific Android capture два incomplete obfs4 handshake по 10001 мс,
оба в фазе Read: written/read 129/0 и 161/0 байт. Для каждого kernel queue
равна written, notsent 0, unacked 1, retransmissions 4.

Это повторение симптома первой TCP-посылки без подтверждения. Данные
переданы TCP-стеку; факт выхода на радио и конкретная точка потери этим
не доказаны. PCAP и точного межхостового flow join в этой серии нет.
Эти два observation не объявляются объяснением всех 23,379 с или причиной
того же call-end. App-specific native capture начат после исходного
mobile-call baseline; полноту более раннего capture не заявляем.

Локальный missed-wake дефект закрыт регрессиями. Следующий участок остаётся
транспортным: от NetworkChanged до пригодного canonical/child канала и
приёма Delivery после него. Таймаут liveness и аудиобуфер не менялись.
Это не A/B и не доказательство регрессии `aa51cc13` против `29ee0700`.

## Очистка

Свои приложения закрыты, exact PID проверены; Mac потребовал SIGKILL после
grace. Отдельная Mac-инстанция восстановления QA-настроек также закрыта.
Logcat остановлен, ADB forward и локальные порты освобождены. QA APK
восстановлен по SHA, основной APK и прежний root QA-контейнер по SHA прежние.
Исходные mobile-on / Wi-Fi-off и awake-настройки восстановлены; validated
cellular подтверждён.

В своих QA-профилях default P2P `contacts` восстановлен явной записью;
до опыта запись отсутствовала. Побайтный возврат самих тестовых профилей
не заявляется: в них также появились тестовые звонки. Реальные профили
не открывались.

Оба собственных временных Mac runtime удалены. Добавленный во время работы
`xveil-debug.log` из своего app bundle сохранён приватно и удалён; после
этого повторная строгая проверка подписи bundle прошла. Удалено 153267538
байт своих упаковочных промежуточных файлов, final/rollback сохранены.
QA-Core, его unit/config/binary/state/runtime и порты удалены; production
PID, executable/config SHA и NRestarts прежние. Push и релиз не выполнялись.
