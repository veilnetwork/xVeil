# Смена сети в звонке через два независимых Core

NETCALL-01 **остаётся открытым**. Выполнены оба направления смены сети на Poco
и Mac с P2P denied. Cellular → Wi-Fi прошёл минутный контроль; после Wi-Fi →
Cellular аудиоприём возобновлялся, но затем повторно задержался: возраст
последнего принятого пакета достиг 8548 мс на телефоне и 9609 мс на Mac.
Доступность двух Core сама по себе дефект не устранила.

## Неизменные клиенты и отдельный тестнет

Клиентская native SDK — `c6699c28`, Core — observational `97dc1295`.
Повторно использованы прежние подписанные Mac app и QA APK; у APK заменены
только два bootstrap assets. AOT/frontend/native payloads и signer проверены
побайтово. Сборки не объявлены текущей SDK: исходный `37f6bb08` и новая
диагностика этого раунда в физическую серию **не входили**.

Два Core находятся на разных серверах, соединены друг с другом; глобальные
meeting points, built-in seeds и PEX отключены. До звонков оба Core имели
соединения с обоими клиентами и друг с другом. Production-узлы не менялись.
Один и тот же процесс каждого клиента использовался во всей основной серии.
Приём проверялся автоматически, слышимость речи, эхо и шум не оценивались.

## Результаты

Свежий RX: тот же call ID, active/running, worker_stalled=0, RX packets > 0,
возраст native RX 0–1000 мс. Исходная готовность и финальный успех требуют
пяти последовательных свежих срезов на обоих концах. Неудача этого строгого
критерия сама по себе не означает длительный обрыв.

| Сценарий | Наблюдение | Строгий финальный критерий |
|---|---|---|
| Wi-Fi, Poco → Mac | 35 с после готовности RX | Пройден |
| Wi-Fi, Mac → Poco | 35 с после готовности RX | Пройден |
| Cellular, Poco → Mac | Краткие скачки RX age до 1,34/1,36 с, приём возобновлялся | Не пройден на Mac |
| Cellular, Mac → Poco | 35 с после готовности RX | Пройден |
| Cellular → Wi-Fi, первая попытка | Предусловие свежести перед переключением не прошло | Сеть не переключалась |
| Wi-Fi → Cellular | 60 с; целевая сеть validated, PID прежний; поздняя пауза RX | Не пройден на Mac |
| Cellular → Wi-Fi, отдельный повтор | 60 с; 113/113 свежих post-switch срезов на каждом конце; RX age ≤340/537 мс | Пройден |

Для отдельного повтора после первоначальных 15 с дополнительно дождались пяти
свежих срезов подряд, не ослабляя RX-критерий. Это новый опыт; отказ первой
попытки не заменён зелёным результатом. Всего реально выполнены **два** перехода.

Wi-Fi → Cellular: примерно на +31…+40 с от команды наблюдалась повторная пауза.
В 13 OS-срезах вокруг неё — только validated Cellular, ошибок наблюдения нет.
На обоих концах движок running, без worker stall; TX payload counter растёт,
RX packet counter не регрессирует. Это не ошибка, вызванная только повторным
созданием счётчика. Первые свежие срезы сразу после переключения не названы
устойчивым восстановлением: они предшествуют этой поздней паузе.

## Что видно внутри пути

До вызовов запущены три family-3 наблюдателя: два Core и Mac. Собрано
23759 / 25085 / 24441 строк; plaintext отсутствует. В публичном результате
нет IDs, адресов, портов, ключей, ciphertext previews или их хешей.

В первые 10 с успешного Cellular → Wi-Fi у Core A в консервативной внутренней
части окна (8543 мс) принята 271 различная opaque media-marker запись от Mac.
Для 262 есть совпадение всего неизменного 224-байтового зашифрованного preview
в наблюдениях A TX → B, B RX ← A и B TX → телефон. Одного совпадения мало:
в 181 случае B уже отправил запись телефону до приёма копии от A.
Только **81** проходит дополнительный порядок RX-before-TX на каждом Core
и имеет ровно один предшествующий ingress на каждом из них. Выбранные четыре
стадии уникальны во всём захвате. Это свидетель работающей пересылки между
Core в пределах наблюдений; приём каждой конкретной записи телефоном
не доказан — frame subscriber на телефоне не использовался. Межхостовой
порядок не выводится из некалиброванных timestamp.

У неудачного Wi-Fi → Cellular на Core наблюдаются `record plane closed`,
keepalive timeout и новые сессии телефона около последующего возобновления RX.
SSH clock interval widths — 1456,746 / 804,763 мс; сравнение времён разных
хостов ограничено этими границами. Односторонняя сетевая задержка не измерена.

**Причинный вывод ограничен.** Старое сообщение о закрытии содержит только
peer/error: у одного peer одновременно бывают живые и retiring receivers.
Без их номера нельзя объявить закрывшийся канал текущим медиапутём.
`record plane closed` также сворачивает EOF, I/O error, expiry, owner drop и
отмену в один исход. Захват не доказывает единственную причину паузы,
переполнение очереди, неисправность провайдера или DPI.

## Подготовленная диагностика

SDK `1572c22b`: при включённом RT trace закрытие теперь дополнительно пишет
`session.rt_trace.datagram_receiver_closed`, номер того же receiver, который
используют периодические срезы, и штатные path counters. Это позволяет отличать
каналы при следующем захвате. Сетевое поведение, таймеры, авторизация, wire и
кодеки не менялись; root cause не объявлен исправленным.

697 session tests passed, 8 ignored отдельно; rustfmt чистый. Проверка AOT
анонимного экспорта прошла. Новая строка найдена в собранном test executable;
его SHA и source hash сохранены приватно. Rust target был на внешней ФС,
mount/free-space watchdog не срабатывал. Новая диагностика физически пока
не квалифицирована и на production не ставилась.

## Исключённые попытки и уборка

Первая фаза потеряла ADB во время первого фиксированного Wi-Fi контроля,
до handover. Она исключена: 0 квалифицированных вызовов, сеть внутри разговора
не переключалась. USB оставался виден, после замены ADB libusb backend на native
вторая фаза прошла без ошибок API/OS-наблюдения. Это сбой наблюдателя,
не доказательство сбоя xVeil. Изменений постоянной конфигурации ADB нет.

В исключённой первой фазе копирование удалённого журнала во время записи не
прошло SHA-проверку и не использовано. Исправленный collector останавливает Core до вычисления
manifest/tar; оба финальных архива и каждая запись проверены. PCAP обоих Core
прочитаны до EOF отдельным parser и tcpdump. Публичные счётчики не приписывают
неаутентифицированные подключения к тестовым портам телефону.

Оба QA Core, capture/subscriber units, их каталоги и порты убраны. Production
PID/binary/config совпадают до/после. Mac и QA phone закрыты; собственные
дочерние процессы завершены, порты освобождены. Прежний QA APK, root container,
normal APK, сеть, mic permission и P2P choices восстановлены и проверены.
Собственный runtime Mac удалён; новый debug log вынесен из app bundle, после
чего deep/strict codesign verification прошла. 29 исходных наблюдательных
входов заморожены с приватными SHA. Push/релиза и sibling mailbox нет.

Следующий шаг — захват с новой receiver-close диагностикой и сопоставление
конкретного канала с потерей RX и восстановлением сессии. Успешный обратный
переход не закрывает неудачный прямой; сравнение с прежним одним Core не A/B.
