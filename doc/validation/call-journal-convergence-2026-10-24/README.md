# Окончательный результат звонка на своих устройствах — 24 октября 2026

## Воспроизведённые расхождения

| Проверка исходного кода | Ожидалось | Получено |
|---|---|---|
| A записал предварительное наблюдение, B — окончательную длительность; обмен в обоих направлениях | Одна одинаковая строка | A сохранял 0 секунд, B — 75 |
| Предварительное наблюдение имеет более позднее время | Итог отвечавшего устройства побеждает | Fold и live-applier выбирали предварительную запись |
| После «ответили на другом устройстве» само соединение завершилось ошибкой | Окончательный failed | Оставался completed от устройства, которое не участвовало в разговоре |
| Отвечавшее устройство не смогло запустить медиа | failed без времени разговора | Recorder считал наличие ответа (`connectedAt`) успешным стартом |

Три регрессионных теста падают на исходном коде. Отдельный контроль с прежним
критерием `connectedAt` воспроизводит ещё две ошибки на настоящем CallService
с управляемым контроллером медиа: неудачный старт записывается как completed,
а ожидание запуска попадает в длительность. После контроля исходник восстановлен
побайтно; настоящие микрофоны в этих тестах не открываются. Первый сценарий дополнительно
воспроизведён независимыми процессами: **общий подписанный журнал A/B уже сходился
на 75 секундах, но локальные истории сохраняли 0 и 75 секунд**. Причина на уровне
хранения — любой повтор call ID считался дублем и никогда не обновлял строку.
Отдельная причина в синхронизации — выбор исключительно по времени наблюдения.

## Исправление

* Запись «ответили на другом устройстве» явно отмечена как предварительная.
  В журнале и чате отображается «Принят на другом устройстве», без ложного 0:00.
  Добавлены строки en/ru/es.
* CallService отмечает первый успешный запуск медиа отдельно от ответа на
  приглашение. Recorder различает отказ запуска и состоявшееся соединение;
  длительность не включает ожидание инициализации. Смена маршрута уже активного
  звонка сохраняет время первого запуска.
* Хранилище, device fold, live-applier и compaction используют одно правило:
  окончательная запись сильнее предварительной; подтверждённое соединение
  сильнее таймаута на другом звонящем устройстве; для completed выбирается
  более полная длительность. Оставшиеся равенства решаются детерминированно.
  Неправильный payload не вытесняет корректную запись.
* Исправление записывается новой append-записью, затем прежняя версия удаляется
  отдельной транзакцией. Смешивать append/delete одного Log namespace native
  хранилище запрещает. При сбое между этими этапами чтение показывает один
  логический звонок. Повторная сверка завершает очистку физических версий.
* При одинаковом времени порядок и отсечение последних 200 звонков зависят от
  call ID, а не порядка получения. Если окончательная запись уточнила время
  назад и изменила состав окна, недостающие звонки восстанавливаются из
  доступного эффективного device fold. Это проверено и с прерыванием записи
  посередине восстановления.
* Сверка не публикует обратных зеркал. Пачка входящих записей использует общий
  проход сверки; завершение messaging дожидается работ через существующие
  shutdown tasks и apply gate. Новых отладочных endpoint или флагов в рабочем
  коде нет.

## Native A/B/C

A/B — разные устройства одной личности X; C — другая личность, указанная как
собеседник в проверочных строках. Каждое устройство и локальные реле работают
отдельными процессами с настоящими зашифрованными контейнерами.

| Этап | Online | Фактический результат исправленной версии |
|---|---|---|
| A записывает 0, B offline | A, C | На A своя запись |
| B записывает 75, A offline | B, C | На B своя запись |
| A возвращается | A, B, C | Подписанные журналы и видимые истории сходятся: 75 секунд, ровно одна строка |
| A/B полностью перезапускаются | После запуска A, B, C | Строки идентичны, длительность сохраняется |
| Через device group приходит предварительная строка с ring time +120 с | A, B, C | B сохраняет её как предварительную |
| B записывает окончательный failed | A, B, C | На обоих устройствах и в device fold итог failed, предварительной метки нет |

Записи создавались существующим API для журнала и device events; **разговор
на 75 секунд не проводился**. Значение 75 — проверочные данные. Смещение +120 с
касается ring time в payload; часы ОС и timestamp самого group-события не
переставлялись. Обратный порядок timestamp событий отдельно проверяется unit-
тестом fold/live gate. Это проверка хранения и синхронизации, не качества медиа.

После первого парного прогона окончательная версия повторно прошла на текущем
SDK; preload и storage worker явно закреплены на одном frozen артефакте
hidden-volume. Хеши библиотек и исходников приведены в [summary.json](summary.json).
Native SDK и hidden-volume в этом цикле не изменялись.

## Проверки и пределы

* **292** выбранных Flutter/Dart теста без пропусков, включая 13 новых проверок
  сходимости/сбоев и обновление открытого журнала без переоткрытия раздела.
* `flutter analyze --no-pub`: **0 замечаний**.
* Native-сценарий прошёл с окончательным кодом, после проверки исходного
  расхождения и первого успешного исправленного прогона. Все собственные
  worker/relay процессы всех запусков завершены, временные контейнеры удалены.
* Обычный Android APK построен с `lib/main.dart`; контроль артефактов в JSON.
  Он не устанавливался. Flutter использовал `TMPDIR=/private/tmp/`.

Для старой строки без метки нельзя всегда отличить настоящий короткий completed
от исторического «ответили где-то ещё». Доступная полная длительность исправляет
старые 0 секунд; отсутствующие данные не восстанавливаются из ничего. Полное
поведение требует обновления своих устройств; смешанные версии этим циклом не
квалифицированы. Возврат вытесненной строки требует её наличия в device journal.
Предел 200/сбои проверены unit-тестами, native-прогон использует небольшую историю.
Полная матрица multi-device, произвольные аварии на всех стадиях, Windows 10,
физический Android и живые аудио/видеозвонки здесь не квалифицированы.

В опубликованном отчёте нет участников, CID/call ID, адресов, паролей, ключей
или сырых журналов — только результаты, счётчики и хеши ПО. Телефон и установленные
пользовательские приложения не менялись. Исторический каталог
`multi-device-2026-10-17` сохранён без изменений.
