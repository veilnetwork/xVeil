# После смены сети теряется соединение с единственным Core

Продолжение [покадрового захвата](../core-frame-join-2026-11-07/README.md).
На отдельном Core — SDK `97dc1295` с новой opt-in диагностикой; клиенты
Poco / Android 16 и Mac остаются на immutable SDK `c6699c28` и прежнем
qualified QA AOT. Между этими SDK только два observational source files.
ELF, SHA, исходники, факт перекомпиляции session и наличие новых diagnostic
strings проверены. Core собран под проверенным внешним FS с watchdog.
Ни один новый клиентский binary не выдаётся за протестированный.

## Физические результаты

Один изолированный testnet Core через obfs4/TCP 443, P2P denied. Production
не менялся. До каждого вызова проверялся validated transport; до перехода
внутри вызова — пять свежих срезов на обоих концах и ещё 15 с устойчивого
контроля. Сброшенный RX/новый epoch не считались восстановлением.

| Сценарий | Пять fresh RX после place | Проверяемый итог |
|---|---:|---|
| Wi-Fi, Poco → Mac | 4,230 с | 35 с, конечные пять свежие |
| Wi-Fi, Mac → Poco | 3,371 с | 35 с, конечные пять свежие |
| Cellular, Poco → Mac | 5,490 с | 35 с, конечные пять свежие |
| Cellular, Mac → Poco | 4,911 с | 35 с, конечные пять свежие |
| Cellular → Wi-Fi внутри Poco → Mac | 4,955 с до перехода | **Не восстановился за 60 с** |

Первые четыре успеха не объясняют прежнюю недоставку и не доказывают ускорения:
маршруты/кэши/повторы между сериями различаются. Пятый разговор сохранил call ID,
но конечные пять срезов на **обоих** концах несвежие. Controller epochs
перешли с 9 через 11/13 к 15; в последнем epoch RX 0 при продолжающемся TX.
Завершение сделал diagnostic API. Самопроизвольный отбой и слышимость человеком
здесь не заявлены. NETCALL-01 остаётся открытым.

## Чем этот захват отличается от предыдущей очереди

Полный Core node log — 2 901 451 байт; `local_reliable_pressure` rows **0**.
Новая ветвь `pressure_route=child` в этом сбое не наблюдалась. Это не основание
ретроактивно отрицать прежние 44 pressure windows / depth 176; у двух захватов
различаются наблюдаемые механизмы. Краткие, не попавшие в throttled log события
также не исключаются.

После включения Wi-Fi новая обфускационная и canonical session телефона с Core
успела установиться. Затем телефон закрыл её по **keepalive timeout**:

- После коррекции часов телефона — примерно **14,114 с** после команды Wi-Fi;
  интервал clock offset ограничен ADB-пробами шириной 40,272 мс.
- В той же строке native log: probe unacked **9807 мс**, genuine data age
  **5124 мс**, swap attempts **2**. Это фактическая причина закрытия session,
  не догадка по совпадению констант.
- Затем три полные reconnect-попытки достигли примерно **10 с** каждая;
  локально прочитано 0 обфускационных handshake bytes. Четвёртая попытка
  ещё шла к окончанию теста.
- Прямые **служебные** Poco ↔ Mac сообщения продолжали приходить. Это не
  означает существование session с Core и не доказывает работоспособность
  медиапути, для которого P2P был запрещён.

Покадровые observers Core/Mac работали до вызовов. В консервативном внутреннем
окне пятого вызова все 552 phone-origin media-marked previews имеют Core TX
и Mac RX witness. Для Mac-origin — 1646 Core RX / 631 Core TX; после потери
подключения телефона кадры Mac продолжали поступать на Core. При одном Core
без P2P у этого стенда нет другого пути к телефону.

**Не доказано**, почему сначала перестал проходить data/ACK на новом соединении
и почему последующие handshake не завершились. Локальное принятие bytes не
равно отправке NIC или доставке. Без однозначного endpoint↔PCAP join нельзя
назначать причиной DPI/провайдера. Не проверена и сходимость на нескольких
независимых Core при такой потере; production failover этим стендом не закрыт.
Ожидание child queue, изменение размера аудиопакета и увеличение таймера
из этих данных не следуют.

[Анонимные агрегаты](summary.json) отделяют физическую серию от последующего
локального исправления повторного bootstrap join.

## Проверяемое исправление ручного восстановления

При разборе контрольного подключения подтверждён отдельный дефект
`BootstrapJoinForwarder`: повторное добавление известного настроенного peer
возвращало `AlreadyRegistered`, но не помещало существующую запись в dial queue.
Комментарий обещал redial; фильтр по synthetic ID оставлял configured peer без
него. Второй подтверждённый дефект: настоящий ID закреплённого реле лежит выше
нижней границы app-added, поэтому прежний числовой guard позволял приглашению
заменять адрес/TLS-поля такого реле. Это не объявляется причиной автоматического
handover-сбоя.

Исправление отправляет существующую запись в прежнюю bounded queue. Здоровое
соединение и незавершённый dial остаются под прежними connector gates;
глобального network-change wake нет. Адрес и остальные operator-owned поля
не берутся из повторного приглашения. Для runtime-discovered P2P peer обновление
адреса сохраняется — запрет всех synthetic IDs сломал бы endpoint refresh.
Guard учитывает `PeerSource::Configured` / `PinnedRelay`, а не только числовой
диапазон. Существующий DHT contact обновляется только при разрешённом refresh.
Backpressure остаётся bounded; после освобождения очереди повтор работает.

Три теста на прежнем коде упали именно на отсутствии dial entry. Отдельно
исправлен сам fixture: условный малый ID закреплённого реле заменён на ID из
реального диапазона `PINNED_RELAY_BASE`; это дало assertion-red на подмене
operator-owned полей. Малый ID раньше скрывал этот дефект. Восемь focused
тестов проверяют обычное добавление, dynamic refresh, configured/pinned retry,
неправильный URI, backpressure, защиту configured даже с synthetic ID и
сохранение Rendezvous endpoint refresh. Ни timeout, ни compile error не
считаются воспроизведением.

Итоговые проверки и source commit записаны в агрегаты отдельно; в пяти
вызовах выше этого исправления **не было**. Физическая проверка обновлённого
ручного retry ещё предстоит.

Source commit: Veil `37f6bb08`. На финальном коде — 818 runtime passed /
11 ignored; форматирование и diff check чистые. Strict Clippy остановился на
ранее существовавших `manual_async_fn`, `needless_borrow`, `collapsible_if` и
`too_many_arguments` в соседнем runtime/dispatcher/IPC-коде. Проверка с
разрешёнными только этими четырьмя категориями прошла; strict-green не
заявляется. Пробные соседние lint-cleanups не включены в итоговый diff.
Сборки/тесты выполнены в том же checkout, без dependency override, с внешним
mount watchdog; исчезновения mount не было.

## Завершение стенда

37740 PCAP packets / 140 flows разобраны до EOF; копия проверена size/SHA до
удалённого cleanup. Core/клиенты, frontend и harness versions заморожены на
время серий. Фактические источники и client artifact SHA не менялись.
Observers/probe/logcat и собственные приложения завершены, порты освобождены.
Mac потребовал SIGKILL после grace. Свой runtime и debug log из bundle убраны,
strict codesign повторно проверен. APK, разрешение микрофона, сеть, stay-on,
P2P policies и старый QA-контейнер восстановлены по readback/SHA.
Отдельные Core/capture/observer services и свои данные удалены, production
PID/exe/config прежние. Сырые логи, previews, адреса, ключи и IDs приватны.
Push/релиза нет.
