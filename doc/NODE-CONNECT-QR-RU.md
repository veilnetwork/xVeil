# Установка и подключение серверного узла по QR

Этот способ заменяет SSH временным HTTPS-сеансом. Основной бинарник Veil
не меняется: на сервере работает отдельный скрипт `veil-connect`, а приложение
использует те же сценарии установки и настройки, что и при подключении по SSH.

**Пока в разработке, в опубликованные версии не входит.** Для проверки из
исходников соберите файл командой ниже. Сборка релиза подготовлена к выпуску
этого же файла как отдельного вложения `veil-connect` и `veil-connect.sha256`.

## Новый сервер

Нужен Debian/Ubuntu с systemd, root-консоль у провайдера и доступный с телефона
входящий TCP-порт. Docker для установки не требуется. Обычный порт помощника —
8443; это отдельный порт управления, не транспортный порт будущего узла.
В firewall сервера и панели провайдера он должен быть разрешён. Скрипт не
меняет firewall и не занимает уже работающий порт nginx.

Из исходников:

```bash
python3 scripts/build_veil_connect.py veil-connect
```

Передайте получившийся файл на сервер через консоль провайдера и запустите
**из root-консоли**:

```bash
bash ./veil-connect --host node.example.org --port 8443
```

`node.example.org` замените адресом своего сервера. Без `--host` помощник
попробует выбрать публичный адрес локального интерфейса. Если сервер за NAT,
укажите внешний адрес и пробросьте порт; при разных внешнем и внутреннем
портах добавьте `--advertise-port ВНЕШНИЙ_ПОРТ`.

После появления вложения в соответствующем релизе будет доступен вариант
одной командой. Здесь `TAG` — **тег, действительно содержащий это вложение**;
в старых выпусках его нет:

```bash
TAG=vX.Y.Z
curl -fsSL "https://github.com/veilnetwork/xVeil/releases/download/$TAG/veil-connect" |
  bash -s -- --host node.example.org --port 8443
```

1. Помощник проверит Python 3.8+, openssl, qrencode, sudo, iproute2, curl,
   доверенные HTTPS-сертификаты и util-linux для блокировки установки. На Debian/
   Ubuntu установит недостающие зависимости через apt. Службу Veil он на этом
   шаге не устанавливает.
2. В терминале появится QR. В xVeil откройте **Мои узлы → Добавить →
   Подключить по QR**, отсканируйте его и нажмите **Подключить**. Код можно
   вставить вручную в поле под кнопкой сканирования.
3. Для нового сервера откроется существующий экран установки: выберите
   архитектуру, релиз, транспорт и нужные компоненты — Veil, ogate,
   oproxy-client или oproxy-server. Проверьте параметры и запустите установку.
4. Терминал на сервере оставьте открытым до окончания операции. Установщик
   проверяет контрольные суммы загружаемых файлов и сообщает созданный ID.
   Приложение сохраняет его у текущей личности и добавляет точку входа.

Помощник устанавливает только собственный дополнительный файл
`/usr/local/bin/veil-connect`. Постоянной службы управления нет. Этот путь
не заменяется, если там уже лежит чужая программа или символическая ссылка.

## Уже установленный узел

После первого запуска достаточно:

```bash
veil-connect --host node.example.org
```

Если помощник ещё не установлен, сначала выполните команду из предыдущего
раздела. QR-подключение прочитает список установленных компонентов, текущий
ID и параметры узла; повторная установка поверх работающего Veil для
добавления записи не нужна. Для выхода в сеть используется публичное
приглашение узла, а не секрет управления из QR.

Поддерживаются стандартные пути существующего установщика xVeil:

| Компонент | Конфигурация |
| --- | --- |
| Veil | `/var/lib/veil/node.toml` |
| ogate | `/etc/ogate/ogate.toml` |
| oproxy-client | `/etc/oproxy/client.toml` |
| oproxy-server | `/etc/oproxy/server.toml` |

Произвольные пути конфигурации и другие имена systemd-служб пока не
подхватываются автоматически. nginx настраивается отдельно по
[инструкции Debian + nginx](NODE-DEBIAN-NGINX-RU.md).

## Как закончить или возобновить доступ

QR даёт управление с правами запустившей скрипт учётной записи. Храните его
в секрете: это не приглашение для друзей и не публичная ссылка на узел.
Приложение сверяет сертификат HTTPS с отпечатком в QR **до передачи секрета**.
Первое сопряжение закрепляет сеанс за этим клиентом; повтор запроса после
потери ответа не выполняет команду второй раз.

По умолчанию новые команды разрешены 10 минут (`--ttl`, от 60 до 900 секунд).
Принятая команда имеет собственный таймаут до 6 минут и короткий срок получения
результата. **Ctrl+C завершает доступ и прерывает выполняемую команду.**
Не закрывайте помощник посреди установки.

Чтобы управлять узлом позже, снова запустите `veil-connect`, откройте узел
в xVeil и выберите **Обновить доступ по QR**. Запись узла остаётся в личности,
но старый сеансовый ключ после перезапуска помощника не работает. Сам ключ
хранится отдельно от каталога узлов внутри зашифрованного пространства xVeil.

Если адрес или порт недоступны с телефона, QR сам по себе это не исправит.
HTTPS здесь — альтернатива SSH для управления, не обещание обхода сетевого
белого списка или гарантированной доступности сети Veil.
